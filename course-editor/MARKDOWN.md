# Markdown и структура файлов

## 1. Общий принцип

Markdown должен быть единообразным технически, но не должен превращать содержание в одинаковый шаблон.

---

# 2. Frontmatter

Каждый урок должен иметь YAML frontmatter, если это предусмотрено текущей архитектурой курса.

Существующие поля необходимо сохранять.

Новые поля добавляются только осмысленно.

---

# 3. ID

ID урока должен быть:

- уникальным;
- стабильным;
- пригодным для ссылок и frontend.

Не изменяй существующий ID без необходимости.

---

# 4. Порядок

Поле order должно соответствовать логическому порядку урока внутри раздела.

Если уроки перемещены внутри раздела, order необходимо привести в соответствие.

---

# 5. Заголовки

Используй корректную иерархию Markdown:

# Название урока

## Раздел

### Подраздел

Не создавай уровни только ради визуального оформления.

---

# 6. Код

Код должен иметь корректный язык Markdown:

```python
    /print("Hello")
    #include <iostream>
    SELECT *
    FROM users;
```

Не используй generic code block там, где язык известен.

7. Код и текст

Не помещай обычный текст в блоки кода ради визуального оформления.

8. Схемы

Схемы должны быть:

короткими;
читаемыми;
полезными.

Не создавай ASCII-схему, если она сложнее самого объяснения.

9. Изображения

Существующие PNG/SVG могут быть удалены в рамках общей редакторской переработки.

Не сохраняй изображение только потому, что оно существовало раньше.

Если визуальный материал действительно необходим, сначала оцени, нельзя ли лучше выразить его Markdown-схемой.

10. Ссылки

Внутренние ссылки должны указывать на существующие материалы.

Внешние ссылки использовать умеренно.

Предпочтительно:

официальная документация;
полезные тренажёры;
качественные практические ресурсы.
11. Форматирование

Не использовать:

чрезмерные разделители;
декоративные символы;
лишние эмодзи;
многочисленные одинаковые блоки;
визуальный шум.
12. Основное правило

Markdown должен помогать читать учебник, а не демонстрировать возможности Markdown.
