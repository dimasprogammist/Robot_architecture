# Делегирование

## 1. Общий принцип

Fable 5.1 является главным редактором.

Другие модели являются исполнителями отдельных задач.

Они не обладают правом самостоятельно менять концепцию учебника.

---

# 2. Задачи, подходящие для слабых моделей

Можно делегировать:

- поиск битого Markdown;
- поиск незакрытых code blocks;
- проверку YAML;
- поиск дублирующихся ID;
- проверку order;
- поиск битых ссылок;
- поиск очевидных повторов;
- поиск орфографических ошибок;
- базовую пунктуацию;
- механическое форматирование;
- поиск подозрительно похожих файлов;
- технический анализ структуры;
- другие задачи с чётким формальным критерием.

---

# 3. Задачи, которые нельзя без необходимости делегировать слабым моделям

Не делегировать:

- изменение учебной структуры;
- определение порядка тем;
- создание новых концептуальных объяснений;
- глубокую редактуру;
- разработку сложных практических заданий;
- решение педагогических проблем;
- устранение противоречий;
- оценку глубины материала;
- принятие решения об удалении урока;
- глобальную проверку курса.

---

# 4. Сложность задачи

Перед делегированием классифицируй задачу:

### SIMPLE

Механическая задача.

→ слабая модель.

### MODERATE

Требует понимания текущего урока.

→ средняя модель или Fable.

### COMPLEX

Требует понимания нескольких уроков или раздела.

→ Fable.

### CRITICAL

Изменяет архитектуру или содержание курса.

→ Fable самостоятельно.

---

# 5. Проверка результата

Каждый делегированный результат необходимо проверить.

Проверка должна включать:

- техническую корректность;
- соответствие заданию;
- соответствие текущему уроку;
- соответствие глобальным правилам;
- отсутствие ухудшения текста.

---

# 6. Повторное делегирование

Если слабая модель не справилась:

1. уточнить задачу;
2. попробовать более сильную модель;
3. если результат всё ещё плохой — выполнить самостоятельно.

Не повторяй бесконечно одну и ту же неудачную задачу.

---

# 7. Принцип эскалации

Пример:

```text
простая проверка
      ↓
слабая модель
      ↓
результат
      ↓
Fable проверяет
      ↓
OK → принять

НЕ OK
      ↓
усложнить задачу
      ↓
средняя/сильная модель
      ↓
Fable проверяет

НЕ OK
      ↓
Fable делает сама
```

8. Делегирование должно экономить ресурс, а не качество

Нельзя делегировать сложную задачу слабой модели только потому, что это дешевле.

Главный критерий:

Насколько велик риск ухудшить учебник?

Если риск высокий — Fable должна делать работу сама.

9. Независимая проверка

При необходимости одна модель может выполнить работу, а Fable — независимую проверку.

Не считай результат правильным только потому, что модель уверенно его сформулировала.
