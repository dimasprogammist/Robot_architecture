# Архитектура учебника

## 1. Общая концепция

Учебник представляет собой последовательный курс от основ компьютера к программированию, разработке программного обеспечения, инфраструктуре, электронике, микроконтроллерам, протоколам, робототехнике, computer vision и нейронным сетям.

Читатель может выбрать любой раздел как следующий, однако внутри каждого раздела предполагается последовательное прохождение уроков.

Порядок разделов должен быть логичным и образовывать общую образовательную траекторию.

---

# 2. Текущая структура

Назначение:

Сформировать базовое понимание того, как устроен современный компьютер.

Глубина:

Фундаментальное понимание без чрезмерного погружения в архитектуру CPU и низкоуровневую реализацию.

# 3. Ограничения архитектуры

Нельзя переносить существующий урок между разделами.

Можно:

- менять порядок внутри раздела;
- объединять уроки;
- разделять уроки;
- создавать новые;
- удалять ненужные;
- дополнять существующие.

В каждом разделе без отдельного решения автора можно создать максимум 3 новых урока.

---

# 4. Особенности крупных разделов

Python и C++ должны рассматриваться как фундаментальные разделы.

Большое количество уроков здесь допустимо.

Не сокращай раздел только ради уменьшения количества файлов.

Если содержание можно сделать более глубоким и полезным, предпочтительно улучшить его.

---

# 5. Незавершённые разделы

Разделы 05, 24, 25 и 26 находятся в разработке.

Не следует искусственно заполнять их большим количеством уроков.

После появления содержания провести отдельный структурный анализ.

---

# 6. Глобальная последовательность

При анализе структуры необходимо определить:

- какие разделы являются фундаментальными;
- какие разделы используют знания предыдущих;
- какие разделы можно проходить относительно независимо;
- где существуют логические зависимости;
- где отсутствуют необходимые промежуточные знания.

Если обнаружена проблема в глобальном порядке разделов, зафиксировать её в отчёте.

Не переносить уроки между разделами без отдельного решения автора.
