# Editorial State

Этот файл является постоянным рабочим состоянием редакторской переработки учебника.

Он нужен для того, чтобы работа над большим проектом не зависела от текущего контекста одной сессии.

`EDITORIAL_STATE.md` не является подробным журналом всех действий.

Здесь фиксируется только информация, которая нужна главному редактору для продолжения работы и понимания уже принятых решений.

---

## Current phase

**Статус:** первичный анализ ещё не выполнен.

**Текущая задача:**

Провести полный анализ существующего учебника, его структуры, содержания, зависимостей и проблем перед масштабной редакторской переработкой.

# 3. Структура курса

Фактическую структуру необходимо определить после анализа директории `course/`.

Не следует заполнять этот раздел предположениями.

После анализа здесь необходимо зафиксировать:

- список разделов;
- порядок разделов;
- количество уроков в каждом разделе;
- важные особенности каждого раздела;
- крупные зависимости между разделами.

---

# 4. Обработанные разделы

Пока ни один раздел не считается полностью обработанным.

Формат записи:

```text
## Название раздела

Статус: NOT_STARTED / IN_PROGRESS / REVIEW / COMPLETED

Что сделано:
- ...

Что осталось:
- ...

Ключевые решения:
- ...

Проблемы:
- ...
````

Не помечать раздел как `COMPLETED`, если проверен только внешний вид отдельных файлов.

Для завершения раздела необходимо проверить его:

* содержание;
* порядок уроков;
* зависимости;
* повторения;
* практику;
* Markdown;
* внутреннюю согласованность.

---

# 5. Разделы в работе

Если работа ведётся одновременно только над одним разделом, указывать его здесь.

```text
Нет.
```

Если работа ведётся над несколькими разделами, явно указать причины.

---

# 6. Проблемные разделы

Сюда помещаются разделы, которые после анализа требуют особенно серьёзной работы.

Для каждой записи указывать:

* проблему;
* масштаб проблемы;
* предполагаемое решение;
* статус.

Пример:

```text
## 06-guide-programming

Проблема:
Некоторые фундаментальные понятия повторяются между уроками.

Решение:
Проверить границы ответственности уроков и убрать полные повторы.

Статус:
OPEN
```

---

# 7. Глобальные проблемы курса

Здесь фиксируются проблемы, которые затрагивают несколько разделов.

Например:

* одинаковые понятия объясняются несколько раз;
* одна и та же терминология используется в разных значениях;
* разные разделы предполагают несовместимый уровень подготовки;
* практические задания имеют разные принципы проверки;
* формат Markdown различается;
* ссылки на предыдущие темы устарели;
* существуют повторяющиеся диаграммы.

Не помещать сюда локальные проблемы одного урока.

# 9. Повторяющиеся понятия

Здесь фиксируются понятия, которые встречаются в нескольких местах и требуют контроля повторов.

Формат:

```text

...

...

...

Решение:
...
```

Цель — не запретить любое повторение, а определить место, где понятие объясняется полноценно.

# 25. Принцип работы с состоянием

`EDITORIAL_STATE.md` должен позволять новому запуску редактора быстро понять:

* где сейчас находится работа;
* что уже сделано;
* что было изменено;
* какие решения уже приняты;
* какие проблемы известны;
* что нельзя забыть;
* что делать дальше.

Если для понимания текущего состояния приходится перечитывать весь `course/`, значит этот файл ведётся недостаточно хорошо.

При этом он не должен превращаться в копию всего курса.

Его задача — хранить **состояние редакторского процесса**, а не содержимое учебника.
