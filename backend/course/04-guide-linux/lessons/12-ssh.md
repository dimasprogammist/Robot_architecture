# SSH — удалённый доступ

SSH даёт зашифрованный канал и проверку **сервера**. Клиент идёт на sshd (часто порт 22), сверяет ключ хоста, доказывает пользователя, получает shell или одну команду.

Пароль с интернета — подбор. Ключи: приватный у вас, публичный в `~/.ssh/authorized_keys` на сервере. Приватный по сети не едет. Первый вход: fingerprint в `known_hosts`. Внезапная смена — MITM или переустановка; проверяйте другим каналом, не `StrictHostKeyChecking=no` навсегда.

`~/.ssh/config` — алиас, User, IdentityFile, порт. Права на `.ssh` и ключи узкие, иначе клиент откажется. Агент держит расшифрованный ключ в памяти сессии; на общей машине это уже доверие к чужим процессам.

Туннели, `scp`/`sftp`, agent forwarding — после того как вход и ключи не дырявят. На сервере: без root-login по паролю, без пустых паролей, ограничить пользователей, обновлять sshd. Смена порта и fail2ban — политика, не магия.

```bash
ls -ld ~/.ssh
ls -l ~/.ssh 2>/dev/null || true
# ssh -G alias  — как клиент развернёт конфиг (если есть хост)
```

Сессия SSH — тот же Linux-shell, не «другая ОС». Права и PATH уже ваши с уроков 3–11.
