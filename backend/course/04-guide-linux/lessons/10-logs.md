# Логи и journald

Без журнала сервер — гадание. Два мира: файлы в `/var/log` и **journald** (stdout служб, ядро, syslog). Читают `journalctl -u`, по времени, по `-b` этой загрузки, по приоритету. Плюс — связь с unit. Минус — нужны права (группа `adm` / `systemd-journal` или root) и знание фильтров.

Текстовые логи крутит logrotate: иначе диск кончится — частая авария. Уровни emerg…debug: на проде info/warning, debug точечно. Токены в access-логе — утечка.

Порядок: status службы → `journalctl -u` → лог приложения → система (`-xb` на ошибках загрузки). Окно времени. Первое плохое событие, не последний симптом. Журнал в памяти (volatile) умрёт после reboot — снимите улики до.

Процесс пишет в fd 1/2 или syslog; journald индексирует бинарно. `journalctl` — запрос к этой базе, не `cat`.

```bash
journalctl -u ssh -n 20 --no-pager 2>/dev/null || journalctl -u sshd -n 20 --no-pager
journalctl -p err -b --no-pager | head
```

Не грепайте секреты в логах «для удобства» в тикет. Не верьте только GUI, если `journalctl` пуст из-за прав.
