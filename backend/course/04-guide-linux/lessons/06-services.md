# Службы — долгоживущие процессы под управлением

Служба — процесс, который должен жить долго: API, база, агент на роботе. Держать его в tmux на проде — сессия оборвётся, никто не поднимет, логи размажутся. Супервизор (на большинстве дистрибутивов **systemd**) стартует при загрузке, ловит падения, тянет зависимости вроде «сначала файловые системы», пишет журнал.

Вы описываете желаемое: включена, выключена, Restart=on-failure. Не ваш login, а **сервисный UID**, явные WorkingDirectory, Environment, лимиты — иначе снова «в терминале работает». Современные unit'ы хотят программу **на переднем плане**: не самодемонизация, супервизор сам сторожит PID.

Обновили бинарник — `restart`. Конфиг в `/etc` — иногда `reload`, если программа умеет без обрыва клиентов. Документация сервиса важнее общего совета.

Зависимость «After=network» — локальная подсистема, не «интернет в облаке жив». Сокет-активация и таймеры — позже; сначала модель «долгоживущий процесс под нянькой».

stdout/stderr часто забирает journald. Свои файлы в `/var/log` — тогда ротация и права на вас.

```bash
systemctl status ssh 2>/dev/null || systemctl status sshd 2>/dev/null || true
systemctl list-units --type=service --state=running | head
systemctl cat cron 2>/dev/null || systemctl cat crond 2>/dev/null || true
```

`status` — жив ли, с какого момента, хвост журнала. `cat` — контракт: ExecStart, User, Restart.
