# Сеть на хосте Linux

Карта (или виртуальный NIC) в ядре — **интерфейс**: `eth0`, `ens33`, `wlan0`, `lo`. Адрес, UP/DOWN, счётчики. `lo` — разговор с собой. Адреса и маршруты держит ядро; смотреть и менять — `ip` (iproute2). Старые `ifconfig`/`route` ещё живы в инструкциях 2012 года.

Маршрут по умолчанию — куда слать «остальной мир». Без него только прямо подключённая сеть. DNS на хосте — резолвер (`/etc/resolv.conf` или systemd-resolved), не «интернет как понятие». Firewall может слушать службе порт, но пакет не пустить: два разных вопроса.

Диагностика режет жалобу «сеть не работает»:

1. Есть адрес на интерфейсе?
2. Есть маршрут?
3. Сосед отвечает (ping, если не режут ICMP)?
4. Имя резолвится?
5. `ss -lntp` — процесс слушает порт?
6. Фильтр пускает?

Контейнер и облако — те же команды, другой namespace. Сначала таблица маршрутов **этого** ns.

Приложение открывает сокет; ядро выбирает маршрут и интерфейс. `ss` отвечает «кто слушает», `ip route` — «куда уйдёт пакет».

```bash
ip -br addr
ip route
ss -lntp | head
```

Не лечите DNS правкой приложения, пока `getent hosts` уже врёт. Не считайте ping истиной: его могут запретить при живом TCP.

Полный стек IP/TCP — раздел сетей; здесь вы врач хоста.

## Практика

### Задание 1. Адрес и шлюз

Снимите `ip addr` и `ip route`. Какой интерфейс в default route? Что будет без него для запроса в интернет?

### Задание 2. Слушает ли

Служба «не доступна снаружи». Чем `ss -lntp` отличается от ping? Два разных отказа.

### Задание 3. DNS

IP пингуется (или TCP открыт), имя нет. Где на хосте искать резолвер и почему приложение «тоже не резолвит»?

### Задание 4. Фильтр

Процесс слушает `0.0.0.0:8080`, с другой машины таймаут. Какие два слоя кроме «код сервиса» проверить?
