# Пакетные менеджеры

Пакет — файлы плюс имя, версия, зависимости, скрипты установки. Менеджер (apt, dnf, zypper, pacman) берёт **репозиторий** (обычно подписанный), считает транзакцию, раскладывает по FHS, помнит учёт. Обновления безопасности идут тем же каналом.

Разбросать бинарник в `/usr/local` можно. Тогда обновления, откат и «какой пакет владеет файлом?» — на вас. Смешали с файлами rpm/deb — менеджер затрёт или откажется.

Перед confirm читайте план: снятие «лишней» библиотеки утягивает полрабочего стола. Pinning/freeze — чтобы прод не уехал на «последнюю с GitHub» без changelog.

Слои поверх: pip, npm, snap — другие задачи. Демон дистрибутива ставьте пакетом дистрибутива, своим пакетом или контейнером с политикой, не `sudo pip install` в системный Python.

```bash
# Debian/Ubuntu: кто владеет файлом
dpkg -S /bin/ls 2>/dev/null || true
# Fedora: rpm -qf /bin/ls
```

Индекс метаданных устарел — «пакета нет» при том, что в docs он есть. Сначала обновить индекс, потом ставить.
