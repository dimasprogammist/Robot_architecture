# Строки

## Цель

Понять str как неизменяемые Unicode-последовательности.

Безопасно создавать, нарезать и собирать текст.

## Что уже пройдено

Вы знаете карту базовых типов.

Строка — первый подробный контейнер-последовательность.

## Объяснение с нуля

`str` хранит текст как последовательность code points. Строки **неизменяемы**: методы возвращают новые объекты.

Литералы в кавычках; f-string — интерполяция; r-string — сырой текст. Индексы и срезы как у последовательностей.

Склейка многих кусков — через список + `join`, не через `+` в длинном цикле. На границе I/O: `str` внутри, `bytes` снаружи, `encode`/`decode` — мост.

## Термины

- **str** — неизменяемая текстовая последовательность.

- **Срез**.

- **f-string / r-string**.

- **bytes**.

- **encode / decode**.

- **join**.

- **Unicode code point**.

## Внутреннее устройство

Объект str содержит буфер представления. Неизменяемость позволяет разделять и иногда интернировать литералы.

Сложение выделяет новый объект и копирует данные — отсюда цена `+=` в цикле.

Индексация возвращает str длины 1. Методы лежат в type object.

## Пример

```python

name = "Ana"

msg = f"Hello, {name}!"

parts = ["a", "b", "c"]

print(msg[0:5], msg[-1])

print("-".join(parts))

print(msg.replace("Ana", "Bob"))

print(name)

```

## Разбор

f-string, срезы и replace создают новые объекты; `name` прежний.

join — предпочтительная сборка. Индекс -1 — последний символ.

## Ошибки

- `s[0] = 'A'` — нельзя.

- Склеивать тысячи кусков через `+`.

- Путать str и bytes.

- Неверная кодировка при decode.

- Считать len всегда равным «буквам на экране» для сложных графем.

## Что запомнить

Строки неизменяемы.

Сборка — join/список кусков.

I/O: помните str vs bytes.
