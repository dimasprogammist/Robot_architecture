# Итераторы

## Цель

Явно понять протокол __iter__/__next__.

Связать for, генераторы и пользовательские итераторы.

## Что уже пройдено

Вы пользовались for и генераторами.

Общий протокол — ниже сахара.

## Объяснение с нуля

Iterable отдаёт iterator через __iter__. Iterator отдаёт элементы через __next__ и бросает StopIteration. for — сахар над протоколом.

Список итерируем: каждый for — новый итератор. Генератор уже итератор. Свой класс реализует протокол при особой стратегии обхода; часто хватает yield.

## Термины

- **Iterable / Iterator**.

- **StopIteration**.

- **Протокол**.

- **Одноразовость**.

- **iter / next**.

- **Контейнер vs iterator**.

- **FOR_ITER** (обзорно).

## Внутреннее устройство

Байткод FOR_ITER работает с итератором.

Изменение коллекции во время обхода опасного итератора списка — плохая идея.

## Пример

```python

class CountDown:

    def __init__(self, n):

        self.n = n

    def __iter__(self):

        return self

    def __next__(self):

        if self.n <= 0:

            raise StopIteration

        self.n -= 1

        return self.n + 1

print(list(CountDown(3)))

```

## Разбор

Класс сам себе итератор. list потребляет next до StopIteration.

Тот же смысл короче через yield; класс показывает протокол явно.

## Ошибки

- Путать iterable и iterator.

- Только __next__ без __iter__.

- Менять список во время итерации.

- Бесконечный __next__ без контракта.

## Что запомнить

for = iter + next до StopIteration.

Генераторы — удобные итераторы.

Iterable не всегда сам iterator.
