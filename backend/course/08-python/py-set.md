# Множества

## Цель

Освоить set как коллекцию уникальных хешируемых элементов.

Понять быстрый `in` и операции над наборами.

## Что уже пройдено

Вы знаете кортежи и хешируемость.

Множество опирается на ту же идею хеша.

## Объяснение с нуля

Множество хранит уникальные элементы без пользовательски значимого порядка. Литерал `{1,2,3}`; пустое — только `set()`, потому что `{}` — dict.

Операции: add, удаление, `in`, union/intersection/difference. Средний `in` быстрее линейного поиска по списку — зачем множества и нужны.

Элементы хешируемы. Изменяемый set сам нехешируем; есть `frozenset`. Модель: уникальность id, тегов, разница списков прав.

## Термины

- **set / frozenset**.

- **Хеш-таблица**.

- **add / discard / remove**.

- **union / intersection / difference**.

- **Уникальность**.

- **Пустой литерал `set()`**.

- **Коллизия хешей** (упрощённо).

## Внутреннее устройство

Внутри — хеш-таблица, родственная dict. Элемент в корзине по хешу; равенство разрешает коллизии.

Только стабильно хешируемые объекты. Методы update меняют на месте; `|` `&` `-` создают новые. Нельзя мутировать set во время for по нему.

## Пример

```python

allowed = {"read", "write"}

requested = {"write", "delete", "read"}

print(requested & allowed)

print(requested - allowed)

allowed.add("execute")

print("delete" in allowed)

```

## Разбор

Пересечение — общие права; разность — лишний `delete`.

`in` использует хеш. На больших данных это заметно быстрее списка.

## Ошибки

- `{}` как пустой set.

- Класть list или set в set.

- Полагаться на порядок обхода.

- remove без нужды вместо discard.

- Мутация во время итерации.

## Что запомнить

Множество = уникальность + быстрый in.

Элементы хешируемы.

Пустое — set().
