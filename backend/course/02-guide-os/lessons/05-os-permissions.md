# Права доступа

Файл лежит на диске, путь известен — и всё равно «отказано в доступе». Это не каприз проводника. Ядро на каждом открытии спрашивает: **кто** просит и **что** ему можно с этим объектом.

«Кто» — не фамилия в паспорте, а учётная запись, от имени которой работает процесс: пользователь и группы. «Что можно» — читать, писать, запускать; для каталога «запускать» обычно значит войти внутрь и пройти по пути. Без права пройти каталог не поможет «у файла внутри как будто чтение есть».

Зачем это новичку: программа робота, запущенная «как удобно, от администратора», может стереть систему так же легко, как свой лог. Запущенная от отдельного служебного пользователя — испортит в худшем случае свои файлы.

Права проверяет ядро, не ваша строка `if`. Обойти проверку из обычной программы штатно нельзя: нет системного вызова «запиши несмотря ни на что», если политика запретила. Администратор (root, SYSTEM) как раз и есть учётная запись с почти полной свободой — поэтому ею не живут «на каждый чих».

Общий файл команды: владелец, группа, остальные. Секрет ключа API — только владелец службы, не «все могут читать». Слишком широкие права «чтобы заработало» — дыра, которую потом забывают закрыть.

На Windows модель другая по деталям (ACL длиннее), смысл тот же: субъект, объект, разрешённые действия. Не учите биты Linux как единственную вселенную, учите вопрос «кто и что».

## Практика

### Задание 1. Каталог закрыт

Каталог вам нельзя обходить, файл внутри «для всех на чтение». Почему `открыть путь/к/файлу` падает? Что проверяют раньше — файл или каждый кусок пути?

### Задание 2. Запуск от себя

Скрипт пишет конфиг в каталог, который принадлежит системе. Под вашим обычным пользователем — отказ, «под админом» — успех. Почему второй путь опасен как привычка, даже если «так проще»?

### Задание 3. Секрет

Файл с паролем читается любой программой на машине. Какая мысль про права здесь сломана? Кто должен быть владельцем?

### Задание 4. Не программа решает

Человек говорит: «в коде же нет проверки пароля на файл, значит защита слабая». Где на самом деле живёт запрет, если файл открывают через ОС?

Дальше кто такие «пользователь» и «группа» как объекты системы, не как люди в чате.
