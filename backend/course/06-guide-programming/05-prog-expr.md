# Выражения

## Цель

Научиться читать и составлять выражения — фрагменты программы, которые **вычисляются в значение**. После урока вы сможете разбирать сложную формулу на части, понимать порядок вычисления и отличать выражение от инструкции-приказа.

## Что уже пройдено

У вас есть переменные и типы. Выражение объединяет значения, переменные и операции в одно вычисляемое целое: из уже известных данных получается новое значение, которое можно сохранить, сравнить или передать дальше.

## Объяснение с нуля

Выражение — это вопрос к программе: «чему равно вот это?» Примеры: `3 + 4`, `speed * dt`, `count > 0`, `name + "-v2"`. У каждого выражения есть результат определённого типа (число, логическое, строка и т.д.).

Инструкция (statement) — это приказ: «сделай». Присваивание `x ← 3 + 4` содержит выражение справа и действие «записать в x». Печать, цикл, объявление функции — тоже инструкции. Путаница возникает, когда человек ждёт «результата» от конструкции, которая ничего не возвращает, а только меняет мир.

Выражения бывают простыми (литерал, имя переменной) и составными (с операторами и вызовами функций). Составное выражение вычисляется по правилам: сначала внутренние части, потом внешние — с учётом приоритета операций и скобок.

Скобки — ваш друг. Даже если приоритет «очевиден» автору, читателю `(a + b) * c` яснее, чем полагаться на память таблицы приоритетов. В условиях особенно полезно группировать логические части явно.

Побочные эффекты внутри выражений (изменение переменной прямо в формуле) усложняют чтение. На этапе обучения лучше: сначала вычислить, потом присвоить или вызвать отдельной инструкцией. Так легче отлаживать.

Выражения бывают арифметическими, строковыми, логическими, сравнительными. Смешивать их можно только там, где тип результата осмыслен. Условие цикла или ветвления почти всегда ждёт логическое выражение (или значение, которое язык умеет трактовать как истину/ложь — с такими правилами будьте осторожны).

Цепочки вроде `h(g(f(x)))` — тоже выражения: результат внутреннего вызова становится аргументом внешнего. Это подготовка к функциям и возврату значений.

Промежуточные имена для подвыражений — не слабость, а ясность: вместо одной непрозрачной строки три понятных. Отладка потом благодарит.

## Термины

- **Выражение** — конструкция, вычисляемая в значение.
- **Операнд** — значение, участвующее в операции.
- **Оператор** — символ или слово операции (`+`, `и`, `>`).
- **Приоритет** — порядок выполнения операций без скобок.
- **Ассоциативность** — направление группировки операций одного приоритета.
- **Побочный эффект** — изменение состояния помимо получения результата выражения.

## Внутреннее устройство

Компилятор или интерпретатор строит для выражения **дерево вычисления**: листья — литералы и переменные, узлы — операции. Затем обходит дерево, получая промежуточные результаты. Для `(a + b) * c` сначала сумма, потом умножение.

На уровне процессора это превращается в последовательность загрузок, арифметических инструкций и сохранений во временные ячейки или регистры. Вам не нужно писать это вручную, но полезно помнить: каждое подвыражение «стоит» работы.

Короткое замыкание логики (`и` / `или`) — важная деталь: если левая часть уже определяет результат, правую могут не вычислять. Поэтому нельзя бездумно класть в правую часть обязательные действия. Лучше побочные эффекты выносить из логических выражений.

Ошибки типов часто всплывают именно при вычислении выражения: сложили несовместимое, разделили на ноль, вызвали операцию у «пустого» значения. Выражение — точка, где контракт типов проверяется на практике.

Порядок вычисления аргументов функции в разных языках может отличаться; поэтому аргументы с побочными эффектами — плохая привычка. Явные промежуточные переменные делают порядок очевидным.

## Пример

```text
Дано:
  distance ← 100
  time_s   ← 20
  limit    ← 4.0

Выражения:
  speed ← distance / time_s          # 5.0
  ok    ← (speed <= limit) И (time_s > 0)

Разбор ok:
  1) time_s > 0      → true
  2) speed <= limit  → 5.0 <= 4.0 → false
  3) false И true    → false

# Python-иллюстрация:
distance = 100
time_s = 20
speed = distance / time_s
ok = (speed <= 4.0) and (time_s > 0)
```

## Разбор

Сначала вычисляется `distance / time_s` — арифметическое выражение, результат вещественный. Затем сравнения дают логические значения. Затем логическое `И` собирает итог.

Скобки вокруг сравнений не всегда обязательны по приоритету, но делают намерение явным: мы сравниваем, потом комбинируем. Если убрать проверку `time_s > 0`, алгоритм станет хрупче: деление на ноль возможно на другом наборе данных.

Итог `ok = false` — не «ошибка программы», а осмысленный результат выражения. Программа должна решить, что делать с `false` (ветвление — следующий большой блок темы после операторов).

Разбор подвыражений слева направо (с учётом скобок) — навык, который переносится в любой язык. Когда формула «врёт», разбейте её на именованные куски.

## Ошибки

- Писать длинную формулу без скобок и удивляться порядку операций.
- Смешивать сравнение и присваивание в уме и в коде.
- Класть обязательные действия внутрь логического выражения с коротким замыканием.
- Считать, что выражение «что-то делает само», если результат никуда не записали и не использовали.
- Игнорировать тип результата: сравнивать строки там, где ждали числа.

## Что запомнить

Выражение вычисляется в значение; инструкция — приказ. Приоритет и скобки задают порядок. Логические выражения питают условия. Побочные эффекты в формулах усложняют жизнь. Дерево вычисления — внутренняя модель любой формулы.

## Задание

Разберите выражение `(n > 0) И (total / n >= threshold)` для `n=4`, `total=20`, `threshold=4.5`. Выпишите результаты каждого подвыражения по шагам. Затем повторите для `n=0` и объясните, какая проблема возникает и как её избежать порядком проверок.
