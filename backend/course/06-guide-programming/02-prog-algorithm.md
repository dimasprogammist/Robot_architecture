# Алгоритм

## Цель

Научиться формулировать алгоритм как конечную последовательность шагов с ясным началом, правилами перехода и критерием окончания. После урока вы сможете отличать алгоритм от расплывчатого совета и проверять его на простых примерах до написания кода.

## Что уже пройдено

Вы знаете, что программа — это запись плана для исполнителя: вход, обработка, выход. Алгоритм — мыслительная основа этого плана. Сначала появляется алгоритм (хотя бы в голове или на бумаге), потом — его запись на языке программирования.

## Объяснение с нуля

Алгоритм — способ решить задачу **по шагам**. Шаги должны быть достаточно мелкими, чтобы исполнитель не додумывал. Хороший алгоритм отвечает на вопросы: с чего начать, что делать дальше, когда остановиться, что считать ответом.

Классические свойства полезного алгоритма:

1. **Дискретность** — работа разбита на отдельные шаги.
2. **Понятность** — каждый шаг однозначен для выбранного исполнителя.
3. **Конечность** — работа завершается за конечное число шагов (или явно описан режим «ждём событие»).
4. **Результативность** — есть понятный результат или понятный отказ.
5. **Массовость** — алгоритм годится не для одного числа, а для класса похожих входов.

Не любой список действий — алгоритм. «Будь умным и найди ошибку» — не алгоритм. «Пройди строки файла с первой до последней; если строка пустая — пропусти; иначе увеличь счётчик» — уже ближе к алгоритму.

Алгоритмы бывают линейными (шаги строго друг за другом), с ветвлением (выбор по условию) и с повторением (цикл). Почти любая реальная программа сочетает все три формы. Позже вы увидите это в операторах условий и циклах; сейчас важно уметь рисовать логику без синтаксиса.

Алгоритм можно записать словами, блок-схемой, псевдокодом. Форма записи — инструмент общения. Псевдокод особенно удобен: он похож на код, но не привязан к языку, поэтому команда может спорить о логике, а не о скобках.

Почему алгоритм важнее «сразу писать код»: ошибки в идее дороже ошибок в синтаксисе. Если алгоритм неверен, идеальный код всё равно даст неверный ответ. Если алгоритм верен, синтаксис языка — лишь перевод.

В инженерии алгоритм часто сначала появляется как словесный протокол: «при низкой батарее снизить скорость, при аварии — стоп». Пока протокол дырявый, код только закрепит дыры.

## Термины

- **Алгоритм** — конечное описание способа решения задачи.
- **Псевдокод** — запись алгоритма «почти как код», без жёстких правил языка.
- **Блок-схема** — графическое представление шагов и переходов.
- **Ветвление** — выбор следующего шага по условию.
- **Итерация** — один проход тела цикла.
- **Инвариант** — свойство, которое остаётся истинным на каждом шаге (полезно для проверки циклов).

## Внутреннее устройство

Когда алгоритм превращают в программу, каждый шаг становится одной или несколькими инструкциями. Условие «если x > 0» превращается в сравнение и переход. Цикл «пока есть элементы» превращается в проверку, тело и возврат к проверке.

Компьютер не «видит» вашу блок-схему. Он видит только инструкции и адреса переходов. Поэтому качество алгоритма проверяют **до** запуска: прогоняют на бумаге с маленькими входами, ищут крайние случаи (пустой список, ноль, отрицательные числа, слишком большие значения).

Сложность алгоритма — отдельная тема: сколько шагов и сколько памяти нужно при росте входа. На этом этапе достаточно интуиции: двойной проход по списку обычно дороже одного; искать элемент в неупорядоченном списке в худшем случае значит посмотреть все элементы.

Алгоритм и данные связаны. Один и тот же алгоритм «найти максимум» работает для списка чисел; для пустого списка нужно заранее решить: ошибка, особое значение или запрет такого входа. Эти решения — часть алгоритма, а не «потом в коде разберёмся».

Прогон «таблицей состояния» — мощный приём: колонки — переменные, строки — шаги. Если не можете заполнить таблицу, алгоритм ещё сырой.

## Пример

```text
Задача: найти наибольшее число в списке.

Алгоритм (псевдокод):
  ЕСЛИ список пуст:
    СООБЩИТЬ об ошибке и ОСТАНОВИТЬСЯ
  max ← первый элемент списка
  ДЛЯ каждого оставшегося элемента x:
    ЕСЛИ x > max:
      max ← x
  ВЕРНУТЬ max

Прогон:
  вход: [4, 1, 9, 2]
  старт: max = 4
  x=1 → 1 > 4? нет
  x=9 → 9 > 4? да → max = 9
  x=2 → 2 > 9? нет
  ответ: 9
```

## Разбор

Алгоритм явно обрабатывает пустой список — это не мелочь, а защита от бессмысленного состояния «максимум неизвестен». Начальное значение `max` берётся из первого элемента, а не из нуля: иначе для списка отрицательных чисел ответ был бы неверным.

Цикл «для каждого оставшегося» гарантирует конечность: список конечен, каждый элемент посещается один раз. Условие `x > max` — единственная точка принятия решения; остальное — движение по данным.

Тот же алгоритм можно реализовать на любом языке. Синтаксис изменится, логика — нет. Именно поэтому модуль начинается с алгоритмов, а не с синтаксиса Python.

Проверьте сами крайние случаи: один элемент; все равны; убывающая последовательность. Если ответы совпадают с ожиданием — идея крепкая.

## Ошибки

- Писать шаги вроде «обработать данные красиво» без критерия.
- Забывать крайние случаи: пустой вход, один элемент, все элементы равны.
- Путать порядок шагов: инициализация после использования, проверка после изменения.
- Создавать алгоритм, который может зациклиться без условия выхода.
- Сразу оптимизировать «красиво», не проверив правильность на простых примерах.

## Что запомнить

Алгоритм — конечные однозначные шаги решения. Его можно записать псевдокодом до выбора языка. Ветвления и циклы — базовые формы управления. Крайние случаи — часть алгоритма. Верная идея важнее раннего синтаксиса.

## Задание

Составьте алгоритм «посчитать, сколько положительных чисел в списке». Запишите псевдокод, затем вручную прогоните на входах: `[]`, `[0, -1]`, `[3, -2, 5, 0]`. Для каждого укажите ожидаемый ответ.

## Связь со следующим уроком

Чтобы алгоритм хранил промежуточные результаты (`max`, счётчики, флаги), нужны **переменные** — именованные места для значений во время выполнения.
