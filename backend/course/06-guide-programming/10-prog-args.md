# Аргументы

## Цель

Понять, как данные передаются в функцию: параметры как «входы по именам», аргументы как конкретные значения при вызове. После урока вы будете различать позиционные и именованные аргументы и не путать внешнюю переменную с параметром внутри функции.

## Что уже пройдено

Функция — именованный блок шагов. Чтобы блок был универсальным, ему нужны входы. Без аргументов функция либо работает с глобальным состоянием (хрупко), либо всегда делает одно и то же.

## Объяснение с нуля

**Параметр** — переменная в объявлении функции, дырка для входа. **Аргумент** — значение, которое вы подставляете при вызове. В объявлении `ФУНКЦИЯ add(a, b)` имена `a` и `b` — параметры. В вызове `add(2, 3)` числа `2` и `3` — аргументы.

Соответствие обычно идёт по порядку (позиционно): первый аргумент → первый параметр. Многие языки позволяют и именованную передачу: `add(b=3, a=2)` — тогда порядок не важен, важны имена. Именованность улучшает читаемость при большом числе входов.

Аргументы бывают обязательными и со значениями по умолчанию. Значение по умолчанию — удобный «обычный случай», но его легко превратить в скрытую магию. Документируйте смысл умолчаний.

Передача по значению vs по ссылке (упрощённо): иногда функция получает копию числа и, меняя параметр, не трогает внешнюю переменную; иногда получает доступ к тому же составному объекту и может изменить его содержимое. На практике всегда спрашивайте: «изменит ли вызов мои данные снаружи?» Если да — это должно быть частью контракта функции, а не сюрпризом.

Число аргументов должно совпадать с ожиданиями объявления (с учётом умолчаний). Лишний или недостающий аргумент — ранняя ошибка, часто ещё до полезной работы функции.

Хороший тон: немного параметров. Если входов десять, возможно, их стоит сгруппировать в структуру. Длинный список аргументов — признак, что граница функции выбрана грубо.

Контракт функции стоит формулировать явно: что обязательно на входе, что считается ошибкой, что вернётся. Аргументы — левая половина этого контракта.

Единицы измерения тоже часть контракта аргументов: скорость в м/с или в долях от максимума? Если это не сказано, два инженера подставят разные числа и оба будут «правы» по синтаксису.

Именованные аргументы особенно полезны, когда подряд идут несколько чисел одного типа: без имён легко перепутать порядок и долго искать логическую ошибку.

## Термины

- **Параметр** — имя входа в объявлении.
- **Аргумент** — фактическое значение при вызове.
- **Позиционный аргумент** — передаётся по порядку.
- **Именованный аргумент** — передаётся по имени параметра.
- **Значение по умолчанию** — что взять, если аргумент не передали.
- **Контракт функции** — ожидания по входам, выходам и побочным эффектам.

## Внутреннее устройство

В момент вызова вычислитель сначала вычисляет выражения-аргументы, затем связывает их с параметрами в кадре функции. Вызов `f(x + 1, g())` сначала получит значения подвыражений, и только потом войдёт в `f`.

Порядок вычисления аргументов в языках стандартизирован по-разному; поэтому аргументы с побочными эффектами — плохая практика. Лучше вычислить промежуточные переменные отдельными строками.

Для неизменяемых простых значений изменение параметра внутри не видно снаружи. Для разделяемых структур запись в поле может быть видна вызывающему. Это не «баг языка», а модель данных: вы передали доступ к общей памяти.

Проверка типов аргументов (статическая или динамическая) — часть защиты контракта. Передали строку вместо числа — лучше узнать сразу, чем получить странный результат через десять строк тела.

Параметры живут в области видимости функции: снаружи одноимённая переменная — другая сущность. Это мост к следующему уроку про scope после возврата значений.

## Пример

```text
ФУНКЦИЯ limited_speed(cmd, battery, reserve=15):
  # reserve — порог батареи по умолчанию
  ЕСЛИ battery < reserve:
    ВЕРНУТЬ 0.0
  ВЕРНУТЬ clamp(cmd, 0.0, 1.0)

Вызовы:
  limited_speed(0.8, 40)           # reserve = 15 → вернёт 0.8
  limited_speed(0.8, 10)           # battery низкий → 0.0
  limited_speed(0.8, 40, 50)       # свой порог 50 → 0.0
  limited_speed(cmd=0.8, battery=40, reserve=20)

Внешние переменные:
  cmd ← 0.8
  bat ← 40
  out ← limited_speed(cmd, bat)    # cmd снаружи не обязан измениться
```

## Разбор

Параметры `cmd` и `battery` делают функцию пригодной для разных вызовов. Умолчание `reserve=15` фиксирует типичную политику, но третий аргумент позволяет ужесточить порог без правки тела.

Именованный вызов читается как документация прямо в месте использования. Для двух-трёх очевидных чисел позиционный стиль нормален; для «похожих» чисел подряд имена спасают от перестановки.

Важно: даже если снаружи есть переменная `cmd`, внутри функции параметр `cmd` — своя привязка в кадре. Перестановка `limited_speed(40, 0.8)` позиционно дала бы бессмыслицу — ещё один аргумент за имена.

Цепочка `clamp` внутри показывает композицию: функция принимает аргументы и передаёт часть из них дальше.

## Ошибки

- Путать имена параметров с внешними переменными «с тем же словом».
- Переставлять позиционные аргументы местами молча.
- Раздувать список аргументов вместо структуры.
- Модифицировать составной аргумент и удивляться, что снаружи данные изменились.
- Прятать критичные настройки только в молчаливых умолчаниях без пояснения.

## Что запомнить

Параметр — дырка в объявлении, аргумент — значение при вызове. Позиционные и именованные способы передачи решают одну задачу: связать входы. Умолчания удобны, но должны быть явными по смыслу. Контракт функции включает, меняет ли она переданные данные. Сначала вычисляются аргументы, потом выполняется тело.
