# Алгоритм

Алгоритм — способ решить задачу **по шагам**, достаточно мелким, чтобы исполнитель не додумывал: с чего начать, что дальше, когда стоп, что ответ. Программа — уже запись; сначала идея (хотя бы на бумаге).

Полезные свойства: дискретность, однозначность для выбранного исполнителя, конечность (или явно «ждём событие»), результат или отказ, массовость — класс входов, не одно число. «Будь умным» — не алгоритм. «Иди по строкам; пустую пропусти; иначе увеличь счётчик» — ближе.

Линейные шаги, ветка, цикл: живая программа мешает все три. Форма записи — слова, схема, псевдокод. Псевдокод спорит о логике, не о скобках. Ошибка в идее дороже синтаксиса: идеальный код неверного плана врёт. В инженерии сначала протокол «низкая батарея — тише, авария — стоп»; дырявый протокол код только бетонирует.

Не любой чеклист конечен: «пока не понравится» без критерия — не алгоритм. Режим сервера конечен **на один запрос**, петля ожидания описана отдельно.

```text
счётчик ← 0
для каждой строки файла:
  если строка не пустая:
    счётчик ← счётчик + 1
выдать счётчик
```

Прогоните руками на трёх строках, одна пустая — до кода. Если на бумаге уже враньё, Python не спасёт.

## Практика

### Задание 1. Не совет

Перепишите «разберись с ошибкой на стенде» в шаги с началом, веткой и критерием конца. Где ещё дыра?

### Задание 2. Ручной прогон

Алгоритм счётчика непустых строк. Вход: `"a"`, `""`, `"b"`. Значение счётчика после каждой строки.

### Задание 3. Конечность

«Крути, пока датчик врёт». Почему это не алгоритм без таймаута или счётчика попыток? Добавьте стоп.

### Задание 4. Массовость

Алгоритм только для числа 7. Что добавить, чтобы он работал для любого целого в диапазоне? Зачем это свойство раньше кода?

Дальше где шаги держат промежуточное: **переменная**.
