# Возврат значения

## Цель

Научиться проектировать функции, которые отдают результат через возврат, а не только «что-то делают внутри». После урока вы будете понимать, чем возврат отличается от печати, и как строить цепочки вычислений из возвращаемых значений.

## Что уже пройдено

Аргументы подают данные внутрь функции. Возврат — обратный канал: функция завершается и отдаёт значение туда, где её вызвали. Вместе вход и выход образуют контракт «данные → данные».

## Объяснение с нуля

Возврат значения — способ сказать: «результат этой работы вот он». В псевдокоде это `ВЕРНУТЬ выражение`. Вызов функции в правой части присваивания забирает этот результат: `y ← f(x)`.

Важные свойства:

1. **Завершение**: возврат обычно сразу заканчивает выполнение тела функции (дальнейшие строки не выполняются).
2. **Одно место результата** для вызывающего: он получает значение и решает, сохранить, сравнить или передать дальше.
3. **Отличие от вывода**: печать показывает человеку, но не даёт программе значение для дальнейших вычислений. Отладочная печать ≠ возврат.

Функция может иметь несколько точек возврата: в разных ветках вернуть разные ответы. Это нормально, если ветки покрывают случаи. Альтернатива — одна переменная `result`, которую заполняют, и один `ВЕРНУТЬ result` в конце; стиль выбирайте ради ясности.

Что возвращать при ошибке? Варианты: специальное значение, пара `(ok, value)`, исключение (урок позже), тип «результат или ошибка». Главное — не молчать: вызывающий должен уметь отличить успех от провала.

Функции без возврата (процедуры) тоже нужны: сохранить файл, отправить команду. Но если цель — вычислить число, логический флаг, новую строку, возврат предпочтительнее глобальных переменных.

Возврат нескольких значений языки оформляют по-разному: кортеж, структура, out-параметры. Концептуально это «вернуть составной результат». Не бойтесь завести маленькую структуру, если пара чисел без имён начинает путаться.

Ранний возврат удобен для охраны предусловий: «если вход плохой — сразу вернуть сигнал ошибки», не утапливая основную логику в `иначе`.

## Термины

- **Возврат (return)** — завершение функции с передачей значения наружу.
- **Возвращаемое значение** — то, что получает место вызова.
- **Процедура** — функция, ориентированная на действие без полезного результата (условно).
- **Чистая функция** — результат зависит только от аргументов, без скрытых эффектов (идеал).
- **Код возврата** — иногда числовой статус успеха/ошибки (особенно в системных утилитах).
- **Ранний возврат** — выход из функции при первой возможности.

## Внутреннее устройство

На стеке вызовов возвращаемое значение передаётся согласованным способом: через регистр, стек, временный объект. Для вас важно другое: после возврата локальные переменные функции исчезают вместе с кадром. Единственное, что гарантированно «выживает» из локального мира — то, что вы вернули (и то, что намеренно записали во внешние объекты).

Если вернуть ссылку на локальные данные в языках с ручной памятью, можно получить висячий указатель — продвинутая ловушка. В управляемых языках модель проще, но идея та же: ясно понимайте время жизни данных.

Цепочка `h(g(f(x)))` вычисляется изнутри: сначала `f`, его результат идёт в `g`, затем в `h`. Это композиция функций — мощный способ собирать алгоритмы из кирпичиков.

Забыли `ВЕРНУТЬ` в одной из веток — вызывающий может получить неявную пустоту. Проверяйте все пути выхода из функции.

## Пример

```text
ФУНКЦИЯ average(numbers):
  ЕСЛИ длина(numbers) == 0:
    ВЕРНУТЬ NOTHING      # явный сигнал "нет среднего"
  sum ← 0
  ДЛЯ каждого x в numbers:
    sum ← sum + x
  ВЕРНУТЬ sum / длина(numbers)

Использование:
  mean ← average([2, 4, 6])     # 4.0
  ЕСЛИ mean == NOTHING:
    сообщить("пустой список")
  ИНАЧЕ:
    использовать mean дальше

Печать ≠ возврат:
  ФУНКЦИЯ bad(numbers):
    print(average(numbers))     # показал, но вернул пусто
  # y ← bad(...)  не даст среднее в y

# Python-иллюстрация:
def average(numbers):
    if len(numbers) == 0:
        return None
    return sum(numbers) / len(numbers)
```

## Разбор

Ранний возврат для пустого списка делает контракт честным: среднего не существует. Вызывающий обязан обработать `NOTHING`. Это лучше, чем тихо вернуть `0` и спутать с реальным средним набора нулей: среднее нулей — ноль, пустой список — другая ситуация.

Тело накапливает `sum` локально. После `ВЕРНУТЬ` локальный `sum` не нужен снаружи — наружу уходит только частное.

Пример `bad` показывает частую путаницу новичков: увидеть число на экране и считать, что функция «вернула» его в алгоритм. Для связи шагов программы нужен именно возврат (или явная запись в общую структуру).

Композиция `print(average(...))` нормальна: сначала получили значение возвратом, потом напечатали. Путаница начинается, когда печать стоит *вместо* возврата.

## Ошибки

- Печатать результат вместо возврата и пытаться использовать его дальше.
- Возвращать «магические» числа ошибок без договорённости.
- Забывать return в одной из веток и получать неявный пустой результат.
- Считать, что локальные переменные доступны после выхода из функции.
- Делать функцию, которая и возвращает значение, и незаметно меняет глобальные флаги «на всякий случай».

## Что запомнить

Возврат отдаёт результат вызывающему и завершает функцию. Печать — для людей, возврат — для программы. Ранний возврат удобен для охраны входов. После выхода локальное состояние кадра исчезает. Композиция вызовов строит сложные вычисления из простых функций.
