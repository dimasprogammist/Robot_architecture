# Зачем помнить версии

## Цель

Понять, какую боль закрывает контроль версий, ещё до любой команды Git.

## Что уже пройдено

Вы умеете сохранять файлы. Для одного вечера этого хватает. Дальше нужна история состояний.

## Объяснение с нуля

Пока вы правите один текст и никогда не возвращаетесь, история не нужна. Трудность начинается, когда сегодняшняя версия сломала вчерашнюю, или два человека правят один абзац.

**Система контроля версий** хранит последовательность состояний проекта. Можно спросить: что изменилось, когда и зачем. Git — такая система. Это не сайт и не облачный диск: программа на компьютере работает с папкой проекта.

Без истории люди плодят копии: `проект_финал`, `проект_финал2`. Имена врут, сравнивать десять файлов глазами тяжело, вернуть один абзац — лотерея. Параллельная работа без общей модели приводит к перезаписи: чья-то правка исчезает. Эксперимент через копию всей папки размывает границу между «пробой» и «основной линией».

Git закрывает эти боли снимками. Коммит — снимок дерева файлов, а не папка «финал2». Разницу программа вычисляет, сравнивая снимки. Git не равен GitHub: сайт хранит копию, сам Git работает и офлайн.

## Термины

- **История** — упорядоченные сохранённые состояния.
- **Снимок** — целый вид дерева файлов в момент времени.
- **Репозиторий** — проект вместе с историей.
- **Git** — локальная программа со своей базой объектов.
- **Удалённая копия** — другой экземпляр истории (часто на сервере).

## Внутреннее устройство

Git мыслит снимками. Объекты появятся позже подробнее: **blob** (байты файла), **tree** (каталог имён → объекты), **commit** (метаданные + указатель на корневое tree + родители). Ветка — имя, указывающее на commit. Пока достаточно карты: история = граф снимков, рабочая папка = витрина текущего выбора.

## Пример

```text
снимок A: speed.txt → "40"
снимок B: speed.txt → "45"   (родитель: A)
сейчас на диске: "45"
```

Вернуться к A — выбрать другой снимок как основу витрины, а не искать `speed_old.txt`.

## Разбор

Снимок B не обязан хранить фразу «замени 40 на 45» как единственную правду. Он хранит состояние после правки и связь с A. Diff — производное. Поэтому модель «контроль версий = список патчей» для Git вторична.

## Ошибки

- Путать Git и GitHub.
- Думать, что Git понимает смысл кода — он знает байты и связи объектов.
- Считать «Сохранить» в редакторе попаданием в историю.
- Класть огромные бинарники как единственное хранилище истории.

## Что запомнить

Git чинит возврат, совместную работу и безопасный эксперимент через снимки. Команды имеют смысл только после этой модели.

## Задание

Запишите три состояния учебного файла, которые хотели бы восстановить через неделю. Это будущие снимки — без команд.

## Связь со следующим уроком

Дальше — конкретный провал без Git: копии, перезапись, потерянные правки.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
