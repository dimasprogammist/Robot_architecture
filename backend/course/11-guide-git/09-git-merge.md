# Слияние историй

## Цель

Понять merge как fast-forward или commit с двумя родителями.

## Что уже пройдено

Две ветки могут указывать на разные коммиты. Слияние соединяет линии.

## Объяснение с нуля

**Слияние** подтягивает одну линию в другую.

1. **Fast-forward** — конец целевой ветки — предок другой; достаточно передвинуть указатель, merge-коммит не обязателен.
2. **Merge commit** — линии разошлись; новый commit с двумя родителями и tree, собранным из обеих сторон (плюс конфликты, если автомат не справился).

Результат — одно дерево файлов. Родители помнят происхождение.

## Термины

- **Fast-forward** — перемотка указателя.
- **Merge commit** — ≥2 parents.
- **Базовый предок** — общий коммит до расхождения.
- **Ours/theirs** — стороны при конфликте (имена коварны).

## Внутреннее устройство

```text
main: A—B—C
feat: A—B—D—E
# merge feat → main:
…—C—M
…—E—┘  M.parents = C, E
```

## Пример

```bash
git switch main
git merge feat
```

## Разбор

Слияние строит снимок, а не «смешивает команды». Направление: быть на принимающей ветке и merge вливающую.

## Ошибки

- Всегда бояться merge-коммитов.
- Не смотреть получившееся дерево и тесты.
- Перепутать, что куда вливают.

## Что запомнить

Merge либо двигает указатель (FF), либо создаёт commit с двумя родителями.

## Задание

Сделайте расхождение и merge. В `git log --graph` найдите родителей (если не FF).

## Связь со следующим уроком

Дальше — rebase: перенос цепочки на новую базу с новыми хешами.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
