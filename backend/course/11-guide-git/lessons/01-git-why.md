# Зачем помнить версии

Пока вы правите один файл и никогда не возвращаетесь, истории не нужно. Она становится нужна в четверг, когда стенд «вчера работал», а в файле уже другой ток и другие обороты. Или когда два человека правят один абзац и побеждает последний, кто нажал «сохранить».

**Система контроля версий** хранит последовательность состояний проекта: что изменилось, когда, зачем. Git — такая система. Это программа на вашем компьютере и база рядом с проектом, не сайт и не облачный диск. GitHub — отдельный хостинг копии; Git работает и без сети.

Без истории плодят `проект_финал`, `проект_финал2`. Имена врут, сравнить десять копий глазами тяжело, вернуть один абзац — лотерея. Эксперимент копией всей папки размывает «проба» и «основа».

Git закрывает это **снимками**. Коммит — снимок дерева файлов плюс связь с предыдущим, не папка «финал2». Разницу программа считает сама. «Сохранить» в редакторе в историю не попадает: на диске черновик, в истории — только то, что зафиксировали.

Огромные бинарники как единственное хранилище версий Git переваривает плохо: он мыслит файлами и снимками, смысл кода не понимает.

```text
снимок A: speed.txt = "40"
снимок B: speed.txt = "45"  (родитель A)
на диске сейчас "45"
вернуться к A — выбрать другой снимок, не искать speed_old.txt
```

B хранит состояние и родителя. «Замени 40 на 45» как единственная правда не нужна: diff вычисляют.
