# Теги

**Тег** — имя на коммите, обычно неподвижное: `v1.2.0`. Ветка едет вперёд с каждым коммитом, тег остаётся на релизе. Annotated-тег — объект с сообщением и автором; lightweight — просто указатель.

Теги не уезжают сами на remote при обычном push — их шлют отдельно. Скачавший clone видит теги, которые были на сервере.

Двигать тег на другой коммит (`-f`) путает всех, кто уже собрал «эту версию». Лучше новый номер. Удаление тега локально не удаляет его на origin.

Тег не замена ветки разработки и не замена changelog. Это якорь: «вот снимок, который мы назвали релизом».

## Практика

### Задание 1. Ветка vs тег

Оба указывают на коммит. Что произойдёт с каждым после нового commit на этой линии?

### Задание 2. Push тегов

Почему на GitHub нет вашего `v0.1`, хотя локально `git tag` его показывает?

### Задание 3. Annotated

Зачем сообщение на теге, если коммит уже с сообщением?

### Задание 4. Force тега

Переставили `v1.0` на другой хеш. Кто сломается и почему лучше `v1.0.1`?

Дальше опасные движения указателя: reset.
