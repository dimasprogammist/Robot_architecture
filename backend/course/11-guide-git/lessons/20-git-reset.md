# Reset: двигать указатель

**Reset** двигает **текущую ветку** на другой коммит и по режиму трогает индекс и рабочее дерево.

- `--soft`: ветка уехала, индекс и файлы как были. Коммиты «исчезли» из log ветки, но их изменения всё ещё staged. Удобно склеить последний шаг.
- `--mixed` (по умолчанию): ветка и индекс как у целевого снимка, файлы на диске ещё с вашими правками. Изменения стали unstaged.
- `--hard`: ветка, индекс и дерево как у цели. Незакоммиченное **пропало** из этого дерева (reflog коммитов ещё может помнить сами коммиты).

Reset не «удаляет объекты сразу». Он переставляет имя ветки. Старые коммиты ищутся по хешу и reflog, пока сборщик не съест недостижимое.

Не делайте hard на коммитах, которые уже на общем remote, если не готовы к force. Не hard, если не уверены, что дерево можно выкинуть.

`reset` файла (`git reset путь`) — другое: убрать путь из индекса, не двигать ветку. Путают с `restore`.

### Задание 1. Три режима

Один лишний коммит. Чем soft отличается от mixed для следующего commit? Что делает hard с файлами?

### Задание 2. Не удаление

После `reset --hard HEAD~1` объект старого коммита сразу стёрт с диска? Где его ещё искать сутки?

### Задание 3. Путь vs ветка

`git reset HEAD файл` и `git reset --hard HASH` — какая команда не двигает ветку?
