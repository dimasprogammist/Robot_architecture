# Pull request

**Pull request (merge request)** — не объект Git, а заявка на хостинге: «возьмите эти коммиты в ту ветку». Под капотом сравнение двух указателей, diff, обсуждение, CI, кнопки merge/rebase/squash на сервере.

Ветка должна быть на remote. PR смотрит на обновления: новый push в ту же ветку дополняет заявку. Не открывают PR «из main в main» без расхождения.

Описание PR — зачем людям, не дамп `log`. Ревью читает diff, не ваши мысли в чате. Squash при merge склеивает историю на целевой ветке — локальные мелкие коммиты могут исчезнуть из `main`, но ветка-источник ещё у вас.

Конфликт на GitHub — тот же конфликт слияния: кто-то обновил цель, пока вы жили. Лечат локально (merge/rebase цели) и push.

Закрыть PR без merge — отказ. Удалить ветку после merge — уборка указателя, объекты ещё в истории `main`.
