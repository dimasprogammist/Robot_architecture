# Слияние

Две ветки разошлись. **Merge** создаёт коммит с **двумя** родителями: «здесь сошлись эти истории». Развилка в графе остаётся видимой. Это не переписывание старых хешей.

Fast-forward: ваша ветка просто отстаёт, чужих коммитов «сбоку» нет — Git двигает указатель вперёд без merge-коммита. Это тоже слияние по смыслу «подтянуть линию», но граф остаётся прямой.

Конфликт — когда обе линии тронули одно место по-разному. Git вставит маркеры в файл, индекс не завершит merge сам. Вы правите, add, `commit` (или `--continue`). Бросить — `merge --abort`.

```text
main:  A—B—C
feat:  A—B—D
merge на main: C и D → M (родители C и D)
```

```bash
git switch main
git merge feat
```

Смысл сообщений merge-коммита — зачем слили, не «merge branch». После публичного merge не переписывают общие коммиты rebase'ом без договорённости.
