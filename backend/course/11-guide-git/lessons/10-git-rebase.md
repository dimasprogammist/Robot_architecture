# Перенос линии (rebase)

Merge сохраняет развилку. **Rebase** говорит: возьми мои коммиты и повтори их поверх другого основания. На деле появляются **новые** объекты с новыми хешами. Старые ещё могут торчать в reflog.

```text
до:    main A—B—C
       feat A—B—D—E
после: feat A—B—C—D'—E'
```

D' и E' — другие коммиты, даже если патч похож: другой родитель.

Типичный сюжет: `feat` отстала от `main`, переносите шаги `feat` на новый конец `main`, чтобы потом слиться без лишнего узла. Линия в `log` прямее. Цена: все, кто уже взяли старые D и E, получат расхождение.

Правило: не rebase коммиты, которые уже на общем remote, без явной договорённости (и тогда часто нужен force-push — опасно). Локальную ветку, которую видели только вы — можно.

Конфликты на rebase идут **по каждому** переносимому коммиту. `--abort` возвращает ветку как было. `--continue` после add.

Интерактивный rebase (squash, перефразировать) — тот же механизм новых хешей плюс редактирование списка. Не путать с merge.
