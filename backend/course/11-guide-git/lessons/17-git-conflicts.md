# Конфликты

Конфликт — не поломка Git, а честный сигнал: автоматическое слияние не знает, какой текст оставить. Маркеры `<<<<<<<`, `=======`, `>>>>>>>` — границы двух (иногда трёх) сторон в файле.

Пока конфликт не разрешён, индекс в состоянии merge/rebase. `status` перечисляет unmerged. Исправить файл руками недостаточно: нужен `add`, затем завершение (`commit` / `--continue`).

Бинарники Git не склеивает строками — выбираете одну сторону. Удаление vs правка — отдельный сюжет: файл исчез в одной истории и изменён в другой.

Не коммитьте маркеры. Не «выбирайте всегда ours» без чтения. После разрешения прогоните смысл: робот с двумя половинами конфигов не едет.

`merge --abort` / `rebase --abort` — выход, если поняли, что рано было сливать.

## Практика

### Задание 1. Маркеры

Что между `<<<<<<<` и `=======`? Что после `=======`? Чего в файле не должно остаться после add?

### Задание 2. add

Почему исправленный файл всё ещё «оба изменили» в status, пока не add?

### Задание 3. Бинарь

Конфликт картинки. Какие варианты есть и какого «склеивания пикселей» Git не обещает?

### Задание 4. Abort

Вы в середине rebase, пять коммитов, второй конфликтует, смысла нет. Что делает abort с уже перенесёнными и с веткой?

Дальше что не должно попадать в снимки: ignore.
