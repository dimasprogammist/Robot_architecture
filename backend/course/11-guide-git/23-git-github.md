# Git и GitHub

## Цель

Разделить Git (модель снимков) и GitHub (хостинг + интерфейс вокруг remote).

## Что уже пройдено

Вы уже push/pull. Часто remote живёт на GitHub.

## Объяснение с нуля

**GitHub** хранит Git-репозитории, даёт URL для clone/push, веб-просмотр истории, права доступа, обсуждения. Модель объектов та же: blob/tree/commit. Сайт не заменяет понимание указателей и снимков.

Можно пользоваться Git без GitHub (другой хостинг или свой сервер). Можно смотреть код на GitHub без глубокого Git — но для командной работы без модели снимков будет больно.

## Термины

- **Хостинг** — сервер с remote.
- **Webhook/CI** — реакции на push (знать на уровне идеи).
- **Issues** — задачи рядом с кодом (не объекты Git).

## Внутреннее устройство

```text
ваш ПК: .git objects
GitHub:  .git objects (другая копия) + веб UI + PR + права
связь: remote URL + fetch/push
```

## Пример

```bash
git remote add origin git@github.com:org/repo.git
git push -u origin main
```

## Разбор

«Залить на GitHub» = иметь коммиты + remote + push. Кнопка на сайте не создаёт осмысленную историю за вас.

## Ошибки

- Путать «есть аккаунт» с «есть локальный репозиторий».
- Коммитить прямо на main в одиночку без договорённости команды — иногда ок, иногда нет.
- Хранить секреты в публичном remote.

## Что запомнить

GitHub — популярный remote с UI. Git — модель данных. Сначала модель, потом кнопки.

## Задание

Создайте пустой репозиторий на GitHub (или вообразите URL) и опишите три шага: remote add, commit, push.

## Связь со следующим уроком

Дальше — pull request: предложение влить линию снимков.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
