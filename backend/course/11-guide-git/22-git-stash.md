# Stash: временно убрать правки

## Цель

Понять stash как временное сохранение незакоммиченных изменений вне ветки.

## Что уже пройдено

Иногда нужно срочно переключить ветку, а снимок ещё не готов.

## Объяснение с нуля

**Stash** записывает состояние правок (рабочее дерево/индекс — в типичном сценарии) в отдельную структуру и возвращает витрину к чистому соответствию HEAD. Потом можно вернуть правки на любую ветку.

Это не замена коммиту: у stash слабая видимость в обычном log, легко забыть. Для долгоживущей работы лучше ветка и коммит.

## Термины

- **Stash** — временный снимок незафиксированного.
- **pop / apply** — вернуть правки (pop ещё убирает запись из списка).

## Внутреннее устройство

```text
грязное дерево → stash → чистое как HEAD → switch ветки → stash pop
```

## Пример

```bash
git stash push -m "черновик фильтра"
git switch main
git stash pop
```

## Разбор

Конфликт возможен и при pop, если дерево ушло далеко. Stash не отменяет нужду понимать снимки.

## Ошибки

- Держать в stash недели.
- Считать stash резервной копией релиза.
- Потерять список stash и забыть про правки.

## Что запомнить

Stash — карман для незакоммиченного. История проекта — всё же коммиты.

## Задание

Испортите файл, спрячьте в stash, переключите ветку туда-обратно, верните правки.

## Связь со следующим уроком

Дальше — GitHub как хостинг удалённых копий и соцслой вокруг Git.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
