# История коммитов

## Цель

Научиться читать цепочку снимков и понимать, что с чем сравнивают.

## Что уже пройдено

Коммит как объект знаком. Теперь навигация по графу.

## Объяснение с нуля

**История** — граф коммитов. Линейный участок похож на список; после слияний — развилки. Журнал отвечает: где регрессия, какой снимок был на стенде, кто менял контракт.

Сравнивают: коммит с родителем; две ветки; рабочее дерево с HEAD. Везде — сравнение деревьев (или дерева с индексом/диском). `git log` идёт от HEAD по родителям.

## Термины

- **`git log`** — обход коммитов назад.
- **HEAD** — текущая позиция.
- **Предок/потомок** — отношение в графе.
- **Дифф** — вычисленная разница.

## Внутреннее устройство

Каждый commit читается из objects по хешу. Имена файлов берутся из tree при необходимости.

```text
log: C5 → C4 → C3 → C2 → C1
```

## Пример

```bash
git log --oneline
git show HEAD
```

`show` даёт метаданные и diff относительно родителя.

## Разбор

История — не чат, а цепочка решений о состоянии. Читайте от вопроса («где сломалось?»), не с сотворения мира.

## Ошибки

- Путать порядок новизны.
- Искать смысл, которого нет в сообщениях.
- Думать, что удаление в последнем снимке стирает файл из предков.

## Что запомнить

История = обход графа commit. Diff всегда между снимками (или снимком и деревом/индексом).

## Задание

Выпишите из `git log` три хеша и стрелки родителей. Укажите, на какой хеш смотрит ветка.

## Связь со следующим уроком

Следующий урок: ветка как именованный указатель на commit.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
