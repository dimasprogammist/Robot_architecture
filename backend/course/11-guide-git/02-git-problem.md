# Проблема без контроля версий

## Цель

Увидеть, как ломается работа без снимков: копии папок, перезапись, невоспроизводимость.

## Что уже пройдено

Вы знаете зачем помнить версии. Теперь — типовой хаос без системы.

## Объяснение с нуля

Инженер ведёт `motor.md`. В понедельник всё корректно, во вторник правят ток, в среду — обороты. В четверг стенд «вчера работал». Где вчерашнее описание?

Обычный ответ — копии `motor_вт.md`, `motor_финал.md`. Через две недели в «финале» может быть старый ток и новый текст про обороты. Нет связи «эта пара значений стояла вместе».

Два человека правят разные абзацы в своих копиях и пересылают файл целиком — побеждает последний отправивший. Нет модели «оба изменения живут, пока их не соберут». Эксперимент с коэффициентом PID через копию всей папки оставляет правки без границы «временное / основное».

Корень не в лени, а в модели данных файловой системы: один путь — одно текущее содержимое. Имена копий — костыль.

## Термины

- **Перезапись** — один файл целиком заменяет другой.
- **Линия истории** — цепочка состояний (без Git её имитируют именами).
- **Конфликт содержимого** — два изменения одного места без явного слияния.
- **Воспроизводимость** — знание набора файлов на момент испытания.

## Внутреннее устройство

Файловая система не хранит «предыдущий снимок пути» и не хранит две альтернативы одного пути как равноправные. Git рядом с рабочей папкой держит базу объектов, где много состояний сосуществуют. Текущие файлы — выбранная витрина.

## Пример

```text
День 1: motor.md = "ток 2A, 1000 об/мин"
День 2: копия + ток 2.2A
День 3: в основном файле обороты 1200
День 4: какая пара (ток, обороты) была во вторник? — неизвестно
```

## Разбор

В день 4 нужны: (1) содержимое на момент, (2) связь состояний. Копии дают размазанные байты. Снимки с родителями дают цепочку.

## Ошибки

- Путать «версии файла в облаке» с полноценным графом веток и слияний.
- Верить имени `_финал`.
- Править две копии параллельно «на всякий случай».

## Что запомнить

Без контроля версий ломаются возврат, слияние чужих правок и честный ответ «что стояло на стенде».

## Задание

Опишите случай, когда пропала правка или искали «правильную» копию. Какого снимка не хватало?

## Связь со следующим уроком

Следующий урок: репозиторий — папка плюс скрытая база `.git`.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
