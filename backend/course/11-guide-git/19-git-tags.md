# Теги

## Цель

Понять тег как имя на конкретный commit (часто неизменное для релиза).

## Что уже пройдено

Ветки двигаются. Для выпуска нужно «закладка навечно».

## Объяснение с нуля

**Тег** — ref, обычно на один коммит, который не двигают при каждом новом снимке. Аннотированный тег — объект с сообщением и автором; лёгкий тег — просто имя→хеш. Релизы помечают тегами (`v1.2.0`), чтобы собрать именно то дерево.

Ветка `main` уйдёт вперёд; тег `v1.2.0` останется на старом commit — воспроизводимость сборки.

## Термины

- **Лёгкий тег** — имя → commit.
- **Аннотированный тег** — объект tag + указатель.
- **Release** — смысл «собрать этот снимок».

## Внутреннее устройство

```text
main ──► C20
v1.0.0 ──► C15   (не двигается от обычных коммитов)
```

## Пример

```bash
git tag -a v1.0.0 -m "Первый стабильный стенд"
git push origin v1.0.0
```

## Разбор

Тег не заменяет сообщение коммита. Он маркирует точку. Перенос тега на другой хеш путает всех, кто уже скачал старый.

## Ошибки

- Двигать опубликованные теги.
- Путать тег с веткой.
- Не пушить тег и удивляться, что на сервере его нет.

## Что запомнить

Тег — стабильное имя снимка. Ветка — движущийся край разработки.

## Задание

Поставьте аннотированный тег на учебный коммит и посмотрите его через `git show`.

## Связь со следующим уроком

Дальше — reset: перемещение указателя ветки (осторожно).

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
