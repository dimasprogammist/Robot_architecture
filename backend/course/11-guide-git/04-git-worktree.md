# Рабочее дерево

## Цель

Отделить файлы, которые вы правите, от объектов в `.git`.

## Что уже пройдено

Репозиторий есть. Теперь — что такое файлы «снаружи» базы.

## Объяснение с нуля

**Рабочее дерево** — обычные файлы проекта. Это не история, а текущий вид плюс незафиксированные правки. Переключение ветки перестраивает витрину под снимок, на который указывает ветка (с оговорками про локальные правки). Правка без снимка меняет только диск.

Файл может совпадать с последним снимком, отличаться, быть новым (неотслеживаемым) или удалённым на диске при живом blob в старых коммитах. `git status` сравнивает рабочее дерево, индекс и HEAD.

## Термины

- **Рабочее дерево** — файлы вне `.git`.
- **Грязное дерево** — есть незафиксированные отличия.
- **Checkout содержимого** — подставить файлы из снимка на диск.
- **Неотслеживаемый** — на диске есть, в индексе/истории пути ещё нет.

## Внутреннее устройство

Commit → tree → blob. Чтобы показать `src/a.py`, Git записывает байты blob в путь. Обратно: вы меняете байты — старый blob в базе не мутирует; появится новый объект, когда содержимое попадёт в индекс и коммит.

```text
commit → tree → blob "hello"
рабочее дерево уже: "hello!"  (база про "!" ещё не знает)
```

## Пример

```bash
echo hello > note.txt
git status
# note.txt неотслеживаемый — в снимках его нет
```

## Разбор

«Сохранил в редакторе» ≠ «попало в историю». Редактор пишет в рабочее дерево. База меняется при создании объектов через индекс и коммит.

## Ошибки

- Ждать, что `git log` покажет несохранённую в коммит правку.
- Думать, что удаление файла в проводнике стирает его из старых снимков.
- Держать секреты в дереве и потом случайно добавить в индекс.

## Что запомнить

Рабочее дерево — витрина и черновик. История — в объектах. Расхождение нормально до сознательного снимка.

## Задание

Создайте файл, посмотрите статус. Позже, после коммита, измените его и сформулируйте разницу «на диске» vs «в HEAD».

## Связь со следующим уроком

Следующий урок — индекс: черновик следующего tree.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
