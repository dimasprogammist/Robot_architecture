# Имя origin

## Цель

Понять, что origin — обычное имя remote по умолчанию, не особая магия.

## Что уже пройдено

Remote как адрес другой копии уже ясен.

## Объяснение с нуля

При клонировании Git почти всегда называет единственный remote **`origin`**. Это привычка, не закон физики. Можно `upstream`, `school`, `backup`. Команды вроде `git push origin main` читаются: «отправь обновление указателя `main` на remote с именем origin».

`origin/main` — remote-tracking ref. Он обновляется при fetch/pull с этого remote. Ваш локальный `main` может отставать или опережать `origin/main` — сравнивают два указателя на графе.

## Термины

- **origin** — имя remote по умолчанию после clone.
- **upstream branch** — с какой remote-веткой связана локальная (для статуса «ahead/behind»).
- **`origin/main`** — локальная запись о main на origin.

## Внутреннее устройство

```text
refs/heads/main          → C5   (ваша работа)
refs/remotes/origin/main → C3   (последнее известное с сервера)
# вы «впереди» на два коммита
```

## Пример

```bash
git branch -vv
git status
# часто пишет ahead/behind относительно upstream
```

## Разбор

Переименовать remote можно; смысл — не сломать привычные скрипты команды. Важно не имя, а куда указывает URL и какие refs обновляются.

## Ошибки

- Считать origin единственно возможным remote.
- Путать `main` и `origin/main`.
- Думать, что push «заливает папку», а не двигает refs и досылает объекты.

## Что запомнить

origin — удобное имя первой удалённой копии. Tracking-refs показывают, где remote был при последнем обмене.

## Задание

В своём репозитории выполните `git remote show origin` (если origin есть) и найдите, какую ветку Git считает tracked.

## Связь со следующим уроком

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs.
