# Рекурсия и математическая индукция

В прошлом уроке мы обходили дерево рекурсивно, вызывая одну и ту же функцию обхода для каждого потомка вершины, — и даже не останавливались на том, что это и есть рекурсия: функция, которая вызывает саму себя. Эта идея куда старше программирования: задолго до появления компьютеров она же применялась для доказательства математических утверждений про все натуральные числа сразу. Этот урок завершает блок дискретной математики, показывая, что рекурсия в коде и математическая индукция в доказательствах — это, по сути, одна и та же идея, выраженная в разных контекстах.

## Рекурсивное определение

**Рекурсивное определение** описывает объект через более простой (обычно меньший) объект того же типа. Классический пример — факториал, с которым мы уже встречались в уроке про комбинаторику, можно определить рекурсивно:

$$
n! = \begin{cases} 1, & n = 0 \\ n \cdot (n-1)!, & n > 0 \end{cases}
$$

Это определение состоит из двух частей: **базового случая** ($0! = 1$ — простейший случай, который не требует дальнейшего раскрытия) и **рекурсивного случая** (факториал любого числа, большего нуля, выражается через факториал меньшего числа). Без базового случая рекурсия никогда бы не остановилась.

```python
def factorial(n):
    if n == 0:          # базовый случай
        return 1
    return n * factorial(n - 1)  # рекурсивный случай

print(factorial(5))  # 120
```

## Как рекурсия разворачивается

Полезно явно проследить, что происходит при вызове `factorial(3)`: функция не может сразу вернуть ответ, потому что он зависит от `factorial(2)`, которая зависит от `factorial(1)`, которая зависит от `factorial(0)` — вот она, база, которая наконец возвращает готовое значение без дальнейших вызовов. После этого вычисления начинают «разворачиваться» в обратном порядке, домножая результат на очередное число:

```text
   factorial(3)
        │
   3 * factorial(2)
             │
        2 * factorial(1)
                  │
             1 * factorial(0)
                        │
                       = 1   (база)
   возврат: 1 → 1*1=1 → 2*1=2 → 3*2=6
```

## Математическая индукция: доказательство для всех чисел сразу

**Математическая индукция** — метод доказательства утверждений вида «это верно для всех натуральных чисел», построенный на точно такой же логике базы и перехода. Чтобы доказать, что утверждение $P(n)$ верно для всех $n \geq n_0$, достаточно доказать два факта:

1. **База индукции**: $P(n_0)$ верно (утверждение верно для самого первого случая).
2. **Индукционный переход**: если $P(k)$ верно для какого-то конкретного $k$, то из этого обязательно следует, что верно и $P(k+1)$.

Если оба пункта доказаны, утверждение автоматически верно для всех чисел, начиная с $n_0$: база даёт нам $P(n_0)$, переход даёт из неё $P(n_0+1)$, из него — $P(n_0+2)$, и так далее, бесконечно продолжая эту цепочку, хотя доказали мы всего два конкретных факта, а не бесконечное число отдельных случаев.

Докажем индукцией известную формулу суммы первых $n$ натуральных чисел:

$$
1 + 2 + \ldots + n = \frac{n(n+1)}{2}
$$

**База** ($n=1$): левая часть равна 1, правая — $\frac{1\cdot 2}{2}=1$. Совпадает.

**Переход**: предположим, формула верна для некоторого $k$, то есть $1+2+\ldots+k = \frac{k(k+1)}{2}$. Тогда для $k+1$:

$$
1+2+\ldots+k+(k+1) = \frac{k(k+1)}{2} + (k+1) = \frac{k(k+1)+2(k+1)}{2} = \frac{(k+1)(k+2)}{2}
$$

Это ровно формула для $n=k+1$ — переход доказан, а значит, формула верна для всех натуральных $n$.

## Рекурсия и индукция — зеркальные идеи

Сходство здесь не случайное совпадение, а по сути одна и та же логика, применённая в двух направлениях. Индукция строит доказательство снизу вверх: доказали базу, затем шаг за шагом доказываем всё более крупные случаи через предыдущие. Рекурсивная функция вычисляет значение сверху вниз: сводит большую задачу к меньшей версии той же самой задачи, пока не доходит до базового случая, а затем результаты «поднимаются» обратно наверх. Поэтому для рекурсивных функций, обрабатывающих структуры наподобие деревьев из прошлого урока, математическая индукция — это естественный способ строго доказать, что функция действительно корректно работает для структуры любого размера, а не только для проверенных вручную маленьких примеров.

## Практическое значение для программиста

Понимание рекурсии важно не только для того, чтобы писать рекурсивные функции, но и чтобы избегать их главной практической опасности — отсутствия корректного базового случая (что приводит к бесконечной рекурсии и переполнению стека вызовов, о котором шла речь в разделе про операционные системы) или базового случая, который на практике никогда не достигается из-за ошибки в рекурсивном переходе. Многие естественно рекурсивные структуры — обход дерева файловой системы, обход дерева HTML-разметки страницы, разбор вложенных скобок или вложенного JSON — прекрасно решаются именно рекурсивно, потому что сама структура данных рекурсивна: каталог может содержать другие каталоги, тег может содержать другие теги.

## Типичные ошибки

Самая опасная ошибка — рекурсивная функция без корректного базового случая или с условием, которое никогда не выполняется для определённых входных данных, что приводит к бесконечной рекурсии. Вторая — неэффективная рекурсия, многократно пересчитывающая одни и те же промежуточные значения (классический пример — наивное рекурсивное вычисление чисел Фибоначчи без сохранения уже вычисленных результатов, что делает алгоритм экспоненциально медленным при небольшом увеличении входных данных). Третья, уже на уровне индуктивных доказательств, — доказать базу и забыть явно опереться именно на предположение индукции в шаге перехода, фактически доказав переход «с нуля», что не является корректным индуктивным доказательством.

## Что нужно запомнить

Рекурсивное определение сводит задачу к более простой версии той же самой задачи, пока не дойдёт до базового случая, который не требует дальнейшего сведения. Математическая индукция доказывает утверждения для всех натуральных чисел сразу через доказательство базы и шага перехода от произвольного $k$ к $k+1$. Эти две идеи — рекурсия в вычислениях и индукция в доказательствах — зеркально отражают друг друга и обе опираются на одну и ту же логику «простой случай плюс правило сведения к нему».
