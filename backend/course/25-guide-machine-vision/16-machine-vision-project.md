# Практический проект системы технического зрения

## Цель

Собрать в одну систему знания из всего раздела и спроектировать полноценную систему машинного зрения для автоматического контроля детали.

После урока вы должны понимать:

* как начинать проект vision-системы;
* как сформулировать задачу;
* как выбрать камеру, объектив и освещение;
* как организовать trigger;
* как выполнять поиск и измерение;
* как формировать OK/NOK;
* как передавать результат в ПЛК;
* как диагностировать систему.

## Задача проекта

Представим производственную линию.

По конвейеру движется металлическая деталь:

```text
→ → → → → → → → → →

       ┌──────────────┐
       │     ○    ○   │
       │              │
       └──────────────┘

→ → → → → → → → → →
```

Необходимо проверить:

1. деталь присутствует;
2. два отверстия присутствуют;
3. отверстия находятся в правильных местах;
4. ширина детали соответствует допуску;
5. деталь не имеет крупного поверхностного дефекта;
6. результат передаётся в ПЛК.

## Требования

Пусть номинальные размеры:

```text
Ширина детали: 100.00 мм
Допуск: ±0.10 мм
```

Отверстия:

```text
Диаметр: 10.00 мм
Допуск: ±0.05 мм
```

Расстояние между центрами:

```text
80.00 мм
Допуск: ±0.10 мм
```

Результат должен быть:

```text
OK
```

только если все проверки пройдены.

Система:

```text
              ┌───────────┐
              │  датчик   │
              └─────┬─────┘
                    │
                    ▼
              ┌───────────┐
              │  trigger  │

                    │

                       │ OK / NOK   │
                       └─────┬──────┘
                             │
                             ▼
                            ПЛК
```

## Шаг 1. Формулируем задачу

Не стоит начинать с программирования.

Сначала описываем:

```text
что проверяем?
где проверяем?
с какой скоростью?
какая точность?
какой результат нужен?
```

Для проекта:

```text
Объект: металлическая деталь
Скорость: движется по конвейеру
Основная задача: геометрический контроль
Дополнительно: поиск дефекта
Результат: OK / NOK
```

## Шаг 2. Определяем рабочую область

Предположим:

```text
ширина зоны = 150 мм
высота зоны = 120 мм
```

Камера должна видеть всю деталь.

Но деталь не должна занимать слишком маленькую часть изображения.

Условно:

```text
┌───────────────────────────┐
│                           │
│    ┌────────────────┐     │
│    │    деталь      │     │
│    └────────────────┘     │
│                           │
└───────────────────────────┘
```

## Шаг 3. Выбираем разрешение

Предположим, камера имеет:

```text
2048 px
```

по горизонтали.

Рабочая область:

```text
150 мм
```

Тогда:

```text
150 / 2048 ≈ 0.073 мм/px
```

Это даёт ориентировочный масштаб.

Требуемый допуск:

```text
0.10 мм
```

Но нельзя считать, что система автоматически измеряет с точностью 0.073 мм.

Необходимо учитывать:

* оптику;
* качество изображения;
* калибровку;
* алгоритм;
* повторяемость.

## Шаг 4. Выбираем освещение

Для измерения внешнего контура удобно использовать backlight.

Схема:

```text
     камера
        ↓
      деталь
        ↓
   ┌──────────┐
   │   LED    │
   │ backlight│
   └──────────┘
```

Деталь получается тёмной на светлом фоне.

Это упрощает поиск контура.

Для дефектов поверхности можно добавить отдельную подсветку.

Например:

```text
камера
   ↓
деталь ← боковой свет
```

В реальной системе для разных задач иногда используются разные источники света.

## Шаг 5. Выбираем объектив

Нужно обеспечить:

```text
FOV ≈ 150 × 120 мм
```

на заданном рабочем расстоянии.

Объектив выбирается после определения:

```text
размер матрицы
рабочее расстояние
поле зрения
```

Здесь не нужно выбирать объектив только по названию камеры.

Камера и объектив образуют единую оптическую систему.

## Шаг 6. Фиксируем механику

Камера должна быть жёстко закреплена:

```text
┌──────────────┐
│    камера    │
└──────┬───────┘
       │
     крепёж
       │
═══════╧════════
     рама
```

Нельзя рассчитывать на то, что оператор каждый день установит её в одинаковое положение.

После калибровки геометрия должна оставаться стабильной.

## Шаг 7. Синхронизация

Перед камерой устанавливается датчик:

```text
конвейер →

датчик ───────────── камера
```

При обнаружении детали:

```text
sensor
  ↓
trigger
  ↓
camera
```

Если скорость конвейера изменяется, можно использовать энкодер.

## Шаг 8. Получаем изображение

После trigger:

```text
frame = camera.capture()
```

На изображении:

```text
┌──────────────────────────┐
│                          │
│    ┌───────────────┐     │
│    │   ○       ○   │     │
│    └───────────────┘     │
│                          │
└──────────────────────────┘
```

## Шаг 9. Предобработка

Для геометрического контроля можно:

```text
BGR
 ↓
grayscale
 ↓
blur
 ↓
threshold
```

Например:

```python
gray = cv2.cvtColor(
    image,
    cv2.COLOR_BGR2GRAY
)

blur = cv2.GaussianBlur(
    gray,
    (5, 5),
    0
)

_, binary = cv2.threshold(
    blur,
    120,
    255,
    cv2.THRESH_BINARY
)
```

## Шаг 10. Находим контур детали

```python
contours, _ = cv2.findContours(
    binary,
    cv2.RETR_EXTERNAL,
    cv2.CHAIN_APPROX_SIMPLE
)
```

Выбираем контур детали по площади:

```python
contour = max(
    contours,
    key=cv2.contourArea
)
```

Теперь можно получить:

```text
контур детали
```

## Шаг 11. Измеряем ширину

Получаем ограничивающий прямоугольник:

```python
x, y, w, h = cv2.boundingRect(contour)
```

Например:

```text
w = 1365 px
```

После калибровки:

```text
scale = 0.073 мм/px
```

получаем приблизительно:

```text
1365 × 0.073 ≈ 99.65 мм
```

Но реальная система должна использовать более точное калибровочное преобразование.

## Шаг 12. Ищем отверстия

Отверстия могут выделяться как внутренние области.

В зависимости от изображения можно использовать:

* контуры;
* Hough Circle;
* бинаризацию;
* шаблон;
* геометрический анализ.

Например:

```python
circles = cv2.HoughCircles(
    gray,
    cv2.HOUGH_GRADIENT,
    dp=1,
    minDist=50,
    param1=100,
    param2=30,
    minRadius=20,
    maxRadius=100
)
```

Если найдено:

```text
2 окружности
```

можно перейти к проверке их размеров и положения.

## Шаг 13. Проверяем диаметр

Для каждого отверстия:

```text
radius → diameter
```

Например:

```text
diameter = 9.98 мм
```

Требование:

```text
10.00 ± 0.05 мм
```

Допустимый диапазон:

```text
9.95 ... 10.05 мм
```

Результат:

```text
OK
```

## Шаг 14. Проверяем расстояние

Пусть центры отверстий:

```text
P1
P2
```

Расстояние:

```text
d = distance(P1, P2)
```

Получили:

```text
79.94 мм
```

Требование:

```text
80.00 ± 0.10 мм
```

Диапазон:

```text
79.90 ... 80.10 мм
```

Результат:

```text
OK
```

## Шаг 15. Проверяем положение

Допустим, первое отверстие должно находиться:

```text
X = 20.00 ± 0.10 мм
Y = 30.00 ± 0.10 мм
```

Измерено:

```text
X = 20.04
Y = 29.96
```

Оба параметра находятся в допуске.

Результат:

```text
OK
```

## Шаг 16. Контролируем поверхность

Для дефектов выделяем отдельную ROI:

```text
┌──────────────────────────┐
│                          │
│    ┌───────────────┐     │
│    │ surface ROI   │     │
│    └───────────────┘     │
│                          │
└──────────────────────────┘
```

В этой зоне можно использовать:

* анализ границ;
* локальный контраст;
* сравнение с эталоном;
* специализированный алгоритм;
* нейросетевую модель.

Например:

```text
defect_area = 37 px
```

Если допустимо:

```text
< 50 px
```

то:

```text
OK
```

## Шаг 17. Формируем общий результат

Пусть:

```text
PartPresent = TRUE
WidthOK = TRUE
Hole1OK = TRUE
Hole2OK = TRUE
HoleDistanceOK = TRUE
PositionOK = TRUE
SurfaceOK = TRUE
```

Тогда:

```text
InspectionOK =
    PartPresent
    AND WidthOK
    AND Hole1OK
    AND Hole2OK
    AND HoleDistanceOK
    AND PositionOK
    AND SurfaceOK
```

Результат:

```text
OK
```

Если хотя бы одно условие:

```text
FALSE
```

получаем:

```text
NOK
```

## Шаг 18. Код причины

Не стоит передавать только:

```text
NOK
```

Лучше сформировать код:

```text
0 = OK
1 = width error
2 = hole missing
3 = hole diameter error
4 = hole position error
5 = surface defect
```

Например:

```text
Result = NOK
ErrorCode = 4
```

означает:

```text
отверстие находится не в допустимом положении
```

## Шаг 19. Передача в ПЛК

Например:

```text
InspectionDone
InspectionOK
ErrorCode
```

ПЛК получает:

```text
InspectionDone = TRUE
InspectionOK = FALSE
ErrorCode = 5
```

и может активировать отбраковку.

## Шаг 20. Сохранение результата

Полезно сохранять:

```text
timestamp
part_id
width
hole_1_diameter
hole_2_diameter
hole_distance
error_code
result
```

Например:

```text
2026-10-02 14:31:25
PART_10025
99.96
10.01
9.98
79.95
0
OK
```

Для NOK полезно сохранять изображение.

## Диагностика

Если система начала выдавать много NOK, нужно проверить:

```text
камера
 ↓
объектив
 ↓
освещение
 ↓
механика
 ↓
калибровка
 ↓
trigger
 ↓
алгоритм
```

Не следует сразу менять пороги.

Например, если камера сместилась:

```text
калибровка → неверная
```

и все измерения начинают уходить.

## Что делать при отсутствии камеры

Нельзя продолжать производство так, будто всё нормально.

Если:

```text
camera disconnected
```

система должна сообщить:

```text
VisionFault = TRUE
```

Дальнейшее поведение определяется требованиями безопасности и технологического процесса.

## Производительность

Предположим:

```text
1 деталь / 2 секунды
```

а обработка занимает:

```text
100 мс
```

запаса достаточно.

Если:

```text
1 деталь / 100 мс
```

и обработка:

```text
150 мс
```

система не успевает.

Поэтому нужно учитывать:

```text
cycle time
```

всей системы.

## Главное

Главный урок этого раздела заключается в том, что машинное зрение — это не отдельная камера и не отдельный алгоритм.

Это целая инженерная система:

```text
процесс
+
механика
+
освещение
+
оптика
+
камера
+
синхронизация
+
обработка
+
калибровка
+
алгоритм
+
управление
```

Если любой из этих элементов нестабилен, результат всей системы может стать нестабильным.

Поэтому хороший проект начинают не с программирования, а с вопроса:

> Какой физический результат должна надёжно получать система?

После этого подбираются:

```text
геометрия
→ свет
→ оптика
→ камера
→ алгоритм
→ интеграция
```

И только затем система превращается в законченный промышленный инструмент контроля.
