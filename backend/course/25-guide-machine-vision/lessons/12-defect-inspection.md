# Поиск дефектов

## Цель

Понять, как системы машинного зрения обнаруживают дефекты изделий и почему задача поиска дефектов значительно сложнее простой проверки наличия объекта.

После урока вы должны понимать:

* что такое визуальный дефект;
* какие типы дефектов можно искать камерой;
* как строится зона контроля;
* чем поиск дефекта отличается от измерения;
* как используются пороги, контуры и сравнение с эталоном;
* почему освещение особенно важно при дефектоскопии;
* где применяются нейросетевые методы.

## Что такое дефект

Дефект — это отклонение изделия от требуемого состояния.

Например:

* царапина;
* трещина;
* скол;
* отверстие не той формы;
* пятно;
* загрязнение;
* отсутствие элемента;
* неправильное положение;
* деформация;
* изменение цвета;
* лишний материал.

Примеры:

```text
нормальная деталь:

████████████

дефект:

██████░█████
```

Главная задача системы:

```text
норма
или
дефект
```

## Дефект бывает разным

Очень важно заранее определить, что именно считается дефектом.

Например, на поверхности может быть:

```text
маленькая царапина
```

Но допустимая царапина может иметь размер:

```text
до 0.2 мм
```

а дефектная:

```text
более 0.2 мм
```

Следовательно, система должна не просто обнаружить отличие от идеального изображения.

Она должна оценить его по заданным критериям.

## Категории дефектов

Условно можно разделить дефекты на несколько групп.

### Геометрические

Например:

```text
размер не соответствует
форма нарушена
отверстие смещено
деталь деформирована
```

### Поверхностные

Например:

```text
царапина
трещина
вмятина
пятно
```

### Цветовые

Например:

```text
неправильный цвет
изменение оттенка
пятно
```

### Комплектность

Например:

```text
нет винта
нет разъёма
нет наклейки
```

### Положение

Например:

```text
элемент установлен наоборот
элемент смещён
```

Для каждой категории могут потребоваться разные алгоритмы.

## Почему освещение критично

Представим небольшую царапину:

```text
поверхность:
████████████████
```

Царапина может почти не отличаться по цвету от поверхности.

При одном освещении:

```text
██████░█████████
```

она хорошо видна.

При другом:

```text
████████████████
```

она почти исчезает.

Поэтому при дефектоскопии освещение часто важнее, чем увеличение разрешения камеры.

## Подсветка под углом

Для небольших поверхностных дефектов может использоваться боковое освещение.

Например:

```text
LED →→→→→ поверхность
              ╲
               ╲
                камера
```

Маленькая неровность создаёт изменение отражения.

На изображении она становится заметнее.

## Прямое освещение

Для других задач удобно равномерное прямое освещение:

```text
      свет
       ↓
       ↓
 ┌───────────┐
 │  деталь   │
 └───────────┘
       ↑
     камера
```

Это помогает уменьшить тени.

Но конкретная схема зависит от поверхности и дефекта.

## Зона интереса

Не всегда нужно анализировать весь кадр.

Можно выделить ROI:

```text
┌──────────────────────┐
│                      │
│   ┌──────────────┐   │
│   │  контрольная │   │
│   │     зона     │   │
│   └──────────────┘   │
│                      │
└──────────────────────┘
```

Преимущества:

* меньше вычислений;
* меньше ложных срабатываний;
* проще алгоритм;
* легче настроить пороги.

## Простая бинаризация

Если дефект отличается по яркости, можно использовать порог.

Например:

```python
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)

_, binary = cv2.threshold(
    gray,
    150,
    255,
    cv2.THRESH_BINARY
)
```

Получаем области, которые отличаются от фона.

Затем можно найти контуры:

```python
contours, _ = cv2.findContours(
    binary,
    cv2.RETR_EXTERNAL,
    cv2.CHAIN_APPROX_SIMPLE
)
```

## Фильтрация шума

На изображении могут быть мелкие точки:

```text
. . .       .
     .   .
```

Не каждая из них является дефектом.

Можно отфильтровать объекты по площади:

```python
if area > min_area:
    defect = True
```

Например:

```text
area < 20 px
→ игнорировать

area >= 20 px
→ анализировать
```

## Морфологическая обработка

Для очистки бинарной маски можно использовать морфологические операции.

Например:

```python
kernel = np.ones((3, 3), np.uint8)

clean = cv2.morphologyEx(
    binary,
    cv2.MORPH_OPEN,
    kernel
)
```

Они позволяют:

* убрать мелкий шум;
* закрыть небольшие разрывы;
* объединить близкие области.

Но параметры нужно подбирать под конкретную систему.

## Сравнение с эталоном

Другой подход — сравнивать изображение с эталонным.

Например:

```text
эталон:
████████████████

деталь:
██████░█████████
```

Можно вычислить разницу:

```text
difference = |image - reference|
```

и найти области, где различие превышает порог.

## Проблема эталонного сравнения

Метод чувствителен к:

* смещению детали;
* изменению освещения;
* изменению фокуса;
* вибрации камеры;
* изменению положения объекта.

Если деталь сдвинулась на несколько пикселей:

```text
эталон:

████████

реальное:

  ████████
```

алгоритм может решить, что вся граница является дефектом.

Поэтому перед сравнением изображения часто необходимо выровнять объект.

## Геометрическое выравнивание

Сначала можно найти положение детали:

```text
объект
 ↓
центр
 ↓
угол
 ↓
выравнивание
 ↓
сравнение
```

Тогда сравниваются уже соответствующие области.

## Дефект как локальное отличие

Часто не нужно сравнивать весь объект.

Например, если проверяется поверхность:

```text
┌──────────────────────┐
│                      │
│     поверхность      │
│          ╱           │
│         ╱            │
│        ╱             │
│                      │
└──────────────────────┘
```

можно искать локальные изменения текстуры или яркости.

## Текстура

Некоторые поверхности имеют естественную неоднородность:

```text
░▒▓░▒░▓▒░▓░▒
```

Поэтому простое сравнение яркости может давать много ложных тревог.

В таких случаях анализируют:

* локальный контраст;
* градиенты;
* текстурные признаки;
* структуру поверхности.

## Цветовые дефекты

Если дефект связан с цветом, RGB может быть не самым удобным представлением.

Можно использовать HSV:

```python
hsv = cv2.cvtColor(
    image,
    cv2.COLOR_BGR2HSV
)
```

Тогда можно анализировать:

```text
Hue
Saturation
Value
```

Например, выделять области определённого оттенка.

## Пример проверки цвета

Допустим, деталь должна иметь красную маркировку.

Можно задать диапазон:

```text
Hue = H1 ... H2
Saturation > S_min
Value > V_min
```

и найти соответствующие области.

Если маркировки нет:

```text
область не найдена
→ NOK
```

## Трещины

Трещины часто выглядят как тонкие линии.

Упрощённый подход:

```text
изображение
 ↓
контрастирование
 ↓
поиск границ
 ↓
линии
 ↓
фильтрация
 ↓
проверка длины/ширины
```

Например:

```text
трещина:
──────────────
```

Можно оценить:

```text
длина
ширина
направление
положение
```

## Царапины

Царапина может быть:

```text
тонкой
длинной
контрастной
```

Поэтому часто анализируются:

* вытянутость;
* длина;
* площадь;
* ориентация;
* контраст.

Можно отфильтровать обычные точки загрязнения, если они имеют другую форму.

## Отсутствие элемента

Это более простая задача.

Например, деталь должна содержать три отверстия:

```text
○     ○     ○
```

Если камера обнаружила:

```text
○           ○
```

то:

```text
количество = 2
ожидалось = 3
→ NOK
```

Это уже относится к визуальному контролю комплектности.

## Нейросетевой поиск дефектов

Классические методы хорошо работают, если:

* дефект предсказуем;
* освещение стабильно;
* поверхность контролируема;
* критерий легко описать математически.

Но некоторые дефекты слишком разнообразны.

Например:

```text
царапины
трещины
пятна
разные формы загрязнения
```

Тогда можно использовать машинное обучение.

Общая схема:

```text
изображения OK
        +
изображения NOK
        ↓
обучение
        ↓
модель
        ↓
новое изображение
        ↓
OK / NOK
```

## Аномалия

Иногда сложно собрать все возможные типы дефектов.

Тогда можно обучать систему преимущественно на нормальных изображениях.

Идея:

```text
много нормальных деталей
        ↓
модель изучает норму
        ↓
новая деталь
        ↓
сильное отличие
        ↓
аномалия
```

Такой подход называется anomaly detection.

## Почему нейросеть не всегда лучше

Нейросеть может требовать:

* много изображений;
* разметку;
* обучение;
* проверку качества;
* вычислительные ресурсы;
* контроль версии модели.

Если дефект можно надёжно определить простой геометрией:

```text
ширина < 20 мм
```

то сложная нейросеть может быть неоправданной.

## Ложные срабатывания

Система может сказать:

```text
NOK
```

хотя деталь нормальная.

Это false positive.

Обратная ситуация:

```text
дефект есть
но система сказала OK
```

Это false negative.

В производстве оба случая важны.

## Настройка порогов

Допустим, система измеряет площадь дефекта.

Устанавливаем:

```text
площадь < 50 px
→ допустимо

площадь >= 50 px
→ дефект
```

Но если поставить порог слишком низко:

```text
много ложных дефектов
```

Если слишком высоко:

```text
мелкие реальные дефекты пропускаются
```

Поэтому порог выбирается на основе реальных образцов.

## Набор тестовых деталей

Для настройки полезно собрать:

```text
нормальные детали
+
реальные дефектные детали
```

и проверить систему на всех них.

Например:

```text
100 OK
30 NOK
```

Это позволяет увидеть:

* сколько нормальных деталей распознано правильно;
* сколько дефектов найдено;
* какие типы дефектов пропускаются;
* где возникают ложные срабатывания.

## Сохранение изображений

При отбраковке полезно сохранять кадр:

```text
2026-10-02_10-15-03_NOK.png
```

и результат:

```text
Defect = Scratch
Area = 82 px
```

Это помогает при анализе спорных случаев.

## Полный цикл

Типичная система поиска дефектов:

```text
trigger
  ↓
camera
  ↓
image
  ↓
ROI
  ↓
preprocessing
  ↓
segmentation / features / neural model
  ↓
defect candidates
  ↓
filtering
  ↓
decision
  ↓
OK / NOK
```

## Главное

Поиск дефектов — это задача не только программного анализа.

Нужно обеспечить:

```text
стабильную механику
+
стабильное освещение
+
правильную оптику
+
качественное изображение
+
подходящий алгоритм
```

Часто хороший свет и правильно выбранная геометрия камеры позволяют решить задачу значительно проще.

Главный принцип:

> Сначала нужно сделать дефект видимым и стабильным на изображении, а уже потом решать задачу его программного обнаружения.
