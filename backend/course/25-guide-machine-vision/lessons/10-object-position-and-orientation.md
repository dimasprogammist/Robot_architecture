# Поиск положения и ориентации объекта

## Цель

Научиться понимать, как система машинного зрения определяет, где находится объект в кадре и под каким углом он расположен.

После урока вы должны понимать:

* что такое положение объекта;
* что такое ориентация;
* как найти центр объекта;
* какие методы используются для поиска положения;
* зачем определять угол поворота;
* как координаты изображения используются роботами;
* почему поиск объекта является отдельной задачей перед измерением.

## Зачем знать положение объекта

Во многих задачах недостаточно просто обнаружить объект.

Нужно знать:

```text
где он находится?
```

и:

```text
как он повернут?
```

Например, робот должен взять деталь.

Камера обнаружила:

```text
объект найден
```

Но этого недостаточно.

Роботу необходимо знать:

```text
X
Y
Angle
```

Например:

```text
X = 420 мм
Y = 180 мм
Angle = 25°
```

После этого робот может рассчитать движение.

## Положение объекта

Самый простой вариант — определить центр объекта.

Например:

```text
┌──────────────────────┐
│                      │
│       ███████        │
│       ███████        │
│          ●           │
│                      │
└──────────────────────┘
```

Точка:

```text
●
```

может быть центром объекта.

В координатах изображения:

```text
X = 520 px
Y = 310 px
```

## Центр ограничивающего прямоугольника

Если найден контур, можно получить его bounding box:

```python
x, y, w, h = cv2.boundingRect(contour)
```

Центр:

```python
center_x = x + w / 2
center_y = y + h / 2
```

Например:

```text
x = 100
y = 200
w = 400
h = 300
```

Тогда:

```text
center_x = 300
center_y = 350
```

Это простой способ определить положение.

## Центр масс

Для бинарного объекта можно использовать моменты изображения.

В OpenCV:

```python
moments = cv2.moments(contour)

cx = moments["m10"] / moments["m00"]
cy = moments["m01"] / moments["m00"]
```

Получаем:

```text
cx → координата центра
cy → координата центра
```

Такой центр может быть полезнее, чем центр bounding box, если объект имеет неправильную форму.

## Почему центр может быть разным

Рассмотрим объект:

```text
████████
████████
████
████
```

Центр ограничивающего прямоугольника находится примерно в середине прямоугольника.

Но центр площади объекта будет смещён в сторону большей массы.

Поэтому нужно понимать, какой именно центр нужен для конкретной задачи.

## Ориентация

Положение отвечает на вопрос:

> Где объект?

Ориентация отвечает:

> Как объект повернут?

Например:

```text
0°

████████
████████
```

и:

```text
30°

   ████
 ███████
```

Положение центра может быть одинаковым, но ориентация разная.

## Зачем знать угол

Представим робота-захватчика.

Деталь лежит на конвейере:

```text
      ╱─────╲
     ╱       ╲
```

Робот должен повернуть захват так же:

```text
Angle = 30°
```

Если робот знает только:

```text
X
Y
```

он может подойти к правильному месту, но захватить деталь неправильно.

## Минимальный набор для плоского объекта

Для многих задач достаточно трёх параметров:

```text
X
Y
Angle
```

Это называется плоской позой объекта.

Условно:

```text
Pose = (X, Y, θ)
```

Например:

```text
Pose = (420, 180, 25°)
```

## Bounding box

Один из простых способов найти ориентацию — построить ограничивающий прямоугольник.

Но обычный:

```python
cv2.boundingRect()
```

всегда ориентирован по осям изображения.

Поэтому для повернутого объекта лучше использовать минимальный повёрнутый прямоугольник.

В OpenCV:

```python
rect = cv2.minAreaRect(contour)
```

Результат содержит:

```text
центр
размер
угол
```

Например:

```python
(center_x, center_y), (width, height), angle = rect
```

## Почему угол может быть неожиданным

В OpenCV угол повёрнутого прямоугольника зависит от того, как библиотека выбрала его стороны.

Например, одна и та же деталь может дать:

```text
angle = -10°
```

в одном случае и:

```text
angle = 80°
```

в другом.

Это связано с ориентацией сторон прямоугольника и тем, какая сторона считается шириной.

Поэтому перед использованием угла в робототехнике необходимо проверить систему координат и правила конкретного алгоритма.

## Контур

Для поиска ориентации часто используется контур объекта.

Общий процесс:

```text
изображение
 ↓
сегментация
 ↓
бинарная маска
 ↓
контур
 ↓
геометрия
 ↓
центр + угол
```

Например:

```python
contours, _ = cv2.findContours(
    binary,
    cv2.RETR_EXTERNAL,
    cv2.CHAIN_APPROX_SIMPLE
)
```

После этого можно выбрать нужный контур.

## Как выбрать правильный объект

В кадре может быть несколько объектов:

```text
████      ████

      ████

████      ████
```

Нужно понять, какой контур является нужным.

Можно использовать признаки:

* площадь;
* ширину;
* высоту;
* соотношение сторон;
* положение;
* цвет;
* форму.

Например:

```python
if 1000 < area < 5000:
    ...
```

Так можно отфильтровать слишком маленькие и слишком большие объекты.

## Центр по контуру

После выбора контура можно вычислить его центр:

```python
M = cv2.moments(contour)

if M["m00"] != 0:
    cx = M["m10"] / M["m00"]
    cy = M["m01"] / M["m00"]
```

Теперь программа знает положение объекта в пикселях.

## Пиксели и миллиметры

Допустим:

```text
центр объекта:
X = 800 px
Y = 450 px
```

После калибровки:

```text
X = 320 мм
Y = 180 мм
```

Получаем:

```text
pixel coordinates
       ↓
calibration
       ↓
physical coordinates
```

Именно эти физические координаты могут быть нужны роботу.

## Система координат

Очень важно понимать, что у изображения и робота могут быть разные системы координат.

Изображение:

```text
        X →
(0,0) ─────────────
  │
  │
  │
  ↓
  Y
```

Робот может использовать:

```text
        X →
        │
        │
        ↑
        Y
```

Кроме того, начало координат может находиться в другом месте.

Поэтому нужно выполнять преобразование.

## Преобразование координат

Упрощённо:

```text
(X_pixel, Y_pixel)
        ↓
   калибровка
        ↓
(X_camera, Y_camera)
        ↓
преобразование
        ↓
(X_robot, Y_robot)
```

В реальной роботизированной системе преобразование может учитывать также:

* масштаб;
* поворот;
* смещение;
* высоту объекта;
* положение камеры;
* систему координат робота.

## Поиск ориентации по главной оси

Для некоторых объектов направление можно определить через геометрию контура.

Например, вытянутый объект:

```text
       /
      /
     /
    /
```

имеет явно выраженную главную ось.

Её направление можно оценить математически.

Один из подходов связан с:

* моментами изображения;
* PCA;
* эллипсом, аппроксимирующим контур.

## PCA

Метод главных компонент позволяет определить направление максимального разброса точек.

Для вытянутого объекта:

```text
████
  ████
    ████
```

главная компонента примерно совпадёт с направлением объекта.

Это может быть полезно, если форма не очень хорошо описывается прямоугольником.

## Шаблон

Иногда объект сложно выделить простой сегментацией.

Тогда можно искать известный шаблон.

Упрощённо:

```text
эталон
  ↓
поиск совпадения
  ↓
координаты
  ↓
угол
```

Шаблонное сопоставление удобно для некоторых стабильных сцен.

Но оно может быть чувствительно к:

* изменению масштаба;
* повороту;
* освещению;
* частичному перекрытию.

## Признаки

Для более сложных объектов можно использовать характерные точки и дескрипторы.

Например:

```text
объект
  ↓
keypoints
  ↓
matching
  ↓
положение
```

Такие методы уже рассматривались в разделе компьютерного зрения.

В машинном зрении они используются как один из инструментов решения конкретной технической задачи.

## Нейросетевой поиск

Если объект имеет большое разнообразие внешнего вида, можно использовать нейросетевую детекцию.

Например:

```text
камера
 ↓
нейросеть
 ↓
объект найден
 ↓
bounding box
 ↓
центр
```

Но для простой стабильной производственной задачи нейросеть может быть избыточной.

Если объект легко выделяется по геометрии или контрасту, классический алгоритм может быть проще и предсказуемее.

## Практический пример

Представим конвейер:

```text
→ → → → → → →
       ███
      █████
       ███
→ → → → → → →
```

Камера делает снимок.

Алгоритм:

```text
1. получает изображение
2. выделяет объект
3. находит контур
4. вычисляет центр
5. вычисляет угол
6. преобразует координаты
7. передаёт данные роботу
```

Результат:

```text
X = 430 мм
Y = 215 мм
Angle = 17°
```

Робот получает:

```text
Pick(
    X=430,
    Y=215,
    Angle=17
)
```

и выполняет захват.

## Ошибки

Система может ошибиться:

```text
объект не найден
```

или:

```text
найден неправильный объект
```

или:

```text
центр найден неправильно
```

или:

```text
угол определён неверно
```

Поэтому полезно контролировать качество результата.

Например:

```text
ObjectFound = TRUE
Confidence = 0.94
Area = 2350 px
Angle = 17.2°
```

Если площадь неожиданно изменилась:

```text
Area = 120 px
```

можно считать результат подозрительным.

## Поиск положения перед измерением

Во многих системах сначала определяют положение объекта, а уже потом измеряют его.

Например:

```text
1. найти деталь
      ↓
2. определить центр
      ↓
3. выровнять систему координат
      ↓
4. найти отверстие
      ↓
5. измерить диаметр
```

Это делает алгоритм устойчивее к небольшому смещению детали.

## Главное

Поиск положения объекта обычно состоит из нескольких задач:

```text
найти объект
    ↓
выделить его
    ↓
найти геометрические признаки
    ↓
определить центр
    ↓
определить ориентацию
    ↓
преобразовать координаты
```

Для простых объектов могут использоваться:

* контуры;
* моменты;
* bounding box;
* `minAreaRect`;
* геометрические признаки.

Для более сложных:

* шаблонное сопоставление;
* признаки и дескрипторы;
* нейросетевые детекторы.

В робототехнике особенно важно перейти от:

```text
пикселей
```

к:

```text
физическим координатам
```

потому что робот должен знать не просто, где объект находится на изображении, а **где он находится в пространстве, в котором робот выполняет движение**.
