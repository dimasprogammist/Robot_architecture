# Архитектура системы машинного зрения

## Цель

Понять, из каких компонентов состоит система машинного зрения и как они взаимодействуют между собой.

После урока вы должны понимать:

* какие элементы входят в систему технического зрения;
* зачем нужны камера, объектив и освещение;
* как происходит запуск съёмки;
* как изображение попадает в компьютер;
* как результат анализа передаётся в систему управления;
* почему механика, датчики и программное обеспечение являются частью vision-системы.

## Общая структура

Типичную систему машинного зрения можно представить следующим образом:

```text
                 ОБЪЕКТ
                    │
                    ▼
              ┌───────────┐
              │ Освещение │
              └─────┬─────┘
                    │
                    ▼
              ┌───────────┐
              │ Объектив  │
              └─────┬─────┘
                    │
                    ▼
              ┌───────────┐
              │  Камера   │
              └─────┬─────┘
                    │
                    ▼
              ┌───────────┐
              │ Компьютер │
              │ / контрол.│
              └─────┬─────┘
                    │
                    ▼
              ┌───────────┐
              │ Алгоритм  │
              │ анализа   │
              └─────┬─────┘
                    │
                    ▼
              ┌───────────┐
              │ Решение   │
              │ OK / NOK  │
              └─────┬─────┘
                    │
                    ▼
              ┌───────────┐
              │ ПЛК /     │
              │ робот     │
              └───────────┘
```

Однако реальная система обычно содержит больше элементов.

## 1. Объект контроля

Первым элементом является объект, который необходимо исследовать.

Например:

* металлическая деталь;
* бутылка;
* электронная плата;
* упаковка;
* сварной шов;
* подшипник;
* автомобильный компонент.

Система должна получать от объекта визуальную информацию.

Но объект не обязательно находится неподвижно.

Он может:

* двигаться по конвейеру;
* вращаться;
* перемещаться роботом;
* проходить через контрольную позицию.

Поэтому положение объекта относительно камеры является важной частью системы.

## 2. Освещение

Освещение определяет, как объект будет выглядеть на изображении.

Можно иметь отличную камеру и хороший алгоритм, но получить плохой результат из-за неправильного света.

Например, металлическая поверхность может отражать свет прямо в объектив.

На изображении появится яркое пятно:

```text
████████████
██  БЛИК  ██
████████████
```

Алгоритм может принять этот блик за дефект.

Поэтому освещение является полноценным элементом системы машинного зрения.

## 3. Объектив

Камера сама по себе не формирует изображение непосредственно на матрице.

Свет проходит через оптическую систему — объектив.

Объектив определяет, каким образом сцена проецируется на матрицу камеры.

Важными параметрами являются:

* фокусное расстояние;
* угол обзора;
* рабочая дистанция;
* глубина резкости;
* оптические искажения.

Например, объектив с большим фокусным расстоянием позволяет получить более узкое поле зрения.

Объектив с меньшим фокусным расстоянием позволяет увидеть более широкую область.

## 4. Камера

Камера преобразует свет в цифровое изображение.

Внутри камеры находится матрица.

Упрощённо:

```text
свет
 ↓
объектив
 ↓
матрица
 ↓
электрический сигнал
 ↓
цифровые данные
 ↓
изображение
```

Камера может иметь различные интерфейсы передачи данных.

Например:

* USB;
* GigE;
* USB3 Vision;
* GigE Vision;
* Camera Link;
* CoaXPress.

Для промышленной системы особенно важны стабильность передачи и возможность синхронизации.

## 5. Триггер

Во многих системах камера не должна постоянно делать снимки самостоятельно.

Нужно точно определить момент съёмки.

Для этого используется **trigger**.

Например:

```text
датчик → объект появился → trigger → камера делает снимок
```

Это особенно важно на конвейере.

Допустим, деталь движется со скоростью:

```text
1 м/с
```

Если задержать съёмку даже на небольшое время, объект уже сместится.

Поэтому положение объекта и момент экспозиции должны быть согласованы.

## Аппаратный и программный trigger

Триггер может формироваться аппаратно:

```text
датчик
  ↓
цифровой вход камеры
  ↓
снимок
```

Или программно:

```text
компьютер
  ↓
команда
  ↓
камера
  ↓
снимок
```

Аппаратная синхронизация обычно позволяет лучше контролировать временные характеристики системы.

## 6. Передача изображения

После получения кадра его необходимо передать в вычислительную систему.

Например:

```text
Camera
   │
   │ Ethernet
   ▼
Computer
```

Компьютер получает массив данных.

Условно:

```python
frame = camera.read()
```

После этого кадр может поступить в алгоритм обработки.

## 7. Программная обработка

Полученное изображение проходит последовательность операций.

Например:

```text
кадр
 ↓
изменение размера
 ↓
преобразование цвета
 ↓
фильтрация
 ↓
сегментация
 ↓
поиск объекта
 ↓
измерение
 ↓
проверка допуска
```

Не всегда используются все операции.

Конкретный алгоритм зависит от задачи.

## 8. Результат

Результатом может быть простое логическое значение:

```text
OK
```

или:

```text
NOK
```

Но система может выдавать гораздо больше информации:

```text
ObjectFound = true
X = 315
Y = 184
Angle = 7.2
Width = 52.4
Height = 31.7
Defect = false
Confidence = 0.97
```

Эти данные могут использоваться другими системами.

## 9. Связь с ПЛК

В автоматизации результат часто передаётся ПЛК.

Например:

```text
Vision system
      │
      │ Ethernet
      ▼
     ПЛК
      │
      ▼
исполнительный механизм
```

ПЛК может получить:

```text
VisionReady
VisionOK
VisionNOK
PartID
PartX
PartY
PartAngle
```

После этого ПЛК управляет технологическим процессом.

## 10. Связь с роботом

Если система используется для роботизированного захвата, результат может быть другим.

Например:

```text
X = 420 мм
Y = 180 мм
Z = 75 мм
Rz = 25°
```

Робот получает координаты и выполняет движение.

Но важно понимать:

> координаты изображения и координаты робота — это не одно и то же.

Пиксель:

```text
(450, 320)
```

не означает автоматически:

```text
(450 мм, 320 мм)
```

Для перехода между системами координат требуется геометрическая модель и часто калибровка.

## 11. Механическая часть

Vision-система зависит и от механики.

Например, камера может быть установлена на:

* раме;
* кронштейне;
* роботизированной оси;
* защитном корпусе.

Если камера вибрирует, изображение может изменяться.

Если положение камеры постоянно меняется, алгоритм может перестать работать.

Поэтому механическое крепление камеры должно быть достаточно стабильным.

## 12. Защита оборудования

В промышленной среде камера может находиться рядом с:

* пылью;
* водой;
* маслом;
* вибрацией;
* высокой температурой;
* движущимися механизмами.

Поэтому могут использоваться:

* защитные корпуса;
* защитные окна;
* охлаждение;
* фильтры;
* герметичные соединения.

Это также часть инженерии машинного зрения.

## Система как цепочка

Очень полезно смотреть на vision-систему как на последовательность преобразований:

```text
Физический объект
       ↓
свет
       ↓
оптика
       ↓
матрица
       ↓
цифровое изображение
       ↓
алгоритм
       ↓
измерение
       ↓
решение
       ↓
управляющий сигнал
       ↓
физическое действие
```

Например:

```text
деталь
 ↓
камера видит деталь
 ↓
найден контур
 ↓
измерен диаметр
 ↓
диаметр = 24.92 мм
 ↓
допуск 25 ± 0.10 мм
 ↓
OK
 ↓
ПЛК получает OK
 ↓
деталь продолжает движение
```

Если диаметр равен:

```text
25.18 мм
```

результат будет:

```text
NOK
```

и ПЛК может активировать механизм удаления.

## Где находится граница между vision и автоматизацией

Граница условна.

Vision-система может отвечать за:

* получение изображения;
* анализ;
* измерение;
* классификацию;
* обнаружение дефекта.

ПЛК обычно отвечает за:

* последовательность процесса;
* блокировки;
* управление приводами;
* датчики;
* исполнительные механизмы;
* аварийную логику.

Но в конкретной системе функции могут распределяться иначе.

Главное — правильно определить ответственность каждого компонента.

## Что происходит при ошибке

Надёжная система должна учитывать не только нормальный сценарий.

Например:

```text
камера отключилась
```

Нельзя автоматически считать:

```text
NOK
```

Потому что `NOK` означает:

> изделие проверено и признано плохим.

А отсутствие изображения означает:

> изделие вообще не удалось проверить.

Это разные ситуации.

Поэтому система может различать:

```text
OK
NOK
NO_IMAGE
CAMERA_ERROR
TIMEOUT
COMMUNICATION_ERROR
```

Такой подход особенно важен в промышленной автоматизации.

## Главное

Система машинного зрения состоит из нескольких взаимосвязанных частей:

```text
объект
освещение
объектив
камера
триггер
передача изображения
вычислительная система
алгоритм
результат
система управления
```

Хорошая vision-система — это не просто хороший алгоритм.

Она должна обеспечить весь путь:

```text
стабильный объект
→ стабильное изображение
→ стабильный анализ
→ корректное решение
→ корректное действие
```

В следующих уроках подробнее разберём отдельные элементы этой цепочки.
