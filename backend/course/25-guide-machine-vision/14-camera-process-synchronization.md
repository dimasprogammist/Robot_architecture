# Синхронизация камеры с процессом

## Цель

Понять, как камера должна взаимодействовать с реальным производственным процессом и почему момент съёмки является частью системы машинного зрения.

После урока вы должны понимать:

* зачем нужен trigger;
* чем свободный видеопоток отличается от синхронной съёмки;
* как камера взаимодействует с датчиками;
* почему задержка имеет значение;
* что такое аппаратный и программный trigger;
* как синхронизировать камеру с конвейером;
* как строится полный цикл инспекции.

## Камера и реальный процесс

В лаборатории можно просто сделать:

```python
ret, frame = camera.read()
```

и обработать кадр.

Но в производстве объект может постоянно двигаться:

```text
→ → → → → → → → →
      деталь
→ → → → → → → → →
```

Нужно определить момент, когда камере следует сделать снимок.

Например:

```text
датчик
  ↓
объект обнаружен
  ↓
trigger
  ↓
camera
  ↓
image
```

Этот механизм называется синхронизацией.

## Почему нельзя просто брать любой кадр

Допустим, конвейер движется.

В одном кадре:

```text
      ███
```

через 100 мс:

```text
           ███
```

через ещё 100 мс:

```text
                ███
```

Если алгоритм работает в случайный момент, положение объекта меняется.

Для некоторых задач это допустимо.

Для точного измерения — нет.

## Trigger

Trigger — это сигнал, который сообщает камере:

> Сделай снимок сейчас.

Условно:

```text
датчик
  │
  │ trigger
  ▼
камера
  │
  ▼
кадр
```

Trigger может быть:

* аппаратным;
* программным.

## Аппаратный trigger

Аппаратный trigger приходит на вход камеры через электрический сигнал.

Например:

```text
датчик
   │
   ├──── сигнал ────→ camera trigger
   │
   └────────────────→ PLC
```

Преимущество — предсказуемость времени.

Это особенно важно при движении.

## Программный trigger

Программа может отправить команду:

```text
capture()
```

или соответствующую команду через SDK камеры.

Схема:

```text
PLC / application
       ↓
 software trigger
       ↓
     camera
       ↓
     image
```

Такой способ проще, но временная точность зависит от программного стека.

## Свободный режим

Камера может работать постоянно:

```text
frame 1
frame 2
frame 3
frame 4
...
```

Программа получает поток и пытается найти объект.

Это удобно для:

* наблюдения;
* операторского интерфейса;
* трекинга;
* некоторых задач контроля.

Но для точной синхронизации с производственным событием trigger обычно удобнее.

## Конвейер

Рассмотрим конвейер:

```text
→ → → → → → → → → →

        деталь

→ → → → → → → → → →
             ↑
           датчик
```

Когда передний край детали проходит датчик:

```text
sensor = ON
```

формируется trigger.

Но камера должна сфотографировать деталь не обязательно в ту же миллисекунду.

Если камера расположена дальше по конвейеру:

```text
датчик ───────────── камера
        расстояние L
```

нужно учитывать время движения.

## Расчёт задержки

Пусть:

```text
L = 500 мм
```

скорость:

```text
v = 250 мм/с
```

Тогда время движения:

```text
t = L / v
```

получаем:

```text
t = 500 / 250 = 2 с
```

Следовательно, если объект должен фотографироваться у камеры после прохождения датчика, нужно учитывать примерно 2 секунды.

## Скорость может изменяться

Если конвейер работает:

```text
v = 200 мм/с
```

время:

```text
500 / 200 = 2.5 с
```

Если:

```text
v = 300 мм/с
```

получаем:

```text
500 / 300 ≈ 1.67 с
```

Поэтому фиксированная задержка может быть недостаточной, если скорость переменная.

## Энкодер

Для движущихся механизмов можно использовать энкодер.

Он сообщает, насколько переместился механизм.

Например:

```text
encoder pulses
      ↓
distance traveled
      ↓
trigger camera
```

Вместо:

```text
ждать 2 секунды
```

можно использовать:

```text
ждать перемещение 500 мм
```

Это намного устойчивее к изменению скорости.

## Синхронизация с ПЛК

Часто ПЛК управляет процессом:

```text
PLC
 │
 ├── conveyor
 │
 ├── sensor
 │
 └── camera trigger
```

Камера после съёмки возвращает результат:

```text
camera
  │
  └── inspection result
             ↓
            PLC
```

Получается замкнутый цикл:

```text
процесс
  ↓
датчик
  ↓
камера
  ↓
анализ
  ↓
результат
  ↓
ПЛК
  ↓
действие
```

## Номер детали

Если детали движутся последовательно, важно понимать, к какой именно детали относится результат.

Например:

```text
Part 101 → camera
Part 102 → camera
Part 103 → camera
```

Если обработка занимает разное время, результаты могут прийти в другом порядке.

Поэтому полезно иметь идентификатор:

```text
PartID = 101
```

и связывать его с результатом.

## Очередь результатов

Условно:

```text
Part 101 → inspection
Part 102 → inspection
Part 103 → inspection
```

Результаты:

```text
101 → OK
102 → NOK
103 → OK
```

ПЛК или управляющее приложение должно знать, какой результат относится к какой детали.

## Задержка обработки

Пусть:

```text
trigger → image = 20 ms
image → result = 80 ms
```

Общая задержка:

```text
100 ms
```

Если деталь за это время перемещается, результат может быть уже поздним.

Поэтому необходимо учитывать полный latency:

```text
sensor
 ↓
trigger
 ↓
exposure
 ↓
transfer
 ↓
processing
 ↓
decision
 ↓
actuator
```

## Экспозиция тоже влияет

Если объект движется со скоростью:

```text
1000 мм/с
```

и экспозиция:

```text
10 мс
```

то за время экспозиции объект переместится:

```text
1000 × 0.010 = 10 мм
```

Это может привести к сильному смазыванию.

Поэтому синхронизация и экспозиция связаны.

## Импульсная подсветка

Чтобы уменьшить смазывание, используют короткий импульс света:

```text
trigger
  ↓
flash
  ↓
camera exposure
```

Например:

```text
экспозиция камеры = 5 мс
```

но эффективная подсветка действует:

```text
0.1 мс
```

Тогда движение объекта во время освещения значительно меньше.

## Синхронизация камеры и света

Типичная схема:

```text
trigger
   │
   ├────────→ camera
   │
   └────────→ light controller
                    │
                    ↓
                  flash
```

Важно, чтобы камера и подсветка работали согласованно.

Если камера снимает в темноте:

```text
кадр → плохой
```

если свет включается слишком поздно:

```text
кадр → недостаточно освещён
```

## Trigger delay

Иногда камера или контроллер поддерживает задержку:

```text
trigger
   ↓
delay = 20 ms
   ↓
exposure
```

Это позволяет подстроить момент съёмки относительно движения детали.

## Положение датчика

Если датчик установлен слишком далеко:

```text
датчик ---------------- камера
```

задержка движения может стать большой.

Если слишком близко:

```text
датчик --- камера
```

может не хватить времени на:

* запуск света;
* экспозицию;
* передачу;
* обработку.

Поэтому положение датчика — часть проектирования системы.

## Синхронизация нескольких камер

Иногда один объект снимают несколькими камерами:

```text
          camera 1
             ↓
        ┌─────────┐
        │ объект  │
        └─────────┘
             ↑
          camera 2
```

Важно, чтобы кадры относились к одному моменту процесса.

В некоторых системах используется общий trigger:

```text
trigger
 ├── camera 1
 ├── camera 2
 └── light
```

## Асинхронная обработка

Камера может продолжать получать кадры, пока программа обрабатывает предыдущий.

Например:

```text
Camera:
frame 1 → frame 2 → frame 3 → frame 4

Processor:
       frame 1 → processing
                  frame 2 → processing
```

Это повышает производительность.

Но необходимо правильно управлять очередью и не потерять соответствие между объектом и результатом.

## Состояния процесса

Полезно описывать систему состояниями:

```text
WAIT_PART
    ↓
TRIGGER
    ↓
CAPTURE
    ↓
PROCESS
    ↓
RESULT
    ↓
WAIT_PART
```

При ошибке:

```text
ERROR
```

Такую архитектуру проще диагностировать.

## Watchdog

Для промышленной системы полезно контролировать, что камера отвечает.

Например:

```text
CameraConnected = TRUE
LastFrameTime = ...
```

Если кадров давно нет:

```text
CameraTimeout = TRUE
```

Система может перейти в безопасное состояние.

## Ошибки синхронизации

Возможны:

* двойной trigger;
* пропущенный trigger;
* задержка камеры;
* потеря кадра;
* неверная скорость конвейера;
* неправильная задержка;
* несинхронный свет;
* результат относится не к той детали.

Такие ошибки нужно учитывать ещё на этапе проектирования.

## Полный промышленный цикл

Например:

```text
1. деталь движется
        ↓
2. датчик обнаруживает деталь
        ↓
3. формируется trigger
        ↓
4. включается подсветка
        ↓
5. камера делает снимок
        ↓
6. изображение передаётся
        ↓
7. выполняется анализ
        ↓
8. результат связывается с деталью
        ↓
9. результат передаётся в ПЛК
        ↓
10. ПЛК выполняет действие
```

## Главное

Камера в машинном зрении не существует отдельно от производственного процесса.

Нужно синхронизировать:

```text
датчик
+
камера
+
подсветку
+
конвейер
+
обработку
+
ПЛК
```

Главный принцип:

> Важно не только получить хорошее изображение, но и получить правильное изображение правильного объекта в правильный момент времени.

Именно синхронизация превращает отдельную камеру в часть автоматизированной системы.
