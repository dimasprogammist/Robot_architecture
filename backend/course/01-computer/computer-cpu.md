# Процессор

Процессор, или CPU (Central Processing Unit), — вычислительная часть системы, которая **исполняет машинные инструкции**.

Когда программа должна сложить числа, сравнить значения, изменить переменную, выполнить условный переход или обработать данные, в конечном счёте соответствующие машинные операции выполняются исполнительными блоками процессора.

При этом CPU не работает отдельно от остальных компонентов:

```text
             Программа
                 │
                 │ инструкции
                 ▼
┌-----------┐  ┌--------------┐
│    RAM    │◄►│     CPU      │
└-----------┘  │              │
               │ регистры     │
               │ ALU          │
               │ управление   │
               │ кэш          │
               └------┬-------┘
                      │
             ┌--------┼---------┐
             ▼        ▼         ▼
           SSD       сеть     периферия
```

Поэтому процессор можно назвать исполнителем программы, но нельзя считать его единственным фактором производительности всей системы.

---

## Что именно выполняет CPU

Допустим, программа должна вычислить:

```text
a = 10
b = 20
c = a + b
```

Для человека это три действия.

Для процессора задача раскладывается на множество операций:

```text
получить инструкцию
       ↓
получить необходимые данные
       ↓
выполнить операцию
       ↓
сохранить результат
       ↓
перейти к следующей инструкции
```

Сам процессор не понимает Python, C++ или русский язык.

Он понимает машинные инструкции, определённые его архитектурой.

Среди них существуют инструкции для:

* сложения;
* вычитания;
* сравнения;
* логических операций;
* загрузки данных;
* записи данных;
* переходов;
* работы с адресами;
* операций над различными типами чисел.

Сложные программы строятся из огромного количества таких более простых операций.

---

## Цикл выполнения инструкции

Для первого понимания удобно использовать модель:

```text
             ┌---------------┐
             │ Счётчик       │
             │ команд (PC)   │
             └-------┬-------┘
                     │
                     ▼
              ┌------------┐
Память ------►│   Fetch    │
              │  выборка   │
              └-----┬------┘
                    │
                    ▼
              ┌------------┐
              │   Decode   │
              │ декодир.   │
              └-----┬------┘
                    │
                    ▼
              ┌------------┐
              │  Execute   │
              │ исполнение │
              └-----┬------┘
                    │
                    ▼
                результат
```

Это упрощение. Современный CPU выполняет много операций параллельно и использует конвейер, предсказание переходов, кэши и другие механизмы.

Но базовая идея остаётся полезной.

### 1. Процессор определяет следующую инструкцию

Для этого используется **счётчик команд** — Program Counter, PC.

Условно:

```text
PC = 0x1000
```

означает, что следующая инструкция связана с адресом `0x1000`.

Процессор получает соответствующие данные из подсистемы памяти.

### 2. Инструкция декодируется

Полученная последовательность битов должна быть интерпретирована как конкретная операция.

Процессор определяет:

```text
какая операция?
какие операнды?
где находятся данные?
куда должен попасть результат?
```

### 3. Инструкция выполняется

Если это сложение, данные поступают в соответствующий исполнительный блок.

Если это загрузка, процессор получает данные из памяти.

Если это переход, меняется поток исполнения программы.

### 4. Результат используется дальше

Результат может оказаться:

* в регистре;
* в памяти;
* в состоянии процессора;
* использоваться следующей инструкцией.

После этого выполнение продолжается.

## Регистры

Процессору постоянно нужны небольшие объёмы данных, поэтому внутри CPU находятся **регистры**.

Упрощённо:

```text
┌----------------------------┐
│            CPU             │
│                            │
│ Register A = 25            │
│ Register B = 17            │
│                            │
│          ┌-----┐           │
│          │ ALU │           │
│          └--┬--┘           │
│             │              │
│          25 + 17           │
│             │              │
│ Register C = 42            │
└----------------------------┘
```

Регистры находятся непосредственно внутри вычислительной части процессора и используются для текущих данных, адресов, состояния и других служебных задач.

Их количество и назначение зависят от архитектуры CPU.

---

## ALU и исполнительные блоки

ALU (Arithmetic Logic Unit) — арифметико-логическое устройство.

Оно выполняет операции вроде:

```text
10 + 5
10 - 5
10 AND 5
10 OR 5
10 < 20
```

Но современный процессор обычно не содержит только один ALU.

Внутри CPU находится множество исполнительных блоков, которые могут выполнять разные типы операций.

Упрощённая схема:

```text
                  CPU
                   │
          ┌--------┴--------┐
          ▼                 ▼
       Регистры       Исполнительные
                         блоки
                       ┌---┼---┐
                       ▼   ▼   ▼
                      ALU ... ...
                       │
                       ▼
                    результат
```

Именно наличие нескольких исполнительных блоков позволяет современному процессору выполнять большое количество работы параллельно.

---

## Как Python или C++ доходят до CPU

Исходный код не является машинными инструкциями процессора.

Например:

```text
a = 10
b = 20
c = a + b
```

В типичной системе с CPython происходит примерно следующее:

```text
Python-код
    ↓
CPython
    ↓
байткод
    ↓
работа интерпретатора
    ↓
машинные инструкции
    ↓
CPU
```

В C/C++ типичная схема:

```text
Исходный код
     ↓
компилятор
     ↓
машинный код
     ↓
CPU
```

Поэтому:

```text
c = a + b
```

не означает:

> одна строка Python = одна инструкция CPU.

В реальной системе за одной строкой может скрываться большое количество операций.

---

## Почему процессору нужна память

Регистры очень быстрые, но их мало.

Программы могут работать с гигабайтами данных.

Поэтому используется иерархия:

```text
             быстрее
                ▲
                │
            Регистры
                │
               L1
                │
               L2
                │
               L3
                │
               RAM
                │
               SSD
                │
                ▼
             медленнее
```

Чем ближе уровень к вычислительным блокам CPU, тем он обычно меньше и быстрее.

Это компромисс между:

```text
скоростью
объёмом
стоимостью
```

Сделать всю систему из очень быстрой памяти было бы слишком дорого и сложно.

---

## Кэш

Кэш предназначен для данных и инструкций, которые процессору, вероятно, скоро снова понадобятся.

Например:

```text
массив:

[10][20][30][40][50][60][70][80]
 ↑
 последовательный доступ
```

Если программа обрабатывает элементы последовательно, подсистема памяти может эффективно загружать их блоками.

Это называется использованием **локальности данных**.

При случайном доступе:

```text
[10] → [700000] → [25] → [900000] → [400]
```

поведение кэша и подсистемы памяти может быть значительно хуже.

Упрощённо:

```text
CPU
 │
 ├-- данные в кэше
 │       │
 │       ▼
 │     быстро
 │
 └── данных нет
         │
         ▼
        RAM
         │
         ▼
      ожидание
```

Если нужные данные найдены в кэше, происходит cache hit.

Если их там нет и требуется получить их с более медленного уровня, происходит cache miss.

Поэтому алгоритм с хорошей локальностью данных иногда работает быстрее другого алгоритма с похожим количеством вычислений.

---

## Тактовая частота

CPU работает с тактовым сигналом.

Например:

```text
3.5 GHz
```

означает примерно 3,5 миллиарда тактов в секунду.

Но нельзя считать:

```text
3.5 GHz = 3.5 миллиарда инструкций в секунду
```

Это неверно.

Разные инструкции требуют разных ресурсов, а современные CPU могут одновременно выполнять несколько операций.

На производительность влияют:

* архитектура;
* тактовая частота;
* количество исполнительных блоков;
* кэш;
* память;
* количество ядер;
* эффективность конвейера;
* характер программы;
* ветвления;
* синхронизация;
* ожидание I/O.

Поэтому процессор на 4 GHz не обязательно вдвое быстрее процессора на 2 GHz.

---

## Конвейер

Современный CPU не обязательно ждёт полного завершения одной инструкции перед началом следующей.

Упрощённо:

```text
Такты:       1        2        3        4        5

Instr 1:   Fetch → Decode → Execute → Write
Instr 2:            Fetch → Decode → Execute → Write
Instr 3:                     Fetch → Decode → Execute → Write
```

Получается конвейер.

Пока одна инструкция находится на этапе исполнения, другая может декодироваться, а третья — загружаться.

Реальные процессоры идут значительно дальше:

* несколько исполнительных блоков;
* предсказание переходов;
* выполнение операций вне исходного порядка;
* предварительная загрузка данных;
* несколько инструкций одновременно.

Поэтому современный CPU нельзя представлять как устройство, которое делает строго:

```text
инструкция 1
инструкция 2
инструкция 3
инструкция 4
```

по одной полностью последовательно.

---

## Несколько ядер

Одно ядро — отдельный вычислительный ресурс, способный выполнять поток инструкций.

Например, процессор с четырьмя ядрами можно представить так:

```text
┌------------------------------┐
│             CPU              │
│                              │
│  ┌───────┐  ┌───────┐        │
│  │ Core0 │  │ Core1 │        │
│  └───────┘  └───────┘        │
│                              │
│  ┌───────┐  ┌───────┐        │
│  │ Core2 │  │ Core3 │        │
│  └───────┘  └───────┘        │
└------------------------------┘
```

Разные потоки могут выполняться параллельно:

```text
Core 0 → задача A
Core 1 → задача B
Core 2 → задача C
Core 3 → задача D
```

Но четыре ядра не делают любую программу автоматически в четыре раза быстрее.

Если программа имеет строго последовательную зависимость:

```text
Шаг 1
  ↓
Шаг 2
  ↓
Шаг 3
  ↓
Шаг 4
```

эти операции нельзя просто распределить между четырьмя ядрами.

Для ускорения необходимо иметь работу, которую можно безопасно разделить.

---

## CPU и операционная система

Если одновременно работают:

```text
браузер
IDE
терминал
музыка
системные службы
```

то операционная система должна распределять вычислительное время между их процессами и потоками.

Упрощённо:

```text
                  CPU
                   ▲
                   │
             Планировщик ОС
             ┌-----┼-----┐
             │     │     │
          браузер  IDE  терминал
```

CPU физически исполняет инструкции.

ОС определяет, **какой поток когда получает возможность их исполнять**.

---

## Прерывания

Компьютер должен реагировать на события:

```text
пришёл сетевой пакет
нажата клавиша
сработал таймер
устройство закончило операцию
произошла аппаратная ошибка
```

Для этого используются прерывания.

Упрощённый сценарий:

```text
Сетевой адаптер
      │
      │ пакет
      ▼
  interrupt
      │
      ▼
     CPU
      │
      ▼
 обработчик
      │
      ▼
возврат к работе
```

В микроконтроллере похожий механизм может выглядеть так:

```text
Таймер
  │
  ▼
 IRQ
  │
  ▼
 ISR
  │
  ├── прочитать датчик
  ├── обновить состояние
  └── завершиться
```

В обычной ОС большую часть этой инфраструктуры предоставляют ядро и драйверы.

В микроконтроллере обработчик часто является частью вашей прошивки.

---

## Почему быстрый CPU не гарантирует быструю программу

Рассмотрим программу, которая читает большой файл:

```text
SSD
 │
 ▼
RAM
 │
 ▼
CPU
 │
 ▼
результат
```

Если данные ещё не получены с диска, более быстрый CPU не сможет вычислить их раньше.

Другой пример:

```text
CPU
 │
 ▼
запрос в сеть
 │
 ▼
ожидание
 │
 ▼
ответ
 │
 ▼
CPU
```

Время ожидания сети может быть гораздо больше времени вычисления.

Поэтому полезно различать характер нагрузки.

### CPU-bound

Большая часть времени уходит на вычисления:

```text
CPU → CPU → CPU → CPU → результат
```

### I/O-bound

Большая часть времени уходит на ожидание:

```text
CPU → диск/сеть → ожидание → CPU
```

### Memory-bound

CPU постоянно ждёт данные:

```text
CPU -----► RAM
 ▲          │
 │ ожидание │
 └----------┘
```

В каждом случае узкое место находится в другой части системы.

---

## Пример с массивом

Пусть программа суммирует миллион чисел:

```text
total = 0

for value in numbers:
    total += value
```

Концептуально внутри цикла происходит:

```text
получить следующий элемент
        ↓
получить total
        ↓
сложить
        ↓
сохранить результат
        ↓
перейти дальше
```

Если данные расположены последовательно:

```text
[10][20][30][40][50][60]
 ↑
 читаем последовательно
```

это хорошо соответствует локальности.

При хаотическом доступе:

```text
[10] → [700000] → [25] → [900000]
```

кэш и подсистема памяти работают менее эффективно.

Поэтому количество математических операций — не единственный показатель сложности реального выполнения.

---

## Пример из робототехники

Пусть контроллер получает данные от датчика каждые 1 мс.

```text
          ┌-----------┐
          │   Таймер  │
          └-----┬-----┘
                │
             interrupt
                │
                ▼
          ┌-----------┐
          │    CPU    │
          └-----┬-----┘
                │
                ▼
          обработчик
                │
                ▼
          чтение датчика
                │
                ▼
            буфер
```

Каждое событие должно быть обработано вовремя.

Здесь недостаточно сказать:

> «CPU мощный, значит всё успеет».

На задержку влияют:

* прерывания;
* планирование;
* конкуренция за CPU;
* кэш;
* память;
* драйверы;
* другие процессы;
* операционная система;
* архитектура системы.

Поэтому в робототехнике важна не только средняя производительность, но и предсказуемость времени реакции.

---

## Где используется CPU в роботе

В сложной робототехнической системе вычисления могут быть распределены:

```text
                       Робот
                         │
          ┌--------------┼--------------┐
          ▼              ▼              ▼
   Микроконтроллер  Промышленный ПК    GPU
          │              │              │
          ▼              ▼              ▼
       моторы         логика, сеть    нейросети
       энкодеры       БД, UI, Python   vision
```

Микроконтроллер подходит для задач с жёсткими временными ограничениями.

Промышленный компьютер — для высокоуровневой логики, сети, интерфейса, хранения и обработки данных.

GPU — для задач с большим количеством параллельных вычислений, например компьютерного зрения и нейросетей.

---

## Как искать причину медленной работы

Не стоит начинать с:

```text
Медленно
  ↓
Нужен процессор мощнее
```

Инженерный путь:

```text
Проблема
   ↓
Измерение
   ↓
Поиск узкого места
   ↓
Изменение
   ↓
Повторное измерение
```

Сначала определяем, где реально тратится время:

```text
Программа
 ├── CPU
 ├── RAM
 ├── диск
 ├── сеть
 ├── синхронизация
 └── ожидание устройств
```

Если приложение 90% времени ждёт базу данных, новый CPU почти ничего не изменит.

Если 90% времени занимает математический расчёт, ситуация уже другая.

## Практика

### 1. Исследуйте свой CPU

Найдите в своей системе:

* модель процессора;
* архитектуру;
* количество физических ядер;
* количество логических потоков;
* базовую частоту;
* максимальную частоту, если она указана.

Затем объясните своими словами:

> Чем физическое ядро отличается от логического потока?

### 2. Сравните вычисление и ожидание

Создайте программу, которая выполняет много вычислений:

```text
total = 0

for i in range(50_000_000):
    total += i

print(total)
```

И программу, которая просто ждёт:

```text
import time

time.sleep(10)
```

Посмотрите загрузку CPU.

Объясните:

* почему первая программа активно использует CPU;
* почему вторая почти не использует CPU;
* почему обе при этом остаются запущенными.

### 3. Разберите собственную программу

Возьмите знакомый проект и найдите:

```text
Что считает CPU?
Что читает программа?
Что хранится в RAM?
Есть ли ожидание сети?
Есть ли ожидание диска?
Где может быть узкое место?
```

### 4. Разберите задачу робота

Для системы:

```text
датчик → контроллер → обработка → двигатель
```

определите, какую часть логично выполнять:

* на микроконтроллере;
* на промышленном компьютере;
* на GPU.

Важно объяснить не только **где** выполнять задачу, но и **почему**.

## Что нужно запомнить

* CPU исполняет машинные инструкции.
* Инструкция проходит через выборку, декодирование и исполнение — это упрощённая модель работы.
* Регистры хранят небольшие объёмы текущих данных непосредственно внутри CPU.
* ALU выполняет арифметические и логические операции.
* Кэш ускоряет доступ к часто используемым данным и инструкциям.
* Тактовая частота сама по себе не определяет производительность.
* Конвейер позволяет перекрывать выполнение разных стадий.
* Несколько ядер позволяют выполнять независимую работу параллельно.
* Прерывания позволяют реагировать на внешние события.
* Программа может быть CPU-bound, I/O-bound или memory-bound.
* В робототехнике важны не только вычислительная мощность, но и задержки и предсказуемость реакции.
* Производительность нужно измерять по всей системе, а не оценивать только по модели CPU.
