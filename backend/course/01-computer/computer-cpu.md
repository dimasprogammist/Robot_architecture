# Процессор

Процессор (CPU, Central Processing Unit) — часть компьютера, которая выполняет машинные инструкции программ. Когда программа должна что-то вычислить, сравнить, переместить данные или принять решение, в конечном счёте эту работу выполняют исполнительные блоки процессора.

При этом CPU не работает изолированно. Для выполнения программы ему постоянно нужны данные и инструкции из памяти, результаты могут передаваться другим устройствам, а сама программа работает под управлением операционной системы или, в микроконтроллере, непосредственно прошивки.

Удобно представить компьютер как систему:

```text
                ┌───────────────┐
                │   Программа   │
                └───────┬───────┘
                        │ инструкции
                        ▼
┌──────────────┐   ┌───────────────┐
│     RAM      │◄─►│      CPU      │
└──────────────┘   │               │
                   │  регистры     │
                   │  ALU          │
                   │  управление   │
                   │  кэш          │
                   └───────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
            SSD          Сеть       Устройства
```

Поэтому процессор можно считать «исполнителем» программы, но скорость всей системы определяется не только им.

## Что именно делает процессор

На самом простом уровне CPU постоянно выполняет последовательность инструкций.

Например, программа должна вычислить:

```text
a = 10
b = 20
c = a + b
```

Для человека это три понятных действия. Для процессора задача раскладывается на множество более мелких операций:

```text
получить инструкцию
        ↓
получить необходимые данные
        ↓
выполнить операцию
        ↓
записать результат
        ↓
перейти к следующей инструкции
```

Сам процессор не понимает Python, C++ или русский язык. Он работает с машинными инструкциями, определёнными архитектурой процессора.

Например, в зависимости от архитектуры существуют инструкции для:

* сложения;
* вычитания;
* сравнения;
* загрузки данных из памяти;
* записи данных в память;
* перехода на другой адрес программы;
* логических операций;
* работы с числами разных типов;
* взаимодействия с некоторыми специальными аппаратными механизмами.

Из этих простых операций строится выполнение гораздо более сложных программ.

## Выполнение одной инструкции

Для начала удобно использовать упрощённую модель:

```text
             ┌──────────────┐
             │ Счётчик      │
             │ команд       │
             └──────┬───────┘
                    │
                    ▼
               ┌─────────┐
Память ───────►│ Fetch   │
               │ выборка │
               └────┬────┘
                    │
                    ▼
               ┌─────────┐
               │ Decode  │
               │ разбор  │
               └────┬────┘
                    │
                    ▼
               ┌─────────┐
               │ Execute │
               │         │
               └────┬────┘
                    │
                    ▼
              Результат
                    │
                    ▼
             Следующая
              инструкция
```

Это называется циклом выполнения инструкции.

### 1. Выборка инструкции

Процессор должен узнать, какую инструкцию выполнять следующей.

Для этого используется специальное значение — **счётчик команд** (Program Counter, PC).

Он содержит адрес инструкции, которую необходимо получить.

Условно:

```text
PC = 0x1000
```

означает:

> следующая инструкция находится по адресу `0x1000`.

Процессор обращается к памяти и получает находящуюся там инструкцию.

### 2. Декодирование

Полученная последовательность битов сама по себе не является для процессора человеческим текстом вроде:

```text
сложить A и B
```

Процессор должен определить:

* какая операция требуется;
* какие данные используются;
* где находятся операнды;
* куда должен попасть результат;
* нужны ли дополнительные обращения к памяти.

Этот этап называется **декодированием инструкции**.

### 3. Исполнение

После определения операции процессор выполняет её.

Например:

```text
5 + 7
```

может привести к операции сложения внутри арифметико-логического устройства CPU.

Для другой инструкции исполнительным действием может быть:

```text
прочитать данные из памяти
```

или:

```text
перейти на другой адрес программы
```

### 4. Получение результата

Результат операции может оказаться:

* в регистре;
* в памяти;
* в специальном состоянии процессора;
* в другом месте, которое предусмотрено конкретной инструкцией.

После этого процессор продолжает выполнение программы.

Важно понимать, что реальный современный процессор устроен значительно сложнее этой модели. Он использует конвейер, кэширование, предсказание переходов, выполнение нескольких инструкций одновременно и другие механизмы.

Но базовая модель «получить инструкцию → понять её → выполнить» остаётся полезной для понимания принципа работы.

## Регистры — самые быстрые рабочие данные CPU

Во время вычислений процессору постоянно нужны небольшие объёмы данных.

Для этого внутри CPU находятся **регистры**.

Условно можно представить:

```text
┌────────────────────────────┐
│            CPU             │
│                            │
│  Регистр A:       25       │
│  Регистр B:       17       │
│  Регистр C:       42       │
│                            │
│          ALU               │
│       25 + 17 = 42         │
└────────────────────────────┘
```

Регистры значительно ближе к исполнительным блокам CPU, чем оперативная память.

Например, если процессору нужно выполнить:

```text
25 + 17
```

условно можно представить последовательность:

```text
регистр A = 25
регистр B = 17

        ↓

       ALU
    25 + 17

        ↓

регистр C = 42
```

Регистры также используются для служебных данных, адресов, состояния процессора и других задач.

Количество и назначение регистров зависят от архитектуры процессора.

## Арифметико-логическое устройство

Одним из основных исполнительных блоков CPU является **ALU** (Arithmetic Logic Unit) — арифметико-логическое устройство.

Оно выполняет различные операции над данными:

```text
10 + 5
10 - 5
10 AND 5
10 OR 5
10 < 20
```

Это не означает, что современный процессор состоит из одного ALU. В реальных CPU есть множество исполнительных блоков, специализирующихся на разных типах операций.

Упрощённо:

```text
                 CPU
                  │
        ┌─────────┴─────────┐
        │                   │
     Регистры              ALU
        │                   │
        └─────────┬─────────┘
                  │
               Результат
```

Процессор получает данные, передаёт их исполнительным блокам и сохраняет полученный результат.

## Как программа связана с машинными инструкциями

Когда мы пишем:

```python
a = 10
b = 20
c = a + b
print(c)
```

процессор не получает этот текст напрямую как последовательность инструкций CPU.

В случае CPython сначала запускается сам интерпретатор Python, который является программой, скомпилированной для конкретной платформы.

Упрощённая цепочка выглядит так:

```text
Python-код
    ↓
Интерпретатор Python
    ↓
байткод Python
    ↓
работа интерпретатора
    ↓
машинные инструкции CPU
    ↓
вычисления
```

В C или C++ типичный путь выглядит иначе:

```text
Исходный код
    ↓
Компилятор
    ↓
Машинный код
    ↓
CPU
```

Поэтому строка:

```python
a = 10
b = 20
c = a + b
```

не означает:

> «процессор выполнил одну инструкцию».

На реальном компьютере за ней может стоять множество операций самого интерпретатора.

Это одна из причин, почему знание языка программирования и понимание работы процессора — разные уровни абстракции.

## Память и процессор работают вместе

CPU не может хранить все данные программы внутри своих регистров.

Поэтому существует несколько уровней хранения:

```text
        Быстрее
           ▲
           │
      Регистры
           │
          L1
           │
          L2
           │
          L3
           │
          RAM
           │
          SSD
           │
           ▼
        Медленнее
```

Чем ближе уровень к вычислительным блокам CPU, тем меньше он обычно по объёму и тем быстрее доступ к нему.

### Почему нельзя сделать всю память как регистры?

Потому что пришлось бы использовать огромное количество очень быстрой и дорогой аппаратуры.

Вместо этого компьютер использует иерархию памяти.

Небольшой объём самых быстрых данных находится рядом с вычислительными блоками, а большие объёмы более медленной памяти используются для хранения остальной информации.

## Кэш процессора

**Кэш** — это небольшая быстрая память, предназначенная для хранения данных и инструкций, которые процессору с высокой вероятностью скоро снова понадобятся.

Например, программа обрабатывает массив:

```text
[10][20][30][40][50][60][70][80]
```

Если элементы расположены подряд, процессор и система памяти могут эффективно загружать данные блоками.

Это хорошо соответствует принципу **локальности данных**.

Если программа постоянно обращается к соседним элементам:

```text
10 → 20 → 30 → 40 → 50
```

доступ к памяти обычно эффективнее, чем при хаотических обращениях:

```text
10 → 700000 → 25 → 900000 → 400
```

Поэтому два алгоритма, выполняющих похожее количество математических операций, могут показывать разную производительность на реальном компьютере.

### Cache hit и cache miss

Упрощённо:

```text
CPU
 │
 ├── данные есть в кэше ─────► быстро получили
 │
 └── данных нет
          │
          ▼
         RAM
          │
          ▼
      загрузка данных
```

Если нужные данные уже находятся в кэше — это **cache hit**.

Если их там нет и приходится получать их из более медленного уровня памяти — **cache miss**.

Это одна из причин, почему архитектура алгоритма и расположение данных в памяти имеют значение.

## Тактовая частота

Процессор работает с определённым тактовым сигналом.

Например:

```text
3.5 GHz
```

означает примерно 3,5 миллиарда тактов в секунду.

Но очень важно не делать вывод:

> 3.5 GHz = 3.5 миллиарда инструкций в секунду.

Это неверно.

Разные инструкции требуют разного количества ресурсов и времени, а современные CPU могут выполнять несколько операций параллельно.

На производительность влияют как минимум:

* тактовая частота;
* архитектура CPU;
* количество исполнительных блоков;
* эффективность конвейера;
* кэш;
* подсистема памяти;
* количество ядер;
* возможность параллельного выполнения;
* характер самой программы.

Поэтому процессор с частотой 4 GHz не обязательно будет в два раза быстрее процессора с частотой 2 GHz.

## Конвейер и параллельное выполнение

Современный CPU не обязательно полностью заканчивает одну инструкцию, прежде чем начать работу со следующей.

Упрощённо несколько стадий могут работать одновременно:

```text
Такты:      1       2       3       4       5

Instr 1:  Fetch → Decode → Execute → Write
Instr 2:          Fetch → Decode  → Execute → Write
Instr 3:                  Fetch → Decode → Execute → Write
```

Это похоже на конвейер на производстве: пока одна инструкция находится на одном этапе, следующая уже может проходить предыдущий этап.

Реальные процессоры делают это намного сложнее:

* используют несколько исполнительных блоков;
* могут менять порядок выполнения некоторых операций;
* предсказывают результат условных переходов;
* заранее загружают данные;
* выполняют несколько инструкций за определённый промежуток времени.

Для первого знакомства не требуется знать все детали реализации.

Главное понять:

> Современный CPU не просто последовательно выполняет одну инструкцию за другой в абсолютно примитивном режиме. Внутри него одновременно происходит много работы.

## Несколько ядер

Одно ядро — это исполнительный блок, способный выполнять поток инструкций.

Если в процессоре несколько ядер:

```text
┌──────────────────────────────┐
│             CPU              │
│                              │
│  ┌──────┐  ┌──────┐          │
│  │Core 0│  │Core 1│          │
│  └──────┘  └──────┘          │
│                              │
│  ┌──────┐  ┌──────┐          │
│  │Core 2│  │Core 3│          │
│  └──────┘  └──────┘          │
└──────────────────────────────┘
```

разные потоки работы могут выполняться параллельно.

Например:

```text
Core 0 → программа A
Core 1 → программа B
Core 2 → программа C
Core 3 → программа D
```

Но из этого не следует, что любая программа автоматически станет в четыре раза быстрее.

Если программа выполняется одним последовательным потоком:

```text
Шаг 1 → Шаг 2 → Шаг 3 → Шаг 4
```

добавление других ядер само по себе не позволяет выполнить эти шаги одновременно, если между ними существуют зависимости.

Для реального ускорения программа должна иметь работу, которую можно безопасно разделить.

## Процессор и операционная система

Процессор выполняет инструкции, а операционная система управляет тем, какие программы получают доступ к CPU, памяти и устройствам.

Например, одновременно запущены:

```text
Браузер
IDE
Музыка
Терминал
Системные службы
```

CPU физически не получает от пользователя команды:

> «теперь выполняй браузер».

Операционная система организует выполнение процессов и потоков, переключая их и распределяя доступное вычислительное время.

Упрощённо:

```text
                 CPU
                  ▲
                  │
          планировщик ОС
          ┌───────┼───────┐
          │       │       │
        Браузер   IDE   Терминал
```

Поэтому операционная система и процессор выполняют разные роли:

* CPU физически исполняет инструкции;
* ОС управляет процессами и ресурсами.

## Прерывания: как процессор узнаёт о событиях

Компьютеру постоянно приходится реагировать на внешние события.

Например:

* пришёл сетевой пакет;
* пользователь нажал клавишу;
* завершилась операция устройства;
* сработал таймер;
* устройство сообщило об ошибке.

Для этого используются **прерывания**.

Упрощённый сценарий:

```text
Сетевой адаптер
      │
      │ «пришёл пакет»
      ▼
  Прерывание
      │
      ▼
     CPU
      │
      ▼
Обработчик события
      │
      ▼
Возврат к предыдущей работе
```

Представим, что процессор выполнял другую программу:

```text
Программа A
    │
    │ работает
    ▼
Сетевой пакет пришёл
    │
    ▼
Прерывание
    │
    ▼
Обработчик сетевого события
    │
    ▼
Возврат к программе A
```

Поэтому внешнее событие не требует постоянного опроса устройства процессором.

В микроконтроллере механизм похож по принципу:

```text
Таймер
  │
  ▼
IRQ
  │
  ▼
ISR
  │
  ├── прочитать датчик
  ├── обновить переменную
  └── выйти
```

Разница в том, кто написал обработчик и какие требования предъявляются ко времени реакции.

В обычной ОС значительную часть такой работы выполняет ядро ОС и драйверы.

В микроконтроллере обработчик прерывания часто является частью непосредственно вашей прошивки.

## Почему CPU не является единственным фактором производительности

Рассмотрим программу, которая читает огромный файл.

```text
SSD
 │
 │ данные
 ▼
RAM
 │
 ▼
CPU
 │
 ▼
обработка
```

Даже очень быстрый CPU не сможет мгновенно обработать данные, которых ещё нет в памяти.

Другой пример:

```text
CPU → запрос в сеть → ожидание ответа
```

Здесь значительную часть времени процессор может вообще ничего полезного не вычислять.

Поэтому программы условно можно разделять по характеру ограничения.

### CPU-bound

Основное время уходит на вычисления:

```text
RAM → CPU → CPU → CPU → CPU → результат
```

Ускорение CPU потенциально может дать заметный результат.

### I/O-bound

Программа большую часть времени ждёт:

```text
CPU → диск
       │
       │ ожидание
       ▼
     данные
       │
       ▼
      CPU
```

В этом случае замена процессора на более мощный может почти ничего не изменить.

### Memory-bound

Процессор постоянно ждёт данные из памяти:

```text
CPU ──────► RAM
 ▲          │
 │          │ ожидание
 └──────────┘
```

Тогда важны пропускная способность и задержки подсистемы памяти, а также организация доступа к данным.

## Почему строка программы не равна одной инструкции CPU

Рассмотрим:

```text
total = 0

for value in values:
    total += value
```

Для человека это очень компактный код.

Но внутри цикла происходит значительно больше действий:

```text
получить следующий элемент
        ↓
проверить состояние итератора
        ↓
получить значение
        ↓
получить текущее значение total
        ↓
выполнить сложение
        ↓
сохранить новый total
        ↓
проверить условие продолжения
        ↓
перейти к следующей итерации
```

А в Python дополнительно работает сам интерпретатор.

Поэтому нельзя рассуждать:

> «В программе десять строк, значит CPU выполняет десять операций».

Количество строк исходного кода и количество машинных инструкций — совершенно разные вещи.

## Пример: обработка массива

Представим программу, которая складывает миллион чисел.

```text
total = 0

for value in numbers:
    total += value

print(total)
```

Концептуально CPU должен многократно:

```text
получить элемент
      ↓
прочитать total
      ↓
сложить
      ↓
сохранить результат
      ↓
перейти дальше
```

Если элементы массива находятся последовательно в памяти, система может эффективно загружать их блоками:

```text
RAM:

[10][20][30][40][50][60][70][80]
 ↑
 последовательно читаем
```

Такой доступ хорошо соответствует принципу локальности.

Если же программа постоянно прыгает по совершенно разным адресам:

```text
[10] → [700000] → [25] → [900000] → [400]
```

кэш и подсистема памяти работают менее эффективно.

В результате более простой алгоритм с хорошей локальностью данных иногда может работать быстрее, чем алгоритм с похожим количеством операций, но плохим доступом к памяти.

## Пример: датчик в роботе

Теперь рассмотрим робототехническую систему.

Пусть контроллер должен периодически получать данные от датчика.

```text
                ┌──────────────┐
                │    Таймер    │
                └──────┬───────┘
                       │
                       │ interrupt
                       ▼
                ┌──────────────┐
                │     CPU      │
                └──────┬───────┘
                       │
                       ▼
                обработчик
                       │
                       ▼
                 чтение датчика
                       │
                       ▼
                  буфер данных
```

Когда таймер генерирует событие, процессор может временно переключиться на обработчик.

Обработчик выполняет необходимые действия:

```text
1. Получить данные.
2. Проверить их.
3. Сохранить в буфер.
4. Завершить обработчик.
```

После этого CPU продолжает выполнение предыдущей работы.

Для робототехники особенно важно, что процессор может быть быстрым, но это ещё не гарантирует точное время реакции.

Если задача требует строгого временного интервала, например:

```text
каждые 1 мс
```

важны не только средняя производительность CPU, но и:

* задержки;
* прерывания;
* конкуренция за ресурсы;
* планирование;
* кэш;
* состояние системы;
* наличие операционной системы реального времени или специализированного контроллера.

## CPU в робототехнической системе

В реальном роботе могут одновременно использоваться разные вычислительные устройства:

```text
                    Робот
                      │
       ┌──────────────┼──────────────┐
       │              │              │
       ▼              ▼              ▼
   Микроконтроллер  Промышленный ПК   GPU
       │              │              │
       │              │              │
   моторы, ШИМ,     логика, сеть,   нейросети,
   энкодеры         UI, БД, Python   компьютерное зрение
```

Микроконтроллер хорошо подходит для задач с жёсткими временными требованиями.

Промышленный компьютер может выполнять:

* высокоуровневую логику;
* обработку данных;
* сетевое взаимодействие;
* интерфейс оператора;
* работу с базой данных;
* Python/C++-приложения.

GPU может использоваться для параллельных вычислений и нейросетей.

Поэтому нельзя рассматривать «процессор» как единственный вычислительный ресурс всей системы.

## Что действительно влияет на скорость программы

Если программа работает медленно, недостаточно посмотреть только на модель CPU.

Нужно определить, где именно тратится время:

```text
Программа
    │
    ├── вычисления CPU
    │
    ├── память
    │
    ├── диск
    │
    ├── сеть
    │
    ├── синхронизация
    │
    └── ожидание других ресурсов
```

Например, если программа 90% времени ждёт базу данных, замена CPU может практически не дать результата.

Если 90% времени занимает математический расчёт — ситуация будет другой.

Поэтому инженерный подход выглядит так:

```text
Проблема
   ↓
Измерение
   ↓
Поиск узкого места
   ↓
Изменение
   ↓
Повторное измерение
```

А не:

```text
Медленно
  ↓
Купить процессор мощнее
```

import time

## Что нужно запомнить

* **CPU** — устройство, которое исполняет машинные инструкции.
* Программа в конечном итоге превращается в последовательность операций, которые выполняются процессором.
* Упрощённая модель выполнения инструкции: **выборка → декодирование → исполнение → получение результата**.
* **Регистры** находятся непосредственно внутри CPU и используются для текущих данных и служебной информации.
* **ALU** выполняет арифметические и логические операции.
* **Кэш** уменьшает время доступа к часто используемым данным и инструкциям.
* **Тактовая частота** сама по себе не определяет производительность процессора.
* Несколько ядер позволяют выполнять независимую работу параллельно, но не ускоряют автоматически любую программу.
* Прерывания позволяют процессору реагировать на события от устройств.
* Производительность программы зависит от всей системы: CPU, памяти, диска, сети, алгоритмов и характера самой задачи.
* Для робототехники важно учитывать не только вычислительную мощность, но и задержки и требования к времени реакции.
