# Что такое компьютер

Компьютер удобно рассматривать не как конкретное устройство вроде системного блока или ноутбука, а как систему, которая **хранит данные, выполняет инструкции и обменивается информацией с внешним миром**.

Эта модель одинаково применима к обычному ПК, серверу, смартфону, микроконтроллеру робота или промышленному компьютеру. Разница между ними в количестве вычислительных ресурсов, устройствах ввода-вывода, способах хранения данных, питании и ограничениях.

Главная идея проста:

```text
                 КОМПЬЮТЕР

        ┌--------------------------┐
        │        Программа         │
        │   инструкции + данные    │
        └--------------------------┘
                     │
                     ▼
              ┌-------------┐
              │     CPU     │
              │  выполняет  │
              │ инструкции  │
              └-------------┘
                     │
             ┌---------------┐
             ▼               ▼
          Память          Ввод-вывод
         RAM/SSD       сеть, экран,
                       датчики, моторы
```

Если убрать одну из этих частей, система перестаёт выполнять привычную роль.

CPU без рабочей памяти не сможет нормально выполнять сложные программы. Память без процессора сама ничего не вычисляет. Компьютер без ввода-вывода может считать внутри себя, но не сможет нормально взаимодействовать с пользователем, сетью, датчиками или исполнительными устройствами.

---

## Инструкции и данные

Любая программа в конечном счёте состоит из инструкций, которые должны быть выполнены вычислительной системой.

Например:

```python
a = 10
b = 20
c = a + b
```

Для человека это понятная последовательность действий:

```text
создать a
создать b
сложить a и b
сохранить результат в c
```

Но компьютер не выполняет Python-код непосредственно как человек читает текст.

На определённом уровне программа должна быть представлена в форме, которую может исполнять конкретный процессор.

В зависимости от используемой технологии путь может выглядеть по-разному:

```text
C/C++
   │
   ▼
компилятор
   │
   ▼
машинный код
   │
   ▼
CPU
```

Для Python в типичном случае:

```text
Python-код
    │
    ▼
интерпретатор Python
    │
    ▼
байткод / внутренняя работа runtime
    │
    ▼
машинные инструкции
    │
    ▼
CPU
```

Поэтому исходная строка программы и машинная инструкция — это разные уровни описания одной вычислительной системы.

## Модель фон Неймана

Для первого понимания удобно использовать классическую модель фон Неймана.

В ней программа и данные находятся в памяти, а процессор получает из памяти инструкции и выполняет их.

Упрощённо:

```text
             ┌--------------┐
             │    Память    │
             │              │
             │  инструкции  │
             │     +        │
             │    данные    │
             └--------------┘
                    │
                    │ чтение / запись
                    ▼
             ┌--------------┐
             │     CPU      │
             │              │
             │ выполнение   │
             │ инструкций   │
             └--------------┘
                    │
                    ▼
             ┌--------------┐
             │ Ввод-вывод   │
             └--------------┘
```

Это не схема конкретного современного процессора. Реальная система намного сложнее: существуют кэши, контроллеры памяти, несколько ядер, DMA, различные шины, ускорители и другие механизмы.

Но эта модель даёт правильную основу:

**программа и данные должны где-то находиться → процессор должен их обработать → результат должен куда-то попасть.**

## Где находятся данные

Одна из самых важных привычек инженера — всегда спрашивать:

> Где сейчас находится эта информация?

Например, есть файл:

```text
C:\project\config.json
```

Пока программа его не открыла, это просто набор байтов на накопителе.

После запуска программы ситуация меняется:

```text
SSD
 │
 │ чтение файла
 ▼
RAM
 │
 │ работа программы
 ▼
CPU
```

Если программа изменила значение внутри объекта, это ещё не означает, что файл на диске изменился.

Например:

```text
config["speed"] = 100
```

может изменить объект, находящийся в памяти процесса.

Чтобы изменение пережило завершение программы, его необходимо сохранить в энергонезависимое хранилище.

Поэтому существуют принципиально разные состояния:

```text
файл на SSD
     │
     │ прочитали
     ▼
данные в RAM
     │
     │ изменили
     ▼
изменённые данные в RAM
     │
     │ сохранили
     ▼
новое содержимое SSD
```

Если питание исчезло до сохранения, изменения, которые существовали только в RAM, могут быть потеряны.

## Четыре основных элемента системы

Для дальнейшего изучения удобно постоянно держать в голове четыре компонента.

### Процессор

CPU выполняет машинные инструкции.

Он выполняет арифметику, сравнения, переходы, перемещение данных и другие операции, определённые архитектурой процессора.

Но CPU не является местом долговременного хранения больших объёмов данных.

### Оперативная память

RAM хранит рабочее состояние запущенных программ:

```text
код программы
переменные
объекты
буферы
стек
данные текущих операций
```

Это память, с которой программа работает во время выполнения.

При отключении питания обычное содержимое RAM теряется.

### Накопитель

SSD, HDD, флэш-память, eMMC и другие накопители предназначены для хранения данных без постоянного питания.

Там находятся:

```text
операционная система
программы
конфигурации
документы
логи
датасеты
```

### Ввод-вывод

I/O связывает вычислительную систему с внешним миром.

Например:

```text
клавиатура
мышь
экран
камера
датчик
Ethernet
USB
мотор
энкодер
```

Для робота эта часть особенно важна:

```text
датчик
   │
   ▼
компьютер
   │
   ▼
алгоритм
   │
   ▼
команда
   │
   ▼
двигатель
```

Таким образом робот — это не просто «процессор с программой». Это система, в которой постоянно перемещаются данные между датчиками, памятью, вычислителями и исполнительными устройствами.

## Что делает операционная система

На обычном компьютере между прикладной программой и аппаратурой обычно находится операционная система.

Она предоставляет программам управляемый доступ к ресурсам:

```text
┌-----------------------------┐
│         Приложение          │
└-----------------------------┘
               │
               ▼
┌-----------------------------┐
│      Библиотеки / API       │
└-----------------------------┘
               │
               ▼
┌-----------------------------┐
│        Операционная ОС      │
│ процессы, память, ФС, сеть  │
│ драйверы устройств          │
└-----------------------------┘
               │
               ▼
┌-----------------------------┐
│          Hardware           │
│ CPU RAM SSD USB Ethernet... │
└-----------------------------┘
```

Когда программа хочет прочитать файл, она обычно не управляет электрическими сигналами SSD самостоятельно.

Она обращается к интерфейсу ОС.

Когда программа хочет отправить данные по сети, она тоже обычно не управляет сетевой картой напрямую.

ОС, драйвер и аппаратный контроллер совместно выполняют эту работу.

На микроконтроллере ситуация может быть совсем другой. Там программа может работать практически непосредственно с периферийными регистрами устройства, а полноценной ОС вообще может не быть.

Это важное различие:

```text
Обычный ПК:

программа → ОС → драйвер → контроллер → устройство


Микроконтроллер:

прошивка → регистры периферии → устройство
```

## Один и тот же принцип на разных компьютерах

Рассмотрим три системы.

### Обычный компьютер

```text
CPU
 │
RAM
 │
SSD
 │
ОС
 │
программы
 │
клавиатура / экран / сеть
```

### Микроконтроллер

```text
CPU
 │
SRAM
 │
Flash
 │
прошивка
 │
GPIO / ADC / PWM / UART / SPI / I²C
 │
датчики / моторы
```

### Робот с промышленным компьютером

```text
              Робот
                │
       ┌--------┼--------┐
       ▼        ▼        ▼
      MCU      IPC      GPU
       │        │        │
    моторы    Linux    vision
    энкодеры  сеть     нейросети
```

Все три системы являются вычислительными системами.

Просто задачи распределены по-разному.

## Что происходит при открытии файла

Возьмём простой сценарий:

> Пользователь открыл `notes.txt`.

На высоком уровне происходит примерно следующее:

```text
1. Пользователь запускает редактор
          │
          ▼
2. ОС создаёт процесс
          │
          ▼
3. Код программы загружается в рабочее адресное пространство
          │
          ▼
4. Редактор просит ОС открыть файл
          │
          ▼
5. ОС получает данные с накопителя
          │
          ▼
6. Данные оказываются в памяти
          │
          ▼
7. CPU обрабатывает текст
          │
          ▼
8. Редактор показывает его на экране
```

Когда пользователь изменяет строку, сначала изменяется рабочее состояние программы.

Когда нажимается «Сохранить», данные должны пройти обратный путь:

```text
RAM
 │
 ▼
ОС
 │
 ▼
файловая система
 │
 ▼
накопитель
```

Это простое действие связывает почти все основные элементы компьютера.

## Компьютер как поток данных

Полезно перестать представлять компьютер как набор отдельных деталей.

Вместо этого можно смотреть на него как на поток данных:

```text
              ┌-----------┐
              │ Источник  │
              └-----------┘
                   │
                   ▼
              ┌-----------┐
              │  Память   │
              └-----------┘
                   │
                   ▼
              ┌-----------┐
              │Вычисления │
              └-----------┘
                   │
                   ▼
              ┌-----------┐
              │ Результат │
              └-----------┘
                   │
                   ▼
                Внешний
                  мир
```

Для робота это превращается в:

```text
датчик
  │
  ▼
буфер
  │
  ▼
обработка
  │
  ▼
решение
  │
  ▼
команда
  │
  ▼
актуатор
```

Например:

```text
камера
  ↓
кадр
  ↓
RAM
  ↓
CPU/GPU
  ↓
обнаружение объекта
  ↓
координаты
  ↓
контроллер
  ↓
мотор
```

При диагностике это позволяет задавать правильные вопросы:

* данные вообще пришли?
* где они находятся?
* кто их обрабатывает?
* сколько времени занимает обработка?
* куда должен уйти результат?
* на каком этапе возникла задержка?

Вместо неопределённого:

> «Компьютер тормозит».

## Современный компьютер сложнее классической модели

Современный компьютер далеко не сводится к одному CPU и одной RAM.

В системе могут присутствовать:

```text
CPU
GPU
NPU
RAM
NVMe
сетевой адаптер
USB-контроллеры
PCIe
DMA
аппаратные ускорители
микроконтроллеры
```

В мобильных и встраиваемых системах многие из этих компонентов могут находиться внутри одного SoC.

Например:

```text
┌-------------------------------┐
│             SoC               │
│                               │
│ CPU ─── GPU ─── NPU           │
│  │       │        │           │
│  ├-------┴--------┤           │
│  │ контроллер RAM │           │
│  │ USB            │           │
│  │ Ethernet       │           │
│  │ другие I/O     │           │
└-------------------------------┘
```

Поэтому выражение «процессор компьютера» иногда требует уточнения: речь может идти о CPU-ядрах, а может — о целом SoC.

## Как инженер должен мыслить о компьютере

Полезная модель для диагностики:

```text
             Что происходит?
                    │
        ┌-----------┼-----------┐
        ▼           ▼           ▼
      CPU          RAM         I/O
        │           │           │
    вычисления   состояние   устройства
        │           │           │
        └-----------┼-----------┘
                    ▼
                 storage
```

Если программа работает медленно, это ещё не означает, что медленный CPU.

Причиной может быть:

```text
CPU
RAM
кэш
диск
сеть
драйвер
ожидание I/O
синхронизация
перегрев
ограничение питания
```

Поэтому инженерный подход начинается с определения места проблемы, а не с предположения о виноватом компоненте.

## Практика

Возьмите любое действие на компьютере: запуск Python-скрипта, открытие изображения или загрузку страницы.

Нарисуйте путь данных:

```text
________________
      ↓
________________
      ↓
________________
      ↓
________________
```

Для каждого этапа укажите, где находятся данные:

* на накопителе;
* в RAM;
* внутри CPU;
* в устройстве ввода-вывода;
* в сети.

Затем разберите тот же принцип для робота:

```text
датчик → ? → ? → ? → двигатель
```

Подставьте реальные компоненты вашей системы.

Главное — не перечислить детали, а показать **как данные перемещаются между ними**.

---

## Что нужно запомнить

* Компьютер — система, которая **хранит данные, выполняет инструкции и взаимодействует с внешним миром**.
* CPU выполняет инструкции.
* RAM хранит рабочее состояние запущенных программ.
* Накопитель хранит данные без питания.
* I/O связывает вычислительную систему с внешним миром.
* Программа и машинные инструкции находятся на разных уровнях абстракции.
* На обычном компьютере ОС является посредником между программами и аппаратурой.
* Один и тот же принцип применим к ПК, серверу, микроконтроллеру и роботу.
* Для понимания системы важно отслеживать не только компоненты, но и **поток данных между ними**.
* Именно эта модель будет использоваться дальше при разборе процессора, памяти, накопителей, ОС и устройств ввода-вывода.
