# HTTP-ответ

## Цель

Читать статус, заголовки и тело ответа; выбирать коды осознанно.

## Что уже нужно знать

HTTP-запрос.

## Объяснение с нуля

Ответ: статус (200, 201, 400, 401, 403, 404, 500), заголовки, тело. 2xx — успех, 4xx — ошибка клиента, 5xx — ошибка сервера. Тело ошибки лучше делать машиночитаемым JSON с кодом и сообщением.

Нельзя всё отдавать 200 с {ok:false} без причины — ломаете клиентов и мониторинг.

## Термины

- **Status code**.
- **Reason phrase** (редко важен).
- **Идемпотентность** рядом с методами.

## Внутреннее устройство

Фреймворк сериализует объект → JSON → байты + статус.

## Пример

201 Created с Location и телом задачи; 404 если id нет.

## Разбор

Клиент ветвится по статусу: 201 показать задачу, 400 подсветить поля.

## Код

```http
HTTP/1.1 201 Created
Content-Type: application/json

{"id":10,"title":"Молоко","done":false}
```

## Практика

Подберите коды для: нет авторизации; нет прав; не найдено; ошибка БД.

## Типичные ошибки

- Всегда 200.
- Отдавать stacktrace наружу.

## Что запомнить

Статус — часть контракта, не украшение.

## Задание

Опишите JSON ошибки валидации для пустого title.
