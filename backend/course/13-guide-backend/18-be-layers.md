# Слои backend

## Цель

Разделить API, service, repository: кто за что отвечает.

## Что уже нужно знать

Логирование.

## Объяснение с нуля

Слои уменьшают кашу. API-слой: HTTP, валидация, коды. Service: бизнес-правила, транзакции. Repository: SQL/ORM. Доменные ошибки рождаются в service, API мапит в HTTP.

Прямой SQL из роута работает в прототипе и мешает расти.

## Термины

- **API / Service / Repository**.
- **DTO / Domain model**.

## Внутреннее устройство

Handler → service.create_task() → repo.insert() → DB.

## Пример

create_task проверяет лимит 100 задач, repo только INSERT.

## Разбор

Если лимит превышен — сервис бросает ошибку; SQL не вызывается.

## Код

```python
def create_task(repo, user_id, title):
    if repo.count_open(user_id) >= 100:
        raise LimitExceeded()
    return repo.insert(user_id, title)
```

## Типичные ошибки

- Толстые роуты.
- Репозиторий с бизнес-if'ами UI.

## Что запомнить

Слои = границы ответственности.
