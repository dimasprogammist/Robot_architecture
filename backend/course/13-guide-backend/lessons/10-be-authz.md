# Авторизация

## Цель

Проверять права: владелец задачи, роли, политики.

## Что уже нужно знать

Аутентификация.

## Объяснение с нуля

Авторизация решает, разрешено ли действие. Пользователь аутентифицирован, но не может удалить чужую задачу. Модели: владение объектом, роли (admin), ACL, policy functions.

Проверку делают на сервере в одном месте сервиса — не только в UI.

## Термины

- **Authorization**.
- **Role / permission**.
- **Owner check**.

## Внутреннее устройство

После authn вызывается policy(user, action, resource).

## Пример

user=5, task.user_id=5 → ok; task.user_id=9 → 403.

## Разбор

403 Forbidden — личность известна, права нет.

## Код

```python
if task.user_id != user.id and not user.is_admin:
    raise Forbidden()
```

## Практика

Нужна ли авторизация на GET списка своих задач?

## Типичные ошибки

- Фильтр только в UI.
- Admin-флаг с клиента.

## Что запомнить

Authz отвечает: можно ли?

## Задание

Политики для read/update/delete задачи.
