# Маршрутизация

## Цель

Связать метод и путь с обработчиком.

## Что уже нужно знать

Запрос и ответ.

## Объяснение с нуля

Роутинг выбирает функцию по методу и шаблону пути: GET /tasks/{id} → get_task(id). Порядок маршрутов и конфликты важны. Параметры пути, query и body разделяют ответственность.

Версионирование /v1/... — способ эволюции API.

## Термины

- **Route / endpoint**.
- **Path param**.
- **Router** — группа маршрутов.

## Внутреннее устройство

Таблица маршрутов → match → вызвать handler с извлечёнными параметрами.

## Пример

GET /tasks/10 → id=10 в обработчик.

## Разбор

Не совпал метод — 405; не совпал путь — 404.

## Код

```python
# псевдокод роутера
routes = {
  ("GET", "/tasks"): list_tasks,
  ("GET", "/tasks/{id}"): get_task,
  ("POST", "/tasks"): create_task,
}
```

## Практика

Спроектируйте пути для комментариев задачи.

## Типичные ошибки

- Один гигантский if path.
- Глаголы в пути вместо методов (/getTasks).

## Что запомнить

Маршрут = метод + шаблон пути → обработчик.
