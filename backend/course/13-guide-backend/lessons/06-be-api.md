# API

## Цель

Увидеть API как контракт между клиентами и backend.

## Что уже нужно знать

Маршрутизация.

## Объяснение с нуля

API фиксирует URL, методы, форматы тел, коды ошибок, авторизацию. Менять контракт без версии — ломать клиентов. Документация и примеры — часть продукта.

Внутренние функции Python — не API. API — то, что видно за границей процесса.

## Термины

- **Контракт**.
- **Обратная совместимость**.
- **Публичный / приватный API**.

## Внутреннее устройство

Контракт проверяется тестами и линтерами схем (OpenAPI).

## Пример

Соглашение: даты ISO-8601, id целые, ошибки {code,message,fields}.

## Разбор

Клиент обновлён раньше сервера — должен получить понятный 400/426, а не мусор.

## Код

```json
{"code":"validation_error","fields":{"title":"required"}}
```
