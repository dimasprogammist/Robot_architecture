# REST-стиль

## Цель

Использовать ресурсы и HTTP-методы в духе REST без религиозных споров.

## Что уже нужно знать

API.

## Объяснение с нуля

Практический REST: существительные-ресурсы /tasks, /tasks/{id}; методы как действия над ресурсом; статусы по смыслу; JSON. Не обязательно «полный учебник Fielding», но единообразие помогает.

RPC-стиль /doCreateTask тоже живёт в мире, но смешивать без правил — хаос.

## Термины

- **Ресурс**.
- **Коллекция / элемент**.
- **Идемпотентность** GET/PUT/DELETE.

## Внутреннее устройство

Роуты отражают ресурсы; сервис — операции предметной области.

## Пример

POST /tasks создать; GET /tasks/{id} читать; PATCH /tasks/{id} частично обновить.

## Разбор

DELETE /tasks/10 → 204 без тела или 404.

## Код

```text
GET /tasks
POST /tasks
GET /tasks/10
PATCH /tasks/10
DELETE /tasks/10
```

## Практика

Смоделируйте /tasks/{id}/comments в REST.

## Типичные ошибки

- Глаголы в URL без причины.
- POST на всё подряд.

## Что запомнить

Ресурсы + методы + статусы = понятный HTTP API.
