# Сервисный слой

## Цель

Собрать use-case в сервисе: правила, транзакция, вызовы репозитория.

## Что уже нужно знать

Слои.

## Объяснение с нуля

Сервис оркестрирует один сценарий: «создать задачу», «закрыть задачу». Он знает правила и границы транзакции. Не знает про FastAPI Request и статус-коды.

Тестировать сервис легче с фейковым репозиторием.

## Термины

- **Use-case / application service**.
- **Транзакционная граница**.

## Внутреннее устройство

service method = open tx → checks → repo ops → commit.

## Пример

complete_task: загрузить, проверить владельца, done=true, audit log.

## Разбор

Чужая задача — исключение до UPDATE.

## Код

```python
class TaskService:
    def complete(self, user_id: int, task_id: int) -> None:
        task = self.repo.get(task_id)
        if task is None:
            raise NotFound()
        if task.user_id != user_id:
            raise Forbidden()
        self.repo.mark_done(task_id)
```

## Практика

Нужен ли отдельный сервис для простого GET?

## Типичные ошибки

- Сервис, принимающий HTTP Request.
- Commit в репозитории и ещё раз в сервисе хаотично.
