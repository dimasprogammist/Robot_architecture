# Сессии

## Цель

Сделать серверную сессию: id в cookie, данные на сервере.

## Что уже нужно знать

Cookies.

## Объяснение с нуля

Сессия: клиент хранит случайный session_id, сервер хранит {user_id, ...} в памяти/Redis/БД. Logout удаляет серверную запись. Удобно отзывать доступ.

Минус — нужна общая хранилка сессий при нескольких инстансах сервера.

## Термины

- **Session id**.
- **Server-side session store**.

## Внутреннее устройство

login → создать id → save store → Set-Cookie; request → load store → user.

## Пример

store['abc'] = {user_id:5, exp:...}

## Разбор

Нет записи в store → 401, даже если cookie пришла.

## Код

```python
session_id = secrets.token_urlsafe(32)
store[session_id] = {"user_id": user.id}
response.set_cookie("session", session_id, httponly=True)
```

## Практика

Как инвалидировать все сессии пользователя?

## Типичные ошибки

- Предсказуемый session_id.
- Сессия в памяти одного инстанса без sticky/store.

## Что запомнить

Сессия = id у клиента + состояние на сервере.

## Задание

Нарисуйте login/logout/request sequence.
