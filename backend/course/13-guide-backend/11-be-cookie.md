# Cookies

## Цель

Понять Cookie как хранилище на клиенте, которое браузер сам прикрепляет.

## Что уже нужно знать

Authn.

## Объяснение с нуля

Set-Cookie в ответе просит браузер хранить пару и слать её обратно. Для сессий важны HttpOnly (недоступно JS), Secure, SameSite. Cookie удобны для браузерных клиентов; для мобильных часто Bearer-токен.

Размер и число cookie ограничены.

## Термины

- **Set-Cookie / Cookie**.
- **HttpOnly, Secure, SameSite**.

## Внутреннее устройство

Браузер хранит cookie по домену/пути; сервер читает заголовок Cookie.

## Пример

Set-Cookie: session=abc; HttpOnly; Path=/; SameSite=Lax

## Разбор

Следующий запрос автоматически несёт Cookie: session=abc.

## Код

```http
HTTP/1.1 200 OK
Set-Cookie: session=abc; HttpOnly; Path=/
```

## Практика

Зачем HttpOnly против XSS-кражи сессии?

## Типичные ошибки

- Класть токен в cookie без флагов.
- Хранить огромный JSON в cookie.

## Что запомнить

Cookie — автоматический заголовок браузера с политикой флагов.

## Задание

Спроектируйте cookie сессии для API на HTTPS.
