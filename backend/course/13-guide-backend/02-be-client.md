# Клиент и сервер

## Цель

Разделить обязанности клиента и сервера без размытия границ.

## Что уже нужно знать

Что такое backend.

## Объяснение с нуля

Клиент инициирует запрос, показывает UI, держит эфемерное состояние экрана. Сервер проверяет подлинность, авторизует, валидирует, сохраняет. Нельзя доверять клиенту: он под контролем пользователя.

Общая БД и тарифные лимиты — только на сервере.

## Термины

- **Доверие границе** — сервер не доверяет клиенту.
- **Контракт API**.

## Внутреннее устройство

Запрос проходит сеть; сервер не видит «что пользователь думал», только байты запроса.

## Пример

Клиент шлёт done=true для чужой задачи — сервер обязан отвергнуть по user_id сессии.

## Разбор

Проверка владельца на сервере обязательна, даже если кнопка скрыта в UI.

## Код

```python
# псевдокод
if task.user_id != current_user.id:
    raise Forbidden()
```

## Практика

Что можно кэшировать на клиенте, а что нельзя считать истиной?

## Типичные ошибки

- Валидация только в UI.
- «Секретный» URL без авторизации.

## Что запомнить

Клиент ненадёжен; сервер — граница доверия.

## Задание

Разнесите проверки формы задачи: UI vs server.
