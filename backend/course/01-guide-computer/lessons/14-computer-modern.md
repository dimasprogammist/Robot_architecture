# Устройство современного компьютера

Мы уже разобрали отдельные части компьютера: процессор, память, накопители, программы, процессы, потоки, операционную систему и ввод-вывод.

Теперь пора собрать их в одну систему.

Современный компьютер — это уже не просто связка `CPU + RAM + диск`. В нём могут одновременно работать несколько вычислительных блоков, разные уровни памяти, контроллеры, устройства хранения, сетевые интерфейсы и специализированные ускорители.

```text
                         ПРОГРАММЫ
                             ↓
                            ОС
              +--------------+--------------+
              ↓              ↓              ↓
             CPU            GPU            NPU
              +--------------+--------------+
                            RAM
              +--------------+--------------+
              ↓              ↓              ↓
            N↓Me            USB            PCIe
              ↓              ↓              ↓
           накопитель      камера        устройства
```

Главная идея этого урока:

> **Современный компьютер — это система специализированных компонентов, между которыми постоянно перемещаются данные.**

Поэтому при оценке компьютера важно спрашивать не только «насколько мощный процессор», а ещё и «где находятся данные, как они перемещаются и какой компонент становится ограничением».

## CPU — универсальный вычислитель

**CPU (Central Processing Unit)** — центральный процессор, предназначенный для выполнения самых разных инструкций.

Он занимается:

```text
условиями и циклами
вычислениями
управлением программами
системными вызовами
обработкой исключений
работой ОС
сетевой и файловой логикой
```

Современный CPU обычно содержит несколько ядер:

```text
CPU
+-- Core 0
+-- Core 1
+-- Core 2
+-- Core 3
+-- ...
+-- Core N
```

Операционная система распределяет выполняющиеся потоки между ядрами.

Главное преимущество CPU — универсальность. Он хорошо подходит для задач, где важны сложная логика, ветвления, последовательные операции и управление большим количеством разных компонентов системы.

Но универсальность не означает максимальную эффективность для любого типа вычислений.

## GPU — массовый параллелизм

**GPU (Graphics Processing Unit)** первоначально создавался для обработки графики.

Графика содержит огромное количество похожих операций:

```text
пиксель 1 -> вычисление
пиксель 2 -> вычисление
пиксель 3 -> вычисление
...
пиксель N -> вычисление
```

Поэтому GPU построен с расчётом на массовый параллелизм.

Сегодня GPU используется не только для изображения. Он может ускорять:

* обработку изображений;
* компьютерное зрение;
* физические симуляции;
* научные вычисления;
* машинное обучение;
* обработку сигналов.

Упрощённо:

```text
CPU
+----------------------+
| несколько мощных     |
| универсальных ядер   |
+----------------------+

GPU
+----------------------+
| много вычислительных |
| блоков               |
|                      |
| массово-параллельные |
| операции             |
+----------------------+
```

Это не означает, что GPU «лучше» CPU. Архитектуры рассчитаны на разные типы задач.

## NPU и другие ускорители

В современных устройствах всё чаще встречается **NPU (Neural Processing Unit)** — специализированный блок для определённых операций, характерных для нейронных сетей.

Нейронные сети выполняют огромное количество операций над массивами чисел:

```text
матрицы
векторы
тензоры
умножения
свёртки
```

Такие операции хорошо подходят для аппаратного ускорения.

Возникает вопрос: если GPU тоже умеет запускать нейронные сети, зачем NPU?

Одна из причин — энергоэффективность. Например, смартфону или роботу может потребоваться постоянно выполнять распознавание речи, обработку изображения или другой AI inference. Для такой задачи специализированный блок может оказаться выгоднее по энергопотреблению.

Поэтому современная система становится **гетерогенной**:

```text
+------+----------------------------+
| CPU  | универсальные задачи       |
| GPU  | массовый параллелизм       |
| NPU  | специализированные AI-задачи|
+------+----------------------------+
```

Границы здесь условны. CPU тоже умеет выполнять векторные операции, GPU используется для AI, а возможности NPU зависят от конкретного устройства.

Важно не запоминать эту таблицу как строгий закон, а понимать принцип: **разные вычислительные блоки оптимизированы под разные классы нагрузки**.

## Почему ускоритель сам по себе не решает задачу

Представим систему компьютерного зрения:

```text
камера
  ↓
получение кадра
  ↓
предобработка
  ↓
AI inference
  ↓
постобработка
  ↓
логика приложения
```

Даже если AI-модель выполняется на очень быстром GPU или NPU, остальные этапы никуда не исчезают.

Например:

```text
GPU очень быстрый
      ↓
данные медленно поступают
      ↓
GPU простаивает
```

Или:

```text
NPU быстрый
      ↓
CPU долго готовит данные
      ↓
NPU простаивает
```

Поэтому реальная производительность определяется всей цепочкой обработки данных.

## Иерархия памяти

Одной из важнейших частей архитектуры компьютера является память.

CPU работает значительно быстрее, чем основная оперативная память, поэтому система использует несколько уровней хранения данных:

```text
быстрее
  ^
регистры
  |
L1 cache
  |
L2 cache
  |
L3 cache
  |
RAM
  |
SSD / N↓Me
  |
сеть / внешнее хранилище
  ↓
медленнее
```

Чем ближе память к вычислительному блоку, тем обычно меньше её объём и ниже задержка доступа.

Регистры находятся непосредственно внутри вычислительного ядра. Кэш хранит часто используемые данные ближе к CPU. RAM содержит гораздо больший объём информации, но имеет большую задержку. SSD предназначен уже для долговременного хранения и значительно медленнее оперативной памяти.

Именно поэтому программа не обращается к SSD каждый раз, когда ей нужна обычная переменная.

## Кэш и локальность данных

Кэш особенно эффективен благодаря тому, что программы часто повторно используют одни и те же данные или обращаются к соседним адресам памяти.

Упрощённо:

```text
CPU
 ↓
L1
 ↓
L2
 ↓
L3
 ↓
RAM
```

Если данные уже находятся в кэше, процессору не нужно обращаться к RAM.

Поэтому две программы, выполняющие одинаковое количество математических операций, могут работать с разной скоростью в зависимости от того, насколько эффективно они используют память.

Для инженера это важная мысль:

> **Производительность определяется не только количеством вычислений, но и тем, насколько быстро вычислитель получает необходимые данные.**

## CPU и память — не всегда единая «плоская» система

В обычном компьютере программа видит виртуальное адресное пространство, но физическая организация памяти может быть значительно сложнее.

Например, в многопроцессорных системах применяется **NUMA (Non-Uniform Memory Access)**.

Упрощённо:

```text
CPU 0
 +-- RAM 0
 |
 +-- связь -------- CPU 1
                       +-- RAM 1
```

Память, расположенная ближе к конкретному процессору, может иметь другие характеристики доступа, чем память другого узла.

Для обычного настольного приложения это часто незаметно. Но при проектировании серверов и высокопроизводительных систем расположение данных становится важным фактором.

## SoC — целый компьютер на одном кристалле

В смартфонах, одноплатных компьютерах и многих робототехнических системах используется **SoC (System on Chip)**.

Вместо большого количества отдельных микросхем в одном кристалле могут находиться:

```text
+--------------------------------+
|              SoC               |
|                                |
| CPU   GPU   NPU   Memory Ctrl  |
|                                |
| USB   PCIe  Camera  Media      |
|                                |
| Network   Security   I/O       |
+--------------------------------+
```

Объединение компонентов позволяет уменьшить размеры системы, энергопотребление и задержки обмена между некоторыми блоками.

Поэтому SoC особенно распространены в:

```text
смартфонах
одноплатных компьютерах
роботах
автомобильной электронике
встраиваемых системах
```

При этом SoC не обязательно содержит абсолютно всё. Например, внешняя память, накопитель или некоторые периферийные устройства могут оставаться отдельными компонентами.

## Как устроен обычный ПК

В настольном компьютере компоненты могут быть распределены по отдельным устройствам.

Упрощённо:

```text
                    CPU
          +----------+----------+
         RAM        PCIe       I/O
                +----+----+
               GPU       N↓Me
```

Современные процессоры сами содержат часть контроллеров, которые раньше находились в отдельных компонентах чипсета.

Поэтому архитектура современного ПК отличается от старых схем с отдельными северным и южным мостами.

Для нас важнее не название конкретной микросхемы, а принцип: **процессор, память и периферия соединены системой контроллеров и высокоскоростных интерфейсов**.

## Интерфейсы и interconnect

Компонентам нужно обмениваться данными.

Для этого используются различные интерфейсы:

```text
PCIe
USB
Ethernet
SATA
I2C
SPI
UART
CAN
```

У каждого свои характеристики:

* скорость;
* задержка;
* протокол;
* топология;
* размер и формат передаваемых данных;
* способ обнаружения ошибок.

Например, N↓Me-накопитель обычно взаимодействует с системой через PCIe, камера может использовать USB или специализированный интерфейс, а микроконтроллер робота — UART, CAN или Ethernet.

Поэтому физическая возможность подключить устройство ещё не говорит о том, насколько хорошо оно будет работать в конкретной системе.

## Где находится bottleneck

Представим компьютер:

```text
CPU  -> 30%
RAM  -> 50%
GPU  -> 98%
SSD  -> 20%
```

В конкретной задаче GPU может быть ограничивающим компонентом.

Но в другой системе:

```text
CPU  -> 95%
RAM  -> 80%
GPU  -> 35%
SSD  -> 90%
```

Теперь проблема может находиться в подготовке данных, памяти или накопителе.

Именно поэтому более мощный CPU не обязательно решает проблему производительности.

Инженерный подход выглядит так:

```text
нагрузка
   ↓
измерения
   ↓
поиск bottleneck
   ↓
изменение архитектуры
   ↓
повторное измерение
```

Смотреть можно на загрузку CPU и GPU, использование RAM, скорость и задержки диска, сетевой трафик, температуру и другие параметры.

Главное правило:

> **Сначала измеряем, потом оптимизируем.**

## Питание и температура

Производительность зависит не только от архитектуры, но и от условий работы.

Современный процессор может временно повышать частоту, если позволяет запас мощности и температуры:

```text
нагрузка
   ↓
Boost / Turbo
   ↓
частота выше
```

Но при перегреве система может уменьшить частоту:

```text
перегрев
   ↓
throttling
   ↓
частота ниже
   ↓
производительность ниже
```

Это особенно важно для компактных устройств и роботов.

Компьютер, который показывает определённый результат на открытом стенде, может работать иначе после установки в закрытый корпус с ограниченным охлаждением.

Поэтому при проектировании системы нужно учитывать:

```text
питание
охлаждение
температуру
допустимую мощность
режим нагрузки
```

## Firmware: первый программный слой

Мы уже рассматривали ОС, но она не является первым кодом, который выполняется после включения компьютера.

До запуска ОС работает **firmware** — встроенное программное обеспечение аппаратной платформы или конкретного устройства.

Примеры:

```text
UEFI
firmware SSD
firmware сетевой карты
firmware камеры
firmware контроллера
```

При загрузке компьютера упрощённо происходит следующее:

```text
питание
   ↓
firmware
   ↓
инициализация железа
   ↓
загрузчик
   ↓
ядро ОС
   ↓
драйверы и службы
   ↓
приложения
```

Firmware может инициализировать оборудование, выполнять низкоуровневое управление и предоставлять системе начальные настройки.

Поэтому современный компьютер правильнее представлять как несколько связанных программно-аппаратных уровней:

```text
hardware
   +
firmware
   +
драйверы
   +
ОС
   +
приложения
```

## Защищённая загрузка

Современные компьютеры могут проверять компоненты, которые запускаются во время загрузки.

Например, Secure Boot позволяет построить цепочку доверия:

```text
firmware
   | проверка
   ↓
загрузчик
   | проверка
   ↓
ядро
   ↓
ОС
```

Идея проста: важные компоненты загрузки должны соответствовать ожидаемому источнику и не быть незаметно подменены.

Для промышленной и встраиваемой техники это особенно важно, когда устройство должно защищать собственную прошивку и программную платформу.

## DMA и IOMMU

В предыдущем уроке мы рассмотрели DMA: устройство может передавать большие блоки данных непосредственно в RAM, не заставляя CPU вручную копировать каждый байт.

Но возникает вопрос безопасности:

> Что будет, если устройство сможет записывать куда угодно в оперативной памяти?

Для ограничения таких операций используется **IOMMU (Input-Output Memory Management Unit)**.

Упрощённо:

```text
устройство
    | DMA
    ↓
  IOMMU
    | разрешённая область
    ↓
   RAM
```

IOMMU позволяет ограничивать доступ устройства к памяти и играет важную роль в защите системы и виртуализации.

## Виртуальные машины и контейнеры

Современный компьютер может одновременно запускать несколько изолированных сред.

Виртуальная машина получает виртуальное представление целого компьютера:

```text
железо
   ↓
гипервизор
   +-- ↓M 1 -> ОС
   +-- ↓M 2 -> ОС
   +-- ↓M 3 -> ОС
```

Каждая виртуальная машина запускает собственную операционную систему.

Контейнеры устроены иначе:

```text
железо
   ↓
одно ядро ОС
   |
   +-- контейнер A
   +-- контейнер B
   +-- контейнер C
```

Контейнеры изолируют процессы и ресурсы, но обычно используют одно ядро хостовой ОС.

Поэтому контейнер и виртуальная машина — это разные уровни виртуализации.

## Современный компьютер в AI-задаче

Теперь можно собрать архитектуру на примере компьютерного зрения.

```text
камера
   ↓
контроллер
   ↓
RAM
   +------> CPU
   |          ↓
   |       логика
   |
   +------> GPU / NPU
              ↓
          AI inference
              ↓
           результат
              ↓
          CPU / ОС
              ↓
          приложение
```

Здесь нет одного «главного» вычислителя, который делает абсолютно всё.

CPU может заниматься управлением и подготовкой данных, GPU или NPU — самой моделью, RAM — хранением рабочих данных, а контроллеры — передачей информации.

При этом AI-ускоритель ограничен не только вычислительной мощностью. На результат влияют объём и пропускная способность памяти, формат данных, передача между блоками и сама структура модели.

Поэтому характеристика вроде `100 TOPS` сама по себе не говорит, насколько быстро конкретная модель будет работать на конкретном устройстве.

## Компьютер робота — распределённая система

В робототехнике вычисления часто распределяются между несколькими микросхемами.

Например:

```text
+---------------------------+
|            SoC            |
|                           |
| CPU + GPU/NPU + Linux     |
+-------------+-------------+
          Ethernet
              ↓
+---------------------------+
|            MCU            |
|                           |
| PWM / энкодеры / realtime |
+-------------+-------------+
              ↓
            мотор
```

SoC может заниматься Linux, сетью, компьютерным зрением, планированием и AI.

MCU может заниматься PWM, энкодерами, быстрыми контурами управления и непосредственным взаимодействием с мотор-контроллерами.

Получается распределённая вычислительная система:

```text
камера
  ↓
SoC
  +-- AI
  +-- планирование
  ↓
MCU
  ↓
мотор
  ↓
энкодер
  +------------> SoC
```

Каждый канал связи между этими компонентами имеет свою задержку, пропускную способность, формат данных и правила обработки ошибок.

Поэтому архитектура робота — это не просто выбор самого мощного процессора.

## Производительность нельзя описать одной цифрой

Нельзя полноценно описать компьютер фразой:

```text
"У него CPU 5 ГГц."
```

Или:

```text
"У него 100 TOPS."
```

Или:

```text
"У него 100 TFLOPS."
```

Каждая цифра характеризует только определённую часть системы.

Реальная производительность определяется всей цепочкой:

```text
данные
  ↓
память
  ↓
интерфейс
  ↓
вычислитель
  ↓
память
  ↓
следующий этап
```

Если один участок становится узким местом, ускорение другого компонента может почти ничего не дать.

Например, очень быстрый GPU будет простаивать, если данные слишком медленно поступают из памяти. Быстрый CPU не поможет, если задача ограничена скоростью сети. Мощный компьютер может потерять производительность из-за перегрева.

Поэтому инженер сначала определяет характер нагрузки, измеряет систему и только после этого решает, какой компонент необходимо изменить.

## Типичные ошибки

### «Чем выше частота CPU, тем мощнее компьютер»

Не обязательно. Производительность зависит от архитектуры, количества ядер, кэшей, памяти, I/O и характера задачи.

### «GPU всегда быстрее CPU»

Нет. GPU эффективен для определённых классов массово-параллельных задач. Для сложной последовательной логики CPU может быть значительно подходящим.

### «Больше TOPS автоматически означает более быстрый AI»

Нет. Нужно учитывать модель, формат вычислений, память, пропускную способность, поддерживаемые операции и передачу данных между компонентами.

### «Вся память работает одинаково быстро»

Нет. В системе есть регистры, несколько уровней кэша, RAM, накопители и другие уровни хранения с разными характеристиками.

### «Если CPU мощный, остальная система уже не важна»

Нет. Ограничением может оказаться память, GPU, NPU, накопитель, сеть, охлаждение или другой компонент.

### «Современный компьютер — это только железо»

Нет. Реальная система включает как минимум:

```text
hardware
   |
firmware
   |
драйверы
   |
ОС
   |
runtime
   |
приложения
```

Все эти уровни взаимодействуют друг с другом.

## Что нужно запомнить

Современный компьютер — это **гетерогенная система вычислений, памяти и ввода-вывода**.

В ней могут одновременно работать:

```text
CPU
GPU
NPU
кэши
RAM
N↓Me
сетевые контроллеры
USB
MCU
```

Главные идеи:

1. CPU — универсальный вычислитель.
2. GPU эффективен для массового параллелизма.
3. NPU и другие ускорители предназначены для специализированных классов вычислений.
4. Производительность зависит не только от вычислителей, но и от памяти и передачи данных.
5. SoC объединяет множество функциональных блоков в одном кристалле.
6. Интерфейсы и interconnect связывают компоненты между собой.
7. Иерархия памяти уменьшает задержки доступа к часто используемым данным.
8. DMA помогает эффективно передавать большие блоки данных.
9. IOMMU позволяет ограничивать доступ устройств к памяти.
10. Firmware участвует в инициализации и работе оборудования.
11. Питание и температура могут напрямую влиять на производительность.
12. В роботах вычисления часто распределяются между SoC, MCU и периферийными контроллерами.
13. Реальную производительность определяет вся цепочка обработки данных.
14. Bottleneck нужно измерять, а не угадывать.

Главная модель всего модуля:

```text
                    ПРОГРАММА
                        ↓
                 ПРОЦЕСС / ПОТОК
                        ↓
                       ОС
             +----------+----------+
             ↓          ↓          ↓
            CPU        RAM        I/O
       +-----+-----+               ↓
       ↓     ↓     ↓          УСТРОЙСТВА
      GPU   NPU   CPU
       +-----+
```

Мы начали модуль с простого вопроса:

> Что такое компьютер?

Теперь у нас есть гораздо более точная модель:

> **Компьютер — это система вычислительных блоков, памяти и устройств, которыми управляет программное обеспечение. ОС предоставляет приложениям контролируемый доступ к этой системе, а специализированные ускорители и контроллеры позволяют эффективно выполнять разные классы задач.**
