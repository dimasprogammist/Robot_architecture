# Реляционная модель

## Цель

Увидеть таблицы как отношения: факты в строках, связи через ключи.

## Что уже нужно знать

Зачем SQL.

## Объяснение с нуля

Отношение — таблица однотипных фактов. Столбцы имеют имена и типы. Связь «у пользователя много задач» кодируют столбцом user_id, а не обязательным вложенным массивом.

Явная модель упрощает обновления, индексы и JOIN. Порядок строк сам по себе не несёт смысл — смысл в значениях.

## Термины

- **Отношение** — таблица.
- **Кортеж** — строка.
- **Атрибут** — столбец.
- **Домен** — допустимые значения.

## Внутреннее устройство

Операции над множествами строк: фильтр, проекция, соединение.

## Пример

users(id, name) и tasks(id, user_id, title).

## Разбор

Строка tasks(10, 5, 'Отчёт') — факт. Без пользователя 5 FK может запретить вставку.

## Код

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL
);
CREATE TABLE tasks (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL,
  title TEXT NOT NULL
);
```

## Практика

Разложите заказ с товарами на несколько таблиц без массива в одной строке.

## Типичные ошибки

- Одна таблица «на всё».
- Дублировать имя пользователя в каждой задаче без синхронизации.

## Что запомнить

Связи — через ключи; строки — факты одного типа.

## Задание

3 пользователя и 6 задач с согласованными user_id.
