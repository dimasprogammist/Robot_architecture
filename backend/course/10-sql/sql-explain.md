# EXPLAIN

## Цель

Читать план: seq scan vs index scan на простом примере.

## Что уже нужно знать

CTE.

## Объяснение с нуля

EXPLAIN показывает план без выполнения (EXPLAIN ANALYZE — с выполнением в PostgreSQL). Ищите Sequential Scan на больших таблицах при селективном WHERE — кандидат на индекс.

План — не приговор навсегда: статистика меняется.

## Термины

- **Seq Scan**, **Index Scan**.
- **Стоимость** в условных единицах планировщика.

## Внутреннее устройство

Статистика таблицы помогает оценить число строк.

## Пример

WHERE user_id=5: без индекса seq scan; с индексом — index lookup.

## Разбор

Сравните два EXPLAIN на учебной БД.

## Код

```sql
EXPLAIN QUERY PLAN SELECT * FROM tasks WHERE user_id = 5;
CREATE INDEX IF NOT EXISTS idx_tasks_user ON tasks(user_id);
EXPLAIN QUERY PLAN SELECT * FROM tasks WHERE user_id = 5;
```

## Практика

Почему SELECT * мешает покрывающим индексам (идея)?

## Типичные ошибки

- Оптимизировать микросекунды на 100 строках.
- Слепо добавлять индексы после первого EXPLAIN.

## Что запомнить

EXPLAIN отвечает «как СУБД будет искать».

## Задание

Снимите план до/после индекса на своём примере.
