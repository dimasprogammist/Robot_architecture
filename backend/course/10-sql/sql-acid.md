# ACID

## Цель

Расшифровать Atomicity, Consistency, Isolation, Durability простыми сценариями.

## Что уже нужно знать

Транзакции.

## Объяснение с нуля

Atomicity — всё или ничего. Consistency — ограничения не нарушены после фиксации. Isolation — параллельные транзакции не видят чужой грязи (с оговорками уровней). Durability — после COMMIT данные не исчезают от мелкого сбоя (за счёт журнала/фсинка).

Уровни изоляции (READ COMMITTED и др.) меняют видимость. Для курса важно: гонки существуют, их лечат транзакции и аккуратный дизайн.

## Термины

- **Грязное чтение**, **неповторяемое чтение**, **фантом**.
- **Уровень изоляции**.

## Внутреннее устройство

Блокировки или MVCC реализуют изоляцию внутри движка.

## Пример

Две транзакции ставят done одной задачи почти одновременно — последняя запись победит, если нет версий/условий.

## Разбор

Покажите, зачем UPDATE ... WHERE id=? AND version=?

## Код

```sql
UPDATE tasks SET done = TRUE, version = version + 1
WHERE id = 10 AND version = 3;
```

## Практика

Если затронуто 0 строк — кто-то изменил раньше.

## Типичные ошибки

- Игнорировать гонки в UI.
- Путать durability с бэкапом.

## Что запомнить

ACID — контракт надёжности транзакций.
