# Типы связей

## Цель

Смоделировать 1:1, 1:N, N:M через ключи и таблицы связи.

## Что уже нужно знать

Ограничения и FK.

## Объяснение с нуля

1:N — классика: users → tasks через user_id. 1:1 — редкий профиль: user_profiles.user_id UNIQUE/PK. N:M — tasks ↔ tags через task_tags(task_id, tag_id).

Ошибка новичка — массив id в TEXT. Правило: связь = таблица или FK-столбец.

## Термины

- **1:1, 1:N, N:M**.
- **Таблица связи** — две FK + обычно PK пары.

## Внутреннее устройство

JOIN восстанавливает картину из нормализованных таблиц.

## Пример

tags: (1,'sql'),(2,'python'). task_tags: (10,1),(10,2),(11,1) — задача 10 с двумя тегами.

## Разбор

Запрос тегов задачи 10 вернёт sql и python через JOIN.

## Код

```sql
SELECT tags.name
FROM task_tags
JOIN tags ON tags.id = task_tags.tag_id
WHERE task_tags.task_id = 10;
```

## Практика

Смоделируйте N:M студентов и курсов.

## Типичные ошибки

- Хранить '1,2,3' в TEXT.
- Дублировать теги строками без таблицы tags.

## Что запомнить

Тип связи диктует форму ключей.

## Задание

Создайте task_tags и вставьте 3 связи.
