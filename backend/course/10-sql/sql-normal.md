# Нормализация

## Цель

Убрать избыточность: нормальные формы на интуитивном уровне 1–3.

## Что уже нужно знать

Типы связей.

## Объяснение с нуля

Нормализация уменьшает дублирование. Если имя пользователя копируется в каждую задачу — при смене имени нужно обновить тысячи строк. Выносят в users и оставляют user_id.

1NF: атомарные значения. 2NF/3NF: атрибуты зависят от ключа, не от других неключевых. На практике — «одна сущность — одна таблица», без транзитивных зависимостей.

## Термины

- **Избыточность**, **аномалии обновления**.
- **Денормализация** — сознательный дубль ради чтения.

## Внутреннее устройство

Нормализация бьёт по удобству записи ценой JOIN при чтении. Иногда денормализуют осознанно.

## Пример

Плохо: tasks(id, title, user_name). Хорошо: user_id + users.name.

## Разбор

Смена имени Ann→Anna трогает одну строку users, задачи не трогаем.

## Код

```sql
-- плохо: user_name в tasks
-- лучше:
SELECT t.title, u.name
FROM tasks t JOIN users u ON u.id = t.user_id;
```

## Практика

Найдите аномалию в таблице orders(order_id, customer_name, customer_city, product).

## Типичные ошибки

- Нормализовать до боли без нагрузки.
- Денормализовать «на глаз» без измерения.

## Что запомнить

Нормализация лечит аномалии обновления.

## Задание

Разнормируйте пример orders в customers и order_items.
