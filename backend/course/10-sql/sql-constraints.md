# Ограничения

## Цель

Использовать NOT NULL, UNIQUE, CHECK как защиту данных.

## Что уже нужно знать

FK и PK.

## Объяснение с нуля

Ограничения — правила, которые СУБД гарантирует. NOT NULL запрещает пустоту. UNIQUE запрещает дубликаты. CHECK задаёт предикат (priority BETWEEN 1 AND 5). PK и FK — тоже ограничения.

Лучше поймать мусор на INSERT, чем чистить годы продом.

## Термины

- **NOT NULL**, **UNIQUE**, **CHECK**.
- **Нарушение ограничения** — ошибка транзакции/оператора.

## Внутреннее устройство

Проверка при записи. Чтение ограничений не «валидирует» старые данные, пока не включите/проверите отдельно.

## Пример

title NOT NULL, priority CHECK (1..5). INSERT с priority=9 — отказ.

## Разбор

Отклонённая вставка не создаёт строку (в рамках транзакции — откат оператора/транзакции по правилам СУБД).

## Код

```sql
CREATE TABLE tasks (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  priority INTEGER NOT NULL CHECK (priority BETWEEN 1 AND 5),
  email TEXT UNIQUE
);
```

## Практика

Какие CHECK поставили бы на статус задачи (todo/doing/done)?

## Типичные ошибки

- Валидировать только в UI.
- UNIQUE на столбце, где дубликаты законны.

## Что запомнить

Ограничения = страховка на границе записи.

## Задание

Добавьте CHECK status IN (...).
