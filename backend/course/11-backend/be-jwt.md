# JWT

## Цель

Понять JWT как самодостаточный токен с подписью и его риски.

## Что уже нужно знать

Сессии.

## Объяснение с нуля

JWT несёт claims (sub, exp) и подпись. Сервер проверяет подпись секретом/ключом без хранения сессии (часто). Отзыв сложнее — нужны blacklist/короткий TTL/refresh.

Не кладите секреты в payload: он только кодирован, не зашифрован (обычно).

## Термины

- **Header.Payload.Signature**.
- **Claims: sub, exp, iat**.
- **Bearer token**.

## Внутреннее устройство

Authorization: Bearer eyJ... → verify → user_id из sub.

## Пример

payload {sub:5, exp: ...} подписан HS256.

## Разбор

Подпись неверна или exp прошёл → 401.

## Код

```python
# псевдокод
claims = jwt.decode(token, secret, algorithms=["HS256"])
user_id = int(claims["sub"])
```

## Практика

Когда сессия лучше JWT?

## Типичные ошибки

- alg=none.
- Долгий TTL без refresh-стратегии.
- Секреты в claims.

## Что запомнить

JWT удобен для stateless, но отзыв и утечка — цена.
