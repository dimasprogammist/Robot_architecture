# Архитектура и память микроконтроллера

## Цель

Чтобы уверенно программировать микроконтроллеры, недостаточно знать только команды языка программирования. Нужно понимать, где находится программа, где хранятся переменные, как CPU обращается к периферии и что происходит после сброса.

После урока вы должны понимать:

* из каких основных блоков состоит архитектура MCU;
* что делает CPU;
* чем Flash отличается от RAM;
* что такое регистры;
* что такое стек;
* где находятся глобальные и локальные переменные;
* что такое адресное пространство;
* как программа попадает в микроконтроллер;
* что происходит после reset;
* зачем нужен bootloader;
* почему объём памяти микроконтроллера имеет значение.

---

# Общая архитектура

Упрощённо микроконтроллер можно представить следующим образом:

```text
                  ┌──────────────┐
                  │     CPU      │
                  └──────┬───────┘
                         │
              ┌──────────┴──────────┐
              │                     │
           Flash                   RAM
              │                     │
              └──────────┬──────────┘
                         │
                     шина / bus
                         │
       ┌─────────────────┼─────────────────┐
       │                 │                 │
      GPIO              ADC              Timers
       │                 │                 │
       └─────────────────┼─────────────────┘
                         │
                   интерфейсы
                  UART / SPI / I²C
```

Конкретная архитектура зависит от семейства MCU, но общая идея остаётся похожей.

---

# CPU

CPU выполняет машинные инструкции.

Например:

```cpp
int a = 10;
int b = 20;
int c = a + b;
```

На уровне языка мы видим:

```text
c = a + b
```

Но CPU фактически выполняет последовательность низкоуровневых операций:

```text
загрузить a
загрузить b
сложить
сохранить результат
```

Именно CPU выполняет программу.

---

# Регистры

Регистры — это небольшие очень быстрые области хранения внутри процессорного ядра.

CPU использует их для:

* операндов;
* адресов;
* результатов;
* состояния;
* управления.

Например условная операция:

```text
R1 = 10
R2 = 20
R3 = R1 + R2
```

После этого:

```text
R3 = 30
```

Количество и назначение регистров зависит от архитектуры CPU.

---

# Тактовая частота

CPU работает синхронно с тактовым сигналом.

Например:

```text
100 MHz
```

означает 100 миллионов тактов в секунду.

Но нельзя напрямую говорить:

> 100 MHz означает 100 миллионов выполненных инструкций в секунду.

Одна инструкция может требовать различное количество тактов.

Кроме того, производительность зависит от:

* архитектуры;
* набора инструкций;
* памяти;
* кэша;
* периферии;
* оптимизации компилятора.

Для микроконтроллеров также важно энергопотребление.

---

# Flash

Flash — энергонезависимая память.

Она сохраняет данные после отключения питания.

Обычно здесь хранится:

```text
программа
константы
часть конфигурации
```

Например MCU может иметь:

```text
Flash: 512 KB
```

Это означает, что размер прошивки ограничен доступным пространством Flash.

Если программа занимает больше доступного объёма:

```text
прошивка > Flash
```

она не поместится.

---

# RAM

RAM используется во время выполнения программы.

Например:

```cpp
int temperature = 25;
int counter = 0;
```

Эти данные должны где-то храниться во время работы.

Для этого используется RAM.

После отключения питания:

```text
RAM → содержимое теряется
```

В отличие от:

```text
Flash → содержимое сохраняется
```

---

# Стек

Стек — область памяти, используемая для временных данных во время выполнения функций.

Например:

```cpp
void calculate()
{
    int a = 10;
    int b = 20;
}
```

Локальные переменные могут размещаться на стеке.

При входе в функцию создаётся её контекст.

При выходе память освобождается.

Упрощённо:

```text
вызвали функцию
      ↓
данные помещены в стек
      ↓
функция работает
      ↓
функция завершилась
      ↓
данные освобождены
```

---

# Stack Overflow

Память микроконтроллера ограничена.

Если программа использует слишком большой стек, может возникнуть stack overflow.

Например опасным может быть чрезмерное использование локальных массивов:

```cpp
void function()
{
    char buffer[10000];
}
```

Если RAM маленькая, такая конструкция может привести к проблемам.

Особенно опасны:

* большие локальные массивы;
* глубокая рекурсия;
* бесконтрольные вызовы функций.

---

# Heap

Некоторые микроконтроллерные программы используют динамическую память:

```cpp
new
delete
```

или контейнеры, которые используют динамическое выделение памяти.

Но в embedded-разработке с этим нужно быть осторожным.

Проблемы:

* фрагментация памяти;
* непредсказуемое время выделения;
* утечки памяти;
* нехватка RAM.

Поэтому в системах реального времени часто предпочитают заранее выделенные буферы и предсказуемое использование памяти.

---

# Глобальные и локальные данные

Например:

```cpp
int global_counter = 0;

void function()
{
    int local_value = 10;
}
```

`global_counter` существует всё время работы программы.

`local_value` существует только во время выполнения функции.

Упрощённая модель памяти:

```text
RAM
├── глобальные данные
├── статические данные
├── heap
│
└── stack
```

Реальное расположение зависит от компилятора и архитектуры.

---

# Память программы

После компиляции программа превращается в машинный код.

Например:

```text
source.cpp
    ↓
компилятор
    ↓
object files
    ↓
linker
    ↓
firmware
    ↓
Flash MCU
```

В результате в микроконтроллер загружается бинарная прошивка.

---

# Linker

Linker объединяет отдельные части программы.

Например:

```text
main.o
driver.o
sensor.o
motor.o
```

объединяются в итоговую прошивку.

При этом linker определяет расположение различных секций:

```text
код
константы
глобальные данные
```

и формирует итоговую карту памяти.

---

# Memory Map

У микроконтроллера существует адресное пространство.

Упрощённо:

```text
0x00000000
     │
     │ Flash
     │
     ▼
     ...
     │
     │ RAM
     │
     ▼
     ...
     │
     │ периферия
     │
     ▼
0xFFFFFFFF
```

Конкретные адреса зависят от архитектуры.

---

# Регистры периферии

Интересная особенность микроконтроллеров — периферия часто управляется через регистры.

Например условно:

```text
GPIO_OUTPUT_REGISTER
```

может управлять состоянием выходов.

Если изменить определённый бит:

```text
0 → LOW
1 → HIGH
```

выход GPIO изменится.

Поэтому когда мы пишем:

```cpp
digitalWrite(LED, HIGH);
```

библиотека в конечном итоге взаимодействует с аппаратной периферией MCU.

---

# Высокоуровневый и низкоуровневый подход

Можно управлять GPIO через библиотеку:

```cpp
digitalWrite(LED, HIGH);
```

А можно непосредственно работать с регистрами:

```text
записать бит
в регистр GPIO
```

Первый способ проще.

Второй даёт больше контроля и часто позволяет лучше понять устройство микроконтроллера.

На практике разработчик может использовать оба подхода.

---

# Reset

При включении питания или аппаратном сбросе MCU начинает запуск.

Причины reset могут быть разные:

* включение питания;
* нажатие кнопки reset;
* watchdog;
* программный reset;
* падение питания;
* аппаратная ошибка.

Упрощённо:

```text
RESET
  ↓
startup
  ↓
инициализация памяти
  ↓
инициализация системы
  ↓
main()
```

---

# Bootloader

Bootloader — небольшая программа, которая может запускаться до основной прошивки.

Она может отвечать за:

* загрузку новой прошивки;
* выбор режима запуска;
* обновление через USB;
* обновление через UART;
* восстановление устройства.

Упрощённо:

```text
Reset
  ↓
Bootloader
  ↓
основная программа
```

Но bootloader присутствует не во всех системах и может быть организован по-разному.

---

# Watchdog

Watchdog — аппаратный таймер, предназначенный для обнаружения зависания программы.

Принцип:

```text
программа работает
      ↓
периодически сбрасывает watchdog
      ↓
watchdog продолжает отсчёт
```

Если программа зависла:

```text
watchdog больше не сбрасывается
      ↓
таймер истекает
      ↓
RESET
```

Это особенно важно для автономных устройств.

Например робот может работать без человека.

Если программа зависла, система должна иметь возможность восстановиться.

---

# Почему память MCU важна

Представим микроконтроллер:

```text
Flash = 64 KB
RAM   = 8 KB
```

Нельзя относиться к нему как к компьютеру с гигабайтами памяти.

Нужно учитывать:

* размер программы;
* размер буферов;
* стек;
* данные;
* периферию;
* коммуникационные буферы.

Поэтому embedded-разработка требует более внимательного отношения к ресурсам.

---

# Пример

Допустим система измеряет температуру.

Нам нужно:

```text
ADC
 ↓
значение температуры
 ↓
фильтр
 ↓
буфер
 ↓
UART
```

В памяти могут находиться:

```text
Flash:
- программа
- константы

RAM:
- текущее измерение
- массив фильтра
- буфер UART
- стек
```

Это уже показывает, почему архитектура памяти имеет практическое значение.

---

# Главное

Упрощённо память и архитектуру MCU можно представить так:

```text
                MCU
                 │
        ┌────────┴────────┐
        │                 │
       CPU              память
        │                 │
        │          ┌──────┴──────┐
        │          │             │
        │        Flash          RAM
        │                        │
        │                 ┌──────┴──────┐
        │                 │             │
        │               Stack         данные
        │
        └─────────── периферия
                    │
          ┌─────────┼─────────┐
          ↓         ↓         ↓
         GPIO      ADC      Timers
```

Эта модель не описывает каждую деталь конкретного MCU, но даёт правильную основу для дальнейшего изучения.
