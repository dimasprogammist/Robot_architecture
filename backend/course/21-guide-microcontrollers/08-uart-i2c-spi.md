# UART, I²C и SPI

## Цель

Понять основные способы обмена данными между микроконтроллером, датчиками, дисплеями, модулями связи и другими электронными устройствами.

После урока вы должны понимать:

* что такое последовательный интерфейс;
* как работает UART;
* чем UART отличается от I²C и SPI;
* что такое baud rate;
* зачем нужны TX и RX;
* как несколько устройств подключаются к I²C;
* что такое адрес устройства;
* как работает SPI;
* зачем нужны CS, SCK, MOSI и MISO;
* какой интерфейс выбрать для конкретной задачи.

---

# Зачем микроконтроллерам интерфейсы

Микроконтроллер редко работает один.

К нему могут подключаться:

```text
датчик температуры
дисплей
память
GPS
Wi-Fi модуль
Bluetooth
другой контроллер
```

Чтобы передавать данные, нужны интерфейсы связи.

Например:

```text
MCU
 │
 ├── UART → компьютер
 │
 ├── I²C → датчики
 │
 ├── SPI → дисплей
 │
 └── GPIO → кнопки
```

---

# Последовательная передача

Самый простой принцип — передавать биты последовательно:

```text
1 0 1 1 0 0 1 0
```

То есть данные идут один за другим.

Это отличается от параллельной передачи, где несколько битов могут передаваться одновременно по нескольким линиям.

В микроконтроллерах последовательные интерфейсы очень распространены.

---

# UART

UART — Universal Asynchronous Receiver/Transmitter.

Это асинхронный последовательный интерфейс.

Обычно используются две линии:

```text
TX
RX
```

Подключение:

```text
MCU A TX ───── RX MCU B
MCU A RX ───── TX MCU B
MCU A GND ──── GND MCU B
```

Важно:

```text
TX → RX
RX → TX
```

---

# Почему UART называется asynchronous

У UART нет отдельной линии тактового сигнала.

Устройства заранее договариваются о скорости передачи.

Например:

```text
115200 baud
```

Оба устройства должны использовать совместимые настройки.

Обычно также задаются:

* количество бит данных;
* parity;
* количество stop bits.

Например:

```text
115200 8N1
```

означает:

```text
115200 baud
8 бит данных
No parity
1 stop bit
```

---

# Формат UART

Передача одного байта выглядит примерно так:

```text
start | data | stop
```

Например:

```text
0 | 10110010 | 1
```

Start bit сообщает:

> Началась передача.

Затем идут данные.

Stop bit сообщает:

> Передача завершена.

---

# Baud rate

Baud rate показывает скорость передачи символов/сигнальных элементов.

В типичном UART с одной битовой единицей на символ часто используют значение как ориентир для битовой скорости, но строго baud и bit/s не всегда одно и то же.

Для стандартного UART часто встречаются:

```text
9600
19200
38400
57600
115200
```

---

# UART на практике

Очень часто UART используется для:

* отладки;
* передачи команд;
* связи с GPS;
* связи с GSM/LTE-модулем;
* связи с другим микроконтроллером;
* подключения преобразователя USB-UART.

Например:

```cpp
Serial.begin(115200);
Serial.println("Hello");
```

Это типичный высокоуровневый пример.

---

# Важное ограничение UART

UART обычно предназначен для связи между конкретными устройствами.

Схема:

```text
A ↔ B
```

а не:

```text
A
│
├── B
├── C
└── D
```

Для нескольких устройств удобнее могут быть другие интерфейсы.

---

# I²C

I²C — двухпроводной синхронный интерфейс.

Основные линии:

```text
SDA — data
SCL — clock
```

Например:

```text
         ┌── Sensor A
         │
MCU ─────┼── Sensor B
         │
         └── Display
```

Все устройства могут находиться на одной шине.

---

# Адресация I²C

Каждое устройство имеет адрес.

Например:

```text
Sensor A → 0x48
Sensor B → 0x68
Display  → 0x3C
```

Микроконтроллер обращается:

```text
"Отправь запрос устройству 0x48"
```

Устройство с другим адресом его игнорирует.

---

# SDA и SCL

SCL — тактовый сигнал.

```text
SCL:
_|‾|_|‾|_|‾|_
```

SDA содержит данные.

Упрощённо:

```text
SCL → тактирование
SDA → данные
```

Так как I²C использует общую шину, электрическая схема требует pull-up резисторов на линиях.

---

# Несколько устройств

Главное преимущество I²C:

```text
             ┌── temperature sensor
             │
MCU ─────────┼── EEPROM
             │
             ├── IMU
             │
             └── display
```

Можно подключить несколько устройств всего через две сигнальные линии, если их адреса и электрические параметры позволяют это сделать.

---

# Проблема одинаковых адресов

Представим два одинаковых датчика:

```text
Sensor A → 0x68
Sensor B → 0x68
```

Они конфликтуют на одной шине, если оба используют один и тот же адрес и не предусмотрен способ их различить.

Возможные решения:

* изменить адрес одного устройства;
* использовать отдельный enable/reset;
* использовать I²C multiplexer;
* подключить устройства к разным шинам.

---

# SPI

SPI — синхронный последовательный интерфейс.

Обычно используются:

```text
SCK
MOSI
MISO
CS
```

Названия:

```text
SCK  → clock
MOSI → Master Out, Slave In
MISO → Master In, Slave Out
CS   → Chip Select
```

---

# SPI-соединение

Например:

```text
MCU
 │
 ├── SCK ─────────────┐
 ├── MOSI ────────────┤
 ├── MISO ────────────┤
 └── CS ──────────────┤
                      ▼
                   Device
```

Для нескольких устройств часто используется отдельный CS:

```text
             ┌── Sensor 1
SCK ─────────┼── Sensor 2
MOSI ────────┼── Sensor 3
MISO ────────┼── Sensor 4
             │
CS1 ─────────┘
CS2 ───────────── Sensor 2
CS3 ───────────── Sensor 3
```

---

# SPI быстрее I²C?

Во многих системах SPI может обеспечивать более высокую скорость передачи, чем типичный I²C.

Но это не означает, что SPI всегда лучше.

SPI требует больше линий.

Например:

```text
I²C:
SDA
SCL

SPI:
SCK
MOSI
MISO
CS
```

Если устройств много, количество CS-линий может стать существенным.

---

# Сравнение

| Интерфейс | Линии | Тактирование | Адресация | Типичная задача |
|---|---:|---|---|---|
| UART | 2 | нет | нет | связь двух устройств |
| I²C | 2 | есть | есть | датчики и периферия |
| SPI | 3–4+ | есть | CS | дисплеи, память, быстрый обмен |

Это упрощённое сравнение. Реальные возможности зависят от конкретного микроконтроллера и периферии.

---

# Почему важно понимать физический уровень

Нельзя просто сказать:

> Это UART, значит я могу соединить любые два устройства.

Нужно проверить:

* напряжение логических уровней;
* скорость;
* распиновку;
* электрическую совместимость;
* землю;
* режим интерфейса;
* максимальную длину линии.

Например:

```text
3.3 V MCU
```

и устройство:

```text
5 V logic
```

могут потребовать согласование уровней.

---

# UART и USB — не одно и то же

USB часто путают с UART.

USB — гораздо более сложный протокол и физический интерфейс.

Но существует:

```text
USB ↔ UART converter
```

Он позволяет компьютеру общаться с UART-устройством через USB.

Например:

```text
PC
 │ USB
 ▼
USB-UART
 │ TX/RX
 ▼
MCU
```

---

# Практический пример: датчик

Представим робота:

```text
MCU
 │
 ├── I²C → IMU
 │
 ├── I²C → temperature sensor
 │
 ├── SPI → display
 │
 └── UART → PC
```

Это вполне типичная архитектура.

---

# Когда выбрать UART

UART удобен, когда:

* устройств мало;
* нужна простая точка-точка связь;
* требуется отладочный порт;
* подключается внешний модуль;
* нужна простая команда/ответ.

---

# Когда выбрать I²C

I²C удобен, когда:

* нужно много небольших периферийных устройств;
* важна экономия GPIO;
* скорость умеренная;
* устройства поддерживают I²C;
* нужна общая шина.

---

# Когда выбрать SPI

SPI удобен, когда:

* нужна высокая скорость;
* устройство поддерживает SPI;
* требуется быстрая передача;
* используется дисплей;
* используется внешняя память;
* допустимо большее количество линий.

---

# Связь с промышленной автоматикой

UART, I²C и SPI чаще встречаются внутри электронного устройства.

Например:

```text
датчик
  │
  └── I²C
       │
       ▼
микроконтроллер
       │
       └── UART
            │
            ▼
       другой модуль
```

А уже внешний промышленный обмен может использовать:

* RS-485;
* Modbus RTU;
* CAN;
* Ethernet;
* другие протоколы.

Это важное различие:

> UART, SPI и I²C — интерфейсы/механизмы обмена, а поверх физических каналов могут работать более высокоуровневые протоколы.
