# Прерывания микроконтроллера

## Цель

Понять, как микроконтроллер может быстро реагировать на события, не проверяя каждое устройство вручную в основном цикле программы.

После урока вы должны понимать:

* что такое прерывание;
* зачем оно нужно;
* чем прерывание отличается от обычного опроса;
* что такое ISR;
* как работают внешние прерывания;
* как таймеры связаны с прерываниями;
* почему обработчик прерывания должен быть коротким;
* что такое `volatile`;
* почему нельзя бездумно выполнять сложный код внутри ISR;
* где прерывания используются в робототехнике и автоматизации.

---

# Опрос устройств

Представим кнопку.

Самый простой способ:

```cpp
while (true) {
    if (buttonPressed()) {
        doSomething();
    }
}
```

Процессор постоянно спрашивает:

```text
Кнопка нажата?
Нет.

Кнопка нажата?
Нет.

Кнопка нажата?
Нет.

Кнопка нажата?
Да!
```

Это называется **опросом**, или polling.

Для некоторых задач он вполне подходит.

Но есть проблема: если событие происходит очень быстро, программа может его пропустить.

---

# Что такое прерывание

Прерывание позволяет периферийному устройству сообщить процессору:

> Произошло важное событие, обработай его.

Например:

```text
GPIO
 │
 │ изменение сигнала
 ▼
система прерываний
 │
 ▼
CPU
 │
 ▼
обработчик
```

Процессору не нужно постоянно спрашивать GPIO.

Событие само вызывает реакцию.

---

# Пример с кнопкой

Допустим, кнопка подключена к GPIO.

При нажатии появляется переход:

```text
HIGH
  │
  │
  └────────────
               │
               ▼
              LOW
```

GPIO может быть настроен так, чтобы при этом переходе вызвать прерывание.

Логически:

```cpp
volatile bool buttonPressed = false;

void buttonInterrupt() {
    buttonPressed = true;
}
```

А основной код:

```cpp
while (true) {
    if (buttonPressed) {
        buttonPressed = false;

        handleButton();
    }

    doOtherTasks();
}
```

---

# ISR

Функция, которая вызывается при прерывании, называется обработчиком прерывания.

Часто используется термин:

```text
ISR
Interrupt Service Routine
```

или:

```text
Interrupt Handler
```

Она выполняет небольшую срочную работу.

Например:

```cpp
void timerISR() {
    tick = true;
}
```

Это хороший пример.

---

# Почему ISR должен быть коротким

Представим:

```cpp
void interruptHandler() {
    calculateHugeMatrix();
    readSeveralSensors();
    sendUARTPacket();
    writeDatabase();
}
```

Это плохая архитектура.

Пока выполняется обработчик, процессор занят им.

Другие события могут:

* задержаться;
* потеряться;
* получить более высокую задержку;
* вызвать переполнение буфера.

Лучше:

```cpp
void interruptHandler() {
    eventPending = true;
}
```

А тяжёлую работу выполнить позже:

```cpp
if (eventPending) {
    eventPending = false;
    processEvent();
}
```

---

# Приоритеты

В реальном микроконтроллере прерываний может быть много.

Например:

```text
аварийный вход
таймер управления
UART
ADC
GPIO
SPI
```

Некоторые события важнее других.

Поэтому многие архитектуры микроконтроллеров позволяют задавать приоритеты.

Упрощённо:

```text
высокий приоритет
       │
       ▼
аварийная остановка

       │
       ▼
контроль двигателя

       │
       ▼
обмен данными

       │
       ▼
диагностика
```

Конкретные возможности зависят от архитектуры CPU.

---

# Прерывание и основной код

Можно представить работу процессора так:

```text
main()
  │
  ├── задача A
  │
  ├── задача B
  │
  ├── задача C
  │
  └── задача D
```

Внезапно происходит событие:

```text
                 interrupt
                    │
                    ▼
main() ─────────► ISR
                    │
                    ▼
                 return
                    │
                    ▼
main() продолжается
```

Процессор временно меняет поток выполнения.

---

# Внешние прерывания

GPIO может генерировать прерывания при разных событиях.

Например:

```text
RISING EDGE
LOW → HIGH
```

или:

```text
FALLING EDGE
HIGH → LOW
```

или:

```text
CHANGE
любое изменение
```

Также некоторые микроконтроллеры поддерживают прерывание при определённом уровне сигнала.

---

# Энкодер

Один из важных примеров — энкодер.

Например, датчик выдаёт:

```text
A:  _|‾|_|‾|_|‾|_
B:   _|‾|_|‾|_|‾
```

По изменению каналов можно определить:

* движение;
* направление;
* количество импульсов.

Прерывания позволяют быстро фиксировать переходы.

---

# Таймер + прерывание

Таймер сам по себе считает время.

Прерывание позволяет сообщить CPU:

```text
таймер достиг нужного значения
```

Например:

```text
Timer
  │
  ├── 1
  ├── 2
  ├── 3
  │
  └── достиг значения
           │
           ▼
       interrupt
```

Так можно реализовать системный тик:

```cpp
volatile uint32_t ticks = 0;

void timerISR() {
    ticks++;
}
```

---

# Что такое volatile

Рассмотрим:

```cpp
bool event = false;
```

Если значение изменяется внутри прерывания, компилятор должен понимать, что оно может измениться независимо от обычного потока программы.

Для этого часто используется:

```cpp
volatile bool event = false;
```

`volatile` говорит компилятору:

> Значение этой переменной может измениться вне обычного последовательного потока выполнения. Не считай, что оно всегда остаётся прежним.

Например:

```cpp
volatile bool dataReady = false;

void uartISR() {
    dataReady = true;
}
```

Основной код:

```cpp
if (dataReady) {
    dataReady = false;
    processData();
}
```

Но важно понимать:

> `volatile` не делает операцию автоматически атомарной и не решает проблемы синхронизации.

---

# Атомарность

Некоторые операции над переменными могут выполняться несколькими машинными инструкциями.

Например, если переменная занимает больше одного машинного слова процессора:

```cpp
volatile uint64_t counter;
```

и ISR одновременно изменяет её, может возникнуть ситуация, когда основной код прочитает промежуточное состояние.

Поэтому для сложных случаев нужны:

* атомарные операции;
* временное отключение конкретного прерывания;
* критические секции;
* специальные примитивы синхронизации.

Конкретный механизм зависит от микроконтроллера и среды разработки.

---

# Антидребезг

Механические кнопки не переключаются идеально.

При одном нажатии контакт может несколько раз изменить состояние:

```text
HIGH
LOW
HIGH
LOW
HIGH
LOW
```

Это может вызвать несколько прерываний вместо одного.

Поэтому для кнопок часто используют программный debounce.

Например:

```cpp
void buttonISR() {
    buttonEvent = true;
}
```

А потом:

```cpp
if (buttonEvent) {
    buttonEvent = false;

    if (millis() - lastButtonTime > 30) {
        lastButtonTime = millis();
        handleButton();
    }
}
```

---

# Прерывания и связь

UART, SPI, I²C и другие периферийные блоки могут использовать прерывания.

Например, UART получает байт:

```text
UART
 │
 │ byte received
 ▼
interrupt
 │
 ▼
buffer
```

ISR быстро помещает байт в буфер:

```cpp
rxBuffer.push(byte);
```

А основная программа позже разбирает сообщение.

Это позволяет не блокировать CPU ожиданием каждого байта.

---

# Прерывания и DMA

В более сложных микроконтроллерах используется DMA — Direct Memory Access.

DMA может самостоятельно передавать данные:

```text
ADC
 │
 ▼
DMA
 │
 ▼
RAM
```

После завершения передачи DMA вызывает прерывание:

```text
DMA finished
     │
     ▼
interrupt
     │
     ▼
process buffer
```

Так CPU не обязан обрабатывать каждый отдельный байт.

---

# Прерывание не равно многопоточности

Важно не путать прерывания с обычными потоками.

Прерывание не создаёт полноценный независимый поток программы.

Обычно происходит:

```text
основной код
    ↓
прерывание
    ↓
ISR
    ↓
возврат
    ↓
основной код
```

Поэтому ISR нужно проектировать очень аккуратно.

---

# Типичная архитектура

Хороший шаблон:

```cpp
volatile bool event = false;

void interruptHandler() {
    event = true;
}

void loop() {
    if (event) {
        event = false;
        processEvent();
    }

    runOtherTasks();
}
```

Принцип:

> Прерывание фиксирует событие, а основной код выполняет сложную работу.

---

# Где это используется

Прерывания применяются для:

* кнопок;
* энкодеров;
* таймеров;
* UART;
* SPI;
* ADC;
* PWM;
* DMA;
* датчиков;
* аварийных сигналов;
* измерения частоты;
* измерения импульсов.

В промышленной автоматизации похожая идея встречается в аппаратных событиях PLC и периферийных модулях.

---

# Что важно запомнить

Прерывание — механизм, позволяющий процессору реагировать на событие без постоянного опроса.

Главное правило:

```text
ISR:
    быстро зафиксировать событие

Основной код:
    выполнить основную работу
```

Не стоит превращать обработчик прерывания в отдельную большую программу.
