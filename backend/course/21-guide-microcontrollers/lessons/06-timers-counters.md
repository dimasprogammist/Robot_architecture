# Таймеры и счётчики микроконтроллера

## Цель

Научиться понимать, зачем микроконтроллеру нужны таймеры и счётчики и почему многие задачи нельзя надёжно решать обычными задержками в программе.

После урока вы должны понимать:

* что такое аппаратный таймер;
* чем таймер отличается от обычного счётчика;
* как микроконтроллер измеряет время;
* что такое частота и период;
* как работают делители частоты;
* как с помощью таймера выполнять действие через заданный интервал;
* как считать импульсы внешнего сигнала;
* почему `delay()` часто является плохим решением;
* как таймеры связаны с PWM, UART, измерением сигналов и управлением двигателями.

---

## Зачем микроконтроллеру нужен таймер

Микроконтроллер работает очень быстро.

Если процессор выполняет миллионы инструкций в секунду, возникает простой вопрос:

> Как заставить программу выполнить определённое действие, например, ровно через 100 миллисекунд?

Самый простой вариант выглядит примерно так:

```cpp
while (true) {
    doSomething();
    delay(100);
}
```

Но здесь процессор большую часть времени просто ждёт.

Для простых программ это допустимо. Но в реальном устройстве одновременно могут происходить разные события:

* нужно опрашивать кнопку;
* читать датчик;
* управлять мотором;
* отправлять данные по UART;
* контролировать аварийный сигнал;
* обновлять дисплей;
* считать импульсы энкодера.

Если программа постоянно блокируется на `delay()`, она начинает хуже реагировать на события.

Поэтому микроконтроллеры имеют специальные аппаратные блоки — **таймеры**.

---

# Что такое таймер

Таймер — это периферийный блок микроконтроллера, который считает тактовые импульсы.

Упрощённо:

```text
тактовый генератор
       │
       ▼
   ┌─────────┐
   │ Таймер  │
   │ 0 1 2 3 │
   └────┬────┘
        │
        ▼
    счётчик
        │
        ▼
 событие / прерывание
```

Таймер получает импульсы от тактового источника и увеличивает внутреннее значение счётчика.

Например:

```text
0
1
2
3
4
5
...
```

Когда счётчик достигает определённого значения, таймер может:

* установить флаг;
* вызвать прерывание;
* изменить состояние вывода;
* перезапустить счёт;
* сформировать PWM;
* запустить другое аппаратное действие.

---

# Тактовая частота

Чтобы понять работу таймера, нужно понимать частоту.

Если микроконтроллер работает с частотой:

```text
16 МГц
```

это означает:

```text
16 000 000 тактов в секунду
```

Период одного такта:

```text
T = 1 / f
```

Для 16 МГц:

```text
T = 1 / 16 000 000
  = 62,5 нс
```

Таймер может использовать эту частоту напрямую или через делитель.

---

# Предделитель

Обычно таймеру не нужно считать каждый такт процессора.

Для этого используется **предделитель**.

Например:

```text
CPU clock = 16 МГц
prescaler = 16

16 000 000 / 16 = 1 000 000 Гц
```

Теперь таймер получает:

```text
1 000 000 импульсов/с
```

Один шаг счётчика соответствует:

```text
1 мкс
```

Это уже намного удобнее для измерения времени.

---

# Переполнение таймера

Допустим, таймер имеет 8-битный счётчик.

Он может хранить:

```text
0 ... 255
```

После:

```text
255
```

следующее значение:

```text
0
```

Происходит **переполнение**.

```text
253
254
255
  ↓
  0
  1
  2
```

На переполнение можно назначить событие.

Например:

```cpp
void timerInterrupt() {
    ledState = !ledState;
}
```

Тогда светодиод может автоматически переключаться через определённый интервал.

---

# Почему аппаратный таймер лучше delay()

Рассмотрим:

```cpp
delay(1000);
```

В течение этой секунды основной код не может нормально продолжать выполнение.

Например:

```cpp
turnMotorOn();

delay(1000);

turnMotorOff();
```

Для такой задачи это может быть нормально.

Но представим:

```text
мотор
датчик температуры
аварийная кнопка
энкодер
UART
```

Нельзя просто написать:

```cpp
delay(1000);
```

и надеяться, что контроллер всё это время ничего не пропустит.

Таймер позволяет разделить задачи:

```text
таймер 1 → каждые 1 мс
таймер 2 → каждые 10 мс
таймер 3 → PWM
UART      → передача данных
CPU       → основная логика
```

---

# Периодическое выполнение

Одна из самых распространённых задач таймера:

> Выполнять действие каждые N миллисекунд.

Например, читать датчик каждые 100 мс.

Логически это выглядит так:

```text
0 ms
│
├── чтение датчика
│
100 ms
│
├── чтение датчика
│
200 ms
│
├── чтение датчика
│
300 ms
│
└── ...
```

В реальном проекте это часто реализуется через системный тик.

Например:

```cpp
uint32_t lastRead = 0;

void loop() {
    uint32_t now = millis();

    if (now - lastRead >= 100) {
        lastRead = now;

        readSensor();
    }

    processButtons();
    processCommunication();
    controlMotor();
}
```

Здесь процессор не блокируется.

---

# Почему проверка разницы лучше абсолютного сравнения

Лучше писать:

```cpp
if (now - lastRead >= 100) {
    ...
}
```

чем:

```cpp
if (now == lastRead + 100) {
    ...
}
```

Причина в том, что значение системного времени постоянно увеличивается и может перейти через максимальное значение.

Кроме того, программа может не попасть ровно в нужную миллисекунду.

Например:

```text
99
100
101
102
```

Если программа проверила время на `102`, условие:

```cpp
now == 100
```

уже не выполнится.

А:

```cpp
now - lastRead >= 100
```

сработает.

---

# Таймер как источник прерываний

Таймер может вызвать **прерывание**.

Основная программа:

```cpp
while (true) {
    mainTask();
}
```

Таймер:

```text
      таймер
         │
         │ время истекло
         ▼
     прерывание
         │
         ▼
 interrupt handler()
         │
         ▼
 возвращение
         │
         ▼
 mainTask()
```

Это позволяет быстро реагировать на события.

Но обработчик прерывания должен быть коротким.

Плохо:

```cpp
void timerInterrupt() {
    readLargeSensor();
    sendHugePacket();
    calculateSomethingComplex();
    delay(100);
}
```

Лучше:

```cpp
volatile bool tick = false;

void timerInterrupt() {
    tick = true;
}
```

А основная программа уже выполняет работу:

```cpp
if (tick) {
    tick = false;
    processTask();
}
```

# Счётчик импульсов

Тот же аппаратный блок может использоваться не только для времени.

Он может считать внешние импульсы.

Например, энкодер создаёт:

```text
|‾|_|‾|_|‾|_|‾|_
```

Каждый импульс увеличивает счётчик:

```text
0
1
2
3
4
...
```

Так можно определить:

* количество оборотов;
* скорость вращения;
* количество изделий;
* расход жидкости;
* количество событий.

---

# Измерение частоты

Если за одну секунду пришло:

```text
500 импульсов
```

то частота:

```text
f = 500 Гц
```

Если известно количество импульсов на оборот, можно вычислить скорость.

Например:

```text
энкодер = 100 импульсов/оборот
```

Получили:

```text
500 импульсов/с
```

Тогда:

```text
500 / 100 = 5 оборотов/с
```

или:

```text
5 × 60 = 300 об/мин
```

---

# Измерение длительности импульса

Таймер можно использовать и наоборот.

Вместо подсчёта количества импульсов можно измерять время между ними.

Например:

```text
↑                  ↑
│<---- 10 ms ----->│
```

Если период:

```text
T = 10 мс
```

то:

```text
f = 1 / 0,01 = 100 Гц
```

Это полезно для:

* датчиков;
* энкодеров;
* тахометров;
* частотных сигналов;
* измерения скорости.

---

# Таймеры и PWM

PWM, который мы рассматривали в предыдущем уроке, обычно создаётся аппаратными таймерами.

Например:

```text
таймер
  │
  ├── считает
  │
  ├── сравнивает значение
  │
  └── переключает GPIO
```

Поэтому PWM и таймеры тесно связаны.

У микроконтроллера может быть несколько таймеров:

```text
Timer 0 → системное время
Timer 1 → PWM
Timer 2 → счёт импульсов
Timer 3 → другой PWM
```

Конкретная архитектура зависит от микроконтроллера.

---

# Таймеры в робототехнике

В роботе таймеры используются практически повсюду.

Например:

```text
каждые 1 мс
    ↓
обновление регулятора

каждые 10 мс
    ↓
чтение датчиков

каждые 20 мс
    ↓
обновление сервопривода

каждые 100 мс
    ↓
диагностика

каждые 1000 мс
    ↓
статистика
```

Так появляется понятная временная архитектура программы.

---

# Практический пример

Представим контроллер двигателя.

Нужно:

* читать энкодер;
* считать скорость;
* обновлять PWM;
* проверять температуру;
* отправлять диагностику.

Можно организовать программу так:

```text
Timer 1:
    PWM

Timer 2:
    системный тик 1 мс

каждые 10 мс:
    скорость

каждые 100 мс:
    температура

каждые 1000 мс:
    диагностика
```

Это гораздо надёжнее, чем строить всё вокруг большого количества `delay()`.

---

# Что важно запомнить

Таймер — это аппаратный механизм измерения времени и формирования событий.

Он может использоваться для:

* периодического выполнения задач;
* формирования PWM;
* генерации прерываний;
* измерения времени;
* подсчёта импульсов;
* измерения частоты;
* измерения скорости;
* работы с энкодерами.

Главная идея:

> Таймер позволяет микроконтроллеру работать со временем аппаратно, не заставляя основной код постоянно ждать.
