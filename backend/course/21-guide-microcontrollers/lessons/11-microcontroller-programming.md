# Программирование микроконтроллера

## Цель

Понять, как обычная программа превращается в прошивку микроконтроллера и как устроен типичный цикл работы embedded-программы.

После урока вы должны понимать:

* что такое firmware;
* чем программа микроконтроллера отличается от программы для ПК;
* что такое компиляция;
* что такое прошивка;
* что происходит после сброса;
* зачем нужны startup-код и `main`;
* как устроен главный цикл;
* как организовать несколько задач;
* зачем нужны состояния;
* почему нельзя строить программу из одних `delay()`;
* как отлаживать embedded-программы.

---

# Что такое firmware

Программа, которая работает непосредственно внутри устройства, часто называется:

> firmware — прошивка.

Например:

```text
Python-программа на ПК
```

работает в операционной системе.

А:

```text
firmware
```

записана во Flash микроконтроллера и запускается непосредственно на устройстве.

---

# Из исходного кода в прошивку

Обычно путь выглядит так:

```text
исходный код
    ↓
компилятор
    ↓
объектный код
    ↓
линкер
    ↓
прошивка
    ↓
запись во Flash
    ↓
микроконтроллер
```

Например, для C/C++ проекта могут получаться файлы:

```text
.elf
.hex
.bin
```

Конкретный набор зависит от toolchain.

---

# Компилятор

Допустим, написано:

```cpp
int main() {
    return 0;
}
```

Компилятор переводит исходный код в машинные инструкции, которые понимает CPU конкретного микроконтроллера.

Например:

```text
C/C++
   ↓
compiler
   ↓
machine code
```

Поэтому программа, собранная для одной архитектуры, не обязательно запустится на другой.

---

# Архитектура процессора

Например, существуют микроконтроллеры на архитектурах:

```text
ARM Cortex-M
RISC-V
AVR
```

У них разные наборы инструкций и периферия.

Поэтому компилятор должен знать целевую платформу.

---

# Flash

После сборки прошивку записывают во Flash.

Упрощённо:

```text
PC
 │
 │ programmer/debugger
 ▼
MCU Flash
```

После этого микроконтроллер может запускать программу самостоятельно.

---

# Что происходит после включения

После подачи питания или сброса процессор начинает выполнение с определённой точки.

Упрощённо:

```text
Power On
   ↓
Reset
   ↓
Startup code
   ↓
инициализация памяти
   ↓
инициализация системы
   ↓
main()
```

Startup-код выполняет подготовительную работу перед основной программой.

---

# main()

Для embedded C/C++ программа часто имеет:

```cpp
int main() {
    initHardware();

    while (true) {
        runTasks();
    }
}
```

В отличие от программы на обычном ПК, микроконтроллерная программа часто не должна завершаться.

Устройство должно работать постоянно:

```text
включили
   ↓
работает
   ↓
работает
   ↓
работает
   ↓
работает
```

---

# Инициализация

До главного цикла нужно настроить оборудование.

Например:

```cpp
void initHardware() {
    initGPIO();
    initADC();
    initTimers();
    initUART();
}
```

После этого:

```cpp
while (true) {
    ...
}
```

может использовать периферию.

---

# Главный цикл

Один из распространённых подходов:

```cpp
while (true) {
    readInputs();
    processLogic();
    updateOutputs();
    processCommunication();
}
```

Это называется super loop.

Он прост и хорошо подходит для небольших систем.

---

# Почему один огромный loop — плохая идея

Если всё поместить в один огромный блок:

```cpp
while (true) {
    // 3000 строк
}
```

становится трудно понимать:

* что отвечает за датчики;
* что отвечает за мотор;
* где связь;
* где аварии;
* где таймеры.

Лучше разделять программу на логические части.

Например:

```cpp
while (true) {
    updateSensors();
    updateControl();
    updateMotors();
    updateCommunication();
    updateDiagnostics();
}
```

---

# Неблокирующая архитектура

Плохо:

```cpp
while (true) {
    motorOn();
    delay(5000);
    motorOff();
    delay(5000);
}
```

Во время `delay()` программа практически не занимается остальными задачами.

Лучше использовать время:

```cpp
uint32_t now = getTime();

if (now - lastMotorUpdate >= 100) {
    lastMotorUpdate = now;
    updateMotor();
}
```

Так одна программа может обслуживать много задач.

---

# Состояния

Для сложных устройств удобно использовать state machine.

Например:

```text
STARTING
   ↓
IDLE
   ↓
RUNNING
   ↓
STOPPING
   ↓
IDLE
```

При аварии:

```text
RUNNING
   ↓
FAULT
```

Программно:

```cpp
enum class State {
    Starting,
    Idle,
    Running,
    Stopping,
    Fault
};
```

Дальше:

```cpp
switch (state) {
    case State::Starting:
        handleStarting();
        break;

    case State::Idle:
        handleIdle();
        break;

    case State::Running:
        handleRunning();
        break;

    case State::Stopping:
        handleStopping();
        break;

    case State::Fault:
        handleFault();
        break;
}
```

Это особенно полезно для роботов и автоматических устройств.

---

# Состояния лучше набора флагов

Можно попытаться написать:

```cpp
bool running;
bool starting;
bool stopping;
bool fault;
```

Но легко получить невозможное состояние:

```text
running = true
fault = true
stopping = true
```

State machine ограничивает набор допустимых состояний.

---

# Работа с ошибками

Embedded-программа должна учитывать неисправности.

Например:

```text
датчик не отвечает
        ↓
ошибка

температура слишком высокая
        ↓
ошибка

питание нестабильно
        ↓
ошибка
```

Не следует просто продолжать управление опасной нагрузкой.

Например:

```cpp
if (!sensorOk) {
    stopMotor();
    state = State::Fault;
}
```

# Диагностика

Очень полезно иметь диагностические данные:

```text
uptime
error code
sensor status
motor status
temperature
counter
communication status
```

И выводить их через:

```text
UART
USB
CAN
Ethernet
```

Это значительно упрощает поиск проблем.

# Отладка

В embedded-разработке используются:

* serial logging;
* debugger;
* breakpoints;
* watch variables;
* logic analyzer;
* oscilloscope;
* multimeter.

Например, если PWM работает неправильно, можно посмотреть реальный сигнал осциллографом.

Если UART не работает — проверить TX/RX и физический сигнал.

---

# Логический анализатор

Логический анализатор особенно полезен для цифровых интерфейсов.

Например:

```text
SCL
_|‾|_|‾|_|‾|_

SDA
__|‾‾|___|‾|__
```

Можно увидеть:

* частоту;
* импульсы;
* протокол;
* ошибки передачи.

---

# Отладка через UART

Простой вариант:

```cpp
debug("Motor started");
```

И в терминале:

```text
Motor started
Temperature: 31.4
Speed: 1200
State: RUNNING
```

Но логирование тоже потребляет ресурсы.

Поэтому в реальном устройстве обычно контролируют объём диагностических данных.

---

# Watchdog

Если программа зависла:

```text
CPU
 ↓
не выполняет main loop
 ↓
watchdog timeout
 ↓
reset
```

Хорошая embedded-система должна предусматривать восстановление после некоторых типов программных зависаний.

---

# Конфигурация

Настройки устройства могут храниться:

* во Flash;
* EEPROM;
* внешней памяти;
* отдельной области памяти;
* внешнем сервере, если устройство сетевое.

Например:

```text
maxTemperature = 80
motorSpeed = 60
timeout = 500
```

Важно отличать:

```text
код программы
```

от:

```text
конфигурации устройства
```

---

# Обновление прошивки

Устройство можно обновлять.

Простой вариант:

```text
PC
 ↓
programmer
 ↓
Flash
```

Более сложный:

```text
server
 ↓
network
 ↓
bootloader
 ↓
new firmware
```

Это называется OTA — Over-The-Air, если обновление выполняется по сети.

Для промышленного устройства обновление должно учитывать:

* проверку целостности;
* совместимость;
* возможность восстановления;
* защиту от повреждённой прошивки.

---

# Bootloader

Bootloader — небольшая программа, которая может запускаться перед основной прошивкой.

Упрощённо:

```text
Reset
  ↓
Bootloader
  │
  ├── нужно обновление?
  │       ↓
  │      YES
  │       ↓
  │    загрузить firmware
  │
  └── иначе
          ↓
       application
```

Это позволяет обновлять устройство без отдельного программатора в некоторых системах.

---

# Организация проекта

Большой embedded-проект не должен быть одним файлом.

Например:

```text
src/
    main.cpp
    gpio.cpp
    gpio.h
    adc.cpp
    adc.h
    motor.cpp
    motor.h
    sensors.cpp
    sensors.h
    communication.cpp
    communication.h
    control.cpp
    control.h
```

Так проще поддерживать код.

---

# Главное правило

Embedded-программа должна быть:

* предсказуемой;
* понятной;
* устойчивой;
* контролируемой по времени;
* безопасной при ошибках.

В микроконтроллере ресурсы ограничены, поэтому архитектура имеет особенно большое значение.
