# Компоненты системы

## Цель

Научиться выделять компоненты — относительно независимые части с чётким интерфейсом — в сервисе заказов. После урока вы назовёте компоненты Orders API и скажете, какой интерфейс у каждого.

## Что уже нужно понимать

Зачем архитектура. Компонент здесь — не React-кнопка, а кусок системы, который можно понять и заменить, не переписывая всё. В коде это часто пакет/класс с узким публичным API и скрытыми деталями.

## Объяснение

Компонент отвечает на вопрос: «что можно обсуждать как единицу?». Примеры в Orders:

- **API HTTP** — перевод HTTP↔DTO, коды ответов;
- **Домен заказов** — статусы, инварианты;
- **Хранилище** — SQL/репозиторий;
- **Уведомления** — email/push;
- **Антифрод** (если появится) — отдельное решение «пропустить/нет».

Признаки хорошего компонента: имя по роли, небольшой публичный интерфейс, внутренности скрыты, зависимости направлены осознанно. Плохой «компонент»: пакет `utils` на всё подряд или класс `OrderManager` на 2000 строк.

Компонент не обязан быть отдельным процессом. В монолите компоненты — модули. Путаница «компонент = микросервис» приводит к разрезанию по техническим слоям через сеть без нужды.

Интерфейс компонента — функции/порты, которые разрешено вызывать снаружи. Всё остальное — `_private` по соглашению или отдельные модули без экспорта в `__init__`.

## Термины

- **Интерфейс компонента** — разрешённые операции снаружи.
- **Инкапсуляция** — детали спрятаны за интерфейсом.
- **Композиция** — система собирается из компонентов.
- **Граничный компонент** — говорит с внешним миром (HTTP, БД, брокер).

## Как это устроено

Сборка Orders monolith:

```text
[Frontend] → [API component] → [Order domain component] → [Orders repository]
                                      ↓
                               [Notifier component]
```

API не вызывает SQL напрямую. Notifier не знает про FastAPI. Repository не шлёт письма. Домен не форматирует HTTP 422.

При росте «отчёты по заказам» может появиться компонент Read Model, который читает БД или проекцию — не обязательно пихать JOIN в `OrderService.ship`.

Документируйте публичные функции модуля. Если коллеги импортируют `from orders.repo.sql import _session_hack` — граница бумажная.

## Пример

```python
# orders/domain.py — компонент домена (упрощённо)
from dataclasses import dataclass
from enum import Enum

class Status(str, Enum):
    NEW = "new"
    PACKING = "packing"
    SHIPPED = "shipped"
    CANCELLED = "cancelled"

@dataclass(frozen=True)
class Order:
    id: int
    customer: str
    city: str
    status: Status

    def start_packing(self) -> "Order":
        if self.status != Status.NEW:
            raise ValueError("only new → packing")
        return Order(self.id, self.customer, self.city, Status.PACKING)


# orders/notifier.py — компонент уведомлений
class Notifier:
    def order_shipped(self, order: Order) -> None:
        raise NotImplementedError

class ConsoleNotifier(Notifier):
    def order_shipped(self, order: Order) -> None:
        print(f"mail to customer of order {order.id}: shipped")
```

```python
# Снаружи разрешено:
# Order.start_packing, Notifier.order_shipped
# Не разрешено (по договорённости): лезть в SQL из Notifier
```

## Разбор примера

`Order.start_packing` держит инвариант перехода. Это часть доменного компонента, доступная сервису приложения. `Notifier` — другой компонент с узким методом; консольная реализация годится для локальной разработки.

Компоненты стыкуются через типы `Order` и абстракцию `Notifier`, а не через общие глобальные переменные. Замена email на «запись в outbox» не требует правки правила `start_packing`.

## Типичные ошибки

- Нарезать компоненты по техническим файлам (`controllers`, `helpers`) без дословной роли.
- Делать «божественный» компонент на всё.
- Путать компонент и поток (thread) или контейнер Docker.
- Экспортировать всё подряд из пакета.

## Что запомнить

Компонент — единица ответственности с интерфейсом. В монолите это модули. Orders API естественно делится на API, домен, хранилище, уведомления. Сеть между ними не обязательна. Дисциплина импортов делает границу реальной.
