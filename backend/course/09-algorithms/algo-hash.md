# Хеш-таблица

## Цель

Понять словарь и множество: ключ отображается в корзину через хеш, средняя сложность вставки и поиска O(1), главный риск — коллизии и нехешируемые ключи.

## Что уже нужно знать

Массивы, O-нотация, идея «ключ уникально идентифицирует запись».

## Объяснение с нуля

Хеш-таблица превращает ключ в индекс корзины функцией хеширования. В идеале разные ключи попадают в разные корзины, и операция сводится к доступу к ячейке. Реально бывают **коллизии**: два ключа в одну корзину. Тогда используют цепочки списков или открытую адресацию.

В среднем при хорошем хеше и умеренном заполнении операции O(1). В худшем (все ключи в одной корзине) поведение как у списка — O(n). В Python `dict` и `set` — хеш-таблицы; контракт для практики: средний O(1) по ключу.

Зачем: индекс по id, подсчёт частот, проверка «уже видели», соединение таблиц в памяти. Ключ должен быть хешируемым: для встроенных типов это неизменяемые объекты (`int`, `str`, `tuple` из хешируемых). Список нельзя сделать ключом dict.

## Термины

- **Хеш-функция** — отображение ключа в целое.
- **Корзина (bucket)** — слот таблицы.
- **Коллизия** — разные ключи попали в один слот.
- **Коэффициент заполнения** — доля занятых слотов относительно ёмкости.

## Внутреннее устройство

При вставке: посчитать хеш → найти слот → разрешить коллизию → записать. При поиске — тот же путь. При росте таблицы делают rehash: выделяют большую таблицу и перекладывают ключи. Это редкая дорогая операция; амортизированно вставки остаются дешёвыми.

## Пример: частоты на восьми числах

Поток: `[2, 7, 2, 9, 7, 2, 1, 9]`.

### Пошаговый разбор

1. 2 → `{2: 1}`
2. 7 → `{2: 1, 7: 1}`
3. 2 → `{2: 2, 7: 1}`
4. 9 → `{2: 2, 7: 1, 9: 1}`
5. 7 → `{2: 2, 7: 2, 9: 1}`
6. 2 → `{2: 3, 7: 2, 9: 1}`
7. 1 → `{2: 3, 7: 2, 9: 1, 1: 1}`
8. 9 → `{2: 3, 7: 2, 9: 2, 1: 1}`

Запрос «сколько двоек» — один доступ по ключу 2.

### Код на Python

```python
from collections import Counter


def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    need: dict[int, int] = {}
    for i, x in enumerate(nums):
        if target - x in need:
            return need[target - x], i
        need[x] = i
    return None


assert two_sum([2, 7, 11, 15, 3, 6], 9) == (0, 1)
assert Counter([2, 7, 2, 9, 7, 2, 1, 9])[2] == 3
```

### Сложность

`two_sum`: один проход, среднее время O(n), память O(n). Наивный двойной цикл был бы O(n²) по времени и O(1) по памяти.

## Практика

Найдите первый элемент с частотой 1 за один-два прохода. Разберите на массиве `[2, 7, 2, 9, 7, 2, 1, 9]`.

## Типичные ошибки

- Использовать `list` как ключ словаря.
- Ожидать O(1) в худшем случае без оговорок.
- Мутировать объект, который уже лежит как ключ (для своих классов).
- Строить dict там, где достаточно массива индексов 0..n-1.

## Что запомнить

Хеш-таблица даёт средний O(1) по ключу ценой памяти и риска коллизий. `dict` и `set` — ежедневный инструмент.
