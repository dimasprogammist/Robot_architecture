# Практика и разбор ошибок

## Цель

Свести модуль к рабочему процессу: читать условие, выбирать структуру, оценивать сложность, проверять края, ловить типовые ловушки.

## Что уже нужно знать

Материал модуля: массивы, хеши, деревья, графы, BFS/DFS, сортировка, поиск, O-нотация, куча и кратчайшие пути.

## Объяснение с нуля

Учебная задача почти всегда маскирует известный шаблон. Вопросы себе перед кодом:

1. Что вход и какой размер? (n до 10² или до 10⁶ меняет алгоритм)
2. Нужны порядок, частоты, связи, минимум/максимум «на лету»?
3. Есть ли веса и могут ли они быть отрицательными?
4. Какие края: пусто, один элемент, дубликаты, уже отсортировано, несвязный граф?

Частые сводки:

- уникальность и частоты → `dict` / `set`;
- скобки и отмена → стек;
- волны и лабиринт без весов → BFS;
- зависимости и циклы → DFS;
- топ-k по приоритету → куча;
- много запросов к статическому массиву → sort + binary search.

Сначала медленный правильный вариант на малом n, затем ускорение. Тесты на края обязательны. Ручной проход на 6–8 элементах ловит половину логических ошибок до запуска.

## Термины

- **Шаблон задачи** — узнаваемая комбинация структуры и алгоритма.
- **Краевой случай** — вход на границе допустимости.
- **Регрессионный пример** — маленький вход, на котором уже ошибались.

## Внутреннее устройство чеклиста отладки

1. Сверка с ручным проходом на маленьком входе.
2. Проверка off-by-one в индексах и в `while lo <= hi`.
3. В графах — visited и направление рёбер.
4. В хешах — хешируемость ключа.
5. В рекурсии — база и глубина.
6. Оценка: не остался ли случайно квадрат на n = 10⁶.

## Пример 1: анаграммы

Идея: частоты символов совпадают.

```python
from collections import Counter


def anagram(a: str, b: str) -> bool:
    return Counter(a) == Counter(b)


assert anagram("listen", "silent") is True
assert anagram("abc", "ab") is False
```

Ошибка новичка: многократно сортировать огромные строки без нужды или забыть нормализацию регистра, если она входит в условие.

## Пример 2: узлы уровня дерева

Идея: BFS с учётом глубины. DFS умеет считать высоту, но для «все узлы уровня k» очередь обычно яснее.

## Пример 3: цикл в неориентированном графе

DFS с передачей родителя: сосед уже visited и это не родитель → цикл. Ошибка: считать родителя циклом.

## Сводная таблица

| Запрос | Инструмент | Порядок |
| --- | --- | --- |
| доступ i-й | массив | O(1) |
| концы последовательности | deque | O(1) |
| ключ → значение | dict | ср. O(1) |
| мин. приоритет | heap | O(log n) |
| кратчайший без весов | BFS | O(V+E) |
| кратчайший, веса ≥ 0 | Dijkstra | O((V+E) log V) |
| общая сортировка | Timsort | O(n log n) |

## Практика

Возьмите задачу «два числа с суммой target». Напишите O(n²) и O(n) решения. Сравните память. Протестируйте дубликаты, пустой вход и отсутствие пары.

## Типичные ошибки модуля целиком

- Учить код наизусть без сухого прогона руками.
- Путать среднюю и худшую оценку.
- Оптимизировать константу, сохранив квадратичную идею на большом n.
- Игнорировать память.
- Копировать обход графа без `visited`.

## Что запомнить

Процесс важнее заученных сниппетов: модель данных → шаблон → оценка → края → тест. Ручной проход на малом входе — обязательный навык.

## Задание

Выберите любую задачу из модуля (скобки, BFS-путь, two sum, insertion sort). Запишите: постановка, идея, ручной вход из 6–8 элементов, код, сложность, один краевой тест. Без этого списка решение не считайте законченным.
