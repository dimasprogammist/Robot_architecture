# O-нотация

## Цель

Научиться читать и писать оценки вида O(n), O(n²), O(log n), понимая, что отбрасывается и зачем такая грубость полезна.

## Что уже нужно знать

Идея сложности как роста T(n) с размером входа; умение насчитать шаги во вложенных циклах.

## Объяснение с нуля

Большое O описывает верхнюю оценку роста с точностью до константы и младших членов. Говоря «алгоритм O(n²)», мы утверждаем: существует константа C и порог n₀ такие, что для больших n число шагов не превосходит C·n².

Зачем так грубо: нас интересует, взорвётся ли решение при росте данных, а не точный коэффициент на конкретной машине. Запись T(n) = 3n² + 10n + 50 для сравнения с другим квадратичным часто избыточна — оба «квадратичные».

Частые классы:

- O(1) — константа (доступ по индексу массива).
- O(log n) — деление области пополам (бинарный поиск).
- O(n) — один проход.
- O(n log n) — хорошие сортировки сравнениями.
- O(n²) — типичные вложенные проходы.
- O(2ⁿ) — полный перебор подмножеств.

O — не единственная буква: Ω — нижняя оценка, Θ — «плотно с обеих сторон». В разговоре «сложность O(...)» часто имеют в виду Θ, но лучше уточнять. Важно: «код есть O(n²)» значит «рост не хуже квадрата»; он может быть и линейным. Для точного класса удобнее Θ, когда можете доказать обе стороны.

## Термины

- **Асимптотика** — поведение при больших n.
- **Доминирующий член** — слагаемое, которое растёт быстрее остальных.
- **Логарифм** здесь обычно по основанию 2: сколько раз можно делить n пополам.
- **Отбрасывание констант** — 5n и n — один класс O(n).

## Внутреннее устройство перевода «код → O»

Смотрите на структуру управления, а не на «красоту» имён:

- один цикл по n элементам без тяжёлого тела → O(n);
- цикл внутри цикла по n → O(n²);
- на каждой итерации бинарный поиск по тому же массиву → O(n log n);
- тело с ещё одним полным проходом того же массива внутри → снова квадрат.

Прячьте вызовы функций: если внутри цикла вызывается линейный поиск по всему массиву, сложность уже не «один цикл».

## Пример: бинарный поиск на 8 числах

Массив: `[1, 3, 4, 7, 9, 11, 15, 18]`, цель `11`.

### Пошаговый разбор

1. lo = 0, hi = 7, mid = 3 → значение 7, мало → lo = 4.
2. lo = 4, hi = 7, mid = 5 → значение 11, нашли.

Два существенных шага при n = 8; при n ≈ 1000 — около десяти. Это и есть логарифмический рост.

### Код на Python

```python
def binary_search(a: list[int], target: int) -> int:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1


data = [1, 3, 4, 7, 9, 11, 15, 18]
assert binary_search(data, 11) == 5
assert binary_search(data, 8) == -1
```

### Разбор по блокам

- Каждая итерация отбрасывает половину диапазона → число итераций ~ log₂ n.
- Дополнительная память O(1): только lo, hi, mid.
- Предусловие: массив упорядочен. Без него оценка O(log n) бессмысленна.

Другие якоря:

```python
x = a[0]                 # O(1)
s = sum(a)               # O(n)
for i in range(n):
    for j in range(n):
        ...              # O(n²)
```

## Практика

Для трёх фрагментов (один цикл; цикл с бинарным поиском внутри; два вложенных цикла) запишите O и одним предложением обоснуйте.

## Типичные ошибки

- Писать O(2n) вместо O(n) — константу убирают.
- Путать O(log n) с O(n/2): второе всё ещё линейно.
- Считать, что O всегда равно точному числу шагов.
- Игнорировать дорогой вызов, спрятанный внутри цикла.
- Сравнивать только по строке Big-O, забыв средний и худший случай хеш-таблицы.

## Что запомнить

O отбрасывает константы и младшие члены, оставляя порядок роста. Учите таблицу частых классов и узнавайте их во вложенности циклов.
