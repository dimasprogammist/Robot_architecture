# Поиск

## Цель

Сравнить линейный и бинарный поиск: когда нужен порядок, сколько шагов на массиве из 8 элементов, где ломаются границы диапазона.

## Что уже нужно знать

Массивы, O(log n), сортировка как предусловие бинарного поиска.

## Объяснение с нуля

Линейный поиск смотрит элементы по очереди — O(n), работает на любом списке. Бинарный поиск требует упорядоченности: делит текущий диапазон пополам и отбрасывает половину — O(log n) сравнений.

Цена предварительной сортировки O(n log n) окупается, если запросов много. Для одного запроса на неотсортированных данных часто достаточно линейного поиска или множества (если нужна только принадлежность, не индекс).

Бинарный поиск легко запороть границами `lo`/`hi` и условием цикла. Поэтому ниже медленный ручной проход обязателен перед кодом.

## Термины

- **Диапазон поиска** — текущие границы lo..hi.
- **Нижняя граница** — первый индекс, где значение ≥ target.
- **Верхняя граница** — первый индекс, где значение > target.
- **Монотонный предикат** — обобщение бинарного поиска на «первое true».

## Внутреннее устройство бинарного поиска

Инвариант: если ответ существует, он лежит в lo..hi включительно. Середина mid = (lo + hi) // 2. Если a[mid] < target, ответ справа → lo = mid + 1. Если a[mid] > target, ответ слева → hi = mid − 1. Если равно — нашли. Когда lo > hi — элемента нет.

## Пример на 8 числах

Отсортированный массив: `[1, 3, 4, 7, 9, 11, 15, 18]`.

### Пошаговый разбор: цель 15

1. lo=0, hi=7, mid=3 → 7 < 15 → lo=4.
2. lo=4, hi=7, mid=5 → 11 < 15 → lo=6.
3. lo=6, hi=7, mid=6 → 15 == 15 → индекс 6.

### Пошаговый разбор: цель 8 (нет)

1. mid → 7 < 8 → lo=4.
2. mid → 11 > 8 → hi=4.
3. mid → 9 > 8 → hi=3.
4. lo > hi → не найден, вернуть −1.

### Код на Python

```python
def linear_search(a: list[int], target: int) -> int:
    for i, x in enumerate(a):
        if x == target:
            return i
    return -1


def binary_search(a: list[int], target: int) -> int:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1


data = [1, 3, 4, 7, 9, 11, 15, 18]
assert binary_search(data, 15) == 6
assert binary_search(data, 8) == -1
assert linear_search(data, 15) == 6
```

### Сложность

Линейный: O(n) время, O(1) память. Бинарный: O(log n) время, O(1) память. Бинарный на неотсортированном массиве просто неверен.

## Практика

Найдите нижнюю границу для 9 (первый индекс, где значение ≥ 9) на том же массиве вручную. Сверьте с ожидаемым индексом 4.

## Типичные ошибки

- Бинарный поиск на неотсортированном массиве.
- Ошибка off-by-one: `hi = mid` вместо `hi = mid - 1` в нужном месте.
- Бесконечный цикл при неверном обновлении границ.
- Ждать O(log n) от поиска в hash-set в модели сравнений массива — там другая стоимость.

## Что запомнить

Линейный — универсальный O(n). Бинарный — O(log n) только на отсортированном. Границы проверяйте тестами на «нет элемента» и на краях массива.
