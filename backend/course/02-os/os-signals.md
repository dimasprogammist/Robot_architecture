# Сигналы

## Цель

Разобрать сигналы Unix как механизм асинхронных уведомлений процессу: кто шлёт, как обрабатывают, чем отличаются SIGTERM и SIGKILL, зачем нужны для корректной остановки роботов и служб.

## Что уже нужно понимать

Процессы имеют PID. Службы останавливают процессы управляемо. Ядро может вмешиваться в жизнь процесса.

## Объяснение

**Сигнал** — программное прерывание для процесса: небольшое сообщение «случилось событие». Примеры: пользователь нажал Ctrl+C (SIGINT), служба просит завершиться (SIGTERM), обращение к запрещённой памяти (SIGSEGV), дочерний процесс завершился (SIGCHLD), таймер (SIGALRM).

Процесс может: установить обработчик, игнорировать некоторые сигналы, оставить действие по умолчанию (часто — завершиться). **SIGKILL и SIGSTOP** нельзя перехватить/игнорировать — это жёсткая власть ядра/админа.

Сигналы не являются полноценной шиной сообщений: они могут сливаться (несколько SIGCHLD → один), не несут больших данных, доставка относительно асинхронна. Для богатого IPC используют сокеты, очереди, pipe.

В многопоточных программах сигналы опасны: кто из потоков получит, async-signal-safe функции ограничены. Часто ставят блокировку сигналов и обрабатывают в одном потоке через signalfd/self-pipe.

Windows имеет иные механизмы (консольные события, TerminateProcess); полный 1:1 маппинг не обязателен, но идея «попросить остановиться vs убить» универсальна.

## Термины

- **Signal** — сигнал.
- **Handler** — обработчик сигнала.
- **SIGTERM** — мягкая просьба завершиться.
- **SIGKILL** — немедленное убийство.
- **SIGINT** — прерывание с терминала.
- **SIGHUP** — «обрыв терминала» / часто reload конфига у демонов.
- **Async-signal-safe** — функции, безопасные в обработчике.

## Как это устроено

`kill -TERM PID` просит ядро доставить сигнал. Если есть handler — процесс перепрыгивает в него (с нюансами масок и SA_RESTART). По умолчанию для TERM — terminate.

systemd при `stop` обычно шлёт SIGTERM, ждёт TimeoutStopSec, затем SIGKILL. Поэтому ваш демон должен ловить TERM, гасить моторы, закрывать файлы, выходить сам.

Семейство сигналов остановки/продолжения (STOP/CONT) используют отладчики и job control оболочки (`Ctrl+Z`).

Ошибки железа/памяти тоже приходят сигналами: SIGBUS, SIGSEGV, SIGFPE — обычно знак бага, а не «надо обработать и жить дальше» без жёсткой причины.

## Пример

Контроллер робота на SIGTERM: ставит флаг «shutdown», цикл управления видит флаг, выдаёт нулевые уставки, отключает реле, пишет «bye» в лог, `exit(0)`. Если вместо этого сразу SIGKILL — реле могут остаться включёнными, буферы логов не сбросятся.

SIGHUP у nginx традиционно означает reload конфига без полного простоя. Ваш сервис может копировать паттерн — или не должен, если HUP не описан; тогда дефолт убьёт процесс неожиданно.

## Типичные ошибки

- Сразу `kill -9` как привычка.
- Тяжёлая работа (malloc, лог в Python) прямо в небезопасном handler.
- Игнорировать SIGTERM в службе — получать SIGKILL и порчу состояния.
- Путать сигнал с RPC: «послал SIGUSR1» без контракта в документации.
- Не учитывать потоки при установке обработчиков.

## Что запомнить

Сигналы — короткие асинхронные события от ядра/других процессов. TERM — корректная остановка; KILL — крайняя мера. Обработчики должны быть минимальными или заменены безопасной схемой. Для роботов реакция на TERM — часть safety. Не стройте сложный протокол только на сигналах.

## Задание

Опишите желаемое поведение вашего долгоживущего процесса при SIGTERM за 5–7 шагов (что выключить первым). Отдельно напишите, в каком случае допустим SIGKILL.

## Практика и нюансы

Реализуйте (или опишите псевдокодом) флаг shutdown, выставляемый из обработчика/через безопасный механизм, и проверку флага в главном цикле. Это шаблон по умолчанию для роботов.

Проверьте, что ваш супервизор даёт достаточно TimeoutStopSec на торможение механизмов. Слишком короткий таймаут = скрытый kill.

Запретите себе kill -9 как первый инструмент. Второй-третий — после диагностированного зависания в syscall/дедлоке.

Не назначайте SIGUSR1 «сделать всё» без документации. Через полгода никто не вспомнит контракт.

## Углубление (дополнение)

Чеклист graceful stop: перестать принимать новое → дождаться безопасной точки → обесточить актуаторы по политике → flush логов → exit 0. Порядок критичен.

TimeoutStopSec согласуйте с временем торможения механики. Иначе получите скрытый SIGKILL.

SIGUSR* только с документацией в README службы. Без контракта это мина для смены команды.
