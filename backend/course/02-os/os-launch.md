# Как ОС запускает программу

## Цель

Пройти детальный сценарий запуска: поиск файла, проверка прав, создание процесса, загрузка образа, аргументы и окружение, точка входа, связь с оболочкой и службами. Уметь локализовать ошибки «не запускается».

## Что уже нужно понимать

Процессы и память. Файлы и права. PATH и env. Сигналы по умолчанию. Роль ядра.

## Объяснение

Запуск — не магия ярлыка, а последовательность syscalls. В Unix-модели часто: `fork` (или `posix_spawn`) создаёт новый процесс, затем `execve` заменяет адресное пространство программой из файла. Windows API CreateProcess объединяет шаги иначе, но результат тот же: новый процесс с образом.

До exec оболочка решает PATH, редиректы, пайпы. Для скрипта с shebang ядро (или загрузчик) запускает интерпретатор из `#!`. Без права execute на скрипт и без `x` на интерпретатор старт сорвётся.

Загрузчик динамических библиотек (ld.so и аналоги) ищет `.so`/DLL по правилам, читает зависимости, релоцирует символы. Ошибка «library not found» — этап загрузки, не вашего `main`.

Аргументы `argv` и окружение `envp` передаются готовыми. Рабочая директория наследуется (важно для относительных путей). Маска сигналов, umask, лимиты — тоже часть наследства с модификациями.

После успешного exec счётчик команд в точке входа: CRT start → main (для C), или runtime языка. Оболочка обычно `wait`ит интерактивную команду и печатает код выхода.

systemd и IDE делают тот же exec от своего лица — с другим cwd/env/user.

## Термины

- **execve** — системный вызов замены образа.
- **fork / spawn** — создание процесса.
- **Динамический линкер** — загрузчик shared libraries.
- **argv / envp** — аргументы и окружение.
- **Shebang** — указание интерпретатора в скрипте.
- **Точка входа** — адрес начала исполнения образа.
- **Код выхода** — статус завершения для родителя.

## Как это устроено

Ошибки по этапам:

1. Оболочка: command not found — не нашли в PATH.
2. FS: permission denied — нет x или нет traverse по пути.
3. Формат: Exec format error — неверная архитектура/битый бинарник.
4. Динамический линкер: missing library.
5. Runtime: падение в main / ImportError интерпретатора.
6. Логика: программа жива, но сразу exit 1 из-за конфига.

Понимание этапа экономит часы. `strace`/`procmon` показывают syscalls; `ldd` — библиотеки.

Скрипты Python: exec на самом деле запускает `python`, которому передали путь. Виртуальный env должен попасть в путь интерпретатора.

setuid-бинарники меняют эффективный UID при exec — особые правила безопасности (игнорирование части env).

## Пример

`./tool` в каталоге: shell ищет в cwd только если так настроен (обычно нужен `./`). Без `./` и без PATH к каталогу — not found, хотя файл «вот он».

Служба: `ExecStart=tool` без пути — зависит от PATH unit (часто минимален). Укажите `/opt/robot/bin/tool`.

Запуск GUI-приложения из cron без `DISPLAY` — процесс стартует и сразу ругается на дисплей: exec успешен, среда неполная.

## Типичные ошибки

- Лечить все проблемы переустановкой, не определив этап.
- Забывать `./` для локальных бинарников.
- Путать отсутствие библиотеки с багом в коде.
- Ожидать тот же cwd, что в IDE, у systemd.
- Не проверять архитектуру бинарника (ARM vs x86) на одноплатнике.

## Что запомнить

ОС запускает программу через создание процесса и загрузку образа. PATH, права, shebang, динамические библиотеки, argv/env/cwd — части контракта. Ошибки диагностируют по этапу. Службы и оболочки отличаются контекстом, не «другой физикой exec».

## Задание

Возьмите команду, которой вы запускаете свой проект. Разложите её на: кто делает PATH-поиск, какой полный путь исполняемого, какие аргументы, какой предполагаемый cwd. Намеренно сломайте один фактор (не тот cwd) и зафиксируйте сообщение об ошибке.

## Практика и нюансы

Сломайте запуск четырьмя способами на копии стенда: неверный PATH, нет execute, неверная архитектура бинарника (если есть), отсутствующая .so. Сохраните тексты ошибок — это ваш справочник диагностики.

В unit всегда пишите абсолютный ExecStart и WorkingDirectory. Относительность — враг автозапуска.

Для Python зафиксируйте интерпретатор venv полным путём. `python3` из PATH службы — лотерея версий.

Проверяйте код выхода в скриптах обёртках: маскирование ошибок `|| true` без причины прячет этап запуска.

## Углубление (дополнение)

Карточка диагностики: not found / denied / bad ELF / missing lib / runtime / exit!=0. Классифицируйте каждый инцидент.

WorkingDirectory и абсолютный ExecStart в unit — обязательны. Относительные пути — для интерактива.

Проверяйте архитектуру бинарника на ARM-борте до выезда в поле. Exec format error на объекте дороже минуты `file` локально.
