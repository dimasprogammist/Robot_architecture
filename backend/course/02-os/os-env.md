# Переменные окружения и PATH

## Цель

Понять окружение процесса как набор строк ключ=значение, наследуемых при запуске; роль PATH в поиске программ; типичные ловушки «у меня в терминале есть, а в службе нет».

## Что уже нужно понимать

Процесс создаётся ОС и получает начальный контекст. Службы и интерактивные сессии — разные способы старта. Пользователи различаются.

## Объяснение

**Переменные окружения** — ассоциативный массив строк, который ядро хранит для процесса и передаёт детям при создании (если не очистить). Программы читают их через API языка (`os.environ`, `getenv`). Это удобный канал конфигурации: пути, режимы, адреса брокеров, локаль, настройки прокси.

Они не секретное хранилище мирового класса: видны в `/proc/PID/environ`, в списке процессов иногда, наследуются случайно. Секреты лучше файлам с правами или secret-хранилищам; если всё же env — ограничьте доступ к хосту.

**PATH** — особая переменная: список каталогов, где оболочка (и иногда `execvp`) ищет команду по короткому имени. `python` найдётся, если есть `.../bin/python` в одном из элементов PATH. Порядок важен: первый матч побеждает.

Интерактивный shell читает profile/bashrc и дополняет env. systemd unit, cron, CI по умолчанию дают **урезанное** окружение. Отсюда классика: «вручную работает, в службе команда not found» — другой PATH, нет активированного venv, нет `ROS_DISTRO`.

`HOME`, `USER`, `LANG`, `LD_LIBRARY_PATH`, `PYTHONPATH`, `JAVA_HOME` — частые гости. `LD_LIBRARY_PATH` особенно коварен для поиска динамических библиотек.

## Термины

- **Environment** — окружение процесса.
- **PATH** — список каталогов поиска исполняемых файлов.
- **Наследование** — копирование env ребёнку.
- **EnvironmentFile** — файл env для службы.
- **Shebang** — строка `#!` выбора интерпретатора.
- **venv / virtualenv** — изоляция Python с своим bin в PATH.
- **Locale** — языковые настройки через env.

## Как это устроено

При `exec` новый образ получает argv и envp. Оболочка при запуске команды сама решает PATH, затем вызывает exec с полным путём. Программа может менять своё окружение для себя и будущих детей, но не «назад» родителю.

systemd: `Environment=`, `EnvironmentFile=`, `PassEnvironment=`. Docker: `ENV`, `-e`. Windows: системные/пользовательские переменные в реестре и UI — та же семантика наследования процессов.

Отладка: напечатать env в точке входа службы; сравнить с интерактивным `env`. Проверить `which`/`where` и полный путь в unit.

## Пример

В терминале сделали `source venv/bin/activate` — PATH начинается с `venv/bin`. Unit вызывает просто `python app.py` системный `/usr/bin/python` без пакетов. Лечится: `ExecStart=/path/venv/bin/python app.py` или явная активация через wrapper.

Другой пример: два `cmake` в PATH — старый первым; сборка «внезапно» древняя. `type -a cmake` показывает порядок.

## Типичные ошибки

- Полагаться на интерактивный PATH в cron/systemd.
- Класть секреты в env на общих хостах без контроля.
- Размножать `PYTHONPATH` до хаоса импортов.
- Менять `LD_LIBRARY_PATH` глобально «навсегда» и ломать систему.
- Забывать кавычки и пробелы в значениях Environment=.

## Что запомнить

Окружение — часть контекста процесса, наследуется при старте. PATH определяет поиск команд. Службы ≠ ваш bashrc. Фиксируйте полные пути или явные Environment в unit. Для отладки сравнивайте env рабочего и нерабочего запуска.

## Задание

Выведите PATH в интерактивной сессии. Найдите, каким полным путём вызывается ваш интерпретатор или компилятор. Напишите, каким `ExecStart` вы бы зафиксировали это в службе без активации вручную.

## Практика и нюансы

Сравните `echo $PATH` в терминале и в unit с `ExecStart=/usr/bin/env` печатью PATH. Разница объяснит половину «у меня работает».

Зафиксируйте в деплое полные пути к python/venv и к бинарникам. Активация руками — для людей, не для демонов.

Секреты: если вынуждены использовать env, ограничьте доступ к хосту и не печатайте env в логи. Лучше файлы 600 или secret manager.

Документируйте обязательные переменные спискаом с дефолтами и без. Отсутствие явного контракта порождает магические значения «откуда-то из bashrc».

## Углубление (дополнение)

Таблица обязательных переменных с примерами — часть поставки. Пустые дефолты лучше магических значений из чужого bashrc.

Секреты в env печатаются в dump процессов: оцените угрозу. Предпочитайте файлы 0600.

В CI явно экспортируйте минимум env; «унаследовалось с раннера» — источник флаппов.
