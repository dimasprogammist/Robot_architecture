# Индексы

## Цель

Понять индекс как структуру ускорения поиска ценой записи и памяти.

## Что уже нужно знать

Нормализация.

## Объяснение с нуля

Индекс — дополнительная структура (часто B-дерево), которая по значению столбца быстро находит строки. WHERE user_id=5 с индексом не обязан сканировать всю таблицу.

Цена: место на диске и замедление INSERT/UPDATE/DELETE. Индексируют избирательные столбцы и FK, по которым часто ищут. PK уже индексирован.

## Термины

- **B-tree индекс**.
- **Селективность**.
- **Покрывающий индекс** (углублённо).

## Внутреннее устройство

Планировщик решает: seq scan или index scan. Неверный индекс — мёртвый груз.

## Пример

tasks на 100000 строк, индекс по user_id. Поиск user_id=5 читает мало страниц.

## Разбор

Без индекса — полный проход. С индексом — прыжок к нужным листьям.

## Код

```sql
CREATE INDEX idx_tasks_user ON tasks(user_id);
EXPLAIN QUERY PLAN
SELECT * FROM tasks WHERE user_id = 5;
```

## Практика

Нужен ли индекс по boolean done в таблице, где 50/50? Обсудите.

## Типичные ошибки

- Индексировать всё подряд.
- Ждать чудес от индекса при SELECT *.
- Забыть индекс на FK.

## Что запомнить

Индекс ускоряет чтение и стоит на записи.
