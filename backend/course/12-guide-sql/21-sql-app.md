# Приложение и БД

## Цель

Собрать путь: process → connection → SQL → rows → transaction в коде сервиса.

## Что уже нужно знать

EXPLAIN и предыдущий SQL.

## Объяснение с нуля

Реальный сервис держит пул соединений (или одно в мелком скрипте). Обработчик HTTP берёт connection/session, выполняет параметризованный SQL, читает строки в объекты/дикты, коммитит при успехе, закрывает/возвращает соединение в пул.

ORM (SQLAlchemy) генерирует SQL, но путь тот же. Ошибка новичка — открыть соединение на каждый чих без пула или держать транзакцию на время внешнего HTTP-вызова.

## Термины

- **Connection pool**.
- **Unit of work / session**.
- **Параметризация**.

## Внутреннее устройство

Слой API → сервис → репозиторий/DAO → драйвер → СУБД.

## Пример

Создание задачи: INSERT + COMMIT; чтение списка: SELECT + маппинг в JSON ответа.

## Разбор

Падение после INSERT до COMMIT — клиент не увидит задачу (пока не зафиксировано).

## Код

```python
def create_task(conn, user_id: int, title: str) -> int:
    cur = conn.cursor()
    cur.execute(
        "INSERT INTO tasks(user_id, title, done) VALUES (?, ?, 0)",
        (user_id, title),
    )
    conn.commit()
    return cur.lastrowid


def list_open(conn, user_id: int) -> list[tuple]:
    cur = conn.cursor()
    cur.execute(
        "SELECT id, title FROM tasks WHERE user_id = ? AND done = 0",
        (user_id,),
    )
    return cur.fetchall()
```

- Строить SQL конкатенацией.
- Забыть commit.
