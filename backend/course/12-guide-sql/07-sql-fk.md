# Внешний ключ

## Цель

Связать таблицы через FOREIGN KEY и понять целостность ссылок.

## Что уже нужно знать

Первичный ключ.

## Объяснение с нуля

Внешний ключ (FK) — столбец (или набор), значения которого должны существовать в PK/UNIQUE другой таблицы. tasks.user_id → users.id. Так СУБД не даст «осиротевшую» задачу на несуществующего пользователя (при включённом FK).

ON DELETE/UPDATE определяют политику: запрет, каскад, SET NULL.

## Термины

- **FOREIGN KEY** — ссылочное ограничение.
- **Родительская / дочерняя таблица**.
- **Каскад** — автоудаление/обновление потомков.

## Внутреннее устройство

При INSERT/UPDATE дочерней строки СУБД проверяет родителя. При DELETE родителя — политику FK.

## Пример

users: (1,'Ann'), (2,'Bob'). tasks: (10,1,'A'), (11,2,'B'). INSERT tasks(12,9,'X') — ошибка, user 9 нет.

## Разбор

Почему ошибка на user_id=9: нарушена ссылочная целостность, а не «Python упал».

## Код

```sql
CREATE TABLE tasks (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  title TEXT NOT NULL
);
```

## Практика

Выберите политику ON DELETE для комментариев задачи: CASCADE или RESTRICT? Обоснуйте.

## Типичные ошибки

- Хранить user_id без FK «для скорости» и копиться мусором.
- Каскады Everywhere без анализа.

## Что запомнить

FK держит связи правдой на уровне СУБД.
