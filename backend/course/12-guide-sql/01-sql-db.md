# Что такое база данных

## Цель

Понять, чем СУБД отличается от файла с данными: схема, запросы, одновременный доступ, сохранность.

## Что уже нужно знать

Файлы, процессы, идея сохранить состояние между запусками.

## Объяснение с нуля

База данных под управлением СУБД — организованное хранилище с правилами. Приложение не двигает байты файла вручную, а отправляет запросы. СУБД проверяет типы и ограничения, координирует писателей, пишет журнал.

Прототип на JSON работает, пока один процесс и мало данных. Дальше появляются гонки, частичные записи и медленный поиск. СУБД забирает эти проблемы в движок.

SQLite встраивается в процесс. PostgreSQL — отдельный сервер. Схема взаимодействия одна: открыть соединение, выполнить SQL, прочитать строки, зафиксировать или откатить транзакцию.

## Термины

- **СУБД** — система управления базами данных.
- **Схема** — описание таблиц и ограничений.
- **Соединение** — сеанс клиента.
- **Транзакция** — атомарная группа изменений.

## Внутреннее устройство

Клиент → драйвер → протокол/API СУБД → разбор SQL → план → чтение страниц → результат → клиент.

## Пример

Таблица tasks:

| id | title | done |
| --- | --- | --- |
| 1 | Купить молоко | 0 |
| 2 | Отчёт | 1 |
| 3 | Звонок | 0 |

## Разбор

Запрос незавершённых возвращает строки 1 и 3. Строка 2 отфильтрована. Приложение получает набор кортежей, а не весь файл целиком.

## Код

```python
import sqlite3
conn = sqlite3.connect("app.db")
cur = conn.cursor()
cur.execute("SELECT id, title FROM tasks WHERE done = 0")
print(cur.fetchall())  # [(1, 'Купить молоко'), (3, 'Звонок')]
conn.close()
```

## Практика

Перечислите три операции трекера, которые опасны при двух писателях в один JSON.

## Типичные ошибки

- Переписывать файл целиком на каждый клик.
- Считать папку бэкапов «базой».
- Игнорировать одновременный доступ.

## Что запомнить

БД = данные + правила + контролируемый доступ через запросы.
