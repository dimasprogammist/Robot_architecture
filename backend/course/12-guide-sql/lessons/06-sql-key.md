# Первичный ключ

Чтобы сказать «обнови вот эту задачу», нужен способ ткнуть в **одну** строку. Заголовок не годится: два «Отчёта» — два факта. **Первичный ключ** однозначно именует строку. Он не бывает `NULL` и не повторяется.

Часто это искусственное число или UUID (`id`) — **суррогат**: в предметной области его не произносят, зато он стабилен. Иногда берут естественный ключ, например email, если он правда уникален и не меняется каждую неделю. Сменили email — менять PK больно: на него уже ссылаются другие таблицы.

СУБД по ключу строит индекс. Поиск и `WHERE id = 3` дёшевы. Вторая вставка с тем же `id` — ошибка уникальности, строка не появится.

```sql
CREATE TABLE tasks (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL
);
INSERT INTO tasks VALUES (1, 'A');
-- INSERT INTO tasks VALUES (1, 'B');  -- отказ
UPDATE tasks SET title = 'A2' WHERE id = 1;
DELETE FROM tasks WHERE id = 1;
```

`UPDATE` и `DELETE` по ключу трогают одну строку. Тот же `UPDATE … WHERE title = 'Отчёт'` может закрыть две задачи или ноль — вы не знаете, какую хотели.

Составной ключ — несколько столбцов вместе уникальны. Для связи «задача–тег» пара `(task_id, tag_id)`: одну и ту же пару дважды вешать незачем. Каждый столбец по отдельности повторяется (у задачи несколько тегов).

Не обновляйте PK без крайней нужды: это переименовать сущность, на которую уже показывают пальцем. Жить без ключа и удалять «по смыслу текста» — путь к сюрпризам в проде.
