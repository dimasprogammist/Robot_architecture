# Транзакции

Списать 100 со счёта A и начислить на B — два UPDATE. Если после первого оборвались, деньги зависли «в воздухе». **Транзакция** — пачка изменений: либо все видны, либо ни одно. `BEGIN` → работа → `COMMIT` или `ROLLBACK`.

Автоcommit (каждая команда сама по себе) удобен для одноразового INSERT. Для перевода денег и «создать задачу + строку в журнале» он вреден: середина пачки уже зафиксирована.

```python
conn.execute("BEGIN")
try:
    conn.execute("UPDATE accounts SET bal = bal - 100 WHERE id = 1")
    conn.execute("UPDATE accounts SET bal = bal + 100 WHERE id = 2")
    conn.commit()
except Exception:
    conn.rollback()
    raise
```

Второй UPDATE упал — откат вернёт оба счёта. Журнал СУБД умеет доиграть или отменить; как именно — движок.

```sql
BEGIN;
INSERT INTO tasks (user_id, title, done) VALUES (5, 'A', 0);
INSERT INTO audit (task_id, action) VALUES (last_insert_rowid(), 'create');
COMMIT;
```

Задача без записи в `audit` — ложь для учёта. Обе вставки в одной транзакции.

Долгий `BEGIN`, пока человек думает в форме, держит блокировки и мешает другим. Транзакция — короткая работа движка, не «сессия UI». Ждать внешний HTTP внутри открытой транзакции — тот же грех.

В трекере: закрыть задачу и дописать событие; перенести задачу между проектами с проверкой обоих FK; создать пользователя и его настройки. Всё, что «частично нельзя».

Изоляцию параллельных транзакций разберёт ACID. Сначала привыкните: граница видимости — COMMIT.
