# ACID

Транзакция уже «всё или ничего». Четыре буквы уточняют обещание.

**Atomicity** — пачка не рвётся посредине. Это не «два успешных запроса подряд» без `BEGIN`: между ними другой клиент уже мог прочитать полусостояние.

**Consistency** — после COMMIT ограничения живы: нет сирот, нет CHECK-мусора. Транзакция, которая хотела нарушить FK, не фиксируется.

**Isolation** — параллельные транзакции не обязаны видеть чужую черновиковую грязь. Насколько строго — **уровень изоляции**. Грязное чтение, неповторяемое чтение, фантом — разные щели. В этом курсе достаточно: гонки реальны. Две вкладки закрывают одну задачу — победит последняя запись, если не поставить условие.

**Durability** — после успешного COMMIT мелкий сбой процесса не должен стереть факт: журнал, fsync. Это не бэкап диска и не защита от «удалили датацентр». COMMIT ≠ архив.

Потерянное обновление:

```sql
UPDATE tasks
SET done = TRUE, version = version + 1
WHERE id = 10 AND version = 3;
```

Вторая вкладка всё ещё думает, что `version = 3`. `rowcount = 0` — кто-то уже изменил. API отвечает конфликтом, не притворяется успехом.

Движок внутри держит блокировки или версии строк (MVCC). Вам на этом уровне важно проектировать запись с явным «какой снимок я меняю», а не надеяться, что UI сам сериализует клики.
