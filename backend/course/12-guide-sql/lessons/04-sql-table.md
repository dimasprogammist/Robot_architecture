# Таблица

Реляционная модель сказала: факт — строка. **Таблица** — именованный набор столбцов, под который эти строки подходят. Имя отражает сущность (`tasks`, `users`), не «data2». Каждый столбец — имя, тип, дозволено ли пусто.

Тип ограничивает значения: целое, текст, логический флаг, момент времени. Это не прихоть синтаксиса: сравнение и индекс зависят от типа. Текст `'1'` и число `1` в разных СУБД склеятся по-разному — лучше не надеяться на молчаливое приведение.

```sql
CREATE TABLE tasks (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  done BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMP NOT NULL
);
```

Строка обязана иметь заголовок и время создания. `done` по умолчанию ложь: новая задача не «неизвестно какая». `NULL` — нет значения, это не `0` и не пустая строка. Разрешить NULL «на всякий случай» во всех столбцах значит: приложение никогда не знает, можно ли на значение опираться.

```sql
INSERT INTO tasks (id, title, done, created_at)
VALUES (1, 'Купить молоко', FALSE, '2026-09-25T10:00:00');
```

`CREATE` задаёт схему, `ALTER` её меняет. Данные уже лежат отдельно от Python, но код зависит от имён столбцов: переименовали — сломался запрос. Добавить `NOT NULL` столбец к непустой таблице без `DEFAULT` некуда: старым строкам нечего подставить.

```sql
ALTER TABLE tasks ADD COLUMN priority INTEGER NOT NULL DEFAULT 3;
```

Плохая таблица пихает в один `TEXT` несколько фактов через запятую или JSON «пока так». Тогда вы теряете тип, ограничение и нормальный JOIN. Если внутри правда другая сущность — ей нужна своя таблица (комментарии к задаче — классика).
