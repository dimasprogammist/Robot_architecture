# Строки и столбцы

Таблица уже задана. Теперь два измерения, которые путают чаще всего.

**Строка** — один факт: все значения этой записи вместе (где пусто — `NULL`). Удалить строку значит: этого факта больше нет. Схема на месте.

**Столбец** — одно свойство у всех фактов: все заголовки, все флаги `done`. Удалить столбец (`ALTER … DROP COLUMN`) значит: такого свойства в схеме больше нет. Данные по нему исчезли у всех строк.

`SELECT` режет оба измерения, **не уничтожая** таблицу. Проекция — какие столбцы показать. `WHERE` — какие строки оставить. Таблица после запроса такая же.

| id | title | done |
| --- | --- | --- |
| 1 | A | 0 |
| 2 | B | 1 |
| 3 | C | 0 |

```sql
SELECT title FROM tasks WHERE done = 0;
-- A
-- C
```

Две строки, один столбец в результате. `title` в таблице не «стёрся».

```sql
SELECT id, title FROM tasks WHERE done = 1;
-- 2 | B

SELECT done FROM tasks;
-- три значения: 0, 1, 0 — это три строки, не «один столбец как одно число»
```

Пустой результат — не ошибка синтаксиса. `WHERE id = 99` вернул ноль строк: факта нет. API это 404 или пустой список, не «SQL сломался».

На диске строки лежат страницами — вам пока достаточно знать, что движок читает куски, а не «магически одну ячейку Excel». Логика запроса всегда: значения и условия.
