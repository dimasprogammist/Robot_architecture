# Первичный ключ

## Цель

Понять PRIMARY KEY: уникальная идентификация строки.

## Что уже нужно знать

Строки и столбцы.

## Объяснение с нуля

Первичный ключ (PK) однозначно определяет строку. Часто это суррогатный id (целое/UUID). Иногда естественный ключ (email), если стабилен. PK не бывает NULL и не дублируется.

Без ключа сложно ссылаться на строку из других таблиц и безопасно обновлять/удалять «ту самую» запись.

## Термины

- **PRIMARY KEY** — главный уникальный идентификатор.
- **Суррогатный ключ** — искусственный id.
- **Естественный ключ** — из предметной области.

## Внутреннее устройство

СУБД строит индекс по PK. Поиск по id дешёвый. Вставка дубликата id — ошибка.

## Пример

tasks: id PK. Попытка вставить второй id=1 отвергается.

## Разбор

UPDATE tasks SET done=true WHERE id=3 затрагивает одну строку, если id уникален.

## Код

```sql
CREATE TABLE tasks (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL
);
INSERT INTO tasks VALUES (1, 'A');
-- INSERT INTO tasks VALUES (1, 'B'); -- ошибка уникальности
```

## Практика

Когда email может быть PK, а когда лучше отдельный id?

## Типичные ошибки

- Обновлять PK без крайней нужды.
- Жить без ключа и удалять по title.
- Составной ключ без понимания уникальности комбинации.

## Что запомнить

PK идентифицирует строку и служит точкой ссылок.
