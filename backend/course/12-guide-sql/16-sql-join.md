# JOIN

## Цель

Соединять таблицы: INNER и LEFT на примере users/tasks.

## Что уже нужно знать

Запись данных.

## Объяснение с нуля

JOIN склеивает строки по условию. INNER — только пары. LEFT — все слева плюс совпадения справа (или NULL). Без JOIN пришлось бы вручную искать в приложении.

Декартово произведение без ON — взрыв строк.

## Термины

- **INNER JOIN**, **LEFT JOIN**.
- **Условие соединения** ON.

## Внутреннее устройство

Реализация: nested loop / hash / merge join — выбор планировщика.

## Пример

users: (1,Ann),(2,Bob). tasks: (10,1,A),(11,1,B),(12,2,C). INNER JOIN по user_id даст 3 строки с именами.

## Разбор

LEFT JOIN от users сохранит пользователя без задач с NULL title — если такой есть.

## Код

```sql
SELECT u.name, t.title
FROM users u
INNER JOIN tasks t ON t.user_id = u.id
ORDER BY u.name, t.id;
```

## Практика

Что будет, если забыть ON?

## Типичные ошибки

- JOIN без условия.
- Фильтровать WHERE по правому столбцу так, что LEFT превращается в INNER неожиданно.

## Что запомнить

JOIN собирает связанную картину из нормализованных таблиц.

## Задание

LEFT JOIN пользователей с числом задач (пока без GROUP — через подзапрос позже).

## Связь со следующим уроком

GROUP BY.
