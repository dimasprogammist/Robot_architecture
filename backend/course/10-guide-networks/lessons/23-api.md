# API — контракт между программами

REST, HTTP, сокеты — способы говорить. **API** — обещание на границе: одна программа пользуется другой по правилам. Сетевой API — сериализованные сообщения. API библиотеки — функции и типы. Без контракта интеграция держится на «у нас так принято» и падает на первом обновлении поля.

В контракт входит не только путь. Транспорт, формат, как узнаём клиента, какие ошибки, лимиты, можно ли повторять, что значит «порядок сообщений», как живёт версия.

```text
POST /v1/devices
Authorization: Bearer …
тело: {"name": string, "type": "robot"|"gateway"}

201  {"id": string}
400  {"error": "validation", "fields": …}
409  имя занято
429  слишком часто; заголовок Retry-After
таймаут сети ≠ 400: клиент решает, повторять ли
```

Добавить опциональное поле часто безопасно. Удалить или сменить смысл — нет. Старые клиенты либо версия `/v2`, либо период «поле ещё есть, но осуждается». «Молча игнорируй неизвестные поля» помогает расти без синхронного релиза всех потребителей.

Схему (OpenAPI и родичи) и **примеры** запросов пишут не для красоты: по ним генерируют клиента и ловят расхождение тестами. Документ без 4xx — фантазия.

Стиль выбирают задачей, не модой. CRUD админки — HTTP-ресурсы и кэш GET. Жёсткие схемы и стриминг — часто RPC (gRPC). Телеметрия робота и fan-out — очередь событий, не «клиент долбит GET». Смешать всё в один POST — потерять и кэш, и понятные коды.

TLS закрывает канал. Это не авторизация «этот токен может выключить конвейер» и не rate limit. Валидация входа, аудит, квоты — часть API, не «сеть уже защитила».

Наблюдаемость: один correlation id в логах клиента и сервера, метрики кодов и задержек. Без них «у меня 500» не склеить с конкретным запросом.

Ошибка сети и ошибка домена — разные ветки клиента: таймаут (повтор?), 400 (чинить тело), 409 (не повторять слепо). Это тоже контракт поведения.

Дальше в курсе Git, SQL вы уже трогали, backend развернёт, как этот контракт кладут в маршруты и сервисы.

## Практика

### Задание 1. Не только путь

Выпишите из фрагмента урока пять элементов контракта, которые не являются URL. Какой из них спасает от двойного создания при повторе сети?

### Задание 2. Совместимость

Клиенты в поле ждут `name`. Вы хотите переименовать в `title`. Как выкатить, не уронив старых? Что нельзя сделать в том же `/v1` в один день?

### Задание 3. Таймаут vs 400

Клиент получил таймаут на `POST /v1/devices`. Почему нельзя автоматически считать «устройство не создано»? Какой код/заголовок помог бы решить?

### Задание 4. Выбор стиля

Для каждого выберите HTTP-ресурс, RPC или очередь и одно предложение «почему»: (а) список складов, (б) поток температур каждую секунду на 500 плат, (в) «пересчитать отчёт» на 10 минут.

Раздел сетей на этом закрывается как карта слоёв: от кадра до контракта программ.
