# TLS — рукопожатие и защищённый канал

HTTPS сказал «обернуть HTTP». **TLS** — сам слой: два узла хотят, чтобы третий на проводе не читал и не подменял байты, и чтобы клиент говорил с нужным сервером, а не с самозванцем в кафе.

После TCP стороны обмениваются сообщениями handshake, проверяют сертификат, получают симметричные **сессионные ключи**, дальше прикладные данные едут в records с проверкой целостности. Версии 1.2 и 1.3 отличаются числом рейсов; цель одна.

```text
TCP уже есть
ClientHello (версии, шифры, случайное число, SNI = имя хоста)
   ↓
ServerHello + сертификат (+ обмен ключами)
   ↓
клиент: цепочка CA, имя, срок
   ↓
Finished → дальше шифртекст (HTTP внутри, если это HTTPS)
```

**SNI** говорит, для какого имени нужен сертификат, пока на одном IP несколько сайтов. Без проверки имени вы зашифруете канал до **чужого** сервера — конфиденциально и бесполезно.

Цепочка: лист + промежуточные до корня, которому клиент уже верит (магазин ОС/браузера). На сервере положили только лист — часть клиентов упадёт. Часы машины врут — `notBefore`/`notAfter` отвергнут живой сертификат. Это чинят временем, не кодом API.

Пересечения шифронаборов нет — handshake не сойдётся, HTTP не начнётся. Устаревший TLS 1.0 на сервере современные клиенты просто не возьмут.

Клиентский сертификат (mTLS) — опция: тогда сервер проверяет клиента криптографией, не только паролем в JSON. Для публичного сайта обычно только сервер предъявляет сертификат.

```bash
openssl s_client -connect example.com:443 -servername example.com </dev/null
```

Смотрите цепочку и срок, не «сайт в браузере открылся». Истечение сертификата — частая прод-авария; автовыпуск не отменяет мониторинг даты.

Отладка «не коннектится»: сначала TCP, потом версия TLS и SNI, потом имя в сертификате, потом уже заголовки HTTP.
