# DNS — имена и адреса

Маршрутизаторам нужны числа. Людям — `example.com`. Держать у каждого хоста файл «все имена мира» нельзя. **DNS** — распределённая система: по имени отдают записи, чаще всего адрес (A — IPv4, AAAA — IPv6). Приложение сначала резолвит, потом уже открывает сокет на полученный IP.

Иерархия зон: корень → зона верхнего уровня (`.com`) → авторитетные серверы домена. На ноутбуке обычно **stub-резолвер**: он спрашивает один настроенный DNS (из DHCP или руками), а уже тот рекурсивно обходит иерархию или отвечает из кэша.

TTL записи говорит, сколько можно помнить ответ. После смены IP у сайта часть мира ещё сутки видит старое — не «у меня сломался интернет», а кэш.

Сообщение DNS: вопрос (имя + тип) и ответ (ресурсные записи). Транспорт часто UDP/53; длинные ответы — TCP. Приложению это обычно не видно: оно зовёт `getaddrinfo`, ОС ходит к nameserver.

```text
вопрос: example.com A?
ответ:  TTL, тип A, адрес (число будет другим в жизни)
```

```bash
getent hosts example.com
python -c "import socket; print(socket.getaddrinfo('example.com', 443)[:2])"
```

Это то, чем пользуется софт, не «сайт в голове». `/etc/hosts` перебивает DNS: опечатка там выглядит как «у всех открывается, у меня нет».

Типичные отказы:

- NXDOMAIN — такого имени нет (или вы его перепутали).
- SERVFAIL — сервер споткнулся.
- Таймаут — фильтр, неверный резолвер, нет сети до него.
- Резолвер жив, маршрута к сайту нет — другое: имя есть, пакеты не ходят.

Пользователь склеивает всё в «нет интернета». Разделение: `ping` по уже известному IP vs резолвинг имени. Шлюз и DNS-сервер — разные роли, даже если дома оба на `192.168.1.1`.

Классический DNS по сети не шифрует. Подделка ответа в чужой LAN — риск. DNSSEC, DoT, DoH — отдельные практики; сначала отличите «имя не резолвится» от «резолвится не туда».

## Практика

### Задание 1. Имя и цифра

Резолвните любое знакомое имя. Затем объясните: если этот IP пингуется, а имя — нет, где ломается путь? Если наоборот — имя есть, IP не пингуется?

### Задание 2. Кэш

Запись с TTL 3600 сменили на стороне домена. Почему коллега ещё час видит старый адрес? Что бы вы проверили, прежде чем «чинить маршруты»?

### Задание 3. hosts

Зачем `/etc/hosts` может сломать отладку DNS? Придумайте одну строку, из‑за которой «сайт открывается не тот».

### Задание 4. Тип записи

Запрос A и запрос AAAA — разные вопросы. Хост dual-stack, в DNS только A. Что получит клиент, который спрашивает только AAAA?
