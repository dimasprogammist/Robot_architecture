# DHCP — автоматическая настройка хоста

Прописать на каждом телефоне IP, маску, шлюз и DNS руками — способ получить два устройства с одним адресом и третье с кривой маской. **DHCP** отдаёт эту пачку с сервера на время (**lease**). Администратор держит **пул**, клиент продлевает аренду, пока жив в сети.

Клиент ещё без адреса, поэтому первые кадры — широковещание в LAN. Обмен называют DORA:

```text
Discover  — «есть кто выдаёт адреса?»
Offer     — «возьми вот этот и вот параметры»
Request   — «беру это предложение»
Ack       — «аренда твоя: маска, шлюз, DNS, время»
```

Поверх UDP, порты 67/68. В опциях — не только IP: router, nameserver, маска, иногда имя хоста. После Ack ОС вешает адрес на интерфейс, ставит default via, прописывает резолвер. «Интернет не работает» при живом IP часто значит: в опциях не приехал шлюз или DNS.

Нет сервера — на IPv4 часто всплывает `169.254.…` (link-local). Адрес вроде есть, default в интернет — нет. Два DHCP в одной LAN без сговора выдают разный бред: разные шлюзы, пересечение пулов.

Серверам чаще делают reservation (этот MAC всегда этот IP) или чистую статику — чтобы адрес не уплыл. Ноутбукам DHCP удобен.

Истёкшая аренда без продления: адрес могут отдать другому. Статика тем же числом, что живёт в пуле, без reservation — конфликт, когда ноутбук приедет.

IPv6 часто настраивается объявлениями роутера (RA) и/или DHCPv6. Не копируйте «в IPv6 всегда тот же DORA».

```bash
ip -4 addr
ip route
```

Журнал NetworkManager или systemd-networkd показывает, застрял ли обмен на Discover.

Один источник правды на интерфейс: либо DHCP, либо статика. Оба сразу — гонка, кто последний записал маршрут.
