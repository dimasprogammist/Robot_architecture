# HTTPS — HTTP поверх защищённого канала

HTTP по открытому TCP читают и подменяют на пути: чужой Wi‑Fi, странный прокси. **HTTPS** — это тот же HTTP **внутри TLS**. Методы, пути, JSON не меняются. Меняется схема URL (`https://`) и то, что до первого заголовка HTTP идёт рукопожатие TLS, обычно на порту 443.

```text
http://   TCP:80   открытый текст запроса
https://  TCP:443  TLS, затем тот же HTTP уже в шифртексте
```

Клиент соединяется, проверяет **сертификат** сервера (имя хоста, срок, цепочка до доверенного центра), вырабатывает ключи сессии, и только потом шлёт `GET`. Для приложения «поменять http на https» — строка. Для эксплуатации — сертификат, промежуточные CA, порт, редирект.

Сертификат связывает имя (`example.com`) с ключом. Не то имя, истек срок, неизвестный издатель — клиент рвёт. Самоподписанный сертификат «для теста» в проде означает: либо все отключат проверку (плохо), либо никто не зайдёт.

HTTPS удостоверяет **сервер** (обычно) и закрывает канал. Логин пользователя — отдельно: сессия, токен. Замочек в браузере не значит «этот человек — админ».

```bash
curl -sI https://example.com
```

Успех — handshake и HTTP-ответ прошли. Отключить проверку CA «чтобы заработало» в клиенте микросервиса — привычка, которая маскирует атаку и опечатку в имени.

Промежуточный сертификат забыли на сервере: в браузере у кого-то открывается (полный магазин CA), у `curl` на сервере сборки — нет. Цепочку проверяют с клиента, не «у меня в Chrome норм».

Открытый HTTP рядом с HTTPS и cookie без Secure — сессия утечёт на первом незащищённом запросе. HSTS заставляет браузер больше не ходить на http — политика, не магия протокола.

Следующий урок разберёт handshake TLS отдельно: этот нужен, чтобы не путать «сайт на 443» с «мы сами изобрели шифр».
