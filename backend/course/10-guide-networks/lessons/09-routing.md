# Маршрутизация пакетов

Шлюз — частный случай. Вообще **маршрутизация** — выбор выходного интерфейса и next hop по адресу назначения. На ноутбуке в таблице три строки, на магистральном роутере — сотни тысяч. Алгоритм тот же: набор префиксов и правило, какой побеждает.

Побеждает **самый длинный** подходящий префикс (longest prefix match). Есть маршрут `203.0.113.0/24 via R1` и `default via R2` — пакет на `203.0.113.10` пойдёт на R1. Default — запасной, не «главный начальник».

```text
dst = 203.0.113.10
кандидаты:  203.0.113.0/24 via R1
            0.0.0.0/0      via R2
победил /24, hop = R1
```

Статические маршруты пишет человек. Динамические протоколы (OSPF внутри площадки, BGP между операторами) позволяют коробкам рассказывать друг другу, какие сети за ними. Серверу-хосту чаще хватает статики и default от DHCP. Интернет как целое держит BGP между автономными системами — это уже не настройка ноутбука.

Петля в таблицах без TTL крутила бы пакет вечно. TTL кончился — пакет выбрасывают. Неверная статика даёт **чёрную дыру**: маршрут есть, за ним тишина.

Путь туда и путь обратно в интернете не обязаны совпадать. Асимметрия — норма, не обязательно поломка.

`traceroute` шлёт пробы с растущим TTL и смотрит, кто ответил ICMP. Звёздочки значат «этот hop не ответил», а не всегда «кабель перерезан». Дальше путь может жить.

```bash
ip route
```

Типичные две строки хоста:

```text
192.168.1.0/24 dev eth0          # свои, без via
default via 192.168.1.1 dev eth0 # всё остальное
```

Роутер делает то же после приёма кадра: вытащил IP, уменьшил TTL, нашёл маршрут, заново упаковал в кадр уже **следующего** канала.

Политики «смотреть не только dst, но и src» существуют. Сначала освойте таблицу по назначению, иначе policy routing превратится в шаманство.

## Практика

### Задание 1. LPM руками

Есть маршруты `/8 via A`, `/16 via B`, `/24 via C`, default via D. Куда уйдёт `10.20.30.40`, если префиксы все покрывают этот адрес как `10.0.0.0/8`, `10.20.0.0/16`, `10.20.30.0/24`?

### Задание 2. Свои строки

Разберите каждую строку `ip route`: on-link это или via? Что будет с пакетом «в интернет», если стереть только default?

### Задание 3. Traceroute

Зачем звёздочки в traceroute не равны «сеть умерла»? Когда звёздочки всё же подозрительны?

### Задание 4. Чёрная дыра

Администратор прописал `0.0.0.0/0 via 10.0.0.99`, а `.99` выключен. Чем это отличается от «нет default» по симптомам?

Дальше имена вместо цифр: DNS.
