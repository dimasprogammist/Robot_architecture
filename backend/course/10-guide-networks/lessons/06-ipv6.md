# IPv6 — расширенное адресное пространство

IPv4 кончился как «каждому устройству по уникальному публичному адресу». NAT оттянул конец, но не отменил тесноту. IPv6 отвечает другой длиной: **128 бит**. Запись — шестнадцатеричные группы по 16 бит через двоеточие. Один раз подряд нулевые группы можно свернуть в `::`. Два раза `::` в одном адресе нельзя: станет непонятно, сколько нулей куда вставить. Регистр букв не важен.

```text
2001:0db8:0000:0000:0000:0000:0000:0001
2001:db8::1
```

Второй вариант — тот же адрес. Префикс `2001:db8::/32` в учебниках — как `192.0.2.0/24` в IPv4: для примеров, не для продакшена.

Почти на каждом интерфейсе живёт **link-local** из `fe80::/10`. Он действует только на этом канале. На машине с двумя сетевыми картами одного `fe80::1` мало: нужно указать зону, `fe80::1%eth0`. Без `%интерфейс` стек не знает, в какую сторону слать.

Глобальные адреса приходят из префикса провайдера, часто через Router Advertisement. ULA (уникальные локальные) по духу близки к частным IPv4, но на площадках их заводят по-разному — не ждите «всегда как 192.168».

NAT как обязательный костыль нехватки здесь не норма. Это не значит «нет файрвола»: фильтр и политика никуда не делись. «Нас прячет NAT, значит безопасно» — привычка IPv4, в IPv6 она врёт.

На канале соседа ищут Neighbor Discovery, не ARP. Hop Limit играет роль TTL.

Пока мир dual-stack: у хоста часто есть и `192.168…`, и `2001:…`, и `fe80::`. Браузер выбирает семейство по своим правилам (Happy Eyeballs). Приложение, которое парсит только четыре числа через точку, на IPv6 молча ломается.

```bash
ip -6 addr
ip -6 route
```

Если «IPv6 выключен» в голове, а `ip -6 addr` показывает адреса — стек уже работает. Отладка «сайт не открывается» без взгляда на оба семейства — лотерея.
