# IP — адресация поверх каналов

## Цель

Понять задачу IP: дать единую адресацию и доставку пакетов через разные канальные технологии и множество сетей.

## Исходные знания

MAC и локальные кадры. LAN/WAN. Идея слоёв.

## Объяснение

Каналы разные: Ethernet, Wi‑Fi, PPP, туннели. Если бы приложения говорили на языке каждого канала, интернет не сложился бы. IP даёт общий формат пакета и адреса хостов/сетей, независимый от нижнего носителя.

IP-пакет содержит адрес источника и назначения, служебные поля и полезную нагрузку (часто TCP/UDP). Маршрутизаторы смотрят на адрес назначения и решают, куда переслать пакет дальше. На каждом прыжке канальный заголовок свой, IP-заголовок (с оговорками) несёт сквозные адреса.

IP не гарантирует доставку, порядок и отсутствие дубликатов. Он делает «best effort». Надёжность, если нужна, добавляет транспорт (TCP) или само приложение.

Есть IPv4 и IPv6 — две семьи адресов. Хост может жить в обеих. Для инженера важно не путать «IP вообще» с конкретной версией записи адреса.

Фрагментация, TTL/Hop Limit, DiffServ — детали, которые всплывают при отладке MTU и петель. База: адрес + маршрут + следующий прыжок.

NAT меняет видимость адресов на границе и усложняет модель «сквозной уникальности» в IPv4, но идея IP как межсетевого слоя остаётся.

## Термины

**IP** — Internet Protocol, межсетевой протокол.

**Пакет** — единица данных сетевого уровня.

**Маршрутизатор** — узел, пересылающий пакеты между сетями.

**Best effort** — доставка без гарантий надёжности.

**TTL / Hop Limit** — ограничение числа прыжков, защита от вечных петель.

## Как это работает

Хост сверяет назначение с таблицей маршрутов: «прямо в моей сети» или «через шлюз». Если через шлюз — отправляет кадр шлюзу (узнав MAC через ARP/ND), внутри кладёт IP-пакет с конечным адресом сервера.

Каждый маршрутизатор уменьшает TTL и выбирает новый выходной интерфейс. Если TTL истекает — пакет уничтожается, иногда отправителю уходит ICMP-уведомление.

## Пример

```text
Приложение → UDP/TCP → IP(src, dst) → кадр до следующего hop
hop1 → hop2 → ... → хост назначения → вверх в сокет
```

```bash
ip addr
ip route
```

## Разбор

Схема показывает сквозные IP-адреса при смене канальных участков.

`ip addr` и `ip route` — взгляд хоста на свою IP-идентичность и правила пересылки.

## Ошибки

- Ждать от IP надёжности TCP.
- Путать адрес интерфейса с именем сайта.
- Игнорировать, что без маршрута «есть IP» недостаточно.
- Считать NAT «отменой» IP-слоя.

## Что запомнить

- IP объединяет разные каналы общей адресацией.
- Доставка пакетная и без гарантий.
- Маршрутизаторы пересылают по адресу назначения.
- Канальный заголовок локален для каждого hop.

## Задание

Посмотрите свои адреса и маршрут по умолчанию. Объясните, куда уйдёт пакет к адресу вне вашей LAN.

## Дополнение: практика и нюансы

Фрагментация IP и MTU: чёрные дыры, когда ICMP запрещён. Симптом — крупные ответы не проходят, маленькие ping ок.

Policy routing и multiple tables на linux-роутерах усложняют отладку — сначала смотрите `ip rule`.

Anycast и ECMP — норма в современных сетях; traceroute может «прыгать».

Не смешивайте документирующие префиксы (192.0.2.0/24, 2001:db8::/32) с реальными в проде.


Проверьте цепочку сертификатов с промежуточными, не только листовой файл.

Убедитесь, что клиентский таймаут больше, чем худший RTT + handshake + обработка.

Разделите метрики ошибок транспорта и прикладных 4xx/5xx — это разные классы проблем.

Проверьте политику ретраев на идемпотентность метода, чтобы не создать дубликаты ресурсов.

Сверьте версии протокола TLS на клиенте и сервере при загадочных handshake failure.
