# Маршрутизация пакетов

## Цель

Понять, как таблица маршрутов и longest prefix match направляют пакеты; чем статическая маршрутизация отличается от динамики на уровне идеи.

## Исходные знания

Подсети, шлюз, IP-пакет с TTL. Разница LAN/WAN.

## Объяснение

Маршрутизация — процесс выбора выходного интерфейса и next hop для пакета по адресу назначения. На хосте и на роутере таблицы похожи по духу: префикс → куда слать.

Longest prefix match: из всех подходящих маршрутов побеждает самый длинный (самый специфичный) префикс. `/32` к хосту сильнее `/16` к большой сети, default `/0` — самый слабый запасной.

Статические маршруты пишет администратор. Динамические протоколы (OSPF, BGP…) позволяют роутерам обмениваться информацией о сетях. На сервере-хосте чаще статика + default от DHCP. В интернете масштаб держит BGP между автономными системами.

Петли опасны: без TTL пакеты крутились бы вечно. При истечении TTL пакет дропают. Неверная статика легко создаёт чёрные дыры: пакет уходит «в никуда».

Policy routing усложняет картину: выбор пути не только по dst, но и по src/firewall mark. Базу сначала освойте без политик.

Трассировка (`traceroute`/`tracepath`) показывает ряд прыжков через TTL-пробы. Не каждый hop отвечает ICMP; «звёздочки» не всегда катастрофа.

## Термины

**Таблица маршрутизации** — набор префиксов и next hop.

**LPM** — longest prefix match.

**AS (autonomous system)** — область маршрутной политики в интернете.

**Чёрная дыра** — маршрут, ведущий к молчаливой потере.

**ECMP** — разделение нагрузки по нескольким равноценным путям.

## Как это работает

Роутер принимает кадр, извлекает IP, уменьшает TTL, ищет маршрут, заново инкапсулирует в кадр следующего канала и отправляет. Контрольные суммы/контрольные поля обновляются по правилам версии IP.

На хосте исходящий путь тот же алгоритм, только обычно меньше маршрутов. Входящий путь независим: асимметрия маршрутов в интернете нормальна.

## Пример

```bash
ip route
# пример смысла строк:
# 192.168.1.0/24 dev eth0 proto kernel scope link
# default via 192.168.1.1 dev eth0

traceroute -n 1.1.1.1 2>/dev/null | head || tracepath -n 1.1.1.1 2>/dev/null | head || true
```

```text
пакет dst=203.0.113.10
совпало: 203.0.113.0/24 via R1  и  0.0.0.0/0 via R2
победит /24 (длиннее), next hop = R1
```

## Разбор

Строки `ip route` прямо иллюстрируют on-link сеть и default.

Пример LPM показывает, почему более узкий префикс важнее default.

traceroute помогает увидеть цепочку, но интерпретировать его нужно осторожно.

## Ошибки

- Добавлять статику без плана отката.
- Путать отсутствие ICMP на hop с полным обрывом пути.
- Игнорировать асимметрию маршрутов.
- Перекрывать чужие префиксы слишком широкими анонсами (на роутерах).

## Что запомнить

- Маршрут выбирается по LPM.
- Default — запасной путь.
- TTL ограничивает петли.
- Хост и интернетный роутер решают одну задачу на разном масштабе.

## Дополнение: практика и нюансы

Статика проста до первого изменения топологии. Динамика сложнее, но переживает сдвиги.

BGP на edge интернета — политика столько же, сколько техника. Не фильтруйте чужие анонсы без понимания.

Маршрут в таблицу не гарантирует обратный путь. Асимметрия ломает stateful firewall.

Документируйте «почему этот static» рядом с конфигом.


Проверьте, что cron/таймер запускает тот же интерпретатор и PATH, что и ручной прогон.
