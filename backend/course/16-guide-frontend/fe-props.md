# Props — данные сверху вниз

## Цель

Надёжно передавать данные и колбэки в React-компоненты через props, понимать обязательность полей и границы ответственности ребёнка. После урока вы спроектируете список и карточку заказа без протечек глобального состояния.

## Что уже нужно понимать

Компонент React — функция. Props — аргумент этой функции (объект). TypeScript уже помогает описать форму. Локальный state через `useState` живёт внутри владельца данных; детям часто достаточно props.

## Объяснение

Props — это вход текущего кадра отрисовки. Родитель решает: «вот этот order». Ребёнок не ходит в родительский state напрямую (в обычной модели). Хочет изменить данные — зовёт колбэк из props. Так сохраняется поток: данные вниз, события вверх.

Почему не читать глобальные переменные: тестировать трудно, побочные связи неочевидны, при двух списках на странице начнётся путаница. Props делают зависимость явной: открыл компонент — видно, что ему нужно.

Опциональные props: `title?: string` или значение по умолчанию в деструктуризации `{ title = "Заказы" }`. `children` — особый prop для вложенной разметки: кнопка-обёртка, layout, модалка.

Не всё нужно тащить через десять уровней. Если пропали в «prop drilling», либо поднимите state разумнее, либо позже изучите контекст — но для учебной панели заказов сверлить три уровня нормально и честнее магии.

Иммутабельность: ребёнок не должен делать `props.order.status = 'x'`. Родитель не увидит сигнал к обновлению так, как ожидается; отладка станет адом. Просите изменение через `onChangeStatus(id, next)`.

## Термины

- **Prop drilling** — протаскивание props через промежуточные слои.
- **children** — вложенное содержимое компонента.
- **Контролируемый ввод** — value и onChange снаружи (связь с формами позже).
- **Default props** — значения по умолчанию.

## Как это устроено

При рендере родителя React вызывает ребёнка с новым объектом props. Даже если поля те же по значению, ссылка на объект props новая; мемоизация — отдельная тема оптимизации, новичку рано. Сначала корректность: правильные данные, правильные колбэки.

Разделяйте props «для отображения» и «для действий». Карточке заказа: `order`, `selected`, `onSelect`, `onPack`. Не передавайте весь `state` приложения целиком — ребёнок начнёт знать лишнее и соблазнится лишними зависимостями.

Составные компоненты: `Panel`, `Panel.Header`, `Panel.Body` через `children` читаются лучше, чем гигантский конфиг-объект из двадцати флагов.

## Пример

```tsx
type Order = {
  id: number;
  customer: string;
  status: "new" | "packing" | "shipped";
};

type OrderCardProps = {
  order: Order;
  selected?: boolean;
  onSelect: (id: number) => void;
  onPack: (id: number) => void;
};

function OrderCard({ order, selected = false, onSelect, onPack }: OrderCardProps) {
  return (
    <article
      className={selected ? "card card--selected" : "card"}
      onClick={() => onSelect(order.id)}
    >
      <h3>
        #{order.id} {order.customer}
      </h3>
      <p>Статус: {order.status}</p>
      <button
        type="button"
        onClick={(e) => {
          e.stopPropagation();
          onPack(order.id);
        }}
      >
        В упаковку
      </button>
    </article>
  );
}

type OrderListProps = {
  orders: Order[];
  selectedId: number | null;
  onSelect: (id: number) => void;
  onPack: (id: number) => void;
  footer?: React.ReactNode;
};

function OrderList({ orders, selectedId, onSelect, onPack, footer }: OrderListProps) {
  return (
    <section>
      {orders.map((order) => (
        <OrderCard
          key={order.id}
          order={order}
          selected={order.id === selectedId}
          onSelect={onSelect}
          onPack={onPack}
        />
      ))}
      {footer}
    </section>
  );
}
```

## Разбор примера

`selected = false` — безопасное умолчание: родитель может не передавать prop. `onPack` на кнопке вызывает `stopPropagation`, чтобы клик не всплыл в `onSelect` карточки — иначе одно нажатие сделает два действия.

`OrderList` не фильтрует сам бизнес-правила домена — получает уже подготовленный массив. Фильтр остаётся у владельца state. `footer?: React.ReactNode` позволяет вставить кнопку «Обновить» без правки нутра списка — расширение через композицию.

Колбэки одни и те же ссылки с родителя пробрасываются вниз: список не оборачивает их без нужды. Позже оптимизация `useCallback` появится по измерению, не заранее.

## Типичные ошибки

- Мутация `props` внутри ребёнка.
- Передача «всего store» вместо узкого контракта.
- Забывать `stopPropagation`, когда вложенные клики конфликтуют.
- Делать обязательным prop, который нужен раз в год — лучше опциональность.
- Prop drilling через 8 слоёв без пересмотра структуры.

## Что запомнить

Props — явный вход компонента. Данные вниз, события вверх. Не мутируйте props. Композиция через `children` часто лучше новых флагов. Узкий контракт props проще широкого «даём всё».
