# DOM — дерево страницы

## Цель

Научиться видеть HTML как дерево объектов в памяти браузера и безопасно менять его из JavaScript. После урока вы найдёте узел списка заказов, создадите элемент, поменяете атрибут и класс — понимая, что именно меняется.

## Что уже нужно понимать

Вы писали HTML и подключали JS. DOM (Document Object Model) — мост между ними: разметка становится объектами, у которых есть свойства и методы. Пока вы не вызовете API DOM, строка в файле `.html` сама по себе «не живая».

## Объяснение

Когда браузер парсит HTML, он строит дерево узлов. У каждого узла есть тип (элемент, текст, комментарий), родитель, дети, соседние узлы. JavaScript работает с этими объектами: `document` — вход в дерево текущей страницы. Изменение DOM заставляет браузер при необходимости пересчитать стили и перерисовать участок экрана.

Зачем думать деревом, а не «строкой HTML»: операции точечные. Вместо «перезаписать всю страницу» вы меняете один `<li>` статуса. Это быстрее для интерфейса и проще для отладки. Кроме того, дерево отражает вложенность: статус — потомок пункта, пункт — потомок списка.

Поиск узлов: `getElementById` (быстро и однозначно), `querySelector` / `querySelectorAll` (CSS-селекторы), устаревающие коллекции вроде `getElementsByClassName` (живые, иногда неожиданные). Для панели заказов обычно: контейнер по id, элементы статусов — по классу внутри контейнера.

Изменение содержимого: `textContent` ставит текст безопасно; `innerHTML` парсит строку как HTML и опасен с недоверенными данными (XSS). Создание узлов: `createElement`, затем `appendChild` / `prepend` / `replaceChildren`. Атрибуты: `setAttribute`, `dataset` для `data-*`, `classList` для классов.

## Термины

- **Узел (node)** — элемент дерева DOM.
- **Элемент** — узел-тег с атрибутами и детьми.
- **Живая коллекция** — список, который меняется при изменении DOM автоматически.
- **XSS** — внедрение чужого HTML/JS через небезопасную вставку строк.

## Как это устроено

Связь «HTML ↔ DOM» двусторонняя в смысле отображения: вы меняете DOM — меняется то, что видит пользователь. Исходный файл на сервере при этом не переписывается; обновление только в памяти вкладки, пока вы сами не отправите данные на бэкенд.

Производительность: тысяча мелких правок подряд может быть дороже одной перерисовки блока. Для учебного списка из десятков заказов это не критично; для тысяч строк уже думают про виртуализацию. Пока достаточно паттерна «обновили массив → перерисовали контейнер списка», либо точечно сменили класс статуса у одного `li`.

Инструменты: вкладка Elements в DevTools показывает живое дерево. Можно править атрибуты руками и сразу видеть эффект — хороший способ проверить селектор до кода.

## Пример

```javascript
const list = document.querySelector("#orders");

function upsertOrder(order) {
  let item = list.querySelector(`[data-id="${order.id}"]`);
  if (!item) {
    item = document.createElement("li");
    item.dataset.id = String(order.id);

    const title = document.createElement("span");
    title.className = "title";
    item.appendChild(title);

    const status = document.createElement("span");
    status.className = "status";
    item.appendChild(status);

    list.appendChild(item);
  }

  item.querySelector(".title").textContent = `#${order.id} — ${order.title}`;
  const statusEl = item.querySelector(".status");
  statusEl.textContent = order.status;
  statusEl.className = `status status-${order.status}`;
}

upsertOrder({ id: 101, title: "Упаковка", status: "new" });
upsertOrder({ id: 101, title: "Упаковка", status: "packing" });
```

## Разбор примера

`querySelector` на контейнере ограничивает поиск поддеревом списка — не заденем чужие элементы страницы. `data-id` хранит идентификатор заказа в DOM, чтобы повторный вызов обновил тот же пункт, а не создал дубликат.

Мы собираем узлы через `createElement` и `textContent`, а не через `innerHTML = '<li>...' + userInput`. Даже если `title` когда-нибудь придёт с сервера с символами `<`, они отобразятся как текст, а не как теги.

Второй вызов `upsertOrder` для того же id меняет только текст и классы статуса: дерево не раздувается. Класс `status-packing` должен быть описан в CSS — DOM меняет крючок, стиль уже готов.

## Типичные ошибки

- Строить разметку конкатенацией строк с данными пользователя.
- Искать элементы до готовности документа.
- Хранить «истину» только в DOM («прочитаю статус из текста») вместо модели данных в JS.
- Массово трогать layout в цикле без нужды (чтение `offsetHeight` между записями стилей).
- Путать `NodeList` из `querySelectorAll` с массивом: методов массива может не быть без преобразования.

## Что запомнить

DOM — объектное дерево страницы. JS ищет узлы, меняет текст, классы, атрибуты, детей. Предпочитайте безопасные API (`textContent`, `createElement`). Контейнер списка + модель данных дают предсказуемый UI. DevTools Elements — ваш рентген.

## Задание
