# События и обработчики

## Цель

Научиться подписываться на действия пользователя и браузера: клик, ввод, submit, изменение. После урока вы свяжете кнопки и форму панели заказов с функциями так, чтобы интерфейс реагировал предсказуемо, а форма не перезагружала страницу без нужды.

## Что уже нужно понимать

Вы умеете найти элемент в DOM и изменить его. Событие — сигнал «что-то произошло»; обработчик — ваша функция, которую браузер вызовет в ответ. Без событий скрипт либо отработает один раз при загрузке, либо вам придётся опрашивать страницу в цикле — плохая идея.

## Объяснение

Браузер генерирует события постоянно: мышь, клавиатура, касания, загрузка ресурса, изменение размера окна. Нас интересует прикладной слой панели: `click` на кнопке статуса, `input`/`change` в поле фильтра, `submit` у формы нового заказа.

Подписка: `element.addEventListener('click', handler)`. Можно и `onclick = handler`, но `addEventListener` позволяет несколько слушателей и явное снятие. Обработчик получает объект `event`: кто источник (`event.target`), что нажато, координаты, методы `preventDefault` и `stopPropagation`.

Всплытие (bubbling): клик по тексту внутри кнопки всплывает вверх по дереву. Это позволяет **делегирование**: один слушатель на списке заказов ловит клики по всем будущим кнопкам «В упаковку», даже если пункты создали позже. Иначе пришлось бы вешать обработчик на каждую кнопку при каждом рендере.

`preventDefault` отменяет действие по умолчанию: у ссылки — переход, у формы — навигационный submit. Для SPA-подобных учебных панелей на `fetch` это нормально: вы сами решаете, когда слать данные. Не путайте с `stopPropagation`, которое только останавливает всплытие к родителям.

## Термины

- **Событие** — уведомление о действии или изменении.
- **Обработчик (listener)** — функция-реакция.
- **Цель (target)** — самый глубокий элемент, на котором событие возникло.
- **Всплытие** — движение события от цели к предкам.
- **Делегирование** — слушатель на предке вместо каждого потомка.

## Как это устроено

Очередь задач браузера: пользователь кликнул → событие поставлено → вызываются слушатели → при необходимости обновляется DOM → кадр отрисовки. Если обработчик долгий, интерфейс «тупит». Поэтому в обработчике: быстро обновить состояние, запустить async-запрос, не считать тяжёлую математику синхронно.

Частые типы для панели:

- `click` — кнопки действий;
- `submit` — форма (лучше слушать форму, а не кнопку);
- `input` — живой фильтр по номеру заказа;
- `change` — select статуса;
- `keydown` — горячие клавиши (осторожно с доступностью).

Снятие слушателя нужно, если элемент уничтожается и вы передавали именованную функцию — иначе утечки в долгих сессиях. Для учебной страницы без снятия часто «прокатывает», но привычка именовать handler полезнее анонимных стрелок «навсегда».

## Пример

```javascript
const list = document.getElementById("orders");
const form = document.getElementById("create-order");
const filterInput = document.getElementById("filter");

const orders = [
  { id: 101, title: "Упаковка", status: "new" },
  { id: 102, title: "Доставка", status: "packing" },
];

function render(filter = "") {
  const q = filter.trim().toLowerCase();
  list.replaceChildren();
  for (const order of orders) {
    if (q && !String(order.id).includes(q) && !order.title.toLowerCase().includes(q)) {
      continue;
    }
    const li = document.createElement("li");
    li.dataset.id = String(order.id);
    li.innerHTML = ""; // очистка; дальше только безопасные узлы
    const label = document.createElement("span");
    label.textContent = `#${order.id} — ${order.title} — ${order.status}`;
    const btn = document.createElement("button");
    btn.type = "button";
    btn.dataset.action = "pack";
    btn.textContent = "В упаковку";
    li.append(label, btn);
    list.appendChild(li);
  }
}

list.addEventListener("click", (event) => {
  const btn = event.target.closest("button[data-action='pack']");
  if (!btn || !list.contains(btn)) return;
  const id = Number(btn.closest("li").dataset.id);
  const order = orders.find((o) => o.id === id);
  if (!order) return;
  order.status = "packing";
  render(filterInput.value);
});

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const data = new FormData(form);
  const title = String(data.get("customer") || "").trim();
  if (!title) return;
  const id = orders.reduce((m, o) => Math.max(m, o.id), 100) + 1;
  orders.push({ id, title, status: "new" });
  form.reset();
  render(filterInput.value);
});

filterInput.addEventListener("input", () => render(filterInput.value));
render();
```

## Разбор примера

Делегирование на `list` ловит кнопки, которых ещё не существовало на этапе подписки. `closest` поднимается от `event.target` к кнопке — даже если клик пришёлся на текст внутри кнопки.

`submit` + `preventDefault` оставляют пользователя на странице: мы читаем `FormData`, обновляем массив, перерисовываем. Валидацию «пустой клиент» сделали на клиенте для UX; настоящая проверка всё равно должна жить на сервере, когда появится API.

Фильтр на `input` перерисовывает список при каждом изменении поля — для короткого списка приемлемо. `replaceChildren()` очищает контейнер без остатков старых узлов и слушателей на них (слушатель у нас на родителе — он остаётся).

## Типичные ошибки

- Слушать `click` на кнопке submit и забывать про Enter в поле — `submit` формы надёжнее.
- Забыть `preventDefault` и получить перезагрузку страницы «из ниоткуда».
- Вешать сотни слушателей на каждый `li` без делегирования.
- В обработчике мутировать DOM хаотично, пока «истина» в массиве разъехалась с экраном.
- Глотать ошибки в async-обработчиках без `try/catch` и сообщения пользователю.

## Что запомнить

События связывают UI и код. `addEventListener`, всплытие и делегирование масштабируют список. `preventDefault` управляет поведением браузера по умолчанию. Обработчик должен быть коротким: изменить модель → отрисовать → при необходимости запросить сервер.

## Задание

Добавьте делегированную кнопку «Отменить» (`status = cancelled`) и обработчик `change` на `<select>` фильтра по статусу. Убедитесь, что новые пункты списка тоже реагируют без повторной подписки.
