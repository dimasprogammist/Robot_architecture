# useEffect — побочные эффекты

## Цель

Научиться запускать побочные эффекты в React: загрузка заказов при монтировании, подписка/отписка, синхронизация с внешним миром — без бесконечных циклов запросов. После урока вы загрузите список с API через `useEffect` и корректно обработаете размонтирование.

## Что уже нужно понимать

`useState` хранит данные. Render должен быть относительно чистым: посчитать JSX из state/props. Сеть, таймеры, ручная подписка на `window` — это **эффекты**: они живут вне чистого вычисления разметки. В ванильном JS вы вызывали `loadOrders()` в конце файла; в React место этому — `useEffect`.

## Объяснение

`useEffect(() => { ... }, [deps])` говорит: после отрисовки выполни функцию; перезапусти, когда изменились зависимости; при необходимости верни cleanup. Пустой массив зависимостей `[]` — «после первого монтирования». Без массива эффект после *каждого* рендера — редко нужно и опасно. С `[filter]` — при смене фильтра.

Типичный сценарий панели: монтирование → `GET /api/orders` → `setOrders`. Ошибка → `setError`. Флаг loading. Cleanup: `AbortController.abort()` чтобы поздний ответ не записал state в уже размонтированный компонент (предупреждение React и гонки).

Эффект — не место для обычных вычислений (`visible = orders.filter`). И не замена обработчику клика: клик обрабатывайте в `onClick`, а эффект — для синхронизации с внешней системой.

Цикл: эффект делает `setState` → рендер → эффект снова, потому что зависимость меняется каждый раз (новый объект/массив в deps без нужды, или зависимость от того, что сам эффект пишет). Лечится правильными deps и функциональными обновлениями.

## Термины

- **Побочный эффект** — взаимодействие с миром вне расчёта JSX.
- **Dependency array** — список значений, от которых эффект зависит.
- **Cleanup** — функция очистки подписки/таймера/запроса.
- **Гонка** — устаревший ответ перетирает более новый.

## Как это устроено

React гарантирует: сначала DOM обновлён под новый JSX, потом эффекты. Поэтому в эффекте можно измерить элемент, но новичкам чаще нужен просто fetch. Строгий режим React в development может намеренно монтировать/размонтировать дважды — пишите эффекты идемпотентно и с cleanup, чтобы не удивляться двойному запросу в dev.

Серверное состояние: после мутации (создание заказа) либо инвалидируете список новым fetch из обработчика, либо обновляете state локально. Эффект с `[orders]` который снова fetchит — почти наверняка ошибка проектирования.

Документ/заголовок вкладки, фокус поля, WebSocket — тоже эффекты. Для WebSocket cleanup обязан закрыть сокет.

## Пример

```tsx
import { useEffect, useState } from "react";

type Order = { id: number; customer: string; status: string };

export function OrdersFromApi() {
  const [orders, setOrders] = useState<Order[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);
  const [filter, setFilter] = useState("");

  useEffect(() => {
    const ac = new AbortController();

    async function load() {
      setLoading(true);
      setError(null);
      try {
        const qs = filter.trim() ? `?q=${encodeURIComponent(filter.trim())}` : "";
        const res = await fetch(`/api/orders${qs}`, { signal: ac.signal });
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const data = (await res.json()) as Order[];
        setOrders(data);
      } catch (e) {
        if ((e as Error).name === "AbortError") return;
        setError((e as Error).message);
      } finally {
        if (!ac.signal.aborted) setLoading(false);
      }
    }

    load();
    return () => ac.abort();
  }, [filter]);

  return (
    <div>
      <input value={filter} onChange={(e) => setFilter(e.target.value)} />
      {loading && <p>Загрузка…</p>}
      {error && <p role="alert">{error}</p>}
      <ul>
        {orders.map((o) => (
          <li key={o.id}>
            #{o.id} {o.customer} — {o.status}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

## Разбор примера

Зависимость `[filter]` перезапускает загрузку при смене фильтра. Cleanup абортит предыдущий запрос — защита от гонки, когда быстрый ввод «а», «аб», «абв» возвращает ответы не по порядку.

`AbortError` глушим: это не ошибка пользователя. `finally` с проверкой abort не гасит loading чужого, уже нового эффекта некорректно — здесь упрощённый учебный вариант; главное — идея отмены.

Пока фильтр на сервере через query; можно было фильтровать локально без эффекта на каждый ввод — и часто так лучше для малых списков. Здесь намеренно показан эффект с deps.

## Типичные ошибки

- `useEffect(() => load())` без deps и с `setState` внутри → цикл.
- Забыть cleanup для сокета/таймера.
- Класть в deps объект, создаваемый каждый рендер.
- Делать эффектом то, что должно быть onClick.
- Игнорировать Strict Mode и плодить дубли без abort.

## Что запомнить

Эффекты синхронизируют React с внешним миром. Указывайте зависимости честно. Cleanup отменяет запросы и подписки. Fetch при монтировании — классика; не превращайте render в сеть. Гонки лечат abort и игнором устаревшего.

## Задание

Добавьте кнопку «Обновить», которая дергает ту же функцию загрузки без смены фильтра (вынесите load или добавьте `reloadToken` в state как зависимость). Закройте страницу/компонент в dev и убедитесь, что abort не показывает ошибку.
