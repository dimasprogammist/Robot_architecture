# CSS — внешний вид без ломки структуры

## Цель

Научиться отделять оформление от HTML: задавать цвета статусов, сетку панели и отступы через CSS так, чтобы разметка оставалась про заказы, а не про пиксели. После урока вы оформите список заказов каскадными правилами и поймёте специфичность селекторов на практике.

## Что уже нужно понимать

У вас есть HTML-документ с семантическими блоками: `header`, `main`, список, форма. CSS не заменяет теги и не создаёт данные — он говорит браузеру, *как* нарисовать уже существующие элементы. Если в HTML нет узла, CSS не «дорисует» смысл из воздуха.

## Объяснение

CSS (Cascading Style Sheets) — язык правил вида «для таких-то элементов применить такие-то свойства». Правило состоит из **селектора** и **блока объявлений**. Селектор отвечает на вопрос «кого красим», объявления — «во что». Каскад означает: несколько правил могут претендовать на один элемент; побеждает более специфичное и более позднее (с оговорками про `!important`, который лучше почти не трогать).

Зачем отделять стили от разметки: один и тот же список заказов может выглядеть как компактная таблица на десктопе и как карточки на телефоне — HTML при этом не дублируют. Меняется файл стилей или медиазапрос. Кроме того, дизайнер и разработчик интерфейса могут работать параллельно, если контракт по классам стабилен.

Подключение бывает трёх видов: инлайн-атрибут `style` (жёстко и плохо масштабируется), тег `<style>` в `head` (удобно для крошечных страниц) и внешний файл через `<link rel="stylesheet">` (норма для проектов). В курсе предпочитаем внешний файл или хотя бы отдельный блок правил — так видно границу ответственности.

Модель отрисовки упрощённо: браузер строит DOM из HTML, сопоставляет CSS-правила, считает геометрию (боксы), затем рисует. Каждый элемент — прямоугольник с margin, border, padding и content. Понимание box model снимает половину «почему отступ съехал».

## Термины

- **Селектор** — условие выбора элементов (по тегу, классу, id, состоянию).
- **Свойство** — параметр оформления (`color`, `display`, `gap`).
- **Каскад** — алгоритм разрешения конфликтующих правил.
- **Специфичность** — «вес» селектора при конфликте.
- **Box model** — margin → border → padding → content.

## Как это устроено

Селекторы от простого к точному: `li` красит все пункты; `.status` — элементы с классом; `#orders` — один уникальный id; `li .status` — статус внутри пункта. Псевдоклассы вроде `:hover`, `:focus`, `:invalid` описывают состояние без JS. Для панели заказов классы на статусах (`status-new`, `status-packing`) читаемее, чем красить по порядковому номеру ребёнка.

`display` меняет роль в потоке: `block`, `inline`, `flex`, `grid`. Flex и grid решают раскладку панели: шапка сверху, две колонки «список | детали». Не нужно абсолютное позиционирование «на глаз» для обычных сеток — оно ломается при изменении длины текста.

Единицы: `px` — абсолютные; `rem` — относительно корня (удобно для типографики); `%` и `fr` — доли контейнера. Цвета — именованные, hex, `rgb`, лучше сразу завести CSS-переменные (`--status-new`) в `:root`, чтобы тема панели не размазалась по файлу.

## Пример

```html
<!-- фрагмент body -->
<ul id="orders" class="order-list">
  <li class="order-item">
    <span class="order-id">#101</span>
    <span class="status status-new">new</span>
  </li>
  <li class="order-item">
    <span class="order-id">#102</span>
    <span class="status status-packing">packing</span>
  </li>
</ul>
```

```css
:root {
  --bg: #f3f5f7;
  --card: #ffffff;
  --text: #1a1f24;
  --status-new: #2f6fed;
  --status-packing: #c47a00;
}

body {
  margin: 0;
  font-family: "Segoe UI", sans-serif;
  color: var(--text);
  background: var(--bg);
}

.order-list {
  list-style: none;
  margin: 1rem;
  padding: 0;
  display: flex;
  flex-direction: column;
  gap: 0.5rem;
}

.order-item {
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 0.75rem 1rem;
  background: var(--card);
  border-radius: 8px;
}

.status {
  padding: 0.2rem 0.55rem;
  border-radius: 4px;
  color: #fff;
  font-size: 0.85rem;
}

.status-new { background: var(--status-new); }
.status-packing { background: var(--status-packing); }

.order-item:hover {
  outline: 2px solid #c5ced8;
}
```

## Разбор примера

HTML по-прежнему говорит «это список заказов». Классы — крючки для CSS, не замена семантики. Переменные в `:root` держат палитру: смена темы — правка нескольких строк, а не охота по файлу.

`list-style: none` убирает маркеры, потому что маркеры здесь визуальный шум; смысл списка сохранён тегом `ul`. Flex на `.order-item` выравнивает номер и статус без таблиц и без абсолютных координат. Hover даёт обратную связь мыши; для клавиатуры позже добавите `:focus-visible`.

Заметьте: цвет статуса задан классом, а не инлайном. Когда JS сменит статус с `new` на `packing`, достаточно заменить класс — CSS уже знает оба варианта.

## Типичные ошибки

- Пихать оформление в HTML через `style="..."` и потом не мочь найти, кто перебил цвет.
- Селекторы вида `div div span` вместо осмысленных классов — хрупко при правке вёрстки.
- Путать margin и padding: «воздух снаружи» и «воздух внутри» рамки.
- Чинить раскладку `position: absolute` там, где хватило бы flex/grid.
- Завышать специфичность (`#a #b .c`) и потом воевать с собственными правилами.

## Что запомнить

CSS описывает внешний вид поверх структуры HTML. Каскад и специфичность решают конфликты. Box model и flex/grid — основа раскладки. Классы и переменные делают панель заказов сопровождаемой. Меняйте вид, не ломая смысл разметки.

## Задание

Возьмите HTML из прошлого урока (или телеметрию). Вынесите стили во внешний `panel.css`: сетка из двух колонок на широком экране, цветные бейджи статусов/типов датчиков, аккуратные поля формы. Добавьте `:focus` для полей ввода. Не используйте инлайн-стили.
