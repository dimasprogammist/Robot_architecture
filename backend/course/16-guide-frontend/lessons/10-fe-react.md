# React — UI как функция от состояния

## Цель

Понять идею React: описывать интерфейс декларативно как функцию от состояния, а обновление DOM доверить библиотеке. После урока вы соберёте маленький список заказов на компонентах React и увидите связь с ванильным `render(state)`.

## Что уже нужно понимать

Вы уже делали компоненты-функции, state-объект и `render` вручную. React не отменяет HTML/CSS/JS и HTTP — он берёт на себя согласование виртуального описания UI с реальным DOM. Синтаксис JSX выглядит как HTML в JavaScript, но это сахар над вызовами функций.

## Объяснение

В ванильном подходе вы императивно говорите: «создай li, поставь текст, повесь слушатель». В React вы говорите: «при таких orders список выглядит так» — и при смене `orders` React пересчитывает описание и минимально обновляет DOM.

Зачем: меньше ручного рассинхрона, удобные компоненты, экосистема (маршрутизация, формы). Цена: сборка (Vite/CRA), модель хуков, иногда избыточность для крошечной страницы. Для панели заказов React оправдан, когда UI растёт.

Компонент React — функция с именем с большой буквы, принимает `props`, возвращает JSX. Состояние внутри компонента — через `useState` (разберём отдельно подробно). Корень монтируют в `document.getElementById('root')` через `createRoot`.

JSX: `className` вместо `class`, `htmlFor` вместо `for`, события `onClick` camelCase. В фигурных скобках — выражения JS. Списки рендерят через `map` и обязательный устойчивый `key`.

## Термины

- **Декларативный UI** — описываем «что», не «как пошагово трогать DOM».
- **JSX** — синтаксис разметки в JS.
- **Props** — вход компонента из родителя.
- **Virtual DOM (упрощённо)** — промежуточное описание для сравнения обновлений.
- **Корень (root)** — точка монтирования приложения.

## Как это устроено

При изменении state React планирует повторный вызов вашего компонента-функции. Новый JSX сравнивается с предыдущим результатом; отличаются — обновляются соответствующие узлы DOM. Вам не нужно вызывать `replaceChildren` вручную.

Данные вниз, события вверх — то же правило, что в ванильных компонентах. Список владеет массивом заказов; элемент получает один `order` и колбэк. Не мутируйте props: считайте их замороженным входом кадра.

Пока без роутера и без Redux: одного дерева компонентов и локального state хватает, чтобы понять суть. Инструменты: React DevTools показывают дерево и props.

## Пример

```jsx
import { useState } from "react";
import { createRoot } from "react-dom/client";

function OrderItem({ order, onPack }) {
  return (
    <li className="order-item">
      <span>
        #{order.id} — {order.customer} — {order.status}
      </span>
      <button
        type="button"
        disabled={order.status === "packing"}
        onClick={() => onPack(order.id)}
      >
        В упаковку
      </button>
    </li>
  );
}

function OrdersApp() {
  const [orders, setOrders] = useState([
    { id: 101, customer: "Ромашка", status: "new" },
    { id: 102, customer: "Василёк", status: "new" },
  ]);

  function pack(id) {
    setOrders((prev) =>
      prev.map((o) => (o.id === id ? { ...o, status: "packing" } : o))
    );
  }

  return (
    <div>
      <h1>Заказы</h1>
      <ul>
        {orders.map((order) => (
          <OrderItem key={order.id} order={order} onPack={pack} />
        ))}
      </ul>
    </div>
  );
}

createRoot(document.getElementById("root")).render(<OrdersApp />);
```

## Разбор примера

`useState` возвращает текущее значение и функцию обновления. Мы не пишем `orders[i].status = ...` — создаём новый массив через `map` и новый объект заказа. Так React надёжно видит изменение.

`OrderItem` чистый: только props. `key={order.id}` помогает согласовать элементы списка при перестановках; индекс массива как key — плохая идея, если список фильтруется и меняется.

`disabled` вычисляется из данных каждого кадра. После `setOrders` React снова вызовет `OrdersApp`, перерисует список — кнопка у упакованного заказа станет неактивной без ручного `btn.disabled = true`.

## Типичные ошибки

- Мутировать массив state «на месте» и ждать обновления.
- Забывать `key` у элементов списка.
- Писать `class` вместо `className`.
- Класть тяжёлый `fetch` прямо в тело компонента без хуков эффектов — получите цикл.
- Думать, что React «заменяет JS» — это библиотека UI, не бэкенд.

## Что запомнить

React: UI = f(state, props). Компоненты-функции + JSX. Обновление state запускает перерисовку описания. Данные вниз, колбэки вверх. Ванильный опыт с state/render переносится напрямую.
