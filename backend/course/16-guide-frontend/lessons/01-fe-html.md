# HTML — каркас страницы

## Цель

Научиться описывать структуру веб-страницы тегами HTML так, чтобы браузер понимал, где заголовок, кнопка, форма и список заказов. После урока вы сможете собрать простую страницу панели заказов без стилей и скриптов, но с правильной семантикой.

## Что уже нужно понимать

Вы уже знаете, что клиент и сервер обмениваются HTTP-запросами, а браузер умеет показать ответ. HTML — это не язык программирования, а язык разметки: он говорит, *что* лежит на странице, а не *как* это красиво выглядит и не *что* делать по клику. CSS и JavaScript подключатся в следующих уроках.

## Объяснение

Когда вы открываете адрес в браузере, сервер чаще всего отдаёт текст в формате HTML. Браузер читает этот текст сверху вниз, строит дерево элементов (DOM) и рисует страницу. Каждый кусок содержимого обёрнут в **тег**: открывающий, закрывающий и содержимое между ними. Вложенность тегов задаёт иерархию: список внутри панели, кнопка внутри формы, заголовок внутри секции.

Смысл HTML — отделить структуру от оформления и поведения. Если вы пишете «это заголовок второго уровня» через `<h2>`, а не через «жирный большой текст», то поисковик, скринридер и ваш будущий CSS понимают роль блока. Для учебной панели заказов это значит: список заказов — список, статус — отдельный элемент, кнопка «Обновить» — кнопка, а не картинка с подписью.

Теги бывают блочные (занимают полосу целиком, как `<section>`, `<div>`, `<ul>`) и строчные (живут в потоке текста, как `<span>`, `<a>`, `<strong>`). Есть пустые теги без содержимого: `<img>`, `<br>`, `<meta>`. Атрибуты уточняют поведение: `href` у ссылки, `type` у поля ввода, `id` и `class` для адресации из CSS и JS.

Документ начинается с объявления `<!DOCTYPE html>` и корня `<html>`. Внутри — `<head>` (метаданные, заголовок вкладки, ссылки на стили) и `<body>` (то, что видит пользователь). Всё, что пользователь должен увидеть и нажать, живёт в `body`. Всё, что нужно браузеру «за кулисами», — в `head`.

## Термины

- **Тег** — метка в угловых скобках, обозначающая тип узла (`<p>`, `<button>`).
- **Элемент** — тег вместе с содержимым и вложенными элементами.
- **Атрибут** — пара имя="значение" внутри открывающего тега.
- **Семантика** — выбор тега по смыслу, а не только по внешнему виду.
- **DOM** — дерево объектов, которое браузер строит из HTML (разберём отдельно).

## Как это устроено

Браузер не «рисует файл». Он парсит HTML в дерево: корневой `html`, дети `head` и `body`, дальше вложенные узлы. Ошибка вложенности (например, закрыли тег не в том порядке) приводит к тому, что браузер «чинит» дерево по своим правилам — и ваша задумка ломается тихо.

Для интерфейса заказов разумная скелетная схема такая: шапка с названием продукта, основная область со списком, боковая или нижняя панель деталей, форма создания заказа. Семантические теги `<header>`, `<main>`, `<section>`, `<form>`, `<ul>`/`<li>` дают этой схеме имена. Универсальный `<div>` допустим как коробка без смысла, но если смысл есть — лучше сказать его тегом.

Формы — отдельный контракт с сервером. Поля `<input>`, `<select>`, `<textarea>` собирают данные; атрибут `name` станет ключом в запросе; `button type="submit"` отправит форму. Пока без JS форма уходит классическим HTTP POST/GET — это полезно помнить, даже если позже вы перейдёте на `fetch`.

## Пример

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8" />
  <title>Панель заказов</title>
</head>
<body>
  <header>
    <h1>Orders Desk</h1>
    <p>Учебная панель: список и создание заказа</p>
  </header>

  <main>
    <section aria-labelledby="list-title">
      <h2 id="list-title">Открытые заказы</h2>
      <ul id="orders">
        <li data-id="101">#101 — упаковка — <span>new</span></li>
        <li data-id="102">#102 — доставка — <span>packing</span></li>
      </ul>
    </section>

    <section aria-labelledby="create-title">
      <h2 id="create-title">Новый заказ</h2>
      <form id="create-order" action="/api/orders" method="post">
        <label>
          Клиент
          <input name="customer" type="text" required />
        </label>
        <label>
          Город
          <input name="city" type="text" required />
        </label>
        <button type="submit">Создать</button>
      </form>
    </section>
  </main>
</body>
</html>
```

## Разбор примера

`lang="ru"` подсказывает язык для доступности и переносов. `charset="UTF-8"` нужен, чтобы кириллица не превратилась в кракозябры. Заголовок вкладки живёт в `<title>`, а видимый заголовок страницы — в `<h1>`: это разные роли.

Список заказов — настоящий `<ul>`, каждый заказ — `<li>`. Атрибут `data-id` пока просто метка; позже JS прочитает его без отдельного скрытого поля. Статус обёрнут в `<span>`, чтобы его можно было перекрасить или заменить текстом отдельно от номера заказа.

Форма явно указывает `action` и `method`: даже без JavaScript браузер знает, куда слать данные. `label` связан с полем через вложенность — клик по тексту фокусирует поле. `required` — первая линия защиты на клиенте; сервер всё равно обязан проверить снова.

## Типичные ошибки

- Лепить всё в `<div>` и терять смысл блоков: список перестаёт быть списком.
- Путать `<h1>`–`<h6>` с «размером шрифта»: уровни — про иерархию заголовков.
- Забывать `charset` и получать битую кириллицу.
- Класть видимый контент в `<head>` или скрипты «куда попало» без понимания порядка загрузки.
- Делать кликабельную область из `<div>` без роли кнопки/ссылки — ломается клавиатура и доступность.

## Что запомнить

HTML задаёт структуру документа. Теги и вложенность образуют дерево. Семантика важнее «похожести на макет». Формы и списки — готовые контракты браузера. Стили и поведение подключаются отдельно; сначала страница должна иметь смысл даже «голой».

## Задание

Соберите HTML-страницу «телеметрия робота»: заголовок, список последних измерений (время, датчик, значение), форма «добавить ручную метку» с полями время и комментарий. Без CSS и JS. Проверьте в браузере, что заголовки и список читаются осмысленно при отключённых стилях.
