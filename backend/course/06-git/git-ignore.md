# Игнорирование файлов

## Цель

Понять .gitignore как фильтр для неотслеживаемых путей, не «удалятор истории».

## Что уже пройдено

Вы уже коммитите осознанно. Нужно отсечь мусор и секреты заранее.

## Объяснение с нуля

**`.gitignore`** перечисляет шаблоны путей, которые Git не предлагает как неотслеживаемые и не добавляет через широкие `add`, если они ещё не tracked. Уже отслеживаемый файл ignore сам не вычеркнет из истории — нужна отдельная работа с индексом.

Игнорируют обычно: артефакты сборки, виртуальные окружения, кэши, локальные секреты, тяжёлые бинарники. Правило — в снимок попадает то, что нужно воспроизвести проект, а не случайный мусор машины.

## Термины

- **`.gitignore`** — шаблоны игнора в репозитории.
- **Tracked vs ignored** — отслеживаемое ignore не «прячет».
- **Локальный exclude** — игнор только у вас (`.git/info/exclude`).

## Внутреннее устройство

```text
рабочее дерево: .venv/, __pycache__/, .env, src/app.py
.gitignore: .venv/, __pycache__/, .env
status покажет интерес к app.py, не к мусору
```

## Пример

```gitignore
.venv/
__pycache__/
*.pyc
.env
```

## Разбор

Секрет, однажды закоммиченный, остаётся в объектах старых коммитов даже после удаления из последнего снимка. Ignore — профилактика, не лечение утечки.

## Ошибки

- Коммитить `.env` «на минутку».
- Игнорировать исходники по ошибке широким шаблоном.
- Ждать, что ignore перепишет историю.

## Что запомнить

Ignore отсекает неотслеживаемый шум. История уже попавшего — отдельная тема.

## Задание

Добавьте `.gitignore` в учебный проект под Python-кэш и `.env`. Проверьте `git status`.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
