# Revert: обратный снимок

## Цель

Понять revert как новый commit, отменяющий изменения другого, без переписывания истории.

## Что уже пройдено

Reset переписывает указатель. Для общих веток нужен другой инструмент.

## Объяснение с нуля

**Revert** создаёт новый коммит, чьё дерево отменяет эффект выбранного коммита (относительно его родителя). История только растёт: плохой снимок остаётся в графе, поверх него — «противоядие». Коллеги делают pull без переписывания хешей.

Для merge-коммитов revert сложнее (нужно указать родителя) — пока достаточно линейного случая.

## Термины

- **Revert** — новый commit-антидот.
- **Сохранение истории** — старый коммит остаётся достижим.

## Внутреннее устройство

```text
…—C3—C4(плохой)—C5
revert C4 → …—C3—C4—C5—R  (R отменяет эффект C4)
```

## Пример

```bash
git revert <hash>
```

## Разбор

Revert не «стирает секрет из всех объектов». Он чинит текущую линию. Для секретов нужна отдельная гигиена истории.

## Ошибки

- Путать с reset --hard.
- Revert не глядя в получившийся diff.
- Думать, что файл исчез из старых снимков.

## Что запомнить

Revert добавляет снимок-отмену. Подходит для уже опубликованной истории.

## Задание

Сделайте коммит с заведомо лишней строкой, затем revert. Сравните log с вариантом reset.

## Связь со следующим уроком

Дальше — stash: временно убрать незафиксированные правки с витрины.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
