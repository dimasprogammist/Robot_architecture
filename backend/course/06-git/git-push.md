# Push: отправить снимки

## Цель

Понять push как передачу объектов и обновление refs на remote.

## Что уже пройдено

Локальные коммиты есть. Remote должен узнать новый конец ветки.

## Объяснение с нуля

**Push** отправляет недостающие объекты и просит remote передвинуть указатель ветки (например `main`) на ваш коммит — если это разрешено правилами. Если на remote ветка ушла туда, куда ваш push не является предком (non-fast-forward), сервер отвергнет обновление: иначе чужие снимки стали бы недостижимы из ветки.

Push не «заливает рабочую папку». Незакоммиченное не уедет. Не в индексе — тем более.

## Термины

- **Push** — объекты + обновление remote ref.
- **Rejected non-FF** — на remote есть коммиты, которых нет у вас в истории этой ветки.
- **Force push** — опасное переписывание указателя (знать, но не делать на общих ветках без договора).

## Внутреннее устройство

```text
локально main → C5
remote main → C3 ; C3 предок C5 → push OK, remote main → C5
если remote → C4' (другая линия) → отказ
```

## Пример

```bash
git push -u origin main
```

`-u` связывает локальную ветку с upstream для следующих push/status.

## Разбор

Сначала fetch, если работаете не один: иначе легко получить отказ и сюрприз. История на remote — общая договорённость.

## Ошибки

- Пушить секреты.
- Force push в `main` команды.
- Ждать, что push закоммитит за вас.

## Что запомнить

Push двигает удалённый указатель и досылает объекты. Успех = remote ветка указывает на ваш снимок.

## Задание

Сделайте push учебной ветки (не обязательно main). Проверьте на сайте/remote, что указатель сдвинулся.

## Связь со следующим уроком

Дальше — конфликты: когда два снимка не сливаются автоматически.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
