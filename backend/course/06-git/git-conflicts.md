# Конфликты слияния

## Цель

Понять конфликт как неавтоматическое объединение двух правок одного места.

## Что уже пройдено

Merge/pull иногда останавливаются. Это ожидаемо.

## Объяснение с нуля

**Конфликт** — Git не смог сам собрать итоговое tree из двух изменений относительно общего предка. Обычно обе стороны меняли одни и те же строки. В файле появляются маркеры границ. Репозиторий в состоянии «слияние не завершено», пока вы не соберёте содержимое, `git add` и не завершите merge/rebase.

Конфликт — не поломка Git. Это сигнал: нужно человеческое решение о снимке.

## Термины

- **Маркеры конфликта** — `<<<<<<<`, `=======`, `>>>>>>>`.
- **Разрешение** — выбрать/собрать итог, убрать маркеры, добавить в индекс.
- **Abort** — отменить попытку слияния/rebase.

## Внутреннее устройство

```text
база:   "timeout=10"
ours:   "timeout=12"
theirs: "timeout=15"
# автомат не угадает политику — конфликт
```

## Пример

```bash
# после конфликта в merge:
# правите файл, убираете маркеры
git add <file>
git commit   # завершает merge (если не FF и не идёт rebase)
```

## Разбор

Иногда «правильное» — взять одну сторону целиком, иногда — смешать смысл (не строки вслепую). Тесты после разрешения обязательны мысленно.

## Ошибки

- Закоммитить маркеры конфликта как текст.
- Удалять чужие правки не глядя.
- Паниковать: конфликт локален и обратим через abort, пока не запушили бессмыслицу.

## Что запомнить

Конфликт = незавершённая сборка tree. Итог должен снова стать осмысленным снимком без маркеров.

## Задание

Спровоцируйте учебный конфликт в двух ветках на одной строке. Разрешите и завершите merge.

## Связь со следующим уроком

Дальше — что не должно попадать в снимки: ignore.

## Ещё раз тем же смыслом

Git не угадывает намерение: он двигает указатели и создаёт объекты по правилам. Рисуйте стрелки «ветка → commit → tree → blob». Контрпример («а если push после rebase?») проявляет цену переписывания хешей. Перескажите урок за две минуты без списка флагов — только снимки и refs. Свой учебный репозиторий ценнее чужого длинного учебника. Сначала модель, потом команда.
