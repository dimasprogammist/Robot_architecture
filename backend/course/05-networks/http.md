# HTTP — запрос и ответ

## Цель

Понять HTTP как протокол приложения: проблему обмена документами/API, структуру сообщения, методы, коды статуса и типичный обмен поверх TCP.

## Исходные знания

TCP, клиент–сервер, порты. Текст как данные.

## Объяснение

### Проблема

Нужен универсальный способ запросить ресурс по URI и получить результат с метаданными (тип содержимого, кэш, ошибки), понятный и браузеру, и API-клиенту.

### Зачем протокол

HTTP задаёт формат запроса и ответа: метод, путь, версия, заголовки, тело. Сервер отвечает кодом статуса и телом. Протокол расширяем заголовками без ломки ядра.

### Принцип

Клиент открывает соединение (часто TCP 80 или TLS 443), шлёт запрос, читает ответ. HTTP/1.1 умеет keep-alive: несколько запросов на одном TCP. HTTP/2/3 улучшают мультиплексирование — детали позже; идея запроса-ответа та же.

### Структура сообщения своими словами

Запрос: стартовая строка `METHOD PATH VERSION`, затем заголовки `Имя: значение`, пустая строка, опциональное тело. Ответ: `VERSION CODE REASON`, заголовки, пустая строка, тело. Заголовки несут Host, Content-Type, Content-Length/Transfer-Encoding, кэш, аутентификацию и др.

Методы: GET (чтение), POST (отправка), PUT/PATCH/DELETE — семантика меняется по соглашению API. Идемпотентность и безопасность методов важны для кэшей и повторов.

### Ход обмена

1) Резолв имени. 2) TCP(+TLS). 3) Запрос. 4) Ответ. 5) Разбор кода: 2xx успех, 3xx редирект, 4xx ошибка клиента, 5xx ошибка сервера. Тело интерпретируется по Content-Type (HTML, JSON…).

### Ошибки

DNS/TCP/TLS ломаются до HTTP. 404 — нет ресурса. 401/403 — авторзация. 502/504 — проблемы шлюза/таймаута. Неверный Host на виртуальных хостах. Смешение HTTP и HTTPS.

## Термины

**URI/URL** — идентификатор ресурса.

**Метод** — глагол запроса.

**Статус-код** — машинный итог ответа.

**Заголовок** — метаданные сообщения.

**Body** — полезная нагрузка.

## Как это работает

Веб-сервер слушает порт, разбирает текст/бинарный фрейминг HTTP, маршрутизирует на обработчик, формирует ответ. Прокси могут стоять посередине и тоже говорить HTTP.

HTTP сам по себе не шифрует. На публичных сетях используют HTTPS.

## Пример

```text
GET /index.html HTTP/1.1
Host: example.com
Accept: text/html

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 13

Hello, world!
```

```bash
curl -sI http://example.com | head
```

## Разбор

Пример показывает стартовые строки, обязательность Host в HTTP/1.1 и отделение тела пустой строкой.

`curl -I` запрашивает заголовки (часто HEAD/эквивалент поведения) — удобно смотреть статус без всей страницы.

## Ошибки новичков

- Путать ошибку TCP с HTTP 500.
- Игнорировать коды и парсить только тело.
- Кэшировать чувствительные ответы неправильно.
- Считать POST «всегда создать» без контракта API.

## Что запомнить

- HTTP — запрос/ответ с методами, кодами и заголовками.
- Сообщение: стартовая строка + headers + body.
- Коды делят ответственность клиента и сервера.
- До HTTP должны успешно пройти нижние слои.

## Задание

Сделайте `curl -v` к любому учебному сайту по HTTP или HTTPS и выпишите: метод, статус, 3 заголовка запроса и 3 ответа. Кратко объясните смысл статуса.
