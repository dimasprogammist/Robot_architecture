# IPv6 — расширенное адресное пространство

## Цель

Понять, зачем появился IPv6, как читать сжатую запись адреса и чем отличаются базовые идеи (link-local, отсутствие NAT как нормы) от бытового IPv4.

## Исходные знания

IPv4 и проблема нехватки адресов. Идея маршрутизации по префиксам.

## Объяснение

IPv6 использует 128-битные адреса. Запись шестнадцатеричная группами по 16 бит, разделёнными двоеточиями. Правила сжатия позволяют один раз заменить последовательности нулевых групп на `::`. Регистр букв не важен.

Цель — огромное пространство, упрощение части механизмов и современный дизайн заголовка. Hop Limit заменяет TTL. Соседство на канале решается Neighbor Discovery (вместо ARP). Link-local адреса `fe80::/10` есть почти на каждом интерфейсе и требуют указания интерфейса при использовании.

Глобальные адреса назначаются из префиксов провайдера. Уникальные локальные (ULA) похожи по духу на частные IPv4, но практика развёртывания зависит от сайта.

NAT в мире IPv6 не считается обязательным спасением от нехватки. Безопасность строится на фильтрах и корректной политике, а не на «нас прячет NAT». На практике переходный период долог: dual-stack, туннели, только-IPv4 сервисы.

Приложения должны уметь работать с длинными адресами и счастливо выбирать A/AAAA записи DNS. Ошибки сокетов часто всплывают, когда код ждал только IPv4-строки.

Заголовок IPv6 фиксированной базовой части проще для маршрутизаторов в ряде аспектов; расширения вынесены в extension headers.

## Термины

**IPv6** — протокол интернет-уровня с 128-битными адресами.

**`::` сжатие** — сокращение нулевых групп в записи.

**Link-local** — адрес только для локального канала.

**AAAA** — DNS-запись для адреса IPv6.

**ND (Neighbor Discovery)** — открытие соседей и роутеров на канале.

## Как это работает

Хост получает префикс через Router Advertisement (часто) и строит адрес. Для связи вне канала использует маршруты, аналогично IPv4. На канале резолвит next hop через ND, не ARP.

Dual-stack хост выбирает семейство по правилам счастливого Eyeballs: пробует быстро доступное. Отладка требует смотреть оба мира.

## Пример

```bash
ip -6 addr
ip -6 route | head

# примеры записи
# 2001:db8::1
# fe80::1%eth0   (link-local с зоной интерфейса)
```

```text
проблема: IPv4-адресов мало для всех устройств
решение IPv6: 128 бит + современный ND/RA
ошибка новичка: игнорировать %iface у fe80::
```

## Разбор

`ip -6` показывает, что стек IPv6 уже может быть активен рядом с IPv4.

`2001:db8::/32` — документационный префикс, как `192.0.2.0/24` для примеров.

Link-local без зоны интерфейса неоднозначен на машине с несколькими NIC.

## Ошибки

- Считать IPv6 «выключенным», не проверив `ip -6`.
- Копировать адрес с лишними сжатиями `::` дважды.
- Ломать приложения жёстким парсингом только dotted-quad.
- Путать отсутствие NAT с «нет файрвола».

## Что запомнить

- IPv6 — 128 бит и другая запись.
- Link-local повсеместен и зонен интерфейсом.
- ND заменяет ARP по роли.
- Сосуществование с IPv4 — норма переходного периода.

## Задание

Выведите IPv6-адреса хоста. Найдите хотя бы один `fe80::` и глобальный/ULA, если есть. Запишите, чем они отличаются по области действия.

## Дополнение: практика и нюансы

Если AAAA есть, а путь IPv6 сломан, клиенты с Happy Eyeballs могут тормозить. Тестируйте оба семейства.

Firewall IPv6 часто забывают включить, «потому что NAT нет» — ошибка.

Privacy extensions меняют адрес хоста со временем — учитывайте в ACL по адресу.

Туннели 6in4/пассивия — временные костыли; предпочитайте native dual-stack.


Сверьте версии протокола TLS на клиенте и сервере при загадочных handshake failure.
