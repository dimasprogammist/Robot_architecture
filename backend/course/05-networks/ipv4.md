# IPv4 — адреса и записи

## Цель

Научиться читать IPv4-адрес, понимать классы частного использования, loopback и почему адресов не хватило для «каждого устройства в мире без трюков».

## Исходные знания

Идея IP как межсетевого слоя. Двоичная арифметика на уровне «байт».

## Объяснение

IPv4-адрес — 32 бита, обычно записывают четырьмя десятичными октетами: `192.0.2.10`. Человек читает десятичную форму; устройства работают с битами. Маска/префикс отделяет часть сети от части хоста — подробно в уроке про подсети.

Специальные адреса: `127.0.0.0/8` — loopback (часто `127.0.0.1`). `169.254.0.0/16` — link-local при отсутствии DHCP. Диапазоны частных сетей (`10/8`, `172.16/12`, `192.168/16`) не маршрутизируются в публичном интернете по соглашению; на границе обычно NAT.

Публичные адреса уникальны в глобальной таблице маршрутизации (в идеале). Их выдают провайдеры из пулов RIR. Нехватка 32-битного пространства привела к NAT и ускорила внедрение IPv6.

Широковещание в IPv4 связано с адресом сети и broadcast-адресом подсети. Направлять трафик «всем» нужно осознанно.

Заголовок IPv4 содержит версию, длину, TTL, протокол полезной нагрузки (TCP=6, UDP=17), контрольную сумму заголовка, адреса src/dst. Приложение обычно не собирает заголовок вручную — это стек ОС.

Запись с портом `203.0.113.5:443` — уже адрес сокета транспортного уровня; сам IPv4 порта не содержит.

## Термины

**Октет** — 8 бит в записи IPv4.

**Частный адрес** — из RFC-диапазонов для внутренних сетей.

**Публичный адрес** — глобально маршрутизируемый в интернете.

**Loopback** — адрес «самому себе».

**TTL** — лимит прыжков пакета IPv4.

## Как это работает

Стек ОС принимает от приложения «отправить на A.B.C.D», выбирает интерфейс и next hop по таблице маршрутов, уменьшает/ставит TTL, передаёт драйверу. При приёме проверяет, что пакет адресован хосту (или широковещание/мультикаст), затем отдаёт полезную нагрузку по полю protocol.

Ping использует ICMP рядом с IP, не TCP. Успешный ping не доказывает, что открыт прикладной порт.

## Пример

```bash
ip -4 addr
ping -c 1 127.0.0.1

# разбор записи
# 192.168.1.10 — часто частный адрес в домашней LAN
# 127.0.0.1    — loopback
```

```text
IPv4 header (упрощённо):
| ver | ... | TTL | proto | checksum | src | dst | payload |
```

## Разбор

`ip -4 addr` показывает только IPv4. Loopback ping проверяет стек.

Упрощённый заголовок напоминает, что src/dst — поля пакета, а не «магия Ethernet».

Частный `192.168.1.10` не обязан быть достижим из интернета напрямую.

## Ошибки

- Путать частный адрес с публичным.
- Думать, что 32 бита бесконечны.
- Писать адрес с портом и считать это «чистым IP».
- Игнорировать TTL при петлях маршрутизации.

## Что запомнить

- IPv4 — 32 бита, запись из четырёх октетов.
- Есть частные, публичные, loopback и link-local.
- IP не несёт порт — порт у транспорта.
- Нехватка адресов породила NAT и интерес к IPv6.

## Дополнение: практика и нюансы

Проверка: адрес + маска + gateway + DNS — четыре поля, которые должны быть согласованы.

Широковещание в больших L2 доменах дорого. Режьте сегменты.

CGNAT у провайдеров ломает входящие соединения ещё сильнее обычного NAT.

Обратный DNS (PTR) не всегда настроен — не стройте на нём жёсткую безопасность.


Убедитесь, что клиентский таймаут больше, чем худший RTT + handshake + обработка.

Разделите метрики ошибок транспорта и прикладных 4xx/5xx — это разные классы проблем.
