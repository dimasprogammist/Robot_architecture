# DHCP — автоматическая настройка хоста

## Цель

Понять, какую проблему решает DHCP, как проходит обмен DORA и какие параметры хост получает вместе с адресом.

## Исходные знания

IPv4-подсети, шлюз, DNS-резолвер. Идея широковещания в LAN.

## Объяснение

### Проблема

Вручную прописывать IP, маску, шлюз и DNS на каждом устройстве масштабируется плохо: конфликты адресов, ошибки маски, устаревшие записи.

### Зачем протокол

DHCP позволяет клиенту получить конфигурацию с сервера аренды адресов. Администратор управляет пулом централизованно, клиент получает lease на время.

### Принцип

Клиент без адреса использует широковещание. Сервер предлагает адрес и параметры. Клиент запрашивает предложенное, сервер подтверждает. Аренда обновляется до истечения.

### Структура сообщения своими словами

Сообщение DHCP (поверх UDP, обычно 67/68) несёт: поля для MAC клиента, предложенного IP, сервера, опции. Опции кодируют маску, router (шлюз), DNS, имя хоста, время аренды и многое другое. Важны не все байты заголовка наизусть, а идея «адрес + опции конфигурации».

### Ход обмена (DORA)

1) Discover — клиент ищет серверы. 2) Offer — сервер предлагает. 3) Request — клиент просит конкретное предложение. 4) Ack — сервер подтверждает аренду. Далее клиент настраивает интерфейс. Продление — Request/Ack к серверу аренды.

### Ошибки

Нет сервера — часто self-assigned 169.254/16. Конфликт, если адрес уже занят (проверка ARP). Истёкшая аренда без продления. Неверные опции DNS/шлюза ломают выход в интернет при «живом» IP. Несколько DHCP в одной LAN без согласования — хаос.

## Термины

**Lease** — аренда адреса на время.

**DORA** — Discover/Offer/Request/Ack.

**Пул** — диапазон адресов для выдачи.

**Опции DHCP** — дополнительные параметры конфигурации.

**Reservation** — закрепление адреса за MAC.

## Как это работает

Клиентский демон (NetworkManager, systemd-networkd, dhclient…) ведёт обмен и применяет настройки в ядро (адрес, маршрут, resolv). Статика на интерфейсе DHCP отключает или конфликтует — выбирайте один источник правды.

Для серверов часто делают reservation или чистую статику, чтобы адрес не «уплыл». Для ноутбуков DHCP удобен.

IPv6 часто использует RA/DHCPv6 комбинации — не копируйте слепо только DHCPv4-мышление.

## Пример

```bash
# взгляд на результат DHCP (имена полей зависят от системы)
ip -4 addr
ip route | head
# время аренды смотрят в журнале NetworkManager/systemd-networkd
journalctl -u NetworkManager -n 30 --no-pager 2>/dev/null | head || true
```

```text
Discover (broadcast) → Offer → Request → Ack (lease + mask + gw + DNS)
```

## Разбор

После успешного DHCP у хоста есть адрес, default via шлюз и nameserver. Логи показывают стадии, если что-то зависло на Discover.

Схема DORA — минимальный каркас для разбора Wireshark-трассировок.

## Ошибки новичков

- Ставить статику тем же адресом, что выдаёт DHCP, без reservation.
- Винить «интернет», когда DHCP не выдал шлюз.
- Держать два конфликтующих DHCP.
- Путать APIPA 169.254 с рабочей конфигурацией.

## Что запомнить

- DHCP автоматизирует IP+маску+шлюз+DNS.
- DORA — базовый обмен аренды.
- Опции так же важны, как сам адрес.
- Lease нужно продлевать.

## Задание

Найдите, кто настроил ваш текущий IPv4: DHCP или статика. Если DHCP — узнайте адрес шлюза и DNS из полученных параметров и сверьте с `ip route` и резолвером.

## Дополнение: практика и нюансы

Reservation по MAC удобны для принтеров/роботов. Документируйте таблицу MAC↔IP.

Option 121 (classless static routes) иногда нужна сложным LAN — проверяйте клиентскую поддержку.

Аренда слишком короткая создаёт лишний трафик; слишком длинная замедляет переезд адреса.

Логи DHCP-сервера — первое место при «не получил адрес».
