# Ошибки в программе

## Цель

Научиться классифицировать ошибки: синтаксические, ошибки выполнения, логические — и выбирать способ их искать. После урока вы будете отличать «программа не запустилась» от «запустилась и тихо считает неверно».

## Что уже пройдено

Вы строите алгоритмы с переменными, ветками, циклами и функциями. Ошибки появляются на любом уровне: от опечатки в имени до неверного условия. Систематический взгляд экономит время отладки.

## Объяснение с нуля

Ошибка — расхождение между намерением и фактическим поведением (или невозможность даже начать выполнение). Удобно делить на три больших класса.

**Синтаксические ошибки.** Текст программы нарушает правила языка: скобка не закрыта, неверное ключевое слово, сломанная структура. Исполнитель часто отказывается запускать программу и указывает место. Это самые «громкие» и обычно самые лёгкие в исправлении ошибки.

**Ошибки выполнения (runtime).** Синтаксис верный, но на конкретных данных шаг невозможен: деление на ноль, доступ к несуществующему элементу, обращение к неинициализированному имени, нехватка памяти. Программа падает или сообщает о сбое в момент операции.

**Логические ошибки.** Программа работает «без падений», но результат неверный: перепутали знак сравнения, неверный инвариант цикла, не та формула. Их сложнее всего ловить, потому что нет красной лампочки — есть тихий неправильный ответ.

Отдельно стоят ошибки окружения: нет файла, нет прав, устройство отключено. Для алгоритма это тоже входные ситуации, которые нужно предусматривать, а не считать «нечестными».

Стратегия поиска: воспроизвести на минимальном примере; проверить вход; пройти шаги с таблицей состояния; посмотреть сообщения и стек вызовов; добавить временные проверки утверждений (assert) на инварианты. Менять всё подряд наугад — антистратегия.

Профилактика: понятные имена, маленькие функции, явная обработка крайних случаев, тесты на типовые и граничные входы. Ошибка, пойманная на этапе мыслительного прогона, дешевле ошибки на роботе в поле.

Порядок починки обычно такой: сначала синтаксис (иначе нет запуска), потом падения на данных, потом сверка смысла с ожиданием.

## Термины

- **Синтаксическая ошибка** — нарушение формы языка.
- **Ошибка выполнения** — сбой во время работы на данных.
- **Логическая ошибка** — неверная идея при «успешном» запуске.
- **Отладка (debugging)** — поиск и устранение причин неверного поведения.
- **Воспроизведение** — способность снова вызвать ту же ошибку контролируемо.
- **Утверждение (assert)** — проверка «здесь должно быть истинно», иначе сигнал тревоги.

## Внутреннее устройство

Сообщения об ошибках часто содержат: тип проблемы, текст, файл, строку, стек вызовов. Стек показывает цепочку функций до места сбоя — читайте его последовательно, не игнорируйте.

Интерпретаторы ловят синтаксис при разборе. Компиляторы — на этапе компиляции; часть семантических проблем тоже. Логику компилятор не знает: он не понимает ваш физический смысл «скорость не может быть отрицательной», пока вы сами не закодируете проверку.

Логирование — запись событий во времени. Для логических ошибок лог значений ключевых переменных часто полезнее, чем только факт «упало». Но логи не заменяют аккуратный прогон на бумаге для маленьких алгоритмов.

В сложных системах вводят коды ошибок, уровни серьёзности, мониторинг. На уровне основ достаточно: не глотать сбой молча, не продолжать управление актуатором после неопределённого состояния.

Минимальный воспроизводимый пример — золотой стандарт: отрежьте лишнее, пока баг остаётся. Так проще понять причину и объяснить её другому.

## Пример

```text
Задумано: среднее списка, пустой список запрещён.

ФУНКЦИЯ average(numbers):
  sum ← 0
  ДЛЯ каждого x в numbers:
    sum ← sum + x
  ВЕРНУТЬ sum / длина(numbers)

Случай A — runtime:
  average([])  → деление на ноль / недопустимая операция

Случай B — логика:
  ФУНКЦИЯ average_bad(numbers):
    ВЕРНУТЬ numbers[0]    # "работает" для непустого, но это не среднее
  average_bad([2, 4, 6]) → 2   # без падения, ответ неверный

Случай C — синтаксис (идея):
  ФУНКЦИЯ average(numbers    # забыли закрыть объявление
    ...

Защита:
  ЕСЛИ длина(numbers) == 0:
    СООБЩИТЬ ошибку входа и ОСТАНОВИТЬСЯ
```

## Разбор

Случай A — классическая ошибка выполнения: формула предполагает ненулевую длину, а вход это нарушает. Исправление — проверка предусловия.

Случай B страшнее для доверия: тесты «программа не упала» пройдут, численный смысл — нет. Нужны тесты на ожидаемое значение, а не только на отсутствие сбоя.

Случай C не даст даже начать: сначала чинят форму текста. Новички иногда чинят логику, когда программа ещё не парсится — порядок должен быть: синтаксис → запуск → проверка смысла.

Один и тот же симптом «неверный ответ» может иметь разные корни: сначала классифицируйте, потом лечите.

## Ошибки

- Игнорировать текст сообщения и стек, правя «рядом наугад».
- Считать отсутствие падения доказательством правильности.
- Не уметь воспроизвести баг и пытаться чинить по памяти.
- Глотать ошибки пустым обработчиком «чтобы не падало».
- Менять несколько мест сразу и не знать, что помогло.

## Что запомнить

Синтаксис мешает запустить; runtime валит на данных; логика врёт молча. Воспроизведение и минимальный пример — основа отладки. Стек вызовов указывает путь. Предусловия и тесты ловят классы ошибок раньше. Тишина после сбоя хуже явного сообщения.

## Задание

Для функции `clamp(value, low, high)` перечислите по одной потенциальной ошибке каждого класса (синтаксис / runtime / логика). Для логической опишите конкретный вход и неверный выход, который вы бы поймали тестом.
