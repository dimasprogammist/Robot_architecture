# Операторы

## Цель

Разобрать основные классы операторов: арифметические, сравнения, логические, присваивания. После урока вы будете выбирать оператор осознанно и понимать разницу между «равно как присвоить», «равно как сравнить» и «логически соединить».

## Что уже пройдено

Выражения состоят из операндов и операторов. Тип значений подсказывает, какие операторы допустимы. Сейчас соберём «азбуку» операторов, без которой невозможны ветвления и циклы.

## Объяснение с нуля

Оператор — правило, которое из одного или нескольких значений делает другое (или меняет состояние). По количеству операндов бывают унарные (`не ready`, `-x`) и бинарные (`a + b`, `x > y`).

**Арифметика:** сложение, вычитание, умножение, деление, остаток от деления, иногда возведение в степень. Для целых и вещественных правила деления могут отличаться: целочисленное деление отбрасывает дробную часть. Остаток (`mod`) полезен для цикличности: «каждый 10-й элемент», «чередование».

**Сравнение:** `>`, `<`, `>=`, `<=`, `==` (равно), `!=` (не равно). Результат — логический. Сравнивать имеет смысл однородное: числа с числами, строки со строками по правилам языка. Сравнение вещественных «на точное равенство» часто плохая идея из-за погрешности — лучше порог близости.

**Логика:** `И`, `ИЛИ`, `НЕ`. Таблицы истинности стоит помнить наизусть на уровне привычки: `И` истинно только если оба истинны; `ИЛИ` — если хотя бы один; `НЕ` переворачивает. В условиях сложные правила безопасности часто строятся именно так: «датчик ок И скорость в диапазоне И НЕ аварийный стоп».

**Присваивание:** оператор, который записывает значение в переменную. Составные формы (`←+`, `+=`) означают «взять старое, изменить, записать». Это удобно для счётчиков, но в уме всегда разворачивайте в полное присваивание.

Операторы не существуют в вакууме: у них приоритет. Обычно арифметика связывается сильнее сравнений, сравнения — сильнее логики, присваивание — «слабее» почти всего. Сомневаетесь — ставьте скобки.

Один и тот же символ иногда значит разное для разных типов: `+` для чисел — сумма, для строк — склейка. Смотрите на типы операндов, а не только на картинку символа.

## Термины

- **Арифметический оператор** — операция над числами.
- **Оператор сравнения** — проверка отношения; результат логический.
- **Логический оператор** — комбинация истинности.
- **Унарный / бинарный** — один или два операнда.
- **Остаток (modulo)** — то, что остаётся после целочисленного деления.
- **Короткое замыкание** — пропуск правого операнда, если результат уже ясен.

## Внутреннее устройство

Процессор умеет аппаратные операции: сложить, сравнить, перейти. Логические выражения часто компилируются в цепочки условных переходов, а не в «магический бит ИЛИ». Поэтому порядок операндов в `И`/`ИЛИ` может влиять и на корректность (если есть побочные эффекты), и на скорость (сначала дешёвая проверка).

Деление на ноль — типичный аппаратный или языковой сбой. Перед делением алгоритм должен гарантировать ненулевой делитель или обрабатывать ошибку. Остаток от деления на ноль — та же семья проблем.

Для строк оператор `+` часто означает конкатенацию. Это другой смысл, чем у чисел, хотя символ тот же. Перегрузка операторов (один символ — разные действия для разных типов) удобна, но требует внимательности к типам операндов.

Сравнение структур и объектов может быть «по содержимому» или «по личности/ссылке». На вводном уровне сравнивайте простые значения; для составных данных явно решайте, что значит «равны».

В языке может быть отдельный оператор тождества («это тот же объект?») рядом с равенством по значению — позже это станет важно для объектов.

## Пример

```text
x ← 17
y ← 5

Арифметика:
  x + y   → 22
  x - y   → 12
  x * y   → 85
  x / y   → 3.4     # вещественное деление (как идея)
  x div y → 3       # целочисленное
  x mod y → 2       # 17 = 3*5 + 2

Сравнение и логика:
  (x > y) И (x mod y == 2)  → true И true → true
  НЕ (y == 0)               → true

Присваивание со счётчиком:
  n ← 0
  n ← n + 1                 # теперь n = 1

# Python-иллюстрация:
x, y = 17, 5
print(x % y, (x > y) and (x % y == 2))
```

## Разбор

`mod` показывает цикличную природу: остаток всегда меньше делителя (для положительных чисел в привычной школьной модели). Это база для «каждого N-го» шага без отдельного счётчика событий.

Логическое выражение сначала получает два сравнения, затем комбинирует. Если бы мы написали `y == 0` без отрицания в знаменателе другой формулы, алгоритм мог бы упасть. Операторы — крошечные, но от них зависит безопасность шага.

Присваивание `n ← n + 1` — не математическое тождество, а изменение состояния. После него старое значение потеряно, если вы его заранее не сохранили.

Составьте мысленно таблицу истинности для `(battery_ok И sensor_ok) ИЛИ emergency_stop == false` — и вы увидите, почему скобки и имена флагов важнее «сжатости в одну строку».

## Ошибки

- Путать `=` присваивания с `==` сравнения (в языках, где оба символа есть).
- Делить или брать остаток при нулевом делителе.
- Писать `a И b ИЛИ c` без скобок и получать не тот смысл.
- Сравнивать вещественные числа на точное равенство без допуска.
- Ожидать от `+` для строк арифметику или наоборот.

## Что запомнить

Операторы — правила комбинирования значений. Арифметика, сравнение, логика и присваивание — разные семьи. Приоритет и скобки задают смысл. Короткое замыкание и деление на ноль — практические ловушки. Один символ может значить разное для разных типов.
