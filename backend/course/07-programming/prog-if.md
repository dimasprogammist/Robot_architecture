# Ветвление

## Цель

Научиться управлять потоком выполнения через условия: если условие истинно — один путь, иначе — другой. После урока вы сможете строить безопасные развилки и избегать «лапши» из вложенных проверок без структуры.

## Что уже пройдено

Логические выражения дают истину или ложь. Ветвление использует этот ответ, чтобы выбрать следующую группу шагов. Без ветвления программа всегда шла бы одной дорогой и не могла реагировать на разные входы.

## Объяснение с нуля

Ветвление (условный оператор) — базовая конструкция алгоритмов. Форма:

```text
ЕСЛИ условие:
  шаги A
ИНАЧЕ:
  шаги B
```

Условие вычисляется один раз в точке развилки (если вы сами не вложили сюда сложную логику с побочными эффектами). Затем выполняется ровно одна ветка — A или B. Иногда ветки `ИНАЧЕ` нет: при ложном условии просто ничего дополнительного не делается.

Цепочка `ЕСЛИ / ИНАЧЕ ЕСЛИ / ИНАЧЕ` нужна, когда вариантов больше двух, но они взаимоисключающие: выбрать ровно одну категорию. Если условия не исключают друг друга, порядок проверок становится частью смысла: первое сработавшее побеждает.

Вложенные `если` допустимы, но быстро ухудшают читаемость. Часто лучше: вычислить понятные флаги заранее, использовать ранний выход («если плохо — сообщить и остановиться»), разбить на функции. Цель — чтобы человек видел решение, а не лабиринт.

Ветвление — не «магия интеллекта». Это явный перечень ситуаций, которые вы предусмотрели. Всё, что не попало в условия, уйдёт в `ИНАЧЕ` или останется без обработки. Проектируя развилку, спросите: какие случаи обязательны? что делать с неожиданным?

В инженерии ветвления часто кодируют политики безопасности: «если авария — стоп», «если батарея низкая — ограничить мощность», «если данных нет — не управлять актуатором». Ошибка в условии здесь дороже синтаксической опечатки.

Таблицы решений помогают: строки — комбинации условий, столбцы — действия. Если таблица неполная, алгоритм дырявый.

## Термины

- **Условие** — логическое выражение в точке выбора.
- **Ветка** — набор шагов, выбранный по результату условия.
- **Иначе (else)** — путь при ложном условии.
- **Иначе-если (else if / elif)** — следующая проверка в цепочке.
- **Поток управления** — порядок, в котором выполняются шаги.
- **Ранний выход** — немедленное завершение ветки/функции при нарушении предусловия.

## Внутреннее устройство

На уровне машинного кода ветвление — сравнение и условный переход по адресу. Предсказатель переходов процессора пытается угадать, какая ветка вероятнее; для программиста это деталь производительности, не логики.

Важно, что невыполняемая ветка **не выполняется**: ошибки внутри неё не проявятся, пока условие не выберет этот путь. Поэтому тестировать нужно все осмысленные ветки, а не один «счастливый» сценарий.

Каскад условий компилируется в цепочку переходов. Чем понятнее взаимоисключение случаев, тем проще доказать, что покрытие полное. Иногда вместо длинной цепочки лучше таблица решений или словарь действий — но идея та же: отобразить ситуацию на поведение.

Состояние переменных до и после ветки может различаться. Хорошая привычка: для каждой ветки выписывать, какие переменные обязаны быть установлены. Иначе одна ветка забудет инициализировать то, что другая ветка потом читает.

Вложенность глубиной больше двух-трёх уровней — сигнал пересмотреть дизайн: флаги, функции, ранние выходы.

## Пример

```text
Алгоритм ограничения скорости:

battery ← ...      # процент
cmd_speed ← ...    # запрошенная скорость
max_speed ← 1.0

ЕСЛИ battery < 15:
  max_speed ← 0.2
ИНАЧЕ ЕСЛИ battery < 30:
  max_speed ← 0.5
ИНАЧЕ:
  max_speed ← 1.0

ЕСЛИ cmd_speed > max_speed:
  out_speed ← max_speed
ИНАЧЕ:
  out_speed ← cmd_speed

# Python-иллюстрация:
battery = 22
cmd_speed = 0.8
if battery < 15:
    max_speed = 0.2
elif battery < 30:
    max_speed = 0.5
else:
    max_speed = 1.0
out_speed = max_speed if cmd_speed > max_speed else cmd_speed
```

## Разбор

Первая цепочка выбирает лимит по батарее. Порядок важен: сначала проверяем самый жёсткий порог `< 15`. Если поставить `< 30` первым, низкая батарея могла бы попасть не в ту категорию.

Вторая развилка уже не про батарею, а про сравнение команды с лимитом. Разделение двух решений делает алгоритм читаемее, чем одно гигантское условие со всеми комбинациями.

Для `battery = 22` и `cmd_speed = 0.8` получим `max_speed = 0.5`, затем `out_speed = 0.5`. Это предсказуемо и проверяемо таблицей случаев.

Добавьте в уме случай `battery = 10`: лимит 0.2, любая большая команда будет урезана. Так политики безопасности становятся проверяемыми, а не «интуитивными».

## Ошибки

- Писать пересекающиеся условия и надеяться на «очевидный» порядок.
- Забывать ветку для неожиданных значений.
- Вкладывать пять уровней `если` вместо флагов и ранних выходов.
- Менять в условии переменные с побочным эффектом так, что повторный взгляд на код врёт.
- Тестировать только одну ветку и считать программу готовой.

## Что запомнить

Ветвление выбирает путь по логическому условию. Цепочки `иначе-если` требуют продуманного порядка. Невыполненная ветка не исполняется — её нужно тестировать отдельно. Политики безопасности часто кодируются именно развилками. Читаемость важнее «компактности в одну строку».

## Задание

Составьте алгоритм выставления режима робота: `stop`, `crawl`, `normal` по правилам: авария → stop; иначе батарея < 10 → stop; иначе батарея < 25 → crawl; иначе normal. Прогоните вручную для четырёх комбинаций входов и запишите результаты.
