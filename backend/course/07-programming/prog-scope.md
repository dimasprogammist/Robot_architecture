# Область видимости

## Цель

Понять, где имя переменной «видно» и как долго оно живёт: локальные имена внутри функции, внешние на уровне модуля, перекрытия имён. После урока вы перестанете случайно читать и писать не ту переменную.

## Что уже пройдено

Функции имеют параметры и локальные вычисления, возвращают результат. Область видимости объясняет, почему имена внутри функции не конфликтуют автоматически с именами снаружи и когда конфликт всё же возникает.

## Объяснение с нуля

Область видимости (scope) — часть программы, в которой имя имеет смысл. Переменная, созданная внутри функции, обычно **локальна**: снаружи её не видно, и после выхода из функции она исчезает. Параметры — тоже локальные имена кадра вызова.

Глобальные (или модульные) переменные видны шире: из нескольких функций. Это удобно для настроек и констант, но опасно для изменяемого состояния: любая функция может незаметно поменять «общее». Чем больше глобалов, тем сложнее понять, кто испортил значение.

Перекрытие имён (shadowing): если внутри функции есть локальная `x`, а снаружи тоже `x`, то внутри имя обычно относится к локальной. Внешняя при этом не исчезает, но из тела функции «прячется» за одноимённой локальной. Читать такой код тяжело — лучше не называть по-разному вещи одинаково без нужды.

Блочная область видимости в некоторых языках ограничивает переменные цикла или ветки ещё сильнее: `i` цикла не торчит наружу. В других языках правила мягче. Смысл обучения: **не предполагайте**, что имя живёт «везде»; проверяйте правила языка и пишите явно.

Замыкания и вложенные функции — продвинутая тема: внутренняя функция может видеть имена окружающей. Пока достаточно модели уровней: локально → объемлющая функция → модуль → глобально (конкретная цепочка зависит от языка).

Практическое правило новичка: передавайте данные аргументами и возвратом; глобалы оставляйте для настоящих констант и редких точек конфигурации.

Время жизни и видимость связаны, но не тождественны: имя может быть не видно, а данные ещё жить (или наоборот — в сложных моделях ссылок). На старте держите связку «локальное имя живёт с кадром вызова».

## Термины

- **Область видимости** — зона, где имя разрешено использовать.
- **Локальная переменная** — живёт в кадре функции/блока.
- **Глобальная / модульная переменная** — доступна шире одного вызова.
- **Время жизни** — период, пока переменная существует в памяти.
- **Перекрытие (shadowing)** — локальное имя скрывает внешнее с тем же идентификатором.
- **Пространство имён** — словарь имён в контексте (модуль, объект, функция).

## Внутреннее устройство

Локальные переменные размещаются в стековом кадре вызова: пришли — выделили, ушли — освободили (в типичной модели). Глобальные живут дольше — в области данных программы/модуля.

Поиск имени при выполнении или компиляции идёт по цепочке областей: нашли локально — взяли; иначе ищем выше. Если нигде нет — ошибка «имя не определено».

Запись в глобальную переменную из функции во многих языках требует явного указания, иначе создаётся локальная. Это защита от случайной порчи общего состояния — и частый источник сюрпризов у новичков.

Потоки и асинхронность позже усложнят картину: общее изменяемое состояние нужно синхронизировать. Уже сейчас минимизация общих записей — правильная привычка.

Модули добавляют ещё один уровень пространств имён: одноимённые функции в разных модулях не сталкиваются, пока вы не импортируете их в одно место без префикса.

## Пример

```text
scale ← 2.0          # модульный уровень

ФУНКЦИЯ stretch(x):
  factor ← 1.5       # локальная
  ВЕРНУТЬ x * factor * scale

ФУНКЦИЯ broken():
  x ← 10
  ФУНКЦИЯ inner():
    # идея: inner видит x объемлющей broken в языках с замыканиями
    ВЕРНУТЬ x + 1
  ВЕРНУТЬ inner()

a ← stretch(4)       # использует scale=2 и factor=1.5 → 12
# print(factor)      # ошибка: factor снаружи не существует

ФУНКЦИЯ confuse(x):
  # параметр x перекрывает внешние x, если они есть
  ВЕРНУТЬ x

# Python-иллюстрация:
scale = 2.0
def stretch(x):
    factor = 1.5
    return x * factor * scale
```

## Разбор

`factor` существует только во время вызова `stretch`. Попытка прочитать его снаружи должна провалиться — так язык защищает инкапсуляцию деталей.

`scale` читается внутри функции как внешнее имя. Если кто-то изменит `scale` между вызовами, поведение `stretch` изменится без изменения аргументов — вот цена глобального состояния. Для предсказуемости лучше передать `scale` аргументом.

`confuse(x)` показывает, что параметр — отдельная привязка. Даже если снаружи есть другое `x`, внутри функции имя указывает на аргумент.

Тест «могу ли я объяснить, откуда взялось каждое имя в этой строке?» — быстрый способ найти дыры в понимании scope.

## Ошибки

- Ожидать, что локальная переменная доступна после функции.
- Молча менять глобалы из глубоких вызовов.
- Называть локальные и глобальные сущности одинаково и терять час на отладке.
- Считать, что «переменная цикла» автоматически видна/не видна одинаково во всех языках.
- Лечить нехватку возврата глобальной переменной «на выход».

## Что запомнить

Имя видно только в своей области. Локальные живут с кадром вызова. Глобалы удобны и опасны. Перекрытие имён путает чтение. Аргументы и возврат — главный чистый канал данных. Время жизни и видимость — связанные, но не тождественные понятия.
