# Функции

## Цель

Научиться выделять именованные блоки шагов — функции: объявлять их, вызывать и понимать, зачем дробить программу на части. После урока вы сможете объяснить вызов как «перейти к подпрограмме и вернуться», а не как магическое слово языка.

## Что уже пройдено

Вы собираете алгоритмы из присваиваний, выражений, ветвлений и циклов. Когда один и тот же фрагмент повторяется или логически автономен («посчитать среднее», «проверить лимит»), его оформляют функцией.

## Объяснение с нуля

Функция — именованный алгоритм с чёткой границей: на входе параметры (об этом подробнее в следующем уроке), внутри — шаги, снаружи — вызов по имени. Идея старше любого современного языка: подпрограмма позволяет не копировать код и мыслить уровнями абстракции.

Объявление говорит: «существует действие `normalize_speed`». Вызов говорит: «выполни его сейчас». Пока функция не вызвана, её тело не выполняется — как невыполненная ветка `если`.

Зачем функции:

1. **Повторное использование** — один раз написали, вызываем в разных местах.
2. **Читаемость** — верхний уровень читается как план из глаголов.
3. **Изоляция** — детали спрятаны; менять реализацию можно, сохраняя смысл имени.
4. **Проверка** — маленькую функцию проще тестировать, чем монолит.

Функция без возврата значения всё равно полезна: она может печатать, менять внешнее состояние, отправлять команду. Но чем меньше скрытых эффектов, тем проще рассуждать. Идеал обучения: функция вычисляет результат и возвращает его; побочные эффекты — осознанно и явно.

Имена функций — глаголы или глагольные фразы: `calculate_average`, `clamp`, `is_valid`. Если имя — существительное без действия, часто это сигнал, что граница ответственности размыта.

Слишком мелкая нарезка тоже вредна: функция из одной очевидной строки без смысла имени создаёт шум. Слишком крупная — прячет роман в одной процедуре. Ориентир: одна функция — одна понятная обязанность.

Порядок чтения программы не равен порядку выполнения: объявления могут быть выше, вызовы — ниже, а реально тело побежит только в момент вызова.

## Термины

- **Функция / процедура** — именованный блок шагов (процедурой иногда зовут вариант без возврата).
- **Объявление** — описание имени и тела.
- **Вызов** — запуск тела функции в точке программы.
- **Параметр** — имя входа внутри функции.
- **Аргумент** — конкретное значение, переданное при вызове.
- **Абстракция** — скрытие деталей за понятным именем.

## Внутреннее устройство

При вызове среда исполнения обычно кладёт на **стек вызовов** кадр: адрес возврата, локальные переменные, аргументы. Затем управление переходит к телу. По завершении кадр снимается, выполнение возвращается к месту вызова.

Рекурсия — вызов функцией самой себя — тоже использует стек; слишком глубокая рекурсия переполняет его. На вводном уровне достаточно знать, что каждый незавершённый вызов занимает место.

Компиляторы могут подставлять простые функции прямо в место вызова (inlining) ради скорости, но логическая модель для человека остаётся: именованный блок с границей.

Отладка идёт по стеку вызовов: «кто кого вызвал». Сообщение об ошибке часто показывает эту цепочку — читайте её, а не только последнюю строку.

Функции помогают держать инварианты: на входе проверили предусловия, на выходе — постусловия. Это мост к теме ошибок и исключений.

## Пример

```text
Объявление:
  ФУНКЦИЯ clamp(value, low, high):
    ЕСЛИ value < low:
      ВЕРНУТЬ low
    ЕСЛИ value > high:
      ВЕРНУТЬ high
    ВЕРНУТЬ value

Использование в алгоритме:
  cmd ← 1.4
  safe ← clamp(cmd, 0.0, 1.0)   # safe = 1.0
  print(safe)

# Python-иллюстрация:
def clamp(value, low, high):
    if value < low:
        return low
    if value > high:
        return high
    return value

safe = clamp(1.4, 0.0, 1.0)
```

## Разбор

`clamp` прячет три ветки проверки за одним именем. В месте вызова читается намерение: «ограничить команду», а не «ещё одна портянка условий». Те же правила можно вызвать для скорости, тока, угла — без копирования.

Функция не знает, откуда взялся `cmd`: ей важны только аргументы. Это свойство делает её переносимой. Возврат значения (урок скоро углубит тему) позволяет записать результат в `safe` и использовать дальше.

Если бы ограничение было встроено копипастой в десяти местах, исправление порога пришлось бы делать десять раз — классическая цена отсутствия функций.

Имя `clamp` честно описывает поведение. Если бы функция ещё писала в лог и меняла глобальный режим, имя уже врало бы.

## Ошибки

- Копировать один и тот же блок вместо выноса функции.
- Давать функции имя, которое врёт о поведении.
- Делать функцию, которая «и считает, и пишет файл, и шлёт сеть» без необходимости.
- Путать объявление с вызовом: «написал объявление — значит уже выполнилось».
- Бояться коротких функций там, где имя действительно улучшает ясность.

## Что запомнить

Функция — именованный переиспользуемый блок шагов. Вызов создаёт кадр на стеке и возвращает управление обратно. Хорошая функция имеет одну обязанность и честное имя. Абстракция позволяет читать программу сверху вниз как план. Параметры и возврат связывают функцию с остальным кодом.
