# Переменная

## Цель

Понять переменную как именованную ячейку состояния программы: в неё можно положить значение, потом прочитать или заменить. После урока вы сможете объяснять, чем имя отличается от значения и почему «переменная изменилась» — нормальный механизм, а не поломка.

## Что уже пройдено

Вы умеете описывать алгоритм шагами и понимаете, что программе нужно где-то держать промежуточные результаты: текущий максимум, счётчик, флаг «нашли / не нашли». Переменная — основной инструмент для этого хранения.

## Объяснение с нуля

Переменная — это **имя**, связанное с **значением** в памяти во время выполнения. Имя выбираете вы: `speed`, `count`, `user_name`. Значение может быть числом, текстом, истиной/ложью, ссылкой на структуру — об этом в следующем уроке про типы.

Аналогия с коробкой полезна, но неполная. Коробка хранит вещь; переменная в языках часто хранит либо само значение (для простых чисел), либо ссылку на данные. Пока достаточно модели: по имени программа находит, **что сейчас лежит** под этим ярлыком.

Важнейшая операция — **присваивание**: связать имя с новым значением. Запись вроде `x ← 10` или `x = 10` означает: отныне имя `x` обозначает `10` (в рамках правил языка). Позже `x ← x + 1` читает старое значение, увеличивает и записывает новое. Это не уравнение из алгебры: слева — куда писать, справа — что вычислить.

Переменная существует во времени. До первого присваивания обращение к ней часто ошибка. После присваивания значение живёт, пока его не изменят или пока переменная не исчезнет вместе с областью видимости (об этом отдельный урок).

Имена важны для людей. `a1`, `tmp2`, `data` в десяти местах делают алгоритм непрозрачным. `retry_count`, `battery_percent`, `is_ready` помогают читать код как текст. Машина принимает почти любые допустимые имена; смысл создаёте вы.

Константа — родственная идея: имя, значение которого по смыслу не должны менять. В разных языках константы оформляют по-разному, но мысль одна: есть значения-параметры («лимит попыток = 3»), которые лучше не путать с рабочим счётчиком попыток.

Одна переменная — один смысл. Если в одной ячейке то флаг, то счётчик, то «код ошибки», отладка превращается в археологию.

## Термины

- **Переменная** — именованная привязка к значению в состоянии программы.
- **Присваивание** — установка (или смена) значения переменной.
- **Инициализация** — первое осмысленное присваивание.
- **Имя (идентификатор)** — как к переменной обращаются в тексте.
- **Значение** — конкретные данные, связанные с именем сейчас.
- **Константа** — имя для значения, которое не предполагается менять.

## Внутреннее устройство

На уровне машины у значения есть место в памяти: адрес, размер, представление в байтах. Язык и среда решают, где именно жить переменной: в регистре, на стеке, в куче. Вам на старте достаточно знать: **чтение** берёт текущее значение, **запись** заменяет его.

Когда вы пишете `y = x`, происходит не «слияние имён», а копирование значения (или копирование ссылки — зависит от типа и языка). После этого `x` и `y` могут жить независимыми жизнями, если значения независимы. Путаница «я изменил x, почему изменился y» почти всегда связана с разделяемыми данными — к этому вернёмся в структурах.

Объявление переменной в некоторых языках отделено от присваивания: сначала говорят «будет число `count`», потом дают значение. В других языках первая запись создаёт привязку. Смысл один: среда должна знать, что имя существует и чем его можно заполнять.

Отладка часто сводится к вопросу: «какое значение у переменной в этой точке?» Логи, точки останова, печать — способы увидеть состояние. Если вы не можете назвать ожидаемые значения переменных на шаге алгоритма, вы ещё не контролируете программу.

Таблица состояния на бумаге — тот же навык без отладчика: после каждого шага выписываете `sum`, `count`, флаги.

## Пример

```text
Алгоритм: посчитать сумму чисел списка.

sum ← 0
count ← 0
ДЛЯ каждого x в списке:
  sum ← sum + x
  count ← count + 1
average ← sum / count   # если count > 0

Состояние после списка [2, 3, 5]:
  sum = 10
  count = 3
  average = 3.333...

# крошечный Python-фрагмент:
sum = 0
count = 0
for x in [2, 3, 5]:
    sum = sum + x
    count = count + 1
```

## Разбор

`sum` и `count` — рабочие переменные. Их начальные значения не случайны: сумма пустого набора — 0, количество — 0. Если начать `sum` с первого элемента, алгоритм изменится (как с поиском максимума).

Строка `sum ← sum + x` читается так: взять старое `sum`, прибавить `x`, записать обратно. Без чтения справа присваивание бессмысленно. Имя `average` появляется позже — это нормально: переменную вводят, когда она нужна.

Прогон «на бумаге» показывает таблицу состояния после каждого шага. Такой приём ловит ошибки до запуска: забыли увеличить `count`, делите на ноль, перепутали порядок.

Заметьте: имя `x` в цикле каждый раз обозначает другой элемент, но это всё ещё переменная — ярлык текущего значения на этой итерации.

## Ошибки

- Использовать переменную до инициализации.
- Давать имена, которые ничего не говорят о роли.
- Путать присваивание с сравнением («равны ли?») — в языках это разные операции.
- Думать, что переменная «помнит историю»: обычно доступно только текущее значение.
- Хранить в одной переменной смыслы разной природы без необходимости (`flag_or_count`).

## Что запомнить

Переменная — имя текущего значения. Присваивание меняет состояние. Инициализация должна быть явной и осмысленной. Хорошие имена — часть ясности алгоритма. Отладка начинается с вопроса о значениях в точке выполнения.

## Задание

Для алгоритма «найти минимум и его позицию в списке» выпишите все нужные переменные, их смысл и начальные значения. Затем заполните таблицу состояния для входа `[7, 2, 2, 5]` после каждого элемента.
