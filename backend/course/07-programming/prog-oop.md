# Объекты и классы (введение)

## Цель

Получить рабочее введение в объекты: класс как чертёж, объект как экземпляр с состоянием и поведением. После урока вы сможете объяснить инкапсуляцию простыми словами и не считать ООП обязательным для каждой задачи.

## Что уже пройдено

Структуры данных хранят поля; функции работают с этими данными. Объектный подход предлагает держать **данные и операции рядом**, под общим типом. Это не отменяет функции и модули — добавляет ещё один способ проводить границы.

## Объяснение с нуля

**Класс** — описание вида вещей: какие поля состояния есть и какие действия допустимы. **Объект (экземпляр)** — конкретная вещь этого вида со своими значениями полей.

Аналогия: класс «Счетчик»; объекты — счётчик попыток входа и счётчик кадров камеры. У обоих есть операции `inc` и `reset`, но числа внутри разные.

Зачем это:

1. **Инкапсуляция** — детали спрятаны; снаружи видны понятные действия.
2. **Связность** — состояние не расползается по десятку глобальных переменных.
3. **Много экземпляров** — один код класса обслуживает много объектов.

Метод — функция, связанная с объектом: она обычно видит состояние этого экземпляра. Вызов `motor.set_speed(0.3)` читается как «попросить мотор установить скорость».

Конструктор / инициализатор задаёт начальное состояние объекта при создании. Без осмысленной инициализации объект легко рождается «пустым и опасным».

Наследование и полиморфизм — следующие этажи ООП: общий базовый интерфейс, разные реализации. На введении достаточно идеи: разные объекты могут отвечать на одно и то же сообщение (`update`) по-своему. Не стройте глубокие иерархии «на вырост» — чаще вредно, чем полезно.

ООП — не религия. Для короткого скрипта преобразования файла достаточно функций. Для системы с многими сущностями и долгим состоянием объекты часто удобны. Выбор стиля — прагматика.

Композиция («объект содержит другой объект») часто проще и яснее глубокого наследования. Мотор содержит счётчик ошибок — понятнее, чем «мотор есть вид счётчика».

## Термины

- **Класс** — тип-чертёж объектов.
- **Объект / экземпляр** — конкретная сущность класса.
- **Поле / атрибут** — данное в состоянии объекта.
- **Метод** — операция, связанная с объектом.
- **Инкапсуляция** — скрытие внутренностей за интерфейсом.
- **Интерфейс объекта** — набор публичных методов и смысл их вызовов.

## Внутреннее устройство

Объект в памяти — блок состояния (поля) плюс связь с информацией о типе/методах. Вызов метода — по сути вызов функции, которой неявно передали «этот объект» (часто под именем `self`/`this`).

Много объектов одного класса разделяют код методов, но не поля: у каждого своё состояние. Это экономит дублирование логики.

Ссылки: переменная часто хранит не «сам объект целиком в себе», а ссылку на него. Присваивание `b ← a` для объектов обычно означает «оба имени смотрят на один экземпляр», пока не создадите новый. Отсюда сюрпризы разделяемого состояния — те же, что у структур.

Уничтожение объектов: в языках со сборкой мусора недоступные объекты освобождаются автоматически; в других — нужно явное управление временем жизни. На введении важно не держать ненужные ссылки на тяжёлые ресурсы (файлы, соединения) без закрытия.

Класс сам по себе лежит в пространстве имён модуля; объекты создаются во время выполнения. Путать «правка класса» с «правка одного экземпляра» — частая ментальная ошибка.

## Пример

```text
КЛАСС Counter:
  ПОЛЯ:
    value
  МЕТОД init(start=0):
    value ← start
  МЕТОД inc():
    value ← value + 1
  МЕТОД get():
    ВЕРНУТЬ value
  МЕТОД reset():
    value ← 0

Использование:
  frames ← Counter.init(0)
  errors ← Counter.init(0)
  frames.inc()
  frames.inc()
  ЕСЛИ sensor_fail:
    errors.inc()
  print(frames.get(), errors.get())   # 2 и, возможно, 1

# Python-иллюстрация:
class Counter:
    def __init__(self, start=0):
        self.value = start
    def inc(self):
        self.value += 1
    def get(self):
        return self.value
```

## Разбор

Два счётчика независимы: увеличение `frames` не трогает `errors`. Без классов пришлось бы помнить две переменные и набор функций, которые легко вызвать не для тех данных.

Методы `inc`/`get`/`reset` образуют маленький интерфейс. Снаружи не обязательно знать, что поле называется `value` — достаточно действий. Позже вы можете сменить хранение (например, ограничить максимум) и сохранить те же методы.

`init` гарантирует стартовое состояние. Создать «пустой» объект без `value` и сразу вызвать `inc` было бы ошибкой использования — конструктор закрывает эту дыру.

Инвариант «value никогда не отрицателен» можно поддерживать внутри методов — ещё один плюс инкапсуляции.

## Ошибки

- Делать класс «на всё сразу» с десятками несвязанных обязанностей.
- Путать класс и объект: менять «чертёж» вместо экземпляра в уме.
- Раскрывать все поля публично и дублировать проверки повсюду.
- Строить глубокое наследование вместо простой композиции.
- Считать, что без ООП «не настоящее программирование».

## Что запомнить

Класс описывает, объект существует. Методы работают с состоянием экземпляра. Инкапсуляция снижает хаос глобальных данных. Ссылки на объекты легко разделяют состояние. ООП — инструмент границ, не обязательный стиль для каждой строки. Дальше в курсе языков вы увидите синтаксис классов предметно; здесь важна модель мышления.
