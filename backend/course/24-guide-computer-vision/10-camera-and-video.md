# Камера и видеопоток

## Цель урока

После этого урока вы должны понимать:

* как камера формирует цифровое изображение;
* что такое видеопоток;
* что такое FPS;
* как разрешение влияет на обработку;
* как получить кадры камеры через OpenCV;
* что такое экспозиция и почему она важна;
* почему фокус и освещение влияют на компьютерное зрение;
* почему параметры камеры нужно учитывать ещё до написания алгоритма.

## Камера как источник данных

В компьютерном зрении камера является источником входных данных.

Упрощённая схема:

```text
Сцена
  ↓
Свет
  ↓
Объектив
  ↓
Матрица камеры
  ↓
Цифровой сигнал
  ↓
Изображение
  ↓
Алгоритм компьютерного зрения
```

Поэтому камера — это не просто устройство, которое «делает фотографию».

Она формирует данные, на которых затем работает весь алгоритм.

Если изображение плохого качества, сложный алгоритм не всегда сможет это исправить.

## Что видит камера

Камера получает свет от окружающей сцены.

Свет попадает через объектив на светочувствительную матрицу.

Матрица состоит из большого количества элементов, которые регистрируют интенсивность света.

Затем электроника камеры преобразует полученные сигналы в цифровые значения.

Упрощённо:

```text
Свет
 ↓
Матрица
 ↓
Числа
 ↓
Пиксели
```

Таким образом появляется цифровое изображение.

## Видеопоток

Когда камера работает непрерывно, она выдаёт последовательность кадров:

```text
Кадр 1
   ↓
Кадр 2
   ↓
Кадр 3
   ↓
Кадр 4
   ↓
...
```

Эта последовательность называется видеопотоком.

Компьютерное зрение может обрабатывать каждый кадр отдельно:

```text
frame
  ↓
обработка
  ↓
результат
```

затем:

```text
следующий frame
  ↓
обработка
  ↓
результат
```

## FPS

**FPS (Frames Per Second)** — количество кадров в секунду.

Например:

```text
10 FPS → 10 кадров/с
30 FPS → 30 кадров/с
60 FPS → 60 кадров/с
```

Если камера работает с:

```text
30 FPS
```

это означает, что за одну секунду она может передать примерно 30 кадров.

## Почему FPS важен

Чем выше FPS, тем меньше времени проходит между соседними кадрами.

Например:

```text
30 FPS
```

даёт интервал примерно:

```text
1 / 30 ≈ 0.033 с
```

То есть около 33 миллисекунд.

Для:

```text
60 FPS
```

интервал примерно:

```text
1 / 60 ≈ 0.0167 с
```

или около 17 миллисекунд.

Более высокая частота кадров позволяет лучше наблюдать быстрое движение.

Но она также увеличивает объём данных и нагрузку на систему.

## Разрешение

Разрешение определяет количество пикселей в кадре.

Например:

```text
640 × 480
1280 × 720
1920 × 1080
3840 × 2160
```

Чем выше разрешение:

```text
↑ деталей
↑ данных
↑ нагрузки на обработку
↑ требования к памяти и пропускной способности
```

Поэтому максимальное разрешение не всегда является оптимальным.

## Разрешение и FPS связаны

Камера может поддерживать разные режимы.

Например:

```text
1920 × 1080 → 30 FPS
1280 × 720  → 60 FPS
```

Если задача требует отслеживать быстро движущийся объект, режим с более высоким FPS может оказаться полезнее.

Если требуется очень точно измерять небольшую деталь, может быть важнее разрешение.

Поэтому параметры выбираются исходя из задачи.

## Получение видео через OpenCV

Простейший пример:

```python
import cv2

camera = cv2.VideoCapture(0)

while True:
    ret, frame = camera.read()

    if not ret:
        print("Не удалось получить кадр")
        break

    cv2.imshow("Camera", frame)

    if cv2.waitKey(1) == 27:
        break

camera.release()
cv2.destroyAllWindows()
```

Это базовый видеопоток:

```text
Камера
  ↓
VideoCapture
  ↓
frame
  ↓
imshow
```

## Проверка камеры

После создания объекта камеры полезно проверить:

```python
if not camera.isOpened():
    raise RuntimeError("Не удалось открыть камеру")
```

Полный вариант:

```python
import cv2

camera = cv2.VideoCapture(0)

if not camera.isOpened():
    raise RuntimeError("Не удалось открыть камеру")

while True:
    ret, frame = camera.read()

    if not ret:
        print("Не удалось получить кадр")
        break

    cv2.imshow("Camera", frame)

    if cv2.waitKey(1) == 27:
        break

camera.release()
cv2.destroyAllWindows()
```

## Настройка разрешения

OpenCV позволяет запросить определённое разрешение:

```python
camera.set(
    cv2.CAP_PROP_FRAME_WIDTH,
    1280
)

camera.set(
    cv2.CAP_PROP_FRAME_HEIGHT,
    720
)
```

После этого можно проверить фактический размер:

```python
width = camera.get(
    cv2.CAP_PROP_FRAME_WIDTH
)

height = camera.get(
    cv2.CAP_PROP_FRAME_HEIGHT
)

print(width, height)
```

Важно:

> запросить определённое значение не всегда означает, что камера действительно будет работать именно в этом режиме.

Камера и драйвер могут выбрать ближайший поддерживаемый режим.

## FPS камеры

Можно запросить частоту кадров:

```python
fps = camera.get(
    cv2.CAP_PROP_FPS
)

print("FPS:", fps)
```

Но это значение зависит от камеры, драйвера и выбранного режима.

В реальной системе полезно измерять фактическую скорость обработки самостоятельно.

## Измерение фактического FPS

Можно подсчитывать кадры и измерять время:

```python
import cv2
import time

camera = cv2.VideoCapture(0)

start_time = time.time()
frame_count = 0

while True:
    ret, frame = camera.read()

    if not ret:
        break

    frame_count += 1

    elapsed = time.time() - start_time

    if elapsed >= 1.0:
        fps = frame_count / elapsed

        print("FPS:", fps)

        frame_count = 0
        start_time = time.time()

    cv2.imshow("Camera", frame)

    if cv2.waitKey(1) == 27:
        break

camera.release()
cv2.destroyAllWindows()
```

Это позволяет оценить, сколько кадров реально обрабатывает программа.

## Обработка видеопотока

Кадр камеры можно обрабатывать так же, как обычное изображение.

Например:

```python
gray = cv2.cvtColor(
    frame,
    cv2.COLOR_BGR2GRAY
)
```

После этого:

```python
blurred = cv2.GaussianBlur(
    gray,
    (5, 5),
    0
)
```

И затем:

```python
edges = cv2.Canny(
    blurred,
    50,
    150
)
```

Получается:

```text
Камера
  ↓
frame
  ↓
Grayscale
  ↓
Blur
  ↓
Canny
  ↓
Границы
```

## Полный пример обработки камеры

```python
import cv2

camera = cv2.VideoCapture(0)

if not camera.isOpened():
    raise RuntimeError("Не удалось открыть камеру")

while True:
    ret, frame = camera.read()

    if not ret:
        break

    gray = cv2.cvtColor(
        frame,
        cv2.COLOR_BGR2GRAY
    )

    blurred = cv2.GaussianBlur(
        gray,
        (5, 5),
        0
    )

    edges = cv2.Canny(
        blurred,
        50,
        150
    )

    cv2.imshow("Original", frame)
    cv2.imshow("Edges", edges)

    if cv2.waitKey(1) == 27:
        break

camera.release()
cv2.destroyAllWindows()
```

Теперь компьютер в реальном времени анализирует изображения с камеры.

## Экспозиция

**Экспозиция** связана с количеством света, которое используется для формирования изображения.

Если экспозиция слишком низкая:

```text
изображение слишком тёмное
```

Если слишком высокая:

```text
изображение пересвечено
```

Например:

```text
слишком тёмно
████
```

против:

```text
нормально
████████
```

и:

```text
пересвет
████████████████
```

Для компьютерного зрения важно получать стабильное изображение.

Если яркость постоянно меняется, алгоритм может начать работать нестабильно.

## Автоматическая экспозиция

Многие камеры используют автоматическую экспозицию.

Она пытается подстроить параметры камеры под текущую сцену.

Для обычной съёмки это удобно.

Но для технического компьютерного зрения автоматическая настройка иногда создаёт проблемы.

Например:

```text
объект появился
      ↓
камера изменила экспозицию
      ↓
яркость всей сцены изменилась
      ↓
пороговый алгоритм получил другой результат
```

Поэтому в контролируемых системах параметры камеры часто стараются фиксировать.

## Фокус

**Фокусировка** определяет, насколько резко отображаются объекты.

Если объект находится вне зоны резкости:

```text
размытый объект
```

его границы становятся менее выраженными.

Например:

```text
резко:

###########

размыто:

~~~~~~~~~~~
```

Это может ухудшить:

* поиск контуров;
* измерение;
* распознавание;
* сегментацию.

Поэтому положение камеры и фокус нужно учитывать при проектировании системы.

## Освещение

Даже хорошая камера не сможет стабильно работать, если объект постоянно меняется из-за освещения.

Например:

```text
день → ярко
вечер → темно
облако → тень
лампа → блик
```

Из-за этого изменяются значения пикселей.

Для учебного компьютерного зрения можно просто учитывать это как источник проблем.

В промышленной системе обычно стараются сделать освещение контролируемым.

## Зачем нужна стабильность

Представим алгоритм:

```text
если яркость > 100:
    объект
```

Если освещение стабильно:

```text
объект → 180
фон → 50
```

алгоритм работает хорошо.

Но если освещение изменилось:

```text
объект → 90
фон → 40
```

условие уже не сработает.

Поэтому устойчивость компьютерного зрения зависит не только от алгоритма.

Она зависит от всей системы:

```text
Камера
+
Объектив
+
Освещение
+
Положение
+
Настройки
+
Алгоритм
```

## Производительность обработки

Есть ещё одна важная проблема.

Камера может выдавать:

```text
60 FPS
```

но алгоритм может успевать обрабатывать только:

```text
20 FPS
```

Тогда система не сможет полноценно обработать каждый входящий кадр в реальном времени.

Например:

```text
Камера:
60 кадров/с

Алгоритм:
20 кадров/с
```

Возникает разница между скоростью поступления данных и скоростью обработки.

Поэтому реальная система должна учитывать:

```text
FPS камеры
+
сложность алгоритма
+
разрешение
+
мощность компьютера
```

## Что делать при высокой нагрузке

Есть несколько подходов.

Можно:

```text
уменьшить разрешение
```

или:

```text
обрабатывать не каждый кадр
```

например:

```text
Кадр 1 → обработать
Кадр 2 → пропустить
Кадр 3 → обработать
Кадр 4 → пропустить
```

Также можно:

```text
уменьшить область обработки
```

через ROI.

Или использовать более быстрый алгоритм.

## Практический принцип

При создании системы компьютерного зрения полезно задавать вопросы:

```text
Какой объект нужно видеть?

Какого размера он находится в кадре?

Насколько быстро он движется?

Какая нужна точность?

Какой FPS необходим?

Какое разрешение необходимо?

Насколько стабильно освещение?

Сколько времени можно тратить на обработку одного кадра?
```

Ответы на эти вопросы определяют параметры всей системы.

## Главное

Запомните:

* камера формирует входные данные для системы компьютерного зрения;
* видео представляет собой последовательность кадров;
* FPS показывает количество кадров в секунду;
* разрешение определяет количество пикселей;
* высокое разрешение увеличивает объём данных и нагрузку;
* высокий FPS полезен для быстрого движения, но требует большей производительности;
* OpenCV позволяет получать видеопоток через `VideoCapture`;
* экспозиция влияет на яркость изображения;
* фокус влияет на резкость;
* освещение сильно влияет на стабильность алгоритмов;
* фактическая скорость обработки может быть ниже FPS камеры;
* параметры камеры и условия съёмки являются частью задачи компьютерного зрения.

На этом первая половина базового знакомства с компьютерным зрением завершена. Мы уже умеем получать изображения, обрабатывать их, сегментировать объекты, находить контуры и работать с видеопотоком. Далее перейдём к **геометрическим преобразованиям изображений — изменению масштаба, повороту, перспективе и работе с координатами**.
