# Детекция объектов

## Цель урока

После этого урока вы должны понимать:

* что такое детекция объектов;
* чем она отличается от классификации;
* что такое bounding box;
* как детектор определяет класс и положение объекта;
* что такое confidence;
* зачем нужна Non-Maximum Suppression;
* как выглядят современные системы детекции;
* где детекция используется в робототехнике.

## Что такое детекция

**Детекция объектов (object detection)** — задача поиска объектов на изображении с определением их положения и класса.

Например, камера получает:

```text
+--------------------------------+
|                                |
|    объект A          объект B  |
|                                |
|         объект C               |
|                                |
+--------------------------------+
```

Детектор может вернуть:

```text
Object 1:
class = A
box = (...)

Object 2:
class = B
box = (...)

Object 3:
class = C
box = (...)
```

То есть детектор отвечает одновременно на два вопроса:

```text
Что находится на изображении?
Где оно находится?
```

## Bounding box

Положение объекта часто представляется ограничивающим прямоугольником:

```text
+----------------------+
|                      |
|    +-----------+     |
|    |  объект   |     |
|    +-----------+     |
|                      |
+----------------------+
```

Например:

```text
x = 120
y = 80
width = 200
height = 150
```

Это и есть bounding box.

## Классификация против детекции

Классификация:

```text
Изображение
     ↓
"автомобиль"
```

Детекция:

```text
Изображение
     ↓
автомобиль → box 1
человек    → box 2
автомобиль → box 3
```

Поэтому детекция особенно полезна, когда на одном изображении находится несколько объектов.

## Confidence

Детектор обычно возвращает оценку уверенности.

Например:

```text
car → 0.94
person → 0.87
dog → 0.42
```

Это можно использовать для фильтрации слабых результатов.

Например:

```python
if confidence < 0.5:
    continue
```

Но важно понимать:

> confidence — это оценка модели, а не абсолютная гарантия правильности.

## Почему появляются несколько рамок

Детектор может предложить несколько рамок для одного объекта.

Например:

```text
+-------------------+
|   +-----------+   |
|   | +-------+ |   |
|   | |объект | |   |
|   | +-------+ |   |
|   +-----------+   |
+-------------------+
```

Получается несколько пересекающихся кандидатов.

Нужно оставить наиболее подходящий результат.

Для этого часто используется **Non-Maximum Suppression (NMS)**.

## Non-Maximum Suppression

NMS можно представить так:

```text
несколько рамок
      ↓
сравнение перекрытия
      ↓
удаление слабых
      ↓
одна основная рамка
```

Например:

```text
box A → confidence 0.91
box B → confidence 0.82
box C → confidence 0.45
```

Если они описывают один и тот же объект, система может оставить наиболее уверенную рамку и удалить остальные.

## IoU

Для оценки перекрытия двух прямоугольников используется **Intersection over Union (IoU)**.

Упрощённо:

```text
             площадь пересечения
IoU = ---------------------------------
      площадь объединения областей
```

Если прямоугольники практически совпадают:

```text
IoU → 1
```

Если вообще не пересекаются:

```text
IoU = 0
```

IoU используется в задачах детекции для сравнения областей.

## Современный детектор

Современную систему детекции можно представить:

```text
Изображение
     ↓
Нейронная сеть
     ↓
Признаки
     ↓
Кандидаты объектов
     ↓
Класс + confidence + box
     ↓
NMS
     ↓
Финальные объекты
```

## YOLO

Одним из известных семейств детекторов является **YOLO**.

Название означает:

```text
You Only Look Once
```

Главная идея семейства — выполнять детекцию изображения как единую задачу с высокой скоростью.

На практике существуют различные версии и реализации YOLO.

Использование конкретной версии зависит от требований проекта.

## Что получает программа

Условно результат детектора может выглядеть:

```python
[
    {
        "class": "person",
        "confidence": 0.93,
        "box": [100, 80, 220, 400]
    },
    {
        "class": "car",
        "confidence": 0.88,
        "box": [400, 150, 800, 500]
    }
]
```

Это уже удобные данные для дальнейшей программы.

## Детекция в видеопотоке

Детектор можно запускать на каждом кадре:

```text
Кадр
 ↓
Детектор
 ↓
Объекты
 ↓
Следующий кадр
```

Например:

```text
Кадр 1 → 2 объекта
Кадр 2 → 2 объекта
Кадр 3 → 3 объекта
```

Чтобы сохранить идентичность объектов между кадрами, к детектору можно добавить tracking.

Получается:

```text
Детектор
   ↓
Трекер
   ↓
ID объектов
```

## Детекция и tracking

Это важное разделение:

```text
Detection:
"на этом кадре здесь находится объект"

Tracking:
"это тот же объект, который был здесь раньше"
```

Они часто используются вместе.

## Детекция в робототехнике

Представим мобильного робота:

```text
Камера
  ↓
Детектор
  ↓
обнаружен человек
  ↓
координаты объекта
  ↓
планирование движения
```

Или манипулятор:

```text
Камера
  ↓
детектор детали
  ↓
bounding box
  ↓
центр детали
  ↓
геометрическое преобразование
  ↓
координаты рабочего пространства
  ↓
робот
```

Важно, что bounding box находится в координатах изображения.

Чтобы робот смог физически переместиться к объекту, понадобятся дополнительные преобразования.

## Почему детектор может ошибаться

Ошибки возможны по разным причинам:

```text
плохое освещение
размытие
частичное перекрытие
необычный ракурс
слишком маленький объект
похожий фон
недостаточно данных обучения
```

Поэтому результат модели нужно рассматривать как данные, которые необходимо проверять и правильно использовать.

## Скорость и точность

У детекторов есть компромисс:

```text
быстрее
   ↕
точнее
```

Более сложная модель может давать более высокое качество, но требовать больше вычислительных ресурсов.

Для реального времени иногда важнее:

```text
30 FPS
```

чем максимальная точность.

Для другой задачи может быть наоборот.

Поэтому модель выбирают исходя из требований системы.

## Детекция маленьких объектов

Маленькие объекты особенно сложны.

Например:

```text
большой объект:

+----------------+
|                |
|      ####      |
|      ####      |
|                |
+----------------+
```

и:

```text
маленький объект:

+----------------+
|                |
|        ##      |
|                |
+----------------+
```

Во втором случае информации намного меньше.

Если уменьшить исходное изображение слишком сильно, объект может практически исчезнуть.

Поэтому разрешение камеры и масштаб объекта в кадре непосредственно влияют на качество детекции.

## Обучение собственного детектора

Если готовая модель не знает нужный тип объекта, можно обучить модель на собственных данных.

Упрощённый процесс:

```text
Фотографии
    ↓
Разметка объектов
    ↓
Dataset
    ↓
Обучение
    ↓
Проверка
    ↓
Готовый детектор
```

Разметка содержит:

```text
класс
+
координаты объекта
```

Например:

```text
class = gear
box = [120, 80, 300, 250]
```

## Главное

Запомните:

* детекция определяет класс и положение объектов;
* положение часто представляется через bounding box;
* confidence показывает оценку уверенности модели;
* несколько кандидатов могут быть объединены через NMS;
* IoU показывает степень перекрытия областей;
* современные детекторы используют нейронные сети;
* YOLO — известное семейство быстрых детекторов;
* детектор можно использовать вместе с трекером;
* детекция особенно полезна, когда на изображении несколько объектов;
* для робототехники координаты bounding box ещё нужно преобразовать в физическую систему координат.

В следующем уроке разберём **основы нейросетевого компьютерного зрения и то, как нейронная сеть учится извлекать признаки непосредственно из изображений**.
