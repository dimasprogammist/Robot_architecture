# Конструкторы и деструкторы

## Цель

Мы уже умеем создавать классы, хранить в них состояние и управлять им через методы. Но остаётся важный вопрос: что должно происходить в момент создания объекта и что должно происходить перед его уничтожением?

Для этого в C++ существуют конструкторы и деструкторы. Они позволяют определить начальную настройку объекта и действия, которые должны выполняться при завершении его жизни.

После урока вы должны понимать:

* что такое конструктор;
* когда он вызывается;
* как создать конструктор с параметрами;
* что такое конструктор по умолчанию;
* как использовать несколько конструкторов;
* что такое деструктор;
* когда вызывается деструктор;
* почему конструкторы и деструкторы особенно важны для управления ресурсами.

---

## Проблема неинициализированного объекта

Рассмотрим класс:

```cpp
class Robot
{
private:
    int battery;
    double speed;
};
```

Создадим объект:

```cpp
Robot robot;
```

Что находится в `battery` и `speed`?

Если значения не были заданы инициализацией, нельзя рассчитывать на корректное состояние объекта. Для сложных классов это особенно опасно.

Нам хотелось бы, чтобы при создании `Robot` он сразу получал корректное начальное состояние.

Именно для этого существует конструктор.

---

## Что такое конструктор

Конструктор — специальный метод класса, который автоматически вызывается при создании объекта.

Его имя совпадает с именем класса:

```cpp
class Robot
{
public:
    Robot()
    {
        std::cout << "Robot created\n";
    }
};
```

Теперь:

```cpp
Robot robot;
```

автоматически вызовет:

```cpp
Robot()
```

Программисту не нужно отдельно вызывать конструктор.

---

## Конструктор задаёт начальное состояние

Например:

```cpp
class Robot
{
private:
    int battery;

public:
    Robot()
    {
        battery = 100;
    }
};
```

Теперь при создании:

```cpp
Robot robot;
```

поле `battery` получит значение `100`.

Объект сразу находится в определённом состоянии.

---

## Список инициализации

В C++ поля класса принято инициализировать через список инициализации:

```cpp
class Robot
{
private:
    int battery;

public:
    Robot()
        : battery(100)
    {
    }
};
```

Здесь:

```cpp
: battery(100)
```

является списком инициализации.

Для простых полей результат может выглядеть похоже на присваивание внутри тела конструктора, но механизм отличается. Некоторые поля вообще можно корректно инициализировать только через список инициализации.

---

## Конструктор с параметрами

Конструктор может получать параметры:

```cpp
class Robot
{
private:
    std::string name;
    int battery;

public:
    Robot(const std::string& robotName, int initialBattery)
        : name(robotName),
          battery(initialBattery)
    {
    }
};
```

Теперь объект можно создать так:

```cpp
Robot robot("R1", 80);
```

При создании:

```text
name    = "R1"
battery = 80
```

Конструктор получает входные значения и создаёт объект в нужном начальном состоянии.

---

## Несколько конструкторов

У класса может быть несколько конструкторов с разными параметрами:

```cpp
class Robot
{
private:
    std::string name;
    int battery;

public:
    Robot()
        : name("Unknown"),
          battery(100)
    {
    }

    Robot(const std::string& robotName)
        : name(robotName),
          battery(100)
    {
    }

    Robot(const std::string& robotName, int initialBattery)
        : name(robotName),
          battery(initialBattery)
    {
    }
};
```

Теперь доступны разные способы создания:

```cpp
Robot robot1;
Robot robot2("R2");
Robot robot3("R3", 75);
```

Компилятор выбирает подходящий конструктор по переданным аргументам.

---

## Значения по умолчанию

Иногда вместо нескольких конструкторов можно использовать значения параметров по умолчанию:

```cpp
class Robot
{
private:
    std::string name;
    int battery;

public:
    Robot(
        const std::string& robotName = "Unknown",
        int initialBattery = 100
    )
        : name(robotName),
          battery(initialBattery)
    {
    }
};
```

Теперь работают:

```cpp
Robot robot1;
Robot robot2("R2");
Robot robot3("R3", 70);
```

---

## Конструктор должен создавать корректный объект

Хороший конструктор не просто присваивает значения. Он должен обеспечить корректное начальное состояние объекта.

Например:

```cpp
class Motor
{
private:
    double speed;

public:
    Motor(double initialSpeed)
        : speed(initialSpeed)
    {
        if (speed < 0)
        {
            speed = 0;
        }
    }
};
```

Так объект не создаётся с отрицательной скоростью.

Позже мы увидим более удобные способы организации таких проверок.

---

## Деструктор

Деструктор — специальный метод, который автоматически вызывается при уничтожении объекта.

Имя деструктора состоит из `~` и имени класса:

```cpp
class Robot
{
public:
    ~Robot()
    {
        std::cout << "Robot destroyed\n";
    }
};
```

Если написать:

```cpp
{
    Robot robot;
}
```

при выходе из блока объект будет уничтожен, и его деструктор вызовется автоматически.

---

## Когда уничтожается локальный объект

Рассмотрим:

```cpp
void test()
{
    Robot robot;

    std::cout << "Inside function\n";
}
```

Когда выполнение доходит до конца `test()`, локальный объект `robot` уничтожается.

Последовательность примерно такая:

```text
вызов test()
↓
создание robot
↓
работа функции
↓
выход из test()
↓
уничтожение robot
↓
вызов ~Robot()
```

Это связано со временем жизни объекта, которое мы уже обсуждали при изучении областей видимости и памяти.

---

## Деструктор и ресурсы

Деструктор особенно важен, когда объект владеет каким-либо ресурсом.

Ресурсом может быть:

* память;
* открытый файл;
* сетевое соединение;
* системный дескриптор;
* блокировка;
* другой внешний ресурс.

Например:

```cpp
class File
{
public:
    File()
    {
        // открыть файл
    }

    ~File()
    {
        // закрыть файл
    }
};
```

Идея заключается в том, что объект получает ресурс при создании и освобождает его при уничтожении.

Это одна из фундаментальных идей современного C++ — RAII.

---

## Порядок конструирования и уничтожения

Если создать несколько локальных объектов:

```cpp
void test()
{
    Robot robot;
    Motor motor;
}
```

сначала будет создан `robot`, затем `motor`.

При выходе из области видимости они уничтожаются в обратном порядке:

```text
создание:
robot
motor

уничтожение:
motor
robot
```

Это правило особенно важно при работе с объектами, которые зависят друг от друга.

---

## Деструктор не принимает параметры

У деструктора нет параметров:

```cpp
~Robot()
{
}
```

Нельзя написать:

```cpp
~Robot(int value)
```

и у класса не может быть нескольких деструкторов.

У объекта всегда один деструктор.

---

## Практический пример

Создадим класс подключения к устройству:

```cpp
#include <iostream>
#include <string>

class DeviceConnection
{
private:
    std::string address;
    bool connected;

public:
    DeviceConnection(const std::string& deviceAddress)
        : address(deviceAddress),
          connected(false)
    {
        std::cout << "Creating connection to "
                  << address
                  << '\n';

        connected = true;
    }

    ~DeviceConnection()
    {
        if (connected)
        {
            std::cout << "Closing connection to "
                      << address
                      << '\n';
        }
    }
};

int main()
{
    {
        DeviceConnection connection("192.168.1.10");

        std::cout << "Working with device\n";
    }

    std::cout << "Connection object destroyed\n";

    return 0;
}
```

Когда объект создаётся, конструктор выполняет настройку. Когда объект покидает область видимости, деструктор автоматически выполняет завершение работы.

---

## Важное правило

Не стоит помещать в деструктор произвольную бизнес-логику.

Деструктор предназначен прежде всего для корректного завершения жизни объекта и освобождения ресурсов, которыми объект владеет.

Например, если класс управляет файлом, закрытие файла — естественная задача деструктора. А вот выполнение сложной операции над базой данных при уничтожении объекта может сделать программу неожиданной и сложной для понимания.

---

## Главное

Конструктор вызывается при создании объекта и отвечает за его начальное состояние.

Деструктор вызывается при уничтожении объекта и используется прежде всего для освобождения принадлежащих объекту ресурсов.

Эти механизмы являются фундаментом RAII — подхода, при котором время жизни ресурса связывается с временем жизни объекта. В следующих уроках эта идея станет особенно важной при изучении управления памятью.
