# Потоки

## Цель

Обычная C++ программа начинает выполнение с функции:

```cpp
main()
```

Но в реальных приложениях одной последовательности операций часто недостаточно.

Например, программа мониторинга может одновременно:

```text
читать оборудование
записывать лог
обновлять интерфейс
обрабатывать сеть
```

Для таких задач используются **потоки выполнения**.

После урока вы должны понимать:

* что такое поток;
* чем поток отличается от процесса;
* зачем нужны несколько потоков;
* как создать поток в C++;
* что происходит при `join()`;
* почему несколько потоков могут создавать проблемы.

---

## Что такое поток

Поток — это отдельная последовательность выполнения инструкций внутри процесса.

Например:

```text
Процесс
│
├── поток 1
├── поток 2
└── поток 3
```

Все потоки одного процесса используют общие ресурсы процесса.

При этом у каждого потока есть собственный стек и состояние выполнения.

---

## Процесс и поток

Можно представить так:

```text
Процесс
│
├── общая память
├── файлы
├── сетевые ресурсы
│
├── Thread A
│     └── свой stack
│
├── Thread B
│     └── свой stack
│
└── Thread C
      └── свой stack
```

Процесс — контейнер ресурсов.

Потоки — выполняющиеся внутри него последовательности инструкций.

---

## Зачем нужны потоки

Представим программу:

```text
прочитать датчик
↓
обработать
↓
записать лог
↓
прочитать датчик
↓
...
```

Если запись лога занимает много времени, чтение датчика будет ждать.

Можно разделить работу:

```text
Поток 1 → датчики
Поток 2 → логирование
```

Тогда задачи могут выполняться независимо.

---

## Первый поток

Когда запускается программа:

```cpp
int main() {
}
```

функция `main` выполняется в основном потоке.

Можно создать дополнительный поток.

В C++ используется:

```cpp
#include <thread>
```

Пример:

```cpp
#include <iostream>
#include <thread>

void worker() {
    std::cout << "Worker thread\n";
}

int main() {
    std::thread thread(worker);

    thread.join();
}
```

Здесь:

```cpp
std::thread thread(worker);
```

создаёт новый поток.

---

## Что делает `join()`

После создания потока программа не обязана автоматически ждать его завершения.

Метод:

```cpp
thread.join();
```

говорит:

> дождаться завершения этого потока.

Например:

```cpp
std::thread thread(worker);

thread.join();

std::cout << "Done\n";
```

Сначала завершится `worker`, затем будет выполнен:

```cpp
std::cout << "Done\n";
```

---

## Почему нельзя забывать `join`

Объект `std::thread` имеет важное правило.

Если объект уничтожается, пока поток всё ещё связан с ним, это может привести к аварийному завершению программы.

Поэтому поток нужно либо:

```cpp
join()
```

либо:

```cpp
detach()
```

---

## `detach()`

`detach()` отделяет поток от объекта `std::thread`.

Например:

```cpp
std::thread thread(worker);

thread.detach();
```

После этого поток продолжает работать самостоятельно.

Для начинающих `detach()` обычно опаснее, чем `join`, потому что становится сложнее контролировать время жизни данных и завершение программы.

Поэтому в большинстве учебных и прикладных задач лучше сначала использовать `join()`.

---

## Передача функции

Потоку можно передать обычную функцию:

```cpp
void worker(int id) {
    std::cout << "Worker: " << id << '\n';
}

int main() {
    std::thread thread(worker, 42);

    thread.join();
}
```

Здесь:

```cpp
42
```

передаётся в функцию `worker`.

---

## Лямбда-функция

Можно использовать lambda:

```cpp
#include <thread>
#include <iostream>

int main() {
    std::thread thread([] {
        std::cout << "Hello from thread\n";
    });

    thread.join();
}
```

Это удобно для небольших задач.

---

## Несколько потоков

Можно создать несколько потоков:

```cpp
#include <iostream>
#include <thread>

void worker(int id) {
    std::cout << "Worker " << id << '\n';
}

int main() {
    std::thread a(worker, 1);
    std::thread b(worker, 2);
    std::thread c(worker, 3);

    a.join();
    b.join();
    c.join();
}
```

Но порядок вывода не гарантирован.

Например, можно получить:

```text
Worker 1
Worker 3
Worker 2
```

или:

```text
Worker 2
Worker 1
Worker 3
```

Это нормально.

---

## Почему порядок меняется

Потоки выполняются независимо.

Операционная система распределяет процессорное время между ними.

Поэтому невозможно без дополнительных механизмов гарантировать:

```text
Thread A
затем
Thread B
затем
Thread C
```

Если порядок важен, программу нужно синхронизировать.

---

## Параллельность

На многоядерном процессоре разные потоки могут действительно выполняться одновременно.

Например:

```text
CPU Core 1 → Thread A
CPU Core 2 → Thread B
CPU Core 3 → Thread C
```

Но даже на одном ядре ОС может быстро переключаться между потоками.

Поэтому многопоточность и параллельное выполнение — связанные, но не полностью одинаковые понятия.

---

## Пример: два независимых действия

```cpp
#include <chrono>
#include <iostream>
#include <thread>

void sensorWorker() {
    for (int i = 0; i < 5; ++i) {
        std::cout << "Sensor check\n";
        std::this_thread::sleep_for(
            std::chrono::milliseconds(500)
        );
    }
}

void loggerWorker() {
    for (int i = 0; i < 5; ++i) {
        std::cout << "Write log\n";
        std::this_thread::sleep_for(
            std::chrono::milliseconds(700)
        );
    }
}

int main() {
    std::thread sensor(sensorWorker);
    std::thread logger(loggerWorker);

    sensor.join();
    logger.join();
}
```

Здесь два потока выполняют разные задачи.

---

## `sleep_for`

В примере используется:

```cpp
std::this_thread::sleep_for(...)
```

Он временно приостанавливает текущий поток.

Например:

```cpp
std::this_thread::sleep_for(
    std::chrono::seconds(1)
);
```

пауза примерно на одну секунду.

Важно: `sleep_for` не является точным механизмом реального времени.

Поток может проснуться позже из-за планирования ОС или других причин.

---

## Передача данных в поток

Можно передавать аргументы:

```cpp
void worker(int value) {
    std::cout << value << '\n';
}

int main() {
    int value = 100;

    std::thread thread(worker, value);

    thread.join();
}
```

Здесь в поток передаётся копия `value`.

---

## Передача по ссылке

Можно передать ссылку через `std::ref`.

```cpp
#include <functional>
#include <thread>

void worker(int& value) {
    value = 200;
}

int main() {
    int value = 100;

    std::thread thread(
        worker,
        std::ref(value)
    );

    thread.join();
}
```

После завершения:

```text
value == 200
```

Но теперь появляется потенциальная проблема: несколько потоков могут одновременно обращаться к одному объекту.

---

## Общая память

Потоки одного процесса обычно имеют доступ к общей памяти.

Например:

```cpp
int counter = 0;
```

Несколько потоков могут обращаться к:

```cpp
counter
```

Это удобно.

Но одновременно это источник серьёзных ошибок.

---

## Гонка данных

Представим:

```cpp
int counter = 0;
```

Два потока делают:

```cpp
++counter;
```

Наивно кажется, что после 1000 увеличений каждым потоком получится:

```text
2000
```

Но операция `++` не обязательно выполняется как одна неделимая аппаратная операция.

Упрощённо:

```text
прочитать counter
изменить
записать обратно
```

Если два потока делают это одновременно, обновления могут потеряться.

Такое состояние называется **data race**.

---

## Почему это опасно

Многопоточные ошибки могут быть особенно неприятными.

Программа может:

```text
работать несколько часов
```

а затем внезапно:

```text
получить неправильные данные
зависнуть
завершиться с ошибкой
```

Причём повторный запуск может пройти нормально.

Это делает ошибки многопоточности сложными для диагностики.

---

## Поток и локальные переменные

Локальные переменные функции обычно находятся в стеке конкретного потока.

Например:

```cpp
void worker() {
    int value = 10;
}
```

У каждого вызова функции в отдельном потоке будет собственная локальная переменная.

Это одна из причин, почему локальные переменные часто проще безопасно использовать в многопоточном коде.

---

## Общие объекты

Если объект расположен в общей памяти:

```cpp
Device device;
```

и несколько потоков обращаются к нему:

```text
Thread A ──┐
           ├── Device
Thread B ──┘
```

необходимо понимать, безопасно ли это.

Если методы объекта изменяют внутреннее состояние, может потребоваться синхронизация.

---

## Потоки в промышленном приложении

Представим монитор оборудования:

```text
Main Thread
    ↓
GUI

Sensor Thread
    ↓
OPC UA / Modbus / TCP

Logger Thread
    ↓
log files

Watchdog Thread
    ↓
health checks
```

Такая архитектура может быть удобной.

Но она требует правильной синхронизации.

Например:

```text
Sensor Thread
      ↓
shared data
      ↓
GUI Thread
```

Если GUI читает данные одновременно с записью, нужно обеспечить корректный доступ.

---

## Потоки не являются бесплатными

Создание потока требует ресурсов.

Кроме того, многопоточность увеличивает сложность программы.

Поэтому нельзя руководствоваться правилом:

> чем больше потоков, тем быстрее программа.

Слишком большое количество потоков может даже ухудшить производительность.

---

## Когда потоки полезны

Потоки подходят, когда есть действительно независимые задачи.

Например:

```text
сетевой обмен
логирование
обработка данных
ожидание устройства
```

Но иногда лучше использовать:

* очередь задач;
* асинхронное программирование;
* пул потоков;
* события;
* специализированные библиотеки.

Выбор зависит от архитектуры приложения.

---

## Главное

Поток — это отдельная последовательность выполнения внутри процесса.

Для создания:

```cpp
std::thread
```

Для ожидания:

```cpp
join()
```

Для временной остановки текущего потока:

```cpp
std::this_thread::sleep_for()
```

Несколько потоков могут использовать общую память.

Именно поэтому многопоточность требует синхронизации.
