# Как устроена память программы

## Цель

До этого момента мы создавали переменные и использовали их, не задумываясь о том, где именно они находятся внутри компьютера. Для начала работы с указателями и динамической памятью это понимание становится необходимым.

Программа во время выполнения использует память компьютера для хранения инструкций, переменных, объектов и временных данных. В этой главе разберём общую модель памяти процесса и подготовимся к следующему уроку об указателях.

После урока вы должны понимать:

* что такое память процесса;
* зачем программе нужны адреса;
* что такое стек;
* что такое динамическая память;
* чем стек отличается от динамической области;
* почему адрес переменной имеет значение;
* почему неправильная работа с памятью опасна.

---

# Память и адреса

Компьютерная память состоит из множества ячеек, каждая из которых имеет адрес.

Упрощённо можно представить память так:

```text
адрес       данные

0x1000      ...
0x1001      ...
0x1002      ...
0x1003      ...
...
```

Когда программа создаёт переменную:

```cpp
int value = 42;
```

значение `42` где-то хранится в памяти.

У этого места есть адрес.

---

# Адрес переменной

В C++ можно получить адрес переменной с помощью оператора:

```cpp
&
```

Например:

```cpp
int value = 42;

std::cout << &value << '\n';
```

Программа может вывести что-то вроде:

```text
0x7ffdf1234560
```

Конкретный адрес будет отличаться от запуска к запуску.

Главное здесь не само число, а понимание:

> переменная занимает определённое место в памяти, у которого есть адрес.

---

# Размер данных

Разные типы занимают разное количество памяти.

Например:

```cpp
int value = 42;
double temperature = 25.5;
char letter = 'A';
```

Можно узнать размер:

```cpp
std::cout << sizeof(value) << '\n';
std::cout << sizeof(temperature) << '\n';
std::cout << sizeof(letter) << '\n';
```

`sizeof` возвращает размер объекта или типа в байтах.

Точный размер некоторых типов зависит от платформы и реализации компилятора.

---

# Что такое байт

Байт — базовая единица хранения данных, состоящая из восьми битов.

Один бит может иметь значение:

```text
0
```

или:

```text
1
```

Восемь бит образуют один байт.

Память компьютера обычно измеряют:

```text
байты
килобайты
мегабайты
гигабайты
```

---

# Память процесса

Когда программа запускается, операционная система создаёт для неё процесс и предоставляет адресное пространство.

Упрощённо память процесса можно представить как несколько областей:

```text
┌──────────────────────────┐
│ Код программы            │
├──────────────────────────┤
│ Глобальные данные        │
├──────────────────────────┤
│ Динамическая память      │
│                          │
│        ...               │
│                          │
├──────────────────────────┤
│ Стек                     │
└──────────────────────────┘
```

Это упрощённая модель. Реальное устройство памяти современного процесса сложнее и зависит от операционной системы, архитектуры процессора, компилятора и настроек программы.

---

# Код программы

Программа содержит машинные инструкции, которые процессор должен выполнять.

Например:

```cpp
int result = a + b;
```

после компиляции превращается в машинные инструкции.

Эти инструкции загружаются в адресное пространство процесса и выполняются процессором.

---

# Глобальные данные

Если программа содержит глобальные переменные:

```cpp
int globalCounter = 0;
```

они также должны где-то храниться.

Для глобальных и статических объектов существуют специальные области памяти процесса.

На этом этапе достаточно понимать главное:

> глобальные и статические данные имеют время жизни, связанное с существованием программы.

---

# Стек

Стек используется для хранения данных, связанных с вызовами функций.

Например:

```cpp
void calculate() {
    int value = 10;
}
```

Локальная переменная:

```cpp
value
```

связана с выполнением функции.

При вызове функции создаётся её контекст выполнения.

При завершении функции соответствующие локальные данные перестают быть доступны.

---

# Вызовы функций

Представим:

```cpp
int add(int a, int b) {
    int result = a + b;
    return result;
}

int main() {
    int value = add(10, 20);
}
```

Когда `main()` вызывает `add()`, появляется новый контекст выполнения функции.

В нём находятся параметры и локальные данные.

После завершения `add()` выполнение возвращается в `main()`.

Именно поэтому стек часто удобно представлять как структуру:

```text
main()
  ↓
add()
  ↓
calculate()
```

Каждый вызов добавляет новый уровень.

---

# Стек работает по принципу LIFO

LIFO означает:

```text
Last In, First Out
```

То есть:

> последним добавили — первым удалили.

Если вызовы выглядят так:

```text
main()
 ↓
A()
 ↓
B()
```

то завершение происходит в обратном порядке:

```text
B()
 ↓
A()
 ↓
main()
```

Это естественно соответствует вложенным вызовам функций.

---

# Что такое переполнение стека

Стек имеет ограниченный размер.

Если программа создаёт слишком глубокую рекурсию или использует слишком большие локальные данные, можно исчерпать доступное пространство стека.

Например, опасным может быть:

```cpp
void recursiveFunction() {
    recursiveFunction();
}
```

Функция вызывает саму себя бесконечно.

Каждый вызов требует новый контекст.

В итоге стек может переполниться.

---

# Динамическая память

Кроме стека существует область памяти, которую программа может использовать динамически.

В классической терминологии её часто называют:

```text
heap
```

или кучей.

Идея состоит в том, что программа может запросить память во время выполнения, когда заранее неизвестно, сколько данных понадобится.

Например:

```text
пользователь ввёл 10 элементов
→ нужна память для 10 элементов

пользователь ввёл 100000 элементов
→ нужна память для 100000 элементов
```

---

# Зачем нужна динамическая память

Представим программу, которая получает от пользователя количество элементов:

```cpp
int count;
std::cin >> count;
```

До запуска программы мы не знаем:

```text
count = 10
```

или:

```text
count = 100000
```

Динамическое выделение памяти позволяет принимать такие решения во время выполнения.

В современном C++ для большинства задач вместо ручной работы с памятью используются контейнеры и умные указатели. Но понимать сам механизм всё равно необходимо.

---

# Стек и динамическая память

Упрощённое сравнение:

| Стек | Динамическая память |
|---|---|
| связана с вызовами функций | выделяется во время выполнения |
| локальные данные | объекты и структуры произвольного размера |
| автоматически управляется | управление зависит от механизма владения |
| обычно быстрее | имеет дополнительные накладные расходы |
| ограниченный размер | позволяет работать с большими динамическими структурами |

Это упрощённое представление. В реальных программах детали зависят от реализации и типа объекта.

---

# Почему память нельзя использовать как угодно

Представим:

```cpp
int value = 42;
```

Если программа каким-то образом обращается к неправильному адресу и пытается записать данные туда, где их быть не должно, могут возникнуть серьёзные проблемы.

Например:

* повреждение данных;
* неправильное поведение программы;
* падение процесса;
* уязвимости безопасности.

Именно поэтому работа с указателями и памятью требует аккуратности.

---

# Автоматическое управление

В современном C++ большинство обычных локальных переменных не требуют ручного освобождения памяти.

Например:

```cpp
void process() {
    int value = 10;

    // работа
}
```

Когда выполнение выходит из соответствующей области, объект `value` перестаёт существовать.

Программисту не нужно писать специальную команду:

```text
delete value
```

---

# Ручное управление памятью

C++ также предоставляет низкоуровневые механизмы:

```cpp
new
delete
```

Например:

```cpp
int* value = new int(42);

delete value;
```

Здесь программа вручную запросила память и затем вручную её освободила.

Но такой код легко сделать неправильным.

В следующих уроках мы подробно разберём указатели, а затем поговорим о том, почему современный C++ старается минимизировать ручное управление памятью.

---

# Адреса и указатели

Если у переменной есть адрес:

```cpp
int value = 42;
```

то возникает естественный вопрос:

> можно ли сохранить этот адрес в другой переменной?

Да.

Для этого существуют указатели.

Например:

```cpp
int value = 42;

int* pointer = &value;
```

Теперь:

```text
value
  ↓
данные 42

pointer
  ↓
адрес value
```

Подробно это мы разберём в следующем уроке.

---

# Почему указатели важны

Указатели являются одной из фундаментальных возможностей C++.

Они используются при:

* работе с памятью;
* передаче объектов;
* низкоуровневом программировании;
* взаимодействии с операционной системой;
* работе с аппаратурой;
* создании структур данных;
* разработке системного программного обеспечения.

В робототехнике указатели также встречаются очень часто, особенно при работе с библиотеками, буферами и низкоуровневыми интерфейсами.

---

# Практический эксперимент

Создайте программу:

```cpp
#include <iostream>

int main() {
    int value = 42;

    std::cout << "Value: " << value << '\n';
    std::cout << "Address: " << &value << '\n';
    std::cout << "Size: " << sizeof(value) << " bytes\n";

    return 0;
}
```

Запустите её несколько раз.

Вы увидите, что адрес может изменяться между запусками.

Это нормальное поведение современных операционных систем и связано, среди прочего, с механизмами защиты и организацией адресного пространства процесса.

# Главное

Память программы — это не просто абстрактное место, где находятся переменные. Каждый объект занимает определённое пространство и существует в рамках определённых правил времени жизни.

Для понимания C++ особенно важны следующие идеи:

* у объектов есть адреса;
* разные типы занимают разный объём памяти;
* программа во время выполнения использует адресное пространство процесса;
* стек связан с вызовами функций и локальными данными;
* динамическая память позволяет выделять память во время выполнения;
* неправильная работа с памятью может привести к серьёзным ошибкам;
* указатели позволяют работать с адресами;
* современный C++ предоставляет механизмы автоматического управления ресурсами, чтобы уменьшить количество ошибок.

Следующий шаг — разобраться, что именно представляет собой указатель и как через него можно работать с объектом в памяти.
