# C++ в микроконтроллерах

## Цель

До этого мы рассматривали C++ в контексте обычного компьютера.

Теперь посмотрим на другой мир — микроконтроллеры.

Микроконтроллер может иметь:

```text
несколько десятков или сотен килобайт RAM
ограниченную Flash-память
таймеры
GPIO
UART
SPI
I²C
ADC
PWM
```

И при этом выполнять программу на C++.

После урока вы должны понимать:

* что такое микроконтроллер;
* чем embedded-программа отличается от обычной программы;
* почему ресурсы микроконтроллера ограничены;
* какую роль играют Flash и RAM;
* что такое HAL;
* почему статическое управление памятью часто предпочтительно;
* как работают циклы и периферия;
* зачем нужны interrupts;
* какие особенности C++ особенно важны в embedded.

---

## Что такое микроконтроллер

Микроконтроллер — это небольшая вычислительная система, в которой процессор, память и периферия находятся внутри одного чипа.

Например:

```text
┌────────────────────────────┐
│       Microcontroller      │
│                            │
│ CPU                        │
│ RAM                        │
│ Flash                      │
│ GPIO                       │
│ UART                       │
│ SPI                        │
│ I²C                        │
│ Timers                     │
│ ADC                        │
└────────────────────────────┘
```

Такой чип может управлять:

```text
двигателем
датчиком
кнопкой
дисплеем
роботом
промышленным устройством
```

## Обычный компьютер и микроконтроллер

На ПК:

```text
CPU
RAM
SSD
GPU
USB
Ethernet
OS
```

На микроконтроллере:

```text
CPU
RAM
Flash
GPIO
Timers
UART
ADC
```

При этом на микроконтроллере может вообще не быть полноценной операционной системы.

---

## Bare metal

Если программа работает непосредственно на микроконтроллере без полноценной ОС, такой подход часто называют:

**bare metal**.

Например:

```text
main()
  ↓
инициализация
  ↓
бесконечный цикл
```

Упрощённо:

```cpp
int main() {
    initializeHardware();

    while (true) {
        readSensors();
        controlMotor();
    }
}
```

Программа может работать так годами, пока устройство получает питание.

---

## Почему `main()` не заканчивается

На обычном компьютере:

```cpp
int main() {
    return 0;
}
```

процесс завершается.

На микроконтроллере программа часто должна работать постоянно.

Поэтому:

```cpp
while (true) {
    process();
}
```

является нормальной архитектурой.

---

## Flash и RAM

У микроконтроллера обычно есть как минимум:

```text
Flash
RAM
```

Flash используется для хранения программы и постоянных данных.

RAM используется во время выполнения:

```text
переменные
стек
буферы
состояние программы
```

---

## Почему память важна

На обычном ПК программа может занимать сотни мегабайт.

На микроконтроллере может быть:

```text
RAM = 64 KB
```

Если программа выделила слишком много памяти:

```text
RAM закончилась
```

и система может перестать работать.

Поэтому разработчик должен понимать, сколько памяти использует каждая структура.

---

## Динамическая память

В embedded-коде часто стараются осторожно использовать:

```cpp
new
delete
std::vector
std::string
```

Это не означает, что они всегда запрещены.

Проблема в том, что динамическое выделение памяти может приводить к:

```text
фрагментации
непредсказуемым задержкам
ошибкам нехватки памяти
сложности анализа ресурсов
```

Для некоторых систем предпочтительнее статические буферы.

---

## Статический буфер

Например:

```cpp
std::array<std::uint8_t, 256> buffer;
```

Размер известен заранее.

Это удобно для embedded.

Можно также использовать обычный массив:

```cpp
std::uint8_t buffer[256];
```

Но современные возможности C++ позволяют безопаснее и удобнее работать с:

```cpp
std::array
std::span
```

если они поддерживаются используемым toolchain.

---

## Ограничение ресурсов

При разработке нужно учитывать:

```text
RAM
Flash
CPU time
stack
timers
I/O pins
power consumption
```

Например, если обработка одного цикла занимает:

```text
20 ms
```

а требуется обновление каждые:

```text
10 ms
```

архитектура уже не соответствует требованиям.

## HAL

HAL — Hardware Abstraction Layer.

Это слой, который скрывает конкретные аппаратные детали.

Например:

```cpp
gpio.write(true);
```

вместо прямой работы с регистрами.

Архитектура:

```text
Application
     ↓
HAL
     ↓
Microcontroller registers
     ↓
Hardware
```

Это позволяет отделить бизнес-логику от конкретного микроконтроллера.

---

## Драйвер периферии

Например:

```cpp
class TemperatureSensor {
public:
    float read();
};
```

Внутри:

```text
TemperatureSensor
       ↓
I²C driver
       ↓
I²C peripheral
       ↓
sensor
```

Основная программа не обязана знать детали протокола.

---

## GPIO

Пример логики:

```cpp
button = gpio.read();
```

Если кнопка нажата:

```cpp
led.write(true);
```

Получается:

```text
Button
  ↓
GPIO input
  ↓
C++
  ↓
GPIO output
  ↓
LED
```

Это одна из первых задач при изучении микроконтроллеров.

---

## ADC

ADC — Analog-to-Digital Converter.

Он преобразует аналоговый сигнал в цифровое значение.

Например:

```text
датчик напряжения
      ↓
ADC
      ↓
число
      ↓
C++
```

Допустим, ADC возвращает:

```text
2048
```

Программа может преобразовать его в физическую величину.

---

## PWM

PWM используется для управления:

```text
двигателями
яркостью LED
нагревателями
```

Упрощённо:

```text
HIGH ──┐    ┌────
       │    │
LOW    └────┘
```

Изменяя duty cycle, можно изменять среднюю мощность сигнала.

---

## Таймеры

Микроконтроллеры имеют аппаратные таймеры.

Они позволяют:

```text
измерять время
создавать периодические события
генерировать PWM
запускать действия через интервалы
```

Например:

```text
Timer
 ↓
каждые 1 ms
 ↓
updateControl()
```

---

## Прерывания

Прерывание позволяет аппаратуре сообщить процессору:

> произошло событие, обработай его.

Например:

```text
GPIO
 ↓
button pressed
 ↓
interrupt
 ↓
handler
```

Другой пример:

```text
UART
 ↓
byte received
 ↓
interrupt
```

---

## Почему interrupt важен

Без прерывания можно постоянно проверять:

```cpp
while (true) {
    if (buttonPressed()) {
        handleButton();
    }
}
```

Это называется polling.

Прерывание позволяет реагировать на событие без постоянной проверки в основном цикле.

Но обработчики прерываний должны быть короткими и аккуратными.

---

## Что нельзя бездумно делать в interrupt

Не стоит выполнять внутри обработчика:

```text
долгие вычисления
блокирующие операции
долгую запись
ожидание
сложные сетевые операции
```

Обычно лучше:

```text
interrupt
   ↓
зафиксировать событие
   ↓
основной код обработает его
```

---

## `volatile` и interrupts

Если значение изменяется обработчиком прерывания и читается обычным кодом, можно встретить:

```cpp
volatile bool event = false;
```

Это помогает компилятору учитывать, что значение может измениться вне обычного потока выполнения.

Но важно:

```text
volatile ≠ atomic
volatile ≠ mutex
volatile ≠ thread-safe
```

Для многопоточной синхронизации нужны соответствующие механизмы.

---

## RTOS

Не все микроконтроллеры работают bare metal.

Можно использовать RTOS — Real-Time Operating System.

Например:

```text
Task A → sensors
Task B → communication
Task C → control
```

RTOS предоставляет механизмы:

```text
tasks
queues
mutexes
semaphores
timers
```

Это уже похоже на многопоточную программу.

---

## C++ и RTOS

C++ можно использовать поверх RTOS.

Например:

```text
C++ application
      ↓
RTOS API
      ↓
microcontroller
```

Классы помогают организовать драйверы:

```cpp
class Motor {
public:
    void setSpeed(float speed);
};
```

А RTOS управляет задачами.

---

## Конструкторы в embedded

C++ классы полезны, но нужно помнить, когда выполняются конструкторы.

Например:

```cpp
Motor motor;
```

глобальный объект может быть создан ещё до входа в `main`.

Это важно для embedded, потому что порядок инициализации оборудования может иметь значение.

Поэтому глобальные объекты нужно проектировать аккуратно.

---

## Исключения и RTTI

В некоторых embedded-проектах отключают или ограничивают:

```text
exceptions
RTTI
динамическое выделение памяти
```

Причины могут быть:

```text
размер прошивки
предсказуемость
ограниченные ресурсы
требования платформы
```

Но это не универсальное правило.

Современные embedded-проекты могут использовать часть возможностей C++ в зависимости от toolchain и требований.

---

## STL в embedded

STL не является автоматически запрещённой.

Можно использовать:

```cpp
std::array
std::span
std::optional
std::algorithm
```

если это поддерживается платформой и соответствует требованиям проекта.

Но нужно учитывать:

```text
RAM
Flash
время выполнения
динамические аллокации
```

Например:

```cpp
std::array<int, 16>
```

часто предсказуемее по ресурсам, чем динамически растущий контейнер.

---

## Watchdog

В embedded-системах часто используется watchdog timer.

Идея:

```text
программа работает
      ↓
периодически сообщает:
"я работаю"
      ↓
watchdog
```

Если программа зависла:

```text
нет сигнала
   ↓
watchdog timeout
   ↓
reset
```

Это позволяет системе самостоятельно восстанавливаться после некоторых зависаний.

---

## Управление временем

Для embedded важно не только:

```text
что делает программа
```

но и:

```text
когда она это делает
```

Например, контроллер должен выполнять цикл каждые:

```text
1 ms
```

Если одна операция иногда занимает:

```text
10 ms
```

это уже может нарушить требования системы.

Поэтому embedded-разработка часто требует анализа worst-case execution time и временных ограничений.
