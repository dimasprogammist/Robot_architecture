# Сетевое программирование: базовые понятия

## Цель

Современные программы редко работают полностью изолированно.

Приложение может:

```text
подключаться к серверу
получать данные от устройства
отправлять команды
работать с базой данных
обмениваться сообщениями с роботом
```

Для этого необходимо понимать основы компьютерных сетей.

После урока вы должны понимать:

* что такое IP-адрес;
* что такое порт;
* что такое клиент и сервер;
* как устанавливается TCP-соединение;
* чем TCP отличается от UDP;
* что такое сокет;
* почему стандартный C++ не содержит универсального socket API;
* где в реальных проектах используется сетевой C++.

---

## Что такое сеть

Компьютерная сеть позволяет нескольким устройствам обмениваться данными.

Например:

```text
PC 1
  │
  │ Ethernet
  │
  ▼
Switch
  │
  ├── PC 2
  ├── PLC
  └── Server
```

Программа на одном компьютере может отправить данные программе на другом.

---

## IP-адрес

Чтобы устройство можно было идентифицировать в IP-сети, используется IP-адрес.

Например:

```text
192.168.8.149
```

IPv4-адрес состоит из четырёх чисел.

В реальных сетях используются также IPv6-адреса.

Например:

```text
2001:db8::1
```

Для начала достаточно понимать принцип:

```text
IP → адрес узла в сети
```

---

## Порт

Одного IP-адреса недостаточно.

На одном компьютере могут одновременно работать:

```text
веб-сервер
OPC UA
база данных
SSH
другое приложение
```

Поэтому используется понятие **порт**.

Например:

```text
192.168.8.149:4861
```

Здесь:

```text
192.168.8.149 → IP
4861           → порт
```

Порт позволяет определить конкретную сетевую службу на узле.

---

## IP + порт

Сетевое соединение часто можно представить как:

```text
адрес + порт
```

Например:

```text
192.168.8.149:4861
```

Можно сказать:

> Подключиться к узлу `192.168.8.149` на порт `4861`.

Это именно тот уровень, который часто встречается при диагностике промышленного оборудования.

---

## Клиент и сервер

Обычно одна сторона ожидает подключения — это сервер.

Другая инициирует соединение — клиент.

```text
Client
   │
   │ connect
   ▼
Server
```

Например:

```text
OPC UA Client
      ↓
OPC UA Server
```

Или:

```text
C++ Application
      ↓
Device Server
```

---

## Сервер

Упрощённо сервер делает:

```text
создать socket
      ↓
назначить IP/порт
      ↓
слушать
      ↓
ждать подключения
      ↓
принять клиента
      ↓
обмениваться данными
```

---

## Клиент

Клиент обычно делает:

```text
создать socket
      ↓
найти сервер
      ↓
connect
      ↓
send / receive
      ↓
close
```

---

## Что такое socket

Сокет — это программный интерфейс, через который приложение работает с сетевым соединением.

Упрощённо:

```text
C++ программа
      ↓
socket
      ↓
TCP/IP
      ↓
сетевой адаптер
      ↓
сеть
```

Сокет не является физическим разъёмом.

Это программный объект или дескриптор, через который приложение взаимодействует с сетевым стеком ОС.

---

## TCP

TCP — протокол транспортного уровня, ориентированный на надёжную передачу потока байтов.

Упрощённо TCP предоставляет:

* установление соединения;
* доставку данных в порядке;
* контроль потерь;
* повторную передачу потерянных сегментов;
* контроль перегрузки.

Поэтому TCP часто используется там, где важно получить данные без потерь и в правильном порядке.

---

## TCP — поток байтов

Это очень важный момент.

Если приложение отправило:

```text
HELLO
```

TCP не гарантирует, что другая сторона получит именно одно сообщение:

```text
HELLO
```

Она получает поток байтов.

Например, приложение может прочитать:

```text
HE
```

а потом:

```text
LLO
```

или несколько отправленных данных могут прийти одним чтением.

Поэтому протокол приложения должен определять границы сообщений.

---

## Как определить конец сообщения

В собственном TCP-протоколе можно использовать:

### Разделитель

```text
TEMP=25.4\n
```

### Фиксированную длину

```text
каждое сообщение = 32 байта
```

### Поле длины

Например:

```text
[4 байта длина][данные]
```

Такой подход часто используется в бинарных протоколах.

---

## UDP

UDP работает иначе.

Он не устанавливает такое же соединение, как TCP, и передаёт отдельные датаграммы.

Преимущества:

* меньше накладных расходов;
* нет обязательного установления соединения;
* подходит для некоторых задач реального времени.

Но приложение должно учитывать, что пакеты могут:

```text
потеряться
прийти не по порядку
дублироваться
```

---

## TCP или UDP

Упрощённо:

```text
TCP
→ надёжный поток
→ порядок данных
→ повторная передача

UDP
→ датаграммы
→ меньше гарантий
→ меньше накладных расходов
```

Нельзя сказать, что один протокол «лучше».

Выбор зависит от задачи.

---

## Где используется TCP

TCP часто используется для:

```text
HTTP
SSH
базы данных
промышленные протоколы
собственные клиент-серверные приложения
```

Например:

```text
C++ программа
     ↓ TCP
контроллер / сервер
```

---

## Где используется UDP

UDP может использоваться там, где важнее свежесть данных, чем гарантированная доставка каждого пакета.

Например:

```text
телеметрия
медиа
игровые сетевые протоколы
некоторые discovery-протоколы
```

Конкретный выбор зависит от требований системы.

---

## Стандартный C++ и сокеты

В стандартной библиотеке C++ нет единого универсального API уровня:

```cpp
std::socket();
std::connect();
```

как части стандартного языка.

Обычно используются:

```text
Windows Socket API
Linux/POSIX sockets
Boost.Asio
Asio
другие сетевые библиотеки
```

Поэтому сетевой C++ код часто зависит от платформы или внешней библиотеки.

---

## Почему библиотеки полезны

Если писать сокеты напрямую через системные API, код Windows и Linux будет различаться.

Например:

```text
Windows
WSAStartup
SOCKET
closesocket
```

и:

```text
Linux
socket
int fd
close
```

Библиотеки вроде Asio позволяют скрыть часть платформенных различий.

---

## Клиент-серверная архитектура

Представим:

```text
                ┌── Client A
Server ─────────┼── Client B
                └── Client C
```

Сервер слушает порт.

Каждый клиент устанавливает своё соединение.

Например:

```text
192.168.8.149:5000
```

может обслуживать несколько клиентов.

---

## Пример промышленной сети

Представим:

```text
C++ Monitor
     │
     │ TCP
     ▼
Industrial Server
     │
     ├── PLC
     ├── sensors
     └── database
```

C++ программа может выполнять:

```text
connect()
send()
receive()
close()
```

Но конкретный формат данных должен быть определён протоколом.

---

## Протокол приложения

Допустим, мы договорились:

```text
GET_TEMP
```

Сервер отвечает:

```text
TEMP:25.4
```

Получается:

```text
Client → GET_TEMP
Server → TEMP:25.4
```

Это уже простой прикладной протокол.

В реальных системах протокол может быть гораздо сложнее.

---

## Бинарные протоколы

Не обязательно передавать текст.

Можно определить бинарный пакет:

```text
┌────────┬────────┬──────────────┐
│ Type   │ Length │ Payload      │
│ 1 byte │ 2 byte │ N bytes      │
└────────┴────────┴──────────────┘
```

Например:

```text
Type = 1
Length = 8
Payload = double
```

Бинарные протоколы позволяют эффективно передавать структурированные данные.

Но они требуют аккуратного проектирования.

---

## Endianness

Когда данные передаются как бинарные числа, возникает вопрос порядка байтов.

Например:

```text
0x12345678
```

может храниться в памяти по-разному в зависимости от порядка байтов.

Поэтому бинарный сетевой протокол должен явно определять формат данных.

Нельзя просто отправлять:

```cpp
reinterpret_cast<char*>(&value)
```

и предполагать, что другая машина гарантированно интерпретирует байты одинаково.

---

## Сетевые ошибки

Сеть ненадёжна как среда.

Может произойти:

```text
сервер выключен
порт закрыт
кабель отключён
маршрут отсутствует
firewall блокирует соединение
соединение разорвано
сервер не отвечает
```

Поэтому сетевой код всегда должен обрабатывать ошибки.

---

## Таймауты

Нельзя всегда ждать ответ бесконечно.

Например:

```text
connect
↓
wait
↓
wait
↓
wait
```

Если сервер завис, программа может зависнуть вместе с ним.

Поэтому сетевые библиотеки обычно предоставляют механизмы таймаутов.

Например:

```text
connection timeout
read timeout
write timeout
```

---

## Сетевое программирование и многопоточность

Эти темы часто пересекаются.

Например:

```text
Thread 1 → принимает сеть
Thread 2 → обрабатывает данные
Thread 3 → пишет лог
```

Или используется асинхронная модель:

```text
event loop
   ↓
network events
   ↓
callbacks/tasks
```

Выбор архитектуры зависит от приложения.

---

## Сетевое программирование в робототехнике

Робот может обмениваться данными с компьютером:

```text
Robot Controller
      ↕
      TCP
      ↕
Control PC
```

Например:

```text
PC → MOVE 100 200
Robot → OK

PC → GET_STATUS
Robot → RUNNING
```

В реальной системе могут использоваться стандартные протоколы или специализированные middleware.

---

## Не путайте порт с устройством

Порт:

```text
192.168.8.149:4861
```

не обязательно означает физический разъём.

Это логический номер сетевой службы.

Физический Ethernet-разъём и TCP-порт — совершенно разные понятия.

---

## Диагностика сетевого приложения

Если C++ программа не может подключиться к:

```text
192.168.8.149:4861
```

проверять нужно несколько уровней:

```text
1. Есть ли связь с узлом?
2. Доступен ли порт?
3. Запущен ли сервер?
4. Правильно ли указан протокол?
5. Правильный ли формат данных?
6. Не блокирует ли firewall?
7. Не требует ли сервер аутентификацию?
```

Это очень важный практический навык.

---

## Главное

Нужно запомнить:

```text
IP
→ адрес узла

Port
→ логическая точка доступа к службе

Socket
→ программный интерфейс сетевого соединения

TCP
→ надёжный поток байтов

UDP
→ датаграммы без тех же гарантий доставки

Client
→ инициирует взаимодействие

Server
→ принимает подключения / предоставляет сервис
```

C++ не содержит единого стандартного socket API, поэтому для сетевой работы используются возможности ОС или библиотеки.
