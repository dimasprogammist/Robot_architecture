# Move semantics

## Цель

До этого момента мы в основном работали с копированием объектов. В современном C++ существует ещё один важный механизм — перемещение объекта.

Move semantics позволяет передавать внутренние ресурсы объекта другому объекту без ненужного копирования. Это особенно важно для больших контейнеров, строк, файлов, сетевых буферов и других объектов, которые владеют ресурсами.

После урока вы должны понимать:

* чем копирование отличается от перемещения;
* что такое ресурс объекта;
* зачем нужен move semantics;
* что такое rvalue;
* почему временные объекты можно перемещать;
* что происходит с объектом после перемещения;
* зачем существуют move-конструкторы и move-операторы;
* почему перемещение обычно быстрее копирования;
* как move semantics используется в STL.

---

# Копирование объекта

Рассмотрим строку:

```cpp
std::string name = "Robot";
```

Если создать другую строку:

```cpp
std::string copy = name;
```

происходит копирование.

Теперь существуют две независимые строки:

```text
name -> "Robot"
copy -> "Robot"
```

Изменение одной не изменяет другую:

```cpp
copy += " Arm";
```

Теперь:

```text
name -> "Robot"
copy -> "Robot Arm"
```

Это правильное поведение для копирования.

---

# Почему копирование может быть дорогим

Для небольшого объекта:

```cpp
int value = 10;
int copy = value;
```

копирование практически ничего не стоит.

Но представим:

```cpp
std::vector<int> values{
    1, 2, 3, 4, 5
};
```

Если сделать:

```cpp
std::vector<int> copy = values;
```

создаётся новый массив и все элементы копируются.

Для миллиона элементов это уже серьёзная операция.

---

# Что такое ресурс объекта

Объект может владеть внешним ресурсом.

Например:

* динамической памятью;
* большим буфером;
* файловым дескриптором;
* сетевым соединением;
* другим системным ресурсом.

Упрощённо можно представить:

```text
vector
  │
  ▼
[10][20][30][40][50]
```

Сам объект `vector` хранит служебную информацию и владеет массивом данных.

При копировании нужно создать новый массив:

```text
vector A ──► [10][20][30]
vector B ──► [10][20][30]
```

При перемещении можно передать владение существующим массивом:

```text
vector A ──┐
           └──► [10][20][30]
vector B ──┘
```

Старый объект больше не владеет этим ресурсом.

---

# Перемещение

Рассмотрим:

```cpp
std::vector<int> createValues() {
    return {10, 20, 30, 40};
}
```

Можно написать:

```cpp
std::vector<int> values = createValues();
```

Функция создаёт временный объект.

Современный C++ способен использовать его внутренний ресурс непосредственно для `values`, вместо того чтобы обязательно создавать ещё одну копию массива.

Это одна из задач move semantics.

---

# Что такое временный объект

Рассмотрим:

```cpp
std::string name = "Robot";
```

`name` — именованный объект.

А результат:

```cpp
std::string{"Robot"}
```

является временным объектом.

Например:

```cpp
std::string result = std::string{"Robot"};
```

Временный объект после выполнения выражения больше не нужен.

Если его ресурс можно передать другому объекту вместо копирования, это выгоднее.

---

# lvalue и rvalue

Для понимания move semantics нужно познакомиться с двумя категориями выражений.

Упрощённо:

**lvalue** — объект, у которого есть устойчивое имя или адрес.

Например:

```cpp
std::string name = "Robot";

name
```

**rvalue** — временное значение или объект, который обычно можно безопасно переместить.

Например:

```cpp
std::string{"Robot"}
```

Также результат функции, возвращающей объект по значению, часто является подходящим источником для перемещения.

---

# Почему временный объект можно переместить

Представим:

```cpp
std::string source = "Robot";
```

Если сделать:

```cpp
std::string target = source;
```

`source` должен остаться полностью рабочим, поэтому выполняется копирование.

Но если объект уже временный:

```cpp
std::string target = std::string{"Robot"};
```

после создания `target` исходный временный объект всё равно будет уничтожен.

Нет смысла обязательно копировать его внутренний буфер, если можно передать владение ресурсом.

---

# Move constructor

Класс может иметь специальный конструктор перемещения:

```cpp
class Buffer {
public:
    Buffer(Buffer&& other);
};
```

Здесь:

```cpp
Buffer&&
```

означает ссылку на объект, который можно переместить.

Move constructor может забрать ресурсы у `other`.

Упрощённая идея:

```text
other ──► [данные]
             │
             │ передаём владение
             ▼
target ───► [данные]
```

После этого `other` должен остаться в допустимом состоянии.

---

# Состояние объекта после перемещения

После перемещения нельзя считать, что исходный объект сохранил прежнее содержимое.

Например:

```cpp
std::string source = "Robot";

std::string target = std::move(source);
```

После перемещения `source` остаётся валидным объектом, но его содержимое не следует использовать как прежнее `"Robot"`.

Для стандартных типов действует важное правило:

> перемещённый объект остаётся валидным, но его конкретное значение обычно не стоит предполагать.

Например, для `std::string` можно безопасно присвоить новое значение:

```cpp
source = "New value";
```

Но нельзя строить логику на предположении, что после перемещения строка обязательно пустая.

---

# Почему перемещение быстрее

Представим большой буфер:

```text
100 MB данных
```

Копирование означает:

```text
прочитать 100 MB
↓
создать новый буфер
↓
записать 100 MB
```

Перемещение может свестись к передаче указателя на существующий буфер и изменению нескольких служебных полей.

Упрощённо:

```text
было:

A ──► [100 MB]

стало:

A
B ──► [100 MB]
```

Сам массив данных не копировался.

# Move semantics в vector

Рассмотрим:

```cpp
std::vector<int> values;

values.push_back(10);
values.push_back(20);
values.push_back(30);
```

Когда `vector` расширяется, ему иногда требуется перенести существующие элементы в новый буфер.

Для типов, поддерживающих перемещение, стандартная библиотека может использовать move semantics, чтобы избежать ненужного копирования ресурсов.

Это одна из причин высокой эффективности современных контейнеров C++.

---

# Копирование и перемещение

Упрощённое сравнение:

```cpp
std::string a = "Robot";

std::string b = a;
```

Здесь копирование.

А:

```cpp
std::string c = std::move(a);
```

здесь разрешено перемещение.

После второго варианта `a` остаётся валидным, но его прежнее содержимое нельзя считать сохранённым.

---

# Важное ограничение

Move semantics не означает:

> всегда перемещать вместо копирования.

Если после операции нужен исходный объект с прежним содержимым, его нужно копировать.

Например:

```cpp
std::string name = "Robot";

std::string copy = name;
```

После этого обе строки должны содержать одинаковые данные.

Перемещение здесь изменило бы состояние `name`.

---

# Практический пример

Представим класс, который хранит большой буфер:

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

class Packet {
private:
    std::vector<int> data;

public:
    Packet(std::vector<int> values)
        : data(std::move(values)) {
    }

    void printSize() const {
        std::cout << data.size() << '\n';
    }
};
```

Теперь:

```cpp
std::vector<int> values{
    1, 2, 3, 4, 5
};

Packet packet(std::move(values));
```

Вместо копирования элементов `vector` его ресурс может быть передан в `Packet`.

---

# Move semantics и функции

Рассмотрим:

```cpp
std::vector<int> createData() {
    std::vector<int> values{
        1, 2, 3, 4, 5
    };

    return values;
}
```

Использование:

```cpp
std::vector<int> result = createData();
```

Современный C++ оптимизирует такой код.

Не нужно вручную писать `std::move` для обычного `return` локального объекта.

Компилятор использует специальные правила оптимизации и перемещения.

---

# Не нужно использовать std::move везде

Новички иногда начинают писать:

```cpp
std::move(value)
```

при каждой передаче объекта.

Это ошибка.

`std::move` не делает объект быстрее автоматически.

Он лишь позволяет использовать объект как источник перемещения.

Если объект ещё нужен, перемещать его нельзя.

---

# Главное

Move semantics позволяет передавать ресурсы объекта другому объекту без обязательного копирования всех данных.

Особенно полезно это для объектов, которые владеют:

* динамической памятью;
* большими буферами;
* файлами;
* сетевыми ресурсами;
* другими дорогими ресурсами.

После перемещения исходный объект остаётся валидным, но его прежнее состояние нельзя предполагать.

Главная идея:

```text
copy:

A ──► [данные]

B ──► [копия данных]


move:

A

B ──► [данные]
```

Перемещение — один из фундаментальных механизмов современного C++.
