# Область видимости и время жизни переменных

## Цель

Мы уже создавали переменные внутри `main()`, циклов и функций. Но пока не разбирали подробно, где именно переменная доступна и сколько времени она существует.

Эти понятия особенно важны в C++, потому что язык позволяет очень точно управлять структурой программы и временем существования объектов.

В этом уроке разберём область видимости, локальные и глобальные переменные, блоки `{}`, время жизни и несколько типичных ошибок.

---

# Что такое область видимости

Область видимости определяет, где в исходном коде можно обратиться к имени переменной.

Например:

```cpp
int main() {
    int value = 10;

    std::cout << value << '\n';
}
```

Здесь `value` доступна внутри `main()` после места её объявления.

Но если создать переменную внутри отдельного блока:

```cpp
{
    int value = 10;
}
```

после закрывающей фигурной скобки:

```cpp
}
```

она больше недоступна.

---

# Блок кода

Блок обозначается фигурными скобками:

```cpp
{
    // код блока
}
```

Блоки используются не только в функциях.

Они появляются в:

```cpp
if
for
while
switch
```

и других конструкциях.

Например:

```cpp
if (true) {
    int value = 10;

    std::cout << value << '\n';
}
```

Переменная `value` существует в области этого блока.

---

# Локальная переменная

Переменная, объявленная внутри функции, является локальной для этой функции.

Например:

```cpp
void process() {
    int value = 10;

    std::cout << value << '\n';
}
```

Из другой функции нельзя просто написать:

```cpp
std::cout << value;
```

потому что `value` находится в другой области видимости.

---

# Переменная main

Например:

```cpp
int main() {
    int number = 10;

    std::cout << number << '\n';

    return 0;
}
```

`number` доступна внутри `main()`, но не является автоматически доступной для других функций.

Если другая функция должна получить это значение, его обычно передают через параметр:

```cpp
void printNumber(int value) {
    std::cout << value << '\n';
}
```

Вызов:

```cpp
int number = 10;

printNumber(number);
```

Это лучше, чем пытаться сделать все переменные глобальными.

---

# Область видимости внутри if

Рассмотрим:

```cpp
if (true) {
    int value = 10;

    std::cout << value << '\n';
}
```

Здесь `value` доступна внутри блока `if`.

Но:

```cpp
if (true) {
    int value = 10;
}

std::cout << value << '\n';
```

такой код некорректен.

После `}` переменная больше не находится в своей области видимости.

---

# Область видимости цикла

То же правило действует для циклов.

Например:

```cpp
for (int i = 0; i < 5; i++) {
    std::cout << i << '\n';
}
```

Переменная:

```cpp
i
```

создана в конструкции `for`.

После завершения цикла обратиться к ней нельзя:

```cpp
std::cout << i;
```

---

# Вложенная область видимости

Можно создавать блоки внутри других блоков:

```cpp
int main() {
    int a = 10;

    {
        int b = 20;

        std::cout << a << '\n';
        std::cout << b << '\n';
    }

    std::cout << a << '\n';
}
```

Внутренний блок видит переменные внешнего блока.

Поэтому внутри можно использовать:

```text
a
b
```

Но после выхода из внутреннего блока доступна только:

```text
a
```

---

# Внешняя и внутренняя область

Упрощённо можно представить так:

```text
внешний блок
│
│  a
│
└── внутренний блок
    │
    │  b
    │
    └── конец
```

Внутренний блок может видеть внешние переменные.

Внешний блок не может видеть переменные, созданные внутри внутреннего блока.

---

# Скрытие имени

Можно создать переменную с таким же именем во вложенном блоке:

```cpp
int value = 10;

{
    int value = 20;

    std::cout << value << '\n';
}
```

Внутри блока будет использоваться:

```text
20
```

а не:

```text
10
```

После выхода из блока снова доступно внешнее `value`.

Такое поведение называется скрытием имени.

На первых этапах лучше не использовать одинаковые имена без необходимости, потому что это может запутывать код.

---

# Глобальные переменные

Переменную можно создать за пределами функций:

```cpp
#include <iostream>

int counter = 0;

int main() {
    std::cout << counter << '\n';

    return 0;
}
```

Такая переменная находится в глобальной области видимости.

Её можно использовать из разных функций в пределах соответствующей области программы.

---

# Почему глобальными переменными не стоит злоупотреблять

Глобальная переменная может быть изменена из большого количества мест.

Например:

```cpp
int battery = 100;
```

Если десятки функций могут менять:

```cpp
battery
```

становится трудно понять, почему в определённый момент значение стало другим.

Это усложняет:

* чтение программы;
* отладку;
* тестирование;
* понимание зависимостей между функциями.

Поэтому обычно лучше передавать данные явно через параметры и возвращаемые значения.

---

# Время жизни переменной

Область видимости отвечает на вопрос:

> где переменную можно использовать по имени?

Время жизни отвечает на другой вопрос:

> сколько времени существует объект, который стоит за этой переменной?

Это связанные, но разные понятия.

---

# Локальная переменная

Рассмотрим:

```cpp
void process() {
    int value = 10;

    std::cout << value << '\n';
}
```

При входе в функцию создаётся локальная переменная `value`.

Когда выполнение покидает её область жизни, переменная перестаёт существовать.

При следующем вызове функции:

```cpp
process();
process();
```

создаётся новая локальная переменная.

---

# Важное различие

Не стоит думать:

> переменная существует всегда, просто иногда к ней нет доступа.

Для обычной локальной переменной это не так.

Её объект создаётся и уничтожается в соответствии с правилами времени жизни.

---

# Переменная внутри блока

Например:

```cpp
{
    int value = 10;

    std::cout << value << '\n';
}
```

Когда выполнение входит в блок, переменная создаётся.

Когда выполнение покидает блок, её время жизни заканчивается.

---

# Переменная внутри цикла

Рассмотрим:

```cpp
for (int i = 0; i < 3; i++) {
    int value = i * 10;

    std::cout << value << '\n';
}
```

На каждой итерации `value` является локальной переменной тела цикла.

Её существование связано с соответствующей итерацией и областью блока.

Главное здесь — не пытаться использовать её после блока цикла.

---

# static локальная переменная

Существует специальный случай:

```cpp
static int counter = 0;
```

Например:

```cpp
void countCalls() {
    static int counter = 0;

    counter++;

    std::cout << counter << '\n';
}
```

Если вызвать:

```cpp
countCalls();
countCalls();
countCalls();
```

получим:

```text
1
2
3
```

Почему?

Потому что `static` локальная переменная сохраняет своё значение между вызовами функции.

Её область видимости остаётся локальной функции, но время жизни отличается от обычной локальной переменной.

---

# Обычная локальная переменная

Без `static`:

```cpp
void countCalls() {
    int counter = 0;

    counter++;

    std::cout << counter << '\n';
}
```

Каждый вызов создаёт новый `counter`.

Поэтому:

```cpp
countCalls();
countCalls();
countCalls();
```

выведет:

```text
1
1
1
```

---

# Параметры функции

Параметры также являются локальными переменными функции.

Например:

```cpp
int square(int value) {
    return value * value;
}
```

`value` существует внутри вызова функции.

Каждый вызов получает своё значение параметра:

```cpp
square(5);
square(10);
```

---

# Практический пример

Рассмотрим:

```cpp
#include <iostream>

void process(int value) {
    int doubled = value * 2;

    if (doubled > 10) {
        int messageCode = 100;

        std::cout << doubled << '\n';
        std::cout << messageCode << '\n';
    }
}

int main() {
    int number = 7;

    process(number);

    return 0;
}
```

Здесь существуют разные области:

```text
main
└── number

process
├── value
├── doubled
└── if
    └── messageCode
```

Каждая переменная имеет свою область видимости.

---

# Почему это важно

Понимание областей видимости становится особенно важным, когда программа становится большой.

Например, если у нас есть:

```text
main()
readSensors()
calculateState()
updateMotors()
```

каждая функция должна иметь понятные данные, с которыми она работает.

Если все функции используют десятки глобальных переменных, связи между частями программы становятся запутанными.

Если же данные передаются явно:

```cpp
calculateState(temperature, battery);
```

становится гораздо легче понять, от чего зависит функция.

# Главное

Область видимости определяет, **где имя переменной доступно в исходном коде**.

Время жизни определяет, **сколько времени существует соответствующий объект**.

Для обычных локальных переменных характерно следующее:

```text
вход в область
    ↓
создание переменной
    ↓
работа с переменной
    ↓
выход из области
    ↓
завершение времени жизни
```

Важно помнить:

* переменная внутри блока не доступна за пределами этого блока;
* параметры функции являются локальными для функции;
* внутренний блок может видеть переменные внешнего блока;
* внешняя область не видит переменные внутреннего блока;
* глобальные переменные доступны шире, но ими не стоит злоупотреблять;
* `static` локальная переменная сохраняет значение между вызовами;
* область видимости и время жизни — разные понятия.

Эти правила станут особенно важными, когда мы перейдём к указателям, ссылкам, объектам и управлению памятью.
