# Умные указатели

## Цель

В предыдущих уроках мы разбирали ручное управление динамической памятью через `new` и `delete`. Такой подход возможен, но он легко приводит к утечкам памяти, висячим указателям и ошибкам владения.

Современный C++ предлагает умные указатели — специальные классы, которые автоматически управляют временем жизни динамических объектов.

После урока вы должны понимать:

* зачем нужны умные указатели;
* что такое владение объектом;
* чем `unique_ptr` отличается от `shared_ptr`;
* зачем нужен `weak_ptr`;
* почему умные указатели относятся к RAII;
* когда использовать каждый тип;
* почему `shared_ptr` не стоит использовать везде;
* как создавать объекты через `make_unique` и `make_shared`.

---

# Проблема обычных указателей

Рассмотрим:

```cpp
int* value = new int(10);
```

Теперь память выделена вручную.

Чтобы освободить её:

```cpp
delete value;
```

Если забыть `delete`:

```cpp
int* value = new int(10);

// забыли delete
```

возникает утечка памяти.

---

# Утечка памяти

Утечка происходит, когда программа больше не может получить доступ к выделенному объекту, но память ещё занята.

Например:

```cpp
int* value = new int(10);

value = nullptr;
```

Что произошло?

Адрес выделенной памяти был потерян.

Освободить этот объект уже невозможно.

Память останется занятой до завершения процесса.

---

# Другая проблема

Даже если `delete` используется, можно сделать ошибку:

```cpp
int* value = new int(10);

delete value;

std::cout << *value;
```

Указатель всё ещё содержит старый адрес, но объект уже уничтожен.

Такой указатель называется висячим.

---

# Идея умного указателя

Умный указатель — это объект, который хранит указатель на другой объект и автоматически управляет его временем жизни.

Например:

```cpp
std::unique_ptr<int> value =
    std::make_unique<int>(10);
```

Когда `value` уничтожается, объект `int` также освобождается.

Вручную писать:

```cpp
delete
```

не требуется.

---

# RAII

Умные указатели используют принцип RAII.

RAII означает:

> ресурс привязывается к времени жизни объекта.

Упрощённо:

```text
создали объект
      ↓
получили ресурс
      ↓
работаем
      ↓
объект уничтожается
      ↓
ресурс автоматически освобождается
```

Это один из фундаментальных принципов современного C++.

---

# Основные умные указатели

В стандартной библиотеке есть три основных типа:

```text
std::unique_ptr
std::shared_ptr
std::weak_ptr
```

Их назначение различается.

---

# unique_ptr

`std::unique_ptr` означает:

> объектом владеет один владелец.

Например:

```cpp
auto sensor =
    std::make_unique<int>(25);
```

Схематично:

```text
sensor
  │
  ▼
[25]
```

Пока `sensor` существует, он владеет объектом.

Когда `sensor` уничтожается, объект освобождается.

---

# Почему unique_ptr нельзя копировать

Если бы можно было:

```cpp
auto a = std::make_unique<int>(10);

auto b = a;
```

получились бы два владельца одного объекта.

Это нарушило бы принцип уникального владения.

Поэтому такой код запрещён.

---

# Передача владения

Вместо копирования используется перемещение:

```cpp
auto a = std::make_unique<int>(10);

auto b = std::move(a);
```

Теперь:

```text
a -> nullptr
b -> объект 10
```

Владение перешло к `b`.

---

# shared_ptr

Иногда один объект действительно должен принадлежать нескольким владельцам.

Для этого существует:

```cpp
std::shared_ptr
```

Например:

```cpp
auto sensor =
    std::make_shared<int>(25);
```

Можно создать ещё один `shared_ptr`:

```cpp
auto copy = sensor;
```

Теперь оба указателя владеют одним объектом.

Упрощённо:

```text
sensor ──┐
         ├──► [25]
copy ────┘
```

---

# Счётчик ссылок

`shared_ptr` хранит информацию о количестве владельцев.

Например:

```cpp
auto a = std::make_shared<int>(10);
```

Количество владельцев:

```text
1
```

После:

```cpp
auto b = a;
```

становится:

```text
2
```

После:

```cpp
b.reset();
```

снова:

```text
1
```

Когда последний `shared_ptr` перестаёт владеть объектом, объект освобождается.

---

# weak_ptr

`std::weak_ptr` используется для наблюдения за объектом, которым владеет `shared_ptr`, без увеличения счётчика владельцев.

Например:

```cpp
auto shared =
    std::make_shared<int>(10);

std::weak_ptr<int> weak = shared;
```

Теперь:

```text
shared ──► [10]
weak   ──► наблюдает
```

`weak_ptr` не владеет объектом.

---

# Зачем нужен weak_ptr

Главная причина — предотвращение циклических ссылок.

Представим:

```text
A владеет B
B владеет A
```

Если оба используют `shared_ptr`, счётчик никогда не станет нулём.

Получается:

```text
A ──shared──► B
B ──shared──► A
```

Объекты могут остаться в памяти навсегда.

`weak_ptr` позволяет создать ссылку без владения:

```text
A ──shared──► B
B ──weak────► A
```

Теперь цикл владения отсутствует.

---

# Почему unique_ptr обычно предпочтительнее

Если объект должен иметь одного владельца:

```cpp
std::unique_ptr
```

обычно является более подходящим выбором.

Он:

* проще;
* не требует счётчика ссылок;
* не имеет стоимости совместного владения;
* явно показывает архитектуру владения.

`shared_ptr` следует использовать тогда, когда действительно необходимо совместное владение.

---

# Создание объектов

Для `unique_ptr`:

```cpp
auto device =
    std::make_unique<Device>();
```

Для `shared_ptr`:

```cpp
auto device =
    std::make_shared<Device>();
```

Это предпочтительнее ручного:

```cpp
std::unique_ptr<Device>(
    new Device()
);
```

и:

```cpp
std::shared_ptr<Device>(
    new Device()
);
```

---

# Умные указатели и классы

Рассмотрим:

```cpp
class Robot {
private:
    std::unique_ptr<Sensor> sensor;

public:
    Robot()
        : sensor(std::make_unique<Sensor>()) {
    }
};
```

Когда объект `Robot` уничтожается, его `sensor` тоже уничтожается автоматически.

Не нужен:

```cpp
~Robot() {
    delete sensor;
}
```

Это и есть преимущество RAII.

---

# Умные указатели и полиморфизм

Они хорошо работают вместе с виртуальными функциями:

```cpp
class Device {
public:
    virtual void start() = 0;
    virtual ~Device() = default;
};

class Motor : public Device {
public:
    void start() override {
        std::cout << "Motor started\n";
    }
};
```

Можно хранить:

```cpp
std::vector<std::unique_ptr<Device>> devices;
```

Добавлять:

```cpp
devices.push_back(
    std::make_unique<Motor>()
);
```

И затем:

```cpp
for (const auto& device : devices) {
    device->start();
}
```

Это очень распространённый современный C++-паттерн.

---

# Не каждый объект должен быть в heap

Важно понимать:

> умный указатель не означает, что объект обязательно должен быть динамическим.

Если объект имеет обычное время жизни:

```cpp
Sensor sensor;
```

этого часто достаточно.

Не нужно автоматически делать:

```cpp
auto sensor =
    std::make_unique<Sensor>();
```

Умный указатель нужен тогда, когда действительно требуется динамическое владение или особая модель времени жизни.

---

# Передача в функцию

Если функция просто использует объект и не становится владельцем, не обязательно передавать умный указатель.

Например:

```cpp
void printSensor(const Sensor& sensor) {
    std::cout << sensor.value;
}
```

Вызов:

```cpp
printSensor(sensor);
```

Если функция должна владеть объектом, можно передать `unique_ptr`:

```cpp
void setSensor(
    std::unique_ptr<Sensor> sensor
) {
    // функция становится владельцем
}
```

Вызов:

```cpp
setSensor(std::move(sensor));
```

# Практический пример

Создадим менеджер устройств:

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <vector>

class Device {
public:
    virtual void start() = 0;
    virtual ~Device() = default;
};

class Motor : public Device {
private:
    std::string name;

public:
    explicit Motor(std::string name)
        : name(std::move(name)) {
    }

    void start() override {
        std::cout << name
                  << " started\n";
    }
};

int main() {
    std::vector<std::unique_ptr<Device>> devices;

    devices.push_back(
        std::make_unique<Motor>("Motor 1")
    );

    devices.push_back(
        std::make_unique<Motor>("Motor 2")
    );

    for (const auto& device : devices) {
        device->start();
    }
}
```

Здесь `vector` владеет всеми объектами устройств.

Когда `devices` уничтожается, каждый `unique_ptr` автоматически освобождает свой объект.

---

# Главное

Основные умные указатели:

```text
unique_ptr
    один владелец

shared_ptr
    несколько владельцев

weak_ptr
    наблюдение без владения
```

В большинстве случаев, если объект должен иметь одного владельца, следует начинать с:

```cpp
std::unique_ptr
```

Для создания:

```cpp
std::make_unique<T>()
```

или:

```cpp
std::make_shared<T>()
```

Умные указатели позволяют строить код без ручного `delete` и являются важной частью современного C++.
