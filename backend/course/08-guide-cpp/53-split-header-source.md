# Разделение программы на .h и .cpp

## Цель

До этого большинство программ мы писали в одном файле. Для небольших примеров это удобно, но реальные C++ проекты быстро становятся слишком большими для такого подхода.

В этом уроке разберём, зачем программа разделяется на заголовочные файлы `.h` и исходные файлы `.cpp`, что такое объявление и определение, как несколько файлов превращаются в одну программу и какую роль играет компоновщик.

После урока вы должны понимать:

* зачем разделять код на `.h` и `.cpp`;
* чем объявление отличается от определения;
* что обычно находится в заголовочном файле;
* что находится в `.cpp`;
* как компилятор обрабатывает несколько исходных файлов;
* что делает linker;
* зачем нужен `#pragma once`;
* какие ошибки возникают при неправильном разделении.

---

## Зачем вообще разделять код

Представим программу управления роботом.

В ней могут быть:

```text
Robot
Motor
Sensor
Controller
Logger
Network
Configuration
```

Если всё поместить в один файл:

```text
main.cpp
```

он быстро превратится в огромный набор классов и функций.

Гораздо удобнее разделить программу:

```text
main.cpp
robot.cpp
robot.h
motor.cpp
motor.h
sensor.cpp
sensor.h
```

Каждый компонент получает собственный файл.

---

## Идея объявления и определения

Одна из главных идей C++ — разделение:

```text
что существует
```

и:

```text
как оно реализовано
```

Например, мы хотим функцию:

```cpp
int add(int a, int b);
```

Это **объявление**.

Оно сообщает компилятору:

> существует функция `add`, которая принимает два `int` и возвращает `int`.

А вот:

```cpp
int add(int a, int b) {
    return a + b;
}
```

это уже **определение**.

Оно содержит реализацию функции.

---

## Заголовочный файл

Объявление можно поместить в:

```text
math_utils.h
```

```cpp
#pragma once

int add(int a, int b);
```

Теперь другие файлы могут подключить этот заголовок:

```cpp
#include "math_utils.h"
```

и использовать функцию.

---

## Исходный файл

Реализация находится в:

```text
math_utils.cpp
```

```cpp
#include "math_utils.h"

int add(int a, int b) {
    return a + b;
}
```

Получается:

```text
math_utils.h
    ↓
объявление

math_utils.cpp
    ↓
реализация
```

---

## main.cpp

Теперь можно написать:

```cpp
#include <iostream>
#include "math_utils.h"

int main() {
    std::cout << add(10, 20) << '\n';
}
```

Программа использует функцию, хотя её реализация находится в другом `.cpp`.

---

## Как компилируется такая программа

У нас есть:

```text
main.cpp
math_utils.cpp
```

Каждый `.cpp` компилируется отдельно.

Упрощённо:

```text
main.cpp
   ↓
компилятор
   ↓
main.o

math_utils.cpp
   ↓
компилятор
   ↓
math_utils.o
```

После этого linker объединяет объектные файлы:

```text
main.o
   +
math_utils.o
   ↓
программа
```

На Windows объектные файлы и конечные файлы могут иметь другие расширения, но принцип тот же.

---

## Что делает #include

Очень важно понимать: `#include` не является обычным механизмом импорта как в некоторых других языках.

Препроцессор фактически вставляет содержимое подключаемого файла в исходный текст.

Например:

```cpp
#include "math_utils.h"

int main() {
    return add(1, 2);
}
```

концептуально превращается в:

```cpp
int add(int a, int b);

int main() {
    return add(1, 2);
}
```

Поэтому заголовочный файл должен содержать информацию, которая необходима компилятору.

---

## Зачем нужен #pragma once

Если один заголовочный файл подключается несколько раз, его содержимое может оказаться обработанным повторно.

Для защиты обычно пишут:

```cpp
#pragma once
```

Например:

```cpp
#pragma once

class Motor {
public:
    void start();
};
```

Это говорит компилятору, что данный заголовок должен быть обработан только один раз в рамках текущей единицы трансляции.

---

## Альтернативный вариант

Классический способ — include guard:

```cpp
#ifndef MOTOR_H
#define MOTOR_H

class Motor {
public:
    void start();
};

#endif
```

Сегодня в большинстве проектов можно встретить:

```cpp
#pragma once
```

Он проще и хорошо поддерживается современными компиляторами.

---

## Класс в .h и .cpp

Рассмотрим простой двигатель.

### motor.h

```cpp
#pragma once

class Motor {
public:
    void start();
    void stop();

private:
    bool running_ = false;
};
```

Здесь описан интерфейс класса.

---

### motor.cpp

```cpp
#include "motor.h"
#include <iostream>

void Motor::start() {
    running_ = true;
    std::cout << "Motor started\n";
}

void Motor::stop() {
    running_ = false;
    std::cout << "Motor stopped\n";
}
```

Здесь находятся реализации методов.

---

### main.cpp

```cpp
#include "motor.h"

int main() {
    Motor motor;

    motor.start();
    motor.stop();
}
```

Получилась простая структура:

```text
main.cpp
    ↓
motor.h
    ↓
motor.cpp
```

---

## Почему это удобно

Теперь `main.cpp` не должен знать, как именно работает двигатель.

Ему достаточно знать публичный интерфейс:

```cpp
class Motor {
public:
    void start();
    void stop();
};
```

Внутреннюю реализацию можно изменить:

```cpp
void Motor::start() {
    // другая реализация
}
```

а код пользователя класса может остаться прежним.

Это один из важных шагов к созданию модульных программ.

---

## Что должно находиться в .h

Обычно в заголовочном файле находятся:

* объявления функций;
* объявления классов;
* объявления структур;
* перечисления;
* константы и типы, которые должны быть доступны другим файлам;
* шаблоны;
* небольшие `inline`-реализации;
* публичный интерфейс компонента.

Например:

```cpp
#pragma once

class Sensor {
public:
    double read();
    bool connected() const;
};
```

---

## Что должно находиться в .cpp

В `.cpp` обычно находятся реализации:

```cpp
double Sensor::read() {
    return 25.4;
}

bool Sensor::connected() const {
    return true;
}
```

Это позволяет скрыть детали реализации от остального проекта.

---

## Объявление без определения

Можно написать:

```cpp
int calculate(int value);
```

и использовать функцию:

```cpp
int main() {
    return calculate(10);
}
```

Компилятор может принять этот код, потому что знает о существовании функции.

Но если определения нигде нет, linker не сможет собрать готовую программу.

Получится ошибка компоновки, например сообщение о том, что символ `calculate` не найден.

Это важное различие:

```text
компилятор:
"я знаю, что функция существует"

linker:
"я не нашёл её реализацию"
```

---

## Определение без объявления

Можно определить функцию прямо в `.cpp`:

```cpp
int calculate(int value) {
    return value * 2;
}
```

Но другой `.cpp` не сможет нормально использовать её, если не знает о существовании функции.

Поэтому для публичных функций объявление обычно помещают в `.h`.

## Компиляция нескольких файлов

При использовании `g++` можно передать несколько `.cpp`:

```text
g++ main.cpp robot.cpp -o robot
```

Компилятор обработает оба исходных файла и затем выполнит компоновку.

Если проект становится большим, вручную перечислять файлы неудобно. Поэтому позже мы познакомимся с CMake.

---

## Частая ошибка

Неправильно:

```cpp
// robot.h

class Robot {
public:
    void start() {
        // большая реализация
    }
};
```

Так делать можно технически, но при большом проекте заголовочные файлы начинают содержать слишком много реализации.

Обычно лучше:

```cpp
// robot.h

class Robot {
public:
    void start();
};
```

а реализацию:

```cpp
// robot.cpp

#include "robot.h"

void Robot::start() {
    // реализация
}
```

---

## Ещё одна распространённая ошибка

Не нужно подключать `.cpp`:

```cpp
#include "robot.cpp"
```

Обычно это неправильная архитектура.

Подключаются заголовки:

```cpp
#include "robot.h"
```

А `.cpp` компилируются отдельно и затем связываются linker'ом.

---

## Практический пример для робота

Представим:

```text
Robot
 ├── Motor
 └── Sensor
```

Можно сделать:

```text
robot.h
robot.cpp
motor.h
motor.cpp
sensor.h
sensor.cpp
main.cpp
```

Каждый компонент имеет свой интерфейс и реализацию.

`main.cpp` работает с ними через публичные интерфейсы:

```cpp
#include "motor.h"
#include "sensor.h"

int main() {
    Motor motor;
    Sensor sensor;

    motor.start();

    if (sensor.connected()) {
        // работа с датчиком
    }
}
```

Так постепенно строится настоящая архитектура C++ проекта.

## Главное

В реальном C++ проекте код обычно разделяется на компоненты.

Заголовок:

```cpp
// motor.h

class Motor {
public:
    void start();
};
```

Реализация:

```cpp
// motor.cpp

#include "motor.h"

void Motor::start() {
}
```

Использование:

```cpp
// main.cpp

#include "motor.h"

int main() {
    Motor motor;
    motor.start();
}
```

Главная идея:

> `.h` обычно описывает интерфейс компонента, а `.cpp` содержит его реализацию.

Дальше эту модель нужно научиться правильно использовать с заголовочными файлами, зависимостями и пространствами имён.
