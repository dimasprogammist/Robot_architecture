# C++ и операционная система

## Цель

До этого момента мы в основном рассматривали C++ как язык, на котором можно создавать отдельные программы. Теперь посмотрим шире: программа не работает сама по себе. Когда мы запускаем приложение, оно взаимодействует с операционной системой, памятью, файлами, процессами, потоками, устройствами и сетью.

После урока вы должны понимать:

* какую роль операционная система играет во время работы C++ программы;
* что такое процесс;
* чем программа отличается от процесса;
* как программа получает ресурсы операционной системы;
* как C++ взаимодействует с файлами, процессами и другими системными ресурсами;
* почему системное программирование отличается от обычного прикладного кода.

---

## C++ работает поверх операционной системы

Когда мы пишем:

```cpp
#include <iostream>

int main() {
    std::cout << "Hello\n";
}
```

может показаться, что компьютер просто выполняет инструкции C++.

На самом деле между нашей программой и аппаратным обеспечением находится несколько уровней.

Упрощённо:

```text
C++ программа
      ↓
стандартная библиотека / системные библиотеки
      ↓
операционная система
      ↓
драйверы
      ↓
аппаратное обеспечение
```

Например, когда программа записывает данные в файл, она не управляет непосредственно магнитной поверхностью диска или ячейками SSD.

Программа обращается к механизмам операционной системы, а ОС уже взаимодействует с файловой системой и драйвером устройства.

То же самое происходит с сетью, клавиатурой, экраном, процессами и многими другими ресурсами.

---

## Что делает операционная система

Операционная система управляет ресурсами компьютера и предоставляет программам удобный интерфейс для работы с ними.

К основным задачам ОС относятся:

* управление процессами;
* управление памятью;
* работа с файлами;
* управление устройствами;
* сетевое взаимодействие;
* управление правами доступа;
* планирование выполнения процессов и потоков.

Например, если одновременно запущены:

```text
браузер
IDE
терминал
C++ программа
музыкальный проигрыватель
```

процессор физически не выполняет все эти программы одновременно на одном ядре.

Операционная система распределяет процессорное время между процессами и потоками.

Для пользователя при этом создаётся ощущение одновременной работы.

---

## Программа и процесс — не одно и то же

Это важное различие.

**Программа** — это набор инструкций и данных, сохранённый, например, в `.exe` файле.

**Процесс** — это уже выполняющийся экземпляр программы.

Например, существует файл:

```text
robot_monitor.exe
```

Если его запустить один раз, ОС создаст процесс.

Если запустить его второй раз и программа разрешает несколько экземпляров, появится ещё один процесс.

Можно представить это так:

```text
robot_monitor.exe
       │
       ├── процесс №1
       │
       └── процесс №2
```

Один и тот же исполняемый файл может стать основой нескольких процессов.

---

## Что находится внутри процесса

Процесс не является просто «запущенным файлом».

ОС выделяет процессу необходимые ресурсы.

Упрощённо процесс можно представить так:

```text
Процесс
├── код программы
├── глобальные данные
├── heap
├── stack
├── открытые файлы
├── сетевые ресурсы
└── потоки выполнения
```

Например:

```cpp
int global_value = 10;

int main() {
    int local_value = 20;
}
```

`global_value` и `local_value` находятся в разных областях памяти процесса.

При этом конкретное расположение и организация памяти зависят от платформы и реализации.

---

## Стек и куча

Мы уже рассматривали память программы.

Теперь важно связать это с операционной системой.

Например:

```cpp
void process() {
    int value = 42;
}
```

Локальная переменная `value` обычно размещается в стеке текущего потока.

Динамически выделенная память:

```cpp
int* value = new int(42);
```

обычно размещается в динамической памяти, которую называют heap.

Но процесс также имеет множество других ресурсов.

Например:

```text
процесс
 ├── виртуальная память
 ├── дескрипторы ресурсов
 ├── потоки
 └── права доступа
```

---

## Виртуальная память

Современные операционные системы обычно предоставляют процессам виртуальное адресное пространство.

Это означает, что программа работает с адресами, которые выглядят как адреса её собственной памяти.

Например:

```text
Процесс A
0x1000 → свои данные

Процесс B
0x1000 → другие данные
```

Один и тот же виртуальный адрес в разных процессах не обязан обозначать одну и ту же физическую память.

Это позволяет операционной системе изолировать процессы друг от друга.

Если одна программа содержит ошибку, она не должна просто так получить доступ к памяти другого процесса.

---

## Почему программа не может делать всё напрямую

Представим программу:

```cpp
int main() {
    // записать данные непосредственно на SSD
}
```

У стандартного C++ нет операции:

```cpp
ssd.write_physical_sector(...);
```

И это сделано не случайно.

Прямой доступ к аппаратуре может быть опасным.

Операционная система должна контролировать:

* кто обращается к устройству;
* какие операции разрешены;
* какие ресурсы заняты;
* какие данные можно читать;
* какие данные можно изменять.

Поэтому прикладные программы обычно используют системные интерфейсы.

---

## Системные вызовы

Операционная система предоставляет механизм, через который программа может попросить ОС выполнить определённую операцию.

Такой механизм часто называют **системными вызовами**.

Например, программа может попросить ОС:

```text
открыть файл
прочитать данные
записать данные
создать процесс
создать поток
создать сетевое соединение
выделить ресурсы
```

Конкретный API зависит от операционной системы.

Например:

```text
Windows → WinAPI
Linux   → POSIX / Linux system calls
```

Поэтому системный C++ код часто оказывается платформозависимым.

---

## Стандартный C++ и API операционной системы

C++ предоставляет стандартную библиотеку.

Например:

```cpp
#include <fstream>

std::ofstream file("data.txt");
file << "Hello";
```

Это стандартный C++ интерфейс работы с файлами.

Под капотом реализация стандартной библиотеки взаимодействует с операционной системой.

Если же нам нужна специфическая функция Windows, можно использовать соответствующий системный API.

Например, Windows предоставляет собственные типы и функции.

Это позволяет получить доступ к возможностям, которых нет в стандартном C++.

Но появляется зависимость:

```text
код
 ↓
Windows API
 ↓
только Windows
```

Поэтому хороший архитектурный подход — изолировать платформенный код.

---

## Платформозависимый код

Предположим, приложение должно получить имя компьютера.

Можно сделать отдельный интерфейс:

```cpp
#include <string>

std::string getComputerName();
```

А реализацию сделать отдельно для Windows и Linux.

Например:

```text
system/
├── system.hpp
├── windows.cpp
└── linux.cpp
```

Основная программа при этом не обязана знать, каким именно API пользуется операционная система.

Это один из важных архитектурных принципов.

---

## Переменные окружения

Операционная система может передавать процессу различные параметры через окружение.

Например:

```text
PATH
TEMP
HOME
USERNAME
```

В C++ можно получить значение переменной окружения через `std::getenv`.

```cpp
#include <cstdlib>
#include <iostream>

int main() {
    const char* path = std::getenv("PATH");

    if (path != nullptr) {
        std::cout << path << '\n';
    }
}
```

Важно помнить, что `std::getenv` возвращает указатель.

Если переменной нет, результат может быть `nullptr`.

## Текущий рабочий каталог

У процесса обычно есть понятие текущего рабочего каталога.

Например:

```text
C:\Projects\RobotMonitor
```

Если программа открывает:

```cpp
std::ifstream file("config.txt");
```

путь:

```text
config.txt
```

является относительным.

Операционная система и библиотека будут искать файл относительно текущего рабочего каталога процесса.

Это объясняет распространённую проблему:

```text
В IDE программа работает.
В .exe программа не находит config.txt.
```

Причина часто заключается не в отсутствии файла, а в другом текущем каталоге.

---

## Пути и файловая система

Современный C++ предоставляет `std::filesystem`.

Например:

```cpp
#include <filesystem>
#include <iostream>

int main() {
    std::cout << std::filesystem::current_path() << '\n';
}
```

Можно проверить существование файла:

```cpp
if (std::filesystem::exists("config.json")) {
    std::cout << "Файл найден\n";
}
```

Можно получить размер:

```cpp
auto size = std::filesystem::file_size("config.json");

std::cout << size << " bytes\n";
```

`std::filesystem` особенно полезен для программ, которые работают с конфигурациями, логами, каталогами и ресурсами.

---

## Права доступа

Операционная система контролирует доступ к ресурсам.

Например, программа может попытаться открыть файл:

```cpp
std::ofstream file("system_config.txt");
```

Но операция может завершиться неудачно.

Причины:

* файл отсутствует;
* нет прав на запись;
* каталог недоступен;
* файл используется другой программой;
* путь некорректный;
* устройство недоступно.

Поэтому системный код должен всегда учитывать ошибки.

```cpp
std::ofstream file("data.txt");

if (!file) {
    std::cerr << "Не удалось открыть файл\n";
    return 1;
}
```

---

## Процессы

Иногда программе необходимо запускать другие программы.

Например, промышленное приложение может запускать:

```text
архиватор
внешний диагностический инструмент
скрипт
служебную программу
```

Но создание процессов — уже задача операционной системы.

Стандартный C++ не предоставляет универсального высокоуровневого API для полноценного управления процессами на всех платформах.

Поэтому здесь часто используются:

* API Windows;
* POSIX/Linux API;
* сторонние библиотеки.

---

## Потоки

Процесс может содержать несколько потоков выполнения.

Например:

```text
Процесс мониторинга
│
├── основной поток GUI
├── поток чтения датчиков
├── поток записи логов
└── поток сетевого обмена
```

Каждый поток выполняет инструкции независимо от других потоков.

Тема потоков будет рассмотрена подробнее в следующих уроках.

---

## C++ в системных программах

C++ особенно полезен там, где важны:

* высокая производительность;
* контроль ресурсов;
* низкие задержки;
* взаимодействие с ОС;
* работа с оборудованием;
* сетевое взаимодействие;
* многопоточность.

Например:

```text
драйверные компоненты
серверы
робототехника
игровые движки
промышленное ПО
системы управления
embedded
```

Но C++ не означает автоматический доступ к железу.

Язык предоставляет инструменты для написания такого ПО, а конкретный доступ к системе определяется платформой, библиотеками и архитектурой приложения.

---

## Пример: программа мониторинга

Представим приложение мониторинга промышленного сервера.

Оно должно:

```text
1. Запуститься.
2. Прочитать config.json.
3. Создать сетевое соединение.
4. Проверить устройство.
5. Записать результат в log.txt.
6. Повторить проверку.
```

Внутри можно получить такую структуру:

```text
Операционная система
        │
        ├── процесс приложения
        │      │
        │      ├── конфигурация
        │      ├── сетевое соединение
        │      ├── файлы логов
        │      └── потоки
        │
        └── сетевой стек
```

Таким образом, обычная прикладная задача постепенно превращается в задачу системного программирования.

---

## Почему это важно для робототехники

Робототехническая программа редко является изолированным консольным приложением.

Она может одновременно:

```text
читать датчики
     ↓
обрабатывать данные
     ↓
управлять двигателями
     ↓
обмениваться по сети
     ↓
записывать логи
     ↓
показывать состояние оператору
```

Все эти задачи используют ресурсы компьютера.

Поэтому разработчику нужно понимать не только C++, но и то, как операционная система управляет процессами, памятью, файлами, потоками и устройствами.

---

## Главное

Важно запомнить несколько вещей.

**Программа** — это код и данные, которые можно запустить.

**Процесс** — экземпляр программы, выполняющийся под управлением ОС.

**Операционная система** управляет ресурсами компьютера и предоставляет приложениям системные интерфейсы.

C++ может работать на уровне стандартной библиотеки:

```cpp
std::filesystem
std::fstream
std::thread
```

или взаимодействовать непосредственно с API конкретной ОС.

Чем ближе программа к операционной системе, тем больше появляется платформенных деталей.
