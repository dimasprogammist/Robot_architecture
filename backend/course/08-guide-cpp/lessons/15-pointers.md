# Указатели

## Цель

В предыдущем уроке мы выяснили, что переменная занимает определённое место в памяти и имеет адрес. Указатель позволяет сохранить такой адрес и работать с объектом через него.

Указатели — одна из самых важных и одновременно самых сложных для начинающих возможностей C++. Они необходимы для понимания динамической памяти, массивов, строк, структур данных, низкоуровневого программирования и многих механизмов стандартной библиотеки.

В этом уроке разберём:

* что такое указатель;
* как получить адрес переменной;
* как объявить указатель;
* оператор `&`;
* оператор `*`;
* разыменование;
* изменение значения через указатель;
* `nullptr`;
* указатели и типы данных;
* типичные ошибки.

---

# Что такое указатель

Указатель — переменная, которая хранит адрес другого объекта.

Например:

```cpp
int value = 42;
int* pointer = &value;
```

Здесь есть две переменные:

```text
value
  ↓
42
```

и:

```text
pointer
  ↓
адрес value
```

То есть `pointer` хранит не само число `42`, а информацию о том, где находится `value`.

---

# Оператор &

Оператор:

```cpp
&
```

перед именем переменной позволяет получить её адрес.

Например:

```cpp
int value = 42;

std::cout << &value << '\n';
```

Результатом будет адрес, например:

```text
0x7ffd12345678
```

Конкретное значение заранее предсказать нельзя.

---

# Объявление указателя

Для указателя на `int` используется:

```cpp
int* pointer;
```

Это означает:

> `pointer` — указатель на объект типа `int`.

Для других типов:

```cpp
double* temperature;
char* letter;
bool* flag;
```

Тип указателя связан с типом объекта, на который он указывает.

---

# Указатель и адрес

Рассмотрим:

```cpp
int value = 42;
int* pointer = &value;
```

Можно представить:

```text
value
┌───────────┐
│    42     │
└───────────┘
     ↑
     │
   address
     │
┌───────────┐
│  pointer  │
└───────────┘
```

`pointer` содержит адрес `value`.

---

# Оператор *

Звёздочка используется не только при объявлении указателя.

Она также позволяет получить объект, находящийся по адресу.

Это называется **разыменованием**.

Например:

```cpp
int value = 42;
int* pointer = &value;

std::cout << *pointer << '\n';
```

Результат:

```text
42
```

Получается:

```text
pointer
   ↓
адрес value
   ↓
value
   ↓
42
```

---

# Изменение значения через указатель

Через указатель можно изменить объект:

```cpp
int value = 42;
int* pointer = &value;

*pointer = 100;
```

После этого:

```text
value = 100
```

Почему?

Потому что:

```cpp
*pointer
```

обращается к объекту, который находится по адресу, хранящемуся в `pointer`.

---

# Полный пример

```cpp
#include <iostream>

int main() {
    int value = 42;
    int* pointer = &value;

    std::cout << "Value: " << value << '\n';
    std::cout << "Address: " << &value << '\n';
    std::cout << "Pointer: " << pointer << '\n';
    std::cout << "Through pointer: " << *pointer << '\n';

    *pointer = 100;

    std::cout << "New value: " << value << '\n';

    return 0;
}
```

Можно заметить:

```text
&value
```

и:

```text
pointer
```

содержат один и тот же адрес.

А:

```text
*pointer
```

даёт само значение объекта.

---

# Три выражения, которые нужно различать

Для:

```cpp
int value = 42;
int* pointer = &value;
```

имеем:

```cpp
value
```

само значение:

```text
42
```

```cpp
&value
```

адрес переменной:

```text
0x...
```

```cpp
*pointer
```

значение объекта, находящегося по адресу:

```text
42
```

Это фундаментальная идея указателей.

---

# Указатель должен соответствовать типу

Например:

```cpp
int value = 42;
int* pointer = &value;
```

Корректно.

Но:

```cpp
double temperature = 25.5;
int* pointer = &temperature;
```

так делать нельзя.

Тип указателя должен соответствовать типу объекта, если не используются специальные преобразования.

Правильно:

```cpp
double* pointer = &temperature;
```

---

# nullptr

Указатель может не указывать ни на какой объект.

Для этого используется:

```cpp
nullptr
```

Например:

```cpp
int* pointer = nullptr;
```

Это означает:

> указатель сейчас не связан с конкретным объектом.

---

# Проверка nullptr

Перед разыменованием указателя можно проверить его:

```cpp
if (pointer != nullptr) {
    std::cout << *pointer << '\n';
}
```

Это безопаснее, чем безусловно писать:

```cpp
std::cout << *pointer;
```

если неизвестно, указывает ли он на действительный объект.

---

# Опасность нулевого указателя

Следующее:

```cpp
int* pointer = nullptr;

std::cout << *pointer << '\n';
```

некорректно.

Мы пытаемся обратиться к объекту по адресу, которого нет.

Такое поведение является неопределённым и может привести к аварийному завершению программы.

---

# Неинициализированный указатель

Особенно опасно создавать указатель без значения:

```cpp
int* pointer;
```

В таком случае у него нет гарантированного безопасного значения.

Нельзя сразу писать:

```cpp
std::cout << *pointer;
```

Хорошая привычка:

```cpp
int* pointer = nullptr;
```

Если указатель пока никуда не должен указывать.

---

# Указатель можно переназначить

Указатель может последовательно указывать на разные объекты:

```cpp
int a = 10;
int b = 20;

int* pointer = &a;

std::cout << *pointer << '\n';

pointer = &b;

std::cout << *pointer << '\n';
```

Результат:

```text
10
20
```

Сначала указатель указывает на `a`, затем на `b`.

---

# Указатель не копирует объект

Очень важно понимать:

```cpp
int value = 42;
int* pointer = &value;
```

не создаёт вторую копию `value`.

Есть один объект:

```text
value → 42
```

и указатель:

```text
pointer → адрес value
```

Поэтому изменение:

```cpp
*pointer = 100;
```

меняет именно `value`.

---

# Указатель как параметр функции

Указатели можно передавать в функции.

Например:

```cpp
void setValue(int* pointer) {
    *pointer = 100;
}
```

Использование:

```cpp
int value = 42;

setValue(&value);

std::cout << value << '\n';
```

Результат:

```text
100
```

Функция получила адрес `value` и смогла изменить исходный объект.

---

# Указатель и const

Можно запретить изменять объект через указатель:

```cpp
const int* pointer;
```

Такой указатель позволяет читать объект:

```cpp
std::cout << *pointer;
```

но нельзя:

```cpp
*pointer = 100;
```

Потому что объект рассматривается через этот указатель как константный.

---

# Указатель на const

Например:

```cpp
int value = 42;
const int* pointer = &value;
```

Сам `value` при этом не обязательно является `const`.

Но через `pointer` изменять его нельзя:

```cpp
*pointer = 100;
```

такой код запрещён.

---

# Указатель можно переназначить

В предыдущем примере:

```cpp
const int* pointer = &value;
```

нельзя изменить `value` через `pointer`.

Но сам указатель можно направить на другой объект:

```cpp
int a = 10;
int b = 20;

const int* pointer = &a;

pointer = &b;
```

Это допустимо.

---

# Константный указатель

Есть другая конструкция:

```cpp
int* const pointer = &value;
```

Теперь сам указатель нельзя переназначить:

```cpp
pointer = &other;
```

нельзя.

Но объект можно изменить:

```cpp
*pointer = 100;
```

Эти две конструкции важно не путать:

```cpp
const int* pointer;
```

и:

```cpp
int* const pointer;
```

---

# Указатели и массивы

Указатели тесно связаны с массивами.

Рассмотрим:

```cpp
int numbers[3] = {10, 20, 30};
```

Имя массива во многих выражениях связано с адресом его первого элемента.

Например:

```cpp
int* pointer = numbers;
```

Теперь:

```cpp
*pointer
```

даст:

```text
10
```

---

# Арифметика указателей

Указатели можно перемещать по элементам массива.

Например:

```cpp
int numbers[3] = {10, 20, 30};

int* pointer = numbers;

std::cout << *pointer << '\n';

pointer++;

std::cout << *pointer << '\n';

pointer++;

std::cout << *pointer << '\n';
```

Результат:

```text
10
20
30
```

При увеличении указателя он переходит к следующему элементу соответствующего типа.

---

# Почему pointer++ не просто прибавляет один байт

Если:

```cpp
int* pointer;
```

то:

```cpp
pointer++;
```

переходит к следующему `int`.

Если `int` занимает 4 байта, адрес изменится примерно на 4 байта.

Для:

```cpp
double*
```

шаг будет соответствовать размеру `double`.

Именно поэтому тип указателя имеет значение.

---

# Указатель на указатель

В C++ можно создать указатель, который хранит адрес другого указателя:

```cpp
int value = 42;
int* pointer = &value;
int** pointerToPointer = &pointer;
```

Теперь:

```text
pointerToPointer
       ↓
    pointer
       ↓
     value
       ↓
      42
```

Разыменование:

```cpp
*pointerToPointer
```

даст сам `pointer`.

А:

```cpp
**pointerToPointer
```

даст:

```text
42
```

Такая конструкция встречается в низкоуровневом коде, но на первых этапах использовать её нужно только для понимания принципа.

---

# Типичная ошибка: dangling pointer

Опасная ситуация возникает, если указатель продолжает хранить адрес объекта, который уже перестал существовать.

Например:

```cpp
int* getPointer() {
    int value = 42;

    return &value;
}
```

После выхода из функции локальная переменная `value` перестаёт существовать.

Возвращаемый указатель больше не указывает на действующий объект.

Такой указатель называется висячим указателем.

Это одна из причин, почему ручная работа с указателями требует осторожности.

---

# Практический пример

Представим функцию, которая увеличивает значение:

```cpp
#include <iostream>

void increment(int* value) {
    if (value != nullptr) {
        (*value)++;
    }
}

int main() {
    int counter = 10;

    increment(&counter);
    increment(&counter);

    std::cout << counter << '\n';

    return 0;
}
```

Результат:

```text
12
```

Функция получает адрес и изменяет исходную переменную.

# Главное

Указатель хранит адрес объекта.

Для:

```cpp
int value = 42;
int* pointer = &value;
```

нужно понимать:

```text
value   → само значение
&value  → адрес value
pointer → адрес value
*pointer → значение по адресу
```

Основные операции:

```cpp
&value
```

получить адрес.

```cpp
*pointer
```

получить объект по адресу.

```cpp
pointer = &other;
```

изменить объект, на который указывает указатель.

```cpp
pointer = nullptr;
```

сделать указатель пустым.

Указатели дают C++ мощный низкоуровневый контроль над памятью, но одновременно требуют аккуратности. Разыменование `nullptr`, использование неинициализированного указателя или обращение к уже уничтоженному объекту может привести к неопределённому поведению.

Следующий урок продолжит эту тему и покажет, как указатели связаны с массивами и ссылками.
