# class

## Цель

`struct` позволяет объединять данные в один тип, но по мере роста программы возникает более важная задача: не просто хранить состояние объекта, а управлять тем, как это состояние изменяется. Для этого в C++ используется `class`.

Класс является основой объектно-ориентированного программирования в C++. Он позволяет объединять данные и функции, описывающие поведение объекта, а также ограничивать прямой доступ к внутреннему состоянию.

После урока вы должны понимать:

* что такое класс;
* как создавать объекты класса;
* что такое `public` и `private`;
* чем `class` отличается от `struct`;
* как методы работают с данными объекта;
* зачем скрывать внутреннее состояние;
* что такое интерфейс объекта.

---

## Что такое класс

Класс — это описание собственного типа, который объединяет данные и операции над этими данными.

Например, можно описать двигатель:

```cpp
class Motor
{
public:
    std::string name;
    double speed;

    void stop()
    {
        speed = 0;
    }
};
```

Теперь можно создать объект:

```cpp
Motor motor;

motor.name = "Motor 1";
motor.speed = 1000;

motor.stop();
```

Объект `motor` содержит состояние и умеет выполнять операцию `stop()`.

---

## Класс и объект

Важно различать класс и объект.

Класс:

```cpp
class Motor
{
    // описание
};
```

описывает, каким будет объект.

Объект:

```cpp
Motor motor;
```

является конкретным экземпляром этого класса.

Можно провести аналогию с чертежом и готовым устройством. Класс описывает конструкцию, а объект является конкретным экземпляром этой конструкции.

Можно создать несколько объектов одного класса:

```cpp
Motor motor1;
Motor motor2;
Motor motor3;
```

Каждый из них имеет собственное состояние.

---

## public

Ключевое слово `public` определяет открытые члены класса.

```cpp
class Motor
{
public:
    std::string name;

    void stop()
    {
        // ...
    }
};
```

Код за пределами класса может обращаться к этим членам:

```cpp
Motor motor;

motor.name = "Motor 1";
motor.stop();
```

То есть `public` формирует часть интерфейса объекта, доступную остальной программе.

---

## private

`private` используется для скрытия внутренних данных:

```cpp
class Motor
{
private:
    double speed;
};
```

Теперь внешний код не может напрямую написать:

```cpp
motor.speed = 1000;
```

Такой доступ запрещён.

Вместо этого класс может предоставить специальный метод:

```cpp
class Motor
{
private:
    double speed = 0;

public:
    void setSpeed(double value)
    {
        speed = value;
    }

    double getSpeed()
    {
        return speed;
    }
};
```

Теперь программа работает с объектом через его интерфейс:

```cpp
Motor motor;

motor.setSpeed(1000);

std::cout << motor.getSpeed();
```

---

## Зачем скрывать данные

Представим, что скорость двигателя не должна быть отрицательной:

```text
0 <= speed <= 3000
```

Если поле открыто:

```cpp
motor.speed = -500;
```

объект можно перевести в некорректное состояние.

Если поле закрыто, класс может контролировать изменение:

```cpp
void setSpeed(double value)
{
    if (value < 0)
    {
        speed = 0;
        return;
    }

    speed = value;
}
```

Теперь объект сам защищает свои правила.

Это одна из основных идей объектно-ориентированного программирования.

---

## Методы класса

Функции, принадлежащие классу, называются методами.

Например:

```cpp
class Motor
{
private:
    double speed = 0;

public:
    void start()
    {
        speed = 1000;
    }

    void stop()
    {
        speed = 0;
    }

    double getSpeed()
    {
        return speed;
    }
};
```

Использование:

```cpp
Motor motor;

motor.start();

std::cout << motor.getSpeed();

motor.stop();
```

Методы могут обращаться к полям своего объекта напрямую.

---

## Состояние объекта

Внутренние значения объекта называют его состоянием.

Например:

```cpp
class Robot
{
private:
    int battery = 100;
    bool enabled = false;
};
```

Состояние робота состоит из:

```text
battery
enabled
```

Методы изменяют это состояние:

```cpp
void enable()
{
    enabled = true;
}
```

или:

```cpp
void disable()
{
    enabled = false;
}
```

Так объект становится не просто набором переменных, а сущностью с определёнными правилами поведения.

---

## class и struct

Класс и структура в C++ очень похожи:

```cpp
struct Data
{
    int value;
};
```

и:

```cpp
class Data
{
public:
    int value;
};
```

В данном случае они практически эквивалентны.

Основное различие — уровень доступа по умолчанию.

Для `struct`:

```cpp
struct Data
{
    int value;
};
```

`value` является `public`.

Для `class`:

```cpp
class Data
{
    int value;
};
```

`value` является `private`.

То есть следующая запись:

```cpp
class Data
{
    int value;
};
```

примерно соответствует:

```cpp
class Data
{
private:
    int value;
};
```

## public, private и интерфейс

Удобно представлять класс как устройство с панелью управления.

Внутри находятся детали:

```text
private
-------------------------
внутреннее состояние
внутренние алгоритмы
служебные переменные
-------------------------
```

Снаружи доступна панель:

```text
public
-------------------------
start()
stop()
setSpeed()
getSpeed()
-------------------------
```

Пользователь объекта не обязан знать, как именно внутри реализован двигатель. Ему достаточно знать, какие операции доступны.

---

## Изменение реализации

Предположим, сначала скорость хранится напрямую:

```cpp
class Motor
{
private:
    double speed = 0;

public:
    void setSpeed(double value)
    {
        speed = value;
    }

    double getSpeed()
    {
        return speed;
    }
};
```

Позже можно изменить внутреннее устройство:

```cpp
class Motor
{
private:
    double rpm = 0;
    double scale = 1.0;

public:
    void setSpeed(double value)
    {
        rpm = value * scale;
    }

    double getSpeed()
    {
        return rpm / scale;
    }
};
```

Внешний код при этом может остаться прежним:

```cpp
motor.setSpeed(1000);
std::cout << motor.getSpeed();
```

Это очень важное свойство хорошего интерфейса: внутреннюю реализацию можно менять, не заставляя весь остальной код переписывать.

## Метод может вызывать другой метод

Методы одного класса могут использовать другие методы этого же класса:

```cpp
class Robot
{
private:
    int battery = 100;

public:
    void consumeBattery(int value)
    {
        battery -= value;

        if (battery < 0)
        {
            battery = 0;
        }
    }

    bool hasBattery()
    {
        return battery > 0;
    }
};
```

Один метод может обращаться к состоянию объекта, а другой — проверять это состояние.

---

## Константные методы

Если метод не должен изменять объект, его можно объявить с `const`:

```cpp
class Robot
{
private:
    int battery = 100;

public:
    int getBattery() const
    {
        return battery;
    }
};
```

`const` после списка параметров означает, что метод не должен изменять состояние объекта.

Это особенно важно для методов, которые только читают данные.

Например:

```cpp
int getBattery() const
{
    return battery;
}
```

Такой метод сообщает компилятору и другим программистам: «эта операция только читает объект».

## Практический пример

Создадим простой класс для управления двигателем:

```cpp
#include <iostream>
#include <string>

class Motor
{
private:
    std::string name;
    double speed = 0;

public:
    void setName(const std::string& value)
    {
        name = value;
    }

    void setSpeed(double value)
    {
        if (value < 0)
        {
            speed = 0;
            return;
        }

        speed = value;
    }

    void stop()
    {
        speed = 0;
    }

    void print() const
    {
        std::cout << name
                  << ": "
                  << speed
                  << " rpm\n";
    }
};

int main()
{
    Motor motor;

    motor.setName("Motor 1");
    motor.setSpeed(1500);

    motor.print();

    motor.stop();

    motor.print();

    return 0;
}
```

Внешний код не изменяет `speed` напрямую. Он использует методы класса.

---

## Главное

`class` позволяет объединить состояние объекта и операции над ним. С помощью `private` класс может скрыть внутреннее состояние, а через `public` предоставить контролируемый интерфейс.

Главная идея не в том, чтобы сделать все поля `private` ради самого `private`. Цель заключается в том, чтобы объект мог контролировать собственное состояние и не позволял внешнему коду случайно нарушить его правила.
