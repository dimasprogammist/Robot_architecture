# Заголовочные файлы

## Цель

В прошлом уроке мы разделили программу на `.h` и `.cpp`. Теперь разберём заголовочные файлы подробнее.

Заголовок — это не просто "файл с объявлениями". Это часть интерфейса компонента, через которую другие части программы узнают, какие типы, функции и объекты им доступны.

После урока вы должны понимать:

* что обычно находится в `.h`;
* зачем нужен `#pragma once`;
* чем объявление отличается от определения;
* зачем нужны `#include`;
* что такое зависимости заголовков;
* когда использовать forward declaration;
* почему нельзя бездумно помещать реализацию в заголовки;
* как проектировать публичный интерфейс класса.

---

## Что такое заголовочный файл

Заголовочный файл обычно имеет расширение:

```text
.h
```

Например:

```text
motor.h
sensor.h
robot.h
```

В нём описывается интерфейс компонента.

Например:

```cpp
#pragma once

class Motor {
public:
    void start();
    void stop();
};
```

Другой файл может подключить этот интерфейс:

```cpp
#include "motor.h"
```

После этого компилятор знает о классе `Motor`.

---

## Объявление и определение

Рассмотрим функцию:

```cpp
int calculate(int value);
```

Это объявление.

Оно говорит:

```text
существует функция calculate
она принимает int
она возвращает int
```

Определение:

```cpp
int calculate(int value) {
    return value * 2;
}
```

содержит уже конкретную реализацию.

Обычно объявление помещается в `.h`, а определение — в `.cpp`.

---

## #pragma once

Практически каждый собственный заголовок стоит начинать с:

```cpp
#pragma once
```

Например:

```cpp
#pragma once

class Sensor {
public:
    double read() const;
};
```

Это предотвращает повторную обработку одного и того же заголовка в рамках одной единицы трансляции.

---

## Почему заголовок может подключиться несколько раз

Представим:

```text
main.cpp
 ├── robot.h
 │    └── motor.h
 └── motor.h
```

Получается, что `motor.h` может оказаться подключён дважды.

Без защиты объявления могут привести к ошибкам повторного определения.

`#pragma once` решает эту проблему.

---

## Include guards

До появления широко распространённого `#pragma once` часто использовали:

```cpp
#ifndef MOTOR_H
#define MOTOR_H

class Motor {
public:
    void start();
};

#endif
```

Это называется **include guard**.

Логика:

```text
если MOTOR_H ещё не определён
    определить MOTOR_H
    обработать содержимое
конец
```

В современном коде часто достаточно:

```cpp
#pragma once
```

---

## Что помещать в заголовок

В заголовке могут находиться объявления типов:

```cpp
struct SensorData {
    double temperature;
    double pressure;
};
```

объявления классов:

```cpp
class Sensor {
public:
    double read() const;
};
```

функции:

```cpp
double convert_temperature(double value);
```

перечисления:

```cpp
enum class DeviceState {
    Stopped,
    Running,
    Error
};
```

и другие элементы, которые должны быть доступны нескольким исходным файлам.

---

## Что не стоит без необходимости помещать в заголовок

Не стоит превращать заголовок в огромный файл с реализацией всей программы.

Например:

```cpp
class Robot {
public:
    void start() {
        // сотни строк реализации
    }
};
```

Такой подход увеличивает связанность проекта.

Обычно лучше:

```cpp
class Robot {
public:
    void start();
};
```

а реализацию оставить в:

```text
robot.cpp
```

---

## Исключение: шаблоны

С шаблонами ситуация другая.

Например:

```cpp
template <typename T>
T maximum(T a, T b) {
    return a > b ? a : b;
}
```

Обычно реализация шаблона должна быть доступна в месте его использования.

Поэтому шаблоны часто полностью определяют в заголовочных файлах.

Это одна из причин, почему нельзя использовать правило "никогда не писать реализацию в `.h`".

---

## Inline-функции

Небольшие функции также могут находиться в заголовке:

```cpp
class Motor {
public:
    int id() const {
        return id_;
    }

private:
    int id_ = 0;
};
```

Такая функция является определённой внутри класса и рассматривается как `inline` в смысле правил языка.

Для небольших функций это нормальный подход.

---

## Зависимости заголовков

Представим:

```cpp
class Robot {
private:
    Motor motor_;
};
```

Чтобы компилятор смог создать объект `Motor` как поле, ему нужно знать полное определение `Motor`.

Поэтому обычно:

```cpp
#include "motor.h"
```

---

## Forward declaration

Но если мы храним указатель:

```cpp
class Motor;

class Robot {
private:
    Motor* motor_;
};
```

можно использовать предварительное объявление:

```cpp
class Motor;
```

Это называется **forward declaration**.

Оно сообщает компилятору:

> существует тип `Motor`.

Полное содержимое класса на этом этапе не требуется для объявления указателя.

---

## Зачем нужны forward declarations

Они позволяют уменьшить количество зависимостей.

Например:

```cpp
#pragma once

class Motor;

class Robot {
public:
    Robot(Motor* motor);

private:
    Motor* motor_;
};
```

Теперь `robot.h` не обязан подключать `motor.h`.

Реализацию можно разместить в `robot.cpp`:

```cpp
#include "robot.h"
#include "motor.h"

Robot::Robot(Motor* motor)
    : motor_(motor) {
}
```

---

## Когда forward declaration недостаточно

Если объект хранится непосредственно:

```cpp
Motor motor_;
```

нужно знать полный размер `Motor`.

Поэтому одного:

```cpp
class Motor;
```

недостаточно.

Нужен:

```cpp
#include "motor.h"
```

Также полное определение требуется в местах, где вызываются методы, используются поля или создаётся объект.

---

## Публичный интерфейс

Хороший заголовок должен показывать пользователю компонента то, что ему действительно нужно.

Например:

```cpp
#pragma once

class Motor {
public:
    void start();
    void stop();
    bool is_running() const;
};
```

Пользователю класса не нужно знать:

```text
какой протокол используется;
какие регистры записываются;
какие внутренние переменные существуют;
какой алгоритм запуска двигателя;
```

Эти детали находятся в `.cpp`.

---

## Скрытие реализации

Например:

```cpp
class Motor {
public:
    void start();
    void stop();

private:
    bool running_ = false;
    int speed_ = 0;
};
```

В `.cpp`:

```cpp
#include "motor.h"

void Motor::start() {
    running_ = true;
    speed_ = 1000;
}
```

Пользователь класса видит только необходимый интерфейс.

---

## Включение стандартных заголовков

Если в вашем заголовке используется `std::string`:

```cpp
class Device {
public:
    std::string name();
};
```

нужно подключить:

```cpp
#include <string>
```

Нельзя рассчитывать на то, что другой заголовок случайно уже подключил `<string>`.

Хорошее правило:

> заголовок должен самостоятельно подключать необходимые ему зависимости.

---

## Самодостаточный заголовок

Например:

```cpp
#pragma once

#include <string>

class Device {
public:
    std::string name() const;

private:
    std::string name_;
};
```

Такой заголовок можно подключить отдельно:

```cpp
#include "device.h"
```

и он будет корректно компилироваться.

---

## Порядок include

Обычно удобно сначала подключить собственный заголовок:

```cpp
#include "motor.h"

#include <iostream>
#include <string>
```

Это помогает обнаруживать ситуации, когда `motor.h` случайно зависит от заголовков, подключённых только в `.cpp`.

---

## Публичные и внутренние заголовки

В большом проекте можно разделять:

```text
include/
src/
```

Например:

```text
robot/
├── include/
│   └── robot.h
├── src/
│   └── robot.cpp
└── main.cpp
```

`include/` содержит публичные интерфейсы.

`src/` — реализацию.

Для библиотек такое разделение особенно удобно.

---

## Практический пример

Создадим датчик.

### sensor.h

```cpp
#pragma once

class Sensor {
public:
    explicit Sensor(int id);

    double read() const;
    int id() const;

private:
    int id_;
};
```

### sensor.cpp

```cpp
#include "sensor.h"

Sensor::Sensor(int id)
    : id_(id) {
}

double Sensor::read() const {
    return 24.5;
}

int Sensor::id() const {
    return id_;
}
```

### main.cpp

```cpp
#include <iostream>
#include "sensor.h"

int main() {
    Sensor sensor(10);

    std::cout << "ID: "
              << sensor.id()
              << '\n';

    std::cout << "Value: "
              << sensor.read()
              << '\n';
}
```

Главная программа знает только интерфейс `Sensor`.

---

## Почему это важно для больших проектов

Представьте проект:

```text
robot/
├── robot.h
├── robot.cpp
├── motor.h
├── motor.cpp
├── sensor.h
├── sensor.cpp
├── controller.h
├── controller.cpp
└── main.cpp
```

Каждый компонент имеет свой интерфейс.

Изменение реализации `sensor.cpp` не требует переписывать `main.cpp`, если публичный интерфейс `sensor.h` остаётся прежним.

Это уменьшает связанность компонентов и делает проект понятнее.

---

## Частые ошибки

### Подключение .cpp

Плохо:

```cpp
#include "motor.cpp"
```

Обычно нужно:

```cpp
#include "motor.h"
```

а `motor.cpp` должен отдельно компилироваться.

### Отсутствие #pragma once

Без защиты заголовок может подключиться несколько раз.

### Отсутствие нужного include

Если заголовок использует:

```cpp
std::string
```

он должен сам подключать:

```cpp
#include <string>
```

### Слишком много реализации

Если заголовок содержит огромный объём реализации, зависимости проекта начинают распространяться слишком широко.

## Главное

Заголовочный файл описывает интерфейс компонента:

```cpp
#pragma once

class Motor {
public:
    void start();
    void stop();
};
```

Исходный файл содержит реализацию:

```cpp
#include "motor.h"

void Motor::start() {
}
```

Основные правила:

* защищайте заголовки через `#pragma once`;
* подключайте необходимые зависимости;
* отделяйте интерфейс от реализации;
* используйте forward declaration, когда полного определения типа не требуется;
* не подключайте `.cpp`;
* не скрывайте реализацию в заголовке без причины.

Хороший заголовочный файл отвечает прежде всего на вопрос:

> **Что предоставляет этот компонент остальной программе?**
