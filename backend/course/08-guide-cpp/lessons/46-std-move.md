# std::move

## Цель

В предыдущем уроке мы познакомились с move semantics. Теперь разберём инструмент, который позволяет явно сообщить C++:

> этот объект можно рассматривать как источник перемещения.

Для этого используется `std::move`.

После урока вы должны понимать:

* что делает `std::move`;
* чего `std::move` на самом деле не делает;
* зачем нужен rvalue cast;
* как перемещать строки и контейнеры;
* что происходит с объектом после `std::move`;
* когда `std::move` использовать нельзя;
* как `std::move` применяется в собственных классах;
* почему не стоит добавлять `std::move` без понимания последствий.

---

# Что делает std::move

Рассмотрим:

```cpp
std::string name = "Robot";
```

Если написать:

```cpp
std::string copy = name;
```

произойдёт копирование.

Если написать:

```cpp
std::string moved = std::move(name);
```

мы разрешаем перемещение ресурсов из `name` в `moved`.

Очень важно:

> `std::move` сам по себе ничего не перемещает.

Он только преобразует выражение так, чтобы оно могло быть использовано как rvalue.

---

# Что происходит после std::move

Рассмотрим:

```cpp
std::string name = "Robot";

std::string result = std::move(name);
```

До перемещения:

```text
name
 │
 ▼
"Robot"
```

После:

```text
name
 │
 ▼
валидный, но прежнее состояние не гарантируется

result
 │
 ▼
"Robot"
```

`result` получил ресурс.

А `name` остаётся существующим объектом.

---

# После перемещения объект не уничтожается

Это важный момент.

После:

```cpp
std::string b = std::move(a);
```

объект `a` не уничтожен.

Можно сделать:

```cpp
a = "New value";
```

Это полностью корректно.

Но нельзя рассчитывать на прежнее значение:

```cpp
// Не следует ожидать,
// что a всё ещё содержит "Robot".
```

---

# std::move и vector

Рассмотрим:

```cpp
std::vector<int> values{
    10, 20, 30
};

std::vector<int> other = std::move(values);
```

Если `vector` поддерживает перемещение, новый объект может забрать внутренний буфер.

Это значительно дешевле, чем копирование всех элементов.

---

# std::move и функция

Представим функцию:

```cpp
void process(std::vector<int> values) {
    // ...
}
```

Есть:

```cpp
std::vector<int> data{
    1, 2, 3, 4, 5
};
```

Если написать:

```cpp
process(data);
```

создаётся копия.

Если:

```cpp
process(std::move(data));
```

функции разрешено переместить ресурс `data`.

После вызова `data` остаётся валидным, но его прежнее содержимое больше нельзя считать доступным.

---

# Когда std::move уместен

`std::move` подходит, когда:

* объект больше не нужен в прежнем состоянии;
* нужно передать владение ресурсом;
* объект передаётся в функцию, которая принимает его по значению или rvalue-ссылке;
* создаётся новый объект из старого;
* класс явно поддерживает перемещение.

Например:

```cpp
std::vector<int> buffer = createBuffer();

sendBuffer(std::move(buffer));
```

Если после `sendBuffer` старый `buffer` больше не нужен, перемещение имеет смысл.

---

# Когда std::move использовать нельзя

Рассмотрим:

```cpp
std::string name = "Robot";

std::string copy = std::move(name);

std::cout << name << '\n';
```

Здесь уже нельзя ожидать:

```text
Robot
```

Если программа требует использовать `name` в исходном состоянии, перемещение было неправильным решением.

Нужно копирование:

```cpp
std::string copy = name;
```

---

# std::move не ускоряет любой тип

Для простого типа:

```cpp
int value = 10;

int other = std::move(value);
```

никакого заметного выигрыша нет.

`int` и так дешёво копируется.

Основная польза move semantics проявляется у объектов, которые владеют ресурсами:

```text
std::string
std::vector
std::unique_ptr
файловые объекты
сетевые буферы
собственные ресурсные классы
```

---

# std::move и const

Очень важный случай:

```cpp
const std::string name = "Robot";

std::string result = std::move(name);
```

Несмотря на `std::move`, перемещение ресурса обычно невозможно, потому что исходный объект является `const`.

Перемещающий конструктор обычно принимает:

```cpp
T&&
```

а `const T` не подходит для изменения состояния исходного объекта.

В результате может быть использовано копирование.

Поэтому не следует ожидать настоящего перемещения из `const` объекта.

---

# std::move и возвращаемые значения

Не нужно писать:

```cpp
std::vector<int> createData() {
    std::vector<int> data{
        1, 2, 3
    };

    return std::move(data);
}
```

Обычно правильнее:

```cpp
std::vector<int> createData() {
    std::vector<int> data{
        1, 2, 3
    };

    return data;
}
```

Компилятор сам применяет правила оптимизации и перемещения.

Более того, лишний `std::move` в `return` иногда может помешать оптимизации копирования.

---

# std::move в конструкторе

Очень распространённый пример:

```cpp
class Device {
private:
    std::string name;

public:
    Device(std::string deviceName)
        : name(std::move(deviceName)) {
    }
};
```

Здесь параметр:

```cpp
std::string deviceName
```

получен по значению.

После этого он больше не нужен.

Поэтому его содержимое можно переместить в поле:

```cpp
name(std::move(deviceName))
```

Это распространённый и удобный паттерн.

---

# Почему параметр принимается по значению

Можно написать:

```cpp
Device(std::string deviceName)
    : name(std::move(deviceName)) {
}
```

Теперь возможны оба варианта.

Если передали lvalue:

```cpp
std::string text = "Motor";

Device device(text);
```

параметр создаётся копированием.

Если передали временный объект:

```cpp
Device device(std::string{"Motor"});
```

параметр может быть создан перемещением.

А затем в обоих случаях:

```cpp
name(std::move(deviceName))
```

передаёт ресурс в поле.

---

# std::move и unique_ptr

Позже мы подробно разберём умные указатели.

Но уже сейчас полезно увидеть:

```cpp
std::unique_ptr<int> a =
    std::make_unique<int>(10);
```

`unique_ptr` нельзя копировать:

```cpp
std::unique_ptr<int> b = a;
```

такой код запрещён.

Чтобы передать владение:

```cpp
std::unique_ptr<int> b = std::move(a);
```

Теперь:

```text
a -> nullptr
b -> объект 10
```

Это один из самых понятных примеров практического применения `std::move`.

---

# std::move не проверяет, можно ли перемещать

`std::move` не делает проверку:

```text
можно ли безопасно переместить этот объект?
```

Он просто преобразует выражение.

Ответственность лежит на программисте.

Например:

```cpp
std::string a = "Robot";

std::string b = std::move(a);

// Здесь a больше нельзя считать содержащей "Robot".
```

---

# std::move — это не перенос памяти сам по себе

Название может вводить в заблуждение.

```cpp
std::move(value)
```

не означает:

> немедленно перенеси объект в другое место памяти.

На самом деле это средство выбора подходящей перегрузки или перемещающего конструктора.

Если у типа нет эффективного перемещения, операция может закончиться копированием.

---

# Практический пример

Создадим контейнер сообщений:

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

class MessageQueue {
private:
    std::vector<std::string> messages;

public:
    void add(std::string message) {
        messages.push_back(std::move(message));
    }

    void print() const {
        for (const auto& message : messages) {
            std::cout << message << '\n';
        }
    }
};

int main() {
    MessageQueue queue;

    std::string message = "Motor started";

    queue.add(std::move(message));

    queue.print();
}
```

Внутри `add` строка перемещается в `vector`.

После вызова:

```cpp
queue.add(std::move(message));
```

`message` больше не следует использовать как прежнюю строку.

---

# Главное

`std::move`:

* не уничтожает объект;
* не перемещает объект сам по себе;
* не гарантирует физическое перемещение;
* превращает выражение в форму, подходящую для перемещения;
* позволяет выбрать move constructor или move assignment operator.

Главное правило:

```cpp
std::move(object)
```

используется тогда, когда вы готовы отказаться от прежнего состояния `object`.

После перемещения объект остаётся валидным, но его старое содержимое больше нельзя считать сохранённым.
