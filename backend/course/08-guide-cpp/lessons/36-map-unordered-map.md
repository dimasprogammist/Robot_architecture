# std::map и std::unordered_map

## Цель

В этом уроке разберём два контейнера STL, которые используются для хранения данных в формате **ключ → значение**: `std::map` и `std::unordered_map`.

После урока вы должны понимать, чем отличается `map` от `unordered_map`, как добавлять и получать значения по ключу, как проверять наличие ключа и когда использовать каждый из контейнеров.

---

## Зачем нужен контейнер «ключ → значение»

До этого мы работали с `std::vector` и `std::array`. В них элементы обычно находятся по числовому индексу:

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<double> temperatures = {21.5, 22.1, 23.0};

    std::cout << temperatures[0] << '\n';
}
```

Здесь `0` — индекс элемента. Но во многих программах мы хотим обращаться к данным не по номеру, а по осмысленному идентификатору.

Например, у нас есть набор датчиков:

```text
temperature → 23.5
pressure    → 101.2
humidity    → 48.7
```

Можно было бы хранить два массива, но это неудобно:

```cpp
std::vector<std::string> names;
std::vector<double> values;
```

Гораздо естественнее использовать контейнер, где каждому значению соответствует ключ:

```cpp
temperature → 23.5
pressure    → 101.2
humidity    → 48.7
```

Для этого существуют `std::map` и `std::unordered_map`.

---

## std::map

`std::map` хранит пары:

```text
ключ → значение
```

Простейший пример:

```cpp
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, double> sensors;

    sensors["temperature"] = 23.5;
    sensors["pressure"] = 101.2;
    sensors["humidity"] = 48.7;

    std::cout << sensors["temperature"] << '\n';
}
```

Тип контейнера записывается так:

```cpp
std::map<Key, Value>
```

В нашем случае:

```cpp
std::map<std::string, double>
```

означает:

```text
ключ   → string
значение → double
```

---

## Добавление элементов

Самый простой способ добавить значение — использовать `operator[]`:

```cpp
std::map<std::string, int> devices;

devices["motor"] = 4;
devices["camera"] = 2;
devices["sensor"] = 12;
```

Теперь контейнер содержит три записи.

Если ключ уже существует, значение будет заменено:

```cpp
devices["motor"] = 5;
```

Теперь:

```text
motor → 5
```

а не `4`.

---

## Получение значения

Значение можно получить через `[]`:

```cpp
std::cout << devices["motor"] << '\n';
```

Но здесь есть важная особенность.

Если ключа не существует, `operator[]` **создаст новый элемент**.

Например:

```cpp
std::map<std::string, int> devices;

std::cout << devices["robot"] << '\n';
```

Ключа `robot` раньше не было, но после обращения он появится со значением `0`.

Это может быть неожиданным поведением.

---

## Проверка наличия ключа

Для проверки существования ключа удобно использовать `contains()`:

```cpp
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, double> sensors;

    sensors["temperature"] = 23.5;

    if (sensors.contains("temperature")) {
        std::cout << "Sensor exists\n";
    }

    if (!sensors.contains("speed")) {
        std::cout << "Sensor does not exist\n";
    }
}
```

`contains()` возвращает `true` или `false`.

Этот метод появился в C++20.

---

## Получение значения без создания элемента

Если мы не хотим создавать отсутствующий ключ, можно использовать `find()`:

```cpp
auto it = sensors.find("temperature");

if (it != sensors.end()) {
    std::cout << it->second << '\n';
}
```

Здесь `it` — итератор на найденную пару.

У пары есть:

```cpp
it->first
```

для ключа и:

```cpp
it->second
```

для значения.

Например:

```cpp
std::cout << "Name: " << it->first << '\n';
std::cout << "Value: " << it->second << '\n';
```

---

## Перебор std::map

`std::map` удобно перебирать через range-based `for`:

```cpp
for (const auto& [name, value] : sensors) {
    std::cout << name << ": " << value << '\n';
}
```

Здесь используется structured binding:

```cpp
[name, value]
```

Он автоматически разбивает пару на две переменные.

Например, если контейнер содержит:

```text
humidity    → 48.7
pressure    → 101.2
temperature → 23.5
```

то каждая итерация получает отдельные `name` и `value`.

---

## std::map хранит ключи отсортированными

Это одна из главных особенностей `std::map`.

Например:

```cpp
std::map<std::string, int> values;

values["z"] = 10;
values["a"] = 20;
values["m"] = 30;
```

При переборе ключи будут идти в отсортированном порядке:

```text
a
m
z
```

То есть порядок добавления не сохраняется.

По умолчанию используется сравнение ключей через `std::less`.

---

## std::unordered_map

Теперь рассмотрим второй контейнер:

```cpp
std::unordered_map
```

Он также хранит пары:

```text
ключ → значение
```

Например:

```cpp
#include <iostream>
#include <unordered_map>
#include <string>

int main() {
    std::unordered_map<std::string, double> sensors;

    sensors["temperature"] = 23.5;
    sensors["pressure"] = 101.2;
    sensors["humidity"] = 48.7;

    std::cout << sensors["temperature"] << '\n';
}
```

С точки зрения использования контейнер очень похож на `std::map`.

Главное отличие находится внутри.

---

## Как работает unordered_map

`std::unordered_map` использует хеш-таблицу.

Для ключа вычисляется специальное числовое значение — **хеш**. По этому хешу контейнер определяет, где хранить соответствующее значение.

Упрощённо:

```text
"temperature"
      ↓
   hash()
      ↓
   число
      ↓
ячейка таблицы
      ↓
   23.5
```

Поэтому контейнер не обязан хранить ключи в отсортированном порядке.

---

## Порядок элементов

Для `unordered_map` нельзя рассчитывать на сортировку ключей:

```cpp
std::unordered_map<std::string, int> values;

values["z"] = 10;
values["a"] = 20;
values["m"] = 30;

for (const auto& [key, value] : values) {
    std::cout << key << '\n';
}
```

Порядок вывода не следует воспринимать как гарантированный.

Он может зависеть от реализации, состояния хеш-таблицы и количества элементов.

Если программе нужен отсортированный порядок, `std::map` обычно подходит лучше.

---

## Скорость доступа

Обычно сложность основных операций выглядит так:

| Операция | `std::map` | `std::unordered_map` |
|---|---:|---:|
| поиск | O(log n) | O(1) в среднем |
| вставка | O(log n) | O(1) в среднем |
| удаление | O(log n) | O(1) в среднем |
| сортированный порядок | Да | Нет |

Для `unordered_map` важно понимать слова **«в среднем»**.

В плохих случаях из-за коллизий хешей производительность может ухудшиться.

Поэтому `unordered_map` не означает «всегда быстрее».

---

## Что такое коллизия

Разные ключи могут получить одинаковое положение в хеш-таблице.

Например:

```text
ключ A → ячейка 5
ключ B → ячейка 5
```

Это называется **коллизией**.

Контейнер умеет самостоятельно разрешать такие ситуации.

Программисту обычно не нужно заниматься этим вручную.

---

## insert

Кроме `operator[]`, можно использовать `insert()`:

```cpp
std::map<std::string, int> devices;

devices.insert({"motor", 4});
devices.insert({"camera", 2});
```

`insert()` особенно полезен, когда мы хотим именно добавить новый элемент, не заменяя существующее значение.

Например:

```cpp
devices.insert({"motor", 10});
devices.insert({"motor", 20});
```

Вторая вставка не заменит существующий `motor`.

---

## try_emplace

В современном C++ существует удобный метод:

```cpp
try_emplace()
```

Например:

```cpp
std::map<std::string, int> devices;

devices.try_emplace("motor", 4);
```

Если ключ уже существует, новая запись не создаётся.

Это особенно полезно, когда значение представляет собой сложный объект и мы хотим избежать лишних операций создания.

---

## erase

Удалить элемент можно по ключу:

```cpp
devices.erase("motor");
```

После этого ключ `motor` исчезнет из контейнера.

Можно также удалить элемент через итератор:

```cpp
auto it = devices.find("camera");

if (it != devices.end()) {
    devices.erase(it);
}
```

---

## size и empty

Как и другие контейнеры STL, `map` и `unordered_map` имеют:

```cpp
devices.size()
```

и:

```cpp
devices.empty()
```

Например:

```cpp
if (devices.empty()) {
    std::cout << "No devices\n";
}
```

---

## Практический пример: параметры робота

Представим контроллер робота, которому нужно хранить параметры устройств:

```cpp
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, double> parameters;

    parameters["max_speed"] = 1.5;
    parameters["max_acceleration"] = 2.0;
    parameters["battery_limit"] = 20.0;

    for (const auto& [name, value] : parameters) {
        std::cout << name << " = " << value << '\n';
    }
}
```

Здесь `map` удобен, потому что параметры автоматически выводятся в отсортированном порядке.

---

## Когда использовать map

`std::map` подходит, если:

* нужен отсортированный порядок ключей;
* нужны операции поиска по диапазону;
* важна предсказуемая логарифмическая сложность;
* данные естественно должны быть упорядочены.

Например:

```text
время → измерение
```

или:

```text
идентификатор → устройство
```

когда порядок ключей имеет значение.

---

## Когда использовать unordered_map

`std::unordered_map` часто подходит, если:

* порядок ключей не важен;
* нужен быстрый доступ по ключу;
* основная операция — поиск значения;
* нет необходимости в диапазонных операциях.

Например:

```text
имя датчика → последнее значение
```

или:

```text
ID устройства → объект устройства
```

---

## Важное правило

Не стоит выбирать контейнер только потому, что `unordered_map` имеет O(1) в среднем.

Сначала нужно понять, какие операции действительно нужны программе.

Если нам требуется:

```text
найти значение по ключу
```

оба контейнера подходят.

Если требуется:

```text
перебирать ключи в отсортированном порядке
```

`map` имеет естественное преимущество.

---

## Главное

`std::map` и `std::unordered_map` хранят данные в формате:

```text
ключ → значение
```

`std::map` хранит ключи в отсортированном порядке и обычно выполняет поиск за O(log n). `std::unordered_map` использует хеш-таблицу и в среднем обеспечивает O(1) для поиска, но не гарантирует порядок элементов.

Для проверки существования ключа удобно использовать:

```cpp
contains()
```

Для поиска без создания нового элемента:

```cpp
find()
```

Для удаления:

```cpp
erase()
```
