# Исключения

## Цель

До этого мы рассматривали ошибки, которые могут привести к аварийному завершению программы или неопределённому поведению.

Но далеко не каждая ошибка означает, что программа должна немедленно завершиться.

Например, файл может отсутствовать, конфигурация может оказаться неправильной, сетевое соединение может быть недоступно. В таких случаях программе нужен механизм, позволяющий сообщить об ошибке и передать её обработку в подходящее место.

В C++ для этого существуют **исключения**.

После урока вы должны понимать:

* что такое исключение;
* зачем используется `throw`;
* как исключение передаётся вверх по стеку вызовов;
* что такое `try` и `catch`;
* почему исключения хорошо сочетаются с RAII;
* какие стандартные исключения существуют;
* почему исключения нужно перехватывать правильно;
* когда исключения уместны, а когда лучше использовать другие механизмы.

---

## Что такое исключение

Исключение — это специальный механизм передачи информации об ошибке от места, где она обнаружена, к коду, который способен её обработать.

Представим:

```text
main()
  ↓
controller()
  ↓
connect()
  ↓
openSocket()
```

Ошибка возникает внутри:

```text
openSocket()
```

Но обрабатывать её там может быть неудобно.

Вместо того чтобы возвращать код ошибки через несколько уровней функций, можно выбросить исключение.

Оно начнёт подниматься вверх по стеку вызовов до подходящего обработчика.

---

## `throw`

Для выбрасывания исключения используется:

```cpp
throw
```

Например:

```cpp
throw std::runtime_error("Connection failed");
```

Здесь создаётся объект исключения `std::runtime_error`.

Текст:

```text
Connection failed
```

описывает проблему.

---

## Простейший пример

```cpp
#include <iostream>
#include <stdexcept>

int divide(int a, int b) {
    if (b == 0) {
        throw std::runtime_error("Division by zero");
    }

    return a / b;
}

int main() {
    std::cout << divide(10, 2) << '\n';
}
```

Если передать:

```cpp
divide(10, 0);
```

функция выбросит исключение.

Но пока в программе нет обработчика, исключение будет продолжать распространяться вверх.

---

## `try` и `catch`

Обработчик создаётся с помощью:

```cpp
try
```

и:

```cpp
catch
```

Например:

```cpp
#include <iostream>
#include <stdexcept>

int divide(int a, int b) {
    if (b == 0) {
        throw std::runtime_error("Division by zero");
    }

    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 0) << '\n';
    }
    catch (const std::exception& error) {
        std::cout << "Error: " << error.what() << '\n';
    }
}
```

Теперь исключение не приводит к завершению программы.

Оно попадает в:

```cpp
catch
```

---

## Что происходит при `throw`

Когда выполняется:

```cpp
throw std::runtime_error("Connection failed");
```

обычное выполнение текущей функции прекращается.

C++ начинает искать подходящий обработчик.

Упрощённо:

```text
функция A
    ↓
функция B
    ↓
функция C
    ↓
throw
    ↑
ищем catch
    ↑
нашли
```

Этот процесс называется **раскруткой стека**, или stack unwinding.

---

## Stack unwinding

Допустим:

```cpp
void level3() {
    throw std::runtime_error("Error");
}

void level2() {
    level3();
}

void level1() {
    level2();
}
```

Если:

```cpp
int main() {
    try {
        level1();
    }
    catch (const std::exception& error) {
        std::cout << error.what() << '\n';
    }
}
```

исключение пройдёт через:

```text
level3
  ↓
level2
  ↓
level1
  ↓
main
```

Пока не найдёт подходящий `catch`.

---

## Локальные объекты и RAII

Здесь проявляется одна из сильных сторон C++.

При раскрутке стека локальные объекты уничтожаются обычным образом.

Например:

```cpp
#include <iostream>

struct Resource {
    Resource() {
        std::cout << "Acquire\n";
    }

    ~Resource() {
        std::cout << "Release\n";
    }
};

void process() {
    Resource resource;

    throw std::runtime_error("Failure");
}
```

Перед выходом из `process()` объект:

```cpp
resource
```

будет уничтожен.

Его деструктор выполнится.

Именно поэтому RAII настолько важен в C++.

---

## Исключения и ручное управление памятью

Рассмотрим опасный код:

```cpp
void process() {
    int* data = new int[100];

    doSomething();

    delete[] data;
}
```

Если:

```cpp
doSomething();
```

выбросит исключение, до:

```cpp
delete[] data;
```

управление может не дойти.

Память останется выделенной.

С RAII:

```cpp
#include <vector>

void process() {
    std::vector<int> data(100);

    doSomething();
}
```

Если возникнет исключение, `vector` будет уничтожен автоматически.

Это одна из причин, почему современный C++ старается минимизировать ручное управление ресурсами.

---

## Стандартные типы исключений

В стандартной библиотеке есть базовый класс:

```cpp
std::exception
```

У него есть метод:

```cpp
what()
```

который возвращает описание ошибки.

Например:

```cpp
catch (const std::exception& error) {
    std::cout << error.what() << '\n';
}
```

Есть специализированные классы:

```cpp
std::runtime_error
std::logic_error
std::out_of_range
std::invalid_argument
std::bad_alloc
```

Например:

```cpp
throw std::invalid_argument("Invalid motor number");
```

---

## `std::out_of_range`

Некоторые операции стандартной библиотеки могут выбрасывать `std::out_of_range`.

Например:

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values = {10, 20, 30};

    try {
        std::cout << values.at(100) << '\n';
    }
    catch (const std::out_of_range& error) {
        std::cout << "Index error: "
                  << error.what()
                  << '\n';
    }
}
```

Здесь ошибка конкретно связана с выходом за допустимый диапазон.

---

## Перехват через `std::exception`

Если вам не важен конкретный тип ошибки, можно использовать:

```cpp
catch (const std::exception& error)
```

Например:

```cpp
try {
    runController();
}
catch (const std::exception& error) {
    std::cout << "Controller error: "
              << error.what()
              << '\n';
}
```

Это позволяет обрабатывать стандартные исключения единым способом.

---

## Почему `catch` принимает ссылку

Предпочтительный вариант:

```cpp
catch (const std::exception& error)
```

а не:

```cpp
catch (std::exception error)
```

При передаче по значению создаётся копия объекта исключения.

При передаче по `const` ссылке копирование не требуется, а полиморфизм сохраняется.

Поэтому стандартный стиль:

```cpp
catch (const std::exception& error)
```

---

## Свои типы исключений

При необходимости можно создать собственный тип:

```cpp
#include <stdexcept>

class DeviceError : public std::runtime_error {
public:
    using std::runtime_error::runtime_error;
};
```

Теперь:

```cpp
throw DeviceError("Motor controller is unavailable");
```

Можно перехватить:

```cpp
catch (const DeviceError& error) {
    std::cout << error.what() << '\n';
}
```

Или более общим обработчиком:

```cpp
catch (const std::exception& error) {
    std::cout << error.what() << '\n';
}
```

---

## Исключения в конструкторах

Конструктор может обнаружить невозможность корректно создать объект.

Например:

```cpp
class Device {
public:
    Device(int address) {
        if (address < 0) {
            throw std::invalid_argument("Invalid address");
        }
    }
};
```

Если объект невозможно создать в корректном состоянии, конструктор может выбросить исключение.

Это лучше, чем создавать объект, который формально существует, но находится в неисправном состоянии.

---

## Когда использовать исключения

Исключения полезны, когда операция не может нормально продолжить работу.

Например:

```text
загрузить конфигурацию
    ↓
файл повреждён
    ↓
объект невозможно создать
```

Или:

```text
подключиться к устройству
    ↓
устройство не отвечает
    ↓
сообщить об ошибке вызывающему коду
```

Исключение позволяет отделить основной сценарий от обработки ошибок.

---

## Когда исключения могут быть неудобны

Не каждую ситуацию нужно превращать в исключение.

Например, если функция постоянно проверяет наличие значения:

```cpp
std::optional<int> findValue();
```

может быть лучше, чем:

```cpp
int findValue();
```

с исключением при каждом отсутствии результата.

Или функция может возвращать:

```cpp
bool
```

если ошибка является обычной частью нормального управления программой.

Например:

```cpp
if (!connect()) {
    std::cout << "Connection failed\n";
}
```

Здесь ошибка подключения может быть ожидаемой частью работы программы.

Выбор механизма зависит от архитектуры приложения.

---

## Исключения и робототехника

Представим контроллер:

```cpp
class MotorController {
public:
    void connect() {
        if (!deviceAvailable()) {
            throw std::runtime_error("Motor controller unavailable");
        }
    }

private:
    bool deviceAvailable() {
        return false;
    }
};
```

Верхний уровень приложения может решить, что делать:

```cpp
try {
    MotorController controller;
    controller.connect();

    // Работа с устройством.
}
catch (const std::exception& error) {
    std::cout << "Controller error: "
              << error.what()
              << '\n';
}
```

Низкоуровневая функция сообщает о проблеме, а более высокий уровень решает, как на неё реагировать.

Это позволяет разделить ответственность между слоями программы.

---

## Не скрывайте ошибки

Плохой обработчик:

```cpp
try {
    run();
}
catch (...) {
}
```

Он перехватывает исключение и ничего не делает.

После этого программа может продолжить работу так, будто ничего не произошло.

В результате реальная причина проблемы исчезает.

Если исключение действительно нужно перехватить, должна существовать понятная причина, почему оно обрабатывается именно там.

---

## Главное

Исключения позволяют передавать ошибки через несколько уровней вызовов.

Основные элементы:

```cpp
throw
```

выбрасывает исключение.

```cpp
try
```

определяет участок кода, где ожидается возможное исключение.

```cpp
catch
```

обрабатывает исключение.

Очень важная особенность C++ — сочетание исключений с RAII. При раскрутке стека локальные объекты уничтожаются, поэтому ресурсы, которыми владеют RAII-объекты, освобождаются автоматически.

Современный C++ обычно старается строить код так, чтобы исключения не приводили к утечкам ресурсов и повреждённому состоянию объектов.
