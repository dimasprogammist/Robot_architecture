# C++ в робототехнике

## Цель

Робот — это не просто двигатель и набор датчиков. Это программно-аппаратная система, которая должна постоянно получать информацию об окружающем мире, принимать решения и управлять исполнительными механизмами.

C++ широко используется в робототехнике, потому что позволяет одновременно работать на достаточно высоком уровне абстракции и при необходимости контролировать ресурсы системы.

После урока вы должны понимать:

* из каких программных компонентов состоит робот;
* какую роль играет C++;
* как связаны датчики, алгоритмы и исполнительные механизмы;
* что такое цикл управления;
* почему важны задержки и период выполнения;
* как организовать обмен данными между компонентами;
* зачем разделять аппаратный и прикладной код;
* где в робототехнике используется ROS 2;
* почему тестирование робота нельзя ограничивать только реальным оборудованием.

---

## Робот как система

Упрощённо робот можно представить так:

```text
        Sensors
           ↓
    ┌─────────────┐
    │ Perception  │
    └──────┬──────┘
           ↓
    ┌─────────────┐
    │ Decision    │
    └──────┬──────┘
           ↓
    ┌─────────────┐
    │ Control     │
    └──────┬──────┘
           ↓
       Actuators
```

Например:

```text
датчик расстояния
       ↓
обнаружен объект
       ↓
решение остановиться
       ↓
контроллер двигателя
       ↓
мотор остановлен
```

C++ может использоваться практически на каждом из этих уровней.

---

## Датчики

Робот получает информацию с помощью датчиков.

Например:

```text
камеры
лидары
ультразвуковые датчики
энкодеры
IMU
температурные датчики
датчики положения
```

Каждый датчик выдаёт свои данные.

Например:

```cpp
struct Distance {
    double meters;
};
```

Или:

```cpp
struct ImuData {
    double accelerationX;
    double accelerationY;
    double accelerationZ;

    double gyroX;
    double gyroY;
    double gyroZ;
};
```

## Исполнительные механизмы

После получения данных робот должен что-то сделать.

Исполнительными механизмами могут быть:

```text
электродвигатели
сервоприводы
пневматические клапаны
реле
захваты
манипуляторы
```

Например:

```cpp
motor.setSpeed(0.5);
```

Но хороший код обычно не должен напрямую знать детали конкретного драйвера двигателя.

## Абстракция двигателя

Можно определить интерфейс:

```cpp
class Motor {
public:
    virtual void setSpeed(double speed) = 0;
    virtual void stop() = 0;

    virtual ~Motor() = default;
};
```

Теперь алгоритм может работать с:

```cpp
Motor& motor
```

а конкретная реализация может использовать:

```text
CAN
PWM
Modbus
Ethernet
```

Это позволяет менять аппаратную реализацию без переписывания всей логики робота.

---

## Контур управления

Одна из главных идей робототехники — feedback loop.

Система:

```text
       ┌───────────────┐
       │               ↓
Sensor → Controller → Motor
  ↑                     │
  └─────────────────────┘
```

Робот измеряет состояние.

Контроллер вычисляет управляющее воздействие.

Двигатель изменяет состояние робота.

Датчик снова измеряет результат.

---

## Пример

Пусть робот должен двигаться со скоростью:

```text
1.0 м/с
```

Датчик сообщает:

```text
0.7 м/с
```

Контроллер может увеличить управление двигателем.

Через некоторое время:

```text
0.9 м/с
```

Затем:

```text
1.0 м/с
```

Так система постепенно приближается к заданному значению.

---

## Setpoint и actual value

В автоматизации часто используются два понятия:

```text
Setpoint
Actual value
```

Например:

```text
Setpoint = 1000 rpm
Actual   = 920 rpm
```

Ошибка:

```text
error = setpoint - actual
```

В C++:

```cpp
double error = setpoint - actual;
```

Это простая основа многих систем управления.

---

## Простейший регулятор

Упрощённо можно написать:

```cpp
double control(double setpoint, double actual) {
    double error = setpoint - actual;

    return error * 0.5;
}
```

Коэффициент:

```text
0.5
```

определяет реакцию контроллера.

Это упрощённый пример пропорционального управления.

В реальных системах используются более сложные алгоритмы.

---

## PID

Один из классических регуляторов — PID.

Он использует:

```text
P — пропорциональная составляющая
I — интегральная составляющая
D — дифференциальная составляющая
```

Упрощённая идея:

```text
error
  ↓
P + I + D
  ↓
control output
```

C++ часто используется для реализации таких алгоритмов.

---

## Период управления

Представим цикл:

```text
каждые 10 ms
```

Он должен:

```text
прочитать датчики
вычислить управление
отправить команды
```

То есть:

```text
0 ms   → цикл
10 ms  → цикл
20 ms  → цикл
30 ms  → цикл
```

Если выполнение иногда занимает 100 ms, система уже не соответствует требуемому периоду.

---

## Почему задержки опасны

Робот работает с физическим миром.

Если программа слишком долго обрабатывает данные:

```text
Sensor
  ↓
100 ms задержка
  ↓
Controller
  ↓
Motor
```

робот принимает решение на основе устаревшего состояния.

Для медленной системы это может быть допустимо.

Для быстрого манипулятора или мобильного робота — уже нет.

## Разделение потоков

Большой робот может использовать несколько потоков:

```text
Sensor Thread
      ↓

      ↓

      ↓
Motor Thread
```

Например:

```text
Camera
 ↓
Vision
 ↓
Object Detection
 ↓
Planner
 ↓
Controller
 ↓
Motor
```

Между компонентами можно использовать:

```text
queues
mutex
condition_variable
atomic
message passing
```

---

## Очереди сообщений

Представим поток камеры:

```text
Camera Thread
     ↓
Image Queue
     ↓
Vision Thread
```

Камера добавляет изображения:

```text
Frame 1
Frame 2
Frame 3
```

Vision извлекает их.

Так компоненты не обязаны выполняться строго одновременно.

---

## Почему нельзя бесконечно накапливать кадры

Если камера выдаёт:

```text
60 FPS
```

а обработчик способен обрабатывать:

```text
20 FPS
```

очередь будет расти:

```text
60
80
100
120
...
```

В итоге данные будут устаревшими.

Для некоторых задач лучше отбросить старые кадры и обрабатывать самый свежий.

Это пример архитектурного решения, зависящего от задачи.

## Робот должен иметь состояние

Например:

```cpp
enum class RobotState {
    Idle,
    Moving,
    Stopping,
    Error,
    EmergencyStop
};
```

Основная логика может выглядеть так:

```cpp
switch (state) {
case RobotState::Idle:
    handleIdle();
    break;

case RobotState::Moving:
    handleMoving();
    break;

case RobotState::Stopping:
    handleStopping();
    break;

case RobotState::Error:
    handleError();
    break;

case RobotState::EmergencyStop:
    handleEmergencyStop();
    break;
}
```

Такой подход называется конечным автоматом состояний.

---

## Аварийная остановка

Для промышленного и физического оборудования нельзя полагаться только на обычную программную логику.

Например:

```text
C++ приложение
      ↓
команда STOP
      ↓
контроллер
```

не обязательно является достаточным механизмом безопасности.

Аварийная остановка может реализовываться аппаратно через:

```text
Safety PLC
safety relay
hardware input
drive safety functions
```

Программное обеспечение должно учитывать такие механизмы, но не заменять их без соответствующей архитектуры безопасности.

## C++ и ROS 2

В робототехнике часто используется ROS 2 — Robot Operating System 2.

Несмотря на название, это не обычная операционная система вроде Windows или Linux.

Это программная инфраструктура для построения распределённых робототехнических систем.

Она предоставляет механизмы для:

```text
nodes
topics
services
actions
parameters
communication
```

C++ является одним из основных языков разработки ROS 2-приложений.

---

## Nodes

Компонент робота может быть отдельным node.

Например:

```text
/camera
/lidar
/localization
/planner
/controller
/motor_driver
```

Каждый компонент выполняет свою задачу.

---

## Topics

Компоненты могут обмениваться сообщениями через topics.

Например:

```text
/camera
    ↓
/vision
    ↓
/planner
    ↓
/controller
```

Камера публикует данные.

Vision подписывается.

Planner получает результат.

---

## Почему это полезно

Вместо огромной программы:

```text
robot.cpp
```

можно получить несколько компонентов:

```text
camera_node
vision_node
planner_node
controller_node
```

Каждый можно разрабатывать и тестировать отдельно.

---

## Симуляция

Одна из важных идей робототехники:

> Не всё нужно тестировать только на реальном роботе.

Можно использовать симулятор.

Архитектура:

```text
Robot Application
       ↓
Simulation
```

Вместо:

```text
Robot Application
       ↓
Real Motor
```

Можно подставить виртуальный двигатель.

## Mock hardware

Например:

```cpp
class MockMotor : public Motor {
public:
    void setSpeed(double speed) override {
        std::cout << "Speed: "
                  << speed << '\n';
    }

    void stop() override {
        std::cout << "Motor stopped\n";
    }
};
```

Теперь алгоритм можно запускать без реального мотора.

---

## Логи

Робототехническая программа должна записывать важные события:

```text
2026-10-02 Sensor connected
2026-10-02 Controller started
2026-10-02 Motor enabled
2026-10-02 Communication timeout
```

Но логирование тоже требует архитектуры.

Нельзя бесконтрольно писать гигабайты данных на диск.

---

## Ошибки оборудования

Робот должен отличать:

```text
Sensor OK
```

от:

```text
Sensor disconnected
```

и:

```text
Sensor returned invalid data
```

Например:

```cpp
enum class SensorStatus {
    Good,
    Disconnected,
    Timeout,
    InvalidData
};
```

Это позволяет алгоритму правильно реагировать на разные ситуации.

## Главное

C++ в робототехнике используется не потому, что робот обязательно должен быть написан целиком на C++.

Он удобен для:

```text

обработки данных
сетевого обмена
компьютерного зрения

```

Главный принцип:

```text
Sensors
   ↓
Data
   ↓
Algorithms
   ↓
Control
   ↓
Actuators
```

И вокруг этого должна быть построена надёжная архитектура.
