# Виртуальные функции

## Цель

В предыдущем уроке мы познакомились с полиморфизмом и увидели, что ключевую роль в нём играют виртуальные функции. Теперь разберём этот механизм подробнее.

Виртуальные функции позволяют базовому классу определить общий интерфейс, а производным классам — предоставить собственные реализации. Это один из главных механизмов объектно-ориентированного C++.

После урока вы должны понимать:

* что делает `virtual`;
* что означает `override`;
* что такое чисто виртуальная функция;
* зачем нужен виртуальный деструктор;
* как работает вызов метода через базовый указатель;
* почему виртуальные функции связаны с динамическим полиморфизмом;
* какие ограничения существуют у виртуальных функций.

---

## Обычный метод

Рассмотрим:

```cpp
class Device
{
public:
    void start()
    {
        std::cout << "Device\n";
    }
};
```

Производный класс:

```cpp
class Motor : public Device
{
public:
    void start()
    {
        std::cout << "Motor\n";
    }
};
```

Теперь:

```cpp
Motor motor;
motor.start();
```

вызовет:

```text
Motor
```

Но через базовый указатель:

```cpp
Device* device = &motor;

device->start();
```

будет выбран метод базового класса, потому что `start()` не является виртуальным.

---

## Добавляем virtual

Изменим базовый класс:

```cpp
class Device
{
public:
    virtual void start()
    {
        std::cout << "Device\n";
    }
};
```

Теперь:

```cpp
class Motor : public Device
{
public:
    void start() override
    {
        std::cout << "Motor\n";
    }
};
```

И:

```cpp
Device* device = &motor;

device->start();
```

вызовет:

```text
Motor
```

Теперь выбор реализации происходит с учётом фактического типа объекта.

---

## Почему это называется динамическим вызовом

В момент компиляции тип указателя:

```cpp
Device*
```

известен.

Но конкретный объект может быть:

```text
Motor
Camera
Lidar
Sensor
```

Если метод виртуальный, C++ выбирает соответствующую реализацию во время выполнения программы.

Это и есть динамическая диспетчеризация.

---

## override

В производном классе рекомендуется всегда писать:

```cpp
override
```

Например:

```cpp
class Camera : public Device
{
public:
    void start() override
    {
        std::cout << "Camera\n";
    }
};
```

`override` не изменяет сам механизм вызова. Это указание компилятору проверить, действительно ли метод переопределяет виртуальный метод базового класса.

---

## Почему override полезен

Допустим, базовый класс:

```cpp
class Device
{
public:
    virtual void start();
};
```

А разработчик случайно пишет:

```cpp
void Start()
{
}
```

Здесь отличается регистр буквы.

Без `override` компилятор может воспринять это как совершенно другой метод.

С:

```cpp
void Start() override
```

будет ошибка компиляции.

Таким образом, `override` помогает обнаруживать ошибки в иерархии классов.

---

## Виртуальная функция может иметь реализацию

Виртуальная функция не обязательно является абстрактной:

```cpp
class Device
{
public:
    virtual void start()
    {
        std::cout << "Generic start\n";
    }
};
```

Производный класс может переопределить её:

```cpp
class Motor : public Device
{
public:
    void start() override
    {
        std::cout << "Motor start\n";
    }
};
```

А другой производный класс может не переопределять:

```cpp
class GenericSensor : public Device
{
};
```

Тогда он унаследует базовую реализацию.

---

## Чисто виртуальная функция

Иногда базовый класс должен задавать только интерфейс, а конкретной реализации у него нет.

Для этого используется:

```cpp
virtual void start() = 0;
```

Такая функция называется чисто виртуальной.

Например:

```cpp
class Device
{
public:
    virtual void start() = 0;
};
```

Теперь производный класс должен предоставить реализацию:

```cpp
class Motor : public Device
{
public:
    void start() override
    {
        std::cout << "Motor\n";
    }
};
```

---

## Виртуальный метод как контракт

Чисто виртуальная функция можно рассматривать как контракт.

Базовый класс говорит:

> Каждый конкретный Device должен уметь выполнять start().

Но сам `Device` не говорит, как именно это делать.

Для двигателя:

```text
запустить вращение
```

Для камеры:

```text
начать захват изображения
```

Для лидара:

```text
начать сканирование
```

Интерфейс одинаковый:

```cpp
start()
```

а реализация различается.

---

## Абстрактный класс

Класс, содержащий хотя бы одну чисто виртуальную функцию, является абстрактным.

Например:

```cpp
class Device
{
public:
    virtual void start() = 0;
};
```

Нельзя написать:

```cpp
Device device;
```

Потому что `Device` не является полностью конкретным объектом.

Но можно:

```cpp
Motor motor;
Device& device = motor;
```

Абстрактный класс используется как общий интерфейс для производных классов.

Подробно абстрактные классы мы разберём в следующем уроке.

---

## Виртуальный деструктор

Рассмотрим:

```cpp
class Device
{
public:
    virtual ~Device()
    {
    }
};
```

Деструктор виртуальный.

Это особенно важно для полиморфного использования:

```cpp
Device* device = new Motor;

delete device;
```

Если базовый деструктор виртуальный, корректно вызывается цепочка:

```text
~Motor()
↓
~Device()
```

---

## Что будет без виртуального деструктора

Если базовый класс используется полиморфно, но его деструктор не виртуальный:

```cpp
class Device
{
public:
    ~Device()
    {
    }
};
```

а затем:

```cpp
Device* device = new Motor;

delete device;
```

поведение может быть некорректным для такой иерархии.

Особенно опасно это, если производный класс владеет ресурсами, которые должны освобождаться в его деструкторе.

Поэтому полиморфные базовые классы обычно объявляют деструктор:

```cpp
virtual ~Device() = default;
```

---

## Вызов базовой реализации

Производный класс может переопределить метод:

```cpp
class Motor : public Device
{
public:
    void start() override
    {
        Device::start();

        std::cout << "Motor specific logic\n";
    }
};
```

Здесь:

```cpp
Device::start();
```

явно вызывает базовую реализацию.

Это полезно, когда производному классу нужно расширить поведение, а не полностью заменить его.

---

## final

Производный класс может запретить дальнейшее переопределение:

```cpp
class Motor : public Device
{
public:
    void start() final
    {
        std::cout << "Motor\n";
    }
};
```

Теперь другой класс не сможет переопределить этот метод.

Аналогично `final` можно применить к классу:

```cpp
class Motor final : public Device
{
};
```

После этого от `Motor` нельзя наследоваться.

---

## Виртуальные функции и ссылки

Полиморфизм работает не только с указателями.

Например:

```cpp
void startDevice(Device& device)
{
    device.start();
}
```

Можно вызвать:

```cpp
Motor motor;

startDevice(motor);
```

Если `start()` виртуальный, будет вызвана:

```cpp
Motor::start()
```

Ссылка позволяет работать с объектом без явной работы с `nullptr`.

---

## Виртуальные функции и указатели

С указателем:

```cpp
void startDevice(Device* device)
{
    device->start();
}
```

также будет работать динамический полиморфизм.

Но здесь нужно учитывать возможность:

```cpp
device == nullptr
```

Поэтому перед разыменованием может потребоваться проверка:

```cpp
if (device)
{
    device->start();
}
```

---

## Виртуальная функция и конструктор

Не следует рассчитывать на обычный полиморфный вызов производного метода из конструктора базового класса.

Например:

```cpp
class Device
{
public:
    Device()
    {
        start();
    }

    virtual void start()
    {
        std::cout << "Device\n";
    }
};
```

При создании производного объекта конструктор базовой части выполняется до конструктора производной части.

Поэтому вызов виртуального метода во время конструирования не работает так, как вызов после полного создания объекта.

На практике виртуальные вызовы из конструкторов и деструкторов требуют особой осторожности.

---

## Как C++ реализует виртуальность

На уровне реализации компилятор обычно использует таблицу виртуальных функций, которую часто называют `vtable`.

Объект полиморфного класса может содержать скрытую информацию, позволяющую найти соответствующую реализацию виртуального метода.

Упрощённо:

```text
Device*
   ↓
объект Motor
   ↓
таблица виртуальных функций
   ↓
Motor::start()
```

Это реализационная деталь. Конкретное устройство зависит от компилятора и ABI, поэтому не следует воспринимать `vtable` как гарантированную часть стандарта C++.

---

## Практический пример

```cpp
#include <iostream>
#include <vector>

class Device
{
public:
    virtual void start() = 0;

    virtual ~Device() = default;
};

class Motor : public Device
{
public:
    void start() override
    {
        std::cout << "Motor starts\n";
    }
};

class Camera : public Device
{
public:
    void start() override
    {
        std::cout << "Camera starts\n";
    }
};

class Lidar : public Device
{
public:
    void start() override
    {
        std::cout << "Lidar starts\n";
    }
};

int main()
{
    Motor motor;
    Camera camera;
    Lidar lidar;

    std::vector<Device*> devices = {
        &motor,
        &camera,
        &lidar
    };

    for (Device* device : devices)
    {
        device->start();
    }

    return 0;
}
```

Один интерфейс:

```cpp
Device::start()
```

используется для трёх разных типов.

---

## Главное

Для динамического полиморфизма основные элементы:

```cpp
virtual
override
```

Базовый класс:

```cpp
virtual void start();
```

Производный:

```cpp
void start() override;
```

Если базовый класс должен задавать только интерфейс:

```cpp
virtual void start() = 0;
```

Если класс используется полиморфно, обычно нужен виртуальный деструктор:

```cpp
virtual ~Device() = default;
```

`virtual` позволяет выбирать реализацию метода по фактическому типу объекта во время выполнения.
