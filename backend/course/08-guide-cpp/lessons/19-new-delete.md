# new и delete

## Цель

В предыдущем уроке мы познакомились с динамической памятью и увидели, что программа может получать память во время выполнения. Теперь подробно разберём механизм `new` и `delete`.

Эти операторы являются частью классического C++ и до сих пор встречаются в существующем коде, библиотеках и низкоуровневых задачах. При этом использовать их нужно очень осторожно, потому что ошибка в управлении памятью может привести к утечкам, повреждению памяти и неопределённому поведению.

После урока вы должны понимать:

* что делает `new`;
* что делает `delete`;
* чем отличаются `new` и `new[]`;
* чем отличаются `delete` и `delete[]`;
* как создавать динамические объекты;
* что такое утечка памяти;
* что такое висячий указатель;
* почему нельзя использовать неправильную пару `new`/`delete`.

---

## Оператор new

Рассмотрим:

```cpp
int* pointer = new int;
```

Здесь программа запрашивает память для одного объекта `int`.

`new` возвращает адрес выделенной памяти.

Получается:

```text
pointer
   ↓
┌───────┐
│ int   │
└───────┘
```

Указатель:

```cpp
pointer
```

хранит адрес объекта.

---

## Инициализация через new

Можно сразу задать значение:

```cpp
int* pointer = new int(42);
```

Теперь:

```cpp
std::cout << *pointer;
```

выведет:

```text
42
```

Для современных форм записи также встречается:

```cpp
int* pointer = new int{42};
```

Фигурные скобки помогают избежать некоторых нежелательных преобразований и являются предпочтительным стилем во многих случаях.

---

## Освобождение памяти через delete

Если память была выделена:

```cpp
int* pointer = new int(42);
```

её нужно освободить:

```cpp
delete pointer;
```

После этого выделенный объект больше не существует.

Схема:

```text
new
↓
выделение памяти
↓
работа с объектом
↓
delete
↓
память освобождена
```

---

## После delete указатель становится опасным

Рассмотрим:

```cpp
int* pointer = new int(42);

delete pointer;
```

После `delete` переменная `pointer` всё ещё содержит старый адрес.

Но объекта по этому адресу уже нет.

Такой указатель называют висячим:

```text
pointer
   ↓
освобождённая память
```

Поэтому после освобождения часто пишут:

```cpp
pointer = nullptr;
```

Теперь указатель явно не указывает на объект:

```cpp
delete pointer;
pointer = nullptr;
```

---

## Нельзя разыменовывать освобождённую память

После:

```cpp
delete pointer;
```

нельзя делать:

```cpp
std::cout << *pointer;
```

Нельзя:

```cpp
*pointer = 100;
```

И нельзя передавать этот указатель туда, где ожидается действующий объект.

Использование освобождённой памяти называется use-after-free и приводит к неопределённому поведению.

---

## new[]

Для нескольких элементов используется `new[]`:

```cpp
int* values = new int[10];
```

Теперь выделено место для десяти `int`.

Можно использовать:

```cpp
values[0] = 10;
values[1] = 20;
```

и так далее.

---

## delete[]

Массив, созданный через `new[]`, должен освобождаться через `delete[]`:

```cpp
delete[] values;
```

Правильные пары:

```text
new       → delete
new[]     → delete[]
```

Нельзя заменять их друг другом.

---

## Почему new и new[] различаются

Рассмотрим:

```cpp
int* value = new int;
```

Создан один объект.

Поэтому:

```cpp
delete value;
```

Теперь:

```cpp
int* values = new int[10];
```

создан массив объектов.

Поэтому:

```cpp
delete[] values;
```

Для объектов сложных типов разница особенно важна, потому что при удалении массива должны корректно обрабатываться все элементы.

---

## Динамический объект класса

Можно создать объект класса динамически:

```cpp
class Robot
{
public:
    std::string name;
};

Robot* robot = new Robot;
```

Теперь доступ через:

```cpp
robot->name = "R1";
```

Оператор `->` является сокращённой формой доступа к члену через указатель.

Следующие записи эквивалентны по смыслу:

```cpp
robot->name
```

и:

```cpp
(*robot).name
```

---

## Удаление объекта

После работы объект нужно удалить:

```cpp
delete robot;
```

При этом для объекта класса будет вызван его деструктор.

Получается:

```text
new Robot
   ↓
конструктор
   ↓
работа объекта
   ↓
delete
   ↓
деструктор
   ↓
освобождение памяти
```

Это особенно важно для классов, которые владеют другими ресурсами.

---

## new и конструкторы

При создании:

```cpp
Robot* robot = new Robot("R1");
```

сначала выделяется память, а затем вызывается конструктор `Robot`.

Например:

```cpp
class Robot
{
public:
    Robot(const std::string& name)
    {
        std::cout << "Created: "
                  << name
                  << '\n';
    }
};
```

Вызов:

```cpp
Robot* robot = new Robot("R1");
```

создаст объект и вызовет его конструктор.

---

## delete и деструкторы

При:

```cpp
delete robot;
```

для объекта вызывается деструктор.

Например:

```cpp
class Robot
{
public:
    ~Robot()
    {
        std::cout << "Destroyed\n";
    }
};
```

Если:

```cpp
Robot* robot = new Robot;

delete robot;
```

деструктор выполнится автоматически перед освобождением памяти.

---

## Утечка памяти

Одна из самых очевидных ошибок:

```cpp
void createRobot()
{
    Robot* robot = new Robot;

    // работа с robot
}
```

Когда функция заканчивается, локальный указатель `robot` исчезает.

Но память, выделенная через `new`, остаётся занятой.

Адрес потерян.

Получается утечка:

```text
robot
  ↓
объект в памяти

выход из функции

robot уничтожен
  ↓
адрес потерян
  ↓
объект остался
```

---

## Двойное удаление

Очень опасная ошибка:

```cpp
int* pointer = new int(10);

delete pointer;
delete pointer;
```

Первый `delete` освобождает объект.

Второй пытается освободить уже освобождённую память.

Это неопределённое поведение.

После удаления можно обнулить указатель:

```cpp
delete pointer;
pointer = nullptr;
```

Повторный:

```cpp
delete pointer;
```

для `nullptr` безопасен.

Но это не означает, что можно бездумно вызывать `delete` в разных местах программы. Главная проблема — правильно определить владельца памяти.

---

## Два указателя на один объект

Рассмотрим:

```cpp
int* first = new int(10);
int* second = first;
```

Теперь оба указателя указывают на один объект.

Если сделать:

```cpp
delete first;
```

объект уничтожен.

Но:

```cpp
second
```

всё ещё содержит старый адрес.

Теперь `second` является висячим указателем.

Если затем:

```cpp
delete second;
```

получится двойное освобождение.

Эта проблема показывает, почему управление владением памятью очень важно.

---

## Исключения и new

Ручное управление памятью может стать особенно сложным при наличии исключений.

Например:

```cpp
int* data = new int[100];

someFunction();

delete[] data;
```

Если `someFunction()` выбросит исключение, выполнение может не дойти до:

```cpp
delete[] data;
```

В результате возникнет утечка памяти.

Именно такие ситуации стали одной из причин широкого распространения RAII и умных указателей.

---

## Современный C++

В современном C++ обычно не стоит использовать `new` и `delete` напрямую без необходимости.

Для массива:

```cpp
std::vector<int> values;
```

Для строки:

```cpp
std::string text;
```

Для объекта с уникальным владельцем:

```cpp
std::unique_ptr<Robot> robot;
```

Такие типы автоматически управляют временем жизни ресурсов.

Это не делает `new` и `delete` ненужными. Они остаются частью языка и встречаются в низкоуровневом коде, реализации библиотек и некоторых специальных задачах.

---

## Практический пример

Классический пример:

```cpp
#include <iostream>

class Counter
{
private:
    int value;

public:
    Counter(int initialValue)
        : value(initialValue)
    {
        std::cout << "Created\n";
    }

    ~Counter()
    {
        std::cout << "Destroyed\n";
    }

    void print() const
    {
        std::cout << value << '\n';
    }
};

int main()
{
    Counter* counter = new Counter(10);

    counter->print();

    delete counter;
    counter = nullptr;

    return 0;
}
```

В этом примере хорошо виден полный цикл:

```text
new
↓
конструктор
↓
использование
↓
delete
↓
деструктор
↓
nullptr
```

---

## Главное

Запомните пары:

```cpp
new       → delete
new[]     → delete[]
```

`new` выделяет динамическую память и создаёт объект. `delete` уничтожает объект и освобождает память.

При ручном управлении нужно следить за тем, чтобы:

* память не терялась;
* объект не использовался после удаления;
* память не освобождалась дважды;
* `new` соответствовал `delete`;
* ответственность за владение была понятной.

В современном C++ большинство таких задач лучше решать через RAII и стандартные контейнеры или умные указатели.
