# std::string_view

## Цель

В этом уроке разберём `std::string_view` — лёгкое представление существующей строки без необходимости создавать её копию.

После урока вы должны понимать:

* зачем нужен `std::string_view`;
* чем он отличается от `std::string`;
* почему `string_view` не владеет строкой;
* как передавать строки в функции без лишних копирований;
* почему время жизни исходной строки критически важно;
* когда `string_view` безопасен, а когда использовать его нельзя.

---

## Зачем нужен string_view

Ранее мы часто передавали строки так:

```cpp
void print_name(const std::string& name);
```

Это хороший вариант.

Но иногда функции вообще не нужно знать, что переданная строка хранится именно в `std::string`.

Например, функции достаточно прочитать текст.

Тогда можно использовать:

```cpp
std::string_view
```

Он представляет собой "окно" на существующую последовательность символов.

---

## Подключение

Нужен заголовочный файл:

```cpp
#include <string_view>
```

Пример:

```cpp
std::string_view name = "robot";
```

`name` позволяет читать символы строки, но сам не владеет памятью, где эти символы находятся.

---

## string и string_view

Сравним:

```cpp
std::string name = "robot";
```

и:

```cpp
std::string_view name = "robot";
```

`std::string` владеет своими данными.

`std::string_view` только ссылается на уже существующие данные.

Упрощённо можно представить:

```text
std::string

┌───────────────┐
│ robot         │
└───────────────┘
      ↑
   владеет данными


std::string_view

┌───────────────┐
│ robot         │
└───────────────┘
      ↑
      │
  string_view
  только смотрит
```

---

## Почему это может быть быстрее

Представим функцию:

```cpp
void process(const std::string& text);
```

Она не копирует строку благодаря ссылке.

Но если функция должна принимать разные виды строковых данных, `std::string_view` часто предоставляет более универсальный интерфейс.

Например:

```cpp
void process(std::string_view text);
```

Ей можно передать:

```cpp
std::string value = "robot";

process(value);
```

строковый литерал:

```cpp
process("robot");
```

и другие совместимые строковые представления.

Функции при этом не нужно создавать отдельную копию текста.

---

## Размер string_view

У `std::string_view` есть:

```cpp
size()
```

и:

```cpp
length()
```

Например:

```cpp
std::string_view text = "robot";

std::cout << text.size() << '\n';
```

Результат:

```text
5
```

---

## Доступ к символам

Работа с символами похожа на `std::string`:

```cpp
std::string_view text = "robot";

std::cout << text[0] << '\n';
```

Результат:

```text
r
```

Также можно использовать:

```cpp
text.at(0);
```

---

## empty()

Проверить пустоту:

```cpp
if (text.empty()) {
    std::cout << "Пустая строка\n";
}
```

---

## substr()

У `string_view` есть `substr()`:

```cpp
std::string_view text = "robot-controller";

auto part = text.substr(0, 5);

std::cout << part << '\n';
```

Результат:

```text
robot
```

Важный момент: `substr()` для `string_view` создаёт новый `string_view`, а не копию символов.

---

## find()

Можно искать подстроку:

```cpp
std::string_view text = "robot-controller";

auto position = text.find("controller");

if (position != std::string_view::npos) {
    std::cout << "Найдено\n";
}
```

---

## string_view не изменяет строку

`string_view` предназначен прежде всего для просмотра.

Например:

```cpp
std::string_view text = "robot";
```

Нельзя использовать его как обычный изменяемый `std::string`.

Если функция должна изменить строку, нужно использовать соответствующий интерфейс, например:

```cpp
std::string&
```

---

## Самая важная проблема: время жизни

`string_view` не владеет строкой.

Поэтому нельзя создавать `string_view`, который переживёт исходные данные.

Например, опасная конструкция:

```cpp
std::string_view get_name() {
    std::string name = "robot";
    return name;
}
```

После выхода из функции объект `name` уничтожается.

`string_view` остаётся указывать на уже недействительную память.

Это называется **висячей ссылкой** или dangling reference/view.

---

## Возврат string_view из литерала

А вот так можно:

```cpp
std::string_view get_name() {
    return "robot";
}
```

Строковый литерал существует в течение всей работы программы, поэтому здесь время жизни достаточное.

---

## Возврат части существующей строки

Можно безопасно вернуть представление части строки, если исходная строка продолжает существовать:

```cpp
std::string_view get_prefix(const std::string& text) {
    return text.substr(0, 3);
}
```

Использование:

```cpp
std::string command = "robot-start";

auto prefix = get_prefix(command);

std::cout << prefix << '\n';
```

Здесь `command` живёт дольше `prefix`.

---

## string_view и временные строки

Особенно опасны временные объекты:

```cpp
std::string_view view = std::string("robot");
```

После завершения выражения временный `std::string` уничтожается.

`view` остаётся ссылающимся на недействительные данные.

Поэтому такой код использовать нельзя.

---

## Практический пример: обработка команды

Представим систему управления роботом.

Команды приходят в виде:

```text
START
STOP
RESET
```

Можно написать:

```cpp
#include <iostream>
#include <string_view>

void process_command(std::string_view command) {
    if (command == "START") {
        std::cout << "Запуск\n";
    } else if (command == "STOP") {
        std::cout << "Остановка\n";
    } else if (command == "RESET") {
        std::cout << "Сброс\n";
    } else {
        std::cout << "Неизвестная команда\n";
    }
}

int main() {
    std::string command = "START";

    process_command(command);
    process_command("STOP");
}
```

Функция может принимать и `std::string`, и литералы.

---

## string_view и параметры функций

Рассмотрим функцию:

```cpp
void log_message(const std::string& message);
```

Если она только читает сообщение, часто можно использовать:

```cpp
void log_message(std::string_view message);
```

Например:

```cpp
log_message("Motor started");
```

или:

```cpp
std::string message = "Motor started";

log_message(message);
```

Это удобный интерфейс для функций, которым нужен только просмотр текста.

---

## Что хранит string_view

Концептуально `string_view` можно представить как пару:

```text
адрес начала данных
+
количество символов
```

То есть:

```text
┌───────────────┐
│ данные строки │
└───────────────┘
       ↑
       │
   pointer
       
length = 5
```

Поэтому сам `string_view` маленький и не содержит копию всей строки.

Точная внутренняя реализация является деталью библиотеки, но для понимания достаточно такой модели.

---

## Нельзя возвращать view на локальный объект

Запомните это правило:

```cpp
std::string_view bad() {
    std::string text = "hello";
    return text;
}
```

Так делать нельзя.

Правильно либо вернуть `std::string`:

```cpp
std::string get_text() {
    return "hello";
}
```

либо убедиться, что источник данных продолжит существовать.

---

## Когда использовать string_view

`std::string_view` особенно полезен:

* в функциях, которые только читают строку;
* при разборе текста;
* при обработке команд;
* при поиске и сравнении;
* в парсерах;
* в логировании;
* при обработке протоколов;
* когда важно избежать лишних копирований.

Например:

```cpp
void parse_command(std::string_view command);
```

выглядит естественно для функции, которая только анализирует команду.

---

## Когда использовать std::string

Если объект должен **владеть текстом**, нужен `std::string`.

Например:

```cpp
class Device {
private:
    std::string name;
};
```

Здесь устройство должно хранить собственное имя.

`string_view` для постоянного хранения имени может быть опасен, потому что источник строки может исчезнуть.

## Главное

`std::string_view` — это **невладеющее представление строки**.

Он позволяет работать с существующими символами без копирования текста.

Основная идея:

```cpp
void process(std::string_view text);
```

Но нужно всегда помнить:

> `string_view` не продлевает время жизни исходной строки.

Если исходные данные уничтожены, `string_view` становится недействительным.

Поэтому `string_view` особенно полезен для временной обработки текста, а `std::string` — когда программе необходимо владеть строкой.
