# Ошибки компиляции

## Цель

Ошибки — нормальная часть разработки на C++. Даже опытный программист регулярно сталкивается с сообщениями компилятора.

Проблема начинающего разработчика обычно не в самом наличии ошибки, а в том, что сообщение компилятора выглядит непонятно. В этом уроке научимся читать такие сообщения, находить реальную причину ошибки и отличать ошибку компиляции от ошибки линковки и ошибки выполнения.

После урока вы должны понимать:

* что такое ошибка компиляции;
* как читать сообщение компилятора;
* чем первая ошибка отличается от последующих;
* как находить строку, вызвавшую проблему;
* почему одна ошибка может породить десятки сообщений;
* какие ошибки встречаются чаще всего;
* как системно исправлять ошибки;
* почему не стоит исправлять ошибки наугад.

---

## Что такое ошибка компиляции

Компилятор должен превратить исходный C++ код в машинный код.

Если код нарушает правила языка или компилятор не может понять его структуру, процесс останавливается.

Например:

```cpp
int main() {
    std::cout << "Hello"
}
```

Здесь пропущена:

```cpp
;
```

Компилятор сообщит об ошибке.

---

## Ошибка — это не всегда проблема в указанной строке

Это очень важное правило.

Например:

```cpp
std::cout << "Hello"

int value = 10;
```

Компилятор может указать на:

```cpp
int value = 10;
```

хотя настоящая проблема находится строкой выше.

Причина:

```text
пропущена ;
```

Поэтому всегда полезно проверить несколько строк перед указанной позицией.

---

## Как выглядит сообщение

У GCC сообщение может выглядеть примерно так:

```text
main.cpp:5:10: error: expected ';' before 'return'
```

Здесь:

```text
main.cpp
```

— файл.

```text
5
```

— номер строки.

```text
10
```

— позиция в строке.

```text
error
```

— тип сообщения.

Остальная часть объясняет, что именно компилятор ожидал.

---

## Самая важная информация

При чтении ошибки сначала ищите:

```text
имя файла
номер строки
тип сообщения
описание ошибки
```

Например:

```text
motor.cpp:17:5: error: ...
```

Начните с:

```text
motor.cpp
строка 17
```

---

## Предупреждение и ошибка

Компилятор может вывести:

```text
warning
```

или:

```text
error
```

`warning` — предупреждение.

Программа иногда всё ещё может быть собрана.

`error` — ошибка, которая обычно не позволяет получить корректный объектный файл.

Например:

```text
warning: unused variable
```

может не остановить сборку.

А:

```text
error: expected ';'
```

обычно остановит её.

---

## Почему нужно читать первую ошибку

Представим, компилятор вывел:

```text
20 ошибок
```

Не обязательно у вас действительно двадцать независимых проблем.

Одна ошибка в начале файла может сломать разбор последующего кода.

Например:

```cpp
class Motor {
public:
    void start()

    void stop();
};
```

После пропущенной `;` компилятор может начать неправильно интерпретировать следующие строки.

Поэтому хорошее правило:

> сначала исправляйте первую осмысленную ошибку, затем компилируйте снова.

---

## Пропущенная точка с запятой

Очень частая ошибка:

```cpp
int value = 10
```

Правильно:

```cpp
int value = 10;
```

То же самое:

```cpp
return value
```

нужно:

```cpp
return value;
```

---

## Пропущенная фигурная скобка

Например:

```cpp
int main() {
    if (true) {
        std::cout << "Hello\n";
}
```

Не хватает:

```cpp
}
```

Компилятор может сообщить об ошибке ближе к концу файла.

Это пример ситуации, когда указанная строка может быть далеко от настоящей причины.

---

## Неправильное имя переменной

Например:

```cpp
int speed = 100;

std::cout << speeed;
```

Здесь:

```text
speed
```

и:

```text
speeed
```

разные имена.

Компилятор не может найти `speeed`.

Исправление:

```cpp
std::cout << speed;
```

---

## Переменная вне области видимости

Например:

```cpp
if (true) {
    int value = 42;
}

std::cout << value;
```

Переменная `value` существует только внутри блока `if`.

После:

```cpp
}
```

она больше недоступна.

Компилятор сообщит, что `value` не объявлена в текущей области.

---

## Забытый include

Например:

```cpp
int main() {
    std::cout << "Hello\n";
}
```

Но:

```cpp
#include <iostream>
```

нет.

Компилятор не знает о `std::cout`.

Исправление:

```cpp
#include <iostream>

int main() {
    std::cout << "Hello\n";
}
```

---

## Неправильный namespace

Например:

```cpp
#include <iostream>

int main() {
    cout << "Hello\n";
}
```

Можно написать:

```cpp
std::cout
```

или использовать подходящий `using`.

Предпочтительный вариант в учебном и большом прикладном коде:

```cpp
std::cout
```

---

## Неправильный тип

Например:

```cpp
int value = "hello";
```

Строка не может быть обычным `int`.

Нужно либо:

```cpp
std::string value = "hello";
```

либо передать число:

```cpp
int value = 42;
```

---

## Ошибка вызова функции

Есть функция:

```cpp
int add(int a, int b);
```

Но вызываем:

```cpp
add(10);
```

Функция требует два аргумента.

Нужно:

```cpp
add(10, 20);
```

---

## Ошибка типа аргумента

Например:

```cpp
void set_speed(int speed);
```

А затем:

```cpp
std::string speed = "1000";

set_speed(speed);
```

Типы не соответствуют ожидаемому интерфейсу.

Нужно преобразовать данные осознанно или изменить интерфейс функции.

---

## Отсутствующее объявление

Представим:

```cpp
int main() {
    Motor motor;
}
```

но компилятор не знает, что такое `Motor`.

Если класс находится в:

```text
motor.h
```

нужно:

```cpp
#include "motor.h"
```

---

## Ошибка в объявлении класса

Например:

```cpp
class Motor {
public
    void start();
};
```

Пропущен:

```cpp
:
```

Правильно:

```cpp
class Motor {
public:
    void start();
};
```

---

## Ошибка в определении метода

В заголовке:

```cpp
class Motor {
public:
    void start();
};
```

А в `.cpp`:

```cpp
void Motor::stop() {
}
```

Такого метода нет.

Нужно:

```cpp
void Motor::start() {
}
```

Если имя, параметры или квалификаторы не совпадают, компилятор сообщит об ошибке.

---

## Ошибка const

Например:

```cpp
class Sensor {
public:
    double read() const;
};
```

А реализация:

```cpp
double Sensor::read() {
    return 10.0;
}
```

Это не одно и то же объявление.

Нужно:

```cpp
double Sensor::read() const {
    return 10.0;
}
```

`const` является частью сигнатуры метода.

---

## Ошибка include path

Если написать:

```cpp
#include "motor.h"
```

но компилятор не знает, где искать этот файл, появится ошибка вида:

```text
fatal error: motor.h: No such file or directory
```

Проблема может быть:

```text
файл отсутствует;
неправильный путь;
не настроен include directory;
неверное имя файла.
```

В CMake это часто исправляется настройкой:

```cmake
target_include_directories(...)
```

---

## Ошибка регистра

На некоторых системах:

```text
Motor.h
```

и:

```text
motor.h
```

могут считаться разными файлами.

Поэтому лучше придерживаться единого соглашения об именовании.

Например:

```text
motor.h
motor.cpp
sensor.h
sensor.cpp
```

---

## Ошибка шаблонов

Шаблон:

```cpp
template <typename T>
T maximum(T a, T b) {
    return a > b ? a : b;
}
```

обычно должен быть доступен в месте использования.

Если объявление находится в `.h`, а реализация спрятана в `.cpp`, можно получить проблемы при использовании шаблона из другого файла.

Это одна из причин, почему шаблонный код часто полностью размещают в заголовках.

---

## Ошибка линковки — это другое

Представим:

```cpp
int calculate(int value);
```

Объявление есть.

Но реализации:

```cpp
int calculate(int value) {
    return value * 2;
}
```

нет среди исходных файлов сборки.

Компиляция `main.cpp` может пройти.

Но linker сообщит об отсутствии реализации.

Например:

```text
undefined reference to calculate(int)
```

Это уже не обычная ошибка компиляции.

---

## Ошибка выполнения

Есть ещё третий тип проблем.

Программа может успешно собраться:

```text
compile → OK
link → OK
```

а затем упасть при запуске.

Например:

```cpp
int* pointer = nullptr;

std::cout << *pointer;
```

Компилятор может принять этот код.

Но выполнение программы приводит к неопределённому поведению.

Ошибки выполнения мы подробно разберём дальше.

---

## Системный подход к исправлению ошибок

Когда программа не компилируется, не стоит сразу менять десять строк.

Используйте последовательность:

```text
1. Прочитать первую ошибку.
2. Открыть указанный файл.
3. Перейти к указанной строке.
4. Проверить несколько строк выше.
5. Понять, что ожидал компилятор.
6. Исправить одну проблему.
7. Собрать снова.
```

Так намного проще найти настоящую причину.

---

## Не нужно бояться длинных сообщений

Современные компиляторы иногда выводят очень длинные ошибки.

Особенно это заметно с:

```text
templates
STL
concepts
generic code
```

Не нужно читать всё сообщение сразу.

Сначала ищите:

```text
error
```

имя файла и строку.

Затем смотрите на непосредственную причину.

---

## Используйте минимальный пример

Если ошибка сложная, попробуйте уменьшить программу.

Например, вместо:

```text
1000 строк проекта
```

оставьте:

```cpp
#include <vector>

int main() {
    std::vector<int> values;

    values.push_back(10);
}
```

Если минимальный вариант работает, значит проблема находится в окружающем коде.

Такой подход называется созданием минимального воспроизводимого примера.

---

## Ошибка компилятора как подсказка

Компилятор не просто говорит:

```text
"не работает"
```

Он пытается сообщить:

```text
что он увидел;
что ожидал;
где возникла проблема.
```

Поэтому хорошая привычка:

> не угадывать, а читать сообщение компилятора.

---

## Практический пример

Рассмотрим ошибочный код:

```cpp
#include <iostream>

class Motor {
public:
    void start()
};

int main() {
    Motor motor;

    motor.start();
}
```

Компилятор сообщит об ошибке рядом с:

```cpp
}
```

Но настоящая проблема выше:

```cpp
void start()
```

должно быть:

```cpp
void start();
```

После исправления:

```cpp
#include <iostream>

class Motor {
public:
    void start();
};

void Motor::start() {
    std::cout << "Motor started\n";
}

int main() {
    Motor motor;

    motor.start();
}
```

программа собирается.

## Главное

Ошибки компиляции — нормальная часть разработки.

При их исправлении важно различать:

```text
ошибка компиляции
        ↓
компилятор не может понять/проверить исходный код
```

```text
ошибка линковки
        ↓
части программы не удалось правильно соединить
```

```text
ошибка выполнения
        ↓
программа уже запустилась, но во время работы возникла проблема
```

Самое полезное правило:

> исправляйте первую понятную ошибку, а затем собирайте проект снова.

Одна ранняя ошибка часто порождает десятки вторичных сообщений. Поэтому не нужно пытаться исправить всё сразу.
