# Командная строка: текст как интерфейс к системе

Графический интерфейс удобен, пока есть мышь и экран. На сервере без монитора, в контейнере и в журнале «что именно запускали вчера» остаётся текст. **CLI** — управление компьютером строкой: программу можно повторить, вставить в скрипт и сравнить с инструкцией символ в символ.

Типичная форма: **команда**, затем **опции**, затем **позиционные аргументы** (операнды). Опции часто начинаются с `-` или `--`. Для shell это всё токены. Смысл «это флаг или имя файла» определяет уже сама программа после запуска. Shell не знает, что такое `-l` у `ls`.

Хороший CLI даёт человекочитаемый вывод по умолчанию и отдельный режим для машин: JSON, «фарфор», тихий режим. Если парсить «красивую таблицу» регулярками, скрипт сломается при смене языка интерфейса или ширины колонок.

Справка — часть интерфейса. `command --help`, `man command`, в PowerShell `Get-Help`. В man-страницах читайте SYNOPSIS: квадратные скобки — необязательно, многоточие — повтор, вертикальная черта — выбор. У `git`, `ip`, `systemctl` сначала карта **подкоманд**, потом флаги.

**Код возврата** — целое число, которым процесс сообщает итог. Ноль по соглашению означает успех. Ненулевые значения кодируют классы ошибок; таблица зависит от программы. Скрипты проверяют код, а не только текст на экране. Следующая команда, даже `echo`, перезапишет `$?` в bash.

Вручную вы смотрите цвета и таблицы. В скрипте нужны предсказуемые строки и отсутствие вопросов «нажмите Enter». Многие утилиты имеют ключ «не спрашивать» именно для этого.

Если программе нужен пароль, она может читать с управляющего терминала, а не из стандартного ввода — чтобы пароль не ушёл в конвейер. Это снова про разделение потоков и TTY из прошлого урока.

```bash
ls -lh /var/log
ls -1 /var/log
false
echo $?
ls --help | head
```

`ls -lh` удобен человеку. Для скрипта чаще нужен простой список или утилита со стабильным форматом. `false` только возвращает код 1 — её используют, чтобы проверить ветку «ошибка».

Документируйте в инструкциях полные имена опций (`--verbose` вместо `-v`), если команда позволяет: через полгода короткие флаги читаются хуже.

## Типичные ошибки

Парсить цветной вывод `ls` в скриптах. Игнорировать код возврата в автоматизации. Считать, что порядок опций везде свободный. Копировать инструкции «нажмите кнопку» на сервер, где кнопки нет.

## Практика

### Задание 1. Справка трёх утилит

Выберите три команды, которыми вы уже пользовались. Для каждой найдите help и выпишите одну опцию и один позиционный аргумент. Запустите команду с заведомо неверным аргументом и запишите код возврата.

### Задание 2. Человек и машина

Сравните вывод одной утилиты «как в окне» и с флагом стабильного формата, если он есть (`-1`, `--porcelain`, `--format`, JSON). Почему второй вариант лучше класть в скрипт?

### Задание 3. Подкоманды

Откройте справку `git` или `ip` (что есть в системе). Нарисуйте два уровня: подкоманда и её флаги. Чем ошибка «не та подкоманда» отличается от «не тот флаг»?

### Задание 4. Пропавший статус

Выполните заведомо неуспешную команду, затем сразу `echo ok`, затем посмотрите код возврата. Почему проверять статус нужно сразу, а не «в конце сессии»?
