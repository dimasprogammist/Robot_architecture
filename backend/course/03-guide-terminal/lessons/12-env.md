# Переменные окружения процесса

Окружение — список строк `имя=значение` **у процесса**, не «настройки всей ОС». При запуске ребёнок получает **копию** на этот момент. Соседние уже запущенные процессы вашу правку не увидят. Родитель тоже нет.

Типичные имена: `PATH`, `HOME`, `USER`, `LANG`, `EDITOR`. При exec ядро передаёт envp рядом с argv. Программа читает через getenv / `os.environ`.

В bash `VAR=1` может остаться таблицей **shell**. Потомки видят только то, что `export`. Классика: Python «не видит MYVAR» — забыли export или запустили не того ребёнка. Префикс `VAR=value команда` действует на **один** запуск, сеанс не портит: удобно для `LANG=C` или временного PATH.

Подстановку `$HOME` делает **shell до** exec. Сама программа синтаксис `$` может не понимать — ей уже готовая строка в argv или свой getenv.

Интерактивный `~/.bashrc` не равен cron, systemd, CI: там беднее PATH и другой пользователь. «В терминале работает, в службе нет» — почти всегда окружение, cwd или UID, не «баг Python».

Секрет в окружении виден в `environ` процесса и копируется детям. Хуже аргумента командной строки (его ещё и `ps` светит), лучше, чем вечный `export PASSWORD` в профиле. Уже — файл с узкими правами или секретница службы.

```bash
echo "$HOME"
echo "$PATH"
export GREETING=hello
python -c "import os; print(os.environ.get('GREETING'))"
LANG=C true
env | head
```

Имена заглавными — соглашение для экспортируемых настроек. Значения всегда строки, пока программа не разберёт.

## Практика

### Задание 1. Export и без него

Переменная без export и с export, каждый раз `python -c` печатает `os.environ`. Затем одноразовый префикс в той же строке.

### Задание 2. PATH службы

Программа находится в терминале и не находится у службы. Три проверки: пользователь, PATH, рабочий каталог.

### Задание 3. Секрет

Кому виден пароль в окружении? Сравните с аргументом команды и с файлом прав `600`.

### Задание 4. Профиль не выполнился

Автозапуск не читает `.bashrc`. Где задать PATH: в скрипте, в юните службы, в login-профиле? Обоснуйте.
