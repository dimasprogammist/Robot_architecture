# Bash — практический язык оболочки

Bash — частая оболочка Linux-серверов: установщики, unit-обёртки, куски CI. Совместим с большой кучей старых сценариев и шире строгого POSIX `sh`. Минимальный контейнер может дать только dash — тогда либо переносимый `sh`, либо образ с bash.

Переменные — строки. Массивы и арифметика есть, структуры как в Python — нет. Язык запускает команды; сложная логика в нём неуклюжа.

`if` / `case`, `[[ ... ]]` для строк и файлов; старый `[` / `test` живёт в чужих скриптах. В условии проверяют **код** и выражения bash, внешние команды — как обычно. Циклы `for`/`while` по файлам: пробелы и glob режут имена. Для странных имён — нуль-разделитель (`-print0` / `read -d ''`).

Функции — именованный блок в том же процессе. На время вызова свои `$1…`. `local` ограничивает переменные. Возврат — статус, не объект.

Подстановки: `$()`, `$(( ))`, `${var%pattern}`. Мощно и быстро становится нечитаемо — комментируйте. Alias из профиля в скриптах не существует: пишите полные имена.

Каждая внешняя команда в цикле на миллион строк дороже, чем `awk`/`sort` одним проходом. Чистый bash-цикл не бесплатен.

`set -x` и `trap` на EXIT/ERR — убрать временные файлы при сбое. Скрипт, который читают раз в полгода, должен быть скучным.

```bash
#!/usr/bin/env bash
set -euo pipefail

greet() {
  local who="$1"
  echo "hi, $who"
}

if [[ -d /tmp ]]; then
  greet "tmp exists"
fi

for f in /tmp/hello.sh /tmp/нет_такого; do
  [[ -e $f ]] && echo "have $f"
done
```

`[[ -e $f ]]` без кавычек снова ловушка пробела — в своём коде кавычьте `"$f"`.
