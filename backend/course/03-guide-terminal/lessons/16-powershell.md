# PowerShell — объекты и конвейер

На Windows (и кроссплатформенно) часто живёт другая оболочка. Внешне тоже строка команд. Внутри `|` тащит **объекты .NET**, не обязательно текст. Следующий cmdlet читает свойства, не колонки глазами.

Cmdlet: глагол-существительное (`Get-ChildItem`, `Select-Object`), параметры `-Path`, `-Recurse`. Справка `Get-Help`. Форматирование в конце цепочки рисует таблицу для человека — то, что на экране, не всегда то, что в конвейере.

UNIX-утилиты (`git`, `ipconfig`) — внешние процессы, их stdout **текст**. Смешение миров: где ещё объекты, где уже байты. Переменные `$`, окружение `$env:NAME`. Код native-программы — `$LASTEXITCODE`. Ошибки самих cmdlet — исключения и поток ошибок, не тот же `$?`, что в bash. Привычка «ненуль = красный» ломается, пока не включите строгую обработку.

Скрипты `.ps1`. Execution policy может запретить неподписанные — это админка, не синтаксис. Планировщик не читает ваш профиль: пути и модули задавайте явно.

Силён в Windows: службы, реестр, CIM, AD. На Linux-роботе чаще bash и нативные утилиты. Инструмент по платформе, не по моде.

```powershell
Get-ChildItem -Path $env:TEMP | Select-Object -First 3 Name, Length
$env:PATH -split ';' | Select-Object -First 5
cmd /c "exit 7"
$LASTEXITCODE
Get-Help Get-Process
```

После `cmd /c "exit 7"` смотрите `$LASTEXITCODE`, не только вывод. `Get-ChildItem` — родственник `ls`, но отдаёт объекты с `Length`, не строку «как в учебнике UNIX».
