# Код возврата и успех команды

Процесс уходит — ядру остаётся маленький статус. В bash он в `$?`, **до следующей команды переднего плана**. Даже безобидный `echo` его перезапишет. POSIX: **0 — успех**, ненуль — неуспех или класс ошибки. Скрипту нужен этот канал, не «красивость» вывода.

Утилиты кодируют по-своему. `grep`: 0 нашло, 1 не нашло, 2 поломка. «Нет совпадений» для пайплайна может быть нормой. Читайте man, не гадайте.

`cmd1 && cmd2` — вторая только при нуле первой. `cmd1 || cmd2` — если первая неуспешна. `if cmd; then` смотрит **код** `cmd`, не её stdout. Сравнение строк — отдельные тесты, у них тоже код.

Конвейер без `pipefail`: статус **последней** стадии. `false | true` — успех. Для CI включают `pipefail` или проверяют каждую ступень.

Сигнал: часто статус 128+номер. 130 после Ctrl+C — SIGINT, не «магическая ошибка 130».

`set -e` рвёт скрипт на ненуле простых команд, но внутри `if cmd; then` и части списков — оговорки. Когда важна ясность, пишут `cmd || exit 1`. `cmd || true` глотает ошибку — только если это решение, не рефлекс.

Диагностика: сообщение, какая ступень дала ненуль (`$?` сразу), аргументы и кавычки, путь и cwd, права. Потом повтор. Не меняйте пять вещей сразу.

```bash
true; echo $?
false; echo $?
ls /tmp >/dev/null && echo ok
ls /нет_такого >/dev/null 2>&1 || echo failed
grep -q '^root:' /etc/passwd
echo $?
```

`true`/`false` существуют ради 0 и 1. `grep -q` молчит текстом, говорит кодом.

`exit N` в скрипте завершает эту оболочку с N. CI красит билд по ненулю — проглоченный статус даёт ложный зелёный.
