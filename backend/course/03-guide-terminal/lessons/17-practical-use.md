# Терминал в работе разработчика

Раздел разобрал механизм: shell превращает строку в процесс, данные текут по fd, путь и cwd задают «где», код возврата — «чем кончилось», скрипт повторяет цепочку. В работе куски не живут порознь. Git, pip, ssh, docker — те же процессы, argv, stdout и статус. Не новые физики.

Контроль версий: `commit` / `push` — внешняя программа, её вывод можно грепать, её ненуль должен рвать скрипт выкладки. Языки и пакеты: интерпретатор, venv, install — PATH и окружение. «У меня работает, на сервере нет» почти всегда отсюда, не от «другого Python в принципе». SSH даёт **тот же** класс оболочки на другой машине: пути, права, процессы уже ваши. Контейнер — снова CLI, только результат — изолированное окружение, не один файл.

Выкладка на стенд: ssh → `cd` в каталог → обновить код → проверить `$?` → restart службы → хвост лога. Каждый шаг уже был в разделе. Диагностика: сервис жив, лог пустой, код 0 — гипотезы из прошлых уроков: писали в stderr, не в тот cwd, не та команда (`type`/`which`).

Не учите «все инструменты на будущее». Идите от задачи. Не считайте git особой магией: магия — объекты Git, CLI — обычный процесс.

```text
задача → команда (git, pip, ssh, …)
       → процесс, потоки, argv, статус
```

До SSH на сервер обязательны: пути, права на уровне «не rm -r вслепую», код возврата, pipe/redirect. Службы, journald, пакеты — следующий раздел Linux, их можно доучить там.

## Практика

### Задание 1. Своя процедура

Выкладка или диагностика сервиса. У каждого шага метка раздела: путь, статус, redirect, процесс, окружение.

### Задание 2. Чеклист воспроизводимости

Пять пунктов, прежде чем «команда такая же на другой машине»: оболочка, cwd, PATH, права, формат вывода (не цвет).

### Задание 3. Инцидент

Лог пустой, код 0, процесс жив. Какие три гипотезы из раздела отбросите последними?

### Задание 4. Мост к Linux

Что обязательно до входа по SSH и что можно выучить уже на сервере (службы, журналы, пакеты)?
