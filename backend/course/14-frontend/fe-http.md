# HTTP из браузера — fetch

## Цель

Научиться запрашивать и отправлять данные с страницы через `fetch`, не перезагружая вкладку. После урока вы загрузите список заказов с API и отправите создание заказа методом POST, обработав успех и ошибку.

## Что уже нужно понимать

HTTP: метод, URL, заголовки, тело, коды ответа. Формы умеют слать GET/POST «по-старому» с перезагрузкой. `fetch` — программный способ сделать тот же обмен из JavaScript и самому решить, что показать пользователю. Бэкенд (FastAPI) вы уже представляете как источник JSON.

## Объяснение

Панель заказов бесполезна, если данные живут только в массиве одной вкладки. Нужен сервер: общая правда для всех операторов, правила, запись в БД. Браузерный код становится клиентом API: «дай заказы», «создай заказ», «смени статус».

`fetch(url, options)` возвращает Promise с объектом `Response`. Важно: успешный сетевой ответ с кодом 404/500 всё равно «резолвится» — сеть доставила ответ. Проверяйте `response.ok` или `status`. Тело читают методами `response.json()`, `text()`, `blob()` — каждый можно вызвать один раз.

Для JSON обычно ставят заголовок `Content-Type: application/json` и `JSON.stringify` тела. Для cookie-сессий важен `credentials` (по умолчанию same-origin поведение зависит от контекста; для учебных API часто используют токен в заголовке — зависит от курса бэкенда). CORS: если фронт на другом origin, сервер должен явно разрешить запрос — иначе браузер заблокирует чтение ответа.

Асинхронность: `async/await` делает код линейным. Оборачивайте в `try/catch`: сеть может упасть, JSON может быть битым, сервер может вернуть `{detail: ...}`.

## Термины

- **fetch** — браузерный API HTTP-запросов.
- **Response** — обёртка над ответом (статус, заголовки, тело).
- **CORS** — политика браузера о доступе к чужому origin.
- **Idempotency (идея)** — повтор GET безопасен; повтор POST создания — нет без защиты.

## Как это устроено

Схема: пользователь открыл страницу → JS вызвал `GET /api/orders` → FastAPI прочитал БД → вернул JSON → JS положил данные в массив → `render()`. Кнопка «Создать» → `POST /api/orders` с телом → сервер валидирует → 201 + объект → клиент добавляет в список или перезагружает список целиком.

Перезагрузка списка после мутации проще и надёжнее для начала, чем вручную сливать объекты. Оптимистичный UI (сразу рисуем, потом откатываем при ошибке) — следующий уровень, его легко сделать плохо.

Индикаторы загрузки: флаг `loading`, кнопка `disabled`, текст «Загрузка…». Иначе двойной клик создаст два заказа. Отмена через `AbortController` полезна при быстрой смене фильтра — старый ответ не должен затереть новый.

## Пример

```javascript
const API = "/api/orders";
let orders = [];
let loading = false;

async function loadOrders() {
  loading = true;
  render();
  try {
    const res = await fetch(API);
    if (!res.ok) {
      throw new Error(`Не удалось загрузить: ${res.status}`);
    }
    orders = await res.json();
  } catch (err) {
    console.error(err);
    alert(err.message || "Сеть недоступна");
  } finally {
    loading = false;
    render();
  }
}

async function createOrder(payload) {
  const res = await fetch(API, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  });
  if (!res.ok) {
    let detail = `Ошибка ${res.status}`;
    try {
      const body = await res.json();
      detail = body.detail || detail;
    } catch (_) {}
    throw new Error(detail);
  }
  return res.json();
}

document.getElementById("create-order").addEventListener("submit", async (e) => {
  e.preventDefault();
  const data = new FormData(e.target);
  const payload = {
    customer: String(data.get("customer") || "").trim(),
    city: String(data.get("city") || "").trim(),
  };
  try {
    await createOrder(payload);
    e.target.reset();
    await loadOrders();
  } catch (err) {
    alert(err.message);
  }
});

loadOrders();
```

## Разбор примера

`loadOrders` всегда снимает `loading` в `finally` — даже при ошибке кнопка не залипнет навечно, если вы завяжете UI на флаг. Проверка `res.ok` отделяет «сервер ответил отказом» от «сети вообще нет» (второе поймает `catch`).

POST сериализует объект в JSON. Сервер ожидает те же имена полей, что в контракте API — рассинхрон `customer`/`client_name` даст 422. После успеха мы не гадаем, какой id выдал сервер вручную: просто перечитываем список. Для учебного темпа это честно.

Сообщение пользователю через `alert` грубо, но ясно; в реальном UI будет баннер. Главное — не глотать ошибку молча.

## Типичные ошибки

- Считать любой завершённый `fetch` успехом без проверки статуса.
- Забыть `JSON.stringify` и отправить `[object Object]`.
- Игнорировать CORS и чинить «бэкенд», когда виновата политика браузера.
- Дублировать POST без защиты от двойного клика.
- Класть токены в `localStorage` бездумно (тема безопасности шире этого урока — хотя бы не светите секреты в репозитории).

## Что запомнить

`fetch` — HTTP из JS без перезагрузки. Проверяйте статус, парсите JSON осознанно, обрабатывайте ошибки. Клиент отображает и собирает ввод; сервер хранит правду. Индикатор загрузки и повторная загрузка списка упрощают жизнь новичку.

## Задание

Добавьте `PATCH` или `POST` смены статуса заказа по id. На время запроса блокируйте кнопку. Если сервер вернул 409/400 — покажите текст ошибки из JSON.
