# Обратная связь и управление движением

## Цель

Робот должен не просто получать команду, а уметь контролировать результат своего действия.

Если мы говорим:

> двигатель должен вращаться со скоростью 1000 об/мин,

роботу нужно понимать не только желаемое значение, но и фактическое.

После урока вы должны понимать:

* что такое система управления;
* чем отличается открытый и замкнутый контур;
* что такое setpoint и actual value;
* что такое ошибка управления;
* зачем нужна обратная связь;
* как строится простой контур управления двигателем;
* почему реальное движение отличается от расчётного;
* зачем роботу несколько уровней управления.

---

# Управление без обратной связи

Начнём с очень простой системы.

Допустим, нужно включить двигатель на 5 секунд.

```text
Программа
    ↓
Включить мотор
    ↓
Ждать 5 секунд
    ↓
Выключить мотор
```

Программа предполагает:

```text
5 секунд работы
→ нужное перемещение
```

Но робот не знает, действительно ли это произошло.

Если колесо проскользнуло:

```text
ожидалось: 5 м
получилось: 4 м
```

Программа этого не узнает.

Такая система называется **управлением без обратной связи** или открытым контуром.

---

# Открытый контур

Упрощённо:

```text
Команда
   ↓
Контроллер
   ↓
Исполнитель
   ↓
Механизм
```

Информация о результате обратно не возвращается.

Например:

```text
PWM = 60%
```

и всё.

Контроллер не знает:

```text
какая реальная скорость?
```

---

# Замкнутый контур

Теперь добавим датчик.

```text
              ┌─────────────────┐
              │   Контроллер    │
              └────────┬────────┘
                       ↓
                    Двигатель
                       ↓
                    Механика
                       ↓
                     Датчик
                       │
                       └──────────→ обратно
```

Теперь контроллер может сравнить:

```text
желаемое значение
```

и:

```text
фактическое значение
```

Например:

```text
Желаемая скорость = 1000 RPM
Фактическая        = 850 RPM
```

Значит, нужно изменить управление.

---

# Setpoint и Actual Value

В системах управления часто используются два важных понятия.

### Setpoint

Желаемое значение.

Например:

```text
Setpoint = 1000 RPM
```

### Actual Value

Фактическое значение, полученное от датчика.

```text
Actual = 850 RPM
```

Контроллер сравнивает их.

---

# Ошибка

Ошибка определяется как разница:

```text
Error = Setpoint - Actual
```

Например:

```text
Setpoint = 1000
Actual   = 850
```

получаем:

```text
Error = 150
```

Контроллер должен использовать эту ошибку, чтобы изменить управляющее воздействие.

---

# Простейший регулятор

Можно сделать очень простой алгоритм:

```text
если ошибка большая:
    увеличить управление

если ошибка маленькая:
    немного увеличить управление

если ошибка около нуля:
    оставить управление
```

Например:

```python
if error > 100:
    pwm += 10
elif error > 20:
    pwm += 2
```

Это уже обратная связь, хотя такой регулятор очень примитивный.

---

# Пример с двигателем

Пусть:

```text
Setpoint = 1000 RPM
```

Первое измерение:

```text
Actual = 700 RPM
```

Ошибка:

```text
300 RPM
```

Контроллер увеличивает управление.

Следующее измерение:

```text
Actual = 900 RPM
```

Ошибка:

```text
100 RPM
```

Ещё немного корректируем.

Следующее:

```text
Actual = 990 RPM
```

Ошибка:

```text
10 RPM
```

Система приблизилась к цели.

---

# Почему одного измерения недостаточно

Предположим, двигатель достиг:

```text
1000 RPM
```

Мы уменьшили управление.

Но нагрузка изменилась.

Например, робот заехал на поверхность с большим сопротивлением.

Скорость упала:

```text
1000 → 800 RPM
```

Если обратная связь работает постоянно, контроллер снова увидит:

```text
Error = 200
```

и увеличит воздействие.

Поэтому замкнутая система постоянно повторяет цикл:

```text
измерить
   ↓
сравнить
   ↓
вычислить ошибку
   ↓
изменить управление
   ↓
измерить снова
```

---

# Цикл управления

В реальной системе это может выглядеть так:

```text
while robot_is_running:

    actual = read_sensor()

    error = setpoint - actual

    control = controller(error)

    apply_control(control)
```

Например:

```python
while True:
    speed = encoder.get_speed()

    error = target_speed - speed

    pwm = controller(error)

    motor.set_pwm(pwm)
```

Такой цикл может выполняться:

```text
10 раз/с
```

или:

```text
100 раз/с
```

или значительно чаще — в зависимости от системы.

---

# Частота цикла

Представим:

```text
цикл = 1 Гц
```

Это означает:

```text
1 измерение в секунду
```

Для медленного процесса этого может быть достаточно.

Но для быстрого двигателя может потребоваться:

```text
100 Гц
```

то есть:

```text
100 циклов/с
```

Если цикл слишком медленный, система может реагировать на изменения с большой задержкой.

---

# Что будет, если контроллер реагирует слишком сильно

Представим:

```text
Setpoint = 1000 RPM
Actual   = 700 RPM
```

Ошибка большая.

Контроллер резко увеличивает управление.

Скорость:

```text
700 → 1300 RPM
```

Теперь система выше цели.

Контроллер резко уменьшает управление.

Скорость:

```text
1300 → 750 RPM
```

Появляются колебания.

```text
700
 ↓
1300
 ↓
750
 ↓
1200
 ↓
800
 ↓
...
```

Такое поведение называют **колебательным**.

---

# Перерегулирование

Если система проходит выше заданного значения:

```text
Target = 1000
```

а фактически:

```text
1300
```

это называется **перерегулированием**.

На графике условно:

```text
значение
  ↑
1300       ╭─╮
           │ │
1000 ──────┘ └──── цель
         ╭─╯
 700 ────╯
  └────────────────→ время
```

Небольшое перерегулирование может быть допустимым.

Сильное — может быть проблемой.

---

# Устойчивость

Хорошая система управления должна после изменения стремиться к требуемому состоянию.

Например:

```text
цель = 1000

900
950
980
995
1001
999
1000
```

Это похоже на устойчивое поведение.

Плохой вариант:

```text
900
1200
700
1400
500
1600
...
```

Система может становиться нестабильной.

---

# Обратная связь в роботе

Рассмотрим мобильного робота.

Нужно ехать:

```text
1 м/с
```

Контроллер задаёт:

```text
Left target  = 1 м/с
Right target = 1 м/с
```

Энкодеры измеряют:

```text
Left actual  = 0.95
Right actual = 0.80
```

Получаем:

```text
Left error  = 0.05
Right error = 0.20
```

Контроллер может немного увеличить управление правым двигателем.

В результате робот снова движется более ровно.

---

# Управление положением

Обратная связь может использоваться не только для скорости.

Например, сустав манипулятора должен находиться:

```text
90°
```

Энкодер сообщает:

```text
Actual = 82°
```

Тогда:

```text
Error = 90 - 82
      = 8°
```

Контроллер управляет двигателем до тех пор, пока ошибка не станет достаточно маленькой.

---

# Управление скоростью

Другой вариант:

```text
Target = 100 RPM
Actual = 80 RPM
```

Контроллер регулирует двигатель, чтобы получить:

```text
Actual ≈ 100 RPM
```

Это контур скорости.

---

# Управление током и моментом

В некоторых приводах регулируется ещё более внутренний уровень.

Условно:

```text
Положение
    ↓
Скорость
    ↓
Момент / ток
    ↓
Двигатель
```

То есть одна система управления может содержать несколько вложенных контуров.

---

# Иерархия управления

Например:

```text
Навигация
   ↓
Требуемая скорость робота
   ↓
Контроллер движения
   ↓
Скорость колёс
   ↓
Регулятор скорости двигателя
   ↓
Ток двигателя
   ↓
Двигатель
```

Верхний уровень думает:

> Куда нужно ехать?

Нижний:

> Какой ток подать на двигатель?

Это разные задачи.

---

# Управление и датчики

Без датчика обратная связь невозможна.

Например:

```text
Цель: 90°
```

Но если нет информации о текущем положении:

```text
???
```

Контроллер не знает, насколько далеко находится цель.

Поэтому для замкнутого управления всегда существует связь:

```text
объект
 ↓
датчик
 ↓
измерение
 ↓
контроллер
 ↓
управляющее воздействие
 ↓
объект
```

---

# Ошибка измерения

Сам датчик может ошибаться.

Например:

```text
реальное значение = 1000
датчик показывает = 980
```

Тогда контроллер видит:

```text
Actual = 980
```

хотя реальное значение:

```text
1000
```

Поэтому качество управления зависит и от качества измерения.

---

# Задержка обратной связи

Допустим:

```text
реальное событие
↓
датчик
↓
передача данных
↓
обработка
↓
контроллер
↓
двигатель
```

Если вся цепочка занимает много времени, система реагирует поздно.

Например:

```text
препятствие обнаружено
```

но команда остановки пришла через:

```text
500 мс
```

За это время робот мог существенно переместиться.

Поэтому для быстрых систем важна не только точность, но и задержка.

---

# Практический пример

Представим роботизированное колесо.

Требуемая скорость:

```text
500 RPM
```

Начальное состояние:

```text
Actual = 0
```

Контроллер увеличивает управление.

Получаем:

```text
Actual = 300
```

Ошибка:

```text
200
```

Дальше:

```text
Actual = 450
Error = 50
```

Дальше:

```text
Actual = 490
Error = 10
```

Наконец:

```text
Actual = 500
Error = 0
```

Но нагрузка увеличилась.

```text
Actual = 460
```

Контроллер снова увидит:

```text
Error = 40
```

и увеличит управление.

Таким образом, система автоматически компенсирует изменение нагрузки.

---

# Где используется обратная связь

Обратная связь используется практически повсюду:

* управление скоростью двигателя;
* управление положением;
* управление температурой;
* стабилизация дрона;
* управление манипулятором;
* движение мобильного робота;
* стабилизация платформы;
* поддержание давления.

То есть это одна из фундаментальных идей автоматического управления.

# Итог

Обратная связь позволяет роботу сравнивать:

```text
что должно быть
```

с:

```text
что происходит на самом деле
```

Основная схема:

```text
Setpoint
   ↓
Контроллер
   ↓
Привод
   ↓
Механика
   ↓
Датчик
   ↓
Actual Value
   ↓
Ошибка
   ↓
Контроллер
```

Это основа автоматического управления.
