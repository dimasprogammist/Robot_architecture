# PID-регулятор на практике

## Цель

PID-регулятор — один из самых распространённых способов управления физическими системами.

Он используется для поддержания:

* скорости двигателя;
* положения механизма;
* температуры;
* давления;
* ориентации;
* других физических параметров.

После урока вы должны понимать:

* что такое PID;
* что делают P, I и D;
* почему одного коэффициента часто недостаточно;
* как PID использует ошибку;
* что такое интегральное накопление;
* что такое производная;
* почему возникают перерегулирование и колебания;
* как выглядит простой PID в программе.

---

# Зачем нужен PID

Представим двигатель.

Мы хотим:

```text
1000 RPM
```

Но реальная скорость постоянно меняется:

```text
850
920
970
1005
990
```

Нам нужен механизм, который будет автоматически изменять управление.

PID делает именно это.

У него есть:

```text
Setpoint
Actual
```

и ошибка:

```text
Error = Setpoint - Actual
```

На основе ошибки PID вычисляет управляющее воздействие.

---

# Что означает PID

PID состоит из трёх частей:

```text
P — Proportional
I — Integral
D — Derivative
```

То есть:

```text
Пропорциональная
+
Интегральная
+
Дифференциальная
```

Каждая часть решает свою проблему.

---

# P — пропорциональная составляющая

Самая простая часть.

Она реагирует непосредственно на текущую ошибку.

```text
P = Kp × Error
```

где:

```text
Kp
```

— коэффициент пропорциональной составляющей.

Например:

```text
Error = 100
Kp = 2
```

тогда:

```text
P = 200
```

Чем больше ошибка, тем сильнее управляющее воздействие.

---

# Интуитивный смысл P

Представим, что робот должен двигаться:

```text
1000 RPM
```

а сейчас:

```text
500 RPM
```

Ошибка:

```text
500
```

Значит, воздействие должно быть достаточно большим.

Если скорость:

```text
950 RPM
```

ошибка:

```text
50
```

и воздействие должно быть значительно меньше.

Получается:

```text
большая ошибка
→ большое воздействие

маленькая ошибка
→ маленькое воздействие
```

---

# Проблема одного P

Может оказаться, что только P не способен полностью устранить ошибку.

Например:

```text
Target = 1000
Actual = 950
```

Ошибка:

```text
50
```

Контроллер выдаёт небольшое управление.

Но этого недостаточно, чтобы преодолеть постоянную нагрузку.

В итоге:

```text
Actual = 950
```

и робот стабильно остаётся ниже цели.

Такая постоянная ошибка называется **остаточной ошибкой**.

---

# I — интегральная составляющая

Интегральная часть учитывает накопленную ошибку.

Идея:

> Если ошибка существует долго, её нужно постепенно накапливать.

Упрощённо:

```text
Integral += Error × dt
```

где `dt` — время между измерениями.

Затем:

```text
I = Ki × Integral
```

---

# Интуитивный пример

Допустим:

```text
Target = 1000
Actual = 950
Error = 50
```

Ошибка небольшая.

Но она существует долго.

Тогда интегральная часть постепенно увеличивается:

```text
50
100
150
200
...
```

И начинает сильнее воздействовать на управление.

В результате система может добраться до:

```text
Actual ≈ 1000
```

---

# Проблема интегратора

Интегральная часть может накопить слишком большое значение.

Представим:

```text
робот долго не может достичь цели
```

Интегратор продолжает накапливаться.

Когда проблема исчезает, накопленное значение ещё некоторое время продолжает воздействовать на систему.

Получается:

```text
цель достигнута
↓
но интегратор всё ещё большой
↓
система проходит дальше
↓
перерегулирование
```

Это называют **integral windup** — насыщение или «накручивание» интегратора.

---

# Ограничение интегратора

Один из способов защиты:

```python
integral += error * dt

integral = max(
    min(integral, integral_limit),
    -integral_limit
)
```

Теперь интегратор не может стать бесконечно большим.

---

# D — дифференциальная составляющая

D смотрит не только на текущую ошибку, но и на скорость её изменения.

Упрощённо:

```text
D = Kd × (Error - PreviousError) / dt
```

Если ошибка быстро меняется, D реагирует сильнее.

---

# Зачем нужен D

Представим:

```text
Target = 1000
```

Система движется к цели:

```text
700
800
900
950
980
```

Ошибка уменьшается очень быстро.

D может заметить:

> Мы приближаемся к цели слишком быстро.

И уменьшить управляющее воздействие.

Это помогает снизить перерегулирование.

---

# Аналогия с автомобилем

Представьте, что вы едете к стоп-линии.

Если вы смотрите только:

```text
насколько далеко до линии
```

это похоже на P.

Если постоянно учитываете:

```text
сколько времени вы уже не доезжаете
```

это похоже на I.

Если смотрите:

```text
насколько быстро приближаетесь к линии
```

это похоже на D.

Хорошее управление использует все три вида информации.

---

# Формула PID

Упрощённая форма:

```text
u(t) = Kp × e(t)
     + Ki × ∫e(t)dt
     + Kd × de(t)/dt
```

В дискретной программе это можно записать примерно так:

```text
error = setpoint - actual

integral += error × dt

derivative = (error - previous_error) / dt

output =
    Kp × error +
    Ki × integral +
    Kd × derivative
```

---

# Простой PID на Python

```python
class PID:
    def __init__(self, kp, ki, kd):
        self.kp = kp
        self.ki = ki
        self.kd = kd

        self.integral = 0.0
        self.previous_error = 0.0

    def update(self, setpoint, actual, dt):
        error = setpoint - actual

        self.integral += error * dt

        derivative = (
            error - self.previous_error
        ) / dt

        output = (
            self.kp * error
            + self.ki * self.integral
            + self.kd * derivative
        )

        self.previous_error = error

        return output
```

Это упрощённый учебный пример.

В реальной системе потребуется дополнительно учитывать ограничения, насыщение, шум и особенности конкретного привода.

---

# Ограничение выхода

Представим:

```text
PWM = 0...100%
```

PID рассчитал:

```text
output = 140%
```

Физически это невозможно.

Поэтому результат нужно ограничить:

```python
output = max(0.0, min(output, 100.0))
```

Теперь:

```text
140% → 100%
```

---

# Полярность управления

Если привод может двигаться в обе стороны, диапазон может быть:

```text
-100% ... +100%
```

Например:

```text
-50% → вращение назад
0%   → остановка
+50% → вращение вперёд
```

Тогда ограничение:

```python
output = max(-100.0, min(output, 100.0))
```

---

# Пример расчёта

Пусть:

```text
Setpoint = 100
Actual = 80
```

Тогда:

```text
Error = 20
```

Пусть:

```text
Kp = 2
```

Тогда:

```text
P = 2 × 20 = 40
```

Если интегральная и дифференциальная составляющие пока равны нулю:

```text
Output = 40
```

То есть PID создаёт управляющее воздействие 40 условных единиц.

---

# Настройка PID

Самая сложная часть — подобрать:

```text
Kp
Ki
Kd
```

слишком большой `Kp` может привести к:

```text
резкой реакции
колебаниям
```

слишком маленький:

```text
медленная реакция
```

слишком большой `Ki`:

```text
сильное накопление
перерегулирование
```

слишком маленький:

```text
остаточная ошибка
```

слишком большой `Kd`:

```text
чувствительность к шуму
```

слишком маленький:

```text
слабое демпфирование
```

---

# Что происходит при увеличении Kp

Представим систему:

```text
Kp маленький
```

Она реагирует медленно.

Если увеличить:

```text
Kp ↑
```

реакция становится быстрее.

Но если увеличить слишком сильно:

```text
Kp ↑↑↑
```

могут появиться:

```text
колебания
перерегулирование
нестабильность
```

---

# Что происходит при увеличении Ki

Увеличение `Ki` помогает убрать остаточную ошибку.

Но слишком большое значение приводит к:

```text
накоплению
```

и:

```text
перерегулированию
```

Поэтому интегральную составляющую обычно вводят осторожно.

---

# Что происходит при увеличении Kd

D помогает системе реагировать на быстрое изменение ошибки.

Это может уменьшить:

```text
перерегулирование
```

Но есть проблема.

Датчики шумят.

Например:

```text
1000
998
1001
997
1000
```

Производная может сильно реагировать на такие изменения.

Поэтому D часто требует фильтрации.

---

# Фильтрация производной

Простейшая идея:

```text
сырое измерение
       ↓
фильтр
       ↓
производная
       ↓
PID
```

Так система становится менее чувствительной к мелкому шуму.

---

# PID для двигателя

Рассмотрим привод колеса.

```text
Target speed
      ↓
     PID
      ↓
     PWM
      ↓
   Driver
      ↓
    Motor
      ↓
    Wheel
      ↓
   Encoder
      ↓
Actual speed
      ↓
     PID
```

Это классическая схема.

---

# PID для положения

Можно регулировать не скорость, а положение.

Например:

```text
Target = 90°
Actual = 60°
```

PID вычисляет управляющее воздействие.

Мотор поворачивает сустав.

Когда:

```text
Actual → 90°
```

управление уменьшается.

В результате сустав останавливается около заданного положения.

---

# PID для робота

На мобильном роботе PID можно использовать сразу в нескольких местах.

Например:

```text
Левое колесо → PID скорости
Правое колесо → PID скорости
```

А выше может находиться:

```text
PID направления
```

или другой алгоритм движения.

Получается иерархия:

```text
Навигация
    ↓
Требуемая скорость
    ↓
Контроллер движения
    ↓
Target Left / Right
    ↓
PID Left / Right
    ↓
Моторы
```

---

# PID — не магия

Важно понимать:

> PID не знает, что такое робот.

Он не понимает:

```text
стена
```

или:

```text
дорога
```

или:

```text
человек
```

Он просто получает числа:

```text
Setpoint
Actual
```

и вычисляет управляющее воздействие.

Поэтому PID является **инструментом управления**, а не полноценным алгоритмом поведения робота.

---

# Где PID не подходит напрямую

PID хорошо работает, когда:

* есть измеряемая величина;
* есть желаемое значение;
* система достаточно предсказуема;
* требуется регулировать физический параметр.

Но PID сам по себе не решает задачи:

```text
куда ехать?
```

```text
какой объект перед роботом?
```

```text
какой маршрут выбрать?
```

```text
как обойти препятствие?
```

Для этого нужны другие алгоритмы.

# Итог

PID объединяет три реакции:

```text
P → текущая ошибка
I → накопленная ошибка
D → изменение ошибки
```

Упрощённо:

```text
              ┌── P
Ошибка ───────┼── I
              └── D
                 ↓
              Управление
```

PID особенно полезен для:

* скорости;
* положения;
* температуры;
* ориентации;
* стабилизации;
* управления приводами.

Но PID не заменяет навигацию, планирование или логику поведения.

Он отвечает на более конкретный вопрос:

> **Как изменить управляющее воздействие, чтобы измеряемая величина приблизилась к заданному значению?**
