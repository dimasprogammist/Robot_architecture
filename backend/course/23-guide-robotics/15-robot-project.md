# Проект: спроектировать робота целиком

## Цель

В предыдущих уроках мы рассмотрели отдельные части робототехнической системы:

* механику;
* приводы;
* датчики;
* координаты;
* управление;
* PID;
* кинематику;
* мобильное движение;
* одометрию;
* навигацию;
* компьютерное зрение;
* состояния;
* программную архитектуру;
* безопасность и диагностику.

Теперь нужно объединить эти знания.

Главная задача урока — не собрать конкретного робота по инструкции, а научиться **проектировать робототехническую систему целиком**.

В качестве примера будем проектировать мобильного робота, который должен самостоятельно перемещаться по помещению и доставлять небольшой груз.

---

## Постановка задачи

Представим робота:

```text
┌───────────────────────┐
│       КОРПУС          │
│                       │
│  [Motor]     [Motor]  │
│                       │
│       Контроллер      │
│                       │
│     Battery           │
└───────────────────────┘
```

Робот должен:

1. получать задание;
2. знать своё приблизительное положение;
3. двигаться к заданной точке;
4. обнаруживать препятствия;
5. останавливаться при опасной ситуации;
6. доставлять груз;
7. сообщать о своём состоянии.

---

## Первый этап — определить требования

Нельзя начинать проектирование с выбора двигателя.

Сначала нужно понять задачу.

Например:

```text
Масса робота:       12 кг
Груз:                5 кг
Максимальная скорость: 1 м/с
Рабочее время:      4 часа
Помещение:          30 × 20 м
Поверхность:        ровный пол
```

Это только пример.

Конкретные требования зависят от реального проекта.

---

## Функциональные требования

Робот должен:

```text
ехать
останавливаться
поворачивать
обнаруживать препятствия
получать команды
передавать состояние
```

Можно добавить:

```text
автоматически возвращаться на зарядку
распознавать метки
перевозить груз
```

Но чем больше функций, тем сложнее система.

Поэтому сначала нужно определить минимально необходимый набор.

---

## Выбор типа робота

Для нашей задачи подходит:

```text
колёсный мобильный робот
```

Почему?

Потому что помещение имеет:

* ровный пол;
* относительно свободное пространство;
* не требуется ходить по лестнице.

Другой тип робота потребовал бы другой механики.

Например:

```text
дрон
```

потребовал бы:

* пропеллеры;
* управление полётом;
* IMU;
* регулирование тяги;
* аккумулятор высокой мощности.

Для нашей задачи это было бы совершенно другой системой.

---

## Выбор шасси

Можно использовать:

```text
дифференциальный привод
```

То есть:

```text
левое колесо    правое колесо
      O────────────O
```

У каждого ведущего колеса свой двигатель.

Если:

```text
Vleft = Vright
```

робот движется прямо.

Если:

```text
Vleft > Vright
```

робот поворачивает.

Если:

```text
Vleft = -Vright
```

робот может вращаться на месте.

---

## Механическая часть

Наш робот может состоять из:

```text
корпус
2 ведущих колеса
1 опорное колесо
2 двигателя
2 редуктора
крепления
защитные элементы
платформа для груза
```

Важно учитывать:

* массу;
* центр тяжести;
* диаметр колёс;
* сцепление;
* нагрузку на двигатель;
* клиренс;
* прочность корпуса.

---

## Выбор двигателя

Нам нужно определить требуемый момент и скорость.

Упрощённо сила тяги связана с моментом:

```text
F = M / r
```

где:

```text
F — сила
M — момент
r — радиус колеса
```

Если требуется большая тяга, можно:

* увеличить момент двигателя;
* использовать редуктор;
* увеличить радиус колеса.

Но увеличение колеса также влияет на требования к моменту.

Поэтому механика и привод должны проектироваться вместе.

---

## Редуктор

Двигатель может вращаться слишком быстро.

Например:

```text
двигатель → 3000 об/мин
```

а колесу нужна гораздо меньшая скорость.

Используем редуктор:

```text
двигатель
   ↓
редуктор
   ↓
колесо
```

Редуктор:

* уменьшает скорость;
* увеличивает момент.

Передаточное отношение:

```text
i = n_motor / n_output
```

Например:

```text
i = 20
```

означает, что выход вращается примерно в 20 раз медленнее входа.

---

## Датчики

Для нашего робота можно выбрать:

```text
энкодер левого колеса
энкодер правого колеса
датчики препятствий
IMU
датчик напряжения батареи
датчики температуры
```

Камера может быть дополнительным датчиком.

---

## Зачем нужны энкодеры

Энкодеры позволяют узнать:

```text
сколько повернулось колесо
```

Из этого можно получить:

```text
скорость
пройденный путь
положение колеса
```

Например:

```text
импульсы
   ↓
угол вращения
   ↓
расстояние
   ↓
скорость
```

---

## Одометрия

Если известно перемещение левого и правого колеса, можно оценивать движение робота.

Пусть:

```text
ΔL — путь левого колеса
ΔR — путь правого колеса
```

Среднее перемещение:

```text
ΔS = (ΔL + ΔR) / 2
```

Разница перемещений влияет на поворот.

Для дифференциального привода:

```text
Δθ = (ΔR - ΔL) / B
```

где:

```text
B — расстояние между колёсами
```

Это позволяет приблизительно вычислять:

```text
X
Y
θ
```

то есть положение и ориентацию робота.

---

## Ограничение одометрии

Одометрия не идеальна.

Если колесо немного проскальзывает:

```text
реальное движение ≠ рассчитанное движение
```

Ошибка постепенно накапливается.

Поэтому можно использовать другие источники:

```text
энкодеры
+
IMU
+
камера
+
датчики внешней системы
```

---

## Датчики препятствий

Предположим, спереди установлен дальномер.

Он показывает:

```text
distance = 0.8 m
```

Если минимально допустимое расстояние:

```text
0.5 m
```

робот может продолжать движение.

Если:

```text
distance = 0.3 m
```

нужно:

```text
остановиться
```

или изменить траекторию.

## Контроллер

Теперь нужен вычислительный блок.

Это может быть:

```text

```

для низкоуровневого управления.

Или:

```text

```

для более сложной обработки.

В более сложной системе можно использовать оба:

```text

   ↓

   ↓
контроллер
   ↓
двигатели
```

## Самотестирование

После включения робот не должен сразу ехать.

Сначала:

```text
BOOT
```

Затем:

```text
SELF_TEST
```

Проверяем:

```text
энкодеры
датчики
связь
питание
температуру
двигатели
```

Например:

```text
Encoder L: OK
Encoder R: OK
Battery: OK
IMU: OK
Communication: OK
```

Если всё хорошо:

```text
READY
```

Если нет:

```text
ERROR
```

## Движение

Предположим, навигация решила:

```text
скорость робота = 0.5 м/с
поворот = 0.1 рад/с
```

Навигация передаёт эту команду контроллеру.

Контроллер преобразует её в скорости колёс.

Упрощённо:

```text
Vleft  = V - ωB/2
Vright = V + ωB/2
```

где:

```text
V — линейная скорость
ω — угловая скорость
B — расстояние между колёсами
```

Затем для каждого колеса работает свой контур управления.

---

## PID

Для каждого двигателя:

```text
заданная скорость
        ↓
      ошибка
        ↓
       PID
        ↓
       PWM
        ↓
      мотор
        ↓
     энкодер
        └──────────→ обратная связь
```

Так робот может поддерживать заданную скорость даже при изменении нагрузки.

---

## Навигация

Теперь робот должен понять:

> куда ехать?

Например:

```text
текущая позиция:
X = 2.0
Y = 3.0

цель:
X = 8.0
Y = 10.0
```

Навигация вычисляет направление движения.

Затем:

```text
Navigation
    ↓
Motion command
    ↓
Controller
```

## Препятствие

Допустим, робот едет к цели:

```text
робот ───────────────→ цель
              █
           препятствие
```

Датчик обнаруживает препятствие.

Система может:

```text
остановиться
```

или:

```text
перестроить маршрут
```

Решение зависит от возможностей системы.


# Практический проект

Теперь ваша задача — самостоятельно спроектировать робота.

## Вариант проекта

Спроектируйте мобильного робота для доставки небольшого груза внутри помещения.

Исходные условия:

```text
Масса робота: до 15 кг
Груз: до 5 кг
Максимальная скорость: 1 м/с
Поверхность: ровный пол
Помещение: до 50 × 30 м
```

Робот должен:

```text
ехать
поворачивать
останавливаться
обнаруживать препятствия
получать задания
сообщать состояние
безопасно останавливаться при ошибке
```

Например:

```text
E001 Encoder timeout
E002 Communication timeout
E003 Low battery
E004 Motor overtemperature
E005 Emergency stop
```

Опишите:

```text
что происходит при нажатии E-STOP

```

Для каждой ситуации должен существовать понятный сценарий.

# Итоговая архитектура

В результате проект должен выглядеть примерно так:

```text
                         ОПЕРАТОР
                             │
                             ▼
                    ┌─────────────────┐
                    │  Управляющий ПК │
                    │                 │
                    │ Navigation      │
                    │ Vision          │
                    │ Application     │
                    └────────┬────────┘
                             │
                        Communication
                             │
                    ┌────────▼────────┐
                    │  Контроллер     │
                    │                 │
                    │ FSM             │
                    │ PID             │
                    │ Diagnostics     │
                    │ Watchdog        │
                    └──────┬─────┬────┘
                           │     │
                    Sensors     Drivers
                           │     │
                           │     ▼
                           │   Motors
                           │
                           ▼
                         Robot
```

Это не единственная возможная архитектура.

Хорошее проектирование не заключается в том, чтобы угадать единственно правильную схему.

Главное — уметь объяснить:

```text
почему выбран именно этот компонент;
зачем нужен каждый датчик;
как передаются данные;
как управляются приводы;
что происходит при ошибке;
где находится логика поведения;
где находится контур управления;
как система переходит в безопасное состояние.
```

# Что нужно уметь после раздела

После завершения этого раздела вы должны понимать робототехническую систему как совокупность связанных частей:

```text
МЕХАНИКА
    ↓
ПРИВОДЫ
    ↓
ДАТЧИКИ
    ↓
КОНТРОЛЛЕР
    ↓
УПРАВЛЕНИЕ
    ↓
ЛОГИКА
    ↓
НАВИГАЦИЯ
    ↓
СВЯЗЬ
    ↓
ДИАГНОСТИКА
    ↓
БЕЗОПАСНОСТЬ
```

И главное — видеть робота не как:

```text
мотор + Arduino + программа
```

а как полноценную инженерную систему.
