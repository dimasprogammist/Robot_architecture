# Пакеты

## Цель

Группировать модули в пакеты с импортами package.module.

Понять роль __init__.py и пространства имён пакета.

## Что уже пройдено

Вы импортируете отдельные файлы-модули.

Пакет — каталог с общим префиксом имени.

## Объяснение с нуля

Модули кладут в каталог: sensors/lidar.py. Импорт: `import sensors.lidar` или `from sensors.camera import Frame`.

`__init__.py` инициализирует пакет при импорте (может быть пустым). Иерархия `robot.drivers.motors`. Относительные импорты работают в пакетном контексте.

Точка входа часто тонкий app.py или `python -m package`.

## Термины

- **Пакет / подпакет**.

- **`__init__.py`**.

- **Абсолютный / относительный импорт**.

- **`__main__.py`**.

- **`__path__`**.

- **Пространство имён пакета**.

- **python -m**.

## Внутреннее устройство

Импорт sensors.lidar сначала грузит пакет sensors, затем lidar. В sys.modules — оба ключа.

`python -m sensors` ищет sensors/__main__.py и сохраняет пакетный контекст.

## Пример

```text

project/

  app.py

  sensors/

    __init__.py

    lidar.py

```

```python

# sensors/lidar.py

def ping():

    return "ok"



# app.py

from sensors.lidar import ping

print(ping())

```

## Разбор

Каталог становится пакетом; импорт загружает пакет и модуль.

Рабочий каталог/sys.path должны включать project.

## Ошибки

- Запуск внутреннего модуля как скрипта ломает относительные импорты.

- Конфликт имени со стандартной библиотекой.

- Тяжёлая работа в __init__.py.

- Путать «лежит рядом» и «установлен в окружение».

- Хаотичная куча файлов без иерархии — или наоборот избыточное дробление.

## Что запомнить

Пакет = каталог + импорт через точку.

__init__.py инициализирует пакет.

Снаружи удобны абсолютные импорты и python -m.

## Задание

Мини-пакет из двух модулей с относительным импортом.

Демонстрация через тонкий app.py вне пакета.
