# Аннотации типов

## Цель

Использовать аннотации как документацию и базу статической проверки.

Понять: CPython по умолчанию типы на вызове не принуждает.

## Что уже пройдено

Вы уверенно пишете функции и классы.

Аннотации описывают ожидания, не меняя сами по себе исполнение.

## Объяснение с нуля

Пишут у параметров/результатов: `def f(x: int) -> str`. Подсказки для людей, IDE, mypy/pyright.

Обычный CPython не проверяет аннотации на каждом вызове. Проверка — отдельный шаг. typing и list[int], X|None описывают структуры. Хранятся в __annotations__; библиотеки могут читать их в рантайме.

## Термины

- **Аннотация типа**.

- **Статическая проверка / runtime**.

- **Optional / | None**.

- **Generic**.

- **`__annotations__`**.

- **Постепенная типизация**.

- **Контракт сигнатуры**.

## Внутреннее устройство

Аннотации собираются в объект функции и по умолчанию не влияют на байткод вызова.

Анализторы читают AST. Некоторые библиотеки валидируют в рантайме — их протокол поверх языка.

## Пример

```python

def greet(name: str, times: int = 1) -> str:

    return " ".join([f"Hello, {name}!"] * times)

def find(xs: list[int], target: int) -> int | None:

    for i, v in enumerate(xs):

        if v == target:

            return i

    return None

print(greet("Ana", 2))

print(find([10, 20, 30], 20))

```

## Разбор

Сигнатуры документируют контракт.

CPython исполнит и с неверным типом, пока операция не сломается — польза в читаемости и CI.

## Ошибки

- Думать, что аннотация защищает рантайм.

- Сверхсложные Generic с первого дня.

- Путать list[int] с рантайм-проверкой содержимого.

- Игнорировать None в возвращаемом типе.
