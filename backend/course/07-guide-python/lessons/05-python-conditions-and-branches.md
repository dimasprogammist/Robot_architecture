# Условия и ветвления

Не всякая строка программы должна выполняться каждый раз. Температура выше порога — стоп. Иначе — ехать. Это **ветвление**. В Python:

```python
if temperature > 80:
    print("перегрев")
    stop = True
elif temperature > 60:
    print("тепло")
else:
    print("норма")
```

После `if` — выражение, которое понимают как истину или ложь. Двоеточие обязательно. Тело — строки **с отступом**. Без отступа Python не знает, что относится к ветке.

`elif` — «иначе если». Ветки проверяются сверху вниз, выполняется **первая подошедшая**. Если уже сработало `> 80`, до `> 60` не дойдут. Порядок порогов важен: широкий сначала съест узкий.

`else` — «ни одно из условий не взялось». Его можно не писать. Тогда при «не подошло» просто идут дальше.

Вложенный `if` внутри `if` читается тяжелее цепочки `elif`, когда выбор один из нескольких взаимоисключающих. Вложение уместно, когда вторая проверка имеет смысл только после первой: «если файл открылся, тогда если строка не пустая».

Истина в Python шире, чем `True`. Ноль, пустая строка, пустой список, `None` — ложь в условии. Непустая строка `"0"` — истина: это не число ноль. Пишите явно `if count == 0`, если имеете в виду число, а не «объект пустой».

Цепочки сравнений законны: `0 <= x <= 100`. Это не трюк с присваиванием, как в C. Для диапазона удобно.

Не сравнивайте `if flag == True:` — достаточно `if flag:`, если `flag` уже булев. И наоборот, не пишите `if items:`, если пустой список — штатные «ноль деталей», а вы хотели отличить «списка нет» (`None`) от «список пуст».
