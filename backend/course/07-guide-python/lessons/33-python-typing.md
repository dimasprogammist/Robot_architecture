# Типизация и аннотации типов

Python остаётся языком с проверкой типов **в основном на выполнении**: объект несёт тип с собой. Аннотации — слой для людей и отдельных программ-проверщиков. Они не заменяют тесты и не делают код «как в C++» сами.

```python
def celsius_from_adc(raw: int, vref: float) -> float:
    return raw / 1023.0 * vref
```

`int`, `float`, `str`, `bool`, свои классы и dataclass — база. Коллекции: `list[str]`, `dict[str, float]`, `tuple[float, float]`. «Может не быть»: `float | None` (или `Optional[float]` в старом стиле).

```python
def last_temp(history: list[float]) -> float | None:
    if not history:
        return None
    return history[-1]
```

Вызывающий обязан учесть `None`. Проверщик ругнётся, если вы сразу сложите результат с числом без проверки.

`Sequence[float]` — любое, по чему можно идти и брать индекс по смыслу протокола, не только `list`. `Mapping` — словарь-подобное. Не усложняйте, пока `list` и `dict` хватает.

`TypeError` на выполнении и «ошибка mypy» — разные миры. Можно иметь идеальные аннотации и упасть на данных из JSON (там всё пришло как есть). На границе ввода по-прежнему проверяйте и преобразуйте.

`Any` выключает пользу. `# type: ignore` точечно, не ковром. `cast` — «я лучше проверщика»: иногда нужно, часто маскирует дыру.

Редактор с pyright уже подсветит `clamp("a", 0, 1)`. Это и есть ежедневная ценность, даже если CI без mypy.
