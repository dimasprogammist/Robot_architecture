# Основы тестирования Python-программ

Программу можно проверять руками: запустил, посмотрел print. После десятой правки вы не вспомните все края. **Тест** — маленький код, который вызывает вашу функцию и **проверяет** результат. Его можно гонять снова и снова.

Самое простое — `assert`:

```python
def clamp(x, lo, hi):
    if x < lo:
        return lo
    if x > hi:
        return hi
    return x


assert clamp(5, 0, 10) == 5
assert clamp(-1, 0, 10) == 0
assert clamp(99, 0, 10) == 10
```

Если утверждение ложно, процесс падает с `AssertionError`. Это уже тест, хоть и в том же файле. Лучше держать проверки отдельно, чтобы импорт модуля не гонял их (как `if __name__ == "__main__"` или отдельный файл — следующий урок про pytest).

Что тестировать: чистую логику с известным входом и выходом. `clamp`, расстояние, разбор строки. Что тяжелее: сеть, робот, время. Их имитируют (подмена), не обязательно в первом тесте.

Плохой тест: смотрит внутреннюю переменную, хрупко привязан к тексту ошибки, зависит от порядка «как повезло с файлом на диске». Хороший: вход, выход, имя говорит ситуацию `test_clamp_below_low`.

Тест не доказывает отсутствие всех багов. Он ловит **регрессии**: вчера работало, правка сломала. Этого достаточно, чтобы не бояться менять код.

`assert` можно отключить флагом интерпретатора — в проде для проверок инвариантов иногда берут явный `if` и исключение. Для учебных тестов `assert` нормален.
