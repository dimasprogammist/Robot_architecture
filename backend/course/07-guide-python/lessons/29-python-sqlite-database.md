# Работа с базами данных SQLite

CSV удобен глазу. Когда нужны поиск по полю, обновление одной записи, несколько таблиц — **база**. **SQLite** — база в одном файле, без отдельного сервера. В Python модуль `sqlite3` из стандартной библиотеки.

```python
import sqlite3
from pathlib import Path

path = Path("robot.db")
conn = sqlite3.connect(path)
conn.row_factory = sqlite3.Row
try:
    conn.execute(
        "CREATE TABLE IF NOT EXISTS readings ("
        "id INTEGER PRIMARY KEY, celsius REAL NOT NULL)"
    )
    conn.execute("INSERT INTO readings(celsius) VALUES (?)", (21.4,))
    conn.commit()
    row = conn.execute("SELECT celsius FROM readings WHERE id = ?", (1,)).fetchone()
    print(row["celsius"])
finally:
    conn.close()
```

Плейсхолдер `?` и кортеж аргументов — **не** склейка SQL строкой с пользовательским текстом. Склейка открывает инъекцию: данные становятся командой. Всегда параметры.

`commit` фиксирует транзакцию. Без него часть правок может не попасть на накопитель так, как вы ждёте. Ошибка — `rollback` (или закрытие без commit).

`Row` позволяет `row["celsius"]` вместо кортежа по индексу — меньше путаницы столбцов.

Соединение лучше не открывать на каждый чих в жёстком цикле без нужды и не держать вечно, если процесс долгий и файл шарится. Для учебного скрипта: открыли, поработали, закрыли. `with sqlite3.connect(path) as conn:` тоже умеет commit при выходе без ошибки.

SQLite не замена PostgreSQL в высоконагруженном бэкенде. Для робота, локального журнала, прототипа — часто идеал.
