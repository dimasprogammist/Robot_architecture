# JSON и сохранение структурированных данных

Словарь в памяти — объект Python. Чтобы отдать его другой программе, серверу или положить на диск переносимо, нужен **общий текст**. Часто это JSON: скобки, кавычки, числа, массивы, объекты. Его понимают браузер, другой язык, человек глазами.

```python
import json
from pathlib import Path

data = {"id": "t-1", "celsius": 21.4, "ok": True}
text = json.dumps(data, ensure_ascii=False, indent=2)
Path("sensor.json").write_text(text, encoding="utf-8")

loaded = json.loads(Path("sensor.json").read_text(encoding="utf-8"))
```

`dumps` / `loads` — строка. `dump` / `load` — сразу файл. `ensure_ascii=False` оставляет кириллицу читаемой. `indent=2` — для людей; для сети часто без отступов, компактнее.

JSON знает объекты, массивы, строки, числа, `true`/`false`/`null`. Не знает кортеж как отдельный тип: станет массивом. Не знает `datetime` из коробки: сериализуйте в строку ISO сами. Ключи в JSON — строки; числовой ключ словаря Python станет `"1"`.

`True` Python → `true` JSON. `None` → `null`. Обратно `json.loads` даст `True` и `None`, не строки.

Битый JSON — `json.JSONDecodeError`. Пустой файл, обрыв записи, комментарии как в JavaScript (в строгом JSON их нет). Пишите атомарно, если боитесь обрыва: во временный файл, потом замена — идея, не обязательно реализовать в первом скрипте.

Не путайте JSON и Python-литерал. `json.loads("{ok: True}")` не пройдёт: ключи в кавычках, `true` маленькими, не `True`.

Большие данные таблицей чаще CSV (следующий урок) или база. JSON удобен конфигу, ответу API, небольшому состоянию.
