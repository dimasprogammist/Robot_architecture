# Модули и импорт кода

Файл `.py` — не только «скрипт с начала до конца». Для Python это **модуль**: набор имён (функции, константы), который можно **импортировать** в другой файл.

Стандартная библиотека уже с вами:

```python
import math

print(math.sqrt(9))
print(math.pi)
```

`import math` выполняет модуль один раз (в этом процессе) и даёт объект `math`. Имена через точку: не захламляют ваши `sqrt`.

```python
from math import sqrt, pi
```

Короче вызов, легче столкновение имён. `from math import *` в прикладном коде почти всегда вред: непонятно, откуда имя.

Свой модуль: рядом файл `geometry.py` с `def distance(...)`. В `app.py`:

```python
import geometry

print(geometry.distance(0, 0, 3, 4))
```

Запускают обычно `app.py`. Каталог запуска влияет на то, какие модули «видны». Пока держите учебные файлы в одном каталоге и запускайте оттуда.

Имя модуля — имя файла без `.py`. Дефис в имени файла сломает `import`. Пишите `sensor_log.py`, не `sensor-log.py`.

Внизу модуля часто:

```python
if __name__ == "__main__":
    print(distance(0, 0, 3, 4))
```

Когда файл запускают как программу, `__name__` равен `"__main__"` — блок едет. Когда тот же файл импортируют, блок не едет: не хотим, чтобы импорт геометрии печатал тесты в лог робота.

Циклический импорт: A тянет B, B тянет A — боль. Режется разделением: общий кусок в третий модуль.

Позже — пакеты (каталог с `__init__.py` или namespace). Сейчас достаточно: один файл = один модуль, `import`, точка.
