# Словари и данные в формате ключ-значение

Список хорош, когда важен **номер**. Часто важнее **имя поля**: температура по id датчика, настройка по ключу `"timeout_s"`. **Словарь** — отображение ключ → значение.

```python
sensor = {"id": "t-1", "celsius": 21.4, "ok": True}
print(sensor["celsius"])
sensor["celsius"] = 21.6
sensor["unit"] = "C"
```

Ключ в квадратных скобках. Нет ключа — `KeyError`. Безопаснее, если отсутствие штатно: `sensor.get("unit")` вернёт `None`, или `sensor.get("unit", "C")` с запасом.

Ключи чаще строки. Подойдут числа, кортежи из неизменяемого. Список ключом быть не может.

Перебор:

```python
for key, value in sensor.items():
    print(key, value)
```

`sensor.keys()`, `sensor.values()` — только ключи или только значения. С Python 3.7+ порядок вставки ключей сохраняется при обходе — удобно, но логику «это упорядоченный ряд» лучше не строить на словаре: для ряда есть список.

Вложенность: словарь списков, список словарей. JSON с сервера почти всегда приходит так. `row["pos"]["x"]` — пока ключей нет, ловите `KeyError` или проверяйте.

`in`: `"celsius" in sensor` смотрит **ключи**, не значения. Это частая путаница.

Два словаря слить: `{**a, **b}` или `a.update(b)` — второе меняет `a` на месте. Одинаковые ключи: побеждает тот, кого пишут позже.

Не делайте гигантский «бог-словарь» на всю программу без структуры. Когда поля фиксированы (всегда id, всегда температура) — позже dataclass. Словарь остаётся уместен для неизвестного набора ключей, конфигов, ответов API.
