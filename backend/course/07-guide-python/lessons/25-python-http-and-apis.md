# HTTP-запросы и работа с API

Программа на одной машине часто просит данные у другой: погода, ваш бэкенд, прошивка «открой JSON». Поверх сети обычно **HTTP**: клиент шлёт **запрос** (метод, URL, заголовки, иногда тело), сервер — **ответ** (код, заголовки, тело).

В Python удобно библиотекой `requests` (после установки в окружение):

```python
import requests

response = requests.get("https://httpbin.org/json", timeout=5)
response.raise_for_status()
data = response.json()
```

`timeout` обязателен по смыслу: без него поток может висеть, пока сеть «думает». `raise_for_status()` превратит 404/500 в исключение, а не в тихий «странный JSON». `response.json()` разберёт тело как JSON — если это не JSON, будет ошибка разбора.

Методы: GET «прочитать», POST «отправить на создание/действие», PUT/PATCH «обновить», DELETE «удалить». Тело POST часто JSON:

```python
r = requests.post(url, json={"celsius": 21.4}, timeout=5)
```

Заголовок `Content-Type` библиотека проставит сама при `json=`.

Коды: 2xx успех, 4xx ошибка клиента (нет ресурса, плохой запрос), 5xx ошибка сервера. Бизнес-ошибка иногда всё равно 200 с `{"ok": false}` — читайте договор API, не только код.

Секреты (токен) — в заголовке или окружении, не в репозитории. HTTP без TLS (обычный `http://`) на открытой сети светит содержимое; для учёбы на localhost иначе, для паролей — HTTPS.

Стандартная библиотека `urllib` умеет то же грубее. В курсе дальше FastAPI — вы будете **сервером**. Здесь вы **клиент**.

Не молотите API в цикле без паузы: лимиты, вежливость, ваш же робот не обязан DDoSить себя.
