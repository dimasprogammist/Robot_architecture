# Синтаксис Python, переменные и значения

Программе нужно помнить числа и тексты между шагами: температуру, скорость, имя файла. В Python это делается **именем**, связанным со **значением**. Знак `=` — не уравнение из школьной алгебры. Справа считают, слева **привязывают имя**.

```python
temperature = 72.5
temperature = temperature + 0.5
```

После первой строки имя `temperature` указывает на вещественное число `72.5`. После второй — на `73.0`. Старое значение, если на него больше никто не ссылается, интерпретатор позже уберёт. Вам не нужно вручную «освобождать ячейку», как в некоторых языках с явным управлением памятью.

Имя — для людей и для программы. Правила: начинается с буквы или `_`, дальше буквы, цифры, `_`. `2speed` нельзя. `speed` и `Speed` — разные имена. Принятый стиль в Python — `snake_case`: `battery_percent`, не `batteryPercent`.

Комментарий начинается с `#` и до конца строки. Интерпретатор его не выполняет. Пишите *зачем*, не «прибавили единицу» к строке, которая и так `count + 1`.

Несколько имён могут указывать на одно и то же, если значение изменяемое (список — позже). Для чисел и строк обычно думайте проще: присваивание кладёт новое значение на имя.

Типичные сбои.

`NameError`: прочитали имя, которому ещё не присваивали. Python не подставляет молча ноль — и это хорошо: ноль мог бы значить «датчик мёртв» так же, как «ещё не читали».

Синтаксическая ошибка: забытая кавычка, двоеточие после `if`, смешение отступов. Программа **даже не начнёт** выполняться: разбор текста не прошёл.

```python
count = 0
count = count + 1
print(count)
```

Здесь три шага: создать связь, изменить, показать. `print(count)` без кавычек печатает *значение* имени. `print("count")` напечатает четыре буквы.

Не кладите в одно имя то флаг, то скорость. Завтра вы сами не вспомните, что сейчас лежит.
