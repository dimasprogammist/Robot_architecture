# Практический проект на Python

Соберите не «все уроки раздела», а **одну маленькую систему**, где видны файлы, функции, ошибка, тест.

Тема по умолчанию: журнал температур робота.

1. Каталог проекта, виртуальное окружение, `requirements.txt` если нужна зависимость; иначе стандартная библиотека.
2. Модуль с функцией `celsius_from_adc(raw: int) -> float` (линейно, как в математике: сырое 0…1023, шкала 0…100 °C или ваша — подпишите единицы).
3. Сохранение записей: JSON-список или CSV, путь через `pathlib`, UTF-8, `with`.
4. Чтение обратно, разбор, `ValueError`/`JSONDecodeError` не глотать молча.
5. Порог с гистерезисом (идея из математики): флаг «горячо» не дребезжит на границе.
6. Два-три теста pytest на перевод АЦП и на порог.
7. Точка входа `main.py` с `if __name__ == "__main__"`: прочитать сырое из аргумента или заглушки, дописать журнал, напечатать состояние.

Не обязательно HTTP, asyncio, SQLite. Если тянет — журнал в SQLite вместо CSV, но тогда плейсхолдеры и commit.

Требования к качеству, не к объёму:

- имена с единицами смысла;
- нет глобального «всего состояния» без нужды;
- один каталог данных, путь от `__file__` или явный аргумент;
- лог или честный print состояния, без токенов;
- README из пяти строк: как создать окружение и запустить тесты и `main`.

Это конец раздела Python. Дальше языки и бэкенд будут опираться на модули, типы на границе, файлы и тесты, а не на «когда-нибудь наведём порядок».

## Практика

### Задание 1. Спека

Запишите вход (сырое АЦП), выход (файл + флаг), формулы. Без кода. Единицы на каждом числе.

### Задание 2. Края

Сырое < 0, сырое > 1023, битый JSON журнала. Поведение каждого. Где исключение, где отказ с сообщением.

### Задание 3. Тесты

Два `assert`/`test_` на перевод и один на гистерезис (два шага: чуть выше и чуть ниже порога). Почему гистерезис одним замером не проверить?

### Задание 4. Ретро

Какие уроки раздела реально вошли в проект? Какие сознательно нет? Короткий список важнее «использовали всё».
