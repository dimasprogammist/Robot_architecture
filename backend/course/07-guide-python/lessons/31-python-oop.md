# Объектно-ориентированное программирование

Словарь `{"x": 1.0, "y": 2.0}` держит данные. Если к точке липнут «сдвинуть», «расстояние до нуля», «проверить в пределах поля» — функции разъедутся по файлу, и легко передать «не ту точку». **Класс** связывает данные и операции под одним типом.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def distance_to(self, other):
        dx = self.x - other.x
        dy = self.y - other.y
        return (dx * dx + dy * dy) ** 0.5


a = Point(0, 0)
b = Point(3, 4)
print(b.distance_to(a))
```

`class` — чертёж. `Point(0, 0)` — **экземпляр**, отдельный объект. `__init__` заполняет поля. Первый аргумент методов — `self`: «этот экземпляр». При вызове `b.distance_to(a)` Python сам подставляет `b` в `self`.

Поля `self.x` живут на объекте, не в локальных переменных `__init__` после выхода.

Наследование: `class Robot(Vehicle):` — взять поведение и добавить. На старте легко наплодить иерархию «ради ООП». Если хватает одной функции — не тащите класс. Класс уместен, когда есть **состояние**, которое живёт между вызовами: позиция, открытый ресурс, накопленный буфер.

`__str__` — как печатать для человека. `__repr__` — для отладки. Сравнение `==` по умолчанию «тот же объект», не «те же координаты». Для точек часто определяют `__eq__` или сравнивают поля явно.

Всё в Python — объект: функции, классы, модули. Это не значит, что вы обязаны писать «предприятие из интерфейсов». Пишите классы там, где они уменьшают путаницу.
