# Контекстные менеджеры и with

Файл, соединение, захват блокировки — ресурс, который нужно **отпустить**. Забыть `close` при ошибке посередине — типичная дыра. Конструкция `with` говорит: войти в блок — захватить, выйти из блока (успех или исключение) — освободить.

```python
from pathlib import Path

path = Path("log.txt")
with path.open("a", encoding="utf-8") as f:
    f.write("старт\n")
# здесь файл уже закрыт
```

Объект после `with` — **контекстный менеджер**: умеет `__enter__` и `__exit__`. Вам не обязательно писать их руками. `path.open`, `open()`, многие соединения так умеют.

Свой через класс — длинновато для старта. Короткий путь — декоратор `contextlib.contextmanager`:

```python
from contextlib import contextmanager


@contextmanager
def pretend_lock():
    print("взяли")
    try:
        yield
    finally:
        print("отдали")
```

`yield` — тело `with`. `finally` отработает даже если внутри `with` исключение.

Несколько ресурсов: два `with` вложенно или `with a, b:` в одной строке.

Что не класть в `with` без нужды: чистый расчёт без ресурса. Что класть: всё, у чего есть «закрыть / откатить / разблокировать».

`__exit__` может проглотить исключение, вернув истину — редко нужно в учебном коде, легко скрыть ошибку.
