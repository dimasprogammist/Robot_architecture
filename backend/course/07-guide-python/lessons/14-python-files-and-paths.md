# Файлы, каталоги и пути

Память процесса умрёт с процессом. Настройки, логи, карта — лежат **файлами** в файловой системе. Путь — как дойти: каталоги и имя.

В современном Python удобен `pathlib`:

```python
from pathlib import Path

path = Path("data") / "temps.txt"
text = path.read_text(encoding="utf-8")
path.write_text(text, encoding="utf-8")
```

`/` у `Path` склеивает части **независимо от ОС**: не конкатенируйте строки с `\` вручную «как в Windows». `encoding="utf-8"` пишите явно. Без него на разных машинах всплывут кракозябры.

Открытие потоком:

```python
with path.open("r", encoding="utf-8") as f:
    for line in f:
        line = line.rstrip("\n")
```

`with` закроет файл даже при ошибке. Режим `"r"` чтение, `"w"` письмо **с обнулением** файла, `"a"` дописывание в конец. Бинарный `"rb"` / `"wb"` — не текст, а байты (картинки, не UTF-8).

Относительный путь считается от **текущего рабочего каталога** процесса, не всегда от каталога, где лежит `.py`. Запустили из другого места — «файла нет», хотя он рядом со скриптом. Надёжнее: `Path(__file__).resolve().parent` — каталог файла модуля — и от него строить путь к данным.

`path.exists()`, `path.is_file()`, `path.mkdir(parents=True, exist_ok=True)` для каталогов. Не путайте файл и каталог: писать текст в путь, который уже каталог — ошибка.

Секреты и огромные логи не кладите в репозиторий без нужды. Учебный `data/` рядом с кодом — нормально.

Старый стиль `open("f.txt")` работает. Новый код лучше сразу на `Path`, чтобы не плодить два мира.
