# Итераторы и генераторы

`for x in xs` работает не только со списком. Python просит у объекта **итератор** — «дай следующий, пока не кончится». Список, строка, файл по строкам, `range`, словарь по ключам — итерируемые.

Итератор помнит место. Пройти второй раз тем же итератором часто нельзя: он исчерпан. Список можно обходить много раз — каждый `for` берёт новый итератор. Файл и генератор — нет.

**Генератор** — функция с `yield` вместо (или вместе с) `return`. При вызове тело не выполняется сразу: получается генератор-итератор. Каждый `next` / шаг `for` крутит до следующего `yield`.

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1


for x in countdown(3):
    print(x)  # 3 2 1
```

Зачем: огромный лог не обязан целиком лежать списком в оперативной памяти. Читаете строку — отдаёте — забываете. Или бесконечный поток событий (осторожно: нужен выход из `for`).

Выражение-генератор: `(x * x for x in nums)` — лениво, как списковое включение `[...]`, но без списка сразу. `sum(x * x for x in nums)` даже без лишних скобок в вызове.

`yield from` пробрасывает из другого итерируемого — позже, когда вложенность мешает.

Не путайте генератор со списком, если дальше нужен `len` и два прохода. Тогда `list(gen)` — сознательно материализовать, если данные влезают.

Остановка: `StopIteration` внутри протокола; в `for` вы её не видите. Своим кодом `next(it)` поймаете на конце.
