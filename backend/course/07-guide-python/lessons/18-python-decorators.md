# Декораторы функций

Функция в Python — объект. Её можно передать, вернуть, обернуть. **Декоратор** — функция, которая берёт функцию и возвращает другую (часто обёртку с тем же «внешним» вызовом). Синтаксис:

```python
def trace(fn):
    def wrapper(*args, **kwargs):
        print("вызов", fn.__name__)
        return fn(*args, **kwargs)

    return wrapper


@trace
def add(a, b):
    return a + b
```

`@trace` над `def add` — то же, что `add = trace(add)` после определения. Вызов `add(1, 2)` идёт в `wrapper`, тот зовёт исходную.

Зачем: не копировать «залогировать вход» в десять функций. Замер времени, проверка прав, повтор при сбое — типичные обёртки. Фреймворки (`@app.get`, `@pytest.fixture`) стоят на этой же идее.

`*args, **kwargs` — «любые позиционные и именованные», чтобы обёртка не ломала сигнатуру. Для учебы достаточно: пробросить всё внутрь.

Порядок нескольких декораторов: ближайший к `def` применяется первым. Читать снизу вверх, если запутались.

Ловушки. Обёртка без `return` исходного результата отдаст `None`. `wrapper` без `functools.wraps(fn)` подменит имя и документацию — отладка врёт. С декораторами с аргументами (`@retry(3)`) появляется ещё один уровень функций — не обязательно писать свои в первую неделю; понять `@` важнее.

Не декорируйте всё «для солидности». Декоратор прячет шаг. Если шаг — суть алгоритма, пусть он виден в теле.

## Практика

### Задание 1. Сахар

Перепишите `@trace` / `def add` без `@` через присваивание. Когда выполняется `trace` — при определении или при каждом вызове `add`?

### Задание 2. None

Обёртка вызвала `fn`, но забыла `return`. Что вернёт `add(1, 2)`? Как это выглядит в логе «сложение сломалось»?

### Задание 3. Зачем

Три функции записи лога робота. Где декоратор «время вызова» честнее копипасты? Где копипаста из трёх строк яснее магии?
