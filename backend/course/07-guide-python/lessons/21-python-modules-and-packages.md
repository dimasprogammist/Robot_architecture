# Модули, пакеты и структура Python-проектов

Один файл на весь робот не масштабируется. **Пакет** — каталог с модулями, который импортируют точкой: `from sensors.temp import read_celsius`.

Минимальная картинка:

```text
project/
  main.py
  geometry.py
  sensors/
    __init__.py
    temp.py
```

`sensors` — пакет. `__init__.py` (может быть пустым) помечает каталог как пакет в привычной модели. `main.py` делает `from sensors.temp import read_celsius` или `import sensors.temp`.

Запускают проект так, чтобы корень `project/` был на пути поиска модулей: обычно `python main.py` из этого каталога. Запуск глубокого файла как скрипта ломает относительные импорты — новичок часто «чинит» добавлением `sys.path`, лучше починить точку запуска.

Относительный импорт внутри пакета: `from .temp import read_celsius` в `sensors/__init__.py`. Точка — «этот пакет». Снаружи, из `main.py`, обычно абсолютный `from sensors.temp import ...`.

Не кладите всё в `__init__.py` «чтобы импорт короче» без меры: файл раздувается, циклы импорта ближе.

Имена каталогов — валидные имена модулей: `snake_case`, без дефиса, не `test` в смысле путаницы с pytest на старте можно жить, но пакет приложения лучше звать `app` или `robot`.

Данные (`data/`), тесты (`tests/`), код — разные ветки дерева. Тесты импортируют пакет, не наоборот.

Позже инструменты сборки (`pyproject.toml`) объявят пакет формально. Сначала дисциплина каталогов важнее.
