# Исключения и обработка ошибок

Не всякая ошибка — «программа плохая навсегда». Нет файла, сеть оборвалась, пользователь ввёл буквы вместо числа. Python поднимает **исключение**: прерывает нормальный поток и ищет, кто готов обработать.

Если никто не поймал — процесс печатает трассировку (файл, строка, тип) и заканчивается ненулевым кодом. Трассировка — друг: читайте **снизу** первое ваше место, не пугайтесь глубины библиотек.

```python
try:
    n = int(text)
except ValueError:
    n = None
    print("это не целое")
```

`try` — попытка. `except ValueError` — только этот тип (и наследники). Голый `except:` или `except Exception` на всё подряд прячет баги: опечатка имени станет «ну, ошибка», и вы не узнаете.

`int("12")` проходит. `int("12.5")` и `int("x")` — `ValueError`. `int(None)` — `TypeError`. Ловите то, что реально ждёте.

`raise ValueError("пустой id")` — сами сказать «так нельзя». Свой тип исключения позже; сначала встроенные.

`finally` выполнится и при успехе, и при ошибке: закрыть ресурс, если ещё не используете `with` (урок про контекстные менеджеры).

Не ловите исключение, чтобы проглотить и жить как ни в чём. Либо восстановились (дефолт, повтор, сообщение человеку), либо пробросьте дальше. Лог без действия — хотя бы честный.

`KeyError`, `IndexError`, `FileNotFoundError`, `ZeroDivisionError` — разные ситуации. Проверка `if key in d` иногда яснее, чем ловить `KeyError`; для файлов «сначала exists» гоняется с гонкой: файл исчез между проверкой и открытием. Тогда `try/except FileNotFoundError` естественнее.
