# Имена и объекты

## Цель

Усвоить модель «имя → объект»: присваивание как привязка ссылки.

Предсказывать эффект нескольких имён на один изменяемый объект.

## Что уже пройдено

Вы знаете синтаксис блоков.

Теперь — что хранят имена в namespaces.

## Объяснение с нуля

Почти всё — объект в куче. `=` **привязывает имя** к объекту, не кладёт значение «в коробку».

Несколько имён могут указывать на один объект (aliasing). Неизменяемые типы при «изменении» обычно дают новый объект; изменяемые методы правят тот же.

`is` — идентичность, `==` — равенство. Пока думаете коробками, баги со списками кажутся магией.

## Термины

- **Имя** — метка в пространстве имён.

- **Привязка** — связь имени с объектом.

- **Изменяемый / неизменяемый** объект.

- **`is` / `==`** — идентичность / равенство.

- **Счётчик ссылок** — сколько ссылок держит объект.

- **Aliasing** — несколько имён на один объект.

- **del** — удаление имени.

## Внутреннее устройство

Namespace модуля — dict; у функций часто оптимизированные слоты, семантика та же. STORE пишет ссылку.

`a = b` увеличивает ссылки. Передача списка в функцию передаёт ту же ссылку — функция может менять содержимое.

## Пример

```python

a = [1, 2]

b = a

c = a.copy()

b.append(3)

print(a, c)

print(a is b, a == c)

```

## Разбор

`b` — то же список; `append` виден через `a`. `c` — копия на момент копирования.

`a is b` истинно; после изменения `a == c` ложно. Для int `+=` создал бы новый объект.

## Ошибки

- Думать, что `b = a` копирует список.

- Путать `is` и `==`.

- Мутировать то, что должно быть независимой копией.

- Сравнивать float через `==` без допуска.

- Изменяемое умолчание у функции (урок про def).

## Что запомнить

Имя хранит ссылку.

`=` перепривязывает.

Мутация видна через все алиасы.
