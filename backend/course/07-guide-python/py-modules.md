# Модули import

## Цель

Понять модули как namespaces и механизм import.

Разделять код по файлам без сюрпризов повторной загрузки.

## Что уже пройдено

Вы пишете функции в одном файле.

Модули разносят код по файлам.

## Объяснение с нуля

`import math` загружает модуль (если ещё нет), кладёт в sys.modules и привязывает имя. Доступ — атрибуты.

`from math import sqrt` копирует ссылку на объект. Первый import исполняет тело модуля; повторный берёт кэш. Поиск — по sys.path.

## Термины

- **Модуль / import**.

- **sys.modules / sys.path**.

- **from ... import**.

- **Атрибут модуля**.

- **Побочный эффект импорта**.

- **Псевдоним as**.

- **Перезагрузка процесса** vs reload.

## Внутреннее устройство

Найти → создать module object → занести в sys.modules → исполнить code object.

Кэш .pyc ускоряет старт. Циклические импорты хрупки на верхнем уровне.

## Пример

```python

# util_math.py

def clamp(x, lo, hi):

    return max(lo, min(hi, x))



# app.py

import util_math as um

from util_math import clamp

print(um.clamp(15, 0, 10))

print(clamp(-3, 0, 10))

```

## Разбор

Первый import исполняет util_math и кэширует.

Два стиля импорта — разные привязки на одни объекты функций.

## Ошибки

- Дефисы в имени файла модуля.

- Ждать повторного исполнения при втором import.

- Тяжёлый I/O на верхнем уровне.

- from module import *.

- Затенение стандартного модуля своим файлом.

## Что запомнить

import один раз за процесс.

Модуль — namespace объектов.

Ищите через sys.path окружения.
