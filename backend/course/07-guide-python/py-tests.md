# Тесты

## Цель

Фиксировать поведение автоматическими тестами.

Понять тест как исполняемую спецификацию.

## Что уже пройдено

Вы пишете функции и классы.

Тесты проверяют контракты после изменений.

## Объяснение с нуля

Ручной print забывается. Автотест вызывает код и сравнивает с ожиданием. unittest в stdlib; популярен pytest. arrange→act→assert; имена test_*.

Проверяйте поведение, не случайные детали. Зависимости подменяйте. Тесты — страховка рефакторинга.

## Термины

- **Автотест / assert**.

- **pytest / unittest**.

- **Фикстура**.

- **Регрессия**.

- **Мок**.

- **Покрытие**.

- **Изоляция тестов**.

## Внутреннее устройство

Раннер импортирует тестовые модули и вызывает test_*. Падение — AssertionError, которое ловит раннер.

Тесты — тот же CPython, импортирующий ваш пакет как клиент. Изоляция важна: порядок не должен влиять.

## Пример

```python

# clamp.py

def clamp(x, lo, hi):

    return max(lo, min(hi, x))



# test_clamp.py

from clamp import clamp

def test_clamp_middle():

    assert clamp(5, 0, 10) == 5

def test_clamp_low():

    assert clamp(-1, 0, 10) == 0

```

```text

python -m pip install pytest

pytest -q

```

## Разбор

Два теста — разные ветви. После рефакторинга внутри clamp зелёный набор подтверждает контракт.

## Ошибки

- Зависимость от порядка тестов.

- Только счастливый путь.

- Покрытие 100% как фетиш.

- Тест деталей реализации.

- Сеть в юнит-тестах без нужды.

## Что запомнить

Тест — исполняемый контракт.

assert фиксирует ожидание.

Изоляция важнее количества.

## Задание

Три теста на sign или clamp, включая края.

Сломайте функцию — тесты должны упасть; верните исправление.
