# pip и зависимости

## Цель

Устанавливать пакеты через pip в активное окружение.

Фиксировать зависимости текстом для воспроизводимости.

## Что уже пройдено

Вы создаёте venv и проверяете sys.executable.

pip ставит пакеты в то окружение, чей python вызван.

## Объяснение с нуля

`python -m pip install requests` привязывает pip к выбранному интерпретатору. Пакет появляется в site-packages и становится импортируемым.

requirements.txt с версиями — простой контракт. Современнее pyproject.toml, идея та же. Не ставьте глобально «на минутку».

## Термины

- **pip / PyPI**.

- **Зависимость**.

- **requirements.txt**.

- **pin версии**.

- **site-packages**.

- **python -m pip**.

- **wheel / sdist** (обзорно).

## Внутреннее устройство

pip скачивает дистрибутив и пишет в site-packages текущего окружения.

Импорт после установки ищет модуль по sys.path. python -m pip избегает чужого pip из PATH.

## Пример

```text

python -m pip install --upgrade pip

python -m pip install requests==2.32.3

python -m pip freeze > requirements.txt

python -m pip install -r requirements.txt

```

## Разбор

Конкретная версия в текущий venv. freeze — снимок; install -r — воспроизведение.

import работает, потому что модуль на sys.path.

## Ошибки

- Голый pip от другого Python.

- Установка вне venv.

- Не фиксировать версии.

- Гигантский freeze всего мира в репозиторий.

- Путать имя PyPI и имя для import.

## Что запомнить

Ставьте через python -m pip активного интерпретатора.

Фиксируйте зависимости.

venv + pip = воспроизводимая среда.
