# Интерпретатор CPython

## Цель

Понять конвейер CPython: исходный текст → байткод → виртуальная машина → объекты в куче.

Связать имена в коде с ссылками в пространствах имён.

## Что уже пройдено

Вы установили CPython и умеете проверить версию вместе с `sys.executable`.

Теперь смотрим внутрь того, что происходит после запуска.

## Объяснение с нуля

Фраза «Python выполнил строку» скрывает цепочку. Исходник — байты (обычно UTF-8). Парсер строит дерево. Компилятор CPython даёт **байткод** — инструкции своей VM, не машинный код CPU.

VM читает операции: загрузить константу, сложить, вызвать, сохранить имя. В куче живут **объекты**: число, строка, список — структуры с типом.

Имена — не коробки со значениями, а связи в **пространстве имён** (часто dict: имя → объект).

REPL повторяет compile→eval. Файл `.py` проходит тот же путь. Модель объясняет «изменил список через другое имя» и «модуль не обновился в живом процессе».

## Термины

- **Исходный код** — текст программы.

- **Байткод** — инструкции VM (кэш `.pyc`).

- **Виртуальная машина** — цикл исполнения байткода.

- **Объект** — сущность в куче с типом и данными.

- **Пространство имён** — отображение имён на объекты.

- **Ссылка** — то, что хранит имя.

- **REPL** — интерактивный цикл чтения и выполнения.

## Внутреннее устройство

Конвейер: токены → AST → code object → frame (локальные имена, стек операндов) → eval-loop.

Объекты в куче; счётчик ссылок + сборщик циклов. `__pycache__` ускоряет импорт, исходник — источник правды.

Закрыли процесс — куча исчезла. Между вводами REPL имена сохраняют объекты живыми.

## Пример

```python

x = 10

y = x

print(id(x) == id(y))

y = y + 1

print(x, y)

```

## Разбор

`y = x` копирует ссылку, не число. `y + 1` для int создаёт новый объект; `x` на старом.

Неизменяемый тип + перепривязка имени. Байткод: LOAD, BINARY_OP, STORE.

## Ошибки

- Считать переменную коробкой со значением.

- Путать байткод с кодом CPU.

- Считать редактор интерпретатором.

- Ждать автообновления уже импортированного модуля.

- Забывать, что каждый запуск — новый процесс.

## Что запомнить

Текст → байткод → VM.

Данные — объекты; имена — ссылки.

REPL и файл делят одну модель исполнения.

## Задание

В REPL: `a=[1]; b=a; b.append(2); print(a)`.

Объясните через объекты и ссылки, не через «скопировались».


На стенде повторите пример урока и проговорите вслух: какие объекты появились в куче, какие имена на них ссылаются и какой шаг потока управления изменился.
