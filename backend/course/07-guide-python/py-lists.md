# Списки

## Цель

Освоить list как изменяемую последовательность.

Понять стоимость операций и ловушку разделяемых ссылок.

## Что уже пройдено

Вы работаете со строками как с неизменяемыми последовательностями.

Список похож внешне, семантика изменения другая.

## Объяснение с нуля

Список хранит упорядоченные ссылки на объекты; элементы могут быть разных типов. Изменяем: append/pop/присвоение по индексу.

Срез даёт новый список; присвоение в срез может менять длину. Динамический массив ссылок: append в конец дёшев, вставка в начало дороже.

Ловушка матрицы: `[[0]*n]*m` копирует ссылки на один внутренний список.

## Термины

- **list**.

- **append / pop / sort**.

- **Срез списка**.

- **Изменяемость на месте**.

- **Алиасинг**.

- **Сложность операций**.

- **Список списков**.

## Внутреннее устройство

CPython list — массив указателей с запасом capacity; при росте иногда перевыделение.

Хранятся ссылки: `[a,a]` — две ссылки на один объект. Итерация через протокол итератора; менять список во время for по нему — источник багов.

## Пример

```python

nums = [3, 1, 2]

nums.append(4)

nums.sort()

head, *rest = nums

print(nums, head, rest)

row = [0] * 3

grid = [row, row]

grid[0][0] = 7

print(grid)

```

## Разбор

append/sort меняют на месте; sort возвращает None.

grid показывает алиасинг одной row. Правильно: `[[0]*3 for _ in range(2)]`.

## Ошибки

- `nums = nums.sort()` → None.

- Матрица через размножение ссылок.

- Модификация списка в своём for.

- Путать append и extend.

- Думать, что срез list — вьюха без копии ссылок.
