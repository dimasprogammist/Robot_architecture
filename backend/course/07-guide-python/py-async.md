# async/await введение

## Цель

Понять кооперативную асинхронность на ожидании I/O.

Написать минимум: async def, await, asyncio.run.

## Что уже пройдено

Вы знаете обычные функции и блокирующие сетевые вызовы.

async позволяет одному потоку чередовать ожидания.

## Объяснение с нуля

Блокирующий get держит поток до ответа. Корутина на await отдаёт управление циклу событий — он может запустить другую задачу.

async def возвращает объект корутины; исполняет asyncio.run. await — только внутри async. Это не ускорение CPU: выигрыш в перекрытии ожидания I/O. Блокирующий вызов внутри корутины замораживает loop.

## Термины

- **Корутина / await / awaitable**.

- **Event loop**.

- **asyncio**.

- **Конкурентность**.

- **create_task / gather**.

- **Блокирующий вызов**.

- **asyncio.sleep**.

## Внутреннее устройство

Корутины родственны генераторам: приостанавливаемый frame. Loop планирует продолжение после готовности I/O.

Код между await в одном потоке непрерывен — долгий CPU без await тормозит всех.

## Пример

```python

import asyncio

async def fetch_name(delay: float, name: str) -> str:

    await asyncio.sleep(delay)

    return name

async def main() -> None:

    a = asyncio.create_task(fetch_name(0.1, "Ana"))

    b = asyncio.create_task(fetch_name(0.1, "Bob"))

    print(await a, await b)

asyncio.run(main())

```

## Разбор

sleep имитирует I/O; задачи перекрывают ожидание.

Без asyncio.run корутина main не исполнится.

## Ошибки

- Вызвать async def без await/run.

- time.sleep/requests внутри корутины.

- Ждать ускорения численных расчётов.

- Вложенный asyncio.run в уже бегущем loop.

## Что запомнить

async/await = кооперация на ожидании.

Нужен event loop.

Не блокируйте loop синхронным I/O.
