# Композиция

## Цель

Собирать поведение из частей («имеет внутри»), а не только наследованием.

Увидеть композицию как практический стиль в Python.

## Что уже пройдено

Вы знаете классы и наследование.

Композиция часто яснее глубоких иерархий.

## Объяснение с нуля

Объект хранит ссылки на другие и делегирует работу: робот имеет моторы; сервис имеет хранилище. В коде: `self.db = Database(...)`.

Плюсы: подмена частей в тестах, меньше жёсткой связанности. Наследование — для «является разновидностью». В Python композиция естественна: всё объекты и ссылки.

## Термины

- **Композиция / делегирование**.

- **Зависимость / инъекция**.

- **Связанность**.

- **Тестовый двойник**.

- **Фасад**.

- **Явная передача зависимости**.

- **Циклические ссылки**.

## Внутреннее устройство

Обычные атрибуты-ссылки, без особого байткода. Поиск метода внутрь не автоматический — вы пишете self.inner.method().

Циклы ссылок возможны; яснее избегать ненужных.

## Пример

```python

class Motor:

    def __init__(self, name):

        self.name = name

    def run(self, speed):

        return f"{self.name}:{speed}"

class Robot:

    def __init__(self, left, right):

        self.left = left

        self.right = right

    def move(self, speed):

        return self.left.run(speed), self.right.run(speed)

bot = Robot(Motor("L"), Motor("R"))

print(bot.move(0.5))

```

## Разбор

Robot не наследует Motor — держит два мотора и делегирует.

Можно подставить мок с методом run без правки Robot.

## Ошибки

- Наследовать лишь чтобы «достать поля».

- Скрытые глобальные синглтоны вместо явных зависимостей.

- Клубок взаимных ссылок.

- Путать композицию с копированием данных.

## Что запомнить

Композиция = ссылки на части + делегирование.

Часто яснее наследования.

Зависимости лучше передавать явно.
