# Ethernet и TCP/IP для устройств

## Цель

В предыдущих уроках мы разбирали последовательную связь, Modbus и CAN. Теперь перейдём к сетям, которые используются компьютерами, серверами, микроконтроллерами и различными устройствами.

После урока вы должны понимать:

* что такое Ethernet;
* чем MAC-адрес отличается от IP-адреса;
* что такое TCP и UDP;
* что такое порт;
* как работает клиент-серверное соединение;
* что такое socket;
* почему IP-адрес сам по себе не определяет конкретное приложение;
* как устройство может обмениваться данными с компьютером по сети.

---

## 1. От последовательной линии к сети

Представим простой микроконтроллер, подключённый к компьютеру через UART.

```text
┌──────────────┐       UART       ┌──────────────┐
│ Микроконтроллер │ ───────────── │   Компьютер  │
└──────────────┘                  └──────────────┘
```

У такой схемы есть понятный недостаток: соединение непосредственно связывает два устройства.

Если устройств становится много, хочется получить общую сеть:

```text
                 ┌──────────────┐
                 │  Компьютер  │
                 └──────┬───────┘
                        │
                 ┌──────┴───────┐
                 │    Switch    │
                 └─┬────┬────┬─┘
                   │    │    │
                ┌──┘    │    └──┐
                ▼       ▼       ▼
             ┌────┐  ┌────┐  ┌────┐
             │MCU │  │PC  │  │MCU │
             └────┘  └────┘  └────┘
```

Для этого используется Ethernet.

Ethernet определяет правила передачи данных внутри локальной сети. Но Ethernet сам по себе не решает всю задачу обмена приложениями.

Поэтому поверх него работают другие протоколы.

Упрощённо стек можно представить так:

```text
Приложение
    ↓
TCP / UDP
    ↓
IP
    ↓
Ethernet
    ↓
Физическая среда
```

Каждый уровень решает свою задачу.

---

# 2. Что такое Ethernet

Ethernet — это набор технологий для построения локальных компьютерных сетей.

В привычном варианте устройство подключается к сети через Ethernet-порт:

```text
[Устройство]
     │
     │ Ethernet
     ▼
[Коммутатор]
     │
     ├──────── [Компьютер]
     │
     ├──────── [Сервер]
     │
     └──────── [Другое устройство]
```

Ethernet может работать по медному кабелю или по оптоволокну.

Скорости могут быть разными:

```text
10 Mbit/s
100 Mbit/s
1 Gbit/s
10 Gbit/s
...
```

Для изучения протоколов конкретная скорость часто не так важна.

Гораздо важнее понять, что Ethernet предоставляет способ передачи кадров между сетевыми интерфейсами.

---

# 3. MAC-адрес

У сетевого интерфейса есть MAC-адрес.

Например:

```text
3C:52:82:AB:17:04
```

MAC-адрес обычно связан с сетевым интерфейсом устройства.

В локальной сети он используется для доставки Ethernet-кадров.

Например:

```text
Компьютер A
MAC: AA:AA:AA:AA:AA:AA

        ↓ Ethernet

Компьютер B
MAC: BB:BB:BB:BB:BB:BB
```

Кадр Ethernet содержит информацию о получателе и отправителе.

Упрощённо:

```text
┌─────────────┬─────────────┬──────────────┐
│ MAC получателя │ MAC отправителя │ Данные │
└─────────────┴─────────────┴──────────────┘
```

Однако человеку неудобно работать с MAC-адресами при построении больших сетей.

Для этого используется IP.

---

# 4. IP-адрес

IP-адрес позволяет логически адресовать устройства в сети.

Например:

```text
192.168.1.10
192.168.1.20
192.168.1.30
```

Можно представить:

```text
MAC → физический адрес интерфейса

IP  → логический адрес устройства в сети
```

Например:

```text
Компьютер:
IP  = 192.168.1.10
MAC = AA:AA:AA:AA:AA:AA
```

Другой компьютер:

```text
IP  = 192.168.1.20
MAC = BB:BB:BB:BB:BB:BB
```

IP позволяет определить, куда нужно доставить IP-пакет.

Ethernet затем используется для передачи данных по конкретному участку сети.

---

# 5. Почему одного IP недостаточно

Представим компьютер:

```text
192.168.1.10
```

На нём одновременно работают:

* браузер;
* сервер базы данных;
* программа мониторинга;
* игра;
* наше собственное приложение.

Все они используют один IP-адрес.

Как же понять, какому приложению предназначены данные?

Для этого существуют **порты**.

Например:

```text
192.168.1.10:80
192.168.1.10:443
192.168.1.10:502
192.168.1.10:8080
```

Здесь:

```text
192.168.1.10
```

— IP-адрес,

а:

```text
8080
```

— номер порта.

Можно представить это как здание:

```text
IP-адрес → адрес здания

порт     → номер нужного входа/службы
```

# 6. TCP

TCP — протокол транспортного уровня.

Он предназначен для надёжной передачи потока данных между двумя участниками.

Упрощённая схема:

```text
Клиент
  │
  │ TCP
  ▼
Сервер
```

Перед обменом данными TCP устанавливает соединение.

После этого приложения могут отправлять данные.

TCP старается обеспечить:

* доставку данных;
* правильный порядок;
* обнаружение потерь;
* повторную передачу потерянных данных.

Например, приложение отправляет:

```text
HELLO
```

TCP может разбить поток данных на отдельные сегменты и передать их по сети.

Получатель собирает данные обратно.

---

# 7. TCP — это поток

Очень важно понимать одну особенность TCP.

TCP не передаёт сообщения в том виде, в котором их видит программа.

Например, программа делает:

```text
send("HELLO")
send("WORLD")
```

Получатель не обязан получить ровно:

```text
HELLO
WORLD
```

Он может прочитать:

```text
HELLOWORLD
```

или:

```text
HEL
LOWORLD
```

или:

```text
HELLOW
ORLD
```

С точки зрения TCP это всё один поток байтов:

```text
H E L L O W O R L D
```

Границы сообщений должен определять протокол приложения.

Например, можно договориться использовать перевод строки:

```text
TEMP=24.5\n
TEMP=24.6\n
TEMP=24.7\n
```

Или длину сообщения:

```text
[длина][данные]
```

Или собственный формат пакета.

Это особенно важно при разработке собственных сетевых устройств.

---

# 8. UDP

UDP тоже является транспортным протоколом, но работает иначе.

В отличие от TCP, UDP не устанавливает соединение в том же смысле и не гарантирует доставку каждого пакета.

Программа может отправить:

```text
UDP → "TEMPERATURE=24.5"
```

Если пакет потеряется, UDP сам по себе не потребует его повторной передачи.

Это делает UDP проще и часто быстрее.

Например, UDP может использоваться там, где важнее свежесть данных, чем гарантированная доставка каждого значения.

Представим поток координат:

```text
X=100
X=101
X=102
X=103
X=104
```

Если потерялось значение:

```text
X=102
```

можно просто получить следующее:

```text
X=103
```

Для некоторых задач это нормально.

---

# 9. TCP и UDP

Упрощённое сравнение:

| Свойство | TCP | UDP |
|---|---|---|
| Соединение | Да | Нет в TCP-смысле |
| Гарантия доставки | Да | Нет |
| Порядок данных | Сохраняется | Не гарантируется |
| Повторная передача | Есть | Нет |
| Поток данных | Да | Нет, датаграммы |
| Сложность | Выше | Ниже |

Нельзя сказать, что один протокол всегда лучше другого.

Выбор зависит от задачи.

# 10. Клиент и сервер

Очень распространённая архитектура:

```text
             TCP
Клиент ───────────────→ Сервер
```

Сервер ждёт подключения:

```text
Server:
IP   = 192.168.1.100
Port = 5000
```

Клиент подключается:

```text
192.168.1.100:5000
```

После установки TCP-соединения они могут обмениваться данными.

Например:

```text
Клиент → GET_STATUS
Сервер → OK
```

или:

```text
Клиент → SET_SPEED 120
Сервер → OK
```

# 11. Socket

В программировании сетевое соединение обычно представляется объектом, который называют **socket**.

Socket можно представить как программный интерфейс для работы с сетью.

Например:

```text
Программа
   │
   ▼
Socket
   │
   ▼
TCP/IP
   │
   ▼
Ethernet
   │
   ▼
Сеть
```

Типичный TCP-сервер делает примерно следующее:

```text
создать socket
      ↓
привязать IP и порт
      ↓
начать ожидание
      ↓
принять соединение
      ↓
получать данные
      ↓
отправлять данные
```

Клиент:

```text
создать socket
      ↓
подключиться к IP:порт
      ↓
отправлять данные
      ↓
получать ответы
```

# 12. Пример TCP-клиента на Python

Для эксперимента можно создать простой клиент:

```python
import socket

sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

sock.connect(("127.0.0.1", 5000))

sock.sendall(b"HELLO")

response = sock.recv(1024)

print(response.decode())

sock.close()
```

Здесь:

```python
socket.AF_INET
```

означает использование IPv4.

А:

```python
socket.SOCK_STREAM
```

означает TCP.

---

# 13. Простой TCP-сервер

Сервер может выглядеть так:

```python
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

server.bind(("0.0.0.0", 5000))
server.listen()

print("Сервер запущен")

client, address = server.accept()

print("Подключение:", address)

data = client.recv(1024)

print("Получено:", data.decode())

client.sendall(b"OK")

client.close()
server.close()
```

После запуска сервер ждёт подключения на порту:

```text
5000
```

К нему может подключиться клиент.

# 14. Что происходит на самом деле

Когда приложение отправляет данные, они проходят через несколько уровней.

Например:

```text
Программа
   │
   │ "HELLO"
   ▼
TCP
   │
   ▼
IP
   │
   ▼
Ethernet
   │
   ▼
Кабель
```

На принимающей стороне процесс идёт в обратную сторону:

```text
Кабель
   │
   ▼
Ethernet
   │
   ▼
IP
   │
   ▼
TCP
   │
   ▼
Программа
```

Каждый уровень добавляет необходимую ему служебную информацию.

Упрощённо:

```text
Ethernet frame
┌───────────────────────────────┐
│ Ethernet header              │
│ ┌───────────────────────────┐ │
│ │ IP packet                 │ │
│ │ ┌───────────────────────┐ │ │
│ │ │ TCP segment           │ │ │
│ │ │ ┌───────────────────┐ │ │ │
│ │ │ │ Application data  │ │ │ │
│ │ │ └───────────────────┘ │ │ │
│ │ └───────────────────────┘ │ │
│ └───────────────────────────┘ │
└───────────────────────────────┘
```

Это называется инкапсуляцией.

# 15. TCP/IP в робототехнике

Представим робота с контроллером и компьютером.

```text
┌───────────────┐
│ Компьютер     │
│               │
│ 192.168.1.10  │
└───────┬───────┘
        │ Ethernet
        │
┌───────▼───────┐
│ Контроллер    │
│               │
│ 192.168.1.20  │
└───────────────┘
```

Можно определить простой протокол:

```text
GET_POSITION
```

Ответ:

```text
X=120.5;Y=80.2;Z=35.0
```

Или использовать бинарный формат:

```text
[COMMAND][LENGTH][DATA][CRC]
```

TCP/IP в данном случае отвечает за доставку потока между устройствами, а формат команд определяется уже вашим приложением.

# 16. Главное

Нужно разделять несколько понятий:

```text
Ethernet
    ↓
передача кадров в локальной сети

IP
    ↓
адресация и маршрутизация

TCP / UDP
    ↓
транспорт данных между приложениями

Порт
    ↓
идентификация сетевой службы

Протокол приложения
    ↓
что конкретно означают данные
```

Например:

```text
192.168.1.50:5000
```

говорит:

> Связаться с устройством по IP 192.168.1.50 и портом 5000.

Но это ещё не говорит, **какие команды нужно отправлять**.

Это определяется протоколом приложения.

## Итог

Теперь вы можете представить сетевой обмен не как одну непонятную технологию, а как несколько уровней:

```text
Приложение
    ↓
TCP / UDP
    ↓
IP
    ↓
Ethernet
    ↓
Физическая сеть
```

Эта модель будет использоваться практически во всех последующих сетевых технологиях.

Следующий шаг — посмотреть на протокол, который работает непосредственно поверх этой сетевой инфраструктуры и предоставляет устройствам структурированную модель данных: OPC UA.
