# Modbus TCP

## Цель

После этого урока вы должны понимать:

* как Modbus работает поверх TCP/IP;
* чем Modbus TCP отличается от Modbus RTU;
* что такое TCP-соединение;
* зачем нужен порт 502;
* что такое MBAP header;
* как выглядит обмен Modbus TCP;
* почему Ethernet не заменяет протокол Modbus;
* как диагностировать простой обмен.

---

## От последовательной линии к сети

В предыдущем уроке мы рассмотрели Modbus RTU.

Типичная схема выглядела так:

```text
Компьютер
   │
   │ RS-485
   │
   ├── Device 1
   ├── Device 2
   └── Device 3
```

Но современные устройства часто имеют Ethernet.

Тогда можно построить:

```text
Компьютер
   │
 Ethernet
   │
 Switch
 ├──── Device 1
 ├──── Device 2
 └──── Device 3
```

Для этого существует Modbus TCP.

---

## Что такое Modbus TCP

Modbus TCP — вариант Modbus, использующий TCP/IP для передачи данных.

Упрощённая цепочка:

```text
Modbus
  ↓
TCP
  ↓
IP
  ↓
Ethernet
```

Это означает, что Modbus отвечает за прикладной обмен, а TCP/IP — за сетевую доставку.

---

## Что меняется по сравнению с RTU

В Modbus RTU используется:

```text
последовательный канал
```

часто:

```text
RS-485
```

В Modbus TCP используется:

```text
Ethernet
```

и:

```text
TCP/IP
```

Поэтому физическая архитектура выглядит иначе.

### RTU

```text
Controller
    │
  RS-485
    │
 Device
```

### TCP

```text
Controller
    │
 Ethernet
    │
 Switch
    │
 Device
```

---

## TCP

TCP — протокол транспортного уровня.

Его задача — обеспечить взаимодействие между двумя сетевыми конечными точками в виде надёжного потока данных.

Упрощённо:

```text
Application
    ↓
TCP
    ↓
IP
    ↓
Ethernet
```

Modbus TCP является приложением поверх TCP.

---

## Соединение

В TCP сначала устанавливается соединение.

Упрощённо:

```text
Client → установить соединение → Server
```

После установления соединения можно передавать данные.

Для Modbus TCP обычно:

```text
Client → Server
```

Клиент отправляет запрос.

Сервер возвращает ответ.

---

## IP-адрес и порт

Чтобы подключиться к устройству, обычно нужны:

```text
IP address
Port
```

Например:

```text
192.168.1.50:502
```

Здесь:

```text
192.168.1.50
```

— IP-адрес устройства,

```text
502
```

— TCP-порт Modbus.

---

## Почему нужен порт

На одном компьютере может работать множество сетевых программ.

Например:

```text
192.168.1.50:80
192.168.1.50:443
192.168.1.50:502
192.168.1.50:8080
```

IP определяет устройство.

Порт помогает определить нужный сетевой сервис.

Поэтому:

```text
IP + port
```

позволяют направить TCP-соединение к нужному приложению или сервису.

---

## Modbus TCP не использует CRC как RTU

Это важное отличие.

В Modbus RTU кадр содержит:

```text
Address
Function
Data
CRC
```

В Modbus TCP структура другая.

TCP уже имеет собственные механизмы проверки и надёжной передачи.

Поэтому отдельное поле Modbus RTU CRC в Modbus TCP обычно не используется.

Вместо этого используется дополнительная информация Modbus TCP — **MBAP header**.

---

## MBAP Header

MBAP расшифровывается как:

**Modbus Application Protocol header**

Упрощённо он содержит:

```text
Transaction Identifier
Protocol Identifier
Length
Unit Identifier
```

После него идут:

```text
Function Code
Data
```

Получается:

```text
┌─────────────────────┐
│ MBAP Header         │
├─────────────────────┤
│ Function Code       │
├─────────────────────┤
│ Data                │
└─────────────────────┘
```

---

## Transaction Identifier

Transaction ID помогает сопоставить запрос и ответ.

Например:

```text
Request:
Transaction ID = 15
```

Сервер возвращает:

```text
Transaction ID = 15
```

Клиент понимает:

> Этот ответ относится к моему запросу №15.

Это особенно полезно, когда программа обрабатывает несколько запросов.

---

## Protocol Identifier

Для Modbus TCP используется идентификатор протокола, соответствующий Modbus.

В стандартном варианте он имеет значение:

```text
0
```

Его задача — указать тип протокола.

---

## Length

Поле Length сообщает длину оставшейся части сообщения.

Получатель может использовать его, чтобы определить, сколько данных нужно прочитать из TCP-потока для формирования одного Modbus TCP сообщения.

---

## Unit Identifier

Unit Identifier позволяет идентифицировать логическое устройство внутри запроса.

В простой Ethernet-системе он может быть менее важен, чем IP-адрес.

Но поле сохраняется в формате Modbus TCP и особенно полезно в архитектурах, где Modbus TCP используется совместно с другими механизмами или шлюзами.

---

## Структура Modbus TCP

Упрощённо:

```text
┌──────────────────────────┐
│ Transaction ID           │
├──────────────────────────┤
│ Protocol ID              │
├──────────────────────────┤
│ Length                   │
├──────────────────────────┤
│ Unit ID                  │
├──────────────────────────┤
│ Function Code            │
├──────────────────────────┤
│ Data                     │
└──────────────────────────┘
```

В сравнении с RTU:

```text
RTU:
Address + Function + Data + CRC

TCP:
MBAP + Function + Data
```

---

## Пример запроса

Допустим:

```text
IP = 192.168.1.50
Port = 502
```

Клиент хочет прочитать:

```text
3 holding registers
starting at address 100
```

Логически запрос выглядит:

```text
Device → 192.168.1.50
Port   → 502

Function → Read Holding Registers
Start    → 100
Count    → 3
```

На уровне TCP это передаётся как последовательность байтов.

---

## Ответ

Устройство возвращает:

```text
Register 100
Register 101
Register 102
```

Например:

```text
245
1500
30
```

Клиент получает эти значения и интерпретирует их согласно документации устройства.

---

## TCP не знает, что такое регистр

Это важная идея.

TCP видит поток данных.

Он не понимает:

```text
Register 100
Temperature
Holding Register
```

Для TCP всё это просто байты.

Modbus интерпретирует эти байты как:

```text
Function Code
Address
Register Count
Register Values
```

Получается:

```text
TCP
 ↓
передаёт байты

Modbus
 ↓
понимает смысл этих байтов
```

---

## TCP — поток, а не набор сообщений

Это важная особенность.

Программа может отправить:

```text
MESSAGE A
MESSAGE B
```

TCP гарантирует доставку последовательности байтов, но не предоставляет отдельные границы сообщений приложения.

То есть получатель может получить данные частями:

```text
часть A
```

затем:

```text
остальная часть A + часть B
```

Поэтому протокол поверх TCP должен сам определять структуру сообщений.

Modbus TCP делает это с помощью MBAP header и поля Length.

---

## Почему это важно программисту

Если вы пишете TCP-сервер самостоятельно, нельзя считать:

```python
data = socket.recv(1024)
```

и автоматически предполагать:

> `data` содержит ровно одно сообщение.

Может быть:

```text
половина сообщения
```

или:

```text
два сообщения сразу
```

или:

```text
сообщение + часть следующего
```

Протокол должен определить, как отделять одно сообщение от другого.

---

## Исключения и ошибки

Modbus также определяет ответы об ошибках.

Например:

```text
запрошена неизвестная функция
```

или:

```text
обращение к недопустимому адресу
```

или:

```text
недопустимое значение
```

В таком случае сервер может сформировать exception response.

Логически:

```text
Client → неправильный запрос
Server → exception
```

---

## Что происходит при отсутствии устройства

Представим:

```text
Client
   │
   │ TCP connect
   ↓
192.168.1.50:502
```

Но устройство выключено.

TCP-соединение не устанавливается.

Программа может получить ошибку соединения или после ожидания получить timeout.

Это отличается от Modbus exception.

### TCP connection error

Проблема на уровне соединения.

### Modbus exception

TCP-соединение работает, но устройство сообщает:

> Ваш запрос некорректен.

Это разные уровни ошибки.

---

## Диагностика

Если Modbus TCP не работает, удобно проверять уровни по порядку.

### 1. Есть ли сеть?

Проверить доступность устройства.

Например:

```text
ping 192.168.1.50
```

Но успешный ping ещё не означает, что Modbus работает.

### 2. Открыт ли порт?

Проверить:

```text
192.168.1.50:502
```

Если TCP-соединение не устанавливается, проблема может быть:

* устройство;
* сеть;
* firewall;
* неправильный IP;
* сервис Modbus.

### 3. Устанавливается ли TCP?

Если TCP работает:

```text
TCP connection = OK
```

можно переходить к Modbus.

### 4. Правильный ли запрос?

Проверяются:

* function code;
* адрес регистра;
* количество регистров;
* Unit ID;
* формат данных.

---

## Типичная ошибка

Представим:

```text
Ping → OK
TCP 502 → OK
```

но чтение регистра не работает.

Это означает:

> Сеть и TCP-соединение уже работают, но проблема может находиться выше.

Например:

```text
неправильный адрес регистра
неправильная функция
неправильный Unit ID
неподдерживаемая команда
неверная интерпретация данных
```

Это очень полезный принцип диагностики:

> проверять систему снизу вверх.

---

## Endianness и данные

Modbus использует 16-битные регистры.

Но реальные значения могут занимать:

```text
32 бита
64 бита
float
double
```

Например, одно число `float32` может занимать два регистра:

```text
Register 100
Register 101
```

А `float64` — четыре регистра.

Возникает вопрос:

> В каком порядке расположены байты и регистры?

Это зависит от конкретного устройства.

Поэтому нельзя автоматически предполагать порядок байтов и слов.

Всегда нужно смотреть документацию производителя.

---

## Modbus TCP в программировании

Например, Python-программа может работать логически так:

```python
client.connect()

value = client.read_holding_registers(
    address=100,
    count=1
)

print(value)
```

Библиотека самостоятельно занимается:

```text
TCP connection
MBAP
Function Code
Data
```

А программист работает с более высоким уровнем:

```text
прочитать регистр
```

Это хороший пример абстракции.

---

## Сравнение RTU и TCP

| Характеристика | Modbus RTU | Modbus TCP |
|---|---|---|
| Транспорт | последовательный | TCP/IP |
| Типичная физика | RS-485 | Ethernet |
| Адрес устройства | есть | Unit ID + IP |
| CRC | используется | нет отдельного RTU CRC |
| TCP-порт | нет | 502 |
| MBAP | нет | есть |
| Среда | последовательная линия | Ethernet-сеть |

---

## Главное

Modbus TCP не является полностью новым протоколом по смыслу.

Это Modbus, работающий через TCP/IP.

Упрощённо:

```text
Программа
   ↓
Modbus TCP
   ↓
TCP
   ↓
IP
   ↓
Ethernet
   ↓
Сеть
```

При диагностике полезно двигаться по уровням:

```text
устройство
   ↓
сеть
   ↓
IP
   ↓
TCP 502
   ↓
Modbus
   ↓
регистр / команда
   ↓
интерпретация данных
```
