# Сложность алгоритмов

## Цель

Научиться оценивать, как растут время работы и расход памяти при росте размера входа, и отличать это от фразы «у меня ноутбук медленный».

## Что уже нужно знать

Понятие алгоритма, циклы, вложенные циклы, параметр `n` как размер входа (длина списка, число вершин и т.д.).

## Объяснение с нуля

Сложность — это не «секунды на моём ПК», а зависимость ресурсов от размера задачи. Один и тот же алгоритм на разных машинах даст разное время, но порядок роста сохранится: если вход стал в 10 раз больше, линейный алгоритм станет примерно в 10 раз дольше, квадратичный — примерно в 100.

Мы разделяем **временну́ю сложность** (сколько шагов) и **пространственную** (сколько дополнительной памяти). «Шаг» в учебной модели — сравнение, присвоение, арифметика, доступ по индексу. На практике константы тоже важны, но сначала сравнивают порядки роста.

Сложность описывают для **худшего**, **среднего** и иногда **лучшего** случая. Поиск в неотсортированном массиве: лучший — элемент на первой позиции, худший — его нет или он в конце. Без уточнения обычно имеют в виду худший случай.

Зачем это инженеру: выбрать структуру данных, понять, почему API тормозит на сотнях тысяч записей, оценить, влезет ли решение в лимит по времени.

## Термины

- **n** — параметр размера входа.
- **T(n)** — число шагов (или оценка) как функция от n.
- **Дополнительная память** — память сверх той, что занимает сам вход.
- **Худший случай** — вход, на котором алгоритм делает максимум работы.
- **Амортизация** — средняя цена серии операций, когда редкие дорогие шаги размазаны по многим дешёвым.

## Внутреннее устройство сравнения

Возьмите два способа поиска дубликата.

Способ А: для каждого элемента просмотреть весь хвост — вложенные циклы. При n = 1000 это порядка миллиона сравнений.

Способ Б: положить элементы в множество и проверять «уже видели» — один проход. При n = 1000 — порядка тысячи шагов плюс память под множество.

На маленьком n разница может быть незаметна. На большом А «умрёт», Б выживет. Сложность как раз про этот переход при росте данных.

## Пример: счёт операций на маленьком входе

Сумма элементов `[3, 1, 4, 1, 5, 9, 2, 6]` (n = 8):

```text
s = 0
для каждого x в списке:
    s = s + x
вернуть s
```

Инициализация — один шаг. Цикл — восемь прибавлений. Итого порядка n шагов → линейно.

Теперь все пары:

```text
для i от 0 до n-1:
    для j от i+1 до n-1:
        посмотреть nums[i] + nums[j]
```

Число пар ≈ n(n−1)/2 → растёт как n². На n = 8 это 28 пар; на n = 800 — уже сотни тысяч.

### Код: два способа уникальности

```python
def has_unique_quadratic(nums: list[int]) -> bool:
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] == nums[j]:
                return False
    return True


def has_unique_linear(nums: list[int]) -> bool:
    seen: set[int] = set()
    for x in nums:
        if x in seen:
            return False
        seen.add(x)
    return True


sample = [3, 1, 4, 1, 5, 9, 2, 6]
assert has_unique_quadratic(sample) is False
assert has_unique_linear(sample) is False
```

### Разбор по блокам

- Квадратичный вариант: внешний цикл даёт n итераций, внутренний в среднем тоже растёт с n → T(n) ~ n², доп. память O(1).
- Линейный вариант: один проход, операции множества в среднем дёшевы → T(n) ~ n, доп. память O(n) под `seen`.
- Выбор — компромисс: время против памяти.

## Практика

Для кода, который для каждой строки матрицы n×n считает сумму элементов строки, оцените порядок T(n). Затем подумайте, что будет, если наивно перебрать все подматрицы.

## Типичные ошибки

- Мерить сложность секундомером на одном входе и делать вывод навсегда.
- Игнорировать константы там, где n маленькое.
- Считать, что O(n) всегда лучше O(n log n) без контекста размера и констант.
- Забывать про память: «быстрый» алгоритм, съедающий гигабайты, может быть неприемлем.
- Путать сложность алгоритма со сложностью «я плохо написал цикл на Python».
