# Массив

`a[i]` кажется «просто взять элемент». Под этим — непрерывный кусок памяти: адрес i-го считают как начало плюс `i × размер`. Отсюда **O(1)** по индексу. Соседние элементы лежат рядом — процессорный кэш это любит.

Плата: дырки в середине нет. Вставить `25` в `[10, 20, 30, 40, 50, 60]` на позицию 2 — сдвинуть хвост вправо, потом положить значение. Сдвигов столько, сколько элементов справа, до **O(n)**. Удаление — сдвиг влево.

```text
[10, 20, 30, 40, 50, 60]  вставить 25 на индекс 2
сдвиг: 60, 50, 40, 30
итог:  [10, 20, 25, 30, 40, 50, 60]
a[4] по-прежнему O(1) — это 40
```

```python
def insert_at(a: list[int], index: int, value: int) -> None:
    a.append(0)
    for i in range(len(a) - 1, index, -1):
        a[i] = a[i - 1]
    a[index] = value
```

**Длина** — сколько занято. **Ёмкость** — сколько слотов выделено. `append` в конец при запасе ёмкости дешёвый; кончилась — новый блок и копирование всех. В Python `list` это амортизированно O(1) на append: редкий дорогой рост размазан по многим дешёвым.

Важная ловушка языка: `list` — динамический **массив ссылок**, не связный список. `lst[i]` быстрый. `insert(0)` и `pop(0)` — сдвиг всех, очередь так не строят (для этого `deque`).

Поиск значения без доп. структуры — линейный проход. Если массив отсортирован, можно делить пополам — это уже следующий сюжет про поиск.

Массив берут, когда много обращений по номеру и мало вставок в середину.
