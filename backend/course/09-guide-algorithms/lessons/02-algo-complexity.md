# Сложность алгоритмов

Секундомер на одном ноутбуке не сравнивает алгоритмы. Сравнивают, как растут время и память, когда вход в десять и в тысячу раз больше. Параметр `n` — длина списка, число вершин, размер файла.

Один и тот же план на разных машинах даст разные секунды, но порядок роста сохранится: линейный на входе ×10 станет примерно в 10 раз дольше, квадратичный — примерно в 100. **Время** — число шагов (сравнение, присвоение, доступ по индексу). **Память** — дополнительная, сверх самого входа. Константы на практике важны, но сначала сравнивают порядки.

Без уточнения обычно имеют в виду **худший** случай. Поиск в неотсортированном массиве: лучший — элемент сразу, худший — нет или в конце. **Амортизация** — средняя цена серии, когда редкий дорогой шаг размазан по многим дешёвым (рост массива с удвоением).

Два способа искать дубликат. А: для каждого элемента смотреть хвост — при n = 1000 порядка миллиона сравнений. Б: множество «уже видели» — один проход плюс память. На маленьком n разница незаметна. На большом А умирает. Сложность про этот переход.

Сумма `[3, 1, 4, 1, 5, 9, 2, 6]` (n = 8): восемь сложений, память на одно число `s`. Удвоение n — удвоение сложений. Вложенный цикл «каждый с каждым» на тех же восьми — уже десятки сравнений, на тысяче — миллион.

Зачем инженеру: выбрать структуру, понять, почему API жив на сотнях записей и мёртв на сотнях тысяч, влезет ли решение в лимит.

Не путайте «медленно на моём входе» и «квадрат от n». Не оптимизируйте константу, оставив квадратичную идею на n = 10⁶.

## Практика

### Задание 1. Два вложенных цикла

Список длины n, для каждого i проход по всему списку. Как растёт число сравнений при n = 10, 100, 1000? Это время или память?

### Задание 2. Дубликат

Опишите способ А и способ Б на `[3, 1, 4, 1]`. Где платит память Б? Когда на крошечном n вы всё равно возьмёте А и не соврёте?

### Задание 3. Худший случай

Линейный поиск `7` в массиве. Придумайте лучший и худший входы одной длины. Почему в паспорте алгоритма пишут худший?

### Задание 4. Амортизация

Массив, который при переполнении копируют в буфер вдвое больше. Почему *средняя* цена `append` ближе к константе, хотя редкий шаг линейный?

Дальше запись роста одной буквой: **O-нотация**.
