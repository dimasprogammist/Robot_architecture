# Поиск

Линейный поиск смотрит элементы по очереди — O(n), любой список. Бинарный требует порядка: делит диапазон пополам — O(log n) сравнений. Сортировка заранее O(n log n) окупается, если запросов много. Один запрос на хаосе — линейный или множество (принадлежность без индекса).

Границы `lo`/`hi` легко запороть. Инвариант: если ответ есть, он в отрезке lo..hi включительно. `mid = (lo + hi) // 2`. Меньше цели — `lo = mid + 1`. Больше — `hi = mid - 1`. Равно — нашли. `lo > hi` — нет. Нижняя граница в расширенной постановке — первый индекс, где значение ≥ target; верхняя — первый > target. Обобщение: монотонный предикат «первое true».

Отсортированный `[1, 3, 4, 7, 9, 11, 15, 18]`, цель 15:

1. lo=0, hi=7, mid=3 → 7 < 15 → lo=4
2. mid=5 → 11 < 15 → lo=6
3. mid=6 → 15, индекс 6

Цель 8: уезжает lo за hi, ответ −1.

```python
def linear_search(a: list[int], target: int) -> int:
    for i, x in enumerate(a):
        if x == target:
            return i
    return -1


def binary_search(a: list[int], target: int) -> int:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1


data = [1, 3, 4, 7, 9, 11, 15, 18]
assert binary_search(data, 15) == 6
assert binary_search(data, 8) == -1
```

Бинарный на неотсортированном массиве не «медленный» — он неверный. Пустой массив: сразу lo=0, hi=−1.
