# Хеш-таблица

Массив ищет по номеру, список — проходом. Часто нужен «этот ключ → значение» без полного скана. **Хеш-таблица** считает по ключу целое, берёт **корзину**, кладёт пару туда. В среднем вставка и поиск **O(1)**.

Идеал редко: два ключа попадают в одну корзину — **коллизия**. Тогда цепочка или открытая адресация. Худший случай (все в одной корзине) как список, O(n). Практический контракт Python `dict`/`set`: средний O(1), не гарантия худшего.

Ключ должен быть хешируемым и не меняться, пока лежит в таблице. `list` ключом быть не может: он изменяемый. Своим классом, если испортить `__hash__` после вставки, сломаете поиск.

Поток частот `[2, 7, 2, 9, 7, 2, 1, 9]`:

```text
2 → {2:1}
7 → {2:1, 7:1}
2 → {2:2, 7:1}
…
итог {2:3, 7:2, 9:2, 1:1}
запрос «двоек» — один доступ по ключу
```

Задача «два числа с суммой target»: помните в словаре, какой индекс ждал дополнение. Один проход vs двойной цикл.

Таблица растёт — **rehash**, редкий дорогой шаг; амортизированно вставки остаются дешёвыми. Коэффициент заполнения держат умеренным.

Не ставьте dict там, где ключ — индекс 0..n−1: массив проще. Не ждите O(1) «навсегда» в доказательстве худшего случая без оговорок.
