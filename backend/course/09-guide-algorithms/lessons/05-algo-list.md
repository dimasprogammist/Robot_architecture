# Связный список

Массив даёт номер за O(1) и карает сдвигом за вставку. **Связный список** меняет счета: каждый **узел** хранит значение и ссылку на следующего. Непрерывного блока нет. До k-го элемента идут k шагов — доступ по индексу **O(n)**.

Зато вставка после **известного** узла — две ссылки, хвост значений не двигают.

```text
10 → 20 → 30 → 40 → 50 → 60
вставить 25 после 20:
  создать узел 25
  25.next = 20.next   (на 30)
  20.next = 25
10 → 20 → 25 → 30 → 40 → 50 → 60
```

Если сначала сделать `20.next = 25`, а потом потерять старый next — хвост от 30 отвалится. Порядок присваиваний — единственное, что держит цепочку.

**Голова** — первый узел. Без неё список потерян. **Хвост** иногда хранят явно, чтобы добавлять в конец за O(1). Удаление значения: найти предыдущего, переставить `prev.next`. Удаление головы — отдельная ветка: новая голова это бывший второй.

Двусвязный узел помнит ещё предыдущего: проще идти назад и снимать «текущий». Плата — память и аккуратность двух ссылок.

```python
class Node:
    def __init__(self, value: int, next: "Node | None" = None):
        self.value = value
        self.next = next


def insert_after(node: Node, value: int) -> None:
    node.next = Node(value, node.next)
```

В проде на Python чаще `list` или `deque`. Модель узлов нужна, чтобы понимать указатели, LRU, стек/очередь «на ссылках» и код на C++.

Циклическая ссылка + обход без счётчика — вечный цикл. Ожидать O(1) от «тысячный элемент» — путать со массивом.
