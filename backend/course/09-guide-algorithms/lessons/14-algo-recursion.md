# Рекурсия

Рекурсия — задача через меньшую версию себя. Нужны **база** (ответ без нового вызова) и **движение к базе** (аргумент меньше или части строго меньше). Каждый вызов кладёт кадр на стек: локальные переменные и адрес возврата. В CPython глубина часто около 1000; глубокие структуры обходят итеративно или лимит поднимают осознанно. Хвостовая рекурсия в Python в цикл не схлопывается.

Наивный Фибоначчи двумя вызовами — антипример: дерево вызовов экспоненциально из-за одних и тех же подзадач. Мемоизация (кэш ответов) или цикл лечат. Обход дерева и divide-and-conquer в сортировках — уместные места.

Пока погружение — стек растёт. База сработала — кадры сворачиваются вверх. `RecursionError`: нет базы, база недостижима, или глубина больше структуры.

Сумма `[4, 1, 7, 3, 9, 2]`:

```text
sum([4,1,7,...]) = 4 + sum([1,7,...]) = ... = 4+1+7+3+9+2
```

База — пустой список даёт 0. Каждый шаг короче на один элемент.

```python
def rec_sum(xs: list[int]) -> int:
    if not xs:
        return 0
    return xs[0] + rec_sum(xs[1:])


assert rec_sum([4, 1, 7, 3, 9, 2]) == 26
```

На длинном списке этот вариант ещё и копиями хвоста дорог; учебный, не прод. Итерация с аккумулятором честнее по памяти.

## Практика

### Задание 1. База

Факториал без `if n == 0`. Что произойдёт? Напишите базу и шаг к ней.

### Задание 2. Фибоначчи

Нарисуйте дерево вызовов `fib(5)` наивно. Сколько раз считают `fib(2)`? Зачем кэш?

### Задание 3. Список

`rec_sum` на списке из 2000 элементов в CPython. Почему упадёт и как переписать циклом?

### Задание 4. Дерево

Почему обход дерева рекурсией естественен, а обход «списка как цепочки» на миллионе узлов — нет?
