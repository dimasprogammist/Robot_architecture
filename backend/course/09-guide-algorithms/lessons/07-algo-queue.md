# Очередь

Стек снимал последнее. **Очередь** снимает **первое**: как касса, FIFO. Новых кладут в хвост (`enqueue`), забирают с головы (`dequeue`). Иногда смотрят голову, не удаляя (`peek`). Пустой dequeue — ошибка контракта, как пустой pop у стека.

Почему не `list.pop(0)`. Массив сдвинет все оставшиеся элементы — O(n) на каждое изъятие. Сто тысяч событий так не живут. Берут кольцевой буфер, двусвязный список или `collections.deque`: концы дешёвые.

```text
enqueue 4, 1, 7, 3, 9, 2
голова 4 … хвост 2

dequeue → 4   осталось 1, 7, 3, 9, 2
dequeue → 1
dequeue → 7   осталось 3, 9, 2
```

Порядок выхода префикса совпал с входом. Это всё, что абстракция обещает; как внутри уложены байты — деталь реализации.

```python
from collections import deque


def demo() -> None:
    q: deque[int] = deque()
    for x in [4, 1, 7, 3, 9, 2]:
        q.append(x)
    out = [q.popleft() for _ in range(3)]
    assert out == [4, 1, 7]
    assert list(q) == [3, 9, 2]


demo()
```

Смысловой, но медленный двойник: `append` + `pop(0)`. На больших n деградирует.

Зачем FIFO в алгоритмах. Обход в ширину идёт волнами: сначала соседи старта, потом их соседи. Очередь как раз хранит «кого посетить на текущей волне». Стек даст глубину — другой порядок и другие свойства пути. Буфер задач и сообщения брокера — та же дисциплина: кто раньше пришёл, того раньше обработать (пока нет приоритета — тогда куча).

Учебный приём «очередь на двух стеках»: входящий стек копит enqueue, при dequeue перекладывают на исходящий. Амортизированно часто O(1), если не перекладывать каждый раз по одному. Имеет смысл как упражнение, в проде берут `deque`.

В этом уроке модель однопоточная. Блокирующие очереди между потоками — другой контракт.
