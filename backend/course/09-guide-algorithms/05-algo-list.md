# Связный список

## Цель

Увидеть, чем связный список отличается от массива: быстрые вставки при известном узле ценой медленного доступа по номеру позиции.

## Что уже нужно знать

Массив и его сложности, идея ссылки «узел знает следующего», O-нотация.

## Объяснение с нуля

В односвязном списке каждый узел хранит значение и ссылку на следующий. Нет непрерывного блока в памяти: чтобы дойти до k-го элемента, идут от головы k шагов — доступ по индексу O(n).

Зато вставка после известного узла — переписать пару ссылок, без сдвига хвоста значений. Удаление — тоже при известном предыдущем узле. Двусвязный список помнит ещё и предыдущего: удобнее удалять «текущий» и идти назад. Плата — лишняя память на ссылку и аккуратность при обновлении связей.

В чистом Python учебный список узлов пишут классами; в проде чаще `list` или `deque`. Но модель связного списка нужна для понимания стека, очереди, LRU-кэша и работы с указателями в других языках.

## Термины

- **Узел (node)** — значение плюс ссылка (или ссылки).
- **Голова (head)** — первый узел.
- **Хвост (tail)** — последний узел (иногда хранят явно для O(1) добавления в конец).
- **Разрыв ссылки** — потеря доступа к части списка при неверном порядке присваиваний.

## Внутреннее устройство

Цепочка: `head -> node -> node -> ... -> None`. Операции:

- пройти до позиции k — O(k);
- вставить после известного узла — O(1) на ссылки;
- найти значение — O(n) в худшем случае.

Порядок обновления ссылок при вставке критичен: сначала новый узел должен указать на старый next, потом предыдущий — на новый. Иначе потеряете хвост.

## Пример: вставка после узла

Список: `10 -> 20 -> 30 -> 40 -> 50 -> 60`. Вставить `25` после `20`.

### Пошаговый разбор

1. Создаём узел со значением 25.
2. `25.next = 20.next` (указывает на 30).
3. `20.next = 25`.
4. Получаем `10 -> 20 -> 25 -> 30 -> 40 -> 50 -> 60`.

Сдвигов значений нет — только ссылки. Но чтобы найти узел 20, имея только голову, всё равно нужен проход O(n).

### Код на Python

```python
class Node:
    def __init__(self, value: int, next: "Node | None" = None):
        self.value = value
        self.next = next


def to_list(head: Node | None) -> list[int]:
    out: list[int] = []
    cur = head
    while cur is not None:
        out.append(cur.value)
        cur = cur.next
    return out


def insert_after(node: Node, value: int) -> None:
    node.next = Node(value, node.next)


head = Node(10, Node(20, Node(30, Node(40, Node(50, Node(60))))))
insert_after(head.next, 25)  # после 20
assert to_list(head) == [10, 20, 25, 30, 40, 50, 60]
```

### Сложность

- Доступ по индексу: O(n).
- Вставка/удаление при известном месте: O(1) на перестановку ссылок.
- Поиск по значению: O(n).
- Память: O(n) узлов плюс накладные расходы на ссылки.

## Практика

Удалите первый узел со значением 40: найдите предыдущий, переставьте `prev.next`. Пройдите руками на списке из шести чисел выше.

## Типичные ошибки

- Переписать ссылки в неверном порядке и потерять хвост.
- Забыть обновлять `tail` при добавлении в конец.
- Ожидать O(1) от «взять 1000-й элемент».
- Создать циклическую ссылку и словить бесконечный обход.
- Путать учебный linked list с `list` в Python.

## Что запомнить

Список: O(n) доступ по индексу, O(1) вставка при известном месте. Массив — наоборот по доступу. Выбирайте структуру под доминирующие операции.
