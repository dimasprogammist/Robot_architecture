# Что такое алгоритм

## Цель

Научиться отличать алгоритм от «просто кода» и от расплывчатой идеи в голове. После урока вы сможете разобрать задачу на вход, выход и шаги, проверить, что решение заканчивается, и объяснить, почему оно даёт нужный ответ.

## Что уже нужно знать

Базовый Python: переменные, циклы `for`/`while`, функции, списки. Достаточно уметь мысленно подставить значения в переменные и пройти цикл руками. Специальные структуры данных пока не нужны — их разберём дальше.

## Объяснение с нуля

Алгоритм — это точный план: какие действия выполнить, в каком порядке и на каких данных, чтобы получить результат. План должен быть конечным (не крутиться вечно без причины), определённым (на каждом шаге ясно, что делать дальше) и результативным (даёт ответ или явно говорит, что ответа нет).

Программа — это запись алгоритма на языке, который понимает машина. Один и тот же алгоритм можно записать на Python, C++ или псевдокоде: идея шагов не меняется. Наоборот, один файл `.py` может реализовывать разные алгоритмы, если вы поменяете порядок сравнений или способ хранения.

Зачем отделять «алгоритм» от «синтаксиса»: когда программа тормозит или ломается на краю, вы ищете не «не тот отступ», а «не тот способ решения». Сортировка пузырьком и быстрая сортировка — разные алгоритмы с разной ценой по времени; оба могут быть написаны аккуратно.

Алгоритм всегда работает на модели данных. Для массива чисел шаги одни, для графа маршрутов — другие. Поэтому сначала фиксируют вход и ограничения, потом шаги, потом цену шагов. Эвристика «попробуй так, если не вышло — иначе» без гарантии завершения полезна в инженерии, но это уже другой класс методов: нужно понимать, где гарантия, а где надежда.

## Термины

- **Вход** — данные, которые алгоритм получает до старта.
- **Выход** — результат или статус «не найдено».
- **Шаг** — элементарное действие: сравнение, присвоение, чтение элемента.
- **Корректность** — для всех допустимых входов выход соответствует постановке.
- **Завершаемость** — на допустимых входах нет бесконечного цикла.
- **Инвариант** — утверждение, которое остаётся истинным на каждом витке цикла и помогает доказать правильность.

## Внутреннее устройство разбора задачи

Удобная схема из четырёх слоёв:

1. **Постановка.** Что на входе? Что на выходе? Какие края: пустой список, один элемент, все элементы равны?
2. **Идея.** Одним предложением: «проходим слева направо и помним минимум».
3. **Ручной проход.** Берёте 5–8 элементов и записываете состояние после каждого шага.
4. **Код и проверка.** Пишете функцию, гоняете те же примеры и ещё пару краевых.

Без третьего слоя легко написать код, который «кажется правильным», но ломается на дубликатах или пустом входе.

## Пример: поиск минимума

Задача: найти наименьшее число в непустом списке. Вход: `[7, 2, 9, 2, 5]`.

Идея: запомнить первый элемент как кандидата в минимум, сравнить с каждым следующим; если встретили меньше — обновить кандидата.

### Пошаговый разбор

1. Старт: `min_val = 7` (первый элемент).
2. Смотрим `2`: `2 < 7` → `min_val = 2`.
3. Смотрим `9`: `9 < 2`? Нет.
4. Смотрим `2`: `2 < 2`? Нет.
5. Смотрим `5`: `5 < 2`? Нет.
6. Ответ: `2`.

Инвариант цикла: «`min_val` — минимум уже просмотренного префикса». В конце префикс равен всему массиву, значит ответ корректен для непустого списка.

### Код на Python

```python
def find_min(nums: list[int]) -> int:
    if not nums:
        raise ValueError("пустой список: минимума нет")
    min_val = nums[0]
    for x in nums[1:]:
        if x < min_val:
            min_val = x
    return min_val


assert find_min([7, 2, 9, 2, 5]) == 2
assert find_min([3]) == 3
```

### Сложность

Один проход по списку длины `n`: число сравнений растёт линейно. Пишем это как O(n) по времени и O(1) дополнительной памяти. Точный смысл O(...) — в следующих уроках; сейчас важно, что цена предсказуемо зависит от размера входа.

## Практика

Сформулируйте вслух алгоритм проверки «есть ли в списке хотя бы одно чётное число»: вход, выход, идея, края. Не пишите код, пока не проговорите шаги на `[1, 3, 4, 7]`.

## Типичные ошибки

- Называть алгоритмом кашу из `if` без ясного входа и выхода.
- Путать «сработало на моём примере» и «верно на всех допустимых входах».
- Забывать пустой вход, один элемент, дубликаты.
- Полировать синтаксис, не меняя идею, и удивляться той же медленности.
- Считать, что встроенный `min()` — «не алгоритм». Это алгоритм, уже реализованный в библиотеке.

## Что запомнить

Алгоритм — конечный определённый план от входа к выходу. Программа — его запись. Разбор: постановка → идея → ручной проход → код. Инварианты помогают не гадать.
