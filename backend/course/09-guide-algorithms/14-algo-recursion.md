# Рекурсия

## Цель

Научиться писать рекурсивные функции с базовым случаем и схемой «задача → меньшие подзадачи», понимая стек вызовов и риск переполнения.

## Что уже нужно знать

Функции, стек как структура, деревья и списки как примеры рекурсивных данных.

## Объяснение с нуля

Рекурсия — определение через меньшую версию той же задачи. Обязательны два элемента: **базовый случай** (ответ без нового вызова) и **движение к базе** (аргумент уменьшается или задача дробится на строго меньшие части).

Каждый вызов кладёт кадр на стек: локальные переменные и адрес возврата. Глубина рекурсии ограничена (в CPython часто около 1000 по умолчанию). Глубокие структуры лучше обходить итеративно или увеличивать лимит осознанно. Хвостовая рекурсия в Python не оптимизируется в цикл — не ждите этого от интерпретатора.

Классика: факториал, обход дерева, divide-and-conquer в сортировках. Наивный Фибоначчи через два рекурсивных вызова — учебный антипример: дерево вызовов растёт экспоненциально из-за повторяющихся подзадач.

## Термины

- **Базовый случай** — условие остановки.
- **Рекурсивный случай** — вызов себя.
- **Дерево рекурсии** — картина вложенных вызовов.
- **Мемоизация** — кэш ответов подзадач, чтобы не считать повторно.

## Внутреннее устройство

Пока идёт погружение, стек растёт. Когда срабатывает база, кадры начинают сворачиваться и возвращают значения вверх. Ошибка RecursionError почти всегда значит: нет базы, база недостижима или глубина слишком велика для структуры данных.

## Пример: сумма списка

Список: `[4, 1, 7, 3, 9, 2]`.

### Пошаговый разбор

```text
sum([4,1,7,3,9,2]) = 4 + sum([1,7,3,9,2])
                   = 4 + 1 + sum([7,3,9,2])
                   = ...
                   = 4+1+7+3+9+2 + sum([])
sum([]) = 0
```

Стек вырастает примерно до семи кадров, затем сворачивается. Итеративный цикл здесь проще и дешевле — рекурсия для ясности идеи.

### Код на Python

```python
def list_sum(xs: list[int]) -> int:
    if not xs:
        return 0
    return xs[0] + list_sum(xs[1:])


assert list_sum([4, 1, 7, 3, 9, 2]) == 26


def list_sum_idx(xs: list[int], i: int = 0) -> int:
    if i >= len(xs):
        return 0
    return xs[i] + list_sum_idx(xs, i + 1)


assert list_sum_idx([4, 1, 7, 3, 9, 2]) == 26
```

Вариант с индексом не копирует хвост на каждом шаге — это важно на больших списках.

### Сложность

Для суммы: время O(n), память стека O(n). Наивный Фибоначчи: время порядка φⁿ — неприемлемо уже на средних n.

## Практика

Нарисуйте дерево рекурсии для `fib(5)` наивной реализации. Сколько раз считается `fib(2)`?

## Типичные ошибки

- Нет базового случая → RecursionError.
- База есть, но аргумент не уменьшается.
- Наивный Фибоначчи на n = 40 «навсегда».
- Резать список через `xs[1:]` в горячем пути без нужды.

## Что запомнить

Рекурсия = база + меньшая подзадача + стек. Думайте о глубине и о дублировании подзадач.
