# Аргументы — как shell собирает argv

## Цель

Разобрать, как кавычки, пробелы, glob и переменные влияют на массив аргументов, который видит программа. Научиться передавать сложные строки без сюрпризов.

## Исходные знания

Потоки stdin/stdout/stderr и базовый запуск команд. Понимание, что программа получает не «одну строку целиком», а список аргументов.

## Объяснение

Программа получает массив строк argv. Границы элементов определяет shell на этапе разбора. Пробел вне кавычек — разделитель. Файл `мой отчёт.txt` нужно передавать как один аргумент: в кавычках или с экранированием. Иначе программа увидит два операнда.

В bash одинарные кавычки сохраняют текст почти буквально. Двойные позволяют подстановку переменных. `$()` подставляет вывод команды. Ошибка новичка — закавычить так, что переменная перестаёт раскрываться, или наоборот оставить путь с пробелом без кавычек.

Glob (`*.log`) раскрывает shell до запуска, если шаблон совпал с именами. Программа часто вообще не видит звёздочку — она получает уже список имён. Если совпадений нет, поведение зависит от настроек shell.

Многие утилиты трактуют `--` как конец опций. Это спасает, когда имя файла начинается с дефиса: иначе `-weird` выглядит как флаг.

В PowerShell правила другие: именованные параметры, разбор типов, иные нюансы quoting при вызове внешних программ. Не копируйте bash-кавычки в PowerShell слепо.

Word splitting в bash — отдельная ловушка: незакавыченная переменная с пробелами может превратиться в несколько аргументов. Правило гигиены: `"$var"` для путей и строк с пробелами.

Отладка аргументов проще, чем кажется: маленькая программа, печатающая sys.argv, сразу показывает, что реально пришло после разбора shell.

Безопасность: не собирайте команду как строку с недоверенными данными через `eval`. Передавайте список аргументов API процесса, когда язык это позволяет.

## Термины

**argv** — массив аргументов процесса; нулевой элемент обычно имя программы.

**Quoting** — кавычки и экранирование, управляющие разбором токенов.

**Glob** — раскрытие шаблонов имён файлов оболочкой.

**`--`** — маркер конца опций у многих CLI-утилит.

**Word splitting** — разбиение результата подстановок по пробельным символам в bash.

## Как это работает

Упрощённый порядок в bash: токенизация → некоторые раскрытия → параметры и подстановки → word splitting → glob → снятие кавычек. Из-за порядка `"$file"` защищает пробелы, а незакавыченный `$file` — нет.

Shell не «угадывает» смысл `-n`. Он только формирует argv. Уже `rm`, `ls` или ваш скрипт решают, что делать с каждым элементом.

Когда вы пишете `cmd $a $b`, число аргументов зависит от содержимого переменных. Когда пишете `cmd "$a" "$b"`, число аргументов стабильнее.

## Пример

```bash
touch "my file.txt"
ls -l "my file.txt"

python -c 'import sys; print(sys.argv)' -- -n "a b" "$HOME"

touch -- -n
rm -- -n

echo *.txt
```

## Разбор

`touch` с кавычками создаёт одно имя. Без кавычек получились бы два файла.

Python печатает массив: видно, как `-n` и `a b` раскладываются по элементам.

`rm -- -n` удаляет файл по имени `-n`, не включая странный режим опций.

`echo *.txt` часто показывает уже раскрытый список, а не буквальную звёздочку.

## Ошибки

- Не закавычивать переменные с путями.
- Ждать, что программа сама увидит `*.txt`.
- Копировать quoting между bash и PowerShell без адаптации.
- Кормить `eval` пользовательским вводом.

## Что запомнить

- Границы argv задаёт shell.
- Кавычки — инструмент точности.
- `--` отделяет опции от имён с дефисом.
- Для отладки печатайте argv явно.

## Практика

Создайте файл с пробелом в имени и скопируйте его одной командой так, чтобы аргументов-путей было ровно два. Проверьте через печать argv, что массив не распался.

Правило гигиены bash: все расширения переменных с путями — в кавычках. Исключения должны быть осознанными (да, иногда нужен splitting, но редко).

Массивы bash с элементами в кавычках и раскрытием вида "${arr[@]}" безопаснее для списка аргументов, чем одна строка с пробелами.

В Python передавайте список в `subprocess.run([...])`, не `shell=True`, когда аргументы приходят извне.

Имена файлов с ведущим дефисом встречаются реже, чем думают, но ломают скрипты внезапно. Привыкайте к `--` в обёртках удаления и копирования.
