# Пути — как система именует файлы

## Цель

Понять путь как строку маршрута в дереве каталогов: разделители, текущий каталог процесса, ссылки и различия POSIX и Windows.

## Исходные знания

Умение передавать имена файлов аргументами. Понимание, что у процесса shell есть текущий каталог.

## Объяснение

Файл в ОС адресуется через иерархию каталогов. Путь — текстовый маршрут: последовательность имён, разделённых разделителем. В POSIX разделитель — `/`, корень — `/`. В Windows традиционно обратный слэш и буквы дисков, хотя многие API принимают и `/`.

Текущий рабочий каталог (cwd) — свойство процесса. Относительные имена интерпретируются от cwd. Одна и та же команда `cat notes.txt` читает разные файлы в разных каталогах. Prompt часто показывает cwd для ориентации, но это лишь удобство интерфейса.

Специальные компоненты: `.` — текущий каталог, `..` — родитель. Логическое и физическое разрешение путей могут различаться, если есть символические ссылки. `pwd -L` и `pwd -P` показывают эту разницу на многих системах.

Символическая ссылка — файл-указатель на другой путь. Права и «где лежит файл на диске» нужно проверять осознанно. Путь может пройти через ярлык, и итоговый inode будет в другом месте дерева.

Регистр имён — частый сюрприз. На типичных Linux-файловых системах `A` и `a` — разные имена. На Windows часто нет. Деплой с ноутбука на сервер ломается именно на этом.

Длина пути, кодировка Unicode и «невидимые» символы при копировании из GUI тоже ломают команды. Путь должен быть тем, что реально видит API open, а не тем, что красиво выглядит в проводнике.

Shell работает с путями при glob и `cd`, но после запуска уже программа вызывает open/read. Путаница «shell не находит» и «программа не находит» решается проверкой cwd и абсолютного пути.

## Термины

**Путь** — строка, задающая место файла или каталога в иерархии.

**cwd** — current working directory процесса.

**Разделитель** — `/` в POSIX; `\` или `/` в Windows API.

**Symlink** — символическая ссылка на другой путь.

**Нормализация** — упрощение пути (лишние `/`, `.`, иногда `..`).

## Как это работает

Когда программа вызывает open с относительным путём, ядро через VFS разбирает компоненты относительно cwd процесса. Если путь начинается с корня, отсчёт от корня. Каждый компонент — поиск имени в каталоге.

Склейка путей вручную через конкатенацию строк хрупка. Библиотеки вроде pathlib знают правила платформы и уменьшают ошибки с лишними разделителями.

Переносимые скрипты хранят логические пути проекта относительно корня репозитория и вычисляют абсолютные во время выполнения.

## Пример

```bash
pwd
ls .
ls ..

python -c "from pathlib import Path; print(Path('docs') / 'a.txt')"

ls -l /etc 2>/dev/null | head
```

## Разбор

`pwd` печатает cwd shell. `ls .` и `ls ..` показывают навигацию без смены каталога.

`pathlib` склеивает компоненты правильно для платформы.

Чтение под `/etc` — пример абсолютного маршрута от корня, не зависящего от того, где вы стоите.

## Ошибки

- Хардкодить `C:\...` в скриптах для Linux-контейнера.
- Путать путь через symlink с реальным расположением.
- Считать регистр неважным на сервере Linux.
- Копировать путь из GUI с кавычками-ёлочками и невидимыми символами.

## Что запомнить

- Путь интерпретируется от cwd или от корня.
- `.` и `..` — компоненты маршрута, не команды.
- POSIX и Windows различаются корнем и разделителями.
- Для склейки путей используйте библиотеки.

## Задание

Из домашнего каталога дойдите до временного каталога только относительными шагами, затем одним абсолютным путём вернитесь. На каждом шаге смотрите `pwd`.

## Дополнение: практика и нюансы

Нормализация пути не всегда сохраняет смысл на symlink-системах. Если важна физическая локация — резолвите явно.

Сетевые ФС и bind-mount в контейнерах меняют «где лежит файл» относительно ожидания разработчика. Печатайте `readlink -f` в логах старта службы.

Длинные пути и не-ASCII имена проверяйте на целевой ФС. Не все носители одинаковы.

В конфигах предпочитайте прямые слэши или API путей языка — особенно в кроссплатформенных репозиториях.


Убедитесь, что время хоста синхронизировано: ложные ошибки TLS и путаница в логах часто из-за часов.

Проверьте лимиты файловых дескрипторов у процесса, если странно падают долгие сервисы под нагрузкой.
