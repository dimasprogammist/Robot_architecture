# Поиск: find и grep

## Цель

Научиться находить файлы по имени и расположению, а также искать нужный текст внутри файлов — и понимать, почему связка этих двух разных инструментов через конвейер решает большинство реальных задач поиска.

## Исходные знания

Пути, базовая работа с файлами и каталогами, идея конвейера как способа передать результат одной команды другой (мы вернёмся к конвейеру подробнее в следующем уроке — здесь достаточно общей идеи).

## Объяснение

Поиск в командной строке распадается на два принципиально разных вопроса, и для каждого есть свой инструмент. Первый вопрос — «**где** находится файл с таким-то именем или свойствами» — на него отвечает команда обхода дерева каталогов: она проходит по всем файлам и подкаталогам начиная с указанного места и для каждого проверяет условия, которые вы задали — имя, тип (файл или каталог), время изменения, размер. Это обычная пользовательская программа, а не отдельная служба, вечно работающая в фоне: она в реальном времени обходит файловую систему прямо во время своей работы.

Второй вопрос — «**что** находится внутри файла» — на него отвечает инструмент поиска текста по образцу: он читает содержимое файла (или потока) строка за строкой и печатает те строки, которые совпали с заданным образцом.

```text
   Нужно найти файл по имени
          ↓
   обход каталогов
          ↓
   нашли путь к файлу

   Нужно найти текст внутри файла
          ↓
   построчный поиск по содержимому
          ↓
   нашли совпадающие строки
```

По-настоящему сильной эта пара инструментов становится, когда их соединяют: сначала найти, **где** искать, а затем передать эти места второму инструменту, чтобы проверить, **что** там внутри. Например, найти все файлы с определённым расширением в каталоге проекта, а затем среди них поискать строки, содержащие конкретное слово. Именно так командная строка решает задачи, для которых в графическом интерфейсе пришлось бы открывать десятки файлов по одному.

Полезно сразу привыкнуть к небольшому, но практичному синтаксису поиска по образцу: простые текстовые шаблоны ищут буквальное совпадение, а более сложные правила с подстановочными символами (специальный язык описания шаблонов текста, называемый регулярными выражениями) позволяют искать не точную строку, а некоторый класс строк — например, «любая строка, начинающаяся с цифры». Это уже отдельная большая тема, которую полезно изучить позже, но для начала вполне достаточно простого поиска буквального текста без специальных символов.

## Термины

**Обход дерева каталогов** — последовательный проход по всем файлам и подкаталогам, начиная с заданного места.

**Образец (паттерн)** — текст или правило, с которым сравнивается содержимое при поиске.

**Регулярное выражение** — более гибкий язык описания образца, позволяющий искать не только буквальный текст, но и классы строк.

## Пример

```bash
find /tmp -maxdepth 1 -type f

find . -name "*.log"

grep -n "error" /tmp/example.log

find . -name "*.log" | xargs grep -l "error"
```

Первая команда перечисляет обычные файлы прямо в `/tmp`, не опускаясь глубже на один уровень. Вторая ищет по всему текущему дереву файлы с расширением `.log`, независимо от того, в каком подкаталоге они лежат. Третья показывает номера строк, в которых встретилось слово «error», в конкретном файле. Последняя команда — пример связки двух инструментов: сначала найти все лог-файлы, а затем передать каждый найденный путь на проверку, есть ли в нём слово «error», и показать только имена подходящих файлов.

## Ошибки

Частая ошибка новичка — пытаться искать текст той же командой, что ищет файлы по имени: это разные задачи и разные инструменты. Вторая — забывать об ограничении глубины обхода там, где оно нужно, и получать неожиданно длинный список файлов из глубоко вложенных подкаталогов. Третья — пытаться с ходу писать сложные регулярные выражения, хотя подавляющее большинство повседневных задач решается простым поиском буквального текста.

## Что нужно запомнить

Поиск файлов по имени и расположению и поиск текста внутри файлов — две разные задачи с двумя разными инструментами. Обход каталогов отвечает на вопрос «где», построчный поиск по содержимому — на вопрос «что внутри». Их комбинация через передачу результата одного инструмента другому покрывает большинство практических задач поиска, а регулярные выражения — это следующий, более продвинутый уровень того же инструмента поиска по содержимому.

## Практика

В каталоге своего учебного проекта найдите все файлы с определённым расширением (например, все текстовые или все файлы с логами). Затем среди найденных файлов найдите те, которые содержат конкретное слово, и выведите только их имена, а не все совпавшие строки.

## Связь дальше

Мы научились находить файлы и текст. Теперь вернёмся к тому, как результат одной команды передать на вход другой, и разберём механизм конвейера подробно.
