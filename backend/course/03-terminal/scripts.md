# Скрипты оболочки

## Цель

Научиться оформлять повторяемые действия как скрипт: shebang, права на исполнение, аргументы, строгий режим и типичные ловушки путей.

## Исходные знания

Команды shell, аргументы, окружение и коды возврата. Умение писать несколько команд подряд вручную.

## Объяснение

Скрипт оболочки — текстовый файл с командами для интерпретатора. Вместо того чтобы каждый раз набирать одну и ту же цепочку, вы сохраняете её и запускаете как программу. Это основа автоматизации на серверах: бэкапы, проверки здоровья, обёртки деплоя.

Shebang в первой строке (`#!/usr/bin/env bash`) говорит ядру, каким интерпретатором запускать файл при исполнении. `env` ищет `bash` через PATH — удобнее жёсткого `/bin/bash` на системах, где bash лежит иначе. Если запускать `bash script.sh`, shebang не обязателен, но для `./script.sh` он важен.

Права execute нужны, чтобы запускать файл по имени пути. Без них остаётся только явный вызов интерпретатора. На FAT/NTFS-монтированиях биты прав могут вести себя иначе — ещё одна причина тестировать на целевой системе.

Аргументы скрипта доступны как `$1`, `$2`, `$@`. Их нужно закавычивать. Сдвиг `shift` помогает разбирать опции. Для серьёзного разбора иногда берут `getopts`.

Строгий режим `set -euo pipefail` в bash резко снижает число «тихих» ошибок: выход при неуспехе, ошибка на неинициализированных переменных, учёт стадий pipe. У режима есть тонкости с условиями; тем не менее для служебных скриптов он почти стандарт.

Скрипт наследует окружение вызывающего. В cron окружение бедное — задавайте PATH явно. Считайте cwd враждебным: вычисляйте базу от расположения скрипта.

Не превращайте shell-скрипт в большую программу со сложной логикой. Когда появляются структуры данных и серьёзная обработка ошибок, лучше Python или другой язык, а shell оставить клеем.

## Термины

**Shebang** — первая строка `#!`, указывающая интерпретатор.

**Исполняемый бит** — право запуска файла как программы.

**`$1`…`$@`** — позиционные параметры скрипта.

**Строгий режим** — набор опций shell, делающих ошибки явными.

**Обёртка** — тонкий скрипт, который готовит окружение и вызывает основную программу.

## Как это работает

При `./script` ядро читает shebang, запускает указанный интерпретатор и передаёт путь скрипта аргументом. Интерпретатор читает файл построчно (с учётом конструкций) и выполняет команды так же, как в интерактиве, но без prompt.

Код возврата скрипта — статус последней выполненной команды или явного `exit`. CI смотрит именно на него.

Отладка: `bash -x script.sh` печатает команды по мере выполнения. Это быстрее гадания по симптомам.

## Пример

```bash
cat <<'EOF' > /tmp/hello.sh
#!/usr/bin/env bash
set -euo pipefail
name="${1:-world}"
echo "hello, $name"
EOF
chmod +x /tmp/hello.sh
/tmp/hello.sh
/tmp/hello.sh Ada
echo $?
```

## Разбор

Shebang выбирает bash через env. `set -euo pipefail` включает строгий режим.

`${1:-world}` подставляет аргумент или значение по умолчанию. Кавычки защищают пробелы.

После успешного запуска код возврата 0. Если заменить последнюю команду на `false`, скрипт завершится с ошибкой из-за `-e`.

## Ошибки

- Писать bash-синтаксис и запускать через `sh`.
- Забывать execute bit и shebang при `./`.
- Полагаться на cwd и интерактивный PATH.
- Растить скрипт до сотен строк сложной логики.

## Что запомнить

- Скрипт — файл команд для интерпретатора.
- Shebang и права нужны для прямого запуска.
- Строгий режим и кавычки — базовая гигиена.
- Shell хорош как клей, не как замена языка приложения.

## Задание

Напишите скрипт с двумя аргументами: исходный и целевой путь. Он должен проверить, что источник существует, скопировать файл и вернуть ненуль, если копирование не удалось. Прогоните успех и ошибку.

## Дополнение: практика и нюансы

Имена скриптов с расширением `.sh` удобны, но shebang важнее расширения. На Windows-клиентах следите за LF.

Входные аргументы валидируйте рано: число параметров, существование файлов, запрет пустых строк.

Пишите скрипты идемпотентными, где возможно: повторный запуск не должен ломать систему.

Тестируйте скрипт с `bash -n` (синтаксис) и прогоном на пустой/минимальной среде.

Итог раздела: закрепляйте механизм на практике, а не только синтаксис команд.
