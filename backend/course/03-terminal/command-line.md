# Командная строка: текст как интерфейс к системе

## Цель

Освоить модель CLI: команда, аргументы, опции, код возврата и поток текста. Научиться читать справку и отличать вывод «для человека» от вывода «для скрипта».

## Исходные знания

Понимание shell и терминала. Умение открыть сессию и выполнить простую команду вроде `pwd`.

## Объяснение

CLI — способ управлять компьютером текстом. В отличие от GUI, действие явно и воспроизводимо: ту же строку можно вставить в скрипт, в CI и в инструкцию. Цена — нужно выучить язык команд и читать ошибки текстом.

Типичная форма: команда, затем опции, затем позиционные аргументы. Опции часто начинаются с `-` или `--`. Аргументы — операнды: имена файлов, хосты, строки. Для shell это всё токены. Смысл «это флаг или имя файла» определяет уже сама программа после запуска.

Хороший CLI даёт человекочитаемый вывод по умолчанию и отдельный режим для машин: `--json`, `--porcelain`, тихий режим. Если парсить «красивую таблицу» регулярками, скрипт сломается при смене локали или ширины колонок. Для автоматизации ищите стабильный формат.

Справка — часть интерфейса. `command --help`, `man command`, в PowerShell `Get-Help`. В man-страницах читайте SYNOPSIS: квадратные скобки — опционально, многоточие — повтор, вертикальная черта — выбор.

Командная строка масштабируется: одна модель на ноутбуке и на сервере без монитора. Эксплуатация контейнеров и удалённых машин почти всегда опирается на CLI, даже если поверх есть веб-панель.

Код возврата — целое число, которым процесс сообщает итог. Ноль по соглашению означает успех. Ненулевые значения кодируют классы ошибок; точная таблица зависит от программы. Скрипты должны проверять код, а не только наличие текста на экране.

Интерактивность и автоматизация требуют разных привычек. Вручную вы смотрите цвета и таблицы. В скрипте вы хотите предсказуемые строки, явные флаги и отсутствие вопросов «нажмите Enter». Многие утилиты имеют ключ «не спрашивать» именно для этого.

## Термины

**CLI** — текстовый интерфейс запуска программ с аргументами и потоками.

**Опция (flag)** — именованный переключатель или параметр, обычно с `-`/`--`.

**Операнд** — позиционный аргумент: файл, URL, идентификатор.

**Код возврата** — целое число статуса завершения процесса.

**Porcelain** — стабильный машиночитаемый режим вывода (идея шире, чем один Git).

## Как это работает

Shell передаёт программе массив аргументов argv. Нулевой элемент — имя программы. Дальше — то, что осталось после разбора кавычек. Программа сама валидирует опции; shell не знает семантики `-l`.

Если программе нужен пароль, она может читать с управляющего терминала, а не из stdin, чтобы пароль не ушёл в pipe. Это снова про разделение потоков и TTY.

Сила CLI — композиция: вывод одной команды становится входом другой. Композиция работает, когда данные имеют понятный контракт (строки, CSV, JSON), а не только псевдографика для глаз.

## Пример

```bash
ls -lh /var/log

ls -1 /var/log

false
echo $?

# справка
ls --help | head
```

## Разбор

`ls -lh` удобен человеку: размеры «по-человечески». Для скрипта чаще нужен простой список или утилиты со стабильным форматом.

`false` только возвращает код 1. Её используют в условиях скриптов, чтобы проверить ветку «ошибка».

`$?` в bash — код возврата последней команды переднего плана. После успешной команды обычно 0.

## Ошибки

- Парсить цветной вывод `ls` в скриптах.
- Игнорировать код возврата и смотреть только текст в CI.
- Считать, что порядок опций везде свободный.
- Копировать GUI-инструкции вместо CLI на сервер.

## Что запомнить

- CLI = текст + аргументы + код возврата + потоки.
- Смысл опций задаёт программа; shell передаёт argv.
- Для автоматизации выбирайте стабильный формат вывода.
- Справка — первый инструмент изучения команды.

## Практика

Выберите три утилиты. Для каждой найдите help и выпишите одну опцию и один позиционный аргумент. Запустите команду с заведомо неверным аргументом и посмотрите код возврата.

Читая SYNOPSIS в man, обращайте внимание на взаимоисключающие опции и обязательные операнды. Если утилита принимает подкоманды (`git`, `ip`, `systemctl`), сначала выучите карту подкоманд, затем флаги.

Стабильный вывод для скриптов важнее красоты. Ищите `-0`, `--porcelain`, `--format`, JSON. Парсинг таблиц с пробелами хрупок.

Документируйте команды с полными именами опций в runbook (`--verbose` вместо `-v`), если команда это позволяет: так меньше двусмысленности через месяцы.

Код возврата проверяйте сразу: любая следующая команда, даже безобидный `echo`, перезапишет сохранённый статус в shell.
