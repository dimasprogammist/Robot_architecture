# Переменные окружения процесса

## Цель

Понять окружение как набор строк «имя=значение», наследуемый дочерними процессами. Научиться задавать переменные для одной команды и для сеанса.

## Исходные знания

Процесс shell, argv и наследование. Базовые команды в терминале.

## Объяснение

Окружение — список переменных, который процесс получает при старте и может менять у себя. Это не магия конфигурации всей ОС, а данные конкретного процесса. Дочерний процесс получает копию окружения родителя на момент запуска.

Типичные переменные: `PATH`, `HOME`, `USER`, `LANG`, `EDITOR`. Программы читают их через API окружения. Shell подставляет `$NAME` в командной строке — это уже раскрытие на этапе разбора.

Разница между переменной shell и переменной окружения важна. В bash `VAR=1` само по себе может остаться локальным для shell, пока вы не сделаете `export VAR`. Экспортированная переменная попадает в окружение потомков. Без export дочерняя программа её не увидит.

Запись `VAR=value команда` задаёт переменную только для одного запуска команды. Удобно для временного `PATH` или режима отладки без порчи сеанса.

Файлы профиля (`~/.bashrc`, `~/.profile` и аналоги) заполняют окружение интерактивных сеансов. Службы systemd, cron и CI часто получают другое, более бедное окружение. Отсюда классика: «у меня в терминале работает, а в cron нет» — другой PATH и другие переменные.

Секреты в окружении удобны, но видны в списке процессов и наследуются. Для чувствительных данных нужны более аккуратные механизмы, чем вечный `export PASSWORD=...` в профиле.

Имена переменных принято писать заглавными для экспортируемых настроек, но это соглашение, а не закон языка. Значения — строки; числа и пути тоже строки до тех пор, пока программа их не разберёт.

## Термины

**Окружение (environment)** — набор строк имя=значение у процесса.

**export** — пометить переменную shell для наследования потомками.

**PATH** — список каталогов поиска программ.

**Профиль shell** — скрипт, настраивающий интерактивный сеанс.

**Наследование** — копирование окружения от родителя к ребёнку при запуске.

## Как это работает

При exec ядро передаёт программе массив envp рядом с argv. Библиотека языка предоставляет getenv/setenv или аналоги. Изменения setenv влияют на текущий процесс и на будущих детей, но не на уже запущенных соседей и не на родителя.

Shell хранит собственную таблицу переменных. Export синхронизирует выбранные имена с envp, который уйдёт детям. Поэтому отладка «почему python не видит VAR» начинается с проверки export и способа запуска.

Подстановка `$VAR` делает shell до запуска. Сама программа может вообще не поддерживать синтаксис `$` — она получит уже готовое значение в argv или прочитает getenv сама.

## Пример

```bash
echo "$HOME"
echo "$PATH"

export GREETING=hello
python -c "import os; print(os.environ.get('GREETING'))"

LANG=C ls --help >/dev/null
echo $?

env | head
```

## Разбор

`HOME` и `PATH` почти всегда есть в интерактивной сессии. Они задают базу путей и поиск команд.

`export` делает `GREETING` видимым дочернему Python через os.environ.

`LANG=C команда` меняет локаль только для одного запуска — пример одноразового окружения.

`env` печатает текущее окружение процесса env (обычно унаследованное от shell).

## Ошибки

- Забыть `export` и удивляться, что дочерняя программа «не видит» переменную.
- Полагаться на интерактивный PATH в cron/systemd.
- Хранить секреты в `~/.bashrc` надолго.
- Путать подстановку shell `$VAR` с чтением окружения внутри программы.

## Что запомнить

- Окружение принадлежит процессу и копируется детям.
- export нужен, чтобы переменная shell стала частью envp.
- Префикс `VAR=value cmd` задаёт окружение на один запуск.
- Сервисы часто видят другое окружение, чем ваш терминал.

## Задание

Задайте переменную без export и с export, каждый раз запуская `python -c "import os; print(os.environ.get('MYVAR'))"`. Объясните разницу. Затем запустите команду с одноразовым префиксом переменной.

## Дополнение: практика и нюансы

`printenv`/`env` показывают окружение. Для конкретного PID — `tr '\0' '\n' < /proc/PID/environ`.

В systemd: `Environment=` и `EnvironmentFile=` (без export-синтаксиса). Кавычки и пробелы читайте в man systemd.exec.

Переменная `PATH` без `/usr/bin` в cron — классика. Задавайте PATH в начале crontab/скрипта.

Не храните долгоживущие секреты в `~/.bashrc`. Для CI — секреты движка CI; для сервера — файлы прав `600` или vault.
