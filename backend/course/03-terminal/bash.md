# Bash — практический язык оболочки

## Цель

Освоить ключевые конструкции Bash: переменные, условия, циклы, функции и подстановки. Понять, где Bash уместен, а где лучше другой инструмент.

## Исходные знания

Скрипты, argv, окружение, коды возврата, pipe и перенаправления.

## Объяснение

Bash — одна из самых распространённых оболочек в мире Linux-серверов. Он совместим с большим пластом сценариев и добавляет удобства сверх строгого POSIX `sh`. Учить Bash стоит потому, что им написаны установщики, обёртки сервисов и куски CI.

Переменные в Bash — строки. Арифметика и массивы есть, но это всё ещё язык, заточенный под запуск команд. Любая «сложная структура данных» быстро становится неуклюжей.

Условия: `if`, `case`, команда `[[ ... ]]` для удобных строковых и файловых проверок. Старый `[` / `test` тоже встречается. Важно помнить: внутри условий проверяются коды и выражения Bash, а внешние команды вызываются как обычно.

Циклы `for`, `while` часто обходят списки файлов. Здесь снова кавычки и glob: неправильный разбор пробелов уничтожает данные. Предпочтительны безопасные формы обхода и нуль-разделители для сложных имён.

Функции группируют команды. Они разделяют позиционные параметры со скриптом на время вызова. `local` ограничивает переменные. Возврат функции — снова код статуса, не «объект».

Подстановки: `$()`, арифметика `$(( ))`, параметрические формы `${var%pattern}`. Они мощны, но читаемость падает. Комментируйте нетривиальные подстановки.

Интерактивные удобства (alias, completion, history) живут в профилях. В скриптах на alias лучше не полагаться: запускайте явные команды.

Bash не обязан быть на минимальных контейнерах: там бывает только `sh`/dash. Пишите переносимо или фиксируйте образ с bash.

## Термины

**Bash** — Bourne Again Shell, распространённый интерпретатор.

**`[[ ]]`** — условная конструкция Bash с расширенным синтаксисом.

**Функция shell** — именованный блок команд внутри процесса оболочки.

**Параметрическое расширение** — синтаксис `${...}` для обработки строк.

**POSIX sh** — более строгий общий знаменатель синтаксиса оболочек.

## Как это работает

Bash читает скрипт, строит команды и вызывает ядро для внешних программ. Встроенные конструкции не порождают процесс. Поэтому цикл на чистом Bash по миллионам итераций может быть медленнее специализированной утилиты: каждая внешняя команда в цикле дорога.

Отладка: `set -x`, ловушки `trap` на EXIT/ERR для очистки временных файлов. Хороший скрипт оставляет систему в понятном состоянии даже при сбое.

Стиль: одна ответственность, явные проверки, мало магии. Если скрипт читают раз в полгода, ясность важнее плотности.

## Пример

```bash
#!/usr/bin/env bash
set -euo pipefail

greet() {
  local who="$1"
  echo "hi, $who"
}

if [[ -d /tmp ]]; then
  greet "tmp exists"
fi

for f in /tmp/*; do
  [[ -e "$f" ]] || continue
  echo "entry: $f"
  break
done
```

## Разбор

Функция `greet` использует `local`, чтобы не загрязнять глобальную область.

`[[ -d /tmp ]]` проверяет каталог без запуска внешней `test`-программы в отдельном процессе (это builtin-поведение).

Цикл по `/tmp/*` закавычивает `"$f"`. `continue` пропускает случай, когда glob не совпал и остался буквальным.

## Ошибки

- Писать «программы» на тысячу строк Bash.
- Обходить файлы без кавычек.
- Полагаться на alias в неинтерактивных скриптах.
- Требовать Bash-фичи, запуская файл через `sh`.

## Что запомнить

- Bash силён как клей команд и файлов.
- Условия и циклы опираются на статусы и строки.
- Кавычки и строгий режим обязательны.
- Для сложной логики выбирайте другой язык.

## Задание

Напишите функцию, принимающую каталог: она считает число обычных файлов внутри (не рекурсивно) и возвращает 1, если каталога нет. Вызовите её из скрипта с аргументом.

## Дополнение: практика и нюансы

`mapfile`/`readarray` читают строки в массив без потери пробелов — лучше, чем `for` по неоткавыченному $(...).

`trap 'cleanup' EXIT` гарантирует уборку временных файлов. В cleanup проверяйте, что переменные заданы.

Арифметика `$(( ))` целочисленная. Для дробей вызывайте `bc`/`awk` или другой язык.

Стиль: 2 пробела или таб — единообразие; `shellcheck` ловит массу реальных ошибок — включите в CI.
