# Python (CPython) — справочник

Справочник опирается на модель CPython: имена ссылаются на объекты в куче; исполнение идёт через байткод виртуальной машины; модули кэшируются в `sys.modules`.

## Установка и запуск

Нужен CPython 3. Проверяйте `python --version`. На Windows часто рядом живут `python`, `py` launcher и разные установки — убедитесь, что IDE и терминал вызывают один и тот же бинарник.

Запуск файла: `python path.py`. REPL — тот же интерпретатор в диалоге. `if __name__ == "__main__":` отделяет сценарий от импорта: при `import` тяжёлая работа на верхнем уровне не должна стартовать сама.

## Цепочка исполнения

Исходник → разбор → байткод → выполнение на стековой машине CPython. Значения — объекты. Ошибка синтаксиса возникает до семантики; `TypeError`/`ValueError` — уже во время операций над объектами. Понимание слоя ошибки экономит время.

## Имена и объекты

Присваивание привязывает имя к объекту. Несколько имён могут делить один объект. Мутация через одно имя видна через другое; перепривязка имени — нет. `is` — тождество, `==` — равенство. Переменная — не «коробка с числом», а имя в пространстве имён.

```python
a = [1, 2]
b = a
b.append(3)  # a тоже изменился
a = [9]      # b всё ещё на старый список с 3
```

Пространство имён модуля — по сути словарь имён. Локальные имена функции живут в кадре вызова.

## Типы и литералы

У объекта есть тип (`int`, `float`, `bool`, `str`, `NoneType`, контейнеры, функции, классы…). Динамическая типизация: имя может перепривязаться к другому типу; ошибки операций — в рантайме (`TypeError`). Аннотации типов — подсказки для инструментов, CPython их сам не принуждает на каждой операции.

`None` — единственный пустой объект-сентинел. Не путайте с `0`, `False`, `""` — они тоже «ложны» в условиях, но значат разное.

## Строки

`str` неизменяем; методы и срезы дают новые строки. f-строки удобны для сборки. `bytes` — сырые байты; encode/decode с кодировкой. Не путайте текст и байты на сокетах и бинарных файлах.

Склеивать строки в цикле через `+` создаёт много промежуточных объектов; для тяжёлого — `join`. Явно указывайте `encoding="utf-8"` на Windows.

## Контейнеры

- **list** — изменяемая последовательность ссылок; `append`, срезы, поверхностное копирование.
- **tuple** — неизменяемый состав; распаковка; возможный ключ dict.
- **set** — уникальные хешируемые элементы; быстрый `in`.
- **dict** — хеш-отображение ключ→значение; `get`, `items`; ключи хешируемы.

Копия через присваивание не создаёт новый контейнер. Для независимости — `copy`/`[:]`/`deepcopy` по нужде. Вложенные структуры при поверхностной копии делят внутренние объекты.

Один элемент в кортеже пишется `(x,)`. Список в set положить нельзя — не хешируем; кортеж чисел — можно.

## Управление потоком

`if/elif/else` по истинности (ложны `None`, `False`, `0`, пустые коллекции…). `for` работает через протокол итератора; `while` — по условию. `break`/`continue`. У цикла есть редкая форма `else` без `break`.

Comprehensions — сжатые выражения построения коллекций; двухуровневая вложенность уже часто хуже обычного цикла по читаемости. Побочные эффекты внутри comprehension — плохой стиль.

## Функции

`def` создаёт function object и привязывает имя. Вызов — новый кадр с локальными именами. Defaults вычисляются **один раз** при определении — классическая ловушка:

```python
def add(item, bucket=[]):  # плохо
    bucket.append(item)
    return bucket
```

Используйте `None` и создавайте новый список внутри. `lambda` — одно выражение; для сложного — `def`. Функции — объекты первого класса: их можно передавать и класть в структуры.

`*args`/`**kwargs` собирают лишние позиционные/именованные. Возврат без `return` даёт `None`. Несколько значений удобно возвращать кортежем с распаковкой.

## Исключения

`try/except/else/finally`, `raise`. Ловите конкретные типы (`ValueError`, `KeyError`, …). Голый `except:` или широкий `Exception` без переоценки — прячет баги. `else` — блок «если исключения не было». `finally` / лучше `with` — очистка.

Трассировка показывает стек. Читайте снизу вверх: где ваш код, какая операция, какой тип исключения.

## Модули и пакеты

`import m` загружает модуль (если ещё нет), кладёт в `sys.modules`, привязывает имя. `from m import x` копирует привязку имени. Повторный import берёт кэш. Пакеты — иерархия каталогов; `__init__.py` полезен как маркер и место публичного API.

Избегайте `import *` в прикладном коде. Тяжёлая работа и доступ к железу на верхнем уровне модуля — сюрприз при любом импорте. Циклические импорты лечатся пересмотром границ, не «магическим порядком».

## Окружение и pip

`python -m venv .venv` изолирует site-packages. Активируйте окружение. `python -m pip install …` ставит в текущий интерпретатор — так меньше шансов промахнуться «не тем pip». Фиксируйте зависимости (`requirements.txt` / `pyproject.toml`). Не коммитьте `.venv` без нужды; коммитьте манифест.

Разные проекты — разные окружения. Глобальная свалка пакетов приводит к необъяснимым конфликтам версий.

## Файлы и JSON

`pathlib.Path`, текстовый режим с `encoding="utf-8"`, бинарный для байтов. `with` закрывает файл даже при исключении. Большие файлы читайте построчно, не обязательно целиком в память.

JSON: `dumps/loads` для строк, `dump/load` для файлов. Типы ограничены: `dict/list/str/number/bool/None`. `set` и произвольные классы сами не сериализуются — нужна схема. Не используйте `eval` для данных.

## HTTP (минимум)

Запрос/ответ, статус, таймаут, разбор JSON. Проверяйте код ответа до доверия телу. Секреты — в окружении, не в репозитории. `urllib` в стандарте; `requests` удобен в venv. Сеть ошибается чаще, чем кажется — таймаут обязателен.

## Классы

`class`, `__init__`, методы с `self`. Атрибуты экземпляра обычно в `__dict__`. Class-атрибут с мутабельным значением разделяется всеми экземплярами — частая ловушка.

Наследование и `super()`, MRO как идея порядка поиска методов. Композиция («имеет») часто яснее глубокого наследования: робот имеет моторы, а не «является мотором».

## Декораторы

`@dec` ≡ `f = dec(f)`. Обёртка перехватывает вызов. Пишите декораторы, когда уверены в замыканиях и `*args/**kwargs`. `functools.wraps` сохраняет имя и докстринг оригинала. Стек декораторов читается снизу вверх по применению.

## Генераторы и итераторы

`yield` замораживает кадр и отдаёт значение; генератор ленив и одноразов — повторный обход требует нового генератора. Протокол: `iter` / `next` / `StopIteration`. Iterable даёт новый iterator; iterator — курсор по данным.

`for` всегда использует этот протокол. Свои коллекции становятся итерируемыми через `__iter__`/`__next__` или генератор.

## Typing и dataclass

Аннотации читают checker/IDE (`mypy`, pyright). Они не делают CPython статически типизированным языком в рантайме. `@dataclass` генерирует шаблон `__init__`/repr/сравнений по полям; `default_factory` для мутабельных умолчаний; `frozen=True` для записей без присваивания полей.

## Async (введение)

`async def` / `await` / event loop. Подходит для ожидания сети и таймеров. Не ускоряет чистый CPU. `time.sleep` в корутине блокирует loop; `asyncio.sleep` — нет. Вызов `async def` без `await`/`asyncio.run` лишь создаёт объект корутины.

## Тесты и логи

`pytest` ищет `test_*`, падает на ложном `assert`. Тест мал, детерминирован, без лишней сети и железа (подделки датчиков). `logging.getLogger(__name__)`, уровни DEBUG…CRITICAL, без секретов в логах. `print` — для черновиков и разовых скриптов.

## Каркас проекта

Пакет кода, `tests/`, манифест зависимостей, README с шагом запуска, `.gitignore`, venv локально. Точка входа `__main__.py` или console script. Раскладка `src/pkg/` снижает риск случайного импорта «из папки наудачу».

Связь с Git: коммитьте исходники и манифест; игнорируйте `.venv`, кэш, `.env`. История снимков кода — в модуле Git.

## Ошибки новичков (сборник)

Путать копирование ссылки и копирование данных; мутабельный default; глотать Exception; блокировать event loop; ждать runtime-гарантий от аннотаций; коммитить venv и `.env`; сравнивать float на точное равенство без нужды; открывать файлы без with; мешать tabs/spaces; запускать не тот интерпретатор.

## Как пользоваться справочником

Когда ломается код, сначала назовите слой: синтаксис, объектная модель (ссылки), протокол (итератор/контекст), импорт/окружение, I/O/сеть. Потом уже правьте. Уроки модуля `08-python` разбирают конструкции по одной; этот файл — карта связей.

## Порядок рядом с уроками

Установка → интерпретатор → запуск → синтаксис → имена/объекты → типы → строки/списки/кортежи/множества/словари → if/циклы → функции/lambda/comprehensions → исключения → модули/пакеты → venv/pip → файлы/JSON/API → классы/наследование/композиция → декораторы/генераторы/итераторы → typing/dataclass/async → тесты/логи/проект.

Перескажите вслух «имя → объект» и «import → sys.modules» перед отладкой незнакомого ImportError. Если схема стабильна, синтаксический сахар перестаёт казаться магией.

## Имена и мутация

```python
a = [1, 2]
b = a
b.append(3)
# a тоже [1, 2, 3]: один список, два имени

c = a.copy()
c.append(4)
# a не изменился: copy создал новый список
```

`a = a + [5]` строит новый список и перепривязывает `a`. `a += [5]` для списка мутирует тот же объект. Для чисел `+=` всегда перепривязка, потому что число неизменяемо. Путаница «почему функция испортила мой список» почти всегда про передачу ссылки, не про «особый Python».

Аргумент по умолчанию вычисляется один раз, при определении функции. Мутабельный default (`def f(items=[]):`) общий для всех вызовов. Нужен свежий список — ставьте `None` и создавайте список внутри.

## Исключения, которые стоит различать

`ValueError` — значение есть, но оно не годится (`int("x")`). `KeyError` — нет ключа. `FileNotFoundError` — нет пути. `TypeError` — операция не для этого типа. Ловить голый `Exception` в библиотечном коде прячет баги. На границе программы (команда, HTTP-обработчик) широкий перехват уместен, если вы логируете и отдаёте понятный отказ, а не пустой ответ.

`raise ... from err` сохраняет причину. Без этого цепочка «почему упало» обрывается на вашей обёртке.

## Итерация

`for` вызывает `iter`, затем `next`, пока не `StopIteration`. Генератор хранит кадр между `yield` и отдаёт значения лениво. Список-включение строит список сразу. Генераторное выражение — нет. Прочитать генератор дважды нельзя: он уже исчерпан. Если нужны два прохода — материализуйте в список или создайте генератор заново.

## async без магии

`async def` делает корутину. Она не бежит, пока её не запустит цикл событий. `await` отдаёт управление, пока ждётся I/O. Долгий расчёт без `await` блокирует цикл так же, как обычная функция. Для блокирующего диска или чужой синхронной библиотеки нужен поток или процесс, а не ещё один `async def` вокруг того же вызова.

## Окружение

`python -m venv .venv` создаёт отдельный интерпретатор с собственным `site-packages`. `pip install` без активированного venv пишет в системный или пользовательский каталог, и «у меня работает» расходится с коллегой. Зависимости фиксируйте в файле (`requirements.txt` или аналог), сам каталог `.venv` не коммитьте.

`PYTHONPATH` и запуск «из какой папки» меняют, какой модуль импортируется первым. Ошибка «импортировался не тот файл» лечится проверкой `sys.path` и запуском через `python -m пакет`, а не случайным скриптом рядом с одноимённой папкой.

## Диагностика по слоям

1. **Синтаксис** — `SyntaxError`, неверные отступы. Правьте до любой логики.
2. **Имена и объекты** — `NameError`, неожиданная общая мутация списка, путаница `is`/`==`.
3. **Типы и операции** — `TypeError`, `ValueError` при преобразовании.
4. **Протоколы** — итератор исчерпан, файл закрыт, контекст `with`.
5. **Импорт и окружение** — не тот venv, нет пакета, циклический import.
6. **I/O и сеть** — путь, кодировка, таймаут, статус HTTP.

Называйте слой вслух — это уже половина отладки.

## Частые рецепты (после модели)

```python
# безопасное чтение конфига
from pathlib import Path
import json

def load_cfg(path: Path) -> dict:
    text = path.read_text(encoding="utf-8")
    data = json.loads(text)
    if not isinstance(data, dict):
        raise TypeError("config root must be object")
    return data
```

```python
# clamp без сюрпризов типов
def clamp(x: float, lo: float, hi: float) -> float:
    if lo > hi:
        raise ValueError("lo > hi")
    return max(lo, min(hi, x))
```

```python
# точка входа
def main() -> None:
    ...

if __name__ == "__main__":
    main()
```

Эти фрагменты не заменяют уроки: они показывают, как модель (типы, исключения, `__main__`) выглядит в коротком коде.

## Сопоставление с модулем programming

| Идея programming | В Python |
|------------------|----------|
| переменная | имя → объект |
| тип | тип объекта |
| функция | `def`, кадр |
| модуль | файл + `import` |
| пакет | каталог пакета |
| исключение | `raise` / `except` |
| объект | экземпляр класса |
| структура | list/dict/set/tuple |

Не учите Python как набор ключевых слов в отрыве от этой таблицы.

## Производительность на уровне привычек

Пока проект учебный, ясность важнее микросекунд. Но базовые привычки дешёвы: не собирайте огромные строки через `+` в цикле; не делайте `O(n²)` там, где нужен set/dict; не читайте гигабайтный файл целиком без нужды; не блокируйте async loop. Измеряйте, прежде чем «оптимизировать наугад».

## Безопасность минимума

Не кладите секреты в исходники. Не `eval` пользовательский ввод. Проверяйте статус HTTP. Ограничивайте пути файлов, если путь приходит снаружи. Логи без паролей и токенов. Это не полный курс безопасности, а гигиена, без которой учебный проект становится опасным при выкладке на сервер.
