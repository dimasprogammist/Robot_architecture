# Устройство компьютера — справочник

Справочник дополняет курс «Основы компьютера». Здесь собраны определения, связи между уровнями, нюансы и ответы на частые вопросы. Это не конспект уроков слово в слово, а рабочая база для поиска.

## 1. Базовая модель

### Определение

Компьютер — программируемое устройство, которое хранит данные и выполняет инструкции. Классическая модель фон Неймана предполагает общую память для команд и данных, центральный исполнитель и каналы ввода-вывода.

### Что из этого следует на практике

- Программа и данные — байты в памяти с адресами.
- Исполнение идёт последовательно (с оговорками про конвейер, внеочередное исполнение, многоядерность).
- Самоизменение кода возможно технически, но в современных системах ограничено защитой памяти и политиками W^X.
- «Понимание задачи» отсутствует: есть только инструкции и данные.

### Гарвардская оговорка

Некоторые МК и DSP разделяют шины/память команд и данных (гарвардская схема). Для инженера это влияет на пропускную способность и размещение констант, но не отменяет идею «инструкции исполняются процессором».

## 2. Процессор (CPU)

### Роль

Исполняет инструкции ISA: арифметика, логика, переходы, доступ к памяти, управление системными регистрами (в привилегированном режиме).

### Ключевые элементы

| Элемент | Смысл |
|--------|--------|
| Регистры | Сверхбыстрые ячейки операндов и состояния |
| PC / IP | Счётчик команд |
| ALU | Арифметико-логическое устройство |
| Кэш L1–L3 | Ускорение доступа к горячим данным |
| Ядра | Параллельные исполнители |
| SMT/HT | Несколько аппаратных потоков на ядро |

### Частота и производительность

Тактовая частота — не единственная метрика. IPC (инструкций за такт), ширина SIMD, скорость памяти, предсказание ветвлений и характер кода важны не меньше. Программа, упирающаяся в память, не ускорится пропорционально гигагерцам.

### Прерывания

Устройства и таймеры прерывают текущий поток команд. CPU сохраняет контекст и передаёт управление обработчику (обычно в ядре ОС). Это основа реакции на I/O без постоянного активного опроса (хотя polling тоже применяют осознанно).

### Типичные ошибки мышления

- «8 ядер = всё в 8 раз быстрее» для однопоточного кода.
- Игнор термотроттлинга при длительной нагрузке.
- Сравнение CPU разных ISA только по частоте.

## 3. Иерархия памяти

Сверху вниз по скорости (упрощённо): регистры → L1 → L2 → L3 → RAM → SSD/NVMe → HDD/сеть.

Свойства уровней:

- **Объём** растёт вниз.
- **Задержка** растёт вниз.
- **Энергозависимость**: регистры/кэш/RAM обычно летучи; SSD/HDD нет.
- **Управление**: кэш прозрачен; RAM и диск видны программам через ОС.

### Единицы

Байт = 8 бит. KiB/MiB/GiB (1024ⁿ) vs KB/MB/GB (1000ⁿ) — смотрите контекст производителя. Для ёмкости дисков маркетинг часто использует десятичные приставки.

## 4. Оперативная память (RAM)

### Назначение

Рабочее пространство процессов и кэша ОС. После выключения содержимое обычной DRAM не сохраняется.

### Взгляд ОС

- Виртуальные адреса процесса.
- Физические фреймы.
- Page cache файловых данных.
- Swap/pagefile как аварийное/расширяющее продолжение на диске (медленно).

### Метрики процесса

- **RSS** — сколько физики занято.
- **VSZ/VSize** — размер виртуального пространства (часто больше и пугает зря).
- **Working set** — активно используемое подмножество.

### Ошибки

- Путать свободное место на диске и свободную RAM.
- Считать swap полноценной заменой RAM для realtime.
- Хранить уникальные данные только в RAM без persist-стратегии.

## 5. Накопители

### HDD

Магнитные пластины. Высокая ёмкость дёшево; случайный доступ дорог из-за механики; чувствительность к ударам.

### SSD / NVMe

Флэш. Лучше случайный доступ; износ циклов записи; внутренняя сборка мусора; TRIM. Контроллер скрывает физическую геометрию.

### Поведение записи

`write` в приложение ≠ гарантия на носителе. Буферы ОС и устройства. Для критичных метаданных используют `fsync`, атомарную замену файлов (write temp + rename), журналы транзакций.

### Встраиваемые носители

eMMC и SD часто слабее enterprise SSD по ресурсу. Стратегии: меньше мелких синхронных записей, вынос логов, read-only корень где возможно.

## 6. Файловая система (уровень обзора)

ФС отображает блоки устройства в имена, каталоги, метаданные, права. Примеры: ext4, XFS, NTFS, APFS, FAT/exFAT.

Понятия:

- путь vs inode/данные;
- жёсткая ссылка vs симлинк;
- дескриптор открытого файла;
- журнал метаданных;
- mount.

Подробнее с точки зрения ОС — в справочнике по ОС и уроках модуля OS.

## 7. Программа и выполнение

### Артефакты

- Исходный код.
- Байткод / промежуточное представление.
- Машинный код под ISA.
- Скрипт + интерпретатор.

### Жизненный цикл

Файл на диске (пассивно) → загрузка ОС в процесс → исполнение CPU → завершение. Один файл — много процессов.

### Зависимости

Динамические библиотеки, runtime языка, конфиги, устройства. Переносимость двоичника ограничена ABI ОС и архитектурой CPU.

## 8. Процессы и потоки

### Процесс

Экземпляр программы: адресное пространство, PID, таблица дескрипторов, учётные данные. Изоляция между процессами — норма на системах с MMU.

### Поток

Путь исполнения внутри процесса: свой стек, общие куча и глобальные данные. Гонки данных требуют синхронизации.

### Когда что выбирать

| Задача | Часто лучше |
|--------|-------------|
| Изоляция сбоя | Процессы |
| Делёж больших структур in-place | Потоки (осторожно) |
| Массовый I/O wait | Async / event loop или пул |
| CPU-параллелизм в CPython | Процессы/нативные расширения |

## 9. Операционная система как слой

На машинах общего назначения программы не владеют сырым железом. ОС:

- планирует CPU;
- управляет виртуальной памятью;
- даёт ФС и сеть;
- изолирует и авторизует;
- загружает драйверы.

Голые МК могут обходиться без полной ОС — тогда ответственность за всё несёт прошивка.

## 10. User space и kernel space

CPU имеет уровни привилегий. Приложения работают в user mode; ядро — в kernel mode. Переходы: syscall, исключение, прерывание. Падение процесса не должно ронять ядро (в идеале). Ошибка драйвера в монолитном ядре опаснее ошибки приложения.

## 11. Ввод-вывод

Цепочка: устройство → контроллер/DMA → драйвер → ядро (сокет/VFS) → syscall → буфер процесса.

Характеристики: latency, throughput, jitter. Буферизация везде. Блокирующий I/O отдаёт CPU; неблокирующий/мультиплексирование обслуживает много потоков событий.

Для контуров управления роботом оценивайте, где допустима ОС общего назначения, а где нужен МК/RTOS.

## 12. Современный компьютер как система

SoC объединяет CPU, GPU/NPU, контроллеры. Шины имеют разную пропускную способность. NUMA на серверах делает «не всю RAM одинаковой». Firmware (UEFI, микрокод, FW дисков) — часть системы. Узкое место плавает: CPU, RAM, диск, PCIe, сеть, теплопакет.

Гетерогенность: не всё считать на CPU. Но GPU не заменяет произвольную ветвящуюся логику управления.

## 13. Карта диагностики «тормозит»

1. CPU 100%? — профиль кода, алгоритмы, GIL/однопоточность.
2. RAM полна / swap? — утечки, слишком большие наборы данных.
3. Диск занят? — логи, антивирус, swap, база.
4. Сеть? — таймауты, DNS, потери.
5. Троттлинг? — температура, питание.
6. Блокировки? — ожидание замков, очередей, устройств.

Снимайте факты (`top`, диспетчер, iostat, perf), не гадайте по одному симптому.

## 14. FAQ

**Чем компьютер отличается от калькулятора?**  
Калькулятор узкоспециализирован; компьютер общего назначения загружает произвольные программы из памяти.

**Почему после BSOD/panic пропали несохранённые файлы?**  
Они жили в RAM и page cache без сброса на диск.

**Нужен ли SSD, если RAM большая?**  
Да для хранения и загрузки; RAM не заменяет накопитель для persist.

**Почему два одинаковых ноутбука «разной скорости»?**  
Термодизайн, фон службы, состояние диска, NUMA/фоновые задачи, версии ПО.

**Можно ли обойтись без ОС на ПК?**  
Технически для учебной ОС/гипервизора да; для экосистемы приложений — нет в практическом смысле.

**Где хранится переменная Python?**  
В куче процесса в RAM (объект интерпретатора); не на диске, пока не сериализовали.

**Что быстрее: поток или процесс?**  
Создание и переключение потоков обычно дешевле; безопасность изоляции выше у процессов. Зависит от задачи.

**Зачем кэш CPU, если есть RAM?**  
Задержка RAM велика относительно ядра; кэш держит горячее рядом.

**Почему NVMe быстрее «просто SSD»?**  
Часто интерфейс и параллелизм очередей (PCIe/NVMe vs SATA), не только «флэш vs флэш».

**Что такое bottleneck?**  
Узкое место системы, ограничивающее скорость цепочки. Оптимизация не-bottleneck почти бесполезна.

## 15. Шпаргалка связей

```
Инструкции  → CPU (+кэш)
Рабочие данные → RAM
Долгое хранение → диск/SSD + ФС
Мир снаружи → устройства + драйверы + I/O
Много программ → ОС (планирование, изоляция)
Запуск файла → процесс
Параллелизм внутри → потоки / async / несколько процессов
```

## 16. Практические правила инженера

1. Различайте «в RAM» и «на диске» в каждом дизайне состояния.
2. Измеряйте, прежде чем покупать «более мощный CPU».
3. Ограничивайте очереди и кэши — защита от OOM.
4. Для критичных записей думайте о fsync и атомарности.
5. Не смешивайте жёсткий realtime и тяжёлый desktop-I/O без анализа.
6. Документируйте, на какой ISA/ABI собран бинарник.
7. Считайте прошивки устройств частью системы обновлений.
8. Помните: ОС — посредник, не враг производительности по умолчанию.

## 17. Мини-глоссарий

- **ISA** — набор команд архитектуры.
- **MMU** — блок управления памятью (вирт→физ).
- **DMA** — устройство пишет/читает RAM без CPU на каждый байт.
- **IRQ** — линия/механизм прерываний.
- **Context switch** — смена задачи на ядре.
- **Page fault** — обращение, требующее реакции ОС на страницу.
- **Throughput / latency** — объём/время отклика.
- **SoC** — system on chip.
- **Firmware** — встроенное ПО.
- **ABI** — двоичный интерфейс совместимости.

## 19. Контрольные вопросы для самопроверки

1. Почему модель фон Неймана допускает, что программа — тоже данные?
2. Чем RSS отличается от размера файла программы на диске?
3. Почему успешный `write` не гарантирует сохранность при внезапном power loss?
4. Чем поток опаснее процесса при наличии бага в работе с памятью?
5. Зачем нужны два режима привилегий CPU?
6. Где в цепочке камеры появляется DMA и зачем?
7. Почему «больше ГГц» не лечит программу, упирающуюся в сеть?
8. Чем SoC отличается от «просто процессора» в бытовом смысле?

Если отвечаете уверенно — база по устройству компьютера у вас собрана; дальше углубляйте ОС и конкретный стек разработки.
