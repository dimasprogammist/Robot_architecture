# Frontend

## Назначение справочника

Плотный справочник по HTML, CSS, JavaScript и React для поиска определений, сравнений и типичных ошибок. Не заменяет уроки модуля frontend: здесь сжатые факты и шпаргалки.

## Карта темы

- HTML: документ, семантика, формы
- CSS: каскад, селекторы, box model, layout
- JavaScript: типы, функции, DOM, события, async
- HTTP с браузера: fetch, JSON, CORS
- React: компоненты, props, state, effects, списки
- Формы и контролируемые поля
- Маршрутизация SPA
- Состояние приложения vs сервер
- Типичные ошибки и чеклисты

## 1. HTML — определения

**HTML** — язык разметки структуры документа. Браузер строит DOM-дерево из тегов.

**Элемент** — пара тегов или void-тег (`<img>`), плюс атрибуты и содержимое.

**Семантика** — выбор тега по смыслу (`<main>`, `<nav>`, `<button>`), а не только `<div>` + клик.

**Форма** — `<form>` собирает поля; `submit` инициирует отправку (в SPA обычно перехватывают JS).

```html
<label>
  Email
  <input name="email" type="email" required />
</label>
<button type="submit">Войти</button>
```

## 2. HTML — частые атрибуты

| Атрибут | Зачем |
|---------|--------|
| `id` | уникальный якорь, `getElementById` |
| `class` | крючок для CSS |
| `name` | имя поля формы / query |
| `type` | поведение input |
| `disabled` | недоступность |
| `aria-*` | доступность для скринридеров |

Ошибка: кликабельный `<div>` без роли и клавиатуры вместо `<button>`.

## 3. CSS — каскад и специфичность

**Каскад** — какие правила побеждают при конфликте: происхождение → специфичность → порядок.

Грубая специфичность: `#id` > `.class` > `element`. `!important` — аварийный рычаг, не стиль жизни.

**Наследование**: `color`, `font-*` наследуются; `margin`, `padding` — нет.

## 4. CSS — box model

Для каждого бокса: content → padding → border → margin.

`box-sizing: border-box` — width включает padding+border (удобный дефолт в сбросах).

Ошибка: «элемент шире родителя» из-за `width: 100%` + padding при `content-box`.

## 5. CSS — селекторы (шпаргалка)

```css
.order-card { }
.order-card > h2 { }      /* прямой потомок */
.order-card .badge { }    /* любой потомок */
input[type="text"] { }
button:hover { }
.list li + li { }         /* сосед */
```

Не злоупотребляйте глубокими цепочками — хрупко при смене вёрстки.

## 6. CSS — layout

| Инструмент | Когда |
|------------|--------|
| Flexbox | ряд/колонка, выравнивание, шапка |
| Grid | двумерная сетка страницы/карточек |
| Position | исключения: sticky, overlay |

```css
.row {
  display: flex;
  gap: 1rem;
  align-items: center;
}
```

Ошибка: абсолютное позиционирование всего подряд вместо flow-layout.

## 7. JavaScript — типы и равенство

Примитивы: `string`, `number`, `boolean`, `null`, `undefined`, `bigint`, `symbol`. Объекты — по ссылке.

`===` — строгое сравнение. `==` с приведением — источник багов (`0 == ""`).

`typeof null === "object"` — историческая ловушка; проверяйте `null` отдельно.

## 8. JavaScript — функции

```js
function add(a, b) { return a + b; }
const add2 = (a, b) => a + b;
```

Стрелки не имеют своего `this` — удобно в колбэках React, осторожно в методах объектов (если нужен dynamic `this`).

**Замыкание** — функция помнит лексическое окружение. Ошибка: цикл `var` + async без блока/`let`.

## 9. DOM и события

**DOM** — объектная модель документа. JS читает/меняет узлы.

```js
const el = document.querySelector("#save");
el.addEventListener("click", (e) => {
  e.preventDefault();
});
```

**Всплытие**: событие идёт с цели вверх. `stopPropagation` режет; используйте редко.

Делегирование: слушатель на родителе для многих детей.

## 10. Async в браузере

```js
const res = await fetch("/api/orders");
const data = await res.json();
```

`fetch` не бросает на 404/500 — проверяйте `res.ok`. Сеть/CORS — бросает TypeError.

`Promise.all` — параллельно; один reject валит всё (есть `allSettled`).

## 11. JSON

Текстовый формат обмена. `JSON.stringify` / `JSON.parse`.

Даты в JSON — строки; на клиенте парсите явно. `undefined` в объектах при stringify пропадает; `NaN` становится `null` — осторожно.

## 12. CORS (с точки зрения фронта)

Браузер блокирует чтение ответа с другого origin, если сервер не разрешил.

Симптом: «CORS error» в консоли при живом Network. Лечится на **бэкенде/прокси**, не «отключением безопасности» в проде.

Same-origin через dev-proxy (`/api` → backend) снимает боль в разработке.

## 13. React — идея

**Компонент** — функция, возвращающая описание UI (элементы). React сравнивает дерево и обновляет DOM точечно.

```tsx
function Badge({ status }: { status: string }) {
  return <span className="badge">{status}</span>;
}
```

**Props** — вход снаружи (как аргументы). **State** — память компонента между рендерами.

## 14. State

```tsx
const [count, setCount] = useState(0);
setCount(c => c + 1); // функциональное обновление
```

Не мутируйте state напрямую (`arr.push`). Создавайте новый массив/объект.

Ошибка: `useState` в условии/цикле — нарушает правила хуков.

## 15. Effects

```tsx
useEffect(() => {
  let cancelled = false;
  (async () => {
    const data = await loadOrders();
    if (!cancelled) setOrders(data);
  })();
  return () => { cancelled = true; };
}, []);
```

Effect — синхронизация с «внешним миром» (сеть, подписки), не «жизненный цикл class-component».

Зависимости в массиве должны быть полными; пустой `[]` — mount/unmount.

## 16. Списки и ключи

```tsx
{orders.map(o => <OrderRow key={o.id} order={o} />)}
```

`key` стабильный id, не индекс массива при перестановках. Иначе сброс state строк и баги фокуса.

## 17. Контролируемые формы

```tsx
const [email, setEmail] = useState("");
<input value={email} onChange={e => setEmail(e.target.value)} />
```

Источник истины — state React. Неконтролируемые (`ref`) — для простых/интеграционных случаев.

## 18. Условный рендер

```tsx
{loading && <Spinner />}
{error ? <ErrorMsg e={error} /> : <List items={items} />}
```

Не возвращайте `undefined` из обработчиков как UI — явно `null` для «ничего».

## 19. Поднятие состояния

Если два ребёнка делят данные — state у общего родителя, вниз props, вверх колбэки.

Альтернативы: контекст, внешний store — когда проп-дриллинг уже боль.

## 20. Контекст

```tsx
const AuthContext = createContext<Auth | null>(null);
```

Для темы/auth/locale. Не кладите туда высочастотный state анимации — лишние рендеры дерева.

## 21. Маршрутизация SPA

URL ↔ экран без полной перезагрузки. React Router: `<Routes>`, `<Route>`, `useParams`, `Link`.

Данные экрана обычно грузят в effect/loader по `id` из URL — URL часть состояния приложения.

## 22. Слои фронтенд-кода

| Слой | Пример |
|------|--------|
| UI-компоненты | Button, Modal |
| Страницы | OrdersPage |
| API-клиент | `createOrder()` |
| Типы DTO | `Order`, `CreateOrderBody` |

Страницы не должны содержать сырой `fetch` в десяти местах — централизуйте клиент.

## 23. Ошибки UI

Различайте:

- ошибка валидации полей (локально или 422);
- 401 — сессия;
- сеть offline;
- 5xx — сообщение + retry.

Не глотайте `catch` пустым блоком.

## 24. Производительность (кратко)

- ключи списков;
- не создавать тяжёлые объекты в рендере без нужды;
- виртуализация длинных списков;
- код-сплит маршрутов.

Преждевременный `memo` везде — шум. Сначала измерьте.

## 25. Доступность (a11y)

- фокус на интерактиве;
- `label` связан с input;
- контраст;
- не убирайте outline без замены;
- кнопки — `button`, ссылки — `a` по смыслу навигации.

## 26. Безопасность на клиенте

- XSS: не вставляйте неэкранированный HTML (`dangerouslySetInnerHTML`) из пользователя;
- токены: httpOnly cookie предпочтительнее localStorage при XSS-риске;
- никогда не кладите секреты API в бандл.

Фронт **не** доверенная граница: проверки на сервере обязательны.

## 27. Сравнение: vanilla vs React

| | Vanilla DOM | React |
|--|-------------|-------|
| Обновление UI | вручную | декларативный рендер |
| State | переменные + ручной sync | useState/store |
| Команда | быстро на малом | масштабируется структурой |

React не отменяет знание HTML/CSS/JS — оборачивает управление UI.

## 28. Типичные ошибки (сборник)

1. Мутация state / props.
2. Бесконечный цикл effect без зависимостей / с неверными deps.
3. `fetch` без проверки `ok`.
4. Индекс как `key` в сортируемом списке.
5. Бизнес-правила только на клиенте.
6. CORS «лечат» расширением браузера.
7. Огромные компоненты на 800 строк без разрезания.
8. Игнор loading/error состояний.
9. WebSocket без reconnect и snapshot.
10. Стили через inline на всё подряд без системы.

## 29. Чеклист экрана заказов

- [ ] Загрузка / пусто / ошибка / данные — четыре состояния
- [ ] Кнопка submit disabled на время запроса
- [ ] Ошибки 422 привязаны к полям
- [ ] Список с стабильными key
- [ ] После создания — обновление списка или navigate
- [ ] Токен не светится в URL/логах UI

## 30. Мини-глоссарий

- **SPA** — одностраничное приложение, навигация без полной перезагрузки.
- **CSR** — рендер в браузере.
- **SSR** — HTML с сервера (за рамками базового справочника).
- **Hydration** — оживление SSR-разметки React.
- **DTO** — форма данных контракта с API.
- **Optimistic UI** — обновить UI до ответа сервера (нужен откат).

## 31. Короткие примеры «правильно / нет»

Нет:

```js
orders.push(newOrder);
setOrders(orders);
```

Да:

```js
setOrders(prev => [...prev, newOrder]);
```

Нет:

```js
useEffect(() => { load(); }); // каждый рендер
```

Да:

```js
useEffect(() => { load(); }, [customerId]);
```

## 32. Связь с бэкендом (карточка)

Фронт владеет UX и локальным state. Контракт — HTTP/JSON и иногда WebSocket. Истина сущностей — сервер и БД. Этот справочник закрывает клиентскую половину; серверную ищите в guide-backend / уроках API.

## 33. Быстрый поиск по симптомам

| Симптом | Куда смотреть |
|---------|----------------|
| Стили «не те» | специфичность, cascade, box model |
| Клик не работает | overlay, pointer-events, disabled |
| State сбрасывается | key списка, размонтирование |
| Двойной fetch StrictMode | учёт double-invoke в dev |
| Старый список после POST | refetch / инвалидация кэша |
| Мигание формы | controlled value + async set |

## 34. Что помнить всегда

HTML — смысл и доступность, CSS — вид и раскладка, JS — поведение, React — композиция UI и состояние экрана, сеть — контракт с сервером. Ошибка почти всегда лежит в одном из этих слоёв — не ищите её «во всём фронте сразу».
