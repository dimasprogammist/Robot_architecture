# Формат практических заданий

Принято 2026-10-05. Цель — разметка, которую `RichMarkdown` показывает уже сейчас
(обычный Markdown + `<details>`), а frontend позже сможет превратить в интерактивный
редактор без переразметки уроков.

## Задание с кодом

```markdown
### Задание 2. Среднее по окну

Напишите функцию `moving_average(values, n)`, которая возвращает список средних
по последним `n` значениям. Для первых элементов, пока значений меньше `n`,
считайте среднее по тому, что есть.

```python task id=py-lists-02 check=tests
def moving_average(values: list[float], n: int) -> list[float]:
    ...
```

<details><summary>Подсказка 1</summary>
Срез `values[i - n + 1 : i + 1]` даёт окно; подумайте, что происходит при `i < n - 1`.
</details>

<details><summary>Подсказка 2</summary>
`max(0, i - n + 1)` убирает отрицательное начало среза.
</details>

<!-- check:
assert moving_average([1, 2, 3, 4], 2) == [1.0, 1.5, 2.5, 3.5]
assert moving_average([5], 3) == [5.0]
-->

<details><summary>Решение</summary>

```python
def moving_average(values, n):
    out = []
    for i in range(len(values)):
        window = values[max(0, i - n + 1): i + 1]
        out.append(sum(window) / len(window))
    return out
```

</details>
```

Правила:

- Строка информации у блока кода: `<язык> task id=<раздел>-<тема>-<номер> [check=tests|output|none]`.
  `react-markdown` читает только первое слово как язык, остальное игнорирует, поэтому
  текущий рендер не ломается. Языки: `python`, `cpp`, `sql`, `bash`, `powershell`, `javascript`, `typescript`.
- `check=tests` — проверка выражениями `assert` в HTML-комментарии `<!-- check: … -->`
  сразу после задания. Комментарий не рендерится. Проверяем результат, а не текст решения.
- `check=output` — ожидаемый вывод в комментарии: `<!-- expect:\nстрока\n-->`.
- `check=none` — задание запускается, но не проверяется (ранние уроки, эксперименты).
- Подсказки — `<details><summary>Подсказка N</summary>`; решение — отдельный `<details>`
  **после** проверки, никогда рядом с условием.
- Стартовый код допустим на ранних уроках; на продвинутых блок может быть пустым или
  содержать только сигнатуру.

## Теоретическое задание

Обычный Markdown без спецразметки:

```markdown
### Задание 3. Предскажите результат

Что выведет программа и почему? Запишите ответ до запуска.
```

Ответ, если нужен, — в `<details><summary>Ответ</summary>`.

## Количество и место

Ориентиры из `course-editor/PRACTICE.md`: 3–5 заданий в обычном уроке, до 7 в большом
программном, до 10 в сложном SQL. Теоретические разделы (01, 02, 20, 25) могут иметь
только вопросы на рассуждение. Задания не блокируют прохождение.
