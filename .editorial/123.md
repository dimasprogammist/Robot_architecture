## КРИТИЧЕСКОЕ ТРЕБОВАНИЕ

Необходимо выполнить **АБСОЛЮТНО ВСЕ пункты данного ТЗ**.

Нельзя:
- пропускать отдельные замечания;
- считать пункт выполненным частично;
- заменять требуемое поведение на похожее;

# 1. Восстановление пароля пользователя

Необходимо добавить полноценное восстановление пароля пользователя по электронной почте.

## Экран авторизации

На существующем экране авторизации добавить кнопку/ссылку:

**«Забыли пароль?»**

Она должна открывать интерфейс восстановления пароля.

## Интерфейс восстановления

Добавить отдельный экран/состояние восстановления пароля.

Пользователь вводит:

```text
Email
[________________________]

[Отправить ссылку]
```

После отправки должен запускаться существующий/новый backend-механизм восстановления пароля.

Необходимо предусмотреть:

проверку корректности email;
понятное сообщение об успешной отправке;
обработку ошибки;
возможность вернуться к авторизации.
Сброс пароля

По ссылке из email пользователь должен иметь возможность задать новый пароль.

Минимально:

Новый пароль
[________________]

Повторить пароль
[________________]

[Сохранить новый пароль]

Проверить:

совпадение паролей;
корректность нового пароля;
недействительность/одноразовость токена восстановления;
корректное сохранение нового пароля;
возможность после этого войти с новым паролем.

Сначала изучи существующую систему пользователей и авторизации и интегрируй восстановление пароля в неё.

Не создавать отдельную независимую систему пользователей.

2. Экран выбора проектов — убрать лишний скролл

Сейчас экран со списком проектов прокручивается даже тогда, когда проектов мало.

Это нужно исправить.

Требуемое поведение

Если карточки проектов полностью помещаются на экране:

вертикального скролла быть не должно;
содержимое не должно прокручиваться;
scrollbar не должен отображаться.

Если проектов становится настолько много, что карточки доходят до нижней границы доступной области:

появляется вертикальная прокрутка;
пользователь может прокручивать список;
scrollbar при этом желательно вообще визуально скрыть.

То есть:

Мало проектов:

┌─────────────────────────────┐
│ Проект 1                    │
│ Проект 2                    │
│ Проект 3                    │
│                             │
│                             │
│                             │
└─────────────────────────────┘

Никакого скролла.

И:

Много проектов:

┌─────────────────────────────┐
│ Проект 1                    │
│ Проект 2                    │
│ Проект 3                    │
│ Проект 4                    │
│ Проект 5                    │
│ Проект 6                    │
│ ...                         │
└─────────────────────────────┘
              ↕
          прокрутка

Проверь реальные размеры контейнеров, height, min-height, overflow, flex/grid и вложенные scroll-контейнеры.

Не просто скрыть scrollbar — нужно убрать саму возможность прокрутки, когда содержимое помещается.

3. Таблица требований — увеличить колонку «Связи»

В таблице требований сейчас проблема с колонкой:

«Связи»

Данные внутри неё не помещаются в одну строку.

Требуется

Увеличить ширину колонки «Связи», чтобы её содержимое нормально помещалось в одну строку.

При этом:

нельзя сильно уменьшать остальные колонки;
не нужно забирать все 100–200 px у одной конкретной колонки;
если дополнительная ширина нужна — распределить уменьшение остальных колонок понемногу;
таблица должна сохранить нормальный внешний вид.

Приоритет:

Связи → сделать достаточно широкой
Остальные колонки → уменьшать только немного и равномерно

После изменения проверить реальные длинные значения в колонке «Связи».

4. Просмотр и переключение предыдущих версий проекта

Необходимо доработать систему версий проекта.

Главное требование

При переключении между сохранёнными версиями не должно появляться непонятное отдельное окно сверху, которое мешает работе.

Текущий механизм такого окна нужно убрать или полностью переработать.

Предпочтительный вариант

Сделать максимально простой механизм:

Версия:
[ v5 ▼ ]

Пользователь выбирает сохранённую версию и проект переключается на состояние этой версии.

После этого пользователь может:

посмотреть канву;
посмотреть архитектуру;
посмотреть БД;
посмотреть остальные данные проекта.

То есть фактически можно переключаться между версиями и визуально сравнивать их.

Важно

Если выбранная версия является только просмотром, не нужно автоматически перезаписывать текущую рабочую версию.

Если архитектура проекта позволяет сделать отдельный режим просмотра — использовать его.

Допустимый альтернативный вариант

Если текущее верхнее окно действительно необходимо сохранить, тогда внутри него обязательно должна отображаться схема канвы именно той версии, которую пользователь просматривает.

Но предпочтение:

не делать отдельное верхнее окно вообще — просто переключение версии.

5. Версии проекта — правильный порядок

Сейчас версии проекта отображаются в обратном порядке:

Самая старая
↓
...
↓
Самая новая

Нужно сделать наоборот.

Требуемый порядок

Самая новая версия должна быть сверху:

v10  ← самая новая
v9
v8
v7
...
v1   ← самая старая

Это должно одинаково работать:

в списке версий;
в dropdown;
в любых других местах, где версии отображаются пользователю.
6. Библиотека компонентов — убрать горизонтальный скролл

Сейчас библиотека компонентов не помещается по ширине и появляется горизонтальный scrollbar.

Это нужно исправить.

Требуется

В библиотеке компонентов:

убрать горизонтальную прокрутку;
скрыть горизонтальный scrollbar;
элементы должны помещаться в доступную ширину;
при необходимости использовать перенос элементов;
не уменьшать элементы до нечитабельного состояния.

При этом пользователь уже отметил, что по фактической ширине всё должно помещаться.

Значит, сначала найти причину появления overflow.

Проверить:

width;
min-width;
max-width;
padding;
gap;
flex/grid;
фиксированные размеры;
дочерние элементы, которые создают overflow.

Не маскировать проблему простым overflow-x: hidden, если реальный layout продолжает вылезать за границы.

7. Библиотека базы данных — убрать горизонтальный скролл

То же самое относится к библиотеке базы данных.

Сейчас там также появляется горизонтальный scrollbar.

Необходимо:

убрать горизонтальный overflow;
сделать содержимое полностью помещающимся;
сохранить текущие размеры и читаемость элементов;
не создавать горизонтальную прокрутку.

Найти реальную причину переполнения, а не просто скрыть последствия.

8. Многопользовательский доступ к проекту

Необходимо добавить возможность подключать проект по уникальному ID.

Настройки проекта

В настройках проекта добавить уникальный идентификатор проекта.

Например:

ID проекта
ABC7-K92P-X41M

ID должен быть уникальным.

Экран выбора проекта

Добавить возможность:

«Подключить проект по ID»

Например:

ID проекта
[____________________]

[Подключить]

Пользователь вводит ID и получает доступ к соответствующему проекту.

Требования

Изучить текущую модель проектов и систему авторизации.

Не создавать отдельную параллельную систему проектов.

Необходимо обеспечить:

уникальность ID;
поиск проекта по ID;
подключение проекта;
корректную загрузку данных;
работу нескольких пользователей с одним проектом.

Если текущая backend-модель уже поддерживает связи пользователей и проектов — использовать её.

Если нет — аккуратно расширить модель.

9. Свойства компонентов — кнопка «Внутренняя архитектура»

В свойствах компонентов кнопка:

«Внутренняя архитектура»

сейчас визуально прилипает к полю:

«Описание»

Нужно исправить отступ.

Между полем «Описание» и кнопкой должен быть нормальный вертикальный интервал.

Не менять остальные отступы панели без необходимости.

10. Учебник — кнопка открытия/закрытия конспекта

В учебнике есть кнопка открытия/закрытия изображения конспекта.

Сейчас при открытии/закрытии она прыгает.

Это нужно полностью исправить.

Требуемое поведение

Положение кнопки должно быть фиксированным.

Закрыто:

[ Открыть конспект ]

Открыто:

[ Закрыть конспект ]

Но кнопка должна находиться ровно на том же месте.

Меняется только состояние/текст/иконка, но не положение элемента.

Не допускается:

вертикальный скачок;
горизонтальный скачок;
изменение положения из-за появления изображения;
изменение положения соседних элементов.
11. Канва архитектуры — кнопка открытия/закрытия панели

Та же проблема существует на канве архитектуры.

Кнопка открытия/закрытия панели должна находиться строго в одной и той же позиции.

При открытии:

[ ← / закрыть ]

При закрытии:

[ → / открыть ]

Но координата кнопки должна оставаться одинаковой.

Появление/исчезновение панели не должно заставлять кнопку прыгать.

12. Канва таблиц БД — кнопка открытия/закрытия панели

То же самое исправить на канве таблиц базы данных.

Кнопка открытия/закрытия поля/панели должна:

иметь одинаковую позицию в открытом состоянии;
иметь одинаковую позицию в закрытом состоянии;
не двигаться вместе с панелью;
не зависеть от ширины открытого содержимого.

Проверить оба состояния вручную.

13. Экспорт — вместо «Скачать» сделать «Просмотр»

В разделе экспорта сейчас есть кнопки:

«Скачать»

Нужно заменить их на:

«Просмотр»

Требуемая логика

При нажатии:

Просмотр

открывается поле/панель с содержимым соответствующего экспортируемого файла.

Пользователь должен увидеть текст файла.

Например:

┌───────────────────────────────────┐
│ Содержимое файла                  │
│                                   │
│ CREATE TABLE ...                  │
│ ...                               │
│ ...                               │
│                                   │
│                    [Скачать]      │
└───────────────────────────────────┘

Внутри просмотра должна находиться отдельная кнопка:

«Скачать»

Таким образом:

Экспорт
  ↓
[Просмотр]
  ↓
просмотр содержимого
  ↓
[Скачать]

Кнопка «Скачать» должна работать именно из окна/поля просмотра.

Не удалять саму возможность скачивания.

14. До 32 цветов компонентов

Необходимо расширить набор цветов компонентов.

Сейчас вариантов недостаточно.

Нужно добавить до 32 вариантов цветов.

Стиль

Все цвета должны быть:

пастельными;
спокойными;
не кислотными;
не слишком яркими;
совместимыми с существующей визуальной стилистикой приложения.

Не использовать:

насыщенный неоновый цвет;
кислотный зелёный;
ярко-красный;
резкий синий;
слишком тёмные заливки.

Цвета должны визуально хорошо сочетаться друг с другом.

Требуется

Пользователь должен иметь возможность выбрать цвет компонента из палитры.

Количество:

32 варианта.

Если UI уже имеет механизм выбора цвета — расширить существующий компонент.

Не создавать второй независимый color picker.

Проверь:

выбор цвета;
сохранение;
загрузку;
отображение на канве;
старые проекты с существующими цветами.
15. Контекстное меню компонентов

В контекстное меню компонентов добавить отдельную кнопку:

«Открыть внутреннюю архитектуру»

При нажатии должна выполняться та же операция, что и при нажатии существующей кнопки:

«Внутренняя архитектура»

в свойствах компонента.

Не создавать второй механизм перехода.

Оба действия должны использовать один общий handler.

16. Кнопка выхода из внутренней архитектуры

Сейчас стрелка назад для выхода из внутренней архитектуры находится левее кнопки открытия библиотеки компонентов (+).

Нужно поменять их местами.

Было
[ ← ] [ + ]
Должно стать
[ + ] [ ← ]

То есть:

кнопка открытия библиотеки компонентов (+) должна находиться левее, а стрелка назад — сразу правее неё.

Другие элементы верхней панели не переставлять без необходимости.

Проверить:

выравнивание;
отступ между кнопками;
hover;
click;
поведение при открытой/закрытой библиотеке.
