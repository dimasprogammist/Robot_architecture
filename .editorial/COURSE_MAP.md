# Карта курса (рабочая память редактора)

Снято: 2026-10-05. Источник: `backend/course/`. 27 каталогов, 505 уроков, ~205 000 строк.

Как учебник отдаётся приложению: `backend/app/services/course.py` читает frontmatter
(`id, title, module_id, module_title, module_order, order`), сортирует глобально по
`(module_order, order)`; «предыдущий/следующий урок» идут по этому порядку.
Frontend (`TutorialView.tsx`) группирует модули по `module_id` в шесть блоков и
отдельно режет C++ на подблоки по `order` (`CPP_BLOCKS`). Рендер — `RichMarkdown.tsx`
(react-markdown + rehype-raw: HTML `<details>` работает; fenced `text` или блоки с
псевдографикой рисуются как диаграммы без подсветки).

## 2. Технические дефекты (найдены скриптом)

- `module_order` не совпадает с номером каталога: 06-programming=7 **и** 07-python=7
  (коллизия → prev/next перемешивает разделы), 10-networks=5, 11-git=6, 12-sql=10,
  13..19 = 11..17, 27-capstone=18 (стоит раньше электроники). Нужно: `module_order` = номер каталога.
- `08-guide-cpp/80-final-project.md`: frontmatter начинается с пустой строки → парсер его
  не видит, урок **не показывается**.
- `26-guide-neural-networks/05-model-and-training.md`: пустой файл.
- `01-guide-computer/*.md`: закрывающая линия frontmatter из 8–9 дефисов → в тело
  попадает `-----` (лишний `<hr>`).
- `01-guide-computer` уроки 2–7: 16 ссылок на `Pictures/*.svg`, файлов нет (есть только
  часть `.png`; в 03 и 06 имена испорчены символом `↓`). 4 файла в `Pictures/` не
  используются вовсе. Картинки по правилам необязательны.
- `16-guide-frontend/19-fe-components.md` имеет `order: 9` (файл назван 19).
- `TutorialView.CPP_BLOCKS` заканчивается на order 80 → уроки C++ 81–83 не попадают
  ни в один подблок и не видны в навигации.
- `22-guide-protocols`: один HTML-подобный фрагмент `<SET…` (проверить экранирование).

### Компьютер (01) ↔ ОС (02)

01/11–13 (ОС-мост, ядро, I/O) подробно объясняют ядро, системные вызовы, процессы.
02/02–04 (ядро, память процесса, ФС) объясняют то же коротко. Основное место
объяснения — 01 (там глубже). 02 должен опираться на 01 ссылками и добавлять
ОС-специфику: права, пользователи, службы, окружение, сигналы, запуск программ.

### C++ (08) — пары с частичным перекрытием

63-exceptions / 64-try-catch-throw (оба объясняют throw/try/catch/std::exception с нуля);
53-split-header-source / 54-header-files (объявление/определение, `#pragma once`).
Прогрессии 45→46, 47→48→49, 69→70→71 корректны. Приоритет средний.

## 4. Ключевые зависимости (для редакторских решений)

```text
01 компьютер (CPU, память, процесс, поток, ядро)
   → 02 ОС (права, службы, окружение, сигналы) → 03 терминал → 04 Linux
06 программирование (переменная…ООП, без языка)
   → 07 Python  → 09 алгоритмы (примеры на Python) → 12 SQL → 13 backend → 14 FastAPI → 15 WebSocket
   → 08 C++     → 21 микроконтроллеры (код на C++) → 23 робототехника
10 сети → 11 Git (remote/push) ; 10 сети → 13 backend, 15 WebSocket, 22 протоколы
16 frontend ← 13 backend, 10 сети ; 17 архитектура ← 13, 14, 16 ; 18 Kafka, 19 Docker ← 13, 04
24 CV ← 07 Python ; 25 MV ← 24 ; 26 NN ← 07 Python, 24
27 capstone ← всё из 12–19
```

Внутри Python: переменные → типы → условия → циклы → коллекции → функции → модули →
область видимости → исключения → файлы/JSON/CSV → **ООП** → dataclass/типизация →
итераторы/генераторы → декораторы → контекстные менеджеры → тесты → пакеты/venv →
HTTP → логирование → SQLite → продвинутые тесты/типизация → asyncio → потоки → проект.

## 6. Практика: формат

Единого формата интерактивных заданий во frontend нет. Принятое соглашение —
`.editorial/PRACTICE_FORMAT.md`. Существующие авторские разделы (07, 08, 20–26)
используют «Практическое задание / Задание посложнее / Практика / Задание N» —
не переформатировать массово, применять формат при переработке.
